# sd-context-requirement-source

사용자 직접 호출용 워크플로가 아니다. 현재 컨텍스트에 Requirement Source(회의록·메일·문서 추출 텍스트·STT 전사·구두 전달·붙여넣기 등 비정형 요구사항 원본)가 포함되어 있고, 이를 해석하거나 근거로 삼을 때 자동 적용한다.

상위 워크플로 스킬이 배치 처리 중 사용자 질의를 `[OPEN]`으로 대체하라고 명시한 경우 그 규칙이 우선한다. 그 외 대화형 처리에서는 아래의 "사용자에게 즉시 확인" 지시를 그대로 따른다.

## STT(음성→텍스트 변환) 텍스트 보정

명백한 오타만 보정한다. 보정 시 `[원문]` 발췌로 원본도 보존한다.

```markdown
> [2026-03-17 회의] "PDF에 빨간색으로 강조"
> [원문] "PDF에 빨간색으루 강조"
> 출처: .docs/회의대본_3.txt:L120
```

판정:
- 명백(오타 1~2글자, 의미 자명): 보정한다.
- 모호(의미가 여러 갈래로 해석 가능): 사용자에게 즉시 확인하고, 원문 그대로 발췌한다.

## 화자 추정

회의록의 화자 표기가 부정확하거나 누락된 경우, 앞뒤 대화 맥락으로 추정한다. `[추정: ...]` 표기한다.

```markdown
> [2026-03-17 회의, 추정: B 차장] "주문 단위로 가는 게 맞다"
> 출처: .docs/회의대본_3.txt:L78-L80
```

판정:
- 앞뒤 대화 맥락으로 화자가 명확: 추정 표기한다.
- 모호: 사용자에게 즉시 확인하고, 화자 미상으로 발췌한다.

## 모호 발화 처리

지시대명사·생략 표현·비격식 발언 예:
- "그거 그렇게" / "이렇게 가는 걸로" / "지난번처럼" / "알아서".

처리:
- 자동 해석 금지. 이전 발언이나 맥락을 추측해서 채워 넣지 않는다.
- 사용자에게 즉시 확인한다. 예: "그거"가 무엇을 가리키는지, "그렇게"가 어떤 방식인지.

## 다중 화자 발언 섞임(회의록)

여러 사람이 같은 주제를 다른 입장에서 말한 경우:
- 모든 화자의 발언을 발췌하여 보존한다.
- 사용자에게 어느 의견을 채택할지 즉시 확인한다.

## 비격식 메일 또는 붙여넣기 텍스트

주어 생략, 맥락 누락:
- 보충 가능한 부분(자명한 주어 등): 발췌 시 `[추정 보충: ...]` 표기로, 원문 자체는 수정하지 않고 보충분을 별도로 명시한다.
- 모호한 부분: 사용자에게 즉시 확인한다.

## 도메인 용어 다의성

요구사항 원본에 등장하는 업무 용어는 시스템 용어가 아니라 현장 은어일 수 있다. 같은 단어가 시스템상 여러 동작에 매핑될 수 있다.

예:
- "출고" → 창고간 재고이동 / 고객사 납품 / 차량 적재 / 그 외.
- "마감" → 일마감 / 월마감 / 정산마감 / 작업종료.
- "주문" → 고객 발주 / 내부 작업지시 / 견적 단계.

위험도 역설: 일반적으로 들리는 업무 용어(출고·입고·재고·주문·마감·등록 등)일수록 더 의심한다. 낯선 용어는 자연스럽게 의문이 생기지만, 익숙한 용어는 모두가 같은 뜻으로 안다고 착각하기 쉽다.

처리:
- 자동 매핑 금지.
- 사용자에게 즉시 확인한다. 해당 단어가 시스템상 어떤 동작을 가리키는지 묻는다.
- 후보 나열 금지. 에이전트가 추측한 후보를 먼저 제시하면, 사용자가 그 후보 안에서만 고르도록 가두는 효과가 발생한다. 후보 없이 사용자가 직접 답하도록 둔다.
