# sd-demo: UI 데모 생성·동기화

wbs.md를 입력받아 고객 컨펌용 UI 데모 코드를 본 코드 위치에 생성하고, 사용자가 직접 수정한 데모를 wbs.md로 역동기화하는 스킬.

개발 프로세스: WBS 작성 → **데모 생성·동기화** → Task 문서 작성 → TDD 개발

| 스킬     | 책임                      |
| -------- | ------------------------- |
| sd-wbs   | 사용자 동작 단위 분해     |
| sd-demo  | 데모 코드 생성·동기화     |
| sd-plan  | 비즈니스 규칙 + 구현 설계 |
| sd-tdd   | 구현                      |

sd-demo는 sd-wbs와 sd-plan 사이에 선택적 단계로 위치하며, 사용자가 호출 여부를 결정한다.

데모 워크플로: 데모 생성 → 사용자 직접 1차 수정 → 고객 시연 → 2차 수정 → `--sync`로 wbs.md 정합화 → 컨펌 → `/sd-plan`.

## 공통 규칙

### 데모 코드 동작 수준

- 컴포넌트 파일 1개 안에서 처리 가능한 인터랙션은 모두 동작시킨다 (signal/useState·하드코딩된 배열 filter·정렬 등).
- DB·서비스·외부 store·별도 fixture 파일·mock service에 의존 금지 — 컴포넌트 내부 선언만 사용한다.
- 하드코딩된 값은 컴포넌트 내부에 직접 작성한다.
- 라우팅·메뉴 진입은 동작한다.

### 데모 코드 위치

- 본 코드 위치(`packages/{app}/src/`)에 직접 생성한다.
- `{app}` 패키지는 wbs.md의 `## 프로젝트 개요`·`환경` 섹션에서 추출한다.
- 추출 불가 시 `sd-clarify` 지침에 따라 명확화한다.
- `.tasks/{topic}/demo/` 같은 격리 폴더 생성 금지 — 본 코드 위치 외 다른 곳에 만들지 않는다.

### sd-plan/sd-tdd와의 관계

- 본 위치에 데모 코드가 이미 있는 상태에서 sd-plan/sd-tdd가 자연스럽게 그 위에서 작업한다.
- 데모 코드의 하드코딩된 값은 sd-tdd 단계에서 실제 호출로 교체된다.
- sd-plan/sd-tdd의 입력 형식·실행 흐름을 변경하라고 안내하지 않는다.

## Step 1: 입력 확인 및 모드 분기

| 입력 형태                     | 모드                                               |
| ----------------------------- | -------------------------------------------------- |
| `{wbs.md경로}`                | 생성 모드 — 전체 화면 일괄 생성 → Step 2           |
| `{wbs.md경로} {Task번호}`     | 생성 모드 — 해당 Task만 부분 생성 → Step 2         |
| `{wbs.md경로} --sync`         | 동기화 모드 → Step 4                               |

`wbs.md` 경로가 입력되지 않으면 `/sd-wbs`를 안내하고 종료한다.

## Step 2: 코드베이스 탐색 (생성 모드)

**CRITICAL: 코드가 source of truth이다.** 이 단계 완료 전 Step 3로 진행하지 않는다.

### 2-1. 패키지 식별

wbs.md의 `## 프로젝트 개요`·`환경` 섹션에서 대상 패키지(`packages/{app}/`)를 추출한다. 명시되어 있지 않거나 후보가 다수면 `sd-clarify` 지침에 따라 사용자에게 묻는다.

### 2-2. 유사 패턴 탐색

대상 패키지 내 유사 화면 컴포넌트를 탐색하여 다음을 메모한다.

- 컴포넌트·템플릿 파일 골격 (Angular `@Component`, signals 사용 패턴 등)
- CSS 클래스 네이밍·스타일 토큰
- 컨트롤 배치
- 라우팅 등록 위치
- 메뉴 구성 위치

대상 패키지에 유사 패턴이 없으면 모노레포 내 다른 패키지의 컴포넌트를 참조한다.

여러 방식이 혼재되어 있거나 결정할 수 없으면 `sd-clarify` 지침에 따라 패턴을 명확화한다.

## Step 3: 데모 코드 생성/재생성 (생성 모드)

대상 Task 범위:

- Task 번호 인자 없음: wbs.md의 모든 Activity·Task
- Task 번호 인자 있음: 해당 Task만

각 Task의 Story를 화면 단위로 묶어 데모 컴포넌트를 생성한다.

### 3-1. 컴포넌트 생성

각 화면마다 1개 컴포넌트 파일을 본 코드 위치에 생성한다.

- 파일 위치: `packages/{app}/src/...` (Step 2 패턴 준수)
- 하드코딩된 값: wbs.md Story의 사례 값·정량 정보를 그대로 컴포넌트 내부에 선언. 사례 값이 없으면 그럴듯한 더미 값을 컴포넌트 내부에 직접 작성한다.
- 인터랙션: 검색·필터·정렬·입력·합계 계산·클릭 등 컴포넌트 내부에서 처리 가능한 것은 모두 동작시킨다.
- 라우팅·메뉴: 메뉴/링크 클릭 시 화면 전환되도록 라우팅 등록 및 메뉴 항목 추가.

### 3-2. 재생성 시 보존 규칙

같은 wbs.md로 재호출되면 기존 데모 코드를 보존한다.

- 사용자가 추가한 컬럼·인터랙션·스타일은 임의로 덮어쓰지 않는다.
- wbs.md 변경분만 반영한다 (신규 Story → 신규 컴포넌트 또는 기존 컴포넌트에 추가).
- 충돌 시 `sd-clarify` 지침에 따라 명확화한다.

### 3-3. wbs.md 직접 수정 금지

생성 모드에서는 입력 wbs.md를 수정하지 않는다. wbs.md 변경은 동기화 모드(`--sync`)에서만 이루어진다.

## Step 4: 차이 추출 및 동기화 (--sync 모드)

### 4-1. 차이 일괄 추출

데모 코드와 wbs.md를 모두 읽고 차이를 일괄 추출한다.

차이 유형:

- **신규 Story 후보**: 데모 코드에 있으나 wbs.md에 대응 Story 없음 (예: 사용자가 추가한 컬럼·필터·버튼)
- **삭제 Story 후보**: wbs.md에 있으나 데모 코드에서 제거됨
- **Story 변경**: 정량 정보·열거값·동작이 달라짐

### 4-2. sd-clarify 분류

추출된 각 차이 항목에 `sd-clarify` 지침을 적용하여 분류한다.

- `VERIFIED` 또는 `INFERRED-High`: 자동 wbs.md 갱신 후보
- `INFERRED-Medium` / `INFERRED-Low` / `ASSUMED`: `sd-ask` 지침에 따라 사용자 질문

분류를 임의 격상하여 질문을 회피하지 않는다.

### 4-3. 일괄 갱신

자동 갱신 항목과 사용자 답변 결과를 일괄 wbs.md에 반영한다.

- Story 추가/삭제/변경 시 기존 체크박스·번호·항목별 근거(`(근거: ...)`)·사용자 메모는 보존한다.
- Story 번호 재부여가 필요한 경우 매핑 표(기존 → 신규)를 변경 보고에 포함한다.
- 의존성 매트릭스·수행 순서 섹션에 영향이 있으면 함께 갱신한다.

### 4-4. 변경 보고

사용자에게 다음을 출력한다.

- 자동 반영된 차이 목록 (분류·근거 인용)
- 사용자 답변으로 결정된 차이 목록
- 보류된 차이 목록 (있는 경우)

### 4-5. 데모 코드 직접 수정 금지

**CRITICAL: 동기화 모드에서는 어떤 이유로도 데모 코드 파일을 수정하지 않는다(NEVER).** 데모 코드는 컨펌 정답으로 취급한다.

- 데모 코드가 미완성·문법 오류·빌드 실패로 보여도 수정 금지 — 발견 사항은 변경 보고에 기록만 한다.
- 신규 Story를 데모에 반영하고 싶으면 사용자가 데모를 직접 수정한 뒤 `--sync`를 다시 호출한다.
- 동기화 모드 도구 사용 범위: wbs.md만 Edit/Write 대상이다.

## Step 5: 다음 단계 안내

### 생성 모드 종료 후

- 컨펌 단계로: 데모 화면 직접 검토 후 고객 시연. 변경 시 데모 직접 수정 후 `/sd-demo {wbs.md경로} --sync`.
- 본 개발 진입: `/sd-plan {wbs.md경로} {Task번호}`로 Task 문서 작성.

### 동기화 모드 종료 후

- 추가 수정 필요 시: 데모 직접 수정 후 `--sync` 재호출.
- 컨펌 완료 시: `/sd-plan {wbs.md경로} {Task번호}`.
