# sd-sit: SIT 검증 진행

sit.md 흐름 체크리스트를 위에서 아래로 자동 실행하며 통과 항목을 `[x]`로 갱신한다. 한계 도달 시 즉시 중단하고 다른 세션 처리를 안내한 뒤 사용자 응답을 대기한다.

각 항목 통과는 "이 작업이 정상이니 프로세스상 다음 단계로 진입 가능"의 의미다. 검증 도구는 검증자(고객 빙의자)가 화면에서 실제로 수행할 동작을 그대로 시뮬레이션한다.

## 공통 규칙

### 출력 갱신 형식

각 항목은 실행 직후 sit.md에서 다음 형식으로 갱신한다.

- 통과: `- [x] {항목명} — {결과 1줄 요약}`
- 실패(중단점): `- [ ] {항목명} — 실패: {사유 1줄}`
- 미수행: 변경하지 않는다 (`- [ ] {항목명}` 그대로 둔다)

체크박스 마커는 `[x]`/`[ ]` 두 개만 사용한다. `[!]`·`[?]`·`[/]` 등 비표준 마커 금지.
결과 1줄 요약은 항목과 같은 줄 끝에 ` — ` 구분자로 붙인다. 들여쓰기 자식 항목·별도 진행 표 등 다른 위치에 추가 금지.

### 중단 트리거

다음 사유 중 하나라도 발생하면 즉시(MUST) 중단하고 Step 4로 진입한다. 추정·우회·임의 다음 항목 진행 금지.

- playwright 자동화 한계 (셀렉터 미발견·페이지 로드 실패·인증 차단 등)
- 코드 버그 (애플리케이션 예외·네트워크 오류·기능이 사용자 의도와 어긋남)
- 시나리오 자체 미스 (sit.md 흐름이 검증자 실제 사용 흐름과 다름)
- sit 항목 낡음 (코드 동작은 사용자 의도와 일치하지만 sit 기대값이 과거 버전을 따라감)
- 픽스처 적재 실패 (`## 기반 데이터` 섹션의 픽스처를 적재하지 못함)
- 권한·설정 누락 (DB·계정·환경변수 부재)
- 그 외 어떤 사유든 자동 실행이 막히는 경우

### 임의 변형 금지

CRITICAL: 입력 sit.md에 없던 항목을 추가하거나 항목 문구를 의역·축약하지 않는다.
`[x]`는 실제 통과한 항목에만 부여한다 (통과하지 않은 항목에 `[x]` 거짓 부여 금지).
한계에 부딪힌 항목은 `- [ ] {항목명} — 실패: {사유 1줄}` 형식으로 반드시 갱신한 뒤 중단한다.
sit.md 외 파일은 수정·생성하지 않는다 (`.claude/`·소스 디렉토리·다른 `.tasks/` 하위 등).

## Step 1: 입력 sit.md 확인

호출 시 전달된 sit.md 경로를 식별하여 끝까지 읽는다.

### 입력 부재 처리

sit.md 경로가 없거나 파일이 존재하지 않으면, 임의로 sit.md를 신규 생성하지 말고 `sd-clarify` 지침에 따라 다음을 안내한다.

- 입력으로 받을 sit.md 경로 요청
- sit.md가 없는 경우 `/sd-sit-plan` 호출 권유

## Step 2: 환경 정보 재확인

sit.md "환경 정보" 섹션을 출력하고 검증자에게 단일 확인을 받는다. sd-sit-plan Step 6에서 수집·기록된 값을 그대로 활용하므로 매 호출 반복 수집을 하지 않는다.

### 재확인 형식

다음 형식으로 출력한 뒤 응답을 대기한다.

```
환경 정보:
- 접속 주소: {sit.md 기록값}
- DB 연결: {sit.md 기록값 — 해당 항목 존재 시}
- 인증 계정: {sit.md 기록값 — 해당 항목 존재 시}

이대로 진행할까요? (예 / 변경됨)
```

- 응답 "예": Step 3으로 진입.
- 응답 "변경됨": 변경 응답 처리로 진입.

### 변경 응답 처리

변경 대상 항목만 `sd-clarify` 지침에 따라 한 번에 하나씩 받는다. 응답을 받아 sit.md "환경 정보" 섹션을 갱신한 뒤 Step 3으로 진입한다.

CRITICAL: 접속 주소를 임의로 결정하지 않는다 (`http://localhost:XXXX` 추측 금지). 반드시 사용자에게 묻는다.

## Step 3: 항목 순차 실행

sit.md를 위에서 아래로 첫 `[ ]` 항목부터 1개씩 처리한다. 이미 `[x]`된 항목은 다시 실행하지 않고 건너뛴다 (재호출 시 진행 재개 동작).

본 항목 처리 전에 Step 3-0에서 `## 기반 데이터` 섹션을 일괄 적재한다.

### 3-0. 기반 데이터 일괄 적재

sit.md `## 기반 데이터` 섹션의 모든 그룹을 위에서 아래로 적재한다. 그룹 헤더 `### {그룹명} ({적재 방식})`의 적재 방식 토큰에 따라 도구를 선택한다.

| 적재 방식 토큰 | 도구 |
|---|---|
| SQL | DB 직접 INSERT |
| API | 서비스 API 호출 |
| UI 업로드 | `playwright-cli` 스킬 호출 |
| 스냅샷 | DB 백업 복원 |

위에 없는 토큰은 `sd-clarify` 지침에 따라 처리 방식을 명확화한다.

적재 실패 시 중단 트리거를 적용한다 (Step 4 진입). `## 기반 데이터` 섹션은 명세이므로 sit.md 본문은 수정하지 않는다 (체크박스 갱신 대상 아님).

재호출 시 이미 적재된 픽스처 위에 중복 적재가 시도되지 않도록 검증한다 (DB 행 존재·계정 존재 등을 사전 점검). 충돌 발생 시 중단 트리거 적용.

### 3-1. 항목 도구 매핑

흐름 그룹(`## 흐름 N. {이름}`) 안 모든 항목은 `playwright-cli` 스킬을 호출하여 검증자가 화면에서 수행할 사용자 동작을 그대로 시뮬레이션한다.

흐름 그룹 외 분류 헤더가 sit.md에 등장하면 `sd-clarify` 지침에 따라 처리 방식을 명확화한다.

### 3-2. 항목 실행

도구 호출 후 결과를 판정한다.

- 통과: 도구 호출 결과가 항목의 분기점 통과 신호를 만족함 (= 이 작업이 정상이니 다음 단계 진입 가능)
- 실패(중단점): 중단 트리거 중 하나라도 해당함

판정 기준이 모호한 경우 임의 판정 금지(NEVER) — 결과를 보고한 뒤 `sd-clarify` 지침에 따라 통과/실패를 명확화한다.

코드 동작과 sit 기대값이 어긋난 경우 사유 분류 절차:

1. 코드 동작이 사용자 의도(현장 사용 흐름)에 맞는가?
   - 맞음 → "sit 항목 낡음" 중단 사유 적용 (코드 버그 X, plan·다른 산출물 갱신 안내 X)
   - 안 맞음 → "코드 버그" 중단 사유 적용
2. sit.md 흐름 자체가 검증자가 따라 하려는 실제 사용 흐름과 다름 → "시나리오 자체 미스" 중단 사유 적용

### 3-3. sit.md 갱신

항목 실행 직후 즉시 sit.md를 갱신한다.

- 통과 시: 해당 항목 줄을 `- [x] {항목명} — {결과 1줄 요약}` 형식으로 갱신
- 실패 시: 해당 항목 줄을 `- [ ] {항목명} — 실패: {사유 1줄}` 형식으로 갱신한 뒤 Step 4로 진행

### 3-4. 다음 항목으로 진행

통과 후 `[ ]` 항목이 더 있으면 3-1로 돌아가 다음 항목 처리. 모든 항목이 `[x]`로 갱신되면 Step 5로 진행.

## Step 4: 중단 처리 및 후속 액션 안내

한계 도달로 중단된 경우 다음을 수행한다. 다음 항목으로 자동 진행하지 않는다.

### 4-1. 상황 보고

다음 형식으로 사용자에게 보고한다.

```
중단점: {sit.md 경로}:{줄번호} — {항목명}
한계 사유: {1줄 사유}
```

### 4-2. 후속 액션 안내

사유 무관하게 다른 세션에서 처리하도록 안내하고, 현재 세션은 사용자 응답을 대기한다.

다음 형식으로 출력한다.

```
다른 세션에서 다음과 같이 처리해주세요.

{사유별 권장 후속 액션}

처리가 완료되면 "완료"라고 응답해주세요. 응답 시 다음 항목부터 자동 재개합니다.
```

사유별 권장 후속 액션:

| 한계 사유 | 권장 후속 액션 |
|---|---|
| 코드 버그 | `/sd-debug {항목명} — {사유 1줄} (sit.md: {경로}:{줄번호})` |
| playwright 자동화 한계 | 셀렉터 점검·DOM 변경 확인 |
| 픽스처 적재 실패 | sit.md `## 기반 데이터` 섹션 보정 또는 수동 적재 |
| 권한·설정 누락 | DB 권한 부여·환경 변수 설정 |
| 시나리오 자체 미스 | sit.md 흐름 보정 (`/sd-sit-plan` 재호출 또는 직접 편집) |
| sit 항목 낡음 | sit.md 항목 보정 (`/sd-sit-plan` 재호출 또는 직접 편집) |

NEVER:

- 위 6종 외 후속 액션을 발명하지 않는다.
- plan·spec·wbs 등 다른 산출물 갱신을 후속 액션으로 안내하지 않는다 (sit.md 흐름·항목과 코드 정합만 SIT 책임 영역이며, 다른 산출물 정합은 sd-plan/sd-wbs 책임 영역).
- 현재 세션에서 후속 액션을 자동 호출하지 않는다 (`Skill` tool 직접 실행 금지). 사용자가 다른 세션에서 처리하도록 안내만 한다.

### 4-3. 사용자 처리 후 재개

사용자가 "완료" 응답 시 Step 3에서 첫 `[ ]` 항목부터 자동 재개한다 (이전 통과 `[x]` 항목은 건너뜀).

## Step 5: 완료 보고

모든 항목이 `[x]`로 통과되면 다음을 보고한다.

```
SIT 진행 완료: {sit.md 경로}
- 통과 항목 수: {N}
- 중단·실패 없음
```
