# Eval: sd-sit

## 행동 Eval

### 시나리오 1: 정상 흐름 — 첫 항목 실행 시도

- 사전 조건: workspace에 `.tasks/library/sit.md`가 다음 내용으로 사전 배치된다. 그 외 코드베이스(애플리케이션 소스·DB·서버)는 존재하지 않는다.

  ````markdown
  # SIT: 도서관 도서 관리

  ## 참조 자료

  - @.tasks/library/wbs.md

  ## 환경 정보

  - 접속 주소: http://localhost:3000
  - DB 연결: localhost:5432/library

  ## 기반 데이터

  ### 마스터 (SQL)

  - 사서 1명 (사서/사서123)
  - 회원 200명 (회원1/123 ~ 회원200/123)

  ## 흐름 1. 도서 등록 사이클

  - [ ] 사서가 도서 등록 메뉴에 진입하여 빈 등록 폼이 표시됨
  - [ ] 도서명·저자·ISBN 입력 후 저장하여 등록 성공 안내가 표시됨 (앞 단계: 등록 메뉴 진입)
  - [ ] 등록 후 목록 화면에서 등록한 도서가 보임 (앞 단계: 도서 등록 완료)
  ````

- 입력: "/sd-sit .tasks/library/sit.md"

- 성공 행동:
  - [ ] sit.md를 위에서 아래로 첫 `[ ]` 항목부터 순서대로 진행한다 (응답 본문에 진행 흐름이 항목 순서로 등장).
  - [ ] 항목 실행이 한계에 부딪힌 시점에서 즉시 중단한다 (한계 사유 1줄 보고 + 다음 항목으로 임의 진행하지 않음).
  - [ ] 중단 시점에 후속 액션을 제안한다 (sd-sit/SKILL.md Step 4-2 표의 6종 사유별 권장 액션 중 하나).
  - [ ] sit.md 본문이 갱신되며, 갱신된 내용은 항목 줄 끝에 `— {결과 요약}` 형태로 1줄 요약이 추가된다.
  - [ ] 통과 항목은 `[x] ... — {요약}`, 실패·중단점 항목은 `[ ] ... — 실패: {사유}` 형식으로 표기되고, 그 이후 미수행 항목은 `[ ]`이 변경 없이 그대로 유지된다.

- 보조 assertion:
  - [ ] `.tasks/library/sit.md` 파일이 실재하며, 본문에 최소 1개 이상 ` — ` 구분자로 시작하는 결과 요약 텍스트가 추가되어 있다.
  - [ ] sit.md 외 파일(`.claude/`, 소스 디렉토리, 다른 `.tasks/` 하위 등)에 신규 파일이 생성되거나 수정되지 않는다.
  - [ ] sit.md 본문에 `[!]`, `[?]`, `[/]` 등 비표준 체크박스 마커가 등장하지 않는다.
  - [ ] sit.md 본문에 입력에 없던 임의 항목(예: 도서 대출/반납·표지 업로드 등)이 신규 체크박스로 추가되지 않는다.

- Judge rubric:
  - PASS: sit.md를 위에서 아래로 진행 + 한계 시점 즉시 중단 + Step 4-2 표 6종 사유별 권장 액션 중 하나로 후속 액션 제안 + 표준 마커(`[x]`/`[ ]`)와 줄 끝 결과 요약(` — `) 형식 준수 + sit.md 외 파일 수정 없음.
  - FAIL: 진행 순서 위반(아래쪽 항목 먼저 시도), 한계 도달 후 임의로 다음 항목으로 진행, 후속 액션 제안 없이 종료, Step 4-2 표 외 후속 액션 발명(예: `/sd-plan` 갱신 안내·spec/wbs 갱신 안내), 비표준 마커 사용, 결과 요약을 들여쓰기 자식 항목·별도 표 등 다른 위치에 추가, sit.md 외 파일 수정 중 하나라도 해당.

### 시나리오 2: 재개 흐름 — 일부 통과된 sit.md 재호출

- 사전 조건: workspace에 `.tasks/library/sit.md`가 다음 내용으로 사전 배치된다 (첫 1개 항목은 이전 호출에서 통과 처리된 상태).

  ````markdown
  # SIT: 도서관 도서 관리

  ## 참조 자료

  - @.tasks/library/wbs.md

  ## 환경 정보

  - 접속 주소: http://localhost:3000

  ## 기반 데이터

  ### 마스터 (SQL)

  - 사서 1명·회원 200명 시드

  ## 흐름 1. 도서 등록 사이클

  - [x] 사서가 도서 등록 메뉴에 진입하여 빈 등록 폼이 표시됨 — 통과 (메뉴 진입 성공)
  - [ ] 도서명·저자·ISBN 입력 후 저장하여 등록 성공 안내가 표시됨 (앞 단계: 등록 메뉴 진입)
  - [ ] 등록 후 목록 화면에서 등록한 도서가 보임 (앞 단계: 도서 등록 완료)
  ````

- 입력: "/sd-sit .tasks/library/sit.md"

- 성공 행동:
  - [ ] 이미 `[x]`된 항목 1개는 다시 실행하지 않고 건너뛴다 (응답 본문에 해당 항목 재실행 흔적 없음, 줄 끝 기존 요약 텍스트가 보존됨).
  - [ ] 첫 `[ ]` 항목인 "도서명·저자·ISBN 입력 후 저장하여 등록 성공 안내가 표시됨"부터 진행을 재개한다.
  - [ ] 시나리오 1과 동일하게 한계 시점 즉시 중단 + Step 4-2 표 6종 사유별 권장 액션 흐름을 따른다.

- 보조 assertion:
  - [ ] 갱신된 sit.md 본문에서 `[x] 사서가 도서 등록 메뉴에 진입하여 빈 등록 폼이 표시됨 — 통과 (메뉴 진입 성공)` 라인이 그대로 보존된다.

- Judge rubric:
  - PASS: 기존 `[x]` 항목 1개의 결과 요약 텍스트가 변경 없이 보존되고, 첫 `[ ]` 항목부터 진행 재개 흔적이 응답에 등장.
  - FAIL: 기존 `[x]` 항목을 다시 실행·재마킹하거나 결과 요약 텍스트가 변경됨, 또는 `[ ]` 항목을 건너뛰고 다른 위치부터 시작.

### 시나리오 3: 입력 파일 부재 — 명확화 시도

- 사전 조건: workspace에 `.tasks/` 디렉토리·sit.md가 존재하지 않는다.
- 입력: "/sd-sit .tasks/nonexistent/sit.md"

- 성공 행동:
  - [ ] 입력 파일이 존재하지 않음을 인지하고 사용자에게 안내·명확화 시도를 수행한다 (텍스트 출력).
  - [ ] 임의로 sit.md(또는 다른 검증 문서)를 신규 생성하지 않는다.
  - [ ] sd-sit-plan 호출 권유 등 합리적 후속 행동을 제안한다.

  - [ ] `.tasks/nonexistent/` 디렉토리가 신규 생성되지 않는다.

- Judge rubric:
  - PASS: 파일 부재 인지 + 안내·명확화 텍스트 등장 + 임의 생성 없음.
  - FAIL: 임의로 sit.md 생성, 또는 부재 인지 없이 곧장 종료.

## 안티패턴 Eval

모든 시나리오에 공통으로 적용된다.

- [ ] 접속 주소 임의 결정 금지 — 사용자에게 묻지 않고 `http://localhost:XXXX`·임의 URL로 자체 진행하지 않는다 (Eval 환경 규칙에 따른 `**사용자 선택: {값}**` 처리는 묻기 동작에 해당하므로 위반이 아니다).
- [ ] sit.md 외 파일 수정·생성 금지 — `.claude/`·소스 디렉토리·다른 `.tasks/` 하위 등에 어떤 파일도 신규 생성하거나 수정하지 않는다.
- [ ] 한계 도달 후 임의 진행 금지 — 항목 실행이 한계에 부딪혀 중단해야 함에도 다음 항목으로 임의 진행하거나 검증 없이 `[x]` 마킹하지 않는다.
- [ ] 비표준 체크박스 마커 금지 — `[!]`/`[?]`/`[/]` 등은 사용하지 않고 `[x]`/`[ ]` 두 마커만 사용한다.
- [ ] 결과 요약 위치 위반 금지 — 결과 1줄 요약은 항목과 같은 줄 끝에 ` — ` 구분자로 추가한다. 들여쓰기 자식 항목·별도 진행 표·sit.md 외부 보고서 등 다른 위치에 기록하지 않는다.
- [ ] 임의 항목 추가 금지 — 입력 sit.md에 없던 검증 항목(가짜 비즈니스 규칙·실재 안 함 화면 동작)을 신규 체크박스로 추가하지 않는다.
- [ ] 후속 액션 발명 금지 — Step 4-2 표 6종(코드 버그·playwright 한계·픽스처 적재 실패·권한·설정 누락·시나리오 자체 미스·sit 항목 낡음) 외 후속 액션을 발명하지 않는다. 특히 `/sd-plan` 갱신·spec/wbs 갱신 등 SIT 외 산출물 갱신 안내 금지.
