# sd-sit-plan: SIT 검증 문서 작성

SIT는 고객에게 빙의해 실제 현장 사용 흐름을 그대로 시뮬레이션하는 통합 검증이다.

입력으로 받은 wbs.md(1개 또는 N개)의 범위를 SIT 범위로 삼고, 그 안의 사용자 사용 흐름을 추출하여 `sit.md`를 생성·갱신한다.

흐름 단위는 고객이 실제로 한 번에 처리하는 작업 단위다. 한 화면에서 시작·끝나는 단순 작업도 1개 흐름, 여러 화면을 왕래하는 작업도 1개 흐름이다.

각 검증 항목은 흐름 안 분기점 통과 신호로 작성한다. 항목 통과 = "이 작업이 정상이니 프로세스상 다음 작업으로 넘어가도 됨".

## Step 1: 입력 자료 수집

호출 시 전달된 인자에서 다음 자료를 식별하여 끝까지 읽는다.

- **wbs.md 경로 (1개 또는 N개)** — Read 도구로 완독. SIT 범위는 입력 wbs.md 범위 그 자체로 한정한다.
- **자연어 본문** — wbs 안에서 어떤 흐름·범위를 추출할지 지정하는 추가 지시로만 사용. 자연어 단독으로 SIT 항목을 도출하지 않는다.

기타 입력(.docx/.xlsx/.pdf/.eml/.msg 등) 동반 시 `/sd-doc-extract`로 텍스트·이미지를 추출하여 보조 자료로 활용한다.

### 자료 부족 처리

다음 중 하나에 해당하면 임의로 sit.md를 작성하지 말고 `sd-clarify` 지침에 따라 명확화한다.

- wbs.md 경로가 입력에 없음
- 입력된 wbs.md 경로가 존재하지 않거나 비어 있음
- wbs.md에서 사용자 흐름 1개 이상 도출이 불가함 (Activity·Task·Story가 비어 있음)

자연어만 들어왔다면 `/sd-wbs` 호출을 권유하고 종료한다.

## Step 2: 출력 경로 결정

입력 wbs.md 수에 따라 분기한다.

- wbs.md 1개 입력: 해당 wbs.md와 같은 디렉토리에 `sit.md` 생성·갱신
- wbs.md N개 입력: `sd-clarify` 지침에 따라 통합 sit.md 출력 위치를 명확화 (대안: 새 `.tasks/{timestamp}_{topic}/` 디렉토리 통합 / 각 wbs 디렉토리별 sit.md 분리)

기존 sit.md가 있으면 갱신 모드로 동작한다. 기존 체크박스 상태(`[x]`/`[ ]`)·사용자 메모는 보존하고 신규 항목만 추가한다.

NEVER: `tests/sit/`, `packages/**/sit/` 등 결정된 경로 외부에 SIT 문서를 생성하지 않는다.

## Step 3: 사용자 흐름 추출 및 항목 도출

### 3-1. 흐름 식별

wbs.md 본문에서 고객이 실제로 한 번에 처리하는 사용 흐름을 추출한다.

식별 출처:

- Activity Backbone — 사용자 여정의 시간 흐름·업무 묶음
- Activity별 업무 플로우 (mermaid) — 시간 흐름·분기 표현
- Task·Story — 사용자 동작의 최소 단위

추출 원칙:

- 트리거-결과 단일 단위로 묶는다. 사용자가 한 번 시작해 한 번 끝맺는 작업 = 흐름 1개.
- 한 Story로 시작·끝나는 단순 작업도 흐름 1개로 인정한다 (강제 묶음 금지).
- 여러 Story·Task에 걸친 흐름은 시간 순서대로 묶는다.
- wbs의 Activity 묶음과 업무 플로우 분기를 우선 활용한다.
- Task/Story 식별자(`Task 1.1`·`Story 1.1.1` 등)는 추출 근거로 본문에 인용하되, 그룹핑 헤더로 사용하지 않는다.

### 3-2. 그룹핑 단위

추출된 흐름 단위로 sit.md 섹션을 구성한다.

- 헤더 형식: `## 흐름 N. {흐름 이름}` (예: `## 흐름 1. 입고 처리 사이클`)
- Task/Story 식별자 그룹핑 금지 — 흐름이 여러 Task에 걸친 경우 한 흐름 안에 묶인다.
- 평면 체크리스트 금지 — 흐름 헤더 없이 모든 항목을 나열하지 않는다.

### 3-3. 기반 데이터 작성

흐름 시작 전 적재해야 할 픽스처(테이블 레코드·파일·계정·권한 등)를 sit.md `## 기반 데이터` 섹션에 명세한다.

하위 그룹은 `### {그룹명} ({적재 방식})` 형식으로 헤더에 적재 방식을 명시한다.

- 그룹명 예: `마스터`, `거래처`, `단가표`, `입고 파일`
- 적재 방식 토큰: `SQL`, `API`, `UI 업로드`, `스냅샷`

각 픽스처 항목은 검증에 필요한 정량/열거값(수치·식별자·필드값)을 그대로 명시한다.
모호한 표현(`적당한 분류 코드 몇 개` 등)은 금지한다 — sd-sit이 자동 적재할 수 있어야 한다.

### 3-4. 항목 형식

각 흐름 안 검증 항목은 흐름 분기점 통과 신호로 작성한다.

- 형식: `- [ ] {항목명}` 마크다운 체크박스
- 항목 본문에 앞 단계 입력·결과 맥락을 포함한다 — 단독 검증 단위로 떠 있는 항목 금지.
  - 좋은 예: `- [ ] 단가표 적용 후 매출 매트릭스에 A서점 13,500원·B서점 12,750원 표시 (앞 단계: 거래처별 단가 13,500/12,750 입력 → 거래 등록)`
  - 나쁜 예: `- [ ] 매트릭스 D8 셀 13,500 표시` (앞 단계 맥락 없음)
- 흐름 첫 항목도 진입 전제 상태(검증자 진입 시점의 사용자 위치·로그인 상태·권한·페이지 위치 등)를 `(앞 단계: ...)` 형태로 명시한다. 첫 항목이라고 맥락 생략하지 않는다.
  - 첫 항목 좋은 예: `- [ ] 사서가 도서 등록 메뉴에 진입하여 빈 등록 폼이 표시됨 (앞 단계: 사서 계정으로 로그인된 상태)`
  - 첫 항목 나쁜 예: `- [ ] 사서가 도서 등록 메뉴에 진입하여 빈 등록 폼이 표시됨` (진입 전제 누락)
- 정량/열거값(수치·필드명·상태값 등)은 wbs.md의 표현을 그대로 옮긴다. 의역·축약 금지 (예: "도서명·저자·ISBN" → "필수 항목들" 금지).
- 항목 통과 의미: "이 작업이 정상이니 프로세스상 다음 단계로 진입 가능".
- 흐름 안 항목은 시간 순서대로 나열한다 (서브 헤더 분리는 강제 아님 — 항목 본문이 순서를 표현).
- 같은 로직을 입력값만 바꿔 케이스 매트릭스로 나열 금지. 시나리오 흐름과 관계식·규칙으로 표현.
  - 금지 예: "수량 5 입력 시 단가 X / 수량 10 입력 시 단가 Y" 단가표 카르테시안 곱.
  - 허용 예: "수량 변경 시 단가가 단가표 규칙대로 재계산 — 시드 단가표 기준 5개 1,200원·10개 1,100원 표시".
- 예외 흐름(빈 입력·권한 없음·임계값 초과 등)은 같은 흐름 안 별도 항목으로 분리한다 (별도 흐름 그룹으로 떼지 않는다).
- wbs.md에 없는 항목(가짜 비즈니스 규칙·실재 안 함 화면 동작·wbs 제외 사항)은 추가하지 않는다.

## Step 4: sit.md 생성

다음 템플릿으로 작성한다.

````markdown
# SIT: {주제}

## 참조 자료

- {입력 wbs.md 경로 — `@path` 형태}

## 기반 데이터

### {그룹명} ({적재 방식})

- {픽스처 항목 — 정량/열거값 그대로 명시}

## 흐름 1. {흐름 이름}

- [ ] {분기점 통과 신호 — 앞 단계 맥락 포함}
- [ ] {다음 분기점 통과 신호 — 앞 단계 맥락 포함}

## 흐름 2. {흐름 이름}

- [ ] ...
````

## Step 5: 격리 검증 (정보 유실·누락 점검)

**CRITICAL: 자체 판단으로 생략 금지(NEVER). 자체 요약 텍스트로 대체 금지(NEVER). 반드시 Agent tool 호출로 수행한다.**

문서 작성 후, 작성자 편향 제거와 정보 유실 차단을 위해 메인 세션과 분리된 Agent tool로 격리 검증을 수행한다.

### 5-1. 검증 호출

Agent tool(effort: `low`)을 다음 입력으로 호출한다:

- **sit.md 절대 경로** — Step 4에서 작성한 검증 대상
- **wbs.md 절대 경로 목록** — 입력 자료
- **사용자 초기 요청 메시지 본문** — 프롬프트에 인라인 삽입

Agent tool에 부여할 제약: "보고만 수행. sit.md를 수정하지 말 것."

### Agent tool 프롬프트에 포함할 검증 가이드

#### 검증 항목

1. **흐름 커버리지** — 입력 wbs.md의 Activity·Task·Story가 sit.md의 흐름 그룹에 빠짐없이 매핑되는지 확인.

   - 컬럼: `wbs 식별자(Task/Story)` / `wbs 표현` / `sit.md 흐름 그룹` / `sit 항목 본문` (sit 그룹 빈칸 = 누락)
   - 누락: wbs에 있는데 sit.md 어떤 흐름에도 매핑되지 않은 사용자 동작
   - 근거 없는 추가: sit.md에 있는데 wbs에서 추적 불가한 항목

2. **단독 검증 단위 검출** — 항목 본문에 앞 단계 입력·결과 맥락이 없어 흐름과 단절된 항목이 있는지 확인 (예: "매트릭스 D8 셀 X 표시" — 앞 단계 입력 맥락 없음)

3. **의역 변형 검출** — wbs 원문이 구체적인데 sit.md가 추상화된 사례 (예: 원문 "도서명·저자·ISBN" → sit "필수 항목들")

4. **체크박스 형식 검증** — 모든 검증 항목이 `- [ ] {항목명}` 형식인지 확인 (`* `, `1.`, `- ` 단독, 체크박스 누락은 위반).

5. **흐름 그룹핑 형식 검증** — sit.md 본문에 `## 흐름 N. {이름}` 헤더가 1개 이상 등장하고, 평면 체크리스트가 아닌지 확인. Task/Story 식별자를 그룹 헤더로 쓴 경우는 위반.

6. **기반 데이터 섹션 검증** — `## 기반 데이터` 섹션과 그 하위 그룹 헤더 `### {그룹명} ({적재 방식})` 형식이 등장하는지 확인.

7. **입력 케이스 매트릭스 나열 검출** — 같은 로직을 입력값만 바꿔 케이스로 나열한 항목이 있는지 확인. 위반 예: 단가표 카르테시안 곱. 권장: 관계식 표현. 시나리오 항목이 기반 데이터 픽스처를 참조한 구체 기대값을 명시하는 것은 위반이 아니다.

#### 완독 의무

원본 자료(wbs.md·인라인 요청 메시지)와 sit.md는 끝까지 읽는다. 키워드 검색만으로 종결하지 않는다.

#### 출력 포맷

- **요약** — wbs 항목 수 / 매핑·누락·근거 없는 추가·의역 변형·단독 검증 단위·형식 위반 (각 정수)
- **흐름 커버리지 표** (항목 1)
- **누락 / 근거 없는 추가 / 단독 검증 단위 / 의역 변형 / 형식 위반 / 흐름 그룹핑 누락 목록** — 각 항목 출처, 권장 반영 위치, 권장 처리 방향 포함

### 5-2. 메인의 결과 처리

1. 모든 결과 항목은 `sd-clarify` 지침에 따라 명확화한다.
2. 흐름 추출·항목 재작성이 필요하면 Step 3으로 되돌아간다.

## Step 6: 환경 정보 수집

sit.md 본문 구조에 따라 환경 정보를 사용자에게 사전 요청한 뒤, sit.md "참조 자료" 섹션 다음에 "환경 정보" 섹션을 작성한다.

### 수집 항목

sit.md 구조에 따라 필요한 항목만 묻는다.

- 흐름 그룹 1개 이상 존재 시: 접속 주소
- `## 기반 데이터` 섹션에 `(SQL)` 적재 그룹 존재 시: DB 연결 정보
- `## 기반 데이터` 섹션에 `(API)` 적재 그룹 존재 시: 인증 계정 정보

CRITICAL: 접속 주소를 임의로 결정하지 않는다 (`http://localhost:XXXX` 추측 금지). 반드시 사용자에게 묻는다.

### 명확화 적용

수집 항목 요청은 `sd-clarify` 지침을 따른다. 한 번에 하나씩, `sd-ask`의 선택지 제시 형식으로 제시한다.

### sit.md 갱신

수집 완료 후 sit.md "참조 자료" 섹션 직후에 "환경 정보" 섹션을 추가한다.

````markdown
## 환경 정보

- 접속 주소: {수집한 값}
- DB 연결: {수집한 값 — `(SQL)` 적재 그룹 존재 시}
- 인증 계정: {수집한 값 — `(API)` 적재 그룹 존재 시}
````

## Step 7: 다음 단계 안내

SIT 문서 작성 완료 후 다음 단계를 안내한다.

```
/sd-sit {sit.md 경로}
```
