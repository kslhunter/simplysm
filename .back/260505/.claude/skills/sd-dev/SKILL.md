# sd-dev: 통합 개발 프로세스

sd-wbs → sd-plan → sd-tdd → sd-check → sd-review를 순차 진행하는 오케스트레이터.
**CRITICAL**: 명시된 상황이 아닌 경우, Step 간 진행을 절대 멈추지 않는다.

## Step 진입·종료 규약

Step 4 진입 직전 다음 4개 Task를 `TaskCreate`로 등록하고 Task 1을 `in_progress`로 마킹한다.

1. `Step 4: sd-tdd`
2. `Step 5: sd-check` (변경 파일 모두 문서/설정이면 호출 없이 즉시 `completed`)
3. `Step 6: sd-review`
4. `Step 7: 완료 보고`

각 Step 종료 직후 같은 턴에서 현재 Task `completed` + 다음 Task `in_progress` 마킹 후 즉시 다음 Step 첫 도구 호출을 발생시킨다. `in_progress` Task가 남은 동안 사용자 응답 대기 금지.
Step 4·5·6 출력 마지막 줄은 `→ Step N+1 진입`.

## Step 1: 입력 분기

인자에 따라 시작 Step을 결정한다. (인자가 없는 경우 대화에서 유추)

| 입력                             | 시작 Step                                                                      |
| -------------------------------- | ------------------------------------------------------------------------------ |
| wbs 경로만 (추가 요청 없음)      | → `/sd-dev {wbs경로} {Task번호}` 안내 후 **종료**                              |
| wbs 경로만 (추가 요청 있음)      | → Step 2 (sd-wbs 업데이트)                                                     |
| wbs + Task 번호                  | → Step 3 (sd-plan)                                                             |
| Task 문서 경로                   | → Step 4 (sd-tdd). Slice 체크박스(`[x]`/`[ ]`)를 확인하여 진행 상태를 복원한다 |
| 그 외 (자연어 요청, 참고자료 등) | → Step 2 (sd-wbs)                                                              |

## Step 2: sd-wbs

`/sd-wbs` 스킬을 즉시 수행한다. 완료 후:

- **Task 2개 이상** → `/sd-dev {wbs경로} {첫 Task 번호}` 안내만 하고 **종료**
- **단일 Task** → 즉시 Step 3 진행

## Step 3: sd-plan

`/sd-plan` 스킬을 즉시 수행한다.
단, Task 문서의 Scenario 수가 2개를 초과하면 Step 4~7을 모두 스킵하고 `/sd-dev {Task파일경로}`로 새 세션에서 진행하도록 안내 후 즉시 종료한다. 이 경우 Step 7 완료 보고는 출력하지 않는다.

## Step 4: sd-tdd

`Step 진입·종료 규약`에 따라 TaskCreate 4개를 등록하고 Task 1을 `in_progress`로 마킹한다.
`/sd-tdd` 스킬을 즉시 수행한다.

## Step 5: sd-check

sd-tdd Step 3-4 `변경 사항 요약`의 `변경 파일 목록`이 비어 있거나 모두 문서/설정 파일(`.md`, `.json` 등)이면 이 단계를 스킵한다.

`변경 패키지` 목록을 인자로 전달하여 `/sd-check`를 즉시 호출한다.

예: `/sd-check core-common angular`

## Step 6: sd-review

Task 문서 경로를 인자로 전달하여 feature 구현이 plan대로 되었는지 리뷰한다. sd-tdd Step 3-4 `변경 파일 목록`은 `변경 파일:` 후미에 명시하여 리뷰 대상을 좁힌다.

예: `/sd-review {Task 문서 경로}가 잘 구현되었는지, 문제는 없는지 리뷰. 변경 파일: {변경 파일들}`

sd-review 보고에 확정 이슈가 없으면 이 단계를 스킵하고 Step 7로 진행한다.

확정 이슈가 있으면:

1. 보고된 이슈를 `.claude/skills/sd-tdd/references/slice-tdd-guide.md`에 따라 메인이 직접 수정한다.
2. 수정 완료 후 `/sd-check` 스킬을 1회 호출하여 회귀가 없는지 확인한다.

수정 내역과 미수정 건은 Step 7 완료 보고의 `리뷰 수정 건` / `리뷰 미수정 건` 섹션에 반영한다.

## Step 7: 완료 보고 양식

모든 단계 완료 후, 아래 양식으로 실행 결과를 대화에 출력한다.

```
## 완료 보고

- **WBS**: {wbs 파일명}
- **Task**: {번호} - {Task 제목} ({Task 파일명})

### 사용자 결정사항
- {결정 내용 요약}

### 리뷰 수정 건
- {수정 내용 한줄 요약}

### 리뷰 미수정 건
- {미수정 내용 한줄 요약} — 사유: {사유}

### 변경 파일
- {파일 경로 목록}

<!-- 아래 두 섹션 중 조건에 맞는 정확히 하나만 출력한다 -->

### 남은 Task  <!-- 미완료(`[ ]`) Task가 1개 이상일 때만 출력 -->
- {번호} {제목} (의존성: {있으면 명시})

### 최종 리뷰 안내  <!-- 모든 Task가 완료(`[x]`)일 때만 출력 -->
`/sd-review {wbs디렉토리경로}/*.md 가 잘 구현되었는지, 문제는 없는지 최종 심층 리뷰`
```

완료 보고 출력 직전에 **반드시(MUST) wbs.md의 현재 상태를 다시 읽어** Task 체크박스(`[x]`/`[ ]`)를 확인한 뒤, 위 두 섹션 중 조건에 맞는 정확히 하나만 출력한다.

- 다시 읽지 않으면 이전 단계에서 변경된 상태가 반영되지 않아 중복 수행 문제가 발생할 수 있다.

**NEVER:** 미완료(`[ ]`) Task가 1개라도 남아 있으면 `/sd-review`를 어떤 형태로도(조건부·제안·예시 포함) 언급하지 않는다. "모든 Task가 끝난 뒤 /sd-review를 권장" 같은 조건부 안내도 금지한다.

완료 보고 출력 직후 TaskCreate Task 4(`Step 7: 완료 보고`)를 `completed`로 마킹하고 종료한다.
