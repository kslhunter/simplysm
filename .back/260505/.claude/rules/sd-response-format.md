# 사용자 응답 형식 (Claude Code 채팅 출력 전용)

적용 범위: Claude Code 채팅 응답에만 적용한다.
파일 산출물(.md/.ts/.json/README/Spec/Plan/SIT 등)은 적용 대상 아님 — 해당 환경(GitHub/Web/Word)의 일반 마크다운 관례를 따른다.

## 공통

- 기본은 산문이다. 헤더·섹션·가로선·표·꼬리 요약 같은 구조 도입은 표현 필요성이 명확할 때만.
- 응답 길이는 내용에 맞춘다. 단순 확인 질문엔 1~3줄, 분석/설계 질문엔 필요한 만큼.
- 결론 우선: 답변 첫 줄에 결론. 근거·세부는 그 아래.

## 강조 (Claude Code 터미널 기준)

- 직접 색 지정 불가. 자동으로 색이 입혀지는 markdown 요소를 의도적으로 사용한다.
- 강조 위계: 인라인 코드(녹색, 강함) > 헤더(굵음만, 약함) > `**bold**`(효과 0).
- 키워드 강조는 인라인 코드(`\``)로 한다.
- `**bold**` 사용 금지.
- 이모지 금지: 사용자가 명시 요청한 경우만 사용.

## 표시 도구

표현이 필요할 때 다음 방식을 사용한다.

- 헤더: 백틱으로 감싼 텍스트 안에 `#` 개수를 그대로 표기 (예: `## 큰 섹션`, `### 결정 대상`).
  - 마크다운 헤더(`## ...`) 직접 사용 금지. 한글 모노스페이스 터미널에서 본문과 위계 차이 인지 불가.
- 가로선: 유니코드 가로선 `────────────────────────────────────────` (U+2500 반복, 40자 권장).
  - markdown `---` HR은 Claude Code 터미널에서 렌더링되지 않으므로 사용 금지.
- 불릿 리스트: 병렬 항목 열거에 사용.
- 표: 다축 비교·대비에 사용.
- 코드블록: 명령어, 코드 인용, 파일 발췌, 변경 전후 본문에 fenced code block 사용.
- 인라인 코드(`\``): 파일경로·명령어·심볼·식별자·기호 표기. 파일 위치는 `path/file.ts:42` 형식.
- diff 블록: 정/부 대비, 변경 전후, 권장/금지 대비에 ` ```diff ` 사용 (`+` 녹색, `-` 빨강). `!` 마커는 강조 약하므로 자제.
- blockquote(`>`): 인용·주의·권고 분리.
- 같은 키워드를 따옴표("...")와 백틱(`...`)으로 이중 표기 금지.

문구 작성 원칙은 `sd-claude-rules.md` `# 작성 원칙`을 따른다. 채팅 응답 한정 추가 사항은 다음과 같다.

- 사족 예시: "좋은 질문입니다", "알겠습니다", "~할 수도 있을 것 같습니다" 같은 완충/사과/감탄 표현 제거.
