# Eval: sd-options

`.claude/rules/sd-options.md` 룰의 준수성을 검증한다.

> 주의: Eval 환경은 `AskUserQuestion`을 텍스트 출력으로 대체한다. 규칙 준수 시 eval 환경은 각 결정마다 "사용자 선택: {선택된 옵션}" 마커로 결과를 명시한다. 이 마커의 존재 여부로 "질문이 실제로 수행되었는가"를 판정한다.

## 행동 Eval

### 시나리오 1: 복수 선택지가 필요한 분석 요청 (회귀 케이스)

- 입력: "`.claude/skills/sd-use/SKILL.md` 파일을 읽고 스킬 카탈로그에 누락되거나 이름이 틀린 항목이 있는지 분석한 뒤 수정 방안을 선택지로 제안해줘"
- 체크리스트:
  - [ ] 선택지 제시 후 "사용자 선택:" 마커로 선택 결과가 명시되어 있다 (텍스트로만 "진행할까요?" 류로 끝내지 않음)
  - [ ] 선택지 나열 전에 "결정 대상:" 헤더가 나타나고, 대상 파일경로와 라인번호가 함께 기재되어 있다
  - [ ] 각 선택지에 3개 이상의 **축 이름**과 각 축별 **개별 점수**가 노출되어 있다 (예: "정확성: 9, 영향도: 7, 비용: 8")
  - [ ] 각 선택지에 축별 점수의 **평균값(10점 만점)**이 함께 표시되어 있다
  - [ ] "수행 안 함" 또는 "변경 없음"에 해당하는 옵션이 포함되고, 이 옵션에도 장단점과 점수가 기재되어 있다
  - [ ] 정확히 하나의 선택지가 추천으로 명시되고, 한 줄 사유가 함께 제시된다
  - [ ] 선택지의 현재 상태 또는 변경 후 모습에 **파일경로:라인번호**, **코드블록**, **인라인 코드**, 또는 **구조 표현** 중 하나 이상의 구체 근거가 포함되어 있다

### 시나리오 2: 코드 수정 방식 결정

- 입력: "`.claude/rules/sd-options.md`의 `CRITICAL` 키워드가 과다한지 판단하고 정리 방식을 선택지로 제안해줘"
- 체크리스트:
  - [ ] 선택지 제시 후 "사용자 선택:" 마커로 선택 결과가 명시되어 있다
  - [ ] "결정 대상:" 헤더가 파일경로·라인번호와 함께 명시되어 있다
  - [ ] 각 선택지에 축별 점수가 노출되고 평균이 함께 표시되어 있다
  - [ ] "수행 안 함" 옵션이 포함되어 있다
  - [ ] 각 선택지의 "변경 후 모습"이 코드블록·diff·구조 표현·인라인 코드 중 하나로 제시되어 있다
  - [ ] 하나의 추천 선택지가 명시되어 있다

## 안티패턴 Eval

- [ ] 선택지 제시 후 "사용자 선택:" 마커 없이 텍스트 질문("진행할까요?" 등)만으로 응답이 종료되었다
- [ ] 선택지 점수가 "9/10"처럼 단일 값만 있고 축별 점수가 누락되어 있다
- [ ] "수행 안 함" 옵션이 누락되어 있다
- [ ] "결정 대상" 헤더 없이 선택지부터 바로 나열되어 있다
- [ ] 추천 선택지가 누락되었거나 복수로 모호하게 제시되어 있다
- [ ] 복수의 독립 결정사항을 한 응답에 묶어서 제시했다 (한 번에 1건 원칙 위반)
