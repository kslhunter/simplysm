# impl.md 템플릿

위치: `.specs/{yyMMdd_HHmmss}/REQ-XXX-슬러그/impl.md`

## 템플릿

```markdown
# REQ-001-슬러그 / Implementation

## 메타
- 상태: implementing | implemented
- 생성일: YYYY-MM-DD
- 마지막 갱신: YYYY-MM-DD

## R 단위 구현 결과

### R1: <요구 제목>
- **상태**: 진행중 | 완료 | 막힘 | 보류
- **모드**: TDD | 사후 | 생략
- **변경 파일**:
  - `<파일경로>`
    - 변경 함수: `<함수/컴포넌트명>`
    - 변경 종류: 추가 | 수정 | 삭제 | 신설
- **테스트**:
  - 추가/수정: `<테스트 파일>`
    - 케이스: <케이스 이름들>
    - 결과: PASS / FAIL
- **plan 대비 차이**: 없음 | <차이 설명>
- **변경 의도**: spec.md R1 + plan.md R1 그대로 | <사유>
- **이슈/결정**: (있을 때만) <막힘/시도/결정 기록>
```

## 섹션별 역할

| 섹션 | 용도 |
|---|---|
| `## 메타` | 상태 |
| `## R 단위 구현 결과` | R별 상태/모드/변경/테스트/차이/의도 인라인 통합 |

## R 항목 내부 요소

| 요소 | 의미 |
|---|---|
| **상태** | `완료` / `진행중` / `막힘` / `보류` (종료 시엔 모두 `완료`) |
| **모드** | TDD / 사후 / 생략 |
| **변경 파일** | 파일 경로 + 변경 함수 + 변경 종류 (라인 번호 X) |
| **테스트** | 추가/수정 테스트 + 케이스 + 결과 |
| **plan 대비 차이** | 계획 vs 실제 (verify가 활용) |
| **변경 의도** | 자명하면 "그대로", 자명하지 않으면 사유 |
| **이슈/결정** | (있을 때만) 막힘 상황, 시도 횟수, 결정 |

`plan 대비 차이`가 "없음"이 아니거나 `이슈/결정`에 결정이 발생한 경우, 결정 출처를 `근거:` 줄로 명시한다.

## 예시

```markdown
### R1: 입고지시서 화면에 "긴급" 체크박스 추가
- **상태**: 완료
- **모드**: 사후 테스트
- **변경 파일**:
  - `src/pages/InboundOrder.tsx`
    - 변경 함수: `InboundOrderForm`
    - 변경 종류: 추가 (Checkbox 컴포넌트, formState.urgent 연동)
- **테스트**:
  - 추가: `src/pages/InboundOrder.test.tsx`
    - 케이스: "체크박스 클릭 → 저장 → 재조회 시 상태 유지"
    - 결과: PASS (1/1)
- **plan 대비 차이**: 없음
- **변경 의도**: spec.md R1 + plan.md R1 그대로

### R3: 권한 체크 추가
- **상태**: 완료
- **모드**: TDD
- **변경 파일**:
  - `src/contexts/PermissionContext.tsx` (신설)
- **테스트**:
  - 추가: `src/contexts/PermissionContext.test.tsx`
    - 케이스: "권한 있는 사용자 → true" / "권한 없는 사용자 → false"
    - 결과: PASS (2/2)
- **plan 대비 차이**: PermissionContext 신설 (plan은 기존 hasPermission 가정)
  - 근거: 사용자 답변 (2026-05-04)
- **이슈/결정**:
  - 이슈: hasPermission 패턴이 사용 안 되고 있음 발견
  - 시도: 1회
  - 결정: PermissionContext 신설
    - 근거: 사용자 답변 (2026-05-04)
```
