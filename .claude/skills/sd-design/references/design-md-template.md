## 화면 작성 규칙

- **3슬롯 항상 작성**: 기능개요·항목·동작. demo 유무와 무관.
- **와이어프레임 슬롯**: demo 있음 → `demo.md 참조` 한 줄. demo 없음 → 텍스트 ASCII 직접 작성.
- **추측·플레이스홀더 금지**: 4슬롯(와이어프레임/기능개요/항목/동작) 작성 중 정보 부족·모호 시 사용자에게 1건씩 질문.

### 항목 구분 어휘

- 입력류: `텍스트 입력` / `암호 입력` / `숫자 입력` / `날짜 입력` / `일시 입력`
- 표시류: `텍스트 표시` / `숫자 표시` / `일시 표시` / `색상 표시`
- 선택류: `목록 선택` / `체크 선택`
- 동작: `버튼`

### 동작 슬롯 룰

- `절차` 의무. `부수효과` / `예외` 는 비어 있으면 슬롯 생략.
- 검증 단계는 `절차` 에 녹여 표기 (별도 슬롯 X).
- 부수효과·예외는 `[모델.X]` · `[외부인터페이스.X]` 참조로 연결.
- `story-map.md` Business Flow 의 한 단계와 1:1 매핑되는 동작이면 부수효과는 `→ Business Flow.<프로세스명>.<단계> 부수효과` 참조로 갈음 가능.
- 구현 어휘 금지 ("DB row 삭제" X) — 비즈니스 어휘 (`[모델.X]` 상태 변경 등).

## Detailed Design 가이드 (UI 외)

| 성격 | 설계 내용 |
|---|---|
| **API** | 엔드포인트 / 요청·응답 스키마 / 에러 케이스 / 인증·권한 |
| **Data Model** | 스키마 변경 / 마이그레이션 / 기존 데이터 처리 |
| **외부 연동** | 호출 시퀀스 / 실패·재시도·타임아웃 / 멱등성 |

## 예시

### 단순 동작 (로그인)

```
**기능 개요**
- 사용자 로그인

**항목**
| 명칭 | 구분 | 필수 | 설명 |
|---|---|---|---|
| 아이디 | 텍스트 입력 | O | |
| 비밀번호 | 암호 입력 | O | |
| `[로그인]` | 버튼 | - | 인증 시도 |

**동작**
- `[로그인]` 클릭:
  - 절차:
    1) 아이디·비밀번호로 인증 시도
    2) 성공 시 대시보드로 이동
  - 예외:
    - 인증 실패 → 상단 에러 메시지 표시
```

### 복합 동작 (거래처 마스터 삭제)

```
**동작**
- `[삭제]` 클릭:
  - 절차:
    1) 선택 행 확인 다이얼로그
    2) [모델.거래처] 와 연관된 [모델.입고지시] 존재 검증
    3) [모델.거래처.상태] → `사용중지`
    4) [외부인터페이스.거래처마스터동기화] 호출
  - 부수효과:
    - [모델.거래처.상태] 변경
    - ERP 통보 발생 ([외부인터페이스.거래처마스터동기화])
  - 예외:
    - 연관 입고지시 존재 시 → "사용 중인 거래처는 삭제할 수 없습니다" 표시 후 차단
    - ERP 통보 실패 → 상태 변경 롤백, "ERP 동기화 실패" 표시
```
