```markdown
- **시연** (필요 R만): 시나리오(plan.md 출처) → 결과 (도구·환경 실패 시 "미수행 — <사유>" 명시, 부분충족 처리)
- **의도 부합**: 사용자 확인됨 ✅ | 부분충족 (<사유>)

- 전체 테스트: PASS (N/M)
- 영향 페이지: <파일경로> 정상/문제
```

## 섹션 역할

| 섹션 | 용도 |
|---|---|
| 메타 | 상태 |
| 충돌·누락 | REQ 차원 통합 발견 (양방향 + 모순) + 처리 Q |
| R 단위 검증 | R별 코드 분석 + 테스트 + 시연 + 판정 |
| 통합/E2E 검증 | R 간 흐름 |
| 회귀 검증 | 전체 테스트 + 영향 페이지 |

## 작성 원칙

- 충돌·누락은 **다 읽고 발견된 것만** 자연어로. 페어 매트릭스 채우기 X.
- 발견 0건이면 "발견 없음" 한 줄.
- R 단위는 R마다 독립 블록 (검증/시연/판정 인라인).

## 예시

```markdown
## 충돌·누락

### 문서 미업데이트
- 코드 `RTPInputForm`에 캐시 무효화 호출 추가됐으나 spec/plan에 근거 없음
- impl.md R3 변경 파일 목록에 `src/api/rtp.ts` 누락 (실제 코드는 변경됨)

### 놓친 구현·문서화
- spec R3가 plan에 미매핑 → 코드도 미반영
- overview.md 의존성과 spec.md 메타 의존성 어긋남 (REQ-002 의존이 overview에만)

### 단계 간 모순
- plan.md R2는 컴포넌트 분리, 코드는 단일 파일

### 처리 Q
- [ ] **Q1**: 캐시 무효화 — (a) spec 재진입 R 추가 / (b) 코드 제거. 어느 쪽?
- [ ] **Q2**: R3 — (a) plan 재진입 / (b) spec 재진입 (재정의/폐기). 어느 쪽?
- [ ] **Q3**: overview ↔ spec 의존성 — 어느 쪽이 진실?
- [ ] **Q4**: R2 분리 vs 단일 — 어느 쪽이 진실? 결정 후 plan 또는 implement 재진입.

### R1: 입력 필드 X 추가
- **충족 여부**: 충족
- **코드 분석**: spec R1 의도 + plan 위치(`src/pages/RTPInput.tsx`) ↔ 코드 일치
- **테스트 실행**: 3 케이스 PASS, impl.md 일치 ✓
- **시연**: X 입력 → 저장 → 새로고침 → 값 유지 (plan.md R1) → OK
- **의도 부합**: ✅

### R2: 헤더 재배치
- **충족 여부**: 부분충족
- **코드 분석**: plan 위치 ↔ 코드 일치, 우중앙 배치 확인
- **시연**: 화면 진입 → 헤더 위치 확인 → 우중앙 OK, **모바일 깨짐**
- **의도 부합**: 부분충족 (모바일 미고려)
- [ ] **Q**: (a) implement 재진입 — 반응형 추가 / (b) spec 재진입 — 모바일 미지원 명시. 어느 쪽?
```
