# verify 단계

spec.md + impl.md + 실제 코드 → 제3자 시각 검증. 자동 검증(코드 분석/테스트/회귀 검증) + 사용자 시연/판정 결합 (human-in-the-loop).

## 산출물

```
.specs/{yyMMddHHmmss}/REQ-XXX-슬러그/
  spec.md / plan.md / impl.md   ← 입력
  verify.md                     ← 본 단계 산출물
```

## 워크플로

1. 입력: 대상 REQ ID

2. 읽기: spec.md + impl.md + 코드베이스 (+ raw input 재참조)

3. **자동 검증** (모든 R)
   - **코드 분석**: spec.md R 의도가 실제 코드에 반영됐는지 확인 (impl.md "변경 위치/방식"이 코드에 있는지 검증 — impl.md 거짓말 검증)
   - **테스트 실행**: impl.md의 테스트 케이스 직접 실행 + 결과 ↔ impl.md 보고 비교
   - **회귀 검증**: 전체 테스트 실행 (implement에서 했어도 다시. 제3자 시각)
   - 미충족 발견 시 → verify.md 기록 + Q (재진입 절차)

4. **시연 필요 R 목록 정리** (plan 모드 기준)
   - TDD: 시연 불필요
   - 사후 / 생략: 시연 필수

5. **사용자 시연** (필요 R만, 한 번에 하나씩)
   - 시나리오 출처: plan.md R별 테스트 케이스 + 통합/E2E 케이스 (verify가 새로 정의 X)
   - 사용자가 직접 동작 확인 → 결과 보고
   - verify.md `시연` 섹션에 기록
   - 미충족 발견 시 → Q (재진입 절차)

6. 모든 R 충족 → 체크포인트 (메타 `상태: verified`, `최근 체크포인트`. spec.md 메타 `상태: done`)

## 충족 판정 (3단계)

| 분류 | 의미 |
|---|---|
| **충족** | spec R 의도 완전 만족 |
| **부분충족** | 일부 sub-criteria만 만족 (어느 부분 미충족인지 명시 필수) |
| **미충족** | 만족 X |

종료 시점엔 모든 R `충족`. 부분/미충족은 재진입으로 해소되어야.

## 미충족 처리 (재진입 단계 3가지)

| 재진입 대상 | 발생 케이스 |
|---|---|
| **implement 재진입** | 코드 수정으로 해결 가능 (누락 코드, 버그 등) |
| **plan 재진입** | 변경 계획 부족 (위치 틀림, 다른 파일 추가 필요) |
| **spec 재진입** | R 정의 자체가 잘못 (의도 표현 오해, R 충돌) |

재진입 단계 결정은 **자동 판단 금지**. verify가 후보 제시 → 사용자 확정.

```
"R3 부분충족 - 검증 로직 누락. implement 재진입 권장. 동의?"
```

## 시연 필요 여부 (plan 모드 기준)

| plan 모드 | 시연 |
|---|---|
| TDD | 자동 테스트로 충족, **불필요** |
| 사후 테스트 | **필수** (UI 시각 확인) |
| 생략 | **필수** (자동 테스트 없음, 수동 검증) |

## 핵심 원칙

- self-contained 블록 (R 블록 안에 검증/시연/판정 인라인)
- raw input 불변
- ID 불변
- 자동 판단 금지 (재진입 단계는 사용자 선택)
- **human-in-the-loop** (자동 검증 한꺼번에, 사용자 시연 묶음)

## 안티패턴

- ❌ impl.md 보고를 그대로 신뢰 (테스트 직접 실행 안 함) — verify의 의의 무력화
- ❌ 시연 시나리오를 verify가 새로 정의 (plan.md/impl.md 활용)
- ❌ 재진입 단계를 에이전트가 자동 결정
- ❌ TDD 모드 R에 사용자 시연 강요
- ❌ 사후/생략 모드 R에 시연 생략
- ❌ 미충족 R 있는 채로 REQ done 처리
