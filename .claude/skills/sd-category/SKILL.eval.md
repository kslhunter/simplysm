# Eval: sd-category

## 행동 Eval

### 시나리오 1: 도서관 통합 시스템 신규 분해

- 입력: "/sd-category 중견 도서관 통합 시스템을 새로 구축. 회원 가입·관리, 도서 등록·검색·대출·반납·예약, 통계 리포트, 결제(연체료/유료 회원권), 푸시알림, 외부 도서 API 연동(국립중앙도서관 등). 조직: 사서 5명 + 관장 1명, 회원 2만명."
- 성공 행동:
  - [ ] `.tasks/{ts}_*/category-map.md` 형식의 산출물 파일이 생성된다
  - [ ] 산출물에 카테고리 헤더(`### 1.`, `### 2.` 등) 형태의 평탄 구조가 있다 (다단 ID 사용 금지)
  - [ ] 모든 카테고리 이름이 `~~ 관리`·`~~ 영역` 형식의 큰 묶음이다 (`가입`·`대출`·`반납` 같은 단일 액션 이름 금지)
  - [ ] 각 카테고리에 `**1줄 설명:**`/`**핵심 액터:**`/`**포함 활동:**`/`**인접 카테고리:**`/`**인용 근거:**` 필드가 작성된다
  - [ ] 산출물에 분류 라벨(`Core`/`Supporting`/`Generic`)·차별화 점수·복잡도 점수·Tune 패턴·Vision Statement·상대성 근거가 등장하지 않는다
  - [ ] `## 의존성 매트릭스` 섹션이 존재하고, 의존 대상이 `없음`인 카테고리가 최소 1개 있다
  - [ ] `## 수행 순서 안내` 섹션이 존재하고 의존성 기반 단계별 묶음 형태가 포함된다
- 보조 assertion:
  - [ ] 산출물 파일이 `.tasks/` 하위 경로에 존재한다
  - [ ] 의존성 매트릭스가 Markdown 표(`| 카테고리 | 의존 대상 |` 헤더) 형식으로 작성된다
- Judge rubric:
  - PASS: 모든 성공 행동 PASS + 안티패턴 0건
  - FAIL: 성공 행동 1개 이상 FAIL 또는 안티패턴 1건 이상 발생

## 안티패턴 Eval

각 항목은 *"발견되면 FAIL"* 인 행동 목록이다. 항목이 산출물·실행 로그에서 발견되지 않으면 PASS.

- [ ] 산출물에 다단 ID(`1.1`, `1.1.1` 형태) 또는 그 헤더(`#### 1.1` 등)가 포함된다
- [ ] 카테고리 이름이 단일 액션 형태(`회원 가입`/`도서 대출`/`도서 반납`/`도서 등록`/`연체 처리` 등)로 작성된다
- [ ] 카테고리 이름에 `Backend`/`Frontend`/`Admin`/`User`가 분류 기준으로 등장한다
- [ ] catch-all 이름(`기타`/`공통`/`Utility`/`Common`/`Misc`)이 카테고리 이름으로 사용된다
- [ ] 산출물 본문에 DDD 분류 어휘(`Core`/`Supporting`/`Generic`/`Subdomain`/`Bounded Context`/`Tune 패턴`/`Vision Statement`)가 등장한다
- [ ] sd-wbs 본체(`.claude/skills/sd-wbs/SKILL.md`)가 수정된다
- [ ] sd-dev 본체(`.claude/skills/sd-dev/SKILL.md`)가 수정된다
- [ ] 산출물 본문에 `추후 결정`/`협의 필요`/`별도 확정`/`미확정`/`보류` 같은 미루기 표현이 있다
- [ ] 산출물 본문에 `아마도`/`추정`/`보임`/`예상`/`가정` 같은 추측·잠정 표현이 있다 (명확화 미통과 항목)
