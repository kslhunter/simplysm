# Eval: sd-sit-plan

## 행동 Eval

### 시나리오 1: sd-* 산출물(wbs.md) 입력 — 정상 흐름

- 사전 조건: workspace에 `.tasks/library/wbs.md`가 다음 내용으로 사전 배치된다 (sd-wbs 산출물을 모사). 그 외 코드베이스는 존재하지 않는다.

  ````markdown
  # WBS: 도서관 도서 관리 시스템

  ## 프로젝트 개요

  - **배경:** 도서관에서 도서 분실 방지 및 관리 효율화를 위해 도서 관리 시스템을 도입한다.
  - **환경:** 사서 1인, 회원 약 200명 규모의 소규모 도서관.
  - **전제조건:** 사서 계정과 회원 계정이 사전에 발급된다.
  - **기술적 제약:** 없음.
  - **참조 자료:** 없음.

  ## Impact Mapping

  - **Goal:** 도서 분실을 방지하기 위해 등록·검색을 시스템으로 관리한다.
    - **Actor:** 사서
      - **Impact:** 도서를 시스템에 등록하여 자산 현황을 파악한다.
        - **Deliverable:** 도서 등록 화면
    - **Actor:** 회원
      - **Impact:** 시스템에서 도서를 검색하여 원하는 책을 찾는다.
        - **Deliverable:** 도서 검색 화면

  ## USM Backbone

  ### Activity 1. 도서 관리

  #### [ ] Task 1.1 도서 등록

  **의존성:** 없음

  **경계:**

  - 도서 표지 이미지 업로드는 이 Task에서 다루지 않음

  **근거:**

  - Impact Mapping Deliverable: "도서 등록 화면"
  - 사용자 답변: "사서가 도서를 직접 등록한다"

  **Stories:**

  ##### Story 1.1.1 도서 정보 등록

  - 사서가 도서명·저자·ISBN을 입력하여 도서를 등록한다. (근거: Impact Mapping Deliverable "도서 등록 화면")

  ##### Story 1.1.2 필수값 누락 차단

  - 도서명·저자·ISBN 중 하나라도 누락되면 등록되지 않고 사서에게 누락 항목이 표시된다. (근거: 사용자 답변 "필수 항목 누락 시 차단")

  #### [ ] Task 1.2 도서 검색

  **의존성:** 1.1

  **경계:**

  - 정렬·필터 기능은 이 Task에서 다루지 않음

  **근거:**

  - Impact Mapping Deliverable: "도서 검색 화면"
  - 사용자 답변: "회원이 도서명으로 검색한다"

  **Stories:**

  ##### Story 1.2.1 도서명 검색

  - 회원이 도서명을 입력하여 도서를 검색한다. (근거: Impact Mapping Deliverable "도서 검색 화면")

  ##### Story 1.2.2 빈 결과 표시

  - 검색 결과가 없으면 회원에게 빈 결과 안내 메시지가 표시된다. (근거: 사용자 답변 "빈 결과는 안내 메시지 표시")

  ## 제외 사항

  - 도서 표지 이미지 업로드 — 사유: 사용자 명시적 제외 / 출처: 사용자 답변 / 재검토 조건: 별도 UX 요구 시
  - 도서 대출/반납 — 사유: 범위 초과 / 출처: 사용자 답변 / 재검토 조건: Phase 2

  ## 의존성 매트릭스

  | Task | 의존 대상 |
  |------|----------|
  | 1.1  | 없음     |
  | 1.2  | 1.1      |
  ````

- 입력: "/sd-sit-plan .tasks/library/wbs.md"

- 성공 행동:
  - [ ] 산출 SIT 문서가 wbs.md와 같은 디렉토리(`.tasks/library/`)에 `sit.md` 파일명으로 신규 생성된다.
  - [ ] sit.md 본문에 Task 1.1과 Task 1.2가 각각 별도 섹션으로 그룹핑되어 등장한다 (예: `## Task 1.1`·`## Task 1.2` 또는 동등 헤더).
  - [ ] 각 Task 섹션 안에 Story 단위 하위 섹션(예: `### Story 1.1.1` 등)이 등장한다.
  - [ ] 모든 검증 항목이 `- [ ] {항목명}` 마크다운 체크박스 형식으로 작성된다.
  - [ ] Story 1.1.1·Story 1.1.2·Story 1.2.1·Story 1.2.2 각각 1개 이상의 SIT 체크박스 항목으로 도출된다.
  - [ ] WBS의 정량/열거 정보(도서명·저자·ISBN 필수, 누락 항목 표시, 빈 결과 안내 메시지)가 SIT 항목 본문에 의역 변형 없이 반영된다.
  - [ ] 데이터 시드 / 메뉴 진입 / CRUD 흐름 / 매트릭스·결과 검증 등 단계 분리 헤더(또는 동등 식별자)가 sit.md 본문에 1개 이상 등장한다 (이슈 #30 명시).
  - [ ] run-output.json의 응답 흐름에 Step 5 격리 검증을 Agent tool 호출로 수행한 흔적(검증 보고서 인용 또는 검증 결과 반영 처리)이 등장한다.

- 보조 assertion:
  - [ ] `.tasks/library/sit.md` 경로에 파일이 실재한다.
  - [ ] `tests/sit/` 디렉토리가 새로 생성되지 않는다.
  - [ ] sit.md 본문에 `Task 1.1`, `Task 1.2`, `Story` 식별자가 등장한다.
  - [ ] sit.md 본문에 입력 범위 외 항목(예: 도서 대출/반납·도서 표지 이미지 — 제외 사항)이 SIT 체크박스로 등장하지 않는다.

- Judge rubric:
  - PASS: wbs.md 디렉토리에 sit.md가 생성되고, Task 단위 섹션 + Story 단위 하위 섹션 + 체크박스 형식이 모두 충족된다. 정량/열거 정보가 의역 변형 없이 반영되며, 단계 분리 헤더가 1개 이상 등장한다. tests/sit/ 등 다른 경로에 산출물이 생기지 않으며, 제외 사항이 SIT 항목으로 혼입되지 않는다.
  - FAIL: 출력 위치 위반(`tests/sit/` 등), 체크박스 형식 위반(`* `, `1.`, `[ ]` 단독 등), Task/Story 그룹핑 누락(평면 체크리스트), 정량/열거 정보 의역 변형(예: "도서명·저자·ISBN"→"필수 항목들"), Story 1.1.1·1.1.2·1.2.1·1.2.2 중 하나라도 SIT 항목 누락, 단계 분리 헤더 0개, 제외 사항(대출/반납·표지 업로드) 혼입 중 하나라도 해당.

### 시나리오 2: 자연어 입력 — 자유 입력 처리

- 사전 조건: workspace에 `.tasks/` 디렉토리·기존 SIT 문서가 존재하지 않는다.
- 입력: "/sd-sit-plan 도서 등록 메뉴 SIT 만들어줘. 도서명·저자·ISBN을 입력받고, 필수값 누락 시 입력이 차단되어야 함. 등록된 도서는 목록 화면에서 확인 가능."

- 성공 행동:
  - [ ] `.tasks/{12자리 timestamp}_{topic}/sit.md` 형식의 신규 디렉토리·파일이 생성된다 (timestamp는 yyMMddHHmmss 12자리 숫자).
  - [ ] 사용자 입력에 등장한 항목(도서명·저자·ISBN 입력, 필수값 누락 차단, 목록 화면 확인)이 SIT 체크박스로 빠짐없이 반영된다.
  - [ ] 모든 검증 항목이 `- [ ] {항목명}` 체크박스 형식으로 작성된다.
  - [ ] 데이터 시드 / 메뉴 진입 / CRUD 흐름 등 단계 분리 헤더가 sit.md 본문에 1개 이상 등장한다.

- 보조 assertion:
  - [ ] 산출 디렉토리명이 `^[0-9]{12}_[a-z0-9-]+$` 패턴을 만족한다.
  - [ ] sit.md 본문에 도서명·저자·ISBN 키워드가 의역 없이 등장한다.
  - [ ] `tests/sit/` 디렉토리가 새로 생성되지 않는다.

- Judge rubric:
  - PASS: `.tasks/{timestamp}_{topic}/sit.md` 형식 산출물이 생성되고, 입력 항목(도서명·저자·ISBN 입력, 필수값 누락 차단, 목록 확인) 3건이 모두 체크박스로 반영되며 형식 준수, 단계 분리 헤더 1개 이상 등장.
  - FAIL: 출력 경로 위반, 입력 항목 1건 이상 누락, 체크박스 형식 위반, 의역 변형(예: "도서명·저자·ISBN"→"기본 정보"), 단계 분리 헤더 0개 중 하나라도 해당.

### 시나리오 3: 정보 부족 입력 — 명확화 시도

- 사전 조건: workspace 비어 있음.
- 입력: "/sd-sit-plan SIT"

- 성공 행동:
  - [ ] 자료가 부족함을 인지하고 추가 정보 요청 또는 sd-clarify 형식의 명확화 시도를 수행한다 (텍스트로 질문/요청 출력).
  - [ ] 임의로 가짜 SIT 문서(workspace 어디에도)를 신규 생성하지 않는다.

- 보조 assertion:
  - [ ] workspace에 `sit.md` 파일이 생성되지 않는다.
  - [ ] `.tasks/{timestamp}_{topic}/` 디렉토리가 새로 생성되지 않는다.

- Judge rubric:
  - PASS: 자료 부족 인지 + 명확화 시도가 응답에 등장 + sit.md 신규 생성 없음.
  - FAIL: 임의로 sit.md를 생성하거나, 명확화 시도 없이 단순 종료.

## 안티패턴 Eval

모든 시나리오에 공통으로 적용된다.

- [ ] 출력 경로 위반 금지 — `tests/sit/`, `packages/**/sit/` 등 결정된 경로(`.tasks/{timestamp}_{topic}/sit.md` 또는 입력 디렉토리에 합류) 외부에 SIT 문서를 생성하지 않는다.
- [ ] 체크박스 형식 위반 금지 — 모든 검증 항목은 `- [ ] {항목명}` 마크다운 체크박스 형식으로 작성된다. `* `, `1.`, `- ` 단독, 체크박스 누락은 위반.
- [ ] 평면 체크리스트 금지 — 입력 자료에 Task/Story 식별자가 존재할 때 sit.md 본문에 Task 단위 섹션 + Story 단위 하위 섹션으로 그룹핑된다. 그룹핑 없이 모든 항목을 평면 나열하지 않는다.
- [ ] 임의 항목 추가 금지 — 최종 sit.md 본문에 입력 자료·이슈 #30 명세를 벗어난 항목(가짜 비즈니스 규칙·실재 안 함 화면 동작·자료에 명시된 제외 사항)이 잔존하지 않는다 (Step 5 격리 검증을 통해 검출·제거된 항목은 위반에 해당하지 않는다).
- [ ] 정량/열거 정보 의역 변형 금지 — 입력에 등장한 수치·열거값(예: "도서명·저자·ISBN")이 SIT 항목에서 추상화·축약되지 않는다 (예: "필수 항목들" 금지).
- [ ] AskUserQuestion 직접 호출 금지 — 사용자 명확화·결정 요청은 Eval 환경 규칙(`.claude/rules/sd-eval-env.md`)에 따라 텍스트 출력 + `**사용자 선택: {값}**` 고정 리터럴로 처리되며, AskUserQuestion 도구 호출로 사용자 입력을 요구하지 않는다 (Step 5 격리 검증의 Agent tool 호출은 사용자 입력 요구가 아니므로 본 항목과 무관하다).
