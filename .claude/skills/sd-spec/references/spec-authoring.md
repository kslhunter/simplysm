## 마커

### 헤더 마커 (섹션 상태)

| 마커                 | 의미                                           |
| -------------------- | ---------------------------------------------- |
| `[확정: YYYY-MM-DD]` | 섹션 확정. 본문에 인라인 `[OPEN]` 있어도 무방. |
| `[OPEN: YYYY-MM-DD]` | 섹션 자체 보류. 본문은 참고용, 추후 재판단.    |

### 본문 인라인 마커

| 마커     | 의미                                      |
| -------- | ----------------------------------------- |
| `[OPEN]` | 정보 부족·근거 없는 항목. 향후 확정 필요. |

- 임의 채우거나 누락하지 말고 `[OPEN]` 인라인 표기.
- 헤더 `[확정]` + 본문 인라인 `[OPEN]` = OPEN 항목 인정한 상태로 섹션 확정. 향후 OPEN 만 처리.
- 묻기 시 선택지: `맞나요? [OPEN 상태로 확정 / 섹션 전체 보류 / OPEN 하나씩 해결]`

## §1 개요

### §1.1 핵심 목적

한줄 동사형 큰 단위 표현.

### §1.2 주요 목표

- 단위: 화면·기능 단위가 아니라 최종 사용자가 수행하는 업무 흐름 1건.
- 표현: 한 줄 동사구. 최종 사용자 도메인 어휘.
- 잔손 보강: 큰 흐름 단위로 묶이지 않는 자잘한 변경은 모아서 `기타 ~ 보강` 한 줄로.

### §1.3 최종 사용자/이해관계자

- 실제 담당자 이름은 넣지 않음.
- 설명은 일반화하여 작성.

### §1.4 환경/장치

- ASCII 구성도: 시스템 노드(서버/클라이언트 장치/외부 시스템) + 통신. Actor 표기 X. 장치 상세 사양(OS·모델·해상도 등)은 구성도가 아닌 장치 목록에 기록.
- 장치 목록: 클라이언트 측 장치(PC/PDA/프린터 등) 의 OS·Browser·해상도·모델 등.

## §2 공통 정의

- §2.1 용어 사전 고정. 도메인 어휘·약어·시스템 내 의미 정의.
- 그 외 시스템 전반 규격(바코드 형식, 라벨, 공통 정책 등)은 §2.2~ 로 추가.

## §3 도메인 모델

- 식별 키: 모든 엔티티에 `ID` 필드 (숫자, 자동 부여) 명시.
- 비즈니스 키 (코드 등): 별도 명시. 수정 가능 (PK 가 아니므로).
- 활성/비활성 boolean = 소프트 삭제 플래그. 마스터에는 완전 삭제 없음. UI 의 "삭제/복구" 액션과 매핑 → §2.1 용어 사전에 한 줄 명문화.
- 섹션 구조: `필드:` 표 + `키/제약:` 불릿.

## §4 업무 프로세스

### 분할 단위

- 최종 사용자가 수행하는 독립 업무 흐름 1건 (시작 트리거 → 종료 결과 명확).
- 다른 프로세스의 사전·부수 단계 (자료 업로드, 조회 등) 는 독립 프로세스 X → 해당 메인 프로세스 안에 흡수.
- §1.2 주요 목표 1건 ≈ §4.x 1건 매핑이 일반적.

### BPMN

- 사용자에겐 ASCII 로 보여주고, 확정 후 mermaid 로 문서 저장.
- 흐름 단위 = 외부 비즈니스 이벤트 트리거부터 결과·후속까지 풀 흐름. 단일 화면 입력 절차 X.
- 노드 = 최종 사용자 액션·시스템 핵심 트랜잭션 (1행 동사구). 줄바꿈(`<br/>`) X.
- 장치·매체(PDA·PC·종이 등)는 액션 컨텍스트로 노드에 명시 OK. OS·해상도·API·DB 등 시스템 내부 디테일은 X.
- 분기 = 사용자 의사결정 분기만.

### 관련 섹션

BPMN 아래에 `[화면.X]` / `[자동 처리.X]` / `[외부인터페이스.X]` 나열.

## §6 화면

### 화면 목록 표

§6 첫머리에 4컬럼 표:

| § | 화면 | 구분 | 장치 |

- 구분: 마스터 / 트랜잭션 / 조회
- 장치: PC / PDA / 기타
- 화면 추가/제거 시 표도 갱신.

### 화면 정의

§6.x 표준 구조 (위→아래 순서):

- 기능 개요: Actor / 관련 프로세스 / (관련 자동 처리) / 기능 개요 설명
- 와이어프레임
- 항목: 데이터 항목만 (필터·시트 컬럼·입력/상세 폼). 액션 버튼은 "동작" 에.
  - 시트 화면: 필터 + 시트 컬럼 2 그룹.
- 동작: 액션 버튼·이벤트 별 처리.

- 화면 헤더에 (장치) 표기: `### N.N 화면명 (PC) [확정: 날짜]` 또는 `(PDA)` 등. 화면 목록 표의 장치 컬럼과 중복이지만 본문 헤더에도 유지.
- 모달 화면은 별도 §6.x 로 분리 (부르는 쪽 동작에 "→ [화면.X] 을 모달로 띄움" 명시). 화면명에 "(모달)" 등 사용 맥락 표기 X — 같은 화면이 다른 곳에서 다르게 호출될 수 있음.

### 마스터 화면 표준

- ID 컬럼이 편집 버튼 역할(`[E N]`).
- 첫 컬럼은 선택 체크박스(`[ ]`).
- 상단 버튼바: `[등록] [선택 삭제] [선택 복구] [엑셀 업로드] [엑셀 다운로드]`.
- ID 정렬 역방향.

### 와이어프레임 (텍스트)

ASCII 그림 공통 규칙은 `sd-base-rules.md` 의 "ASCII 그림" 절 참조. 와이어프레임 전용:

- 아이콘은 ASCII placeholder: `[ ]` (체크박스), `[E N]` (편집 버튼: E = Edit 아이콘, N = ID), `[X]` (삭제 아이콘).
- 비활성 행 등 시각 표현은 인라인 괄호 텍스트: `(비활성: 행 전체 취소선)`.
- placeholder·시각 표현이 자명하지 않을 때 코드블록 끝에 범례 + 시각 규칙 안내.
  - 예: `|| = fixed 경계`, `[E N] = 편집 버튼 (N = ID). 클릭 시 편집 모달`, `비활성 행은 텍스트 취소선 + 회색 처리`
