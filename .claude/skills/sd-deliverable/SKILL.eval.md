# Eval: sd-deliverable

## 행동 Eval

### 시나리오 1: 신규 생성 (코드 기반)
- 입력: "/sd-deliverable packages/client-admin/src/app/home/scheduling"
- 사전 조건: scheduling 관련 코드 존재, 기존 매뉴얼/SIT 없음
- 체크리스트:
  - [ ] 코드베이스를 계층적으로 분석했다 (라우트/메뉴 구조 → DB 엔티티 → 상수/유틸 → UI 컴포넌트)
  - [ ] 매뉴얼 md 파일이 생성되었고, 기능별 섹션으로 구조화되어 있다
  - [ ] SIT md 파일이 생성되었고, 테스트 케이스가 테이블 형식으로 작성되어 있다
  - [ ] SIT 각 항목에 고유 식별 가능한 번호가 있다 (기능번호.순번 형식)
  - [ ] SIT에 Pass 컬럼(체크박스)과 비고 컬럼이 포함되어 있다
  - [ ] 매뉴얼과 SIT의 기능 범위가 일치한다 (매뉴얼에 있는 기능은 SIT에도 테스트가 있다)
  - [ ] 출력 파일 경로를 사용자에게 안내했다

### 시나리오 2: 스펙 문서 참조 생성
- 입력: "/sd-deliverable packages/client-admin/src/app/home/scheduling --ref .tasks/260327160111_scheduling"
- 사전 조건: scheduling 코드 + task MD 스펙 파일 존재
- 체크리스트:
  - [ ] task MD 파일들을 읽어서 비즈니스 규칙과 용어를 반영했다
  - [ ] 코드도 함께 분석하여 스펙에 없는 구현 상세를 보완했다
  - [ ] 매뉴얼에 스펙의 비즈니스 용어가 일관되게 사용되었다
  - [ ] SIT에 스펙의 유효성 검증 규칙이 테스트 케이스로 포함되었다

### 시나리오 3: SIT 증분 업데이트 (변경/추가/삭제)
- 입력: "/sd-deliverable packages/client-admin/src/app/home/scheduling --out .docs/260328_Scheduling_매뉴얼"
- 사전 조건: 기존 SIT.md 파일 존재 (일부 항목 [x] Pass 체크, 비고 기입됨), 코드에 기능 변경 있음
- 체크리스트:
  - [ ] 기존 SIT.md 파일을 읽었다
  - [ ] 변경된 기능의 기존 테스트 항목이 [~] (재테스트 필요)로 변경되었다
  - [ ] 신규 기능에 대한 테스트 항목이 [ ]로 추가되었다
  - [ ] 삭제된 기능의 테스트 항목이 취소선으로 처리되었다
  - [ ] 변경되지 않은 항목의 [x] Pass 상태와 비고가 보존되었다
  - [ ] 변경 사항 요약이 출력에 포함되었다

### 시나리오 4: 매뉴얼 증분 업데이트
- 입력: "/sd-deliverable packages/client-admin/src/app/home/scheduling --out .docs/260328_Scheduling_매뉴얼"
- 사전 조건: 기존 매뉴얼 md 파일 존재, 코드에 기능 변경 있음
- 체크리스트:
  - [ ] 기존 매뉴얼 파일들을 읽었다
  - [ ] 변경된 기능의 섹션이 업데이트되었다
  - [ ] 신규 기능의 섹션이 추가되었다
  - [ ] 삭제된 기능의 섹션이 제거되었다
  - [ ] 변경되지 않은 섹션의 내용이 보존되었다

## 안티패턴 Eval

- [ ] 코드를 읽지 않고 추측만으로 문서를 생성하지 않았다
- [ ] 매뉴얼에 존재하는 기능이 SIT에 누락되지 않았다 (커버리지 불일치 금지)
- [ ] 기존 SIT 업데이트 시 변경되지 않은 항목의 Pass/Fail 상태를 임의로 변경하지 않았다
- [ ] xlsx, docx 등 바이너리 파일을 생성하지 않았다 (md만 사용)
- [ ] 사용자가 지정하지 않은 범위의 코드까지 분석 대상에 포함하지 않았다
