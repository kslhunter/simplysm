## 참조 자료

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | 소스 커스텀 유틸리티 대체 | 네이티브 Angular API 사용 | `transformBoolean`→`booleanAttribute`, `$computed`→`computed()`, `forwardRef` 제거 (별도 파일 import, 순환 참조 없음). v14 완성 Feature 패턴과 일치 |

## 요구명세

```gherkin
Feature: 2.2 폼 레이아웃 및 뷰 전환

  Background:
    Given Angular 21 standalone 컴포넌트 환경이다

  Rule: Form Box는 수직(vertical) 또는 수평(inline) 폼 레이아웃을 제공한다

    Scenario: 기본 form-box는 수직 배치이다
      Given sd-form-box에 inline을 지정하지 않는다
      When 렌더링된다
      Then CSS 클래스 "form-box"가 적용된다
      And 자식이 column 방향 flex로 gap-default 간격을 갖는다

    Scenario: inline=true이면 수평 배치이다
      Given sd-form-box에 inline=true를 지정한다
      When 렌더링된다
      Then CSS 클래스 "form-box-inline"이 적용된다
      And 자식이 row 방향 inline-flex로 flex-wrap, gap-sm 간격을 갖는다

    Scenario: 수직 모드에서 label은 블록 표시되고 bold이다
      Given sd-form-box 안에 label이 있는 form-box-item이 있다
      When 렌더링된다
      Then label이 display:block, font-weight:bold로 표시된다
      And label의 margin-bottom이 gap-xs이다
      And label의 border가 1px solid transparent이다

    Scenario: 수평 모드에서 label은 인라인 정렬된다
      Given sd-form-box inline 안에 label이 있는 form-box-item이 있다
      When 렌더링된다
      Then form-box-item이 display:flex, align-items:center로 표시된다
      And label의 padding-left과 padding-right이 gap-sm이다

    Scenario: 터치 디바이스에서 수직 모드의 간격이 조정된다
      Given 터치 디바이스(pointer: coarse)에서 sd-form-box를 사용한다
      When 렌더링된다
      Then form-box-item의 margin-bottom이 gap-default로 증가한다
      And label의 margin-bottom이 gap-xxs로 감소한다

  Rule: Form Box Item은 라벨-입력 쌍을 래핑한다

    Scenario: sd-form-box-item 디렉티브를 사용하면 클래스가 적용된다
      Given sd-form-box 안에 sd-form-box-item을 사용한다
      When 렌더링된다
      Then "form-box-item" CSS 클래스가 적용된다

    Scenario: plain div도 동일한 스타일을 받는다
      Given sd-form-box 안에 plain div를 사용한다
      When 렌더링된다
      Then SCSS의 "> div" 선택자에 의해 동일한 레이아웃 스타일이 적용된다

  Rule: Form Table은 테이블 기반 라벨-입력 정렬을 제공한다

    Scenario: sd-form-table은 CSS table 레이아웃을 적용한다
      Given sd-form-table을 사용한다
      When 렌더링된다
      Then display:table, border-collapse:separate 스타일이 적용된다

    Scenario: th 셀은 shrink-to-fit 라벨 영역이다
      Given sd-form-table 안에 tr > th + td 구조를 사용한다
      When 렌더링된다
      Then th는 width:0, text-align:right, white-space:nowrap으로 라벨 영역이 된다
      And th의 padding-left이 gap-sm이다

    Scenario: td 셀은 입력 영역이다
      Given sd-form-table 안에 tr > th + td 구조를 사용한다
      When 렌더링된다
      Then td는 padding:0 gap-default gap-sm 0, vertical-align:middle이다
      And 마지막 td의 padding-right은 0이다
      And 마지막 tr의 td/th padding-bottom은 0이다

    Scenario: th에 form-table-header 클래스를 적용하면 섹션 구분 헤더가 된다
      Given th에 class="form-table-header"를 적용한다
      When 렌더링된다
      Then text-align:left, font-size:font-size-sm, color:theme-gray-default로 표시된다
      And padding-top이 gap-xxl, font-weight가 normal이다
      And 첫 번째 tr의 header th는 padding-top이 0이다

  Rule: View는 value 매칭으로 하위 View Item의 표시/숨김을 전환한다

    Scenario: value가 일치하는 view-item만 표시된다
      Given sd-view에 value="tab1"이 지정되어 있다
      And sd-view-item value="tab1"과 sd-view-item value="tab2"가 있다
      When 렌더링된다
      Then value="tab1" item은 display:block으로 표시된다
      And value="tab2" item은 display:none으로 숨겨진다

    Scenario: value 변경 시 표시 item이 전환된다
      Given sd-view에 value="tab1"이 지정되어 있다
      When value가 "tab2"로 변경된다
      Then value="tab1" item이 숨겨진다
      And value="tab2" item이 표시된다

    Scenario: view-item은 부모 SdViewControl을 inject하여 선택 상태를 판단한다
      Given sd-view-item이 sd-view 안에 있다
      When sd-view-item이 생성된다
      Then 부모 SdViewControl을 inject()로 참조한다
      And computed()로 isSelected(parentValue === myValue)를 계산한다

  Rule: View는 fill 모드로 부모 높이를 채울 수 있다

    Scenario: fill=true이면 view가 100% 높이를 차지한다
      Given sd-view에 fill=true를 지정한다
      When 렌더링된다
      Then sd-view의 height가 100%이다

    Scenario: fill=true일 때 선택된 view-item도 100% 높이이다
      Given sd-view fill=true 안에 선택된 sd-view-item이 있다
      When 렌더링된다
      Then 선택된 sd-view-item의 height도 100%이다

    Scenario: fill 미지정 시 컨텐츠 높이에 맞춘다
      Given sd-view에 fill을 지정하지 않는다
      When 렌더링된다
      Then sd-view가 컨텐츠 높이에 맞춰 표시된다
```

## 구현계획

### 배경

대상 패키지(`packages/angular`)에 Epic 1(공통 인프라)과 Feature 2.1(기본 레이아웃)이 완성되어 `src/ui/layout/` 하위에 dock, flex, grid 등 10개 컴포넌트/디렉티브와 4개 SCSS 파일이 갖춰져 있다. Feature 2.2는 소스(`D:\workspaces-12\simplysm\packages\sd-angular`)의 form 레이아웃 3개 디렉티브와 view 전환 2개 컴포넌트를 Angular 21 네이티브 API로 마이그레이션한다.

### 목표

- form 레이아웃 디렉티브 3개(SdFormBoxDirective, SdFormBoxItemDirective, SdFormTableDirective) 마이그레이션
- view 전환 컴포넌트 2개(SdViewControl, SdViewItemControl) 마이그레이션
- 대응하는 SCSS 2개 파일(_form-box.scss, _form-table.scss) 생성
- 각 컴포넌트에 대한 테스트 작성

### 비목표

- Kanban 레이아웃 (sd-kanban-board, sd-kanban-lane, sd-kanban) → Feature 6.3
- Tab 네비게이션 (sd-tabview, sd-tabview-item) → Epic 4

#### 소스 유틸리티 → 대상 네이티브 API 매핑

| 소스 | 대상 | import |
|------|------|--------|
| `transformBoolean` | `booleanAttribute` | `@angular/core` |
| `$computed(() => ...)` | `computed(() => ...)` | `@angular/core` |
| `forwardRef(() => SdViewControl)` | 직접 `SdViewControl` 참조 | 별도 파일이므로 forwardRef 불필요 |

#### SCSS

2개 파일을 `scss/controls/`에 생성하고, `scss/styles.scss`에서 `@use`로 import한다. 소스 SCSS를 기반으로 하되, v14 컨벤션에 맞게 조정한다.

- `_form-box.scss`: 소스 그대로 + `var(gap-xxs)` → `var(--gap-xxs)` 오타 수정 (D2)
- `_form-table.scss`: 소스 그대로

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| SdViewItemControl에서 부모 inject 대신 contentChildren 패턴 사용 | 미채택 | view-item이 자신의 선택 상태를 판단하는 패턴이 더 단순. dock-container는 자식 위치/크기를 계산하므로 contentChildren이 적절하나, view는 단순 표시/숨김이므로 inject가 적합 |
| form-box를 data-attribute 기반으로 변경 | 미채택 | 기존 SCSS 기반 클래스 패턴 유지. v14 flex 디렉티브와 동일한 `[class]` 바인딩 패턴 |
