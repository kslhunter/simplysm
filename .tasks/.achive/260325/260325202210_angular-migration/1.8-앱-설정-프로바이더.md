# Feature 1.8 앱 설정 프로바이더

## 참조 자료

- [wbs.md](./wbs.md)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | SdSystemConfigProvider의 SdLocalStorageProvider 의존성 | Feature 1.9로 이관 | SdLocalStorageProvider가 1.9 범위이므로 자연스러운 의존성 순서 유지 |
| D2 | 동기 handleError에서 SdSystemLogProvider 호출 방식 | void writeAsync() (fire-and-forget) | writeFn은 DB/서버 전송 등 비동기 본질. void로 fire-and-forget 의도를 명시 |
| D3 | SdAngularConfigProvider 속성 | clientName만 유지 | defaultTheme 제거(1.2.1), defaultDark 제거(테마는 SdThemeProvider가 관리) |

      And "관리" 하위에 Leaf item "사용자" (code: "user")가 있다
      When usableMenus를 계산한다
      Then 결과에 "관리" 그룹이 포함된다

      Then 해당 메뉴가 제외된다

      Given Leaf item에 isNotMenu true가 설정되어 있다
      When usableMenus를 계산한다

      And 에러 UI는 표시되지 않는다

## 구현계획

### 배경

v14 @simplysm/angular의 `src/core/providers/`에는 SdThemeProvider와 SdNavigateWindowProvider만 존재한다. v12의 앱 설정 프로바이더 4개 중 SdSystemConfigProvider는 Feature 1.9로 이관되었으며, 나머지 3개를 마이그레이션한다. Feature 1.5에서 구현된 에러 핸들러가 console 직접 호출 중이며, SdSystemLogProvider 연동이 보류된 상태이다.

### 목표

- SdAngularConfigProvider, SdAppStructureProvider, SdSystemLogProvider 마이그레이션
- SdGlobalErrorHandlerPlugin에 SdSystemLogProvider 연동

### 비목표

- SdSystemConfigProvider (Feature 1.9로 이관 — D1)
- provideSdAngular() 부트스트래핑 (Feature 1.10)
- SdLocalStorageProvider (Feature 1.9)

### 설계

#### SdAngularConfigProvider

`src/core/providers/sd-angular-config.provider.ts` — providedIn: "root". clientName 프로퍼티만 유지 (D3). defaultTheme(1.2.1에서 제거), defaultDark(SdThemeProvider가 관리), icons(v12에서 이미 주석) 제거.

#### SdSystemLogProvider

`src/core/providers/sd-system-log.provider.ts` — providedIn: "root". v12 코드와 동일 구조. `/* eslint-disable no-console */` 파일 레벨 (console 호출이 프로바이더 목적). writeFn은 optional, writeAsync()에서 console 즉시 호출 + writeFn try-catch.

#### SdAppStructureProvider

`src/core/providers/sd-app-structure.provider.ts` — providedIn: "root", abstract class. v12 코드에서 `$computed` → `computed()` 치환. usePermsSignal 함수도 동일 치환. SdAppStructureUtils(static 메서드)와 타입 정의(TSdAppStructureItem, ISdMenu, ISdFlatMenu, ISdPermission, ISdFlatPermission)는 변경 없이 포함.

#### SdGlobalErrorHandlerPlugin (기존 파일 수정)

SdSystemLogProvider inject 추가. `_displayErrorMessage()`의 `console.error(...)` → `void this._systemLog.writeAsync("error", ...)`. ErrorEvent error null의 `console.warn(message)` → `void this._systemLog.writeAsync("warn", message)`. catch block의 `console.error(err, event)`는 유지 (error handler 자체 실패 시 무한 재귀 방지).

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| SdAngularConfigProvider를 InjectionToken으로 대체 | 미채택 | Feature 1.9(SdLocalStorageProvider)가 class 주입에 의존. 향후 속성 추가 가능성 |
| SdAppStructureUtils를 standalone 함수로 분리 | 미채택 | v12 구조와 동일하게 유지. 변경 이유 없음 |
| providers/ 하위에 app/ 서브디렉토리 생성 | 미채택 | v14 기존 패턴이 flat 구조. 파일 5개 수준에서 불필요 |
