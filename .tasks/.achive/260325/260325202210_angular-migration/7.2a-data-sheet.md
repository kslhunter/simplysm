## 구현계획

### 배경

v12의 SdDataSheetControl + AbsSdDataSheet + SdDataSheetColumnDirective를 v14로 마이그레이션한다. v14는 Angular 21의 signal-first 아키텍처를 사용하며, v12의 커스텀 signal 래퍼(`$signal`, `$computed`, `$effect`, `$arr`)를 네이티브 API로 교체한다.

### 목표

- SdDataSheetControl 프레젠테이션 컴포넌트
- AbsSdDataSheet 추상 비즈니스 로직 디렉티브
- SdDataSheetColumnDirective (SdSheetColumnDirective 확장)
- 인터페이스: ISdDataSheetItemPropInfo, ISdDataSheetItemInfo, ISdDataSheetSearchResult
- 유틸리티: setupCumulateSelectedKeys, setupCloserWhenSingleSelectionChange

### 비목표

- SdDataDetailControl (Feature 7.2b)
- SdDataSelectButtonControl (Feature 7.2c)
- ISdSelectModal 인터페이스 변경 (이미 v14에 존재)
- SdSheetControl 수정

### 설계

#### v12 → v14 API 매핑

| v12 | v14 | 근거 |
|-----|-----|------|
| `$signal(value)` | `signal(value)` | Angular 21 네이티브 |
| `$computed(() => ...)` | `computed(() => ...)` | Angular 21 네이티브 |
| `$effect(() => ...)` | `effect(() => ...)` | Angular 21 네이티브 |
| `$signal.$mark()` | `signal.update(v => [...v])` / `signal.update(v => ({...v}))` | 새 참조 생성으로 변경 알림 |
| `$arr(items).snapshot(keyFn)` + `.diffs(opts)` | 수동 snapshot 저장 + `Array.oneWayDiffs(orgItems, keyFn, opts)` | core-common 확장 메서드 활용 |
| `TArrayDiffs2Result<T>` | `ArrayOneWayDiffResult<T>` | core-common v14 타입 |
| `ISdSortingDef` | `ISortingDef` | useSortingManager export |
| `transformBoolean` | `booleanAttribute` | Angular 21 내장 |
| `SdSheetColumnCellTemplateDirective` + `[cell]` | `<ng-template #cellTpl>` + `ngTemplateOutletContext` | v14 SdSheetControl 패턴 |
| `columnControl.headerTplRef()` | (제거) | v14 SdSheetColumnDirective에 headerTplRef 없음 |
| `columnControl.headerStyle()` / `tooltip()` | (제거) | v14 SdSheetColumnDirective에 해당 input 없음 |

#### 변경 추적 설계

- `_itemsSnapshot: TItem[]` — `refresh()` 후 `ObjectUtils.clone(items)` 저장
- `_getDiffs()` — `items.oneWayDiffs(_itemsSnapshot, keyFn, { excludes }).filter(d => d.type !== "same")`
- `checkIgnoreChanges()` — `_getDiffs().length === 0 || confirm(TXT_CHANGE_IGNORE_CONFIRM)`

#### setupCumulateSelectedKeys 설계

selectedItems ↔ selectedItemKeys 양방향 동기화:
- items 변경 → selectedItems에서 현재 items에 존재하지 않는 항목 제거
- selectedItems 변경 → selectedItemKeys 갱신
- selectedItemKeys 외부 변경 → items에서 매칭 항목을 selectedItems에 설정

#### setupCloserWhenSingleSelectionChange 설계

selectMode="single"일 때 selectedItemKeys가 비어있지 않으면 close 이벤트 자동 발생.

### 대안 검토

| 접근 방식 | 선택 | 이유 |
|-----------|------|------|
| Abstract Directive 유지 | 채택 | 소비 코드 호환성, 확장 포인트 보존 |
| Composition Function으로 전환 | 미채택 | 소비 코드가 모든 로직을 수동 조립해야 함 |
| 커스텀 signal 래퍼 재구현 | 미채택 | 불필요한 추상화, Angular 21 네이티브로 충분 |
| setup 유틸을 features/ 내부 배치 | 미채택 | 기존 패턴 불일치, Feature 5.1에서 재사용 불가 |
