Feature: 2.1 기본 레이아웃

  Background:
    Given Angular 21 standalone 컴포넌트 환경이다

  Rule: Dock 레이아웃은 고정 패널과 유동 컨텐츠 영역을 배치한다

    Scenario: top dock 하나를 배치하면 컨텐츠에 padding-top이 적용된다
      Given sd-dock-container 안에 position="top"인 sd-dock이 있다
      When 레이아웃이 렌더링된다
      Then sd-dock은 컨테이너 상단에 고정 표시된다
      And 컨텐츠 영역에 dock 높이만큼 padding-top이 적용된다

    Scenario: 여러 방향의 dock을 조합하면 각 방향에 padding이 적용된다
      Given sd-dock-container 안에 position="left"인 sd-dock과 position="top"인 sd-dock이 있다
      When 레이아웃이 렌더링된다
      Then 컨텐츠 영역에 padding-left과 padding-top이 각각 적용된다

    Scenario: dock 없이 컨테이너만 사용하면 컨텐츠가 전체 영역을 차지한다
      Given sd-dock-container 안에 sd-dock이 없다
      When 레이아웃이 렌더링된다
      Then 컨텐츠 영역이 전체 크기를 사용한다

    Scenario: dock의 position을 4방향으로 지정할 수 있다
      Given sd-dock의 position을 "top", "bottom", "left", "right" 중 하나로 지정한다
      When 레이아웃이 렌더링된다
      Then 해당 방향에 dock이 고정 배치된다

    Scenario: 컨테이너의 contentClass가 컨텐츠 영역에 적용된다
      Given sd-dock-container에 contentClass="my-class"를 지정한다
      When 레이아웃이 렌더링된다
      Then 컨텐츠 영역 div에 "my-class" CSS 클래스가 적용된다

  Rule: Dock 패널은 사용자가 드래그로 크기를 조절하고 저장할 수 있다

    Scenario: resizable이 false이면 크기 조절이 불가하다
      Given sd-dock에 resizable=false이다
      When 레이아웃이 렌더링된다
      Then resize bar가 표시되지 않는다

    Scenario: resizable이 true이면 드래그로 크기를 변경할 수 있다
      Given sd-dock에 resizable=true이다
      When 사용자가 resize bar를 드래그한다
      Then dock의 크기가 드래그 거리만큼 변경된다

    Scenario: key가 지정된 dock의 크기 변경이 시스템 설정에 저장된다
      Given sd-dock에 key="sidebar"와 resizable=true가 지정되어 있다
      When 사용자가 크기를 300px로 변경한다
      Then 시스템 설정에 "sidebar" 키로 300px가 저장된다
      And 페이지 새로고침 후 dock이 300px로 복원된다

    Scenario: key가 없는 dock의 크기 변경은 저장되지 않는다
      Given sd-dock에 key 없이 resizable=true만 지정되어 있다
      When 사용자가 크기를 변경한다
      Then 크기가 즉시 반영되나 새로고침 시 초기값으로 돌아간다

  Rule: Flex 레이아웃은 1차원 유연 배치를 제공한다

    Scenario: 기본 방향은 수평(row) 배치이다
      Given sd-flex에 vertical을 지정하지 않는다
      When 렌더링된다
      Then 자식 요소가 수평(row) 방향으로 배치된다

    Scenario: vertical=true이면 수직(column) 배치이다
      Given sd-flex에 vertical=true를 지정한다
      When 렌더링된다
      Then 자식 요소가 수직(column) 방향으로 배치된다

    Scenario: inline=true이면 inline-flex로 표시된다
      Given sd-flex에 inline=true를 지정한다
      When 렌더링된다
      Then display가 inline-flex이다

    Scenario: sd-flex-grow="fill"이면 남은 공간을 채운다
      Given flex 컨테이너 안에서 자식에 sd-flex-grow="fill"을 지정한다
      When 렌더링된다
      Then 해당 자식이 남은 공간을 모두 채운다 (flex: 1 1 auto, overflow: auto)

    Scenario: sd-flex-grow="auto"이면 컨텐츠 크기를 유지한다
      Given flex 컨테이너 안에서 자식에 sd-flex-grow="auto"를 지정한다
      When 렌더링된다
      Then 해당 자식이 컨텐츠 크기를 유지하되 늘어날 수 있다 (flex: 1 0 auto)

    Scenario: sd-flex-grow="min"이면 최소 크기이다
      Given flex 컨테이너 안에서 자식에 sd-flex-grow="min"을 지정한다
      When 렌더링된다
      Then 해당 자식이 최소 크기만 차지한다 (flex: 0 0 0)

  Rule: Grid 레이아웃은 반응형 12열 배치를 제공한다

    Scenario: colSpan으로 열 너비를 지정한다
      Given sd-grid 안에 sd-grid-item colSpan=6이 2개 있다
      When 렌더링된다
      Then 각 항목이 6/12(50%) 너비로 2열 배치된다

    Scenario: colSpanSm으로 1280px 이하에서 열 너비가 변경된다
      Given sd-grid-item에 colSpan=12, colSpanSm=6을 지정한다
      When 화면 너비가 1280px 이하이다
      Then 항목이 6/12(50%) 너비로 표시된다

    Scenario: colSpanXs로 1024px 이하에서 열 너비가 변경된다
      Given sd-grid-item에 colSpanXs=12를 지정한다
      When 화면 너비가 1024px 이하이다
      Then 항목이 12/12(100%) 너비로 표시된다

    Scenario: colSpanXxs로 800px 이하에서 열 너비가 변경된다
      Given sd-grid-item에 colSpanXxs=12를 지정한다
      When 화면 너비가 800px 이하이다
      Then 항목이 12/12(100%) 너비로 표시된다

  Rule: 기본 구조 요소로 컨텐츠를 배치하고 간격을 조절한다

    Scenario: sd-pane은 부모를 채우고 오버플로우 시 스크롤한다
      Given sd-pane 안에 부모보다 큰 컨텐츠가 있다
      When 렌더링된다
      Then pane이 부모 크기(100% x 100%)를 채운다
      And 오버플로우된 컨텐츠에 스크롤바가 표시된다

    Scenario: sd-gap에 사전정의 높이를 지정하면 수직 간격이 생긴다
      Given sd-gap에 height="default"를 지정한다
      When 렌더링된다
      Then 0.5rem 높이의 block 요소가 표시된다

    Scenario: sd-gap에 사전정의 너비를 지정하면 인라인 수평 간격이 생긴다
      Given sd-gap에 width="sm"을 지정한다
      When 렌더링된다
      Then 0.3333rem 너비의 inline-block 요소가 표시된다

    Scenario: sd-gap에 px 단위 높이를 지정할 수 있다
      Given sd-gap에 heightPx=20을 지정한다
      When 렌더링된다
      Then 20px 높이의 block 요소가 표시된다

    Scenario: sd-gap에 em 단위 너비를 지정할 수 있다
      Given sd-gap에 widthEm=2를 지정한다
      When 렌더링된다
      Then 2em 너비의 inline-block 요소가 표시된다

    Scenario: sd-card는 카드 스타일 컨테이너를 표시한다
      Given sd-card를 사용한다
      When 렌더링된다
      Then 배경색(control-color), 둥근 모서리, elevation 2 그림자가 적용된다

    Scenario: sd-card에 hover하면 elevation이 상승한다
      Given sd-card가 렌더링되어 있다
      When 사용자가 마우스를 올린다
      Then elevation이 4로 상승한다

    Scenario: sd-table은 CSS table 레이아웃을 적용한다
      Given sd-table을 사용한다
      When 렌더링된다
      Then display: table 스타일이 적용된다

## 구현계획

### 배경

대상 패키지(`packages/angular`)에 Epic 1(공통 인프라)이 완성되어 core/ 디렉토리에 프로바이더, 디렉티브, 플러그인, 유틸리티가 갖춰져 있다. UI 컴포넌트는 아직 없으며, Feature 2.1이 첫 UI Feature이다. 소스(`D:\workspaces-12\simplysm\packages\sd-angular\src\ui\layout\`)의 10개 컴포넌트/디렉티브를 Angular 21 네이티브 API로 마이그레이션한다.

### 목표

- dock, flex, grid, pane, gap, card, table 레이아웃 컴포넌트/디렉티브 10개 마이그레이션
- 대응하는 SCSS (flex, grid, card, table) 4개 파일 생성
- 각 컴포넌트에 대한 테스트 작성

### 비목표

- Form 레이아웃 (sd-form-box, sd-form-box-item, sd-form-table) → Feature 2.2
- View 전환 (sd-view, sd-view-item) → Feature 2.2
- Kanban (sd-kanban-board, sd-kanban-lane, sd-kanban) → Feature 6.3

#### 소스 유틸리티 → 대상 네이티브 API 매핑

| 소스 | 대상 | import |
|------|------|--------|
| `$effect(() => ...)` | `effect(() => ...)` | `@angular/core` |
| `$signal(0)` | `signal(0)` | `@angular/core` |
| `$computed(() => ...)` | `computed(() => ...)` | `@angular/core` |
| `injectElementRef<T>()` | `inject(ElementRef<T>)` | `@angular/core` |
| `transformBoolean` | `booleanAttribute` | `@angular/core` |
| `.filterExists()` | `.filterExists()` | `@simplysm/core-common` (array extension, 이미 의존성) |

#### SCSS

4개 파일을 `scss/controls/`에 생성하고, `scss/styles.scss`에서 `@use`로 import한다. 소스 SCSS를 그대로 사용하되, import 경로를 대상 구조에 맞게 조정한다 (`../commons/variables`, `../commons/mixins`).

- `_flex.scss`: flex-row/column/inline, flex-auto/fill/min 클래스
- `_grid.scss`: grid 12열, grid-{1..12}, 반응형 breakpoint (sm≤1280px, xs≤1024px, xxs≤800px)
- `_card.scss`: card 스타일 (elevation, animation, hover 효과)
- `_table.scss`: table 스타일 (border, th/td, 변형 클래스)

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| 소스 커스텀 유틸리티($effect 등) 그대로 재구현 | 미채택 | 완성된 Feature들이 네이티브 API를 사용하므로 일관성 유지 |
| Flex/Grid SCSS를 컴포넌트 inline styles로 이동 | 미채택 | 전역 CSS 클래스가 다른 컴포넌트에서도 재사용됨 |
| CSS-in-JS 방식으로 전환 | 미채택 | 기존 SCSS 기반 테마 시스템과 일관성 유지 |
