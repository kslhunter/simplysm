## 요구명세

```gherkin
Feature: 4.1 목록·접기

  Background:
    Given Angular 앱이 @simplysm/angular 패키지를 사용하고 있다
    And core-common의 Array 확장(remove, single, first, last)이 로드되어 있다

  Rule: 목록 컨테이너는 중첩 가능하며 inset 모드를 지원한다

    Scenario: 기본 목록 렌더링
      Given sd-list 컴포넌트가 렌더링된다
      Then 배경색이 var(--control-color)이다
      And user-select가 none이다

    Scenario: inset 모드 활성화
      Given sd-list에 inset=true가 설정된다
      Then 배경이 투명해진다
      And 내부에 중첩된 sd-list도 배경이 투명해진다

    Scenario: 목록 중첩
      Given sd-list 내부에 sd-list-item과 하위 sd-list가 있다
      Then 외부와 내부 sd-list 모두 정상 렌더링된다

  Rule: 목록 아이템은 accordion/flat 레이아웃으로 하위 항목을 표시한다

    Scenario: accordion 레이아웃에서 클릭으로 열림 토글
      Given sd-list-item의 layout이 "accordion"(기본값)이다
      And 하위 sd-list가 존재한다
      When _content 영역을 클릭한다
      Then open 상태가 토글된다
      And sd-collapse-icon이 표시되어 열림 상태를 반영한다

    Scenario: accordion 레이아웃에서 open=true로 하위 목록 펼침
      Given sd-list-item의 layout이 "accordion"이다
      And open=true이다
      Then 하위 sd-list가 sd-collapse를 통해 펼쳐져 보인다

    Scenario: flat 레이아웃에서 항상 펼쳐진 상태
      Given sd-list-item의 layout이 "flat"이다
      And 하위 sd-list가 존재한다
      Then 하위 목록이 항상 펼쳐져 있다
      And sd-collapse-icon이 표시되지 않는다
      And _content 영역이 헤더 스타일(작은 글씨, 불투명도 0.7, cursor: default)로 표시된다

    Scenario: 하위 항목이 없는 목록 아이템
      Given sd-list-item에 하위 sd-list가 없다
      Then hasChildren이 false이다
      And sd-collapse 영역이 렌더링되지 않는다
      And sd-collapse-icon이 표시되지 않는다

  Rule: 목록 아이템은 선택 상태와 읽기 전용 모드를 지원한다

    Scenario: 선택 상태 활성화
      Given sd-list-item에 selected=true가 설정된다
      Then _content 배경이 var(--trans-lighter)이다
      And 글씨가 bold이다

    Scenario: 선택 아이콘과 선택 상태
      Given sd-list-item에 selectedIcon이 지정되어 있다
      And selected=true이다
      And 하위 항목이 없다
      Then 아이콘이 tx-theme-primary-default 색상으로 표시된다

    Scenario: 선택 아이콘과 미선택 상태
      Given sd-list-item에 selectedIcon이 지정되어 있다
      And selected=false이다
      Then 아이콘이 tx-trans-lightest(흐림) 색상으로 표시된다

    Scenario: 읽기 전용 모드
      Given sd-list-item에 readonly=true가 설정된다
      Then cursor가 default이다
      And hover 시 배경 변경이 없다
      And 리플 효과가 비활성화된다

    Scenario: tool 템플릿 슬롯
      Given sd-list-item 내부에 #toolTpl 템플릿이 정의되어 있다
      Then _content 우측에 tool 영역이 렌더링된다

  Rule: 접기 컴포넌트는 애니메이션으로 콘텐츠를 접고 편다

    Scenario: 닫힌 상태에서 콘텐츠 숨김
      Given sd-collapse에 open=false가 설정된다
      Then 내부 _content의 margin-top이 -(contentHeight)px로 설정된다
      And transition이 margin-top 0.1s ease-in이다

    Scenario: 열린 상태에서 콘텐츠 표시
      Given sd-collapse에 open=true가 설정된다
      Then 내부 _content의 margin-top이 ""(초기값)이다
      And transition이 margin-top 0.1s ease-out이다

    Scenario: 콘텐츠 크기 변경 시 높이 재계산
      Given sd-collapse가 렌더링되어 있다
      When 내부 콘텐츠의 크기가 변경되어 sdResize 이벤트가 발생한다
      Then contentHeight가 새로운 offsetHeight 값으로 갱신된다

  Rule: 접기 아이콘은 열림 상태에 따라 회전한다

    Scenario: 닫힌 상태의 아이콘
      Given sd-collapse-icon에 open=false가 설정된다
      Then transform이 ""(회전 없음)이다

    Scenario: 열린 상태의 기본 회전
      Given sd-collapse-icon에 open=true가 설정된다
      And openRotate가 90(기본값)이다
      Then transform이 rotate(90deg)이다
      And transition이 transform 0.1s ease-out이다

    Scenario: 커스텀 회전 각도
      Given sd-collapse-icon에 open=true가 설정된다
      And openRotate가 180이다
      Then transform이 rotate(180deg)이다

  Rule: 확장 매니저(useExpandingManager)는 계층 구조의 펼침 상태를 관리한다

    Scenario: flat 아이템 목록 (getChildrenFn 미제공)
      Given items에 [A, B, C]가 바인딩된다
      And getChildrenFn이 undefined이다
      When useExpandingManager를 호출한다
      Then displayItems가 [A, B, C]이다
      And 모든 아이템의 depth가 0이다
      And hasExpandable이 false이다

    Scenario: 계층 아이템의 트리 순회
      Given items에 [Parent]가 바인딩된다
      And getChildrenFn이 Parent의 자식으로 [Child1, Child2]를 반환한다
      When useExpandingManager를 호출한다
      Then displayItems가 [Parent, Child1, Child2]이다
      And Parent의 depth는 0, hasChildren은 true이다
      And Child1/Child2의 depth는 1, parentDef.item은 Parent이다

    Scenario: 단일 아이템 토글
      Given expandedItems가 []이다
      When toggle(Parent)를 호출한다
      Then expandedItems에 Parent가 추가된다
      When toggle(Parent)를 다시 호출한다
      Then expandedItems에서 Parent가 제거된다

    Scenario: 전체 펼치기/접기
      Given hasExpandable이 true이다
      And isAllExpanded가 false이다
      When toggleAll()을 호출한다
      Then 모든 expandable 아이템이 expandedItems에 추가된다
      And isAllExpanded가 true이다
      When toggleAll()을 다시 호출한다
      Then expandedItems가 빈 배열이 된다
      And isAllExpanded가 false이다

    Scenario: 가시성 판단
      Given Parent → Child → Grandchild 3단계 계층이 있다
      And expandedItems에 Parent만 포함되어 있다
      When isVisible(Child)를 확인한다
      Then true이다 (부모 Parent가 expanded)
      When isVisible(Grandchild)를 확인한다
      Then false이다 (부모 Child가 expanded 아님)

    Scenario: 아이템 정의 조회
      Given Parent 아이템이 존재한다
      When def(Parent)를 호출한다
      Then item, depth, hasChildren, parentDef를 포함하는 정의 객체가 반환된다
```

## 구현계획

### 배경

v12 sd-angular의 list(2), collapse(2) 컴포넌트와 SdExpandingManager 유틸리티를 v14 Angular 21 환경으로 마이그레이션한다. v14에는 SdRippleDirective, SdEventsDirective(sdResize), NgIcon(tabler), SdAnchorControl이 이미 구현되어 있다.

### 목표

- SdCollapseControl, SdCollapseIconControl 컴포넌트 구현
- SdListControl, SdListItemControl 컴포넌트 구현
- useExpandingManager 유틸리티 함수 구현
- 각 컴포넌트의 테스트 fixture 및 spec 작성
- index.ts에 export 등록

### 비목표

- SdPaginationControl (Feature 4.1.1에서 별도 구현)
- SdSelectionManager/SdSortingManager (Feature 6.1에서 구현)
- 모바일 테마 CSS `.sd-theme-mobile` (D3: 제거)

#### v14 치환 매핑

| v12 | v14 |
|-----|-----|
| `transformBoolean` | `booleanAttribute` |
| `$signal()` | `signal()` |
| `$computed()` | `computed()` |
| `$effect()` | `effect()` |
| `forwardRef(() => SdListControl)` | `SdListControl` (D2: 직접 참조) |
| `.sd-theme-mobile > sd-list-item` | 제거 (D3) |
| `class SdExpandingManager` | `function useExpandingManager` (D1) |

#### useExpandingManager API

```typescript
function useExpandingManager<T>(binding: {
  items: Signal<T[]>;
  expandedItems: WritableSignal<T[]>;
  getChildrenFn: Signal<((item: T, index: number) => T[] | undefined) | undefined>;
  sort: (items: T[]) => T[];
}): {
  displayItems: Signal<T[]>;
  hasExpandable: Signal<boolean>;
  isAllExpanded: Signal<boolean>;
  toggle(item: T): void;
  toggleAll(): void;
  isVisible(item: T): boolean;
  def(item: T): IExpandItemDef<T>;
}

interface IExpandItemDef<T> {
  item: T;
  parentDef: IExpandItemDef<T> | undefined;
  hasChildren: boolean;
  depth: number;
}
```

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| class SdExpandingManager | 미채택 | v14에 class 매니저 패턴 전례 없음, use* 함수 패턴이 일관적 |
| @angular/animations으로 collapse | 미채택 | CSS transition + margin-top으로 충분, 외부 모듈 추가 불필요 |
| contentChild에 forwardRef 유지 | 미채택 | v14 standalone 컴포넌트에서 불필요 |
