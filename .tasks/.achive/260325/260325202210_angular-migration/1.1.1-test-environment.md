## 구현계획

### 배경

현재 `packages/angular/tests/`의 6개 테스트 파일이 전부 `readFileSync`로 소스 파일을 읽어 문자열 패턴만 확인하는 방식이다. 이는 실제 동작을 검증하지 않으므로 Angular TestBed 기반의 실제 인스턴스 테스트로 교체한다.

### 목표

- Vitest browser 환경에서 Angular TestBed 동작 확인
- EventManagerPlugin, 커맨드 플러그인, 에러 핸들러, 테마 프로바이더 테스트를 실제 인스턴스 기반으로 교체
- 설정 파일 검증 테스트(package-setup, theme-styles)는 readFileSync 유지

### 비목표

- SdEventsDirective 단독 테스트 (D3: 통합 테스트에서 검증)
- 컴포넌트 렌더링 테스트 (서비스/플러그인만)
- E2E 테스트

### 설계

#### 의존성 추가

`packages/angular/package.json` devDependencies:
- `@angular/compiler`: `"^21.0.0"`
- `@angular/platform-browser-dynamic`: `"^21.0.0"`

#### Vitest setup 파일

`packages/angular/tests/vitest.setup.ts`:
- `initTestEnvironment(BrowserDynamicTestingModule, platformBrowserDynamicTesting())` 호출
- 각 테스트 전 `TestBed.resetTestingModule()` (afterEach)

#### vitest.config.ts 조정

- browser 프로젝트에서 angular 테스트용 setup 파일 연결
- node 프로젝트에서 angular TestBed 테스트 제외 (readFileSync 테스트만 실행)

#### 테스트 파일 분리

| 파일 | 환경 | 방식 |
|------|------|------|
| package-setup.spec.ts | node | readFileSync 유지 |
| theme-styles.spec.ts | node | readFileSync 유지 |
| theme-provider.spec.ts | browser | TestBed.inject → signal 동작 검증 |
| event-plugins.spec.ts | browser | TestBed.inject → supports()/addEventListener() |
| command-plugins.spec.ts | browser | TestBed.inject → KeyboardEvent dispatch |
| error-handler.spec.ts | browser | TestBed.inject → handleError() + DOM 검증 |

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| Angular TestBed (D1) | 채택 | Angular 공식 테스트 방식, inject() 컨텍스트 제공 |
| vi.mock()으로 inject() 우회 | 미채택 | Angular DI 실제 동작 미검증, 구현에 결합 |
| runInInjectionContext() 직접 사용 | 미채택 | parent injector 필요, TestBed가 더 간편 |
