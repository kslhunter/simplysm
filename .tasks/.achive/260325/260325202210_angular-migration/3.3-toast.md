# Feature 3.3 토스트

## 참조 자료

- [wbs.md](./wbs.md)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | ARIA 접근성 | 심각도별 role/aria-live 속성 추가 | info/success → role="status" + aria-live="polite", warning/danger → role="alert" + aria-live="assertive". 스크린 리더 지원 |
| D2 | 동적 컴포넌트 바인딩 패턴 | model() + 인스턴스 직접 접근 | v12의 inputBinding() 대신, v14 modal 패턴(setInput + model)과 일관. 단순하고 명시적 |
| D3 | progress effect 수명 관리 | effect({ injector: toastRef.injector }) | 토스트 destroy 시 effect 자동 정리. appRef.injector 사용 시 누수 위험 |

## 구현계획

### 배경

v12 토스트 시스템(3파일: provider, control, container)을 v14 Angular 21로 마이그레이션한다. v14에는 이미 modal/dropdown의 overlay 패턴(`createComponent` + `setInput()` + `model()` 직접 접근)이 존재하며, 동일한 패턴을 따른다.

### 목표

- v12 토스트의 모든 기능을 v14 컨벤션으로 포팅
- ARIA 접근성 추가 (D1)
- v14 API 치환: `$signal`→`signal()`, `$effect`→`effect()`, `transformBoolean`→`booleanAttribute`, `inputBinding`→`model()` 직접 접근 (D2)

### 비목표

- 자동 해제 시간 커스터마이징 (3s/5s/1s 하드코딩 유지)
- `prefers-reduced-motion` 지원 (별도 전역 Feature에서 고려)

### 설계

#### 파일 구조

```
src/ui/overlay/toast/
  sd-toast.provider.ts          — SdToastProvider (@Injectable root)
  sd-toast.control.ts           — SdToastControl (@Component)
  sd-toast-container.control.ts — SdToastContainerControl (@Component)
  sd-toast-test.fixture.ts      — 테스트 Fixture 컴포넌트
tests/
  toast-control.spec.ts
  toast-provider.spec.ts
```

#### SdToastControl

| 프로퍼티 | 종류 | 타입 | 설명 |
|---------|------|------|------|
| `open` | `model` | `boolean` | 표시 여부 — provider가 직접 set |
| `useProgress` | `input` | `boolean` (booleanAttribute) | 프로그래스 바 표시 |
| `theme` | `input` | `TSdToastTheme` | 테마 색상 |
| `progress` | `model` | `number` | 진행률 — provider가 직접 set |
| `message` | `model` | `string \| undefined` | 메시지 — provider가 직접 set |

- host: `[attr.data-sd-open]`, `[attr.data-sd-theme]`, `[attr.role]`→computed, `[attr.aria-live]`→computed
- ARIA (D1): info/success → `role="status"` + `aria-live="polite"`, warning/danger → `role="alert"` + `aria-live="assertive"`, 그 외 → 없음
- SCSS: v12 스타일 유지 (theme iteration, slide-in/out, elevation(12), 520px 반응형)

#### SdToastContainerControl

| 프로퍼티 | 종류 | 타입 | 설명 |
|---------|------|------|------|
| `overlap` | `input` | `boolean` (booleanAttribute) | 기존 토스트 교체 모드 |

- SCSS: fixed positioning, z-index-toast, flex column, 520px column-reverse

#### SdToastProvider

- `alertThemes`: `WritableSignal<TSdToastSeverity[]>` — 네이티브 alert() 사용 심각도 목록
- `overlap`: `WritableSignal<boolean>` — overlap 모드 (container에 `setInput`으로 동기화)
- `beforeShowFn?`: 토스트 표시 전 콜백
- `containerRef` getter: lazy creation + body append + appRef.attachView
- `_show()`: `createComponent(SdToastControl)` → `setInput`(theme, useProgress) → `instance.open/progress/message` 직접 접근 → `repaint()` → `open.set(true)` → auto-dismiss setTimeout(3s) / progress effect(D3)
- `notify()`: `createComponent(사용자 타입)` → `setInput` → `SdToastControl` 래퍼 → `outputToObservable(close)` 구독 → 5s auto-dismiss
- `try()`: async/sync overload, Error 시 `danger()` + `SdSystemLogProvider.writeAsync("error", stack)`, 비-Error re-throw

#### 타입 정의 (provider 파일 내 export)

```typescript
type TSdToastSeverity = "info" | "success" | "warning" | "danger";
type TSdToastTheme = "primary" | "secondary" | TSdToastSeverity | "gray" | "blue-gray";

interface ISdToast<O> { close: OutputEmitterRef<O | undefined>; }
interface ISdToastInput<T extends ISdToast<any>> {
  type: Type<T>;
  inputs: Omit<TDirectiveInputSignals<T>, "close">;
}
```

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| `inputBinding()` reactive 바인딩 (v12 방식) | 미채택 | v14 modal이 `setInput()` + `model()` 패턴 사용, 코드베이스 일관성 |
| `model()` + 인스턴스 직접 접근 | **채택** | v14 modal 패턴과 동일, 단순하고 명시적 |
| progress effect: `toastRef.injector` | **채택** | 토스트 destroy 시 effect 자동 정리 |
| progress effect: `appRef.injector` | 미채택 | 토스트 destroy 후 effect 누수 위험 |
