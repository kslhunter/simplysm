# Feature 5.3 모달 선택 및 상태 프리셋

## 참조 자료

- [wbs.md](./wbs.md)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | ISdSelectModal/TSdSelectModalInfo 타입 배치 위치 | sd-modal-select-button.control.ts에 함께 정의 | ISdSelectModal은 ISdModal의 소비자 측 확장이므로 sd-modal.provider.ts가 알 필요 없음. v12 패턴(소비자 파일에 정의)과 동일 |
| D2 | SdStatePresetControl의 prompt()/confirm() 방식 | 커스텀 모달로 교체 | 네이티브 대화상자 대신 SdModalProvider 기반 커스텀 프롬프트/확인 모달 사용 |
| D3 | 커스텀 프롬프트/확인 모달 구현 방식 | ISdModal 구현 독립 컴포넌트 (ui/overlay/modal/) | showAsync()가 충분히 범용적이므로 Provider 확장 불필요. 기존 모달 코드와 동일 위치 |
| D4 | SdStatePresetControl의 설정 저장 방식 | useSdSystemConfigResource 활용 | v14 resource() 기반 반응형 패턴. elTag="sd-state-preset"으로 v12와 동일한 키 패턴 |

      And selectedItems에 선택된 항목 객체가 반영된다

      When 검색 버튼을 클릭한다

      Then value에 선택된 항목 키의 배열이 반영된다

    Scenario: single 모드에서 선택 취소

      And required가 false이다
      When 취소(eraser) 버튼을 클릭한다
      Then value가 undefined로 설정된다

    Scenario: multi 모드에서 선택 취소

      And required가 false이다
      When 취소(eraser) 버튼을 클릭한다
      Then value가 빈 배열로 설정된다

      Given sd-modal-select-button이 disabled true로 설정되어 있다

## 구현계획

### 배경

v12의 SdModalSelectButtonControl(모달 기반 항목 선택 버튼)과 SdStatePresetControl(상태 프리셋 CRUD)을 v14로 마이그레이션한다. 기반 인프라(SdModalProvider, SdSystemConfigProvider, SdToastProvider, setupInvalid, SdAdditionalButtonControl)는 이미 v14에 존재한다. v12→v14 Signal API 변환($signal→signal, $computed→computed, $effect→effect, transformBoolean→booleanAttribute)과 함께, D2에 따라 네이티브 prompt()/confirm()을 커스텀 모달로 교체한다.

### 목표

- SdModalSelectButtonControl 마이그레이션 (모달 기반 항목 선택 버튼, single/multi 모드)
- ISdSelectModal/TSdSelectModalInfo/ISelectModalOutputResult 타입 정의 (D1: 버튼 파일에 배치)
- SdPromptModalControl, SdConfirmModalControl 생성 (D2/D3: 범용 커스텀 모달)
- SdStatePresetControl 마이그레이션 (D4: useSdSystemConfigResource 활용, 커스텀 모달)

### 비목표

- AbsSdDataSelectButton, SdDataSelectButtonControl (Feature 7.2)
- SdSharedDataSelect* 컴포넌트들 (Feature 7.3)

### 설계

#### SdModalSelectButtonControl

파일: `packages/angular/src/ui/form/button/sd-modal-select-button.control.ts`

v12→v14 변환:
- 제너릭 `<T, K, M>` → `<T extends object>` (v14 TSelectModeValue가 단순 union이므로 M 제거)
- `value: model<TSelectModeValue<K>[M]>()` → `value: model<TSelectModeValue<any>>()`
- selectMode를 런타임 분기로 처리 (single→단일값, multi→배열)
- `transformBoolean` → `booleanAttribute`
- `$computed` → `computed`
- `.filterExists()` → `@simplysm/core-common` Array 확장 메서드

타입 (같은 파일에 정의):
- `ISdSelectModal<T>`: ISdModal을 확장, selectMode + selectedItemKeys InputSignal 추가
- `TSdSelectModalInfo<T>`: ISdModalInfo에서 selectMode/selectedItemKeys를 제외한 inputs
- `ISelectModalOutputResult<T>`: selectedItemKeys + selectedItems

#### SdPromptModalControl

파일: `packages/angular/src/ui/overlay/modal/sd-prompt-modal.control.ts`

ISdModal<string> 구현. inputs: message(required). 내부 텍스트 입력 + 확인/취소 버튼. 확인 시 입력값 emit, 취소 시 undefined emit.

#### SdConfirmModalControl

파일: `packages/angular/src/ui/overlay/modal/sd-confirm-modal.control.ts`

ISdModal<boolean> 구현. inputs: message(required). 메시지 표시 + 확인/취소 버튼. 확인 시 true emit, 취소 시 undefined emit.

#### SdStatePresetControl

파일: `packages/angular/src/ui/form/choice/sd-state-preset.control.ts`

v12→v14 변환:
- `$signal` → `signal`, `$effect` → useSdSystemConfigResource의 반응형 로드로 대체
- `prompt()` → `SdModalProvider.showAsync(SdPromptModalControl)`
- `confirm()` → `SdModalProvider.showAsync(SdConfirmModalControl)`
- 저장: `useSdSystemConfigResource.update()` (내부적으로 setAsync + signal 갱신)
- v12의 `SdSystemConfigProvider.getAsync("sd-state-preset.{key}")` → useSdSystemConfigResource가 elTag로 자동 네임스페이싱

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| ISdSelectModal을 sd-modal.provider.ts에 배치 | 미채택 | 의존 방향 위반 — sd-modal은 select-modal을 알 필요 없음 (D1) |
| SdModalProvider에 promptAsync/confirmAsync 편의 메서드 추가 | 미채택 | showAsync()가 충분히 범용적, 별도 컴포넌트가 더 일관적 (D3) |
| SdSystemConfigProvider 직접 사용 | 미채택 | useSdSystemConfigResource가 v14 resource 패턴에 맞음 (D4) |
