# Feature 4.4 톱바

## 참조 자료

- [wbs.md](./wbs.md)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | v14 컴포넌트 host 스타일 패턴 | host class 유틸리티 그대로 사용 | sidebar-menu 선례: `host: { "class": "flex-column fill" }` |
| D2 | v12 querystring 모듈 대체 | Object.fromEntries(new URLSearchParams()) | sidebar D2 동일 결정, Node.js 의존성 제거 |
| D3 | v14 SdListItemControl에 contentClass/contentStyle 미존재 | depth 0: `[style.padding-block]` host binding, depth>0: `[style.padding-left.em]` host binding | topbar sd-list가 dropdown-popup 안에 있어 sidebar의 host `>` SCSS 선택자 사용 불가 |
| D4 | v12 $computed 커스텀 래퍼 | Angular 네이티브 computed() | WBS Impact Mapping 결정 사항 |

## 요구명세

```gherkin
Feature: 4.4 톱바

  Background:
    Given 앱이 sd-topbar-container > sd-topbar 구조로 렌더링되어 있다

  Rule: 톱바 컨테이너가 수직 레이아웃으로 콘텐츠를 감싼다

    Scenario: sd-topbar-container 안에 sd-topbar와 콘텐츠가 수직으로 배치된다
      Given sd-topbar-container 안에 sd-topbar와 메인 콘텐츠가 있다
      Then display: flex, flex-direction: column으로 렌더링된다
      And height: 100%로 전체 높이를 차지한다

  Rule: 사이드바가 있으면 톱바에 토글 버튼이 표시된다

    Scenario: SdSidebarContainerControl이 부모에 있으면 토글 버튼이 표시된다
      Given sd-topbar의 조상에 sd-sidebar-container가 있다
      Then 햄버거(tablerMenu2) 아이콘 버튼이 표시된다

    Scenario: sidebarContainer input으로 외부 사이드바를 연결하면 토글 버튼이 표시된다
      Given sidebarContainer input에 SdSidebarContainerControl 인스턴스가 전달되었다
      Then 햄버거 아이콘 버튼이 표시된다

    Scenario: 사이드바가 없으면 토글 버튼이 숨겨진다
      Given sd-topbar의 조상에 sd-sidebar-container가 없다
      And sidebarContainer input이 미지정이다
      Then 햄버거 아이콘 버튼이 표시되지 않는다

    Scenario: 토글 버튼 클릭 시 사이드바 toggle이 반전된다
      Given 사이드바가 연결되어 있다
      And sidebar toggle이 false이다
      When 햄버거 버튼을 클릭한다
      Then sidebar toggle이 true가 된다

  Rule: 드롭다운 기반 계층 메뉴를 표시한다

    Scenario: 최상위 메뉴마다 드롭다운 버튼이 생성된다
      Given menus에 최상위 메뉴 3개가 있다
      Then 3개의 드롭다운 버튼이 가로로 나열된다

    Scenario: 드롭다운 버튼에 캐럿 다운 아이콘이 표시된다
      Given 최상위 메뉴가 렌더링되어 있다
      Then 각 드롭다운 버튼에 tablerCaretDown 아이콘이 표시된다

    Scenario: 메뉴에 아이콘이 있으면 제목 앞에 표시된다
      Given 메뉴의 icon 프로퍼티가 설정되어 있다
      Then ng-icon으로 아이콘이 표시되고 그 뒤에 제목이 표시된다

    Scenario: 하위 메뉴가 있으면 재귀 렌더링된다
      Given 메뉴에 children 배열이 있다
      Then 중첩된 sd-list 안에 하위 메뉴가 렌더링된다
      And 하위 메뉴의 배경색은 trans-lightest이다

    Scenario: depth에 따라 들여쓰기가 적용된다
      Given depth 2인 메뉴 항목이 있다
      Then padding-left가 (2+1)*0.5 = 1.5em이 적용된다

    Scenario: depth 0 항목에 기본 수직 패딩이 적용된다
      Given depth 0인 메뉴 항목이 있다
      Then 기본 수직 패딩(padding-block: var(--gap-default))이 적용된다

  Rule: 메뉴 항목은 라우터 링크 또는 외부 URL로 연결된다

    Scenario: children과 url이 없는 메뉴는 라우터 링크로 연결된다
      Given 메뉴의 children이 없고 url이 없다
      And codeChain이 ["module", "page"]이다
      Then sd-router-link에 "/home/module/page"가 설정된다

    Scenario: codeChain에 쿼리스트링이 포함되면 queryParams로 분리된다
      Given codeChain의 마지막 항목이 "page?key=value"이다
      Then 라우터 링크는 "/home/module/page"이고 queryParams는 {key: "value"}이다

    Scenario: url이 있는 메뉴 클릭 시 새 탭에서 열린다
      Given 메뉴의 url이 "https://example.com"이다
      When 메뉴를 클릭한다
      Then window.open("https://example.com", "_blank")이 호출된다

    Scenario: children이 있는 메뉴는 라우터 링크가 없다
      Given 메뉴에 children 배열이 있다
      Then sd-router-link가 undefined이다

    Scenario: 현재 페이지와 일치하는 메뉴가 선택 상태로 표시된다
      Given 현재 fullPageCode가 "module.page"이다
      And 메뉴의 codeChain이 ["module", "page"]이다
      Then 해당 메뉴의 selected가 true이다

    Scenario: 커스텀 선택 함수가 제공되면 해당 함수로 선택 상태를 판단한다
      Given getMenuIsSelectedFn이 제공되어 있다
      When 메뉴의 선택 상태를 판단한다
      Then getMenuIsSelectedFn(menu) 반환값을 사용한다

    Scenario: 메뉴 클릭 시 드롭다운이 닫힌다
      Given 드롭다운이 열려있고 메뉴 항목이 표시되어 있다
      When 메뉴 항목을 클릭한다
      Then 드롭다운의 open이 false가 된다

  Rule: 사용자 드롭다운 메뉴를 표시한다

    Scenario: ng-content로 사용자 정보가 드롭다운 트리거에 표시된다
      Given sd-topbar-user 안에 "홍길동" 텍스트가 있다
      Then 인라인 link-gray 테마 버튼에 "홍길동"이 표시된다

    Scenario: 사용자 버튼 클릭 시 메뉴 목록이 표시된다
      Given menus에 항목 2개가 있다
      When 사용자 버튼을 클릭한다
      Then 드롭다운 팝업 안에 2개의 메뉴 항목이 표시된다

    Scenario: 메뉴 항목 클릭 시 onClick 콜백이 실행된다
      Given 메뉴가 열려있고 "로그아웃" 항목이 있다
      When "로그아웃" 항목을 클릭한다
      Then 해당 항목의 onClick 함수가 호출된다
      And 드롭다운이 닫힌다
```

## 구현계획

### 배경

v12의 톱바 네비게이션 시스템(4개 컴포넌트)을 v14 Angular 21 패턴으로 마이그레이션한다. v14에는 SCSS 변수(`--topbar-height: 3em`)와 의존 컴포넌트(SdDropdown, SdList, SdButton, sd-router-link 등)가 이미 마이그레이션되어 있다. 같은 Epic 4의 sidebar(4.3)가 이미 완료되어 마이그레이션 패턴이 확립되었다.

### 목표

- SdTopbarContainerControl, SdTopbarControl, SdTopbarMenuControl, SdTopbarUserControl 4개 컴포넌트 마이그레이션
- v14 signal API 및 의존 컴포넌트와 통합
- 드롭다운 기반 계층 메뉴, 사이드바 토글 연동 동작 유지

### 비목표

- 사이드바 컴포넌트 변경 (Feature 4.3에서 완료)
- 새로운 톱바 기능 추가 (마이그레이션 범위)

### 설계

#### 컴포넌트 구조

```
packages/angular/src/ui/navigation/topbar/
├── sd-topbar-container.control.ts  # flex column 컨테이너
├── sd-topbar.control.ts            # 사이드바 토글, 콘텐츠 프로젝션
├── sd-topbar-menu.control.ts       # 드롭다운 계층 메뉴, 라우팅
└── sd-topbar-user.control.ts       # 사용자 드롭다운 메뉴
```

#### v12 → v14 변환 매핑

| v12 | v14 |
|-----|-----|
| `$computed(() => ...)` | `computed(() => ...)` |
| `host: { class: "flex-row ..." }` | 동일 유지 (sidebar-menu 선례) |
| `querystring.parse(q)` | `Object.fromEntries(new URLSearchParams(q))` |
| `[contentClass]="'pv-default'"` | `[style.padding-block]="depth === 0 ? 'var(--gap-default)' : undefined"` |
| `[contentStyle]="'padding-left: ...'"` | `[style.padding-left.em]="(depth + 1) * 0.5"` |

#### API

| 컴포넌트 | Input | Public 프로퍼티 | 기타 |
|----------|-------|---------------|------|
| SdTopbarContainerControl | — | — | 순수 레이아웃 |
| SdTopbarControl | `sidebarContainer` | `hasSidebar: Signal<boolean>` | SdSidebarContainerControl optional inject |
| SdTopbarMenuControl | `menus`, `getMenuIsSelectedFn` | `fullPageCode: Signal<string>` | useFullPageCodeSignal, ISdTopbarMenu |
| SdTopbarUserControl | `menus` (required) | — | ng-content |

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| host class 유틸리티 → SCSS 직접 정의 | 미채택 | sidebar-menu가 host class 유틸리티를 사용하는 선례 확인 |
| depth 0 padding → SCSS `>` 선택자 | 미채택 | sd-list가 dropdown-popup 안에 있어 host 직접 자식 선택자 사용 불가 |
| contentClass/contentStyle input 추가 | 미채택 | v14 SdListItemControl API 변경 최소화 (sidebar D1) |
