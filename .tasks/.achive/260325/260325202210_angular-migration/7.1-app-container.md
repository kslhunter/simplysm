## 요구명세

```gherkin
Feature: 7.1 앱 컨테이너

  Background:
    Given v14 Angular 패키지가 초기화되어 있다
    And SdBusyContainerControl, SdTopbarContainerControl, SdTopbarControl이 사용 가능하다
    And SdAppStructureProvider가 앱 구조를 제공한다

  Rule: 뷰 타입별 레이아웃 렌더링

    Scenario: page 뷰 타입일 때 topbar 레이아웃 표시
      Given SdBaseContainerControl이 page 뷰 타입 컨텍스트에서 렌더링된다
      When 컨테이너가 초기화된다
      Then topbar-container 안에 topbar(제목 + pageTopbarTplRef)와 content가 표시된다

    Scenario: modal 뷰 타입일 때 flex 레이아웃 표시
      Given SdBaseContainerControl이 modal 뷰 타입 컨텍스트에서 렌더링된다
      When 컨테이너가 초기화된다
      Then flex-column 레이아웃으로 content가 표시된다
      And modalBottomTplRef가 제공되면 하단 영역이 상단 테두리와 함께 표시된다

    Scenario: control 뷰 타입일 때 content만 표시
      Given SdBaseContainerControl이 control 뷰 타입 컨텍스트에서 렌더링된다
      When 컨테이너가 초기화된다
      Then content만 표시되고 레이아웃 크롬은 없다

    Scenario: viewType 입력으로 뷰 타입 강제 지정
      Given SdBaseContainerControl에 viewType="modal" 입력이 지정되어 있다
      And 부모 컴포넌트의 뷰 타입은 "page"이다
      When 컨테이너가 초기화된다
      Then modal 레이아웃이 표시된다

  Rule: 권한 제한 시 접근 차단 UI 표시

    Scenario: restricted=true일 때 권한 없음 안내
      Given SdBaseContainerControl에 restricted=true가 지정되어 있다
      When 컨테이너가 초기화된다
      Then 경고 아이콘과 "'{타이틀}'에 대한 사용권한이 없습니다" 메시지가 표시된다
      And 컨텐츠는 표시되지 않는다

    Scenario: restricted=false일 때 정상 렌더링
      Given SdBaseContainerControl에 restricted=false가 지정되어 있다
      When 컨테이너가 초기화된다
      Then 뷰 타입에 따른 정상 레이아웃이 표시된다

  Rule: 타이틀 결정 우선순위

    Scenario: header 입력이 지정된 경우
      Given SdBaseContainerControl에 header="커스텀 제목"이 지정되어 있다
      When topbar 또는 restricted 메시지에서 타이틀을 표시한다
      Then "커스텀 제목"이 표시된다

    Scenario: header 미지정이고 모달 컨텍스트인 경우
      Given SdBaseContainerControl에 header가 지정되지 않았다
      And 모달 컨텍스트에서 모달 제목이 "주문 상세"이다
      When 타이틀을 표시한다
      Then "주문 상세"가 표시된다

    Scenario: header 미지정이고 페이지 컨텍스트인 경우
      Given SdBaseContainerControl에 header가 지정되지 않았다
      And 현재 페이지 코드가 "admin.user.manage"이다
      When 타이틀을 표시한다
      Then SdAppStructureProvider.getTitleByFullCode로 결정된 제목이 표시된다

  Rule: 초기화 상태에 따른 컨텐츠 표시 제어

    Scenario: initialized 미지정(undefined)이면 정상 렌더링
      Given SdBaseContainerControl에 initialized가 지정되지 않았다
      When 컨테이너가 렌더링된다
      Then 정상적으로 컨텐츠가 표시된다

    Scenario: initialized=true이면 정상 렌더링
      Given SdBaseContainerControl에 initialized=true가 지정되어 있다
      When 컨테이너가 렌더링된다
      Then 정상적으로 컨텐츠가 표시된다

    Scenario: initialized=false이면 컨텐츠 숨김
      Given SdBaseContainerControl에 initialized=false가 지정되어 있다
      When 컨테이너가 렌더링된다
      Then busy 컨테이너만 표시되고 컨텐츠는 숨겨진다

  Rule: injectParent 유틸리티

    Scenario: 타입 없이 호출하면 가장 가까운 부모 반환
      Given 자식 컴포넌트가 부모 컴포넌트 안에 렌더링되어 있다
      When injectParent()를 호출한다
      Then 가장 가까운 부모 컴포넌트 인스턴스가 반환된다

    Scenario: 특정 타입으로 호출하면 해당 타입 부모까지 순회
      Given ParentA > ParentB > Child 계층 구조가 있다
      And ParentA는 TargetType 인스턴스이다
      When injectParent(TargetType)을 호출한다
      Then TargetType인 ParentA가 반환된다

    Scenario: optional=true이고 해당 부모가 없으면 undefined 반환
      Given 컴포넌트 트리에 TargetType 부모가 없다
      When injectParent(TargetType, { optional: true })을 호출한다
      Then undefined가 반환된다

    Scenario: optional 미지정이고 해당 부모가 없으면 에러 발생
      Given 컴포넌트 트리에 TargetType 부모가 없다
      When injectParent(TargetType)을 호출한다
      Then "부모 컴포넌트를 찾을 수 없습니다" 에러가 발생한다
```

## 구현계획

### 배경

v14 Angular 패키지에 core(프로바이더/유틸/디렉티브/플러그인)와 ui(data/form/layout/navigation/overlay/visual) 구조가 확립되어 있다. 모든 의존성(SdBusyContainerControl, SdTopbar*, useViewTypeSignal, SdActivatedModalProvider, SdAppStructureProvider 등)이 구현 완료되어 있다. Feature 7.1은 부모 컴포넌트 접근 유틸리티(`injectParent`)와 페이지/모달 공통 컨테이너(`SdBaseContainerControl`)를 추가한다.

### 목표

- `injectParent` 유틸리티 함수 (typed/untyped/optional 오버로드)
- `SdBaseContainerControl` 컴포넌트 (뷰 타입별 레이아웃, 권한 제한 UI, 타이틀 결정, 초기화 상태)
- 테스트 및 index.ts 등록

### 비목표

- Feature 7.2 data-view 컴포넌트 (SdDataSheetControl, SdDataDetailControl 등)
- Feature 7.4 권한 매트릭스 편집 UI
- `usePermsSignal` (Feature 1.8에서 구현 완료)

### 설계

#### injectParent (`src/core/utils/injectParent.ts`)

- `ViewContainerRef.injector`에서 시작, `_lView[CONTEXT=8]`로 컴포넌트 인스턴스 접근
- `Injector.get(Injector, undefined, { skipSelf: true, optional: true })`로 injector 트리 상위 순회
- 오버로드 3종: `injectParent()` → any, `injectParent(type)` → T, `injectParent(type, { optional: true })` → T | undefined
- 부모 없으면 에러 throw (optional 제외)

#### SdBaseContainerControl (`src/features/base/sd-base-container.control.ts`)

- v12 → v14 치환: `$computed` → `computed`, `transformBoolean` → `booleanAttribute` (restricted/busy)
- `initialized`: 3-state 유지 → `input<boolean | undefined>(undefined)` (booleanAttribute 미사용)
- 뷰 타입: `injectParent()` + `useViewTypeSignal(() => parent)`, `viewType` input이 우선
- 타이틀: `computed(() => header() ?? activatedModal?.modalComponent()?.title() ?? appStructure.getTitleByFullCode(...))`
- 템플릿: `@if`/`@else` 제어 흐름, `NgTemplateOutlet`으로 contentTplRef/pageTopbarTplRef/modalBottomTplRef 투영
- imports: SdBusyContainerControl, SdTopbarContainerControl, SdTopbarControl, NgTemplateOutlet, NgIcon

### 대안 검토

| 접근 방식 | 선택 | 이유 |
|-----------|------|------|
| `_lView[8]` 직접 접근 | 채택 | D1 결정. Angular 9~21에서 7년+ 안정 |
| 토큰 기반 DI | 미채택 | 범용성 부족, 보일러플레이트 |
| features/ 디렉토리 | 채택 | D2 결정. ui/와 features/ 구분, Epic 7 일관성 |
