```gherkin
Feature: 3.4 비지 인디케이터

  Background:
    Given Angular 앱이 provideSdAngular로 초기화되어 있다
    And SdBusyProvider가 root에 주입되어 있다

  Rule: 전역 busy 카운팅으로 로딩 상태를 관리한다

    Scenario: globalBusyCount 0→1 증가 시 전역 busy 활성화
      Given globalBusyCount가 0이다
      When globalBusyCount가 1로 증가한다
      Then body에 추가된 sd-busy-container의 busy가 true가 된다
      And 인디케이터 UI가 표시된다

    Scenario: globalBusyCount 1→0 감소 시 전역 busy 비활성화
      Given globalBusyCount가 1이다
      When globalBusyCount가 0으로 감소한다
      Then sd-busy-container의 busy가 false가 된다
      And 인디케이터 UI가 숨겨진다

    Scenario: 동시 비동기 작업의 카운팅
      Given 비동기 작업 A가 count를 1로 올렸다
      When 비동기 작업 B가 count를 2로 올린다
      And 작업 A가 완료되어 count가 1로 감소한다
      Then 전역 busy는 여전히 활성화 상태이다
      When 작업 B가 완료되어 count가 0으로 감소한다
      Then 전역 busy가 비활성화된다

  Rule: 로컬 busy 컨테이너로 특정 영역에 로딩 표시를 한다

    Scenario: busy=true로 영역 인디케이터 표시
      Given sd-busy-container가 콘텐츠를 감싸고 있다
      When busy input이 true로 설정된다
      Then 해당 영역에 인디케이터가 표시된다

    Scenario: busy=false로 인디케이터 숨김
      Given sd-busy-container의 busy가 true이다
      When busy input이 false로 변경된다
      Then 인디케이터가 숨겨진다

    Scenario: message input으로 메시지 표시
      Given sd-busy-container의 busy가 true이다
      When message input에 "저장 중..."이 설정된다
      Then 인디케이터 아래에 "저장 중..." 메시지가 표시된다

    Scenario: progressPercent input으로 진행률 바 표시
      Given sd-busy-container의 busy가 true이다
      When progressPercent input에 50이 설정된다
      Then 진행률 바가 50% 위치에 표시된다

  Rule: 인디케이터 타입을 선택할 수 있다

    Scenario: spinner 타입 선택
      Given sd-busy-container의 busy가 true이다
      When type input이 "spinner"로 설정된다
      Then 회전 원형 인디케이터가 표시된다

    Scenario: bar 타입 선택 (기본값)
      Given sd-busy-container의 busy가 true이다
      When type input이 지정되지 않는다
      Then SdBusyProvider의 기본 type인 "bar" 인디케이터가 표시된다

    Scenario: cube 타입 선택
      Given sd-busy-container의 busy가 true이다
      When type input이 "cube"로 설정된다
      Then 4분할 큐브 회전 애니메이션 인디케이터가 표시된다

  Rule: busy 상태에서 사용자 인터랙션을 차단한다

    Scenario: busy 상태에서 키보드 입력 차단
      Given sd-busy-container의 busy가 true이다
      When 사용자가 키보드를 입력한다
      Then keydown 이벤트가 preventDefault + stopPropagation으로 차단된다

    Scenario: 전역 busy에서 마우스 클릭 차단
      Given globalBusyCount가 0보다 크다
      Then 전역 sd-busy-container의 pointerEvents가 "auto"로 설정되어 클릭이 차단된다

    Scenario: busy 해제 시 인터랙션 복원
      Given globalBusyCount가 0이다
      Then 전역 sd-busy-container의 pointerEvents가 "none"으로 설정되어 클릭이 통과한다

  Rule: 라우터 네비게이션 시 전역 busy를 표시한다

    Scenario: NavigationStart 시 busy 활성화
      Given globalBusyCount가 0이다
      When Router에서 NavigationStart 이벤트가 발생한다
      Then globalBusyCount가 1로 증가한다
      And 전역 busy가 활성화된다

    Scenario: NavigationEnd 시 busy 비활성화
      Given NavigationStart로 globalBusyCount가 1이 되었다
      When Router에서 NavigationEnd 이벤트가 발생한다
      Then globalBusyCount가 0으로 감소한다
      And 전역 busy가 비활성화된다

    Scenario: NavigationCancel 시 busy 비활성화
      Given NavigationStart로 globalBusyCount가 1이 되었다
      When Router에서 NavigationCancel 이벤트가 발생한다
      Then globalBusyCount가 0으로 감소한다

    Scenario: NavigationError 시 busy 비활성화
      Given NavigationStart로 globalBusyCount가 1이 되었다
      When Router에서 NavigationError 이벤트가 발생한다
      Then globalBusyCount가 0으로 감소한다
```

## 구현계획

### 배경

v14 `@simplysm/angular`의 overlay 카테고리에 dropdown, modal, toast가 이미 구현되어 있다. busy 인디케이터는 동일한 overlay 패턴을 따르며, v12의 `SdBusyProvider` + `SdBusyContainerControl` 구조를 v14 API(`signal`, `computed`, `effect`, `input`, `booleanAttribute`)로 마이그레이션한다.

### 목표

- `SdBusyProvider`: 전역 busy 카운팅 + 전역 컨테이너 lazy 생성
- `SdBusyContainerControl`: 3종 인디케이터(spinner/bar/cube) + 메시지 + 진행률 + 인터랙션 차단
- 라우터 네비게이션 busy: `provideSdAngular`에 initializer 추가
- SCSS: `_busy.scss` 파일 + `styles.scss`에 `@use`
- Export: `index.ts`에 busy 관련 export 추가

### 비목표

- SdPrintProvider의 busy 연동 (Feature 3.5에서 구현)
- 커스텀 인디케이터 템플릿 (v12에도 없음)

### 설계

#### SdBusyProvider (`providedIn: "root"`)

| 멤버 | 타입 | 설명 |
|------|------|------|
| `type` | `WritableSignal<"spinner" \| "bar" \| "cube">` | 전역 기본 인디케이터 타입. 초기값 `"bar"` |
| `globalBusyCount` | `WritableSignal<number>` | 전역 busy 카운터. `> 0`이면 busy |
| `containerRef` (getter) | `ComponentRef<SdBusyContainerControl>` | lazy 생성. body에 append, `position: absolute`, `pointerEvents: none` |

- constructor의 `effect()`에서 `globalBusyCount() > 0`에 따라 전역 컨테이너의 `pointerEvents`를 `"auto"` / `"none"`으로 전환
- `containerRef` getter에서 `setInput("type", ...)`, `setInput("busy", ...)`으로 바인딩. v12의 `inputBinding` 대신 effect로 반응형 바인딩 구현

#### SdBusyContainerControl

| Input | 타입 | 기본값 | 설명 |
|-------|------|--------|------|
| `busy` | `boolean` | `false` | `booleanAttribute` transform |
| `message` | `string \| undefined` | `undefined` | 메시지 표시 |
| `type` | `"spinner" \| "bar" \| "cube" \| undefined` | `undefined` | 미지정 시 Provider 기본값 사용 |
| `progressPercent` | `number \| undefined` | `undefined` | 진행률 바 (0~100) |

- `currType = computed(() => this.type() ?? inject(SdBusyProvider).type())`
- host: `[attr.data-sd-busy]`, `[attr.data-sd-type]`, `(keydown.capture)` 이벤트
- template: `._screen` > `._rect` > `._indicator` + `._message` + `._progress`

#### provideSdAngular 라우터 busy initializer

```typescript
provideAppInitializer(() => {
  const router = inject(Router, { optional: true });
  if (!router) return;
  const sdBusy = inject(SdBusyProvider);
  router.events.subscribe((event) => {
    if (event instanceof NavigationStart) {
      sdBusy.globalBusyCount.update((v) => v + 1);
    } else if (
      event instanceof NavigationEnd ||
      event instanceof NavigationCancel ||
      event instanceof NavigationError
    ) {
      sdBusy.globalBusyCount.update((v) => v - 1);
    }
  });
});
```

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| effect + setInput으로 전역 컨테이너 바인딩 | 채택 | v14에서 inputBinding 미사용, toast 패턴과 동일 |
| createComponent의 bindings 옵션 사용 | 미채택 | v14 코드베이스에서 사용하지 않는 패턴 |
