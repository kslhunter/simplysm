# Feature 1.5 이벤트 시스템

## 참조 자료

- [wbs.md](./wbs.md)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | 커맨드 플러그인 모달 감지 | Feature 3.2로 이관 | 모달 미존재 시점에서 모달 로직 구현 부적절, 관심사 분리 |
| D2 | 에러 핸들러 로그 프로바이더 | Feature 1.8로 이관, console 직접 사용 | SdSystemLogProvider는 Feature 1.8 범위 |
| D3 | .findParent() 대체 | Element.closest() 네이티브 API 사용 | v14 core-browser에 findParent 미포함, closest()는 동일 기능의 네이티브 DOM API |
| D4 | process.env["NODE_ENV"] 대체 | Angular isDevMode() 사용 | Angular 표준 빌드 모드 감지 API |
| D5 | SdIntersectionEventPlugin 등록 방식 | opt-in (수동 등록) 유지 | 원본에서도 provideSdAngular()에 미등록, 소비자가 필요 시 직접 등록 |

```gherkin
Feature: 1.5 이벤트 시스템

  Background:
    Given Angular 앱이 EventManagerPlugin들과 함께 부트스트랩되어 있다

  Rule: SdOptionEventPlugin이 표준 DOM 이벤트에 .capture/.passive/.once 옵션을 추가한다

    Scenario: 캡처 단계에서 이벤트 리스너 등록
      Given 요소에 "(click.capture)" 이벤트가 바인딩되어 있다
      When 하위 요소에서 클릭 이벤트가 발생한다
      Then 캡처 단계에서 리스너가 실행된다

    Scenario: passive 옵션으로 이벤트 리스너 등록
      Given 요소에 "(scroll.passive)" 이벤트가 바인딩되어 있다
      When 스크롤 이벤트가 발생한다
      Then passive 옵션으로 리스너가 실행되어 preventDefault를 호출할 수 없다

    Scenario: 복합 옵션(capture+passive) 이벤트 리스너 등록
      Given 요소에 "(touchstart.capture.passive)" 이벤트가 바인딩되어 있다
      When 터치 이벤트가 발생한다
      Then 캡처 단계에서 passive 옵션으로 리스너가 실행된다

    Scenario: once 옵션으로 이벤트 리스너 등록
      Given 요소에 "(transitionend.once)" 이벤트가 바인딩되어 있다
      When transitionend 이벤트가 두 번 발생한다
      Then 리스너는 첫 번째 이벤트에서만 실행된다

    Scenario: 지원하지 않는 이벤트명
      Given 이벤트명이 window/document/HTMLElement에 정의되지 않았다
      When supports()가 호출된다
      Then false를 반환하여 다른 플러그인에 위임한다

  Rule: SdResizeEventPlugin이 요소 크기 변화를 감지한다

    Scenario: 요소 높이 변경 감지
      Given 요소에 "(sdResize)" 이벤트가 바인딩되어 있다
      When 요소의 높이가 변경된다
      Then ISdResizeEvent가 발생하며 heightChanged는 true, widthChanged는 false이다

    Scenario: 요소 폭 변경 감지
      Given 요소에 "(sdResize)" 이벤트가 바인딩되어 있다
      When 요소의 폭이 변경된다
      Then ISdResizeEvent가 발생하며 heightChanged는 false, widthChanged는 true이다

    Scenario: 요소가 뷰포트에 진입할 때 초기 크기 이벤트 발생
      Given 요소가 뷰포트 밖에 있다
      When 요소가 뷰포트에 진입한다
      Then IntersectionObserver를 통해 초기 크기 정보가 포함된 ISdResizeEvent가 발생한다

    Scenario: 연속 리사이즈 시 프레임당 1회 제한
      Given 요소에 "(sdResize)" 이벤트가 바인딩되어 있다
      When 한 프레임 내에 여러 번 크기가 변경된다
      Then requestAnimationFrame으로 프레임당 1회만 이벤트가 발생한다

    Scenario: 요소 제거 시 옵저버 정리
      Given 요소에 "(sdResize)" 이벤트가 바인딩되어 있다
      When addEventListener의 반환 함수(cleanup)가 호출된다
      Then ResizeObserver와 IntersectionObserver가 disconnect된다

  Rule: SdIntersectionEventPlugin이 요소의 뷰포트 교차를 감지한다 (opt-in)

    Scenario: 요소가 뷰포트와 교차할 때 이벤트 발생
      Given 요소에 "(sdIntersection)" 이벤트가 바인딩되어 있다
      And SdIntersectionEventPlugin이 EVENT_MANAGER_PLUGINS에 수동 등록되어 있다
      When 요소가 뷰포트와 교차한다
      Then ISdIntersectionEvent가 발생하며 IntersectionObserverEntry를 포함한다

    Scenario: 요소 제거 시 옵저버 정리
      Given 요소에 "(sdIntersection)" 이벤트가 바인딩되어 있다
      When addEventListener의 반환 함수(cleanup)가 호출된다
      Then IntersectionObserver가 disconnect된다

  Rule: 커맨드 플러그인이 키보드 단축키로 앱 명령을 실행한다

    Scenario: Ctrl+S로 저장 커맨드 발생
      Given 요소에 "(sdSaveCommand)" 이벤트가 바인딩되어 있다
      When 사용자가 Ctrl+S를 누른다
      Then sdSaveCommand 이벤트가 발생하고 브라우저 기본 동작이 차단된다

    Scenario: Ctrl+Alt+L로 새로고침 커맨드 발생
      Given 요소에 "(sdRefreshCommand)" 이벤트가 바인딩되어 있다
      When 사용자가 Ctrl+Alt+L을 누른다
      Then sdRefreshCommand 이벤트가 발생하고 브라우저 기본 동작이 차단된다

    Scenario: Ctrl+Insert로 삽입 커맨드 발생
      Given 요소에 "(sdInsertCommand)" 이벤트가 바인딩되어 있다
      When 사용자가 Ctrl+Insert를 누른다
      Then sdInsertCommand 이벤트가 발생하고 브라우저 기본 동작이 차단된다

    Scenario: 무관한 키 조합은 무시
      Given 요소에 "(sdSaveCommand)" 이벤트가 바인딩되어 있다
      When 사용자가 Ctrl+Shift+S를 누른다
      Then 이벤트가 발생하지 않는다

  Rule: SdEventsDirective가 옵션 이벤트와 커스텀 이벤트를 타입 안전하게 바인딩한다

    Scenario: 커스텀 리사이즈 이벤트 타입 안전 바인딩
      Given 템플릿에서 SdEventsDirective의 (sdResize) output을 사용한다
      When sdResize 이벤트가 발생한다
      Then $event는 ISdResizeEvent 타입으로 바인딩된다

    Scenario: 옵션 이벤트 타입 안전 바인딩
      Given 템플릿에서 SdEventsDirective의 (click.capture) output을 사용한다
      When 클릭 이벤트가 캡처 단계에서 발생한다
      Then $event는 MouseEvent 타입으로 바인딩된다

    Scenario: 커맨드 이벤트 타입 안전 바인딩
      Given 템플릿에서 SdEventsDirective의 (sdSaveCommand) output을 사용한다
      When sdSaveCommand 이벤트가 발생한다
      Then $event는 KeyboardEvent 타입으로 바인딩된다

  Rule: SdGlobalErrorHandlerPlugin이 전역 에러를 처리한다

    Scenario: Promise rejection (Error 객체) 처리
      Given Angular의 ErrorHandler가 SdGlobalErrorHandlerPlugin으로 등록되어 있다
      When Error 객체를 reason으로 가진 PromiseRejectionEvent가 발생한다
      Then 에러 메시지와 스택이 콘솔에 로깅된다
      And 앱이 destroy되고 에러 오버레이가 표시된다

    Scenario: Promise rejection (문자열) 처리
      Given Angular의 ErrorHandler가 SdGlobalErrorHandlerPlugin으로 등록되어 있다
      When 문자열을 reason으로 가진 PromiseRejectionEvent가 발생한다
      Then 문자열이 콘솔에 로깅된다
      And 앱이 destroy되고 에러 오버레이가 표시된다

    Scenario: Promise rejection (객체) 처리
      Given Angular의 ErrorHandler가 SdGlobalErrorHandlerPlugin으로 등록되어 있다
      When 객체를 reason으로 가진 PromiseRejectionEvent가 발생한다
      Then JSON 직렬화된 내용이 콘솔에 로깅된다
      And 앱이 destroy되고 에러 오버레이가 표시된다

    Scenario: ErrorEvent (error 존재) 처리
      Given Angular의 ErrorHandler가 SdGlobalErrorHandlerPlugin으로 등록되어 있다
      When error 속성이 존재하는 ErrorEvent가 발생한다
      Then 파일명, 라인, 컬럼, 스택이 콘솔에 로깅된다
      And 앱이 destroy되고 에러 오버레이가 표시된다

    Scenario: ErrorEvent (error null) 경고 처리
      Given Angular의 ErrorHandler가 SdGlobalErrorHandlerPlugin으로 등록되어 있다
      When error 속성이 null인 ErrorEvent가 발생한다
      Then 메시지가 경고로 콘솔에 로깅된다
      And 앱은 destroy되지 않고 계속 실행된다

    Scenario: Error 객체 직접 처리
      Given Angular의 ErrorHandler가 SdGlobalErrorHandlerPlugin으로 등록되어 있다
      When Error 객체가 handleError에 전달된다
      Then 스택 또는 메시지가 콘솔에 로깅된다
      And 앱이 destroy되고 에러 오버레이가 표시된다

    Scenario: 에러 오버레이 클릭 시 새로고침 (production)
      Given 에러 오버레이가 표시되어 있다
      And 앱이 production 모드이다
      When 사용자가 에러 오버레이를 클릭한다
      Then location.hash가 "/"로 설정되고 페이지가 새로고침된다

    Scenario: 에러 오버레이 클릭 시 새로고침 (development)
      Given 에러 오버레이가 표시되어 있다
      And 앱이 development 모드이다
      When 사용자가 에러 오버레이를 클릭한다
      Then 페이지가 새로고침된다
```

## 구현계획

### 배경

Angular의 `EventManagerPlugin` 확장 패턴으로 커스텀 DOM 이벤트와 이벤트 옵션을 처리한다. v12 소스를 v14로 마이그레이션하되, 설계 결정(D1~D5)에 따라 모달·로그 의존성을 제거한 독립적 이벤트 인프라를 구축한다.

### 목표

- `.capture/.passive/.once` 이벤트 옵션 지원 (SdOptionEventPlugin)
- ResizeObserver + IntersectionObserver 기반 크기 변화 감지 (SdResizeEventPlugin)
- IntersectionObserver 기반 뷰포트 교차 감지 — opt-in (SdIntersectionEventPlugin)
- 키보드 단축키 커맨드 — 모달 필터링 없이 (SdSave/Refresh/InsertCommandEventPlugin)
- 전역 에러 핸들링 — console 기반 (SdGlobalErrorHandlerPlugin)
- strictTemplates 호환 타입 안전 이벤트 바인딩 (SdEventsDirective)

### 비목표

- 모달 컨텍스트 필터링 (Feature 3.2)
- SdSystemLogProvider 연동 (Feature 1.8)
- provideSdAngular() 등록 (Feature 1.10)
- SdBackbuttonEventPlugin (@deprecated, 제거)

#### v12→v14 변경 사항

| 항목 | v12 | v14 |
|------|-----|-----|
| 커맨드 플러그인 모달 감지 | `SdModalProvider` inject + `findParent()` | 제거 (Feature 3.2 이관) |
| 에러 핸들러 로깅 | `SdSystemLogProvider` inject | `console` 직접 사용 |
| 빌드 모드 감지 | `process.env["NODE_ENV"]` | `isDevMode()` |
| 배열 확장 `.single()` | core-common | 동일 (v14에 존재) |
