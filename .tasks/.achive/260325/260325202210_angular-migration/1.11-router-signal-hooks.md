|---|---------|------|------|

## 요구명세

```gherkin
Feature: 1.11 라우터 시그널 훅

  Background:
    Given Angular 21 @simplysm/angular 패키지가 있다

  Rule: 라우터 파라미터 시그널을 제거한다

    Scenario: useParamMapSignal을 이관하지 않는다
      Given 소스에 useParamMapSignal 함수가 있다
      When Feature 1.11 이관을 수행한다
      Then 대상에 useParamMapSignal 파일이 생성되지 않는다
      And index.ts에서 useParamMapSignal이 export되지 않는다

    Scenario: useQueryParamMapSignal을 이관하지 않는다
      Given 소스에 useQueryParamMapSignal 함수가 있다
      When Feature 1.11 이관을 수행한다
      Then 대상에 useQueryParamMapSignal 파일이 생성되지 않는다
      And index.ts에서 useQueryParamMapSignal이 export되지 않는다

  Rule: 현재 페이지 코드 시그널을 이관한다

    Scenario: useCurrentPageCodeSignal이 현재 페이지 코드를 반환한다
      Given ActivatedRoute가 있고 pathFromRoot에 3개 이상의 세그먼트가 있다
      When useCurrentPageCodeSignal()을 호출한다
      Then pathFromRoot[2:]의 URL 세그먼트를 "."으로 결합한 문자열을 시그널로 반환한다

    Scenario: useCurrentPageCodeSignal이 URL 변경 시 반응한다
      Given useCurrentPageCodeSignal()으로 시그널을 얻었다
      When ActivatedRoute의 URL 세그먼트가 변경된다
      Then 시그널 값이 새 URL 세그먼트 기반으로 업데이트된다

    Scenario: useCurrentPageCodeSignal이 ActivatedRoute 없으면 undefined를 반환한다
      Given ActivatedRoute가 inject되지 않는다 (optional: true)
      When useCurrentPageCodeSignal()을 호출한다
      Then undefined를 반환한다

  Rule: 전체 페이지 코드 시그널을 이관한다

    Scenario: useFullPageCodeSignal이 전체 페이지 코드를 반환한다
      Given Router가 있고 현재 URL이 "/app/main/sub?q=1"이다
      When useFullPageCodeSignal()을 호출한다
      Then "main.sub"를 시그널로 반환한다

    Scenario: useFullPageCodeSignal이 매트릭스 파라미터를 제거한다
      Given Router가 있고 현재 URL이 "/app/page;id=1/child"이다
      When useFullPageCodeSignal()을 호출한다
      Then "page.child"를 시그널로 반환한다

    Scenario: useFullPageCodeSignal이 NavigationEnd 시 업데이트된다
      Given 현재 URL이 "/app/page1"이다
      When NavigationEnd 이벤트로 URL이 "/app/page2"로 변경된다
      Then 시그널 값이 "page2"로 업데이트된다

  Rule: 뷰 제목 시그널을 이관한다 (모달 로직 제외 — Feature 3.2에서 추가)

    Scenario: useViewTitleSignal이 앱 구조에서 제목을 반환한다
      Given SdAppStructureProvider가 있고 페이지 코드 "main.sub"에 대한 제목이 "[메인] 서브"이다
      When useViewTitleSignal()을 호출한다
      Then "[메인] 서브"를 시그널로 반환한다

    Scenario: useViewTitleSignal이 currPageCode 우선, fullPageCode 폴백한다
      Given useCurrentPageCodeSignal이 undefined를 반환한다 (ActivatedRoute 없음)
      And useFullPageCodeSignal이 "page1"을 반환한다
      When useViewTitleSignal()을 호출한다
      Then "page1"을 기반으로 SdAppStructureProvider에서 제목을 조회한다

  Rule: 뷰 타입 시그널을 이관한다 (모달 로직 제외 — Feature 3.2에서 추가)

    Scenario: useViewTypeSignal이 page 타입을 반환한다
      Given ActivatedRoute.component가 현재 컴포넌트의 constructor와 일치한다
      And fullPageCode와 currPageCode가 동일하다
      When useViewTypeSignal(getComp)을 호출한다
      Then "page"를 시그널로 반환한다

    Scenario: useViewTypeSignal이 control 타입을 반환한다
      Given 현재 컴포넌트가 ActivatedRoute.component와 일치하지 않는다
      When useViewTypeSignal(getComp)을 호출한다
      Then "control"을 시그널로 반환한다

    Scenario: TSdViewType 타입이 export된다
      When @simplysm/angular에서 TSdViewType을 import한다
      Then "page" | "modal" | "control" 유니언 타입으로 사용 가능하다

  Rule: 라우터 가드 셋업을 이관한다 (모달 로직 제외 — Feature 3.2에서 추가)

    Scenario: setupCanDeactivate가 라우터 canDeactivate 가드를 등록한다
      Given ActivatedRoute가 있고 routeConfig가 있다
      And reflectComponentType(activatedRoute.component)의 selector가 현재 컴포넌트 태그와 일치한다
      When setupCanDeactivate(fn)을 호출한다
      Then routeConfig.canDeactivate에 CanDeactivateFn이 등록된다
      And 네비게이션 시도 시 fn()의 반환값으로 이탈 허용 여부가 결정된다

    Scenario: setupCanDeactivate가 routeConfig 없으면 무시한다
      Given ActivatedRoute.routeConfig가 null이다
      When setupCanDeactivate(fn)을 호출한다
      Then 아무 동작도 하지 않는다

    Scenario: setupCanDeactivate가 컴포넌트 셀렉터 불일치 시 무시한다
      Given reflectComponentType(activatedRoute.component)의 selector가 현재 컴포넌트 태그와 일치하지 않는다
      When setupCanDeactivate(fn)을 호출한다
      Then 아무 동작도 하지 않는다
```

## 구현계획

### 배경

@simplysm/angular v12→v14 마이그레이션. 라우터 및 뷰 관련 시그널 유틸리티 함수를 이관한다. 소스의 커스텀 바인딩(`$computed`)을 Angular 네이티브 API(`computed`)로 대체하고, 모달 의존성(SdActivatedModalProvider)은 Feature 3.2에서 추가한다.

### 목표

- 페이지 코드 시그널 이관 (useCurrentPageCodeSignal, useFullPageCodeSignal)
- 뷰 상태 시그널 이관 (useViewTitleSignal, useViewTypeSignal + TSdViewType) — 모달 로직 제외
- 라우터 가드 이관 (setupCanDeactivate) — 모달 로직 제외
- 제거 대상 미이관 (useParamMapSignal, useQueryParamMapSignal)

### 비목표

- SdActivatedModalProvider 통합 (Feature 3.2)
- useParamMapSignal/useQueryParamMapSignal 사용처 마이그레이션 (사용처 Feature에서 toSignal 인라인)

### 설계

#### 파일 배치

| 파일 | 위치 | 비고 |
|------|------|------|
| useCurrentPageCodeSignal.ts | `src/core/utils/` | 신규 |
| useFullPageCodeSignal.ts | `src/core/utils/` | 신규 |
| useViewTitleSignal.ts | `src/core/utils/` | 신규 |
| useViewTypeSignal.ts | `src/core/utils/` | 신규 (TSdViewType 포함) |
| setupCanDeactivate.ts | `src/core/utils/setups/` | 신규 |
| index.ts | `src/` | 편집 (5개 export 추가) |

#### API 교체

| 소스 | 대상 | 적용 함수 |
|------|------|-----------|
| `$computed(fn)` | `computed(fn)` from `@angular/core` | useCurrentPageCodeSignal, useFullPageCodeSignal, useViewTypeSignal |
| `injectElementRef()` | `inject(ElementRef)` from `@angular/core` | setupCanDeactivate |
| `activatedRoute.component as any` | 타입 가드 narrowing (`typeof component === "string"` 체크 후 `reflectComponentType` 호출) | setupCanDeactivate |

#### 모달 로직 제외 변경

| 함수 | 제외 내용 |
|------|-----------|
| useViewTitleSignal | `SdActivatedModalProvider` inject 제거, `modalComponent()?.title()` 분기 제거 |
| useViewTypeSignal | `SdActivatedModalProvider` inject 제거, `"modal"` 분기 제거 (TSdViewType은 `"modal"` 포함 유지) |
| setupCanDeactivate | `SdActivatedModalProvider` inject 제거, `activatedModal.canDeactiveFn` 분기 제거 |

### 대안 검토

| 접근 방식 | 선택 | 이유 |
|-----------|------|------|
| `signals/` 서브디렉토리 생성 | 미채택 | 대상의 useSdSystemConfigResource.ts가 `core/utils/`에 flat 배치된 패턴 |
| `$computed` 래퍼 유지 | 미채택 | wbs.md 설계 결정: 네이티브 Angular API로 전면 대체 |
| `getComp: () => any` 유지 | 미채택 | `any` 금지 규칙. `() => object`로 대체 — `.constructor`만 사용 |
