## 구현계획

### 배경

Feature 2.6에서 label, note, progress, calendar 등 내부 visual 컴포넌트가 v14로 마이그레이션되었다. Feature 2.7은 외부 라이브러리(echarts, bwip-js) 기반의 시각화 컴포넌트를 추가한다. v12 소스의 sd-barcode.control.ts와 sd-echarts.control.ts를 v14 패턴으로 마이그레이션하며, `injectElementRef` → `inject(ElementRef)`, `$effect` → native `effect()` / `afterNextRender()` 치환을 적용한다.

### 목표

- bwip-js 기반 `sd-barcode` 컴포넌트 구현 (140+ 바코드 타입, QR 코드 포함)
- echarts 기반 `sd-echarts` 컴포넌트 구현 (SVG 렌더러, 반응형 옵션/로딩/리사이즈)

### 비목표

- 커스텀 차트 테마 시스템
- 바코드 스캐너(카메라 입력) 기능
- echarts/bwip-js lazy import (tree-shaking으로 충분)

### 설계

#### sd-barcode

- `type` (required): `TBarcodeType` union 타입 — bwip-js의 bcid 값 140+ 종
- `value` (optional): 바코드에 인코딩할 문자열, 미지정 시 `""` 사용
- `effect()`로 type/value 변경 시 `bwipjs.toSVG()` 호출 → 호스트 엘리먼트 `innerHTML`에 SVG 삽입

#### sd-echarts

- `option` (required): `echarts.EChartsOption` — 차트 설정 객체
- `loading` (optional, default: false): 로딩 인디케이터 표시 여부
- 차트 인스턴스를 `signal<EChartsType | undefined>`로 관리
  - `afterNextRender()`에서 `echarts.init(el, null, { renderer: "svg" })` → signal에 set
  - `effect()`에서 chart signal + option 추적 → `setOption()` 호출
  - `effect()`에서 chart signal + loading 추적 → `showLoading()` / `hideLoading()` 호출
- `(sdResize)` 호스트 이벤트 → `chart.resize()` 호출
- 스타일: `display: block; height: 100%`

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| `afterNextRender` + signal로 차트 인스턴스 관리 | 채택 | effect가 chart 초기화 후 자연스럽게 반응, Angular 21 표준 DOM 초기화 API |
| 생성자에서 직접 `echarts.init()` | 미채택 | echarts.init()이 엘리먼트 dimensions를 필요로 할 수 있어 DOM 마운트 후 실행이 안전 |
| canvas 렌더러 | 미채택 | SVG가 인쇄/해상도 독립적, 소스와 동일 |
