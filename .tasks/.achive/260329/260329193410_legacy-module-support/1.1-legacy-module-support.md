## 구현계획

### 배경

simplysm 모노레포의 service-common/service-client는 Chrome 67+ API(BigInt, DataView BigInt 메서드)와 Chrome 72+ API(postMessage options 형태)를 사용한다. sd-cli의 `SdBrowserSupportConfig`에는 `splitting` 옵션이 있으나, dynamic import와 import.meta 미지원을 통합 처리하는 옵션이 없다.

### 목표

- service-common 바이너리 프로토콜에서 BigInt 의존 제거 (역호환 유지)
- service-client postMessage를 Chrome 17+ 호환 형태로 변경
- sd-cli에 `legacyModule` 옵션 추가하여 `splitting`을 대체하고 import.meta 치환 플러그인 통합

### 비목표

- polyfill 대상(Promise.allSettled, Error.cause) 처리 — 기존 polyfills 메커니즘 활용
- 프로토콜 헤더 구조 변경 — 8바이트 TotalSize 필드 유지 (역호환)
- build 모드의 import.meta 처리 — Vite가 번들링 시 자체 처리하므로 불필요

### 설계

#### BigInt 제거 (역호환)

BigEndian 8바이트에서 상위 4바이트(offset 16)에 0을 쓰고, 하위 4바이트(offset 20)에 setUint32로 값을 기록한다. MAX_TOTAL_SIZE(100MB) < 2^32(4GB)이므로 정밀도 손실 없음. 기존 BigUint64 인코딩과 동일한 바이너리 출력을 생성하여 역호환성 유지.

```
인코딩:
  headerView.setUint32(16, 0, false);              // 상위 4바이트 = 0
  headerView.setUint32(20, header.totalSize, false); // 하위 4바이트 = 값

디코딩:
  const totalSize = headerView.getUint32(20, false); // 하위 4바이트만 읽기
```

#### postMessage 호환

```
// before
worker.postMessage(msg, { transfer: transferables });
// after
worker.postMessage(msg, transferables);
```

#### legacyModule 옵션

`SdBrowserSupportConfig`에서 `splitting`을 `legacyModule`로 교체. `legacyModule: true`일 때:
1. `inlineDynamicImports: true` (기존 splitting: false 동작)
2. `sd-legacy-import-meta` Vite 플러그인 활성화

#### import.meta 치환 플러그인

```typescript
{
  name: "sd-legacy-import-meta",
  enforce: "post",
  transform(code, id) {
    if (!code.includes("import.meta")) return;

    const varName = "__sd_import_meta__";
    const metaUrl = JSON.stringify(id);
    const injected = `const ${varName} = { url: ${metaUrl} };\n`;
    const replaced = code.replaceAll("import.meta", varName);

    return { code: injected + replaced, map: null };
  }
}
```

`import.meta.hot = createHotContext(...)` → `__sd_import_meta__.hot = createHotContext(...)` — 일반 객체 프로퍼티 할당으로 정상 동작.

`/@vite/client`가 transform 훅을 타지 않을 경우 `resolveId` + `load` 훅으로 fallback.

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| TotalSize를 4바이트로 변경 (헤더 24바이트) | 미채택 | 프로토콜 역호환 깨짐 |
| BigInt polyfill (JSBI) 사용 | 미채택 | DataView.setBigUint64이 네이티브 BigInt 요구, polyfill 불가 |
| esbuild define으로 import.meta 치환 | 미채택 | Vite HMR 주입 이후 실행 불가, import.meta.url 모듈별 값 불가 |
| configureServer 미들웨어로 응답 후처리 | 미채택 | 사용자 요구: 미들웨어 사용 지양 |
| browserslist 자동 판별 | 미채택 | 브라우저별 import.meta 지원 버전 매핑 유지보수 부담 |
