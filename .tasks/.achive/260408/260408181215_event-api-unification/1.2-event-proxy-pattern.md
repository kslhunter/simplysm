## 구현계획

### 배경

현재 `ServiceClient`는 `getService<T>(name)` 메서드로 서비스 호출을 1회 등록 후 타입 안전하게 사용할 수 있다. 이벤트는 동일한 편의 메서드가 없어 매번 제네릭 타입 파라미터와 이벤트 이름 문자열을 반복해야 한다. [근거: 사용자 요청]

`getService()`는 동적 메서드명이 필요하여 `Proxy`를 사용하지만, 이벤트는 `addListener`/`removeListener`/`emit` 3개 메서드가 고정이므로 단순 객체 리터럴로 충분하다. [근거: service-client.ts:80-89]

### 목표
- `getEvent<TEventDef>(eventName)` 메서드를 `ServiceClient`와 `ServiceServer`에 추가 [근거: Rule "getEvent()는 이벤트 이름과 타입을 캡처"]
- 라이브러리 내부 소비자(`SdSharedDataProvider`)를 새 패턴으로 마이그레이션 [근거: wbs 범위]

### 비목표
- 기존 `addListener`/`removeListener`/`emitEvent` 메서드 제거 [근거: wbs 경계]
- 소비 프로젝트 `AppServiceProvider` 패턴 변경 [근거: wbs 경계]

### 설계

**ClientEventProxy 인터페이스** (service-client):
```typescript
interface ClientEventProxy<TEventDef extends ServiceEventDef> {
  addListener(
    info: TEventDef["$info"],
    cb: (data: TEventDef["$data"]) => PromiseLike<void>,
  ): Promise<string>;
  removeListener(key: string): Promise<void>;
  emit(
    infoSelector: (item: TEventDef["$info"]) => boolean,
    data: TEventDef["$data"],
  ): Promise<void>;
}
```

**ServerEventProxy 인터페이스** (service-server):
```typescript
interface ServerEventProxy<TEventDef extends ServiceEventDef> {
  emit(
    infoSelector: (item: TEventDef["$info"]) => boolean,
    data: TEventDef["$data"],
  ): Promise<void>;
}
```

**`getEvent()` 구현**: 기존 메서드를 이벤트 이름으로 바인딩한 객체 리터럴 반환.

### 대안 검토

| 대안 | 설명 | 불채택 사유 |
|------|------|------------|
| `defineEvent()` 런타임 객체를 인자로 전달 | `getEvent(OrderUpdated)` | 클라이언트에서 `import type`만 가능하므로 런타임 값 전달 불가 |
| `EventClient`에 직접 추가 | `eventClient.getEvent()` | `EventClient`는 내부 모듈. 공개 API는 `ServiceClient` |
