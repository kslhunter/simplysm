# Feature 1.1 컴포넌트 클래스 Control 접미사 제거

## 참조 자료

- WBS: [wbs.md](./wbs.md)
- 네이밍 규칙: `packages/angular/CLAUDE.md` — Naming Conventions 섹션
- 현재 export 목록: `packages/angular/src/index.ts`

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | 변수명(`_parentControl`, `dockControls` 등)은 변경하는가? | 변경하지 않음 | 클래스 접미사가 아닌 일반 변수명이며, WBS 범위에 포함되지 않음 |
| D2 | 메서드명(`getControlStep`, `toControlValue`)은 변경하는가? | 변경하지 않음 | HTML input 컨트롤의 속성을 의미하는 도메인 용어로, 클래스 네이밍과 무관 |
| D3 | 프로퍼티명(`noFirstControlFocusing`)은 변경하는가? | 변경하지 않음 | "첫 컨트롤 포커싱" 의미의 옵션명으로, 클래스 네이밍과 무관 |
| D4 | 클래스명을 참조하는 주석(`// SdModalControl 생성`, `//#region`)은 변경하는가? | 변경함 | 주석이 클래스명을 직접 참조하므로 정확성 유지를 위해 함께 업데이트 |

    And 합의된 네이밍 규칙이 packages/angular/CLAUDE.md에 기록되어 있다

      When 참조 업데이트를 적용한다
      Then import { SdButton } from "../button/sd-button"으로 변경된다

    Scenario: @Component imports 배열이 업데이트된다
      Given @Component 데코레이터의 imports에 [SdButtonControl, SdAnchorControl]이 포함되어 있다

      When 참조 업데이트를 적용한다
      Then inject(SdView), viewChild(SdDropdown), createComponent(SdModal)로 변경된다

      Given ComponentRef<SdToastControl>, input<SdSidebarContainerControl>() 타입이 있다
      When 참조 업데이트를 적용한다
      Then ComponentRef<SdToast>, input<SdSidebarContainer>()로 변경된다

    Scenario: index.ts export가 업데이트된다
      Given index.ts에서 export { SdButtonControl } from "./ui/form/button/sd-button.control"이 있다
      When export 업데이트를 적용한다
      Then export { SdButton } from "./ui/form/button/sd-button"으로 변경된다

## 구현계획

### 배경

@simplysm/angular 패키지의 66개 컴포넌트 클래스가 `*Control` 접미사를 사용 중이다. Angular 생태계 표준(Material: `MatButton`, CDK: `CdkDrag`)에서는 접미사 없는 형식을 사용한다. 합의된 네이밍 규칙(`packages/angular/CLAUDE.md`)에 따라 일괄 리네임을 수행한다.

### 목표

- 66개 컴포넌트 클래스에서 `Control` 접미사 제거 [근거: Rule "Control 접미사 제거"]
- 66개 파일명을 `.control.ts` → `.ts`로 변경 [근거: Rule "Control 접미사 제거"]
- 패키지 내부 ~75개 소스 파일의 클래스 참조 동기화 [근거: Rule "참조 동기화"]
- ~101개 테스트 파일(62 fixture + 39+ spec)의 참조 동기화 [근거: Rule "테스트 참조 동기화"]

### 비목표

- Selector 변경 [근거: wbs 경계 "selector는 변경하지 않음"]
- Provider/Pipe/Plugin 클래스 리네임 [근거: wbs 제외사항]
- 디렉티브 클래스 리네임 [근거: Feature 1.2에서 별도 처리]
- 변수명/메서드명/프로퍼티명 중 "Control"을 포함하는 것 [근거: D1, D2, D3]

### 설계

**치환 전략** — 66개 개별 클래스명에 대한 targeted find-and-replace: [근거: Rule "참조 동기화" 처리를 위해]

| 대상 | 패턴 | 예시 |
|------|------|------|
| 파일명 | `sd-{name}.control.ts` → `sd-{name}.ts` | `sd-button.control.ts` → `sd-button.ts` |
| 클래스명 | `Sd{Name}Control` → `Sd{Name}` | `SdButtonControl` → `SdButton` |
| import 경로 | `./sd-{name}.control` → `./sd-{name}` | `"./sd-button.control"` → `"./sd-button"` |

**치환 시 주의사항:**
- 각 클래스명을 개별적으로 치환하여 변수명(`_parentControl` 등)의 의도치 않은 변경 방지
- import 경로에서 `.control` 접미사만 제거 (전체 경로 변경 아님)
- 클래스명을 참조하는 주석(`// SdModalControl 생성`, `//#region SdDataSheetControl`)도 함께 업데이트

**영향 파일 분류:**

| 유형 | 파일 수 | 변경 내용 |
|------|---------|----------|
| `.control.ts` 소스 파일 | 66 | 파일명 + 클래스 선언 + 내부 import |
| 비-control 소스 파일 (provider, modal, picker 등) | ~9 | import 경로/클래스명 참조 |
| `index.ts` | 1 | export 경로/클래스명 |
| 테스트 fixture | 62 | import 경로/클래스명 |
| 테스트 spec | ~39 | import 경로/클래스명 |

### 대안 검토

| 접근법 | 장점 | 단점 | 판정 |
|--------|------|------|------|
| 스크립트 일괄 치환 (`git mv` + targeted replace) | 66개 동일 패턴을 빠르게 처리. typecheck로 누락 검증 가능 | regex 정확성 필요 | **선택** |
| IDE Rename Symbol 반복 | 정확한 참조 추적 | 66회 반복, 파일명 자동 변경 미지원, CLI 환경에서 불가 | 기각 |
| 수동 편집 | 정확성 | 176개 파일에 대한 수작업으로 시간 과다 | 기각 |
