## 구현계획

### 배경

`SdAppStructureUtils`(angular)에 타입 5개와 유틸 함수 6개가 정의되어 있다. 이 중 서버에서 필요한 타입 5개(`TSdAppStructureItem`, `ISdAppStructureGroupItem`, `ISdAppStructureLeafItem`, `ISdAppStructureSubPermission`, `ISdFlatPermission`)와 함수 3개(`getFlatPermissions`, `isUsableModules`, `isUsableModulesChain`)를 service-common으로 추출한다. angular는 service-common에 이미 의존하므로 의존 방향 변경이 없다. [근거: wbs 기술적 제약]

### 목표

- service-common에 공유 타입 5개와 standalone 함수 3개를 배치한다 [근거: Rule "공유 타입/유틸은 service-common에서 정의"]
- angular의 기존 public API를 유지한다 [근거: Rule "기존 public API 하위 호환성 유지"]

### 비목표

- Provider 변경 [근거: wbs 경계 "Provider는 이 Feature에서 변경하지 않음"]
- 클라이언트 전용 타입/유틸(`ISdMenu`, `ISdFlatMenu`, `ISdPermission`, `getMenus`, `getFlatMenus`, `getPermissions` 등) 이동 [근거: wbs 경계]
- 서비스 정의 [근거: wbs 경계 "Feature 1.2에서 다룸"]

### 설계

**service-common 신규 파일:**

`src/app-structure/app-structure.types.ts` [근거: D1]:
- angular의 `sd-app-structure.types.ts`에서 공유 타입 5개를 복사:
  - `SdAppStructureItem<TModule = unknown>` (union type)
  - `SdAppStructureGroupItem<TModule>` (children 보유)
  - `SdAppStructureLeafItem<TModule>` (perms, subPerms, url 등 보유)
  - `SdAppStructureSubPermission<TModule>`
  - `SdFlatPermission<TModule = unknown>` (titleChain, codeChain, modulesChain)

`src/app-structure/app-structure.utils.ts` [근거: Rule "standalone 함수"]:
- `isUsableModules<TModule>(modules, requiredModules, usableModules): boolean` — angular `_isUsableModules` 로직 그대로
- `isUsableModulesChain<TModule>(modulesChain, requiredModulesChain, usableModules): boolean` — angular `_isUsableModulesChain` 로직, 내부에서 `isUsableModules` 호출
- `getFlatPermissions<TModule>(items, usableModules): SdFlatPermission<TModule>[]` — angular `SdAppStructureUtils.getFlatPermissions` 로직, 내부에서 `isUsableModulesChain`/`isUsableModules` 호출

`src/index.ts` 추가:
```typescript
export * from "./app-structure/app-structure.types";
export * from "./app-structure/app-structure.utils";
```

**angular 파일 수정:**

`sd-app-structure.types.ts`:
- `TSdAppStructureItem`, `ISdAppStructureGroupItem`, `ISdAppStructureLeafItem`, `ISdAppStructureSubPermission`, `ISdFlatPermission`를 `export type { ... } from "@simplysm/service-common"` 으로 re-export
- `ISdMenu`, `ISdFlatMenu`, `ISdPermission`은 그대로 이 파일에서 정의 유지

`sd-app-structure.utils.ts`:
- `import { getFlatPermissions, isUsableModules, isUsableModulesChain } from "@simplysm/service-common"` 추가
- `static getFlatPermissions(...)` → `return getFlatPermissions(items, usableModules);` 위임
- 모든 `this._isUsableModules(...)` → `isUsableModules(...)` 대체 (5곳: getMenus:88, getPermissions:194, getFlatPermissions 위임으로 제거, getFlatPermissions 내 subPerms:292 위임으로 제거)
- 모든 `this._isUsableModulesChain(...)` → `isUsableModulesChain(...)` 대체 (2곳: getFlatMenus:157, getFlatPermissions 위임으로 제거)
- `private static _isUsableModules` 메서드 삭제
- `private static _isUsableModulesChain` 메서드 삭제

### 대안 검토

| 대안 | 불채택 사유 |
|---|---|
| 별도 패키지로 분리 | 파일 2개를 위한 별도 패키지는 과도. service-common이 이미 적절한 공유 위치 |
| 타입만 공유, 함수는 angular 유지 | 서버에서 permission 초기화 시 `getFlatPermissions` 실행 필요 (Feature 1.2 참조) |
| angular에서 import 변경 없이 복사본 유지 | 코드 중복. wbs에서 "단일 소스 방식" 채택 명시 |
