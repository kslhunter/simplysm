## 구현계획

### 배경

현재 `angularVitestPlugin` (`vitest-plugin.ts`)은 `sdAngularPlugin`과 동일한 Angular AOT 컴파일을 별도 구현하고 있다. Feature 1.1~2.1을 통해 `sdAngularPlugin`이 `AngularBuildPipeline`을 사용하도록 개선되었으므로, `angularVitestPlugin`을 제거하고 `sdAngularPlugin`으로 대체한다. [근거: wbs "dev/build랑 test랑 서로 다른 방식의 빌드를 한다는거 자체가 단 1도 이해가 안감"]

### 목표

- `angularVitestPlugin`을 제거하고 `sdAngularPlugin`으로 대체한다 [근거: wbs 범위]
- `sdAngularPlugin`에 `includeFixtures` 옵션을 추가하여 테스트 fixture AOT 컴파일을 지원한다 [근거: wbs 범위]
- non-client 패키지 타입 안전성을 개선한다 [근거: 설계 결정 D2]

### 비목표

- `sdAngularPlugin`의 Vite 플러그인 고유 로직(JavaScriptTransformer, configureServer, handleHotUpdate) 변경 — 이미 Vitest 호환 [근거: 코드 분석]
- `createClientViteConfig` 정리 — Feature 3.1 범위 [근거: wbs 경계]
- ngHmrMode의 Vitest 최적화 — 무해한 dead code이므로 현상 유지 [근거: 설계 결정 D3]

### 설계

**1. SdAngularPluginOptions에 includeFixtures 추가** [근거: Rule "includeFixtures 옵션"]

```typescript
export interface SdAngularPluginOptions {
  pkg: string;
  onBuildStart?: () => void;
  onBuild?: (result: { ... }) => void;
  /** @internal test용 pkgDir 오버라이드 */
  _pkgDir?: string;
  /** true이면 *.fixture.ts 파일도 AOT 컴파일 대상에 포함 (테스트 전용) */
  includeFixtures?: boolean;
}
```

`buildStart()`에서 Pipeline 생성 시:
```typescript
rootNames: getPackageSourceFiles(resolvedPkgDir, parsed, {
  includeFixtures: options.includeFixtures,
}),
```

**2. non-client 패키지 타입 안전 처리** [근거: 설계 결정 D2]

현재 (`vite-angular-plugin.ts:68-69`):
```typescript
let pkgConfig: SdClientPackageConfig | undefined;
// ...
pkgConfig = rawPkgConfig as SdClientPackageConfig;
```

변경 후:
```typescript
let pkgConfig: SdPackageConfig | undefined;
// ...
pkgConfig = rawPkgConfig;
```

browserSupport 접근 시:
```typescript
const browserSupport = pkgConfig?.target === "client"
  ? (pkgConfig as SdClientPackageConfig).browserSupport
  : undefined;
const legacyModule = browserSupport?.legacyModule === true;
const postCssPlugins = browserSupport?.postCss?.plugins;
```

**3. vitest-plugin.ts 삭제 + index.ts export 교체** [근거: Rule "angularVitestPlugin 완전 제거"]

`packages/sd-cli/src/index.ts` 변경:
```typescript
// Config
export * from "./sd-config.types";

// Angular Vite Plugin
export { sdAngularPlugin, type SdAngularPluginOptions } from "./angular/vite-angular-plugin";
```

**4. vitest.config.ts 마이그레이션** [근거: Rule "Vitest에서 sdAngularPlugin 정상 동작"]

```typescript
// Before
import { angularVitestPlugin } from "./packages/sd-cli/src/vitest-plugin";
// ...
plugins: [
  angularVitestPlugin({
    tsconfig: resolve(import.meta.dirname, "packages/angular/tsconfig.json"),
  }),
],

// After
import { sdAngularPlugin } from "./packages/sd-cli/src/angular/vite-angular-plugin";
// ...
plugins: [
  sdAngularPlugin({ pkg: "angular", includeFixtures: true }),
],
```

**5. 테스트 파일 정리** [근거: 설계 결정 D1]

- `vitest-plugin.spec.ts` 삭제 — sdAngularPlugin 기존 테스트(`vite-angular-plugin.spec.ts`)가 동일 시나리오 커버
- `vitest-plugin-cwd.spec.ts` 삭제 — cwd 옵션이 더 이상 존재하지 않음
- 새 테스트: `vite-angular-plugin-vitest.spec.ts` — Vitest 환경에서 sdAngularPlugin이 non-client 패키지(angular)로 정상 동작하는지 검증

### 대안 검토

| 대안 | 설명 | 불채택 이유 |
|------|------|------------|
| angularVitestPlugin을 sdAngularPlugin의 thin wrapper로 유지 | vitest-plugin.ts에서 sdAngularPlugin을 호출하는 래퍼 함수 제공 | API가 2개 유지되어 혼란. wbs 목표인 "단일 파이프라인"에 부합하지 않음 |
| includeFixtures 대신 rootNames 직접 전달 | sdAngularPlugin에 rootNames 옵션 추가 | API 복잡도 증가. getPackageSourceFiles에 이미 includeFixtures 옵션이 있으므로 불필요 |
| pkg 옵션에 tsconfig 경로 fallback 추가 | pkg가 sd.config.ts에 없으면 tsconfig 경로로 fallback | sd.config.ts 기반 자동 resolve 원칙에 위배. angular 패키지는 sd.config.ts에 이미 존재 |

### Vertical Slicing

#### [x] Slice 1: sdAngularPlugin 옵션 확장 + non-client 타입 안전
- **구현 내용:**

  - `buildStart()`에서 `getPackageSourceFiles()`에 `{ includeFixtures }` 전달

- **Scenarios:** includeFixtures=true로 fixture 파일 컴파일, includeFixtures 미지정 시 src/ 파일만 컴파일, browser target 패키지에서 플러그인 초기화

#### [x] Slice 2: angularVitestPlugin 제거 + vitest.config.ts 마이그레이션

- **Scenarios:** vitest-plugin.ts 삭제, index.ts export 교체, vitest.config.ts 마이그레이션, Vitest 환경에서 Angular 소스 컴파일 및 transform, node_modules .js Linker 처리
