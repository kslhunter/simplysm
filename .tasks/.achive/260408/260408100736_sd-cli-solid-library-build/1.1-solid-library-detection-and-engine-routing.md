## 구현계획

### 배경

v14 sd-cli의 BuildEngine 아키텍처에서 라이브러리 빌드는 `createBuildEngine()` 팩토리가 패키지 특성에 따라 엔진을 라우팅한다. Angular 라이브러리는 `hasAngularCoreDependency` → `NgtscEngine` 패턴이 확립되어 있다 [근거: `engines/index.ts:55-57`, `package-utils.ts:212-227`]. Solid 라이브러리도 동일한 자동 감지 + 전용 엔진 패턴으로 지원한다.

### 목표

- solid-js 의존성 자동 감지 함수 구현 [근거: Rule "solid-js 의존성 자동 감지"]
- createBuildEngine 팩토리에 Solid 분기 추가 [근거: Rule "엔진 라우팅 우선순위"]
- SolidEsbuildEngine 클래스 + solid-library.worker 스켈레톤 [근거: D1, Rule "typecheck 모드 처리"]
- esbuild-plugin-solid 의존성 추가 [근거: wbs]

### 비목표

- 실제 esbuild 기반 JS emit (Feature 1.2) [근거: wbs 경계]
- watch 모드 증분 리빌드 (Feature 1.3) [근거: wbs 경계]
- tsx/jsx 확장자 지원 (Feature 1.4) [근거: wbs 경계]

### 설계

**1. `hasSolidDependency(pkgDir)` 함수** (`packages/sd-cli/src/utils/package-utils.ts`)

- `hasAngularCoreDependency`와 동일 구조 [근거: package-utils.ts:212-227]
- package.json의 dependencies/peerDependencies에서 `"solid-js"` 키 확인
- package.json 없음 또는 파싱 실패 시 `false` 반환

**2. `createBuildEngine()` Solid 분기** (`packages/sd-cli/src/engines/index.ts`)

- angular 분기(`hasAngularCoreDependency`) 후, TscEngine 폴백 전에 배치 [근거: engines/index.ts:55-61]
- `hasSolidDependency(pkg.dir)` → `new SolidEsbuildEngine({...options, pkg})` 반환
- import 추가: `hasSolidDependency`, `SolidEsbuildEngine`

**3. `SolidEsbuildEngine` 클래스** (`packages/sd-cli/src/engines/SolidEsbuildEngine.ts`)

- `BaseEngine<BuildPackageInfo, typeof SolidLibraryBuildWorkerModule & CommonBuildWorkerModule>` 상속 [근거: TscEngine.ts, NgtscEngine.ts 패턴]
- `_getWorkerPath()` → `import.meta.resolve("../workers/solid-library.worker")` [근거: D1]
- `_getTarget()` → `this._pkg.config.target`
- `_callBuild(output)` → `this._worker!.build({name, config, cwd, pkgDir, output})` → EngineResult 변환 [근거: TscEngine.ts:46-65]
- `_callStartWatch(output)` → `this._worker!.startWatch({...})` [근거: TscEngine.ts:67-77]

**4. `solid-library.worker.ts` 스켈레톤** (`packages/sd-cli/src/workers/solid-library.worker.ts`)

- `library-build.worker.ts` 구조 참조하여 동일한 패턴으로 구성 [근거: library-build.worker.ts]
- Types: `SolidLibraryBuildInfo`, `SolidLibraryBuildResult`, `SolidLibraryBuildWorkerEvents`
- `build(info)`: `runTscPackageBuild` 위임 + lint 실행 (Feature 1.2에서 esbuild 로직으로 교체)
- `startWatch(info)`: FsWatcher + rebuildAll (Feature 1.3에서 esbuild incremental 확장)
- `stopWatch()`: cleanup
- `createWorker` 사용하여 sender 생성

**5. `esbuild-plugin-solid` 의존성** (`packages/sd-cli/package.json`)

- `dependencies`에 `"esbuild-plugin-solid": "^0.6.0"` 추가 [근거: sd-cli는 런타임 빌드 도구이므로 dependencies]

### 대안 검토

- **library-build.worker 재사용 (임시):** TscEngine과 사실상 동일한 클래스가 되며, Feature 1.2에서 _getWorkerPath 변경 필요. NgtscEngine 패턴(전용 워커)과 비일관적 → 기각 (D1)
- **SolidEsbuildEngine 미생성 (감지만):** createBuildEngine 라우팅과 typecheck 요구사항 미충족 → 기각
