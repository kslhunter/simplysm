## 구현계획

### 배경
`SdAppStructureProvider`는 현재 `abstract class`로 구현되어 있어, 소비 프로젝트에서 반드시 서브클래스를 만들어야 한다. 패키지 내 프로덕션 상속 클래스가 없고, `serviceKey`, `usableModules`, `permRecord`는 모두 단순 값이므로 concrete class로 전환하여 직접 사용 가능하게 한다. [근거: D1, D2, D3]

### 목표
- abstract class → concrete class 전환 [근거: Rule "concrete class로 직접 사용 가능"]
- `fetchItems()` → `initialize(serviceKey: string)` [근거: Rule "initialize(serviceKey)로 items를 로드"]
- `usableModules`, `permRecord`를 WritableSignal로 노출 [근거: Rule "WritableSignal"]
- 기존 computed signal 및 메서드 동작 유지 [근거: Rule "기존 API 동작 유지"]

### 비목표
- `SdAppStructureUtils` 변경 [근거: wbs 경계]
- 타입 (`AppStructureItem`, `SdFlatMenu` 등) 변경 [근거: wbs 경계]
- inject 사용처 (`injectPermsSignal`, `injectViewTitleSignal`, `SdBaseContainer`) 변경 [근거: 메서드만 호출하므로 변경 불필요]

### 설계

**변경 전** (`sd-app-structure.provider.ts`):
```typescript
export abstract class SdAppStructureProvider<TModule = unknown> {
  abstract serviceKey: string;
  abstract usableModules: Signal<TModule[] | undefined>;
  abstract permRecord: Signal<Record<string, boolean> | undefined>;
  readonly items = signal<AppStructureItem<TModule>[]>([]);
  async fetchItems(): Promise<void> { ... }
}
```

**변경 후:**
```typescript
export class SdAppStructureProvider<TModule = unknown> {
  readonly usableModules = signal<TModule[] | undefined>(undefined);
  readonly permRecord = signal<Record<string, boolean> | undefined>(undefined);
  readonly items = signal<AppStructureItem<TModule>[]>([]);
  async initialize(serviceKey: string): Promise<void> { ... }
}
```

- `abstract` 키워드 제거
- `abstract serviceKey` → `initialize(serviceKey)` 파라미터
- `abstract usableModules` → `signal<TModule[] | undefined>(undefined)`
- `abstract permRecord` → `signal<Record<string, boolean> | undefined>(undefined)`
- `fetchItems()` → `initialize(serviceKey)` (내부에서 `this._clientFactory.get(serviceKey)` 사용)
- 나머지 computed (`usableMenus`, `usableFlatMenus`) 및 메서드는 변경 없음

### 대안 검토

`usableModules`/`permRecord`를 setter 패턴으로 감싸는 방안 — 단순 signal이 더 Angular 관용적이고 코드가 간결하므로 채택하지 않음.
