# Feature 2.1 startActivityForResult 구현

## 참조 자료

- [wbs.md](wbs.md)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | uri+type 동시 지정 처리 | setDataAndType 사용 | Android API에서 setData/setType 개별 호출 시 상호 초기화됨 |
| D2 | packageName만 지정 vs packageName+className | setPackage / setComponent 분기 | Android API 표준: 앱만 지정 vs 특정 Activity 지정 |
| D3 | 결과 변환 시 uri 포함 | intentToJson에 없는 uri를 결과 변환에 추가 | API 시그니처에 data.uri 명시 |
| D4 | 결과 변환 방식 | 기존 intentToJson 수정 대신 결과 전용 변환 로직 작성 | 기존 broadcast 동작 보존 (IntentResult에 uri 없음) |
| D5 | Capacitor Activity Result 패턴 | startActivityForResult(call, intent, callbackName) + @ActivityCallback | Capacitor 공식 문서 표준 패턴 |

## 구현계획

### 배경

`capacitor-plugin-intent`는 Feature 1.1에서 broadcast → intent로 리네이밍 완료된 상태이다. 현재 broadcast 송수신, 실행 인텐트 조회, newIntent 리스너 기능을 제공한다. TypeScript 인터페이스(`IntentPlugin.ts`) + 정적 래퍼(`Intent.ts`) + Web 스텁(`IntentWeb.ts`) + Android 구현(`IntentPlugin.kt`) 구조이다.

### 목표

- `startActivityForResult` 메서드를 TypeScript 인터페이스, Android Kotlin, Web 스텁에 추가
- 기존 broadcast 기능에 영향 없이 새 기능 추가

### 비목표

- `startActivity` (결과 수신 없는 단순 실행) — wbs.md 제외 사항
- iOS 지원
- 기존 `intentToJson` 함수 변경

### 설계

#### TypeScript 타입 정의 (`IntentPlugin.ts`)

```typescript
export interface StartActivityForResultOptions {
  action?: string;
  uri?: string;
  extras?: Record<string, unknown>;
  type?: string;
  packageName?: string;
  className?: string;
  flags?: number;
}

export interface StartActivityForResultResult {
  resultCode: number;
  data?: {
    action?: string;
    uri?: string;
    extras?: Record<string, unknown>;
  };
}
```

`IntentPlugin` 인터페이스에 메서드 추가:
```typescript
startActivityForResult(options: StartActivityForResultOptions): Promise<StartActivityForResultResult>;
```

#### Android 구현 (`IntentPlugin.kt`)

Intent 빌드 로직:
- `action` → `intent.action = action`
- `uri` + `type` 조합 → `setData` / `setType` / `setDataAndType` 분기
- `extras` → 기존 `populateExtras` 재활용
- `packageName` / `className` → `setPackage` / `setComponent(ComponentName)` 분기
- `flags` → `intent.addFlags(flags)`

결과 변환:
- `result.resultCode` → `resultCode`
- `result.data` (Intent) → `data` 객체: `action`, `data?.toString()` (uri), `extras` (bundleToJson 재활용)
- data Intent가 null이면 `data` 필드 생략

Capacitor 패턴:
- `@PluginMethod fun startActivityForResult(call)` → Intent 빌드 후 `startActivityForResult(call, intent, "handleActivityResult")` 호출
- `@ActivityCallback private fun handleActivityResult(call, result)` → 결과 변환 후 `call.resolve()`

추가 import: `android.net.Uri`, `android.content.ComponentName`, `androidx.activity.result.ActivityResult`, `com.getcapacitor.annotation.ActivityCallback`

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| 기존 intentToJson에 uri 추가 | 미채택 | 기존 IntentResult 타입에 uri가 없고, broadcast 결과에 불필요한 필드가 추가됨 |
| 결과 전용 변환 로직 작성 | 채택 | 기존 동작 보존, startActivityForResult 결과 구조에 맞는 변환 |
