## 구현계획

### 배경

Capacitor 클래스(Feature 6.1)와 Electron 클래스(Feature 6.2)가 독립 유틸리티로 구현되어 있으나, BuildOrchestrator와 DevWatchOrchestrator에 통합되지 않았다. build/dev 명령어에서 client 패키지를 ViteEngine으로만 처리하고 있어, 네이티브 빌드/디바이스 실행이 불가능하다.

**핵심 동작 차이:**
- `Capacitor.run(url)`: cap copy + cap run 실행 후 반환 (단기 실행). 디바이스에 앱 배포 완료 후 Promise resolve.
- `Electron.run(url)`: esbuild watch + Electron 프로세스 스폰. SIGINT/SIGTERM까지 무기한 블로킹. 내부 시그널 핸들러로 cleanup.
- `Capacitor.build(outPath)` / `Electron.build(outPath)`: 동기적 빌드 실행 후 반환.

### 목표

- BuildOrchestrator에서 client ViteEngine 빌드 후 네이티브 빌드(Capacitor/Electron) 실행
- DevWatchOrchestrator에서 ViteDevServer 시작 후 네이티브 디바이스 실행
- Capacitor.run() / Electron.run() 단위 테스트 작성

### 비목표

- publish 명령어 변경 (dist/ 하위 산출물이 기존 배포에 자동 포함)
- watch 명령어 변경 (library 전용, 네이티브 무관)
- Electron.run()의 별도 stop() 메서드 추가 (내부 시그널 핸들러로 충분)

### 설계

#### BuildOrchestrator 통합

client 패키지의 ViteEngine 빌드 후, `config.capacitor` / `config.electron` 존재 시 네이티브 빌드를 수행한다. 기존 buildTasks 루프 내에서 ViteEngine 빌드 성공 후 순차 실행:

```
ViteEngine.run() → 성공 → Capacitor.create() + initialize() + build(distPath)
                         → Electron.create() + initialize() + build(distPath)
                → 실패 → 네이티브 빌드 건너뜀
```

- `distPath`: `path.join(pkgDir, "dist")`
- Capacitor와 Electron 빌드는 독립적이므로 `Promise.all()`로 병렬 실행 가능
- 네이티브 빌드 에러는 `state.hasError`에 반영하되, 다른 패키지 빌드를 중단하지 않음

#### DevWatchOrchestrator 통합

`_startDevMode()`에서 client ViteDevServer 시작 후, port가 확보된 시점에 네이티브 앱을 실행한다:

```
ViteEngine.startWatch() → serverReady(port) → devServerUrl = `http://localhost:${port}`
                                             → Capacitor.create() + initialize() + run(devServerUrl)  -- await (단기)
                                             → Electron.run(devServerUrl)  -- fire-and-forget (장기 블로킹)
```

- Capacitor.run()은 await 가능 (cap run 완료 후 반환)
- Electron.run()은 fire-and-forget: `void electron.run(url).catch(...)`. 내부 시그널 핸들러가 SIGINT/SIGTERM에 반응하여 cleanup
- 네이티브 실행 에러는 로그로 출력하되 orchestrator를 중단하지 않음

#### 종료 관리

- **Capacitor**: run() 완료 후 관리할 프로세스 없음. 디바이스 앱은 독립 실행.
- **Electron**: run() 내부의 `process.once("SIGINT"/"SIGTERM")` 핸들러가 DevWatchOrchestrator의 SignalHandler와 함께 동작. 시그널 발생 시 두 핸들러가 독립적으로 실행되어 각각 cleanup 수행.

### 대안 검토

| 접근 방식 | 선택 | 이유 |
|-----------|------|------|
| 기존 buildTasks 내에서 네이티브 빌드 순차 실행 | 채택 | ViteEngine 빌드 결과(dist/) 의존, 기존 에러 처리 패턴과 일관 |
| 네이티브 빌드를 별도 Phase로 분리 (모든 Vite 빌드 완료 후) | 미채택 | 패키지 간 독립성 훼손, 하나의 패키지 빌드 지연이 다른 패키지의 네이티브 빌드도 지연 |
| Electron.run()에 stop() 메서드 추가 | 미채택 | 현재 시그널 기반 cleanup이 충분, 추가 인터페이스 불필요 |
| Electron.run() 블로킹을 AbortSignal로 제어 | 미채택 | API 변경 필요, 기존 시그널 핸들러와 중복 |
