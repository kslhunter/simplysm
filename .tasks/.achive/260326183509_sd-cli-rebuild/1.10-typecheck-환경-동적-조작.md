### v13 핵심 함수 원본

```typescript
type TypecheckEnv = "node" | "browser";

const DOM_LIB_PATTERNS = ["dom", "webworker"] as const;

async function getTypesFromPackageJson(packageDir: string): Promise<string[]> {
  const packageJsonPath = path.join(packageDir, "package.json");
  if (!(await fsx.exists(packageJsonPath))) return [];
  const packageJson = await fsx.readJson<{ devDependencies?: Record<string, string> }>(packageJsonPath);
  const devDeps = packageJson.devDependencies ?? {};
  return Object.keys(devDeps)
    .filter((dep) => dep.startsWith("@types/"))
    .map((dep) => dep.replace("@types/", ""));
}

async function getCompilerOptionsForPackage(
  baseOptions: ts.CompilerOptions,
  env: TypecheckEnv,
  packageDir: string,
): Promise<ts.CompilerOptions> {
  const options = { ...baseOptions };
  const packageTypes = await getTypesFromPackageJson(packageDir);
  options.typeRoots = [
    path.join(packageDir, "node_modules", "@types"),
    path.join(process.cwd(), "node_modules", "@types"),
  ];
  switch (env) {
    case "node":
      options.lib = options.lib?.filter(
        (lib) => !DOM_LIB_PATTERNS.some((pattern) => lib.toLowerCase().includes(pattern)),
      );
      options.types = [...new Set([...packageTypes, "node"])];
      break;
    case "browser":
      options.types = packageTypes.filter((t) => t !== "node");
      break;
  }
  return options;
}

function toTypecheckEnvs(target: string | undefined): TypecheckEnv[] {
  if (target === "node") return ["node"];
  if (target === "browser" || target === "client") return ["browser"];
  return ["node", "browser"];
}
```

### v14 현재 상태

- 패키지별 tsconfig.json 존재 (typeRoots 설정, types 미설정)
- `parseTsconfig(pkgDir)`로 패키지 tsconfig를 그대로 읽어 사용
- `TypecheckEnv`, `toTypecheckEnvs()`, `getCompilerOptionsForPackage()` 제거됨 (Feature 1.2에서)
- Angular 감지: `hasAngularCompilerOptions(pkgDir)` — 패키지 tsconfig의 angularCompilerOptions 존재 여부
- neutral 패키지 이중 typecheck 없음

## 구현계획

### 배경

v14 sd-cli는 Feature 1.2에서 패키지별 tsconfig.json을 도입하면서 `TypecheckEnv` 기반 환경 조작 로직을 제거했다. 이로 인해 neutral 패키지의 이중 typecheck가 사라졌다. 현재 코드 구조:
- `parseTsconfig(pkgDir)` → 패키지 tsconfig 그대로 사용
- `createBuildEngine()` → `hasAngularCompilerOptions(pkgDir)`로 Angular 감지
- `typecheck.ts` → 패키지당 1개 engine, 1회 `run({js:false, dts:false})`
- Workers(`library-build.worker`, `ngtsc-build.worker`, `server-build.worker`) → `parseTsconfig()` 호출 후 output 플래그만 조작

### 목표

- `TypecheckEnv` 기반 lib/types 동적 조작 복원
- neutral 패키지 node+browser 이중 typecheck 복원
- Angular 감지를 package.json `@angular/core` 의존성 기반으로 변경
- angularCompilerOptions를 루트 tsconfig로 이동

### 비목표

- 패키지별 tsconfig.json 제거 (IDE 전용으로 유지)
- build emit 시 env 조작 (build는 패키지 tsconfig 그대로)
- watch 모드에서 env 조작

### 설계

#### TypecheckEnv 유틸리티

`utils/tsconfig.ts`에 추가:

```typescript
export type TypecheckEnv = "node" | "browser";

const DOM_LIB_PATTERNS = ["dom", "webworker"] as const;

// package.json devDependencies에서 @types/* 수집
export function getTypesFromPackageJson(packageDir: string): string[]

// baseOptions + env → 조작된 compilerOptions
export function getCompilerOptionsForEnv(
  baseOptions: ts.CompilerOptions,
  env: TypecheckEnv,
  packageDir: string,
): ts.CompilerOptions

// target → TypecheckEnv[] 매핑
export function toTypecheckEnvs(target: string | undefined): TypecheckEnv[]
```

v13과의 차이:
- v13은 `getCompilerOptionsForPackage()`에서 typeRoots도 설정 → v14는 패키지 tsconfig에 typeRoots가 이미 있으므로 typeRoots는 건드리지 않음
- v13 node env에서 `types = [...packageTypes, "node"]`로 세팅 → v14는 types 미설정 유지 (typeRoots auto-include 활용)

#### BuildOutput 확장

```typescript
// engines/types.ts
export interface BuildOutput {
  js: boolean;
  dts: boolean;
  env?: TypecheckEnv;  // 추가
}
```

`env`가 있으면 worker에서 `getCompilerOptionsForEnv()` 적용. 없으면 패키지 tsconfig 그대로.

#### Worker에서 env 처리

각 worker(`library-build.worker`, `ngtsc-build.worker`, `server-build.worker`)의 build 함수에서:

```typescript
let parsedConfig = parseTsconfig(info.pkgDir);
let compilerOptions = parsedConfig.options;

// env가 있으면 lib/types 조작
if (info.output.env != null) {
  compilerOptions = getCompilerOptionsForEnv(compilerOptions, info.output.env, info.pkgDir);
}
```

#### tsBuildInfoFile env 분리

env별로 별도 캐시 파일 사용하여 incremental 충돌 방지:

```typescript
const envSuffix = output.env != null ? `-${output.env}` : "";
const tsBuildInfoFile = path.join(pkgDir, ".cache", `typecheck${envSuffix}.tsbuildinfo`);
```

#### typecheck 명령 이중 실행

```typescript
// typecheck.ts
for (const [name, config] of Object.entries(sdConfig.packages)) {
  if (config == null || config.target === "scripts" || config.target === "client") continue;

  const envs = toTypecheckEnvs(config.target);
  for (const env of envs) {
    typecheckTasks.push({
      name,
      dir: path.join(cwd, "packages", name),
      config,
      env,  // "node" 또는 "browser"
    });
  }
}

// 각 task에서 engine.run({js: false, dts: false, env: task.env})
```

#### Angular 감지 변경

`utils/tsconfig.ts`의 `hasAngularCompilerOptions(pkgDir)` → 새 함수:

```typescript
// utils/package-utils.ts
export function hasAngularCoreDependency(pkgDir: string): boolean
// package.json의 dependencies 또는 peerDependencies에 @angular/core 존재 여부
```

`engines/index.ts`의 `createBuildEngine()`에서 호출 변경.

#### angularCompilerOptions 이동

- `packages/angular/tsconfig.json`의 `angularCompilerOptions` → 루트 `tsconfig.json`으로 이동
- `ngtsc-build-core.ts`에서 root tsconfig raw JSON 읽어 병합:

```typescript
const rootRawConfig = ts.readConfigFile(path.join(info.cwd, "tsconfig.json"), ts.sys.readFile);
const angularOptions = rootRawConfig.config?.angularCompilerOptions ?? {};
const mergedOptions = { ...compilerOptions, ...angularOptions };
// NgtscProgram에 mergedOptions 전달
```

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| BuildOutput에 env 추가 | 채택 | optional field라 기존 build/watch 호출에 영향 없음 |
| Engine 생성 시 env 전달 | 미채택 | Engine이 env를 알아야 하므로 BuildEngine 인터페이스가 복잡해짐 |
| typecheck에서 engine 없이 직접 worker 호출 | 미채택 | 기존 BuildEngine 추상화를 깨뜨림 |
| angularCompilerOptions를 sd.config.ts에서 관리 | 미채택 | IDE Angular LS와의 호환 필요, tsconfig에 있어야 IDE가 읽음 |
