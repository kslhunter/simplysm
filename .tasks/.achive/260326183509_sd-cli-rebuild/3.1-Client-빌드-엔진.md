## 구현계획

### 배경

현재 ViteEngine은 `vite-build.worker.ts`를 통해 `@angular/build/private`의 `buildApplicationInternal`과 `serveWithVite` API를 사용한다. 이 방식은 Angular CLI의 내부 빌드 파이프라인에 전적으로 의존하여, browserslist/PostCSS/polyfills/splitting 등의 빌드 옵션을 제어할 수 없다 (WBS "Angular 빌드 제약" 참조). Vite를 직접 제어하고 Angular 컴파일만 Vite 플러그인으로 통합하는 방식으로 전환한다.

### 목표

- `buildApplicationInternal`/`serveWithVite` 의존을 제거하고 Vite API(`createServer`/`build`)를 직접 사용
- `AngularFacade`로 Angular AOT 컴파일을 격리하여 Vite 플러그인으로 통합
- BuildEngine 인터페이스(run/startWatch/stop) 동일 계약 유지

### 비목표

- HMR/증분 컴파일 (Feature 3.3)
- browserslist/PostCSS/polyfills/splitting 옵션 (Feature 4.1)
- PWA (Feature 4.2)
- env/configs 확장 (Feature 3.4, 기존 기능은 유지)

### 설계

#### AngularFacade (`src/angular/angular-facade.ts`)

`@angular/build/private`의 low-level API를 래핑하는 Facade. Client 빌드 경로의 Angular 어댑터 역할 (Library 경로의 `angular-build.ts`와 별개).

- 정적 팩토리: `AngularFacade.create(options)` → 인스턴스
- 라이프사이클: `create` → `initialize` → (`emitAffectedFiles`, `transformJs`, `diagnose`) → `dispose`
- `ComponentStylesheetBundler`로 인라인 SCSS 처리 (PostCSS/browserslist 옵션은 존재하되 기본값 비활성)
- `AsyncDisposable` 구현으로 `using`문 호환

#### sd-angular Vite 플러그인 (`src/angular/vite-angular-plugin.ts`)

- `enforce: "pre"` — Vite esbuild 변환 전에 Angular 컴파일 적용
- `config`: `ngDevMode`/`ngJitMode` define 설정
- `buildStart`: `AngularFacade` 생성 + `initialize` + `emitAffectedFiles` + `diagnose`
- `transform(.ts)`: emit 캐시 조회 + `transformJs` → 컴파일된 JS 반환
- `buildEnd`: `AngularFacade` dispose + emit 캐시 정리

#### Vite Config (`src/utils/vite-config.ts`)

`createClientViteConfig(options)` → Vite `InlineConfig` 반환. Feature 3.1 범위:

| 항목 | 설명 |
|------|------|
| `root` | 패키지 디렉토리 |
| `base` | `/{패키지명}/` |
| `plugins` | `vite-tsconfig-paths`, `sdAngularPlugin` |
| `define` | env → `process.env`/`import.meta.env` 치환 |
| `server` | port 설정 (dev 모드) |
| `esbuild` | `tsconfigRaw` (패키지 tsconfig compilerOptions) |
| `logLevel` | build 모드에서 `"silent"` |

후속 Feature에서 추가될 항목: PostCSS inline 플러그인(4.1), PWA(4.2), polyfills(4.1), browserslist target(4.1), splitting(4.1), replaceDeps watch(미정)

#### client.worker (`src/workers/client.worker.ts`)

- `build(info)`: `createClientViteConfig` + `viteBuild` → `ClientBuildResult` 반환
- `startWatch(info)`: `createClientViteConfig` + `createServer` + `listen` → `serverReady` 이벤트
- `stopWatch()`: `server.close()`
- `writeConfigJson()`: `dist/.config.json` 생성

Worker 입력 인터페이스:

```typescript
interface ClientBuildInfo {
  name: string;
  cwd: string;
  pkgDir: string;
  port?: number;
  env?: Record<string, string>;
  configs?: Record<string, unknown>;
}
```

#### ViteEngine 변경 (`src/engines/ViteEngine.ts`)

- worker 참조: `vite-build.worker` → `client.worker`
- worker 메시지 타입: `ViteBuildInfo` → `ClientBuildInfo`
- `ResultCollector`/`RebuildManager` 연동 패턴 유지
- `startWatch` Promise 패턴 유지 (초기 빌드 완료 시 resolve)

#### angular-build.ts 정리 (`src/utils/angular-build.ts`)

제거 대상:
- `buildApplicationInternal`, `ResultKind`, `Result`, `ResultFile`, `ExternalResultMetadata` re-export
- `serveWithVite`, `normalizeDevServerOptions`, `NormalizedDevServerOptions` re-export
- `ApplicationBuilderOptions`, `DevServerBuilderOptions`, `BuildOutputFile`, `BuildOutputFileType`, `BuildOutputAsset`, `DevServerBuilderOutput` re-export
- `IndexHtmlGenerator` 및 관련 타입 re-export (미사용)
- `checkPort`, `emitFilesToDisk` re-export (미사용)
- `createAngularBuilderContext` 함수 및 `AngularBuilderContextOptions` 인터페이스

유지 대상:
- `NgtscProgram`, `OptimizeFor` (`ngtsc-build.worker`, `vitest-plugin` 사용)
- `AngularLibraryHostExtensions` (`vitest-plugin` 사용)

### 대안 검토

| 접근 방식 | 선택 | 이유 |
|-----------|------|------|
| Vite 직접 제어 + AngularFacade 플러그인 | **채택** | browserslist/PostCSS 등 빌드 옵션 제어 가능, _back 코드의 검증된 접근 |
| buildApplicationInternal 유지 + dev server만 Vite | 미채택 | 빌드 옵션 제어 불가 문제가 해결되지 않음 |
| AngularFacade 없이 플러그인에서 @angular/build/private 직접 사용 | 미채택 | Angular 버전 변경 시 여러 파일 수정 필요, 기존 angular-build.ts의 격리 패턴과 불일치 |
