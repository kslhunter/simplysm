## 구현계획

### 배경

v14 sd-cli에 `SdElectronConfig` 타입 정의만 존재하고 구현이 없다. v14 _back에 완전한 Electron 클래스(363줄)와 테스트(348줄)가 있으며, 이를 v14에 포팅한다. 구조는 Capacitor 클래스와 동일한 패턴(private constructor + static factory + public methods)을 따른다.

### 목표

- v14 _back Electron 클래스를 v14에 포팅 (initialize + build + run)
- 테스트 커버리지 확보 (initialize + build 시나리오)

### 비목표

- `run()` 테스트 — Feature 6.3 (코드는 포함하되 테스트는 6.3에서)
- Orchestrator/명령어 통합 — Feature 6.3
- Capacitor — Feature 6.1 (완료)
- macOS/Linux 빌드 — Windows만 지원

### 설계

#### 파일 구조

```
packages/sd-cli/src/electron/
  electron.ts          ← v14 _back에서 포팅
packages/sd-cli/tests/electron/
  electron.spec.ts     ← v14 _back에서 포팅
```

Electron 클래스는 Capacitor와 마찬가지로 BuildEngine이 아닌 독립 유틸리티. Feature 6.3에서 Orchestrator가 호출.

#### 클래스 구조

```typescript
export class Electron {
  private constructor(pkgPath, config, npmConfig, exclude)
  static async create(pkgPath, config, exclude?): Promise<Electron>
  private static _validateConfig(config): void

  // Public
  async initialize(): Promise<void>   // package.json + npm install + electron-rebuild
  async run(url: string): Promise<void>  // esbuild watch + Electron spawn (테스트는 6.3)
  async build(outPath: string): Promise<void>  // bundle + web assets + electron-builder + output copy

  // Private
  private _localBin(name): string
  private _exec(cmd, args, cwd, env?): Promise<string>
  private _setupPackageJson(srcPath): Promise<void>
  private _bundleMainProcess(outDir): Promise<void>
  private _copyWebAssets(outPath, srcPath): Promise<void>
  private static _canCreateSymlink(): boolean
  private _runElectronBuilder(srcPath): Promise<void>
  private _copyBuildOutput(outPath): Promise<void>
}
```

#### 의존성

v14 sd-cli에 이미 존재하는 의존성만 사용:
- `execa` (^9.6.1) — 명령어 실행
- `esbuild` — 번들링 (dynamic import)
- `@simplysm/core-node` (fsx) — 파일 시스템
- `consola` — 로깅
- `os`, `fs`, `path`, `module` — Node.js built-in

electron, electron-builder, electron-rebuild는 소비 패키지의 devDependencies로 설치 (sd-cli 자체에는 불필요).
