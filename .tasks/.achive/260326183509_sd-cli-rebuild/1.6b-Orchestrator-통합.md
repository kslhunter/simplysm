      Given Library 패키지에 copySrc가 설정되어 있다
      When sd-cli watch를 실행한다

    Scenario: watch에서 replaceDeps 감시
      Given sd.config.ts에 replaceDeps가 설정되어 있다
      When sd-cli watch를 실행한다
      Then replaceDeps 패키지가 감시된다

  Rule: dev 명령어가 server 대상으로 실행된다 (client는 client-ready 구조)

## 구현계획

### 배경

Feature 1.6a에서 명령어 통합(check --type, dts.worker 삭제, concurrency 제한)이 완료됐다. 현재 WatchOrchestrator(Library + Scripts watch)와 DevOrchestrator(Server watch + runtime)가 분리되어 있으며, ResultCollector/RebuildManager/SignalHandler 초기화 등 중복 코드가 존재한다. wbs.md 제거 대상에 "DevOrchestrator + WatchOrchestrator 분리 → 단일 Orchestrator"가 명시되어 있다.

### 목표

- DevOrchestrator + WatchOrchestrator → 단일 DevWatchOrchestrator로 통합
- watch 명령어: 전체 패키지(Library + Server + Scripts) 대상
- dev 명령어: Server + client-ready 대상
- 기존 WatchOrchestrator.ts, DevOrchestrator.ts 삭제

### 비목표

- Client BuildEngine(ViteEngine) 구현 (Feature 3.x)
- BuildOrchestrator 변경 (Feature 1.6a에서 완료)
- 명령어 통합 (Feature 1.6a에서 완료)

### 설계

#### DevWatchOrchestrator

DevOrchestrator + WatchOrchestrator를 단일 클래스로 통합. mode 파라미터로 watch/dev 분화.

```typescript
type OrchestratorMode = "watch" | "dev";

interface DevWatchOrchestratorOptions {
  mode: OrchestratorMode;
  targets: string[];
  options: string[];
}

class DevWatchOrchestrator {
  private readonly _mode: OrchestratorMode;

  // Common: engines, ResultCollector, RebuildManager, SignalHandler, replaceDepWatcher
  // Dev-specific: serverRuntimeWorkers Map, printServersTimer
  // Watch-specific: watchHookPackages, watchHookWatchers, copySrcWatchers
}
```

#### initialize() 패키지 분류

| mode | Library(node/browser/neutral) | Server | Client | Scripts |
|------|------|--------|--------|---------|
| watch | BuildEngine(js+dts) | BuildEngine(js) | — | watch hook |
| dev | 제외 | BuildEngine(js) + runtime | 인식 + 스킵(경고) | 제외 |

#### start()

- watch: engine.startWatch() + copySrc watchers + watch hook watchers
- dev: engine.startWatch() + runtime workers (batchComplete에서 재시작)

#### shutdown()

- 공통: engine.stop(), replaceDepWatcher.dispose()
- watch: copySrc/watchHook watcher.close()
- dev: runtime worker.terminate()

#### watch.ts / dev.ts 변경

```typescript
// watch.ts
const orchestrator = new DevWatchOrchestrator({ mode: "watch", targets, options });
// dev.ts
const orchestrator = new DevWatchOrchestrator({ mode: "dev", targets, options });
```

initialize() → start() → awaitTermination() → shutdown() 패턴 동일.

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| mode 파라미터로 watch/dev 분화 | 채택 | watch/dev 차이가 패키지 분류와 runtime 유무에 한정. 단순 |
| Orchestrator 3개 유지 (Watch에 server 추가만) | 미채택 | Watch + Dev 중복 코드. wbs.md "단일 Orchestrator" 방향과 불일치 |
| Orchestrator 상속 (base + watch/dev subclass) | 미채택 | 공유 상태(engines, infra)가 많아 상속보다 mode 파라미터가 단순 |
