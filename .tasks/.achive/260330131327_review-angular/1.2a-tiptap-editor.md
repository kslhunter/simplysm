## 구현계획

### 배경

`sd-tiptap-editor.control.ts`는 TipTap 에디터를 감싸는 Angular OnPush 컴포넌트이다. `DEFAULT_EXTENSIONS` 배열에 확장을 등록하고, `effect()`로 에디터 라이프사이클과 disabled/readonly 상태를 관리한다.

### 목표

- Underline 확장을 등록하여 밑줄 버튼이 동작하도록 한다 (LOGIC-004)
- `editor`를 signal로 변환하여 disabled/readonly effect가 editor 생성을 추적하도록 한다 (LOGIC-012)
- `activeStates`, `activeColor`, `activeBgColor`를 signal로 변환하여 OnPush에서 변경 감지되도록 한다 (DESIGN-005)

### 비목표

- 에디터 툴바 레이아웃이나 버튼 구성 변경
- 에디터 콘텐츠 직렬화 방식 변경

### 설계

#### Underline 등록

`@tiptap/extension-underline`을 import하고 `DEFAULT_EXTENSIONS`에 추가한다. StarterKit에 포함되지 않으므로 별도 등록이 필수이다.

#### editor signal 변환

- `editor: Editor | undefined` → `editor = signal<Editor | undefined>(undefined)`
- 첫 번째 effect(extensions/value 동기화)에서 editor 읽기: `untracked(() => this.editor())`로 순환 추적 방지
- 두 번째 effect(disabled/readonly)에서 editor 읽기: `this.editor()`로 추적 활성화
- `createEditor`/`destroyEditor`에서 `this.editor.set()`로 값 갱신
- 외부에서 `editor` 접근 시 `this.editor()` 호출 필요 (기존 테스트 fixture 갱신)

#### activeStates signal 변환

- `activeStates: Record<string, boolean> = {}` → `activeStates = signal<Record<string, boolean>>({})`
- `activeColor = ""` → `activeColor = signal("")`
- `activeBgColor = ""` → `activeBgColor = signal("")`
- `refreshActiveStates`에서 `.set()`으로 갱신
- 템플릿에서 `activeStates.bold` → `activeStates().bold`, `activeColor` → `activeColor()` 등

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| editor를 signal로 변환 | 채택 | 두 번째 effect가 자연스럽게 editor 생성을 추적. Angular signal 패턴에 부합 |
| disabled/readonly 로직을 첫 번째 effect에 통합 | 미채택 | disabled/readonly 변경마다 editor 재생성 분기를 거쳐야 하며, 관심사 분리 위반 |
| ChangeDetectorRef.markForCheck() 호출 | 미채택 | signal 변환이 더 선언적이며, 향후 Angular signal-based 변경 감지와 호환 |

## 요구명세

```gherkin
Feature: 1.2a TipTap Editor 수정

  Background:
    Given sd-tiptap-editor 컴포넌트가 렌더링되어 있다

  Rule: Underline 확장이 등록되어 밑줄 기능이 동작해야 한다

    Scenario: 밑줄 토글
      Given 에디터에 텍스트가 입력되어 있고 텍스트가 선택된 상태이다
      When U 버튼을 클릭한다
      Then 선택된 텍스트에 밑줄이 적용된다

    Scenario: 밑줄 active state 반영
      Given 에디터에 밑줄이 적용된 텍스트가 있다
      When 밑줄 영역에 커서를 위치시킨다
      Then activeStates.underline이 true이다
      And U 버튼에 _active 클래스가 적용된다

  Rule: disabled/readonly 상태가 editor 생성 직후에도 반영되어야 한다

    Scenario: disabled 상태로 초기 렌더링
      Given disabled 입력이 true이다
      When 컴포넌트가 초기화되어 editor가 생성된다
      Then editor의 editable이 false이다

    Scenario: 런타임 disabled 전환
      Given editor가 editable 상태로 생성되어 있다
      When disabled가 false에서 true로 변경된다
      Then editor.setEditable(false)가 호출된다

    Scenario: 런타임 readonly 전환
      Given editor가 editable 상태로 생성되어 있다
      When readonly가 false에서 true로 변경된다
      Then editor.setEditable(false)가 호출된다

  Rule: 에디터 툴바 active states가 OnPush에서 변경 감지되어야 한다

    Scenario: Bold 토글 시 툴바 반영
      Given 에디터에 텍스트가 선택된 상태이다
      When Bold를 토글한다
      Then 툴바의 B 버튼에 _active 클래스가 즉시 반영된다

    Scenario: 텍스트 색상 변경 시 인디케이터 반영
      Given 에디터에 텍스트가 선택된 상태이다
      When 텍스트 색상을 #ff0000으로 변경한다
      Then 색상 인디케이터의 배경색이 #ff0000으로 즉시 갱신된다
```
