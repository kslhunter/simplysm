# Feature 1.8 배포 파이프라인

## 참조 자료

- [wbs.md](wbs.md)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | 자동 커밋 방식 | Claude CLI (`claude -p "/sd-commit all"`) | v14 고유 기능으로 추가. 커밋 메시지 품질 보장. Claude CLI 미설치 시 에러로 수동 커밋 유도 |
| D2 | 버전 자동 업그레이드 범위 | patch/prerelease만 자동 | major/minor는 의도적 변경이므로 수동으로 package.json 수정 후 publish |
| D3 | 빌드 실패 시 복구 방식 | 수동 복구 안내 (자동 롤백 없음) | 자동 롤백 시 부분 성공 상태를 덮어쓸 위험. git checkout 명령어를 안내하여 개발자가 판단 |
| D4 | postPublish 실패 처리 | 경고만 출력, 배포 롤백 없음 | 이미 배포된 패키지를 롤백할 수 없으므로 경고로 처리 |
| D5 | 테스트 전략 | runPublish 통합 테스트 (내부 함수 간접 테스트) | runPublish만 export됨. 기존 check.spec.ts 패턴과 동일. 모든 외부 의존성 mock |

## 구현계획

### 배경

publish.ts (839줄)가 v13에서 v14로 마이그레이션되어 이미 동작 중이다 (8개 동작 명령 중 하나). 코드 구조:
- `replaceEnvVariables()`: 환경변수 치환 순수 함수 (56-73행)
- `waitWithCountdown()`: 카운트다운 출력 (78-93행)
- `ensureSshAuth()`: SSH 키 인증 설정 (102-172행) → `testSshKeyAuth()`, `registerSshPublicKey()`
- `upgradeVersion()`: 버전 업그레이드 (268-319행)
- `publishPackage()`: 개별 패키지 배포 (329-392행)
- `computePublishLevels()`: 의존성 레벨 계산 (402-455행)
- `runPublish()`: 메인 publish 진행 (472-836행) — **유일한 export 함수**

### 목표

- 기존 publish.ts의 모든 Gherkin Scenario를 테스트로 커버
- 기존 check.spec.ts 패턴(`vi.hoisted` → `vi.mock` → `await import`)과 동일한 구조로 작성

### 비목표

- publish 파이프라인 재작성 또는 리팩터링
- 새로운 배포 타입 추가
- 실제 npm/SSH/FTP 연결을 사용하는 E2E 테스트
