# Feature 2.1 Angular 빌드 어댑터

## 참조 자료

- [wbs.md](wbs.md)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | Library 빌드 컴파일 API | 하이브리드: `NgtscProgram`(`@angular/compiler-cli` 공식 export) + `AngularLibraryHostExtensions`(어댑터 자체 정의) | 공식 export의 안정성. `@angular/build/src/tools/angular/angular-host`가 exports 필드에 의해 차단되므로 `createAngularCompilerHost` re-export 대신 duck-typing 인터페이스를 자체 정의. v12 선례에서 `NgtscProgram`의 per-file emit 제어가 library 빌드에 적합함을 검증 |
| D4 | Angular Host 확장 방식 | `AngularLibraryHostExtensions` 인터페이스 자체 정의 | `@angular/build`의 exports 필드가 `./src/tools/...` 내부 경로를 차단하여 `createAngularCompilerHost` 접근 불가. NgtscProgram이 duck-typing으로 확인하는 메서드(`readResource`, `transformResource`, `getModifiedResourceFiles`)를 인터페이스로 정의 |
| D2 | `@angular/compiler-cli` 의존성 | sd-cli package.json에 직접 의존성으로 추가 | D1에서 `NgtscProgram`을 직접 import하므로 간접 의존성으로는 불충분 |
| D3 | 어댑터 래핑 범위 정책 | 필요 시 추가 (Lazy) | YAGNI 원칙. 2.1에서는 Client 빌드 API + Library 컴파일 API만 래핑. browserslist/PostCSS 등은 Feature 5.1에서 필요할 때 추가 |

## 구현계획

### 배경

`angular-build.ts` 어댑터 모듈(134줄)이 `@angular/build/private` API를 re-export하여 Client(Application) 빌드에 필요한 API를 제공한다. Angular Library 빌드(Feature 2.2)에는 `@angular/compiler-cli`의 `NgtscProgram`과 `@angular/build` 내부의 Host 유틸리티가 추가로 필요하다. 현재 어댑터를 import하는 소비자는 없으며(Client 빌드 코드 미구현), 이 Feature에서는 어댑터의 API 표면을 확장한다.

### 목표

- `@angular/compiler-cli`를 sd-cli의 직접 의존성으로 추가
- Library 빌드에 필요한 Angular 컴파일러 API(`NgtscProgram`, `OptimizeFor`, `AngularLibraryHostExtensions`)를 어댑터에 추가
- 격리 구조 유지: Angular internal/private API는 오직 `angular-build.ts`에서만 import

### 비목표

- browserslist/PostCSS 관련 API 래핑 (Feature 5.1에서 필요 시 추가)
- ServiceWorker/i18n 관련 API 래핑
- Library 빌드 로직 구현 (Feature 2.2)
- Client 빌드 Worker 구현 (Feature 3.1)

### 설계

#### 변경 파일

| 파일 | 변경 내용 |
|------|----------|
| `packages/sd-cli/package.json` | `dependencies`에 `@angular/compiler-cli: "^21"` 추가 |
| `packages/sd-cli/src/utils/angular-build.ts` | Library 컴파일 API re-export 섹션 추가 |

#### Library 컴파일 API re-export 구조

기존 어댑터의 섹션 구조를 따라 새 섹션을 추가한다:

```
// ── Re-exports: Angular Compiler (Library) ──
NgtscProgram, OptimizeFor  ← @angular/compiler-cli

// ── Angular Library Host Extensions ──
AngularLibraryHostExtensions (interface)  ← 어댑터 자체 정의
```

`@angular/build/src/tools/angular/angular-host`의 `createAngularCompilerHost`는 exports 필드에 의해 차단되므로 사용 불가. 대신 `NgtscProgram`이 duck-typing으로 확인하는 메서드를 인터페이스로 자체 정의한다.

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| `AngularLibraryHostExtensions` 인터페이스 자체 정의 | 채택 | `@angular/build`의 exports 필드가 내부 경로를 차단하여 `createAngularCompilerHost` 접근 불가. duck-typing 인터페이스로 동일 효과 달성 |
| `createAngularCompilerHost` re-export | 미채택 | `@angular/build`의 exports 필드에 의해 차단됨 (`./src/tools/...` 경로 미노출) |
| `createAngularCompilation` (`@angular/build/private`) | 미채택 | application 빌드 전용 설계, per-file unbundled 출력에 부적합 (D1 결정) |
