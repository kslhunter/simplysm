## 요구명세

Feature: 1.1 빌드 시 side-effect SCSS → CSS 컴파일 및 출력

  Background:
    Given NgtscEngine으로 Angular 라이브러리를 빌드한다
    And 패키지에 `declare module "*.scss" {}` ambient 선언이 있다

  Rule: Side-effect .scss import는 CSS로 컴파일되어 dist에 출력된다

    Scenario: 기본 side-effect SCSS 컴파일
      Given src/ui/layout/sd-flex.directive.ts에 `import "./sd-flex.scss"` side-effect import가 있다
      And src/ui/layout/sd-flex.scss 파일이 존재한다
      When 라이브러리를 빌드한다
      Then dist/ui/layout/sd-flex.css가 생성된다
      And 파일 내용은 SCSS를 CSS로 컴파일한 결과이다

    Scenario: SCSS @use 의존성 해석
      Given SCSS 파일이 `@use "commons/variables"` 를 사용한다
      And buildScssLoadPaths에 pkgDir/scss가 포함되어 있다
      When 라이브러리를 빌드한다
      Then @use 참조가 정상 해석되어 컴파일된 CSS에 포함된다

    Scenario: SCSS 컴파일 에러
      Given SCSS 파일에 문법 에러가 있다
      When 라이브러리를 빌드한다
      Then 빌드 결과에 SCSS 에러가 포함된다

    Scenario: 참조하는 SCSS 파일이 존재하지 않음
      Given import 경로의 .scss 파일이 존재하지 않는다
      When 라이브러리를 빌드한다
      Then 빌드 결과에 파일 미존재 에러가 포함된다

  Rule: Emitted JS에서 .scss import 경로가 .css로 변환된다

    Scenario: 기본 import 경로 변환
      Given src/ui/layout/sd-card.directive.ts에 `import "./sd-card.scss"` 가 있다
      When 라이브러리를 빌드한다
      Then dist/ui/layout/sd-card.directive.js에 `import "./sd-card.css"` 가 포함된다

    Scenario: 하위 디렉토리 경로 변환
      Given `import "./styles/card.scss"` side-effect import가 있다
      When 라이브러리를 빌드한다
      Then emitted JS에 `import "./styles/card.css"` 가 포함된다
      And dist에 해당 하위 경로에 card.css가 생성된다

  Rule: TypeScript가 .scss side-effect import를 에러 없이 처리한다

    Scenario: ambient module 선언으로 .scss import 해석
      Given 프로젝트에 `declare module "*.scss" {}` ambient 선언이 있다
      And 소스에 `import "./sd-card.scss"` 가 있다
      When TypeScript 컴파일을 진행한다
      Then .scss import에 대한 TS 에러가 발생하지 않는다

  Rule: package.json sideEffects에 CSS 패턴이 포함된다

    Scenario: sideEffects에 CSS 패턴 추가
      Given package.json sideEffects가 `["./src/index.ts", "./dist/index.js"]` 이다
      When side-effect SCSS import를 사용하는 패키지를 배포한다
      Then sideEffects에 `"./dist/**/*.css"` 패턴이 포함되어야 한다

## 구현계획

### 배경

NgtscEngine은 Angular 라이브러리 빌드를 담당한다. 현재 SCSS 처리 경로:
1. `@Component` 인라인/외부 styles → `createLibraryTransformStylesheet` → CSS 변환 (JS에 인라인)
2. 글로벌 `scss/styles.scss` → `compileGlobalScss` → `dist/styles.css`

Side-effect import(`import "./foo.scss"`)는 미처리. emitted JS에 `.scss` 경로가 그대로 남아 런타임 에러 유발.

### 목표

- emitted JS에서 `.scss` side-effect import 감지 및 `.scss` → `.css` 경로 변환
- 참조된 SCSS 파일을 CSS로 컴파일하여 dist에 출력
- TypeScript 컴파일 호환성 보장 (ambient module declaration)
- bundler tree-shake 방지를 위한 sideEffects 설정

### 비목표

- Watch mode SCSS 변경 감지 (Feature 1.2)
- Client dev mode HMR (Feature 1.3)
- SCSS 파일 이동/directive 전환 (Feature 2.1)

### 설계

#### `rewriteScssImports` 유틸리티 (`output-path-rewriter.ts`)

`addJsExtensionToImports`와 동일한 regex 패턴 기반. `.scss`로 끝나는 상대 import를 `.css`로 변환하면서 변환된 원본 import 경로 목록을 반환한다.

```ts
export function rewriteScssImports(text: string): { text: string; scssImports: string[] }
```

- `from`과 `import` 모두 처리 (동적 import 포함)
- 반환된 `scssImports`는 SCSS 컴파일 대상 경로

추가로 `addJsExtensionToImports`의 skip list에 `.scss` 추가 — `tsc-build` 경로에서 `.scss` import에 `.js` 확장자가 붙는 것을 방지.

#### `writeEmitResults` 확장 (`ngtsc-build-core.ts`)

optional SCSS 처리 파라미터 추가:

```ts
export interface SideEffectScssOptions {
  loadPaths: string[];
  scssErrors: string[];
  scssDependencies: Map<string, Set<string>>;
}

export function writeEmitResults(
  emitResults: Iterable<{ filename: string; contents: string; sourceFileName?: string }>,
  pkgDir: string,
  scss?: SideEffectScssOptions,
): void
```

처리 흐름 (scss 옵션 제공 + `.js` 파일):
1. `rewriteScssImports(contents)` → 변환된 텍스트 + SCSS import 경로 목록
2. 각 SCSS import를 `sourceFileName` 디렉토리 기준으로 절대 경로 해석
3. `compileScssFile(scssPath, scss.loadPaths)` → CSS + dependencies
4. CSS를 rewritten JS와 동일 디렉토리에 출력 (경로: import의 `.scss` → `.css`)
5. 에러 시 `scss.scssErrors`에 추가, dependency는 `scss.scssDependencies`에 `trackDeps`로 추적

#### `runNgtscBuild` 갱신

기존 `writeEmitResults(emitResults, info.pkgDir)` 호출에 SCSS 옵션 전달:

```ts
writeEmitResults(emitResults, info.pkgDir, {
  loadPaths,
  scssErrors,
  scssDependencies,
});
```

`loadPaths`, `scssErrors`, `scssDependencies`는 이미 `runNgtscBuild` 스코프에 존재.

#### TypeScript ambient 선언 (`packages/angular/src/scss.d.ts`)

```ts
declare module "*.scss" {}
```

#### package.json sideEffects (`packages/angular/package.json`)

`sideEffects` 배열에 `"./dist/**/*.css"` 추가.

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| `writeEmitResults` 후처리 (regex 기반) | 채택 | `addJsExtensionToImports`와 동일 패턴, 기존 파이프라인에 자연스럽게 통합 |
| TypeScript custom transformer (AST 기반) | 미채택 | transformer에서 SCSS 컴파일(부작용)은 incremental 캐싱과 충돌 가능 |
| dist 디렉토리 후처리 (파일 시스템 스캔) | 미채택 | 메모리의 emit 결과를 디스크에서 재읽기하는 불필요한 I/O, sourceFileName 매핑 소실 |
