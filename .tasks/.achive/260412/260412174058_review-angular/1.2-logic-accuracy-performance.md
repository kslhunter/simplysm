## 구현계획

### 배경

`packages/angular/src/` 내 5개 파일에서 로직 방어, 설계 개선, 성능 최적화가 필요하다. 모든 수정 대상은 독립적 파일에 위치하여 상호 간섭이 없다.

### 목표
- key undefined 시 constructor.name 폴백 적용 [근거: Rule "key undefined 시 폴백 적용"]
- bwipjs.toSVG() computed 내 try/catch 적용 [근거: Rule "bwipjs.toSVG() 예외 안전 처리"]
- 프리셋 추가 시 이름 중복 검사 [근거: Rule "프리셋 이름 중복 검사"]
- isSelected()를 Set.has() 기반 O(1)로 변경 [근거: Rule "isSelected() O(1)"]
- getChildren 정렬 결과를 computed로 메모이제이션 [근거: Rule "getChildren 메모이제이션"]

### 비목표
- LOGIC-002 filter 깊은 복제 — 의도된 설계 [근거: D1]
- LOGIC-004 persist 실패 시 롤백 — 에러 보고만으로 충분 [근거: D2]

### 설계

#### LOGIC-001: key 폴백 (`sd-data-sheet.base.ts:87`)

현재:
```typescript
key = reflectComponentType(this.constructor as any)?.selector;
```

변경:
```typescript
key = reflectComponentType(this.constructor as any)?.selector ?? this.constructor.name;
```

`constructor.name`은 클래스명이므로 고유성이 보장된다. Chrome 61+에서 지원된다. [근거: Rule "key undefined 시 폴백 적용"]

#### LOGIC-003: barcode try/catch (`sd-barcode.ts:30-39`)

현재:
```typescript
protected _trustedSvgHtml = computed(() => {
  const text = this.value();
  if (text == null || text === "") { return ""; }
  const svg = bwipjs.toSVG({ bcid: this.type(), text });
  return this._sanitizer.bypassSecurityTrustHtml(svg);
});
```

변경: bwipjs.toSVG() 호출을 try/catch로 감싸고, 예외 시 빈 문자열 반환. [근거: Rule "bwipjs.toSVG() 예외 안전 처리"]

#### DESIGN-004: 프리셋 이름 중복 검사 (`sd-state-preset.ts:120`)

`onAddClick()` 내에서 name 입력 후 `_presets()`에 동일 이름 존재 여부 확인. 중복 시 `_sdToast.warning()` 후 early return. [근거: Rule "프리셋 이름 중복 검사"]

#### PERF-001: isSelected Set 기반 (`useSelectionManager.ts:89-91`)

computed `selectedItemsSet`을 추가하여 `new Set(options.selectedItems())`를 캐싱. `isSelected()`에서 `selectedItemsSet().has(item)` 사용. [근거: Rule "isSelected() O(1)"]

참고: 같은 파일의 `isAllSelected`(32행)에서 이미 `new Set(options.selectedItems())`를 생성하고 있으므로, 이를 공유 computed로 통합한다.

#### PERF-002: getChildren 메모이제이션 (`sd-shared-data-select.ts:324-341`)

현재 `getChildren`은 일반 메서드로 호출마다 정렬을 수행한다. 정렬된 자식 Map을 computed로 캐싱한다.

현재:
```typescript
getChildren = (item: SharedDataBase<string | number>): TItem[] => {
  let result = this.itemByParentKeyMap()?.get(item.__valueKey as TItem["__valueKey"]) ?? [];
  const orderProp = this.displayOrderKeyProp();
  if (orderProp != null) {
    result = [...result].sort((a, b) => { ... });
  }
  return result;
};
```

변경: `sortedChildrenMap` computed를 추가. `itemByParentKeyMap`과 `displayOrderKeyProp`에 의존. `getChildren`은 이 Map에서 lookup만 수행. [근거: Rule "getChildren 메모이제이션"]

### 대안 검토

| 항목 | 대안 | 미채택 사유 |
|---|---|---|
| LOGIC-001 | key를 abstract으로 변경 | API 변경이 크고 모든 소비 코드 수정 필요. 폴백이 더 안전 |
| PERF-001 | WeakSet 사용 | Set으로 충분하고 WeakSet은 iteration 불가 |
| PERF-002 | getChildren 호출자에서 캐싱 | sd-select 내부이므로 수정 범위가 넓어짐 |
