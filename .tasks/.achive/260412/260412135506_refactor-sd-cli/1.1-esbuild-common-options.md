## 구현계획

### 배경

`Electron` 클래스의 `run()` (dev 모드)과 `_bundleMainProcess()` (프로덕션)에서 esbuild 설정이 중복 구성된다. 공통 부분을 추출하여 DRY 원칙을 적용한다. [근거: STRUCT-001]

### 목표

- `run()`과 `_bundleMainProcess()`의 공통 esbuild 옵션을 단일 메서드로 통합 [근거: Rule "공통 esbuild 옵션이 일관되게 생성된다"]

### 비목표

- `run()` 메서드의 Electron 프로세스 스폰/재시작 로직 변경 [근거: wbs 경계]
- `build()` 메서드의 웹 에셋 복사, electron-builder 실행 변경 [근거: wbs 경계]

### 설계

`_createBaseEsbuildOptions(extraEnv?)` private async 메서드 추출:
- entryPoint 해석 + 존재 확인
- builtinModules 계산
- reinstallDeps 추출
- envBanner/bannerJs 구성
- esbuild 공통 옵션 객체 반환

`run()`: `_createBaseEsbuildOptions({ ELECTRON_DEV_URL: url })` 호출 → 결과에 plugins 추가 → `esbuild.context()`
`_bundleMainProcess()`: `_createBaseEsbuildOptions()` 호출 → `esbuild.build()`

### 대안 검토

- **독립 유틸 함수 추출**: 클래스 외부로 추출할 수도 있으나, `this._pkgPath`, `this._srcPath`, `this._config`, `this._exclude` 등 인스턴스 상태에 의존하므로 private 메서드가 자연스러움. 불필요한 파라미터 전달 회피.

- **Scenarios:** 전체 (공통 옵션 생성, entryPoint 미존재 에러)
