## 구현계획

### 배경

sd-cli client 빌드에서 `@angular/build`의 `createCompilerPlugin`은 `.ts` 인라인 SCSS에 PostCSS를 적용하지만, library `.js`의 inline CSS와 SCSS side-effect import에는 적용하지 않는다. Feature 1.1에서 onEnd 플러그인으로 출력 파일 통합 처리를 구현했고, Feature 1.2에서는 createCompilerPlugin의 내부 PostCSS를 비활성화하고, SCSS 플러그인과 onEnd 플러그인으로 모든 CSS 경로를 통합한다. [근거: wbs 배경]

### 목표

- `createCompilerPlugin`의 `postcssConfiguration`을 항상 `undefined`로 설정하여 이중 처리 방지 [근거: Rule "postcssConfiguration 비활성화"]
- `esbuild-scss-plugin`에서 SCSS→CSS 후 PostCSS 적용으로 side-effect SCSS 커버 [근거: Rule "SCSS 플러그인 PostCSS"]
- `createPostcssPlugin`(Feature 1.1)을 plugins 배열에 등록하여 `.css`/`.js` inline CSS 커버 [근거: Rule "onEnd 플러그인 배치"]
- PostCSS 플러그인 튜플을 인스턴스로 로딩하여 두 플러그인에 전달 [근거: D1, D2]

### 비목표

- library 빌드 변경 [근거: wbs 경계]
- `client-transform-stylesheet.ts` 변경 [근거: wbs 경계]
- `sd-config.types.ts` 인터페이스 변경 [근거: 소비측 인터페이스 유지]

### 설계

**변경 파일:**

1. **`packages/sd-cli/src/esbuild/esbuild-scss-plugin.ts`**
   - `CreateScssPluginOptions`에 `postcssPlugins?: AcceptedPlugin[]` 추가
   - `import postcss from "postcss"` 및 `import type { AcceptedPlugin } from "postcss"` 추가
   - `onLoad`에서 SCSS→CSS 후 PostCSS 적용
   - PostCSS 실패 시 sass 에러와 동일한 패턴으로 esbuild errors 반환
   [근거: `client-transform-stylesheet.ts:62-64`의 postcss 사용 패턴]

2. **`packages/sd-cli/src/esbuild/esbuild-client-config.ts`**
   - `import { createRequire } from "module"` 추가
   - `import { createPostcssPlugin } from "./esbuild-postcss-plugin"` 추가
   - `CreateClientEsbuildOptions`에서 `postcssConfigPath` 제거 [근거: D3]
   - `postcssConfiguration` 삼항(94-100행)을 `postcssConfiguration: undefined`로 교체
   - PostCSS 플러그인 로딩 로직 추가: `createRequire(pkgDir/package.json)`로 resolve [근거: D2]
   - `createScssPlugin({ loadPaths, postcssPlugins: loadedPlugins })` 호출 [근거: wbs]
   - plugins 배열에 `createPostcssPlugin({ plugins: loadedPlugins })` 등록 (customPlugins 뒤, sd-legacy-strip-dynamic-import 앞) [근거: wbs]
   - 등록 조건: `loadedPostcssPlugins != null` [근거: D4]

3. **`packages/sd-cli/src/workers/client.worker.ts`**
   - `postcssConfigPath: info.pkgDir` 전달 제거 (121행, 229행) [근거: D3]

**plugins 배열 최종 순서:**
```
[sd-hmr-reset?, angularPlugin, scssPlugin, ...customPlugins, sd-postcss?, sd-legacy-strip-dynamic-import?, sd-on-end?]
```

**PostCSS 플러그인 로딩 로직 (esbuild-client-config.ts):**
```typescript
import { createRequire } from "module";

let loadedPostcssPlugins: AcceptedPlugin[] | undefined;
if (options.postcssPlugins != null && options.postcssPlugins.length > 0) {
  const req = createRequire(path.join(options.pkgDir, "package.json"));
  loadedPostcssPlugins = options.postcssPlugins.map(([name, pluginOptions]) => {
    const pluginFn = req(name);
    const fn = pluginFn.default ?? pluginFn;
    return pluginOptions != null ? fn(pluginOptions) : fn;
  });
}
```

**SCSS 플러그인 PostCSS 적용 (esbuild-scss-plugin.ts):**
```typescript
const result = await compileScssFileAsync(args.path, options.loadPaths);
let css = result.css;

if (options.postcssPlugins != null && options.postcssPlugins.length > 0) {
  const processed = await postcss(options.postcssPlugins).process(css, { from: args.path });
  css = processed.css;
}

return { contents: css, loader: "css", watchFiles: result.dependencies };
```
