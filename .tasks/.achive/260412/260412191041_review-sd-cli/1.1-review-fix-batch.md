## 구현계획

### 배경

sd-cli 패키지의 코드 리뷰에서 에러 처리 누락, 일관성 문제, dead code 등 8개 이슈가 발견되었다. 모두 1-5줄 수준의 독립적 수정이며 기존 동작(성공 경로)에 영향을 주지 않는다.

### 목표

- startWatch 실패 시 에러 가시성 확보 [근거: DESIGN-001, DESIGN-002]
- HMR 변경 감지 정확도 개선 [근거: DESIGN-003]
- 코드 일관성 및 dead code 정리 [근거: CONSIST-001, CONSIST-002, DESIGN-004, DESIGN-005, LOGIC-001]

### 비목표

- 기존 성공 경로 동작 변경 [근거: wbs 경계 "방어적 수정만 수행"]
- 새로운 기능 추가

### 설계

#### DESIGN-001: BaseEngine.ts:185-187

현재: `this._callStartWatch(output).catch(() => { resolveInitialBuild(); });`

수정: catch 블록에서 에러를 로깅하고 ResultCollector에 보고 후 resolveInitialBuild() 호출.
- `err as errNs` import는 이미 존재 (BaseEngine.ts에는 없지만, `@simplysm/core-common`에서 가져와야 함)

#### DESIGN-002: EsbuildClientEngine.ts:135-138

현재: `logger.error(...)` 로깅만 수행.

수정: ResultCollector에 status:"error" 보고 추가. setupWatchEvents에서 이미 처리하는 부분과 중복되지 않도록, 기존 logger.error는 유지하되 ResultCollector 보고가 누락된 경우에만 추가.

재검증: setupWatchEvents가 worker의 startWatch 결과를 별도 이벤트로 보고하는지 확인 필요. worker.startWatch()는 직접 결과를 반환하므로 setupWatchEvents의 이벤트 경로와는 별개. → ResultCollector 보고 추가 필요.

#### DESIGN-003: hmr-service.ts:52-61, 94-96

현재: `output.bytes` (파일 크기)로 변경 감지.

수정: HmrServiceOptions에 `distDir` 추가. collectOutputs에서 파일을 읽어 `crypto.createHash("md5")` 해시를 계산하여 저장. Map<string, number> → Map<string, string> (해시 문자열).

영향 파일: hmr-service.ts (옵션 타입 + collectOutputs + dispatchHmrMessage), client.worker.ts (HmrService 생성 시 distDir 전달).

#### CONSIST-001: TypecheckOrchestrator.ts:265-266

현재: `d.category === 1`, `d.category === 0`

수정: `d.category === ts.DiagnosticCategory.Error`, `d.category === ts.DiagnosticCategory.Warning`. `ts` import는 이미 존재 (line 0).

#### CONSIST-002: WatchOrchestrator.ts:180-182

현재: `this._watchHookWatchers.length = 0`

수정: `this._watchHookWatchers = []` (다른 두 배열과 동일 패턴)

#### DESIGN-004: engine-factory.ts:27, DevOrchestrator.ts:100,112

현재: `resolvedReplaceDeps` 파라미터 정의 + 전달.

수정: engine-factory.ts에서 파라미터 제거, DevOrchestrator.ts에서 변수 생성 및 전달 코드 제거.

#### DESIGN-005: storage-publisher.ts:141

현재: `conn.on("error", () => { resolve(false); });`

수정: `conn.on("error", () => { conn.end(); resolve(false); });`

#### LOGIC-001: electron.ts:169

현재: `void ctx.dispose(); resolve();`

수정: cleanup 함수를 async로 변경하고 `await ctx.dispose(); resolve();`

### 대안 검토

DESIGN-003에서 hash 대신 다른 접근:
- **esbuild OutputFile.hash 사용**: `write: false` 모드 전환 필요 → 변경 범위가 큼. 기각.
- **metafile.inputs 구조 비교**: inputs의 bytesInOutput도 content hash가 아님. 기각.
- **항상 full-reload**: CSS-only 최적화를 포기. 기각 — hash 계산 비용이 미미하므로.

### Vertical Slicing

#### Slice 1: 에러 보고 개선 (DESIGN-001, DESIGN-002)
- **구현 내용:** BaseEngine.catch 블록에 로깅/ResultCollector 보고 추가, EsbuildClientEngine에 ResultCollector 보고 추가
- **Scenarios:** BaseEngine._callStartWatch() RPC 실패, EsbuildClientEngine 초기 빌드 실패

#### Slice 2: HMR 변경 감지 개선 (DESIGN-003)
- **구현 내용:** HmrServiceOptions에 distDir 추가, collectOutputs를 hash 기반으로 변경, client.worker에서 distDir 전달
- **Scenarios:** 파일 내용 변경되었지만 크기 동일한 경우

#### Slice 3: 일관성 및 정리 (CONSIST-001, CONSIST-002, DESIGN-004, DESIGN-005, LOGIC-001)
- **구현 내용:** 매직 넘버→enum, 배열 정리 통일, dead parameter 제거, SSH conn.end() 추가, await ctx.dispose()
- **Scenarios:** TypecheckOrchestrator 진단 필터링, WatchOrchestrator shutdown, createBuildEngine resolvedReplaceDeps 제거, SSH error 정리, Electron cleanup
