- CONSIST-001: `sd-checkbox.ts:250`, `sd-switch.ts:24` — tabindex 불일치

### 설계 결정
| # | 결정사항 | 선택 | 근거 |

| D1 | `headerStyle` 처리 방식 | SdModal input + SdModalOptions에서 제거 | WBS 경계: 기능 구현은 범위 초과. 소비자가 사용해도 효과 없었으므로 제거가 적합 |

## 구현계획

### 배경

SdModal 컴포넌트(`sd-modal.ts`)에 `headerStyle`과 `noFirstControlFocusing` 두 input이 선언되어 있으나, 컴포넌트 템플릿이나 로직에서 사용되지 않는 dead code이다.

SdModalProvider(`sd-modal.provider.ts:128-133`)는 `SdModalOptions`의 모든 key를 `modalRef.setInput(key, value)` 루프로 SdModal에 전달한다. input을 제거할 때 이 루프에서 해당 key를 필터링해야 런타임 에러를 방지한다.

SdCheckbox와 SdSwitch는 같은 `controls/checkbox/` 디렉토리에 위치하는 같은 성격의 컴포넌트이나, tabindex 호스트 바인딩 표현식이 다르다. [근거: CONSIST-001]

### 목표
- SdModal에서 dead input 2건을 제거하여 API 정합성 확보 [근거: DESIGN-001]
- tabindex 바인딩 통일 [근거: CONSIST-001]

### 비목표
- headerStyle 기능 구현 (헤더에 인라인 스타일 적용) [근거: WBS 제외사항]

### 설계

**SdModal dead input 제거:**
1. `sd-modal.ts`: `headerStyle` input, `noFirstControlFocusing` input 삭제
2. `sd-modal.provider.ts`:
   - `SdModalOptions`에서 `headerStyle` 프로퍼티 삭제
   - `noFirstControlFocusing`은 유지 (line 171에서 직접 사용)
   - setInput 루프(line 128-133)에서 `noFirstControlFocusing` key를 필터링

**tabindex 통일:**
3. `sd-checkbox.ts`: `"[attr.tabindex]": "0"` → `"[attr.tabindex]": "'0'"`

### 대안 검토

- `headerStyle` 기능 구현 대신 제거를 선택 — 기존에 한 번도 동작한 적 없는 기능을 새로 구현하는 것은 범위를 초과하고, 소비자 코드에서 사용 중이어도 효과가 없었으므로 제거가 적합
- `noFirstControlFocusing`을 SdModalOptions에서도 제거하는 대안 — provider가 line 171에서 직접 사용하므로 불가
