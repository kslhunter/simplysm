## 구현계획

### 배경

`@simplysm/angular` 패키지의 코드 리뷰에서 발견된 Critical 1건, Medium 5건의 이슈를 수정한다. 모든 수정은 기존 코드베이스의 패턴을 따르며, 공개 API 시그니처를 변경하지 않는다.

### 목표

- TipTap 에디터의 Underline 기능 정상 동작 [근거: Rule "TipTap Underline 확장이 등록되어야 함"]
- 데이터 시트 셀 복사 시 null 안전성 확보 [근거: Rule "clipboard.writeText에 null을 전달하면 안 됨"]
- SdTextfield 입력 시 UI-model 일관성 보장 [근거: Rule "파싱 실패 시 input UI를 이전 유효 값으로 복원"]
- 에러 핸들링 안정성 향상 [근거: Rule "에러를 삼키지 않고 로깅", "이중 destroy 방지"]
- 이벤트 리스너 교체 시 경합 방지 [근거: Rule "리스너 교체 시 이벤트 이중 처리 방지"]

### 비목표

- Low severity 이슈 수정 (Feature 1.2에서 처리) [근거: wbs 경계 "Low severity 이슈는 이 Feature에서 다루지 않음"]

### 설계

**LOGIC-001**: `sd-tiptap-editor.ts`에 `@tiptap/extension-underline` import 추가, `DEFAULT_EXTENSIONS` 배열에 `Underline` 포함. `package.json`에 의존성 추가.

**LOGIC-002**: `useSheetCellAgent.ts:196`에서 `td.textContent`를 `td.textContent ?? ""`로 변경.

**LOGIC-003**: `sd-textfield.ts`의 `onInput` 메서드에서 `parsed === undefined` 분기에 `inputEl.value = this.controlValue()` 추가. `onInputPaste`와 동일한 패턴.

**LOGIC-004**: `sd-base-container.ts`에 `SdSystemLogProvider` inject 추가. catch 블록에서 `void this._systemLog.writeAsync("warn", ...)` 호출.

**DESIGN-001**: `sd-global-error-handler.plugin.ts:81-82`의 catch 블록에서 `appRef.destroy()`를 try-catch로 래핑.

**DESIGN-002**: `sd-shared-data.provider.ts`의 `register` 메서드에서 `void client.removeListener(...)` → `await client.removeListener(...)`. `register` 메서드를 `async`로 변경.

### 대안 검토

**DESIGN-002 대안**: register를 async로 변경하지 않고, `_loadAndListen`에서 entry의 리스너 키 유효성을 체크하는 방식. 그러나 이 방식은 이벤트 수신 시점의 경합만 줄이고 근본적으로 해결하지 못하므로 기각.
