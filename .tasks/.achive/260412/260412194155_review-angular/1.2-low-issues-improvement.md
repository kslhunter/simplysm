## 구현계획

### 배경

`@simplysm/angular` 패키지의 코드 리뷰에서 발견된 Low severity 이슈 7건에 대한 수정. 각 이슈는 독립적이며, signal 기반 상태 관리, 이벤트 처리, 에러 핸들링 패턴에 대한 개선. [근거: review.md LOGIC-005~006, CONSIST-001~002, DESIGN-003~005]

### 목표

- setupModelHook에서 async canFn + model.update 조합 시 stale value 방지 [근거: Rule "LOGIC-005", D3]
- SdNavigateWindowProvider.open에서 params 미지정 시 깔끔한 URL 생성 [근거: Rule "LOGIC-006"]
- SdCheckbox와 SdSwitch의 canChangeFn + stopPropagation 기능 통일 [근거: Rule "CONSIST-001", D2]
- _getOrmDataEditToastErrorMessage 중복 제거 [근거: Rule "CONSIST-002"]
- SdModal의 void async 호출에 .catch() 에러 핸들링 추가 [근거: Rule "DESIGN-003"]
- SdDataDetailBase의 queueMicrotask async 패턴에 try-catch 추가 [근거: Rule "DESIGN-004"]
- SdPermissionTable�� collapsedItems를 문자열 키 기반으로 변경 [근거: Rule "DESIGN-005"]

### 비목표

- PERF-001: SdSelect contentHTML effect 최적화 — 이미 `untracked()` + 선택 아이템만 `contentHTML()` 읽기로 해결됨 [근거: D4, sd-select.ts:336,354]
- 기존 공개 API 시그니처 변경 [근거: wbs 경계 "기존 공개 API 시그니처는 변경하지 않음"]

### 설계

**LOGIC-005** (`setupModelHook.ts`):
`model.update`를 변경하여 async canFn인 경우 canFn resolve 후 `fn(model())`을 재계산. 동기 canFn은 기존처럼 `model.set`에 위임. [근거: D3]

**LOGIC-006** (`sd-navigate-window.provider.ts`):
`open()` 메서드의 두 분기에서 params가 undefined이거나 빈 객체일 때 세미콜론 + params 부분을 생략하는 헬퍼 로직 추가. [근거: Rule "LOGIC-006"]

**CONSIST-001** (`sd-switch.ts`, `sd-checkbox.ts`):
- `sd-switch.ts`: `canChangeFn` input 추가 (기본값 `() => true`), `setupModelHook` 호출 추가. import에 `setupModelHook`, `input` 시그니처 변경 등.
- `sd-checkbox.ts`: `onClick()`에 `event: Event` 파라미터 추가, `event.preventDefault()` + `event.stopPropagation()` 추가. host 바인딩의 `(click)` 핸들러에 `$event` 전달. `onKeydown`에도 `event.stopPropagation()` 추가.
[근거: D2]

**CONSIST-002** (새 파일 + `sd-data-detail.base.ts`, `sd-data-sheet.base.ts`):
`getOrmDataEditToastErrorMessage()` 함수를 `data/getOrmDataEditToastErrorMessage.ts`로 추출. 두 base 클래스에서 private 메서드를 제거하고 import하여 사용. `index.ts`에 export 추가. [근거: Rule "CONSIST-002"]

**DESIGN-003** (`sd-modal.ts`):
`ErrorHandler`를 inject하고, `void this._restoreConfig(k)` → `void this._restoreConfig(k).catch((err) => this._errorHandler.handleError(err))`, `void this._saveConfig()` 3곳에 동일 패턴 적용. [근거: Rule "DESIGN-003"]

**DESIGN-004** (`sd-data-detail.base.ts`):
`ErrorHandler`를 inject하고, `queueMicrotask(async () => { ... })` 내부에 최외곽 try-catch 추가, catch에서 `errorHandler.handleError(err)` 호출. [근거: Rule "DESIGN-004"]

**DESIGN-005** (`sd-permission-table.ts`):
- `collapsedItems`를 `signal(new Set<string>())`로 변경 (키: `item.codeChain.join(".")`)
- `getIsPermCollapsed()`: `item.codeChain.join(".")`으로 조회
- `onPermCollapseToggle()`: 문자열 키 기반으로 add/delete, 자식도 codeChain 키 사용
[근거: Rule "DESIGN-005"]

### 대안 검토

**LOGIC-005 대안 — 문서화만:** 코드 변경 없이 주석으로 stale value 가능성을 문서화. D3에서 재계산 방식을 선택했으므로 기각.

**CONSIST-002 유틸 배치 위치 대안:**
- `core/`에 배치: ORM 에러 메시지 변환이라는 도메인 로직이 core에 부적합. 기각.
- `data-detail/` 또는 `data-sheet/` 중 하나에 배치: 한쪽이 다른 쪽에 의존. 기각.
- `data/getOrmDataEditToastErrorMessage.ts`에 배치: 두 소비자가 모두 `data/` 하위이므로 적합. 채택.

**DESIGN-003/004 대안 — `SdGlobalErrorHandlerPlugin` 의존:** 현재도 unhandled rejection을 글로벌 핸들러가 잡지만, 명시적 에러 처리가 디버깅과 에러 추적에 유리. 명시적 .catch()/try-catch 채택.
