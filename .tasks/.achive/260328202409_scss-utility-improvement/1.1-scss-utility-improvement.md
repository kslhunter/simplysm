# Feature 1.1 SCSS 유틸리티 클래스 개선

## 참조 자료

### 대상 파일
- `packages/angular/scss/commons/_styles.scss` — 유틸리티 클래스 정의 (메인 대상)
- `packages/angular/scss/commons/_mixins.scss` — 공유 mixin
- `packages/angular/scss/commons/_variables.scss` — CSS 변수 정의
- `packages/angular/scss/controls/_flex.scss` — flex 유틸리티
- `packages/angular/scss/controls/_form-box.scss` — form-box 유틸리티
- `packages/angular/scss/controls/_card.scss` — card 유틸리티

### 현재 구조
- `@layer base, theme-variant, utilities` 이미 구현됨 (`_theme-variables.scss:5`)
- 모든 유틸리티 클래스에 `!important` 사용 — 이번 범위에서 변경하지 않음
- `ViewEncapsulation.None` + `data-sd-*` 속성 기반 컴포넌트 스타일링

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | `tx-` 접두사 분리 | 현상 유지 | 사용자가 모호하지 않다고 판단 |
| D2 | `.bd-trans` 모호성 | `.bd-transparent`로 변경 | `.bd-trans-{level}`(투명도 레벨)과 구분 |
| D3 | 위치 클래스(`.t-sm` 등) 네이밍 | 현상 유지 | 짧고 간결한 현재 형태 유지 |
| D4 | gap 토큰 다용도 사용 | 현상 유지 | Tailwind과 동일 관행, spacing scale 공유 |
| D5 | `!important` 제거 | 범위 제외 | 유틸리티/컴포넌트 모두 유지 |

## 구현계획

### 배경

`_styles.scss`는 `@layer utilities` 내에 유틸리티 클래스를 SCSS `@each` 루프로 자동 생성한다. 현재 동일한 `gap` 맵을 4개의 별도 루프에서 순회하고, border 방향별 생성이 반복적이다. `_mixins.scss`에 mixin 패턴이 이미 존재하므로 동일 방식으로 반복 코드를 추출한다.

### 목표

- `.bd-trans` → `.bd-transparent` 네이밍 변경 (D2)
- padding/margin/size/position 생성 루프 통합
- border 방향별 생성 로직 mixin 추출
- border-radius 방향별 생성 정리
- 리팩토링 전후 CSS 출력 동일성 보장 (네이밍 변경 제외)

### 비목표

- `!important` 제거 (D5)
- 클래스명 변경 (`.bd-transparent` 제외)
- 새로운 유틸리티 클래스 추가
- `_flex.scss`, `_form-box.scss`, `_card.scss` 변경

### 설계

#### `.bd-trans` → `.bd-transparent` 변경 범위

| 현재 | 변경 후 | 위치 |
|---|---|---|
| `.bd-trans` | `.bd-transparent` | `_styles.scss:209` |
| `.bdt-trans` | `.bdt-transparent` | `_styles.scss:243` (루프 내) |
| `.bdr-trans` | `.bdr-transparent` | 동일 루프 |
| `.bdb-trans` | `.bdb-transparent` | 동일 루프 |
| `.bdl-trans` | `.bdl-transparent` | 동일 루프 |

#### padding/margin 루프 통합

현재 4개 루프 → 2개로 통합:
- 루프 1: `@each $key in gap` → `.p-*`, `.m-*`, `.pv-*`, `.ph-*`, `.mv-*`, `.mh-*`, `.sw-*`, `.sh-*`, `.gap-*` + 방향별 `.p{d}-*`, `.m{d}-*`, `.{d}-*`
- 루프 2: `@each $key1, $key2 in gap × gap` → `.p-{k1}-{k2}`, `.m-{k1}-{k2}` (2차원 조합, 별도 유지)

#### border 방향별 mixin

`_mixins.scss`에 추가:

```scss
@mixin border-direction-variants($dir, $d) {
  .bd#{$d} {
    border-#{$dir}: 1px solid !important;
  }
  @each $key, $val in map.get(variables.$vars, theme) {
    @each $key1, $val1 in $val {
      .bd#{$d}-theme-#{$key}-#{$key1} {
        border-#{$dir}-color: var(--theme-#{$key}-#{$key1}) !important;
      }
    }
  }
  @each $key, $val in map.get(variables.$vars, trans) {
    .bd#{$d}-trans-#{$key} {
      border-#{$dir}-color: var(--trans-#{$key}) !important;
    }
  }
  @each $key, $val in map.get(variables.$vars, border-color) {
    .bd#{$d}-color-#{$key} {
      border-#{$dir}-color: var(--border-color-#{$key}) !important;
    }
  }
  .bd#{$d}-none {
    border-#{$dir}: none !important;
  }
  .bd#{$d}-transparent {
    border-#{$dir}-color: transparent !important;
  }
}
```

`_styles.scss`에서 호출:

```scss
@each $dir in (top, right, bottom, left) {
  $d: string.slice($dir, 1, 1);
  @include mixins.border-direction-variants($dir, $d);
  // border-width도 이 루프 내에서 처리
}
```

#### border-radius 방향별 정리

방향 → 코너 매핑을 map으로 정의하여 루프화:

```scss
$radius-dirs: (
  t: (top-right, top-left),
  b: (bottom-right, bottom-left),
  l: (top-left, bottom-left),
  r: (top-right, bottom-right),
);
```

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| mixin으로 border 방향 코드 추출 | 채택 | 기존 `_mixins.scss` 패턴과 일관 |
| `@function`으로 클래스명 생성 | 미채택 | SCSS function은 값 반환 전용, 선택자 생성에 부적합 |
| padding/margin 완전 통합 (1루프) | 미채택 | 2차원 조합(`.p-sm-lg`)은 별도 루프가 가독성에 유리 |
