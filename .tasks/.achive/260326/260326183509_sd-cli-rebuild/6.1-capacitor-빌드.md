## 구현계획

### 배경

v14 sd-cli에 Capacitor 타입 정의(`SdCapacitorConfig` 등)만 존재하고 구현이 없다. v14 _back에 완전한 Capacitor 클래스(946줄)와 테스트(icon, build, run 3파일)가 있으며, 이를 v14에 포팅하고 workspace:* 플러그인 해석 문제를 해결한다.

### 목표

- v14 _back Capacitor 클래스를 v14에 포팅
- workspace:* 플러그인을 .capacitor/ 프로젝트에서 symlink로 해석
- 테스트 커버리지 확보

### 비목표

- `run()` (runOnDevice) 테스트 — Feature 6.3
- Orchestrator/명령어 통합 — Feature 6.3
- Electron — Feature 6.2
- iOS 지원

### 설계

#### 파일 구조

```
packages/sd-cli/src/capacitor/
  capacitor.ts          ← v14 _back에서 포팅
tests/capacitor/
  capacitor-icon.spec.ts
  capacitor-build.spec.ts
```

Capacitor 클래스는 BuildEngine이 아닌 독립 유틸리티. Feature 6.3에서 Orchestrator가 호출.

#### workspace:* 플러그인 해석 (symlink 방식)

`_initCap()` 내부에서 처리:

1. `_setupNpmConf()`: 플러그인 버전이 `workspace:`로 시작하면 `.capacitor/package.json`에 추가하지 않고 `workspacePlugins` 목록에 보관
2. `npm install`: core Capacitor deps만 설치
3. `_linkWorkspacePlugins(workspacePlugins)`: 각 workspace 플러그인에 대해
   - `createRequire(this._pkgPath)`로 플러그인의 실제 경로 resolve
   - `.capacitor/node_modules/<plugin>` → 실제 패키지 경로로 symlink 생성
   - scoped 패키지는 scope 디렉토리(`@simplysm/`) 먼저 생성

근거: cap sync는 `package.json`의 `capacitor.android.src` 필드로 native code 경로만 참조. JS 의존성은 Vite 클라이언트 빌드가 별도 처리.

#### CLAUDE.md 규칙 적용

v14 _back 코드의 `Buffer` 사용을 `Uint8Array`로 변환:
- `Buffer[]` → `Uint8Array[]`
- `Buffer.concat()` → `BytesUtils.concat()` (`@simplysm/core-common`)

### 대안 검토

| 접근 방식 | 선택 | 이유 |
|-----------|------|------|
| symlink 직접 생성 | 채택 | cap sync는 native code만 필요, 가장 단순 |
| file: protocol | 미채택 | transitive workspace:* deps resolve 시도 → npm install 실패 |
| pnpm pack → tarball | 미채택 | 사전 빌드 필수, 미게시 transitive deps 해결 불가 |
| 전체 의존성 재귀 resolve | 미채택 | 복잡도 높음, cap sync에 불필요 |
