      Then Angular @Component의 인라인 스타일에 vendor prefix가 추가된다

## 구현계획

### 배경

Client 빌드는 Vite 기반으로 Feature 3.1~3.4에서 구현되었다. 설정 흐름은 `SdClientPackageConfig` → `ViteEngine` → `client.worker` → `createClientViteConfig()` → Vite 설정이며, Angular AOT 컴파일은 `sdAngularPlugin` → `AngularFacade` → `ComponentStylesheetBundler`로 처리된다.

현재 `esbuild.target`은 `"es2022"`로 하드코딩되어 있고, PostCSS/polyfills/splitting 옵션이 없다.

### 목표

- `sd.config.ts`의 `browserSupport` 설정으로 browserslist, PostCSS, polyfills, splitting을 제어한다
- 설정이 JS 번들링(esbuild target), CSS 처리(Vite PostCSS + Angular ComponentStylesheetBundler), Angular 컴파일 전 과정에 일관되게 적용된다

### 비목표

- PWA 지원 (Feature 5.2)
- Library 빌드에 browserslist 적용 (Client 전용)
- Server 빌드에 대한 영향

### 설계

#### Config 타입

```typescript
// sd-config.types.ts
export interface SdBrowserSupportConfig {
  /** browserslist 쿼리 (예: "last 2 Chrome versions" 또는 ["ie 11", "last 2 versions"]) */
  browserslist?: string | string[];
  /** PostCSS 플러그인 설정 */
  postCss?: { plugins: unknown[] };
  /** 코드 분할 여부 (기본: true) */
  splitting?: boolean;
}

export interface SdClientPackageConfig {
  // ... 기존 필드
  /** 브라우저 호환성 설정 */
  browserSupport?: SdBrowserSupportConfig;
}
```

polyfills는 config에 포함하지 않는다 (D1: `src/polyfills.ts` 파일 컨벤션 자동 감지).

#### Config 전달 경로

```
sd.config.ts (SdClientPackageConfig.browserSupport)
  → ViteEngine.run/startWatch (pkg.config.browserSupport → ClientBuildInfo)
    → client.worker (browserSupport + polyfills 자동 감지)
      → createClientViteConfig (browserslist, postCssPlugins, polyfills, splitting)
        ├→ esbuild.target (browserslist-to-esbuild 변환)
        ├→ css.postcss (postCssPlugins)
        ├→ sdAngularPlugin (postCssPlugins, browserslist → AngularFacade)
        │   └→ ComponentStylesheetBundler (target, postcssConfiguration)
        ├→ sdPostCssInlinePlugin (postCssPlugins → library JS inline CSS)
        ├→ sd-polyfills plugin (transformIndexHtml → <script> 주입)
        └→ rollupOptions.output.inlineDynamicImports (splitting=false 시)
```

#### PostCSS 3계층 적용

| 계층 | 대상 | 처리 위치 |
|------|------|---------|
| Angular 컴파일 | `@Component` 인라인 스타일 + `styleUrls` | `ComponentStylesheetBundler` (postcssConfiguration) |
| Vite CSS | 독립 `.css`/`.scss` 파일 | Vite `css.postcss` 설정 |
| Library inline | Angular 라이브러리 번들 JS 내 `@Component` styles | `sdPostCssInlinePlugin` (TypeScript AST 파싱) |

#### 신규 의존성

- `browserslist-to-esbuild`: browserslist 쿼리 → esbuild target 배열 변환
- `postcss`: sdPostCssInlinePlugin에서 직접 사용

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| polyfills를 config 배열로 지정 | 미채택 | D1: 파일 컨벤션이 Angular 관행과 일치, 설정 불필요 |
| @vitejs/plugin-legacy로 폴리필/변환 | 미채택 | esbuild target + 별도 polyfills.ts가 더 직접적이고 제어 가능 |
| PostCSS를 Vite css.postcss로만 처리 | 미채택 | Angular 인라인 스타일과 library JS inline CSS에 적용 불가 |
