# Feature 1.2 패키지별 tsconfig.json 도입

## 참조 자료

- [wbs.md](wbs.md)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | neutral 이중 typecheck 전략 | 패키지별 tsconfig로 자연 해소 (단일 typecheck) | 코드 분석 결과 neutral 5개 패키지 모두 DOM API(document, window) 미사용. web-standard API만 사용하며, 패키지별 lib/types 명시 선언으로 이중 검증 불필요 |
| D2 | sd-claude(scripts) 포함 여부 | 제외 | target: "scripts"로 typecheck/build 대상 아님 |

### neutral 패키지 실제 API 사용 현황

| 패키지 | web-standard API | DOM API | Node API |
|--------|-----------------|---------|----------|
| core-common | `crypto.getRandomValues`, `Blob`, `TextEncoder`/`TextDecoder` | 없음 | `process.env` (typeof guard + 로컬 declare) |
| excel | `Blob`, `TextEncoder`/`TextDecoder` | 없음 | 없음 |
| orm-common | 없음 | 없음 | 없음 |
| service-client | `Worker`, `URL`, `fetch`, `FormData`, `Blob` | 없음 | `@types/ws` devDep |
| service-common | `TextEncoder`/`TextDecoder` | 없음 | 없음 |

### 제거 대상 함수/타입

| 대상 | 파일 | 이유 |
|------|------|------|
| `getCompilerOptionsForPackage()` | `utils/tsconfig.ts` | 패키지 tsconfig 파싱으로 대체 |
| `TypecheckEnv` 타입 | `utils/tsconfig.ts` | 환경 추측 불필요 |
| `getTypecheckEnvFromTarget()` | `utils/esbuild-config.ts` | 환경 추측 불필요 |
| `toTypecheckEnvs()` | `commands/typecheck.ts` | 패키지당 단일 typecheck |
| `DOM_LIB_PATTERNS` | `utils/tsconfig.ts` | lib 조작 불필요 |
| `getTypesFromPackageJson()` | `utils/tsconfig.ts` | types를 tsconfig.json에 명시 |

## 구현계획

### 배경

현재 sd-cli는 루트 `tsconfig.json`만 사용하고, `getCompilerOptionsForPackage()`로 패키지 환경(node/browser)을 런타임에 추측하여 `lib`/`types`/`typeRoots`를 동적 조작한다. 이 패턴은 `tsconfig.ts`, `typecheck.ts`, `esbuild-config.ts`, 3개 worker(dts/library/server), `BuildOrchestrator`, `DtsBuilder`에 걸쳐 `TypecheckEnv` 타입으로 연결되어 있다.

### 목표

- 각 패키지가 자체 `tsconfig.json`으로 환경을 명시적 선언
- sd-cli가 패키지 tsconfig를 그대로 읽고 빌드 모드별 옵션만 오버라이드
- `TypecheckEnv` 기반 환경 추측 로직 완전 제거
- neutral 패키지 이중 typecheck 해소 (단일 typecheck)

### 비목표

- BuildEngine 인터페이스 구현 (Feature 1.3)
- 새 명령어 구조 (Feature 1.6)
- 루트 `tsconfig.json`의 IDE 용도 변경

### 설계

#### 파일 구조 변경

```
simplysm/
├── tsconfig.json          (기존 유지 — IDE root용)
├── tsconfig.base.json     (NEW — 공통 옵션만, lib/types/paths 제외)
├── packages/
│   ├── sd-cli/tsconfig.json         (NEW — node)
│   ├── core-node/tsconfig.json      (NEW — node)
│   ├── core-common/tsconfig.json    (NEW — neutral)
│   ├── angular/tsconfig.json        (NEW — browser)
│   ├── ... (17개 총)
│   └── sd-claude/                   (tsconfig 없음)
```

#### tsconfig.base.json 설계

루트 `tsconfig.json`에서 **공통 컴파일러 옵션만** 추출. `lib`, `types`, `baseUrl`, `paths`는 **제외** (패키지별로 설정).

```json
{
  "compilerOptions": {
    "target": "ESNext",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true,
    "noImplicitOverride": true,
    "noImplicitReturns": true,
    "noImplicitAny": true,
    "noFallthroughCasesInSwitch": true,
    "useUnknownInCatchVariables": true,
    "noPropertyAccessFromIndexSignature": true,
    "forceConsistentCasingInFileNames": true,
    "useDefineForClassFields": true,
    "esModuleInterop": true,
    "verbatimModuleSyntax": true,
    "declaration": true,
    "declarationMap": true,
    "sourceMap": true,
    "inlineSourceMap": false,
    "skipLibCheck": true,
    "importHelpers": true
  }
}
```

#### 패키지 tsconfig.json 템플릿

공통 구조:

```json
{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": {
    "lib": [...],
    "types": [...],
    "typeRoots": ["./node_modules/@types", "../../node_modules/@types"],
    "baseUrl": ".",
    "paths": { "@simplysm/*": ["../*/src/index.ts"] }
  },
  "include": ["src/**/*.ts", "tests/**/*.ts"]
}
```

환경별 `lib`/`types` 매핑:

| 환경 | lib | types 기본 | 패키지별 추가 types |
|------|-----|-----------|-------------------|
| node | `["ESNext"]` | `["node"]` | sd-cli: +semver,ssh2,yargs / orm-node: +pg,pg-copy-streams / service-server: +nodemailer,semver,ws / storage: +ssh2-sftp-client |
| browser | `["ESNext","DOM","DOM.Iterable"]` | `[]` | angular: +qrcode,semver / capacitor-plugin-auto-update: +semver |
| neutral | `["ESNext","WebWorker"]` | `[]` | service-client: +ws |

#### sd-cli 코드 변경

`parseRootTsconfig()`를 범용 `parseTsconfig(dir)`로 일반화하고, 패키지/루트 모두 지원:

```typescript
export function parseTsconfig(dir: string): ts.ParsedCommandLine {
  const tsconfigPath = path.join(dir, "tsconfig.json");
  const configFile = ts.readConfigFile(tsconfigPath, ts.sys.readFile);
  if (configFile.error) { throw ... }
  const parsed = ts.parseJsonConfigFileContent(configFile.config, ts.sys, dir);
  if (parsed.errors.length > 0) { throw ... }
  return parsed;
}
```

Worker 전환 패턴 (before → after):

```typescript
// Before (모든 worker 공통):
const parsedConfig = parseRootTsconfig(info.cwd);
const env = getTypecheckEnvFromTarget(info.config.target); // or "node" / info.env
const compilerOptions = await getCompilerOptionsForPackage(parsedConfig.options, env, info.pkgDir);

// After:
const parsedConfig = parseTsconfig(info.pkgDir);
const compilerOptions = parsedConfig.options;
```

typecheck 명령 변경:

```typescript
// Before:
envs: toTypecheckEnvs(config.packages[pkgName]?.target) // neutral → ["node", "browser"]
// → 2개 task 생성

// After:
// envs 제거, 패키지당 1개 task
```

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| `tsconfig.base.json` 분리 | 채택 | root tsconfig의 `lib`에 DOM 포함 → 패키지가 extends 시 DOM 상속됨. base에서 lib 제외 필요 |
| root tsconfig에서 lib 제거 | 미채택 | 루트 수준 .ts 파일의 IDE 경험 저하 |
| TypeScript project references | 미채택 | 빌드가 esbuild 기반이라 TS project references 빌드 기능 불필요, 복잡성만 증가 |
| `parseTsconfig(dir)` 일반화 | 채택 | `parseRootTsconfig()`와 동일 로직이므로 하나로 통합 |
