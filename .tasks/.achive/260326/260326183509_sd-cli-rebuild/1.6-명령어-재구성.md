## 구현계획

### 배경

Feature 1.3/1.4/1.5에서 BuildEngine 추상화(EsbuildEngine, ServerEsbuildEngine)와 library-build.worker, server-build.worker가 완성됐다. 현재 CLI는 8개 명령어(lint, typecheck, check, watch, dev, build, publish, replace-deps)에 3개 Orchestrator(Build, Watch, Dev)가 분리되어 있다. typecheck 명령어는 dts.worker를 사용하며 이는 Feature 1.4 D4에서 임시 유지된 상태다. BuildOrchestrator는 모든 빌드 태스크를 동시에 실행하여 Worker 스레드가 폭증하는 문제(PERF-001)가 있다.

### 목표

- typecheck/lint 독립 명령어 제거, check --type으로 통합
- check --type typecheck이 BuildEngine.run({js:false, dts:false})를 사용
- dts.worker 삭제
- DevOrchestrator + WatchOrchestrator → 단일 DevWatchOrchestrator로 통합
- watch가 전체 패키지(Library + Server + Scripts) 대상
- dev가 Server + client-ready 대상
- BuildOrchestrator Worker 동시 생성 수 제한

### 비목표

- Client BuildEngine(ViteEngine) 구현 (Feature 3.x)
- Angular 관련 빌드 (Feature 2.x)
- build/publish/replace-deps 명령어 로직 변경 (concurrency 제한 외)
- watch/dev startup concurrency 제한 (long-lived workers, 영향 미미)

### 설계

#### Concurrency utility (utils/concurrency.ts)

```typescript
/**
 * Run task functions with limited concurrency.
 * Uses a shared index pattern (same as typecheck.ts pool).
 */
async function runWithConcurrency<T>(
  tasks: Array<() => Promise<T>>,
  concurrency: number,
): Promise<PromiseSettledResult<T>[]> {
  const results: PromiseSettledResult<T>[] = new Array(tasks.length);
  let index = 0;

  async function worker(): Promise<void> {
    while (index < tasks.length) {
      const currentIndex = index++;
      try {
        results[currentIndex] = { status: "fulfilled", value: await tasks[currentIndex]() };
      } catch (reason) {
        results[currentIndex] = { status: "rejected", reason };
      }
    }
  }

  const workerCount = Math.min(concurrency, tasks.length);
  await Promise.all(Array.from({ length: workerCount }, () => worker()));
  return results;
}

function getMaxConcurrency(): number {
  return Math.max(Math.floor((os.cpus().length * 7) / 8), 1);
}
```

#### BuildOrchestrator concurrency 적용

현재 `start()` (line 330):
```typescript
await Promise.allSettled([lintTask(), ...buildTasks.map((task) => task())]);
```

변경:
```typescript
const buildPromise = runWithConcurrency(buildTasks, getMaxConcurrency());
await Promise.allSettled([lintTask(), buildPromise]);
```

lint는 concurrency pool 밖에서 독립 실행. buildTasks는 side effect로 results 배열에 수집하므로 반환값은 사용하지 않는다.

#### executeTypecheck() 리팩토링 (commands/typecheck.ts)

dts.worker pool → BuildEngine.run({js:false,dts:false}) + runWithConcurrency로 전환.

```
1. loadSdConfig()
2. classifyPackages() → buildPackages + serverPackages
3. targets 필터링: path에서 package name 추출하여 패키지 목록 필터
4. 각 패키지 → createBuildEngine → engine.run({js:false,dts:false}) → engine.stop()
5. runWithConcurrency(tasks, getMaxConcurrency())
6. non-package 판별: targets가 비어있거나 packages/ 외 경로 포함 시
7. typecheckNonPackageFiles() 호출
8. 결과 aggregation (diagnostics 통합, 중복 제거)
```

`runTypecheck()` 함수는 삭제(CLI command handler 역할 제거). `executeTypecheck()`만 export하여 check.ts에서 사용.

target filtering helper:
```typescript
function filterPackagesByCheckTargets<T extends { name: string }>(
  packages: T[],
  targets: string[],
): T[] {
  if (targets.length === 0) return packages;
  const names = new Set(
    targets.map((t) => t.match(/^packages\/([^/]+)/)?.[1]).filter(Boolean),
  );
  return packages.filter((p) => names.has(p.name));
}
```
