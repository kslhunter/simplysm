## 구현계획

### 배경

`@simplysm/excel` 패키지는 ZIP 기반 OOXML 구조의 Excel 파일을 읽고 쓰는 라이브러리다. 내부적으로 `ZipCache`가 XML 파일을 lazy-load하여 `ExcelXml` 구현 객체로 캐싱하고, `ExcelWorksheet`/`ExcelCell` 등이 이 캐시를 통해 셀 데이터를 조작한다. 코드 리뷰(LOGIC-001, CONSIST-001, PERF-001, DESIGN-001)에서 4건의 이슈가 발견되었다.

### 목표

- 빈 SharedString 텍스트가 `""` (빈 문자열)을 반환하도록 수정
- Relationship ID 파싱을 `num.parseInt` 직접 호출로 통일
- `setDataMatrix`/`setRecords`에서 XML 리소스를 한 번 pre-load 후 동기 루프로 전환
- 동일 (r, c) 좌표에 대해 단일 `ExcelCell` 인스턴스를 반환하도록 통합

### 비목표

- `ExcelWrapper.write`의 스타일 적용 루프 최적화 (별도 Feature로 분리)
- `ExcelCell.setValue`의 개별 호출 최적화 (기존 async 인터페이스 유지)

### 설계

#### LOGIC-001: `_getStringFromTTag` 수정

`excel-xml-shared-string.ts:75`에서 `firstItem._ ?? " "` → `firstItem._ ?? ""` 변경.

#### CONSIST-001: `_getRelId` 통일

`excel-xml-relationship.ts:82-88`에서 regex `/[0-9]+$/` 제거. `num.parseInt(rel.$.Id)` 직접 호출. `undefined` 시 기존과 동일하게 에러 throw.

#### DESIGN-001: 셀 인스턴스 통합

`ExcelWorksheet`에 `_cellMap: Map<string, ExcelCell>`을 추가하고 `_getOrCreateCell(r, c)` 메서드를 제공. `ExcelRow`/`ExcelCol` 생성자에 cell factory 콜백(`(c: number) => ExcelCell` / `(r: number) => ExcelCell`)을 추가하여, `cell()` 호출 시 worksheet의 통합 맵을 사용. `ExcelRow._cellMap`과 `ExcelCol._cellMap`은 제거.

#### PERF-001: 배치 셀 쓰기

`ExcelWorksheet`에 private 리소스 로딩 메서드 추가:
- `_getOrCreateSsData()`: SharedStrings XML을 로드/생성 (Content_Types, workbook rels 등록 포함)
- `_getOrCreateStyleData()`: Styles XML을 로드/생성

`setDataMatrix`/`setRecords`를 다음 패턴으로 재작성:
1. `wsData`, `ssData`, `styleData`를 한 번 await로 pre-load
2. 동기 루프에서 `wsData.setCellType/Val/StyleId`, `ssData.getIdByString/add`, `styleData.add` 등을 직접 호출

셀 값 설정의 동기 로직(`setValue`에서 async 제거한 핵심 로직)을 `ExcelWorksheet`의 private 메서드 `_setCellValueSync(wsData, ssData, styleData, addr, val)`로 추출하여 `setDataMatrix`/`setRecords` 양쪽에서 재사용.

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| PERF: ExcelCell.setValue를 refactor하여 sync helper를 공유 | 미채택 | ExcelCell의 public API 변경 불필요, worksheet 내부에 배치 로직 격리가 더 단순 |
| DESIGN: ExcelCell에 ExcelWorksheet 역참조 추가 | 미채택 | 순환 의존 발생, cell factory 콜백이 더 느슨한 결합 |
| PERF: Promise.all로 병렬 처리 | 미채택 | 공유 가변 상태(XML 데이터)에 대한 동시 접근 문제 |
