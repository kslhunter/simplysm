# Feature 1.1 Server/Electron env 주입 방식을 define에서 banner로 전환

## 참조 자료

### 문제

- esbuild `define`은 컴파일 타임 텍스트 치환이다. `define["process.env.KEY"]`는 코드에서 `process.env.KEY`를 리터럴로 치환한다
- `core-common/src/env.ts`는 `{ ...process.env }`로 spread 접근하는데, esbuild define은 `process.env` 전체가 아닌 개별 키만 치환하므로 spread에 잡히지 않는다
- Client(Vite)는 `define["import.meta.env.KEY"]`를 사용하며, Vite 내부에서 bare `import.meta.env` 객체를 자동 구성하므로 spread가 정상 동작한다 (변경 불필요)

### 현재 코드 위치

- env 정의: `packages/sd-cli/src/utils/esbuild-config.ts` (Server esbuild define)
- env 정의: `packages/sd-cli/src/electron/electron.ts` (Electron esbuild define)
- env 정의: `packages/sd-cli/src/utils/vite-config.ts` (Client Vite define — 변경 불필요)
- env 소비: `packages/core-common/src/env.ts` (변경 불필요)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | Client(Vite) env 주입 방식 | 현행 define 유지 | Vite가 내부적으로 bare `import.meta.env` 객체를 자동 구성하여 spread 정상 동작 |
| D2 | Server/Electron env 주입 방식 | define → banner 전환 | esbuild define은 개별 키만 치환하므로 spread에 잡히지 않음. banner로 실제 `process.env`에 병합하면 spread 동작 |
| D3 | 런타임 ENV 우선순위 | 런타임 > 빌드 시점 | `??=` 연산자로 빌드 시점 값은 기본값, 런타임 ENV가 이미 있으면 유지 |
| D4 | Vite config의 `define["process.env"]` | 제거 | 브라우저에 `process`가 없어 `typeof process !== "undefined"` 체크에서 걸려 무의미한 코드 |

## 구현계획

### 배경

sd-cli는 환경변수(VER, DEV, 사용자 정의)를 빌드 번들에 주입한다. 현재 Server/Electron은 esbuild `define`으로 `process.env.KEY`를 리터럴로 텍스트 치환하지만, `core-common/src/env.ts`가 `{ ...process.env }` spread로 읽기 때문에 치환된 값이 반영되지 않는다. Client(Vite)는 Vite 내부에서 bare `import.meta.env` 객체를 자동 구성하므로 문제 없다.

### 목표

- Server/Electron esbuild: `define` → `banner`로 전환하여 process.env에 실제 값 주입
- Vite: 불필요한 `define["process.env"]` 제거
- 런타임 ENV 오버라이드 지원 (`??=` 연산자)

### 비목표

- env.ts 변경
- Client Vite의 import.meta.env define 방식 변경
- 라이브러리 빌드 변경

### 설계

#### env banner 생성 유틸리티

`esbuild-config.ts`에 `createEnvBanner()` 함수 추가. 3곳(server esbuild, electron run, electron build)에서 공유.

```typescript
export function createEnvBanner(env?: Record<string, string>): string {
  if (env == null || Object.keys(env).length === 0) return "";
  return `for(const[__k,__v]of Object.entries(${JSON.stringify(env)})){process.env[__k]??=__v;}`;
}
```

- `??=`: 빌드 시점 값은 기본값, 런타임 ENV가 이미 있으면 유지
- 변수명 `__k`, `__v`: 번들 코드와의 충돌 방지

#### Server esbuild 변경 (`esbuild-config.ts`)

- `define` 블록 제거
- `banner.js`에 `createEnvBanner()` 결과를 기존 createRequire shim 뒤에 연결
- `createServerEsbuildOptions` 반환값에서 `define` 프로퍼티 제거

#### Electron 변경 (`electron.ts`)

- `run()`: define 블록 → `banner: { js: createEnvBanner({ELECTRON_DEV_URL: url, ...config.env}) }`
- `build()`: define 블록 → `banner: { js: createEnvBanner(config.env) }`
- `createEnvBanner`를 `esbuild-config.ts`에서 import

#### Client Vite 변경 (`vite-config.ts`)

- `define["process.env"] = JSON.stringify(options.env)` (line 88) 제거
- `define["import.meta.env.KEY"]` (line 89-91) 유지

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |

| banner로 process.env 병합 | 채택 | 실제 process.env에 값 주입, 런타임 오버라이드 자연 지원 |
| define 전체 객체 치환 | 미채택 | Server에서 런타임 process.env 손실 |
