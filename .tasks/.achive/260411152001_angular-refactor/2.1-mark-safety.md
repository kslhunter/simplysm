## 구현계획

### 배경

`mark()` 함수(`packages/angular/src/core/utils/mark.ts`)는 WritableSignal의 값이 in-place mutation된 후 소비자에게 변경을 알리는 유틸리티이다. 현재 `clone` 파라미터에 따라 두 경로로 분기한다:
- `clone=true`: `sig.update(v => Array.isArray(v) ? [...v] : {...v})` — 공식 API만 사용
- `clone=false`(기본값): `@angular/core/primitives/signals`의 비공개 API 5개를 직접 호출

내부 사용처 2곳 모두 `clone=false`로 호출하지만, `clone=true`로 대체 가능하다.

### 목표

- Angular 비공개 API 의존을 완전히 제거한다 [근거: DESIGN-001]
- mark() 함수를 단순화하여 유지보수성을 높인다 [근거: D1]
- 기존 테스트와 동작을 유지한다 [근거: wbs 경계]

### 비목표

- mark() export 제거 [근거: wbs 경계 "공개 API 유지"]
- 호출부의 로직 변경 [근거: wbs 경계 "내부 구조만 변경"]

### 설계

**mark.ts 변경:**
- `@angular/core/primitives/signals` import 전체 제거
- `clone` 파라미터 제거, 항상 shallow copy 방식으로 동작
- 시그니처: `mark(sig: WritableSignal<any>): void`
- 구현: `sig.update(v => Array.isArray(v) ? [...v] : {...v})`
- JSDoc으로 용도와 변경 이력 문서화

**호출부 변경:**
- `injectDataSheetInlineEditManager.ts:85` — `mark(options.items)` → 변경 불필요 (clone 파라미터 없이 호출 중)
- `sd-data-sheet.base.ts:244` — `mark(this.lastFilter)` → 변경 불필요

**테스트 변경 (mark.spec.ts):**
- clone 파라미터 관련 테스트에서 `mark(sig, true)` → `mark(sig)`로 변경
- "clone 옵션 사용 시" Rule 제목을 "mark 호출 시 새 참조를 생성한다"로 변경
- 비공개 API 경로 테스트는 기존 "mark 호출 시 signal consumer에게 변경 알림" Rule의 테스트와 통합
- computed 내부 에러 테스트 유지 (sig.update() 내부적으로 동일하게 에러 발생)

### 대안 검토

**mark() 함수 자체 제거 + 호출부에서 직접 sig.update() 사용:**
선택하지 않음 — mark()는 공개 API이며, "in-place mutation 후 알림"이라는 의도를 명확히 표현하는 유틸리티로 가치가 있다. `sig.update(v => [...v])`보다 `mark(sig)`가 의도를 더 잘 전달한다.
