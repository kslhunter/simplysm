## 구현계획

### 배경

sd-modal.ts(617줄)과 sd-tiptap-editor.ts(513줄)이 500줄을 초과하며, 독립적으로 추출 가능한 로직 블록이 식별됨. sd-sheet.ts(585줄)는 이미 10개 composable로 분해되어 범위에서 제외(D1). [근거: STRUCT-001]

기존 코드베이스의 composable 패턴:
- `inject*`: inject() 사용, 상태/핸들러 반환 (예: `injectSheetColumnResizing`)
- `setup*`: inject() 사용, void 반환, 부수효과 전용 (예: `setupRipple`)
- `use*`: inject() 미사용, Signal 입력 → 상태/메서드 반환 (예: `useSheetColumnFixing`)

### 목표

- sd-modal.ts에서 포커스 트랩, 드래그/리사이즈 로직을 inject* composable로 추출 [근거: WBS 범위 + D3]
- sd-tiptap-editor.ts에서 툴바 커맨드/상태 로직을 use* composable로 추출 [근거: WBS 범위]
- 추출 후 sd-modal.ts ~445줄, sd-tiptap-editor.ts ~375줄으로 축소 [근거: 줄 수 분석]

### 비목표

- sd-sheet.ts 추가 분해 [근거: D1]
- 새로운 컴포넌트 생성 [근거: WBS 경계]

### 대안 검토

| 접근 | 선택 여부 | 이유 |
|---|---|---|
| setup* 네이밍 (WBS 원문) | 미선택 | 코드베이스에서 setup*은 void 반환 전용. 핸들러 반환이 필요하므로 inject* 사용 (D3) |
| setupDrag() + setupResize() 분리 | 미선택 | document 핸들러를 공유하므로 통합이 깔끔. 분리 시 핸들러 조율 로직 필요 (D2) |
| Plain utility functions (tiptap) | 미선택 | 관련 상태(signals)를 그룹화하는 use* composable이 코드베이스 패턴과 일치 |
| sd-modal config 로직도 추출 | 미선택 | _saveConfig/_restoreConfig는 ~30줄로 소규모. key/systemConfig에 의존하여 컴포넌트에 잔류가 자연스러움 |
