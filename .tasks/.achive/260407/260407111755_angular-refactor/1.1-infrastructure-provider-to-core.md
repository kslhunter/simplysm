## 구현계획

### 배경
@simplysm/angular 패키지의 3-Layer 구조(core/ → features/ → ui/)에서 SdBusyProvider, SdToastProvider, SdActivatedModalProvider 3개 provider가 ui/overlay/에 위치하여 core/ → ui/ 역방향 의존 7건을 발생시킨다. provider들은 글로벌 인프라 역할(busy count, 알림, 모달 컨텍스트)을 수행하며 UI 컴포넌트와 분리 가능하다. [근거: refactor.md ARCH-001]

### 목표
- core/ → ui/ 역방향 의존 7건 제거 [근거: Rule "SdBusyProvider/SdToastProvider/SdActivatedModalProvider는 core/에 위치해야 한다"]
- ISelectModalOutputResult type-only 역방향 의존 해소 [근거: D1]

### 비목표
- UI 컴포넌트(SdBusyContainerControl, SdToastControl 등) 이동 [근거: wbs 경계 "UI 컴포넌트는 ui/에 그대로 유지"]
- Provider 로직 변경 [근거: wbs 경계 "Provider 내부 로직 변경 없음"]
- SdModalProvider/ISdModal/ISdModalInfo/ISdModalOptions 이동 [근거: wbs 경계]

### 대안 검토

1. **Provider를 ui/에 유지하고 core/에서 index.ts 경유로 import** — 순환 의존 발생 가능, 근본 해결 아님. 기각.
2. **core/에서 사용하는 provider 인터페이스만 추출** — Provider 구현과 인터페이스를 분리하는 방식이지만 현재 구조 대비 과도한 추상화. 기각.
