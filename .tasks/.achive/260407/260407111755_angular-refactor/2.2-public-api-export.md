## 구현계획

### 배경

Feature 2.2는 public 컴포넌트가 사용하는 유틸리티 export 추가가 목표였으나, 분석 중 ISdMenu 이름 충돌(sd-app-structure.types.ts vs menu-utils.ts)과 ISdMenu.modules 죽은 프로퍼티를 발견하여 타입 재설계를 포함.

### 목표

- ISdMenu 타입 통합: modules 제거, url 추가, TModule 제네릭 제거 [근거: D1]
- TSdAppStructureLeafItem에 url 지원 추가 [근거: D1]
- 미노출 유틸리티(getMenuRouterLinkOption, getIsMenuSelected, matchesSearchText) public export [근거: STRUCT-001]

### 비목표

- ISdFlatMenu 타입 변경 [근거: wbs 경계]
- UI 컴포넌트 로직 변경 [근거: wbs 경계]

### 설계

#### ISdMenu 변경

```typescript
// Before
export interface ISdMenu<TModule = unknown> {
  title: string;
  codeChain: string[];
  icon: string | undefined;
  modules: TModule[] | undefined;
  children: ISdMenu<TModule>[] | undefined;
}

// After
export interface ISdMenu {
  title: string;
  codeChain: string[];
  url?: string;
  icon?: string;
  children?: ISdMenu[];
}
```

#### ISdAppStructureLeafItem 변경

```typescript
// url?: string 추가
export interface ISdAppStructureLeafItem<TModule> {
  // ... 기존 프로퍼티
  url?: string;  // 외부 링크 URL
}
```

#### SdAppStructureUtils.getMenus() 변경

- 반환 타입: `ISdMenu<TModule>[]` → `ISdMenu[]`
- Leaf 메뉴 생성 시 `url: item.url` 추가, `modules` 제거
- Group 메뉴 생성 시 `modules` 제거

#### menu-utils.ts 변경

- ISdMenu 인터페이스 정의 제거
- `import type { ISdMenu }` + `export type { ISdMenu }` from sd-app-structure.types
- 함수 시그니처 변경 없음 (ISdMenu에 url이 포함되므로)

#### index.ts export 추가

```typescript
export { getMenuRouterLinkOption, getIsMenuSelected } from "./ui/navigation/menu-utils";
export { matchesSearchText } from "./features/shared-data/matchesSearchText";
```

### 대안 검토

- **ISdNavigationMenu extends ISdMenu**: url을 UI 레이어에서 확장 → ISdMenu.modules가 죽은 코드인 점을 발견하여 통합이 더 적합
- **alias re-export** (`ISdMenu as ISdNavigationMenu`): ISdMenu 중복이 그대로 남아 설계 결함 미해결
