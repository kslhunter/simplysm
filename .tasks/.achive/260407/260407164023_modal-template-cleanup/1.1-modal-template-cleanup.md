# Feature 1.1 sd-prompt-modal / sd-confirm-modal 템플릿 정리

## 참조 자료

- WBS: [wbs.md](./wbs.md)
- 대상 파일: `packages/angular/src/ui/overlay/modal/sd-prompt-modal.control.ts`
- 대상 파일: `packages/angular/src/ui/overlay/modal/sd-confirm-modal.control.ts`
- 테스트: `packages/angular/tests/ui/overlay/modal/prompt-confirm-modal.spec.ts`
- 유틸리티 클래스: `packages/angular/scss/commons/_styles.scss` (`.p-default`, `.mb-default`, `.flex-row`, `.main-align-end`, `.gap-sm`)
- sd-textfield: `packages/angular/src/ui/form/input/sd-textfield.control.ts` — `value = model<T>()`, `type = input.required<K>()`

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | 호스트 display 설정 방식 | `host: { style: "display: block" }` | 유틸리티 클래스에 display: block 전용 클래스 없음, 기존 패턴과 동일 |
| D2 | sd-textfield keydown.enter | 호스트에 `(keydown.enter)` 바인딩 | keydown은 버블링 이벤트, ViewEncapsulation.None이므로 내부 input에서 호스트로 전파 |
| D3 | _inputValue 타입 변경 | `signal<string \| undefined>("")` | sd-textfield의 `model<string \| undefined>()` 호환. 초기값 `""`로 기존 동작 유지 |
| D4 | 테스트 셀렉터 업데이트 | `p` (message), `sd-textfield input` (input) | 래퍼 div/클래스 제거 후 태그 기반 셀렉터로 전환 |
| D5 | sd-textfield 값 바인딩 방식 | native `(input)` 이벤트 버블링 + `[value]` 단방향 | 동적 생성 컴포넌트(SdModalProvider.showAsync)에서 model two-way binding이 테스트 환경에서 전파 안됨. native event 방식은 동기적으로 작동 |

      When 모달이 렌더링되면
      Then actions 영역에 flex-row, main-align-end, gap-sm 클래스가 적용되어 있다

  Rule: sd-prompt-modal은 sd-textfield 사용
    # 근거: 사용자 "sd-textfield를 써야지 뭐 엄한걸 직접 스타일링 하고있냐"
    Scenario: 텍스트 입력에 sd-textfield가 사용된다

      Given sd-prompt-modal이 열려있다
      When sd-textfield에 값을 입력하고 Enter를 누르면

## 구현계획

### 배경

두 모달 컴포넌트가 불필요한 래퍼 div, 인라인 SCSS, raw input 직접 스타일링을 사용하고 있다. 프로젝트에 유틸리티 클래스(`.flex-row`, `.main-align-end`, `.gap-sm`, `.p-default`, `.mb-default`)와 sd-textfield 컴포넌트가 이미 존재한다.

### 목표

- 래퍼 div 제거하여 DOM 중첩 감소 [근거: Rule "래퍼 div 없이 호스트 직속으로"]
- 인라인 SCSS를 유틸리티 클래스로 대체 [근거: Rule "인라인 SCSS 없이 유틸리티 클래스로"]
- raw input을 sd-textfield로 교체 [근거: Rule "sd-prompt-modal은 sd-textfield 사용"]

### 비목표

- sd-sheet-config-modal 등 다른 모달 수정 [근거: WBS 제외사항]

### 설계

**호스트 설정:**
```typescript
host: {
  style: "display: block",
  class: "p-default",
}
```
[근거: 기존 `display: block; padding` 스타일 유지를 위해]

**sd-confirm-modal 템플릿:**
```html
<p class="mb-default">{{ message() }}</p>
<div class="flex-row main-align-end gap-sm">
  <sd-button [theme]="'primary'" (click)="onConfirm()">확인</sd-button>
  <sd-button (click)="onCancel()">취소</sd-button>
</div>
```

**sd-prompt-modal 템플릿:**
```html
<p class="mb-default">{{ message() }}</p>
<sd-textfield [type]="'text'" [(value)]="_inputValue" (keydown.enter)="onConfirm()" class="mb-default" />
<div class="flex-row main-align-end gap-sm">
  <sd-button [theme]="'primary'" (click)="onConfirm()">확인</sd-button>
  <sd-button (click)="onCancel()">취소</sd-button>
</div>
```
[근거: Rule "sd-textfield 사용" + D2 keydown.enter 버블링]

**sd-prompt-modal 타입 변경:**
- `_inputValue`: `signal("")` → `signal<string | undefined>("")` [근거: D3]
- `onConfirm`: `val !== ""` → `val != null && val !== ""` [근거: D3 undefined 가능성]
- `onInputChange` 메서드 제거 (sd-textfield 양방향 바인딩으로 대체)
- imports: `SdTextfieldControl` 추가

**테스트 셀렉터 업데이트:**
- `querySelector("._message")` → `querySelector("p")` [근거: D4]
- `querySelector("input._input")` → `querySelector("sd-textfield input")` [근거: D4]

### 대안 검토

| 대안 | 불채택 사유 |
|------|-----------|
| data-testid 속성 추가 | 태그 셀렉터로 충분, 불필요한 속성 추가 |
| 래퍼 div 유지 + 클래스만 교체 | 호스트가 래퍼 역할을 이미 하므로 불필요한 중첩 |
