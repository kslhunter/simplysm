## 구현계획

### 배경

`server-build.worker.ts`는 서버 패키지의 빌드(esbuild+tsc)를 담당하는 Worker Thread 모듈이다. 현재 프로덕션 배포용 파일 생성 로직(외부 모듈 수집, lockfile 파싱, 프로덕션 파일 생성) ~158줄이 Worker 내부에 위치하여 Worker의 단일 책임(빌드 실행)을 넘어선다.

### 목표

- 프로덕션 배포 관련 4개 함수를 `utils/server-production-files.ts`로 추출하여 Worker의 책임을 빌드 실행으로 한정 [근거: wbs "Worker에 프로덕션 파일 생성, YAML 파싱 등 빌드 실행과 무관한 비즈니스 로직이 ~158줄 포함"]

### 비목표

- Worker의 빌드 실행 로직(`build`, `rebuildAll`, `startWatch`, `stopWatch`, `cleanup`) 변경 [근거: wbs 경계]
- 추출된 함수의 내부 로직 변경 [근거: wbs 경계 "코드 이동만"]
- 타입 정의(`ServerBuildInfo` 등)의 위치 변경 [근거: D1]

### 설계

#### 새 모듈: `src/utils/server-production-files.ts`

**export 함수 4개:**

| 함수 | 시그니처 | 원본 위치 |
|---|---|---|
| `collectAllExternals` | `(pkgDir: string, manualExternals?: string[]) => string[]` | worker line 143 |
| `parseLockfileVersions` | `(cwd: string) => Map<string, string>` | worker line 156 |
| `resolveLockedVersions` | `(cwd: string, pkgNames: string[]) => Record<string, string>` | worker line 197 |
| `generateProductionFiles` | `(info: ServerBuildInfo, externals: string[]) => void` | worker line 216 |

**import 의존성:**

- `import type { ServerBuildInfo } from "../workers/server-build.worker"` — type-only, 런타임 순환 없음 [근거: D1]
- `import { collectAllDependencyExternals } from "./esbuild-config"` — `collectAllExternals`에서 사용
- `import { cpx } from "@simplysm/core-node"` — `generateProductionFiles`에서 `cpx.spawnSync` 사용
- `import path from "path"`, `import fs from "fs"` — 파일 I/O
- `import { consola } from "consola"` — 모듈 레벨 logger [근거: D2]

#### worker 변경: `src/workers/server-build.worker.ts`

- 4개 함수 정의 제거 (line 143~315)
- `import { collectAllExternals, generateProductionFiles } from "../utils/server-production-files"` 추가 (worker에서 실제 호출하는 함수 2개만)
- `collectAllDependencyExternals` import 제거 (새 모듈로 이동)
- `cpx` import 제거 (새 모듈로 이동, worker에서 더 이상 직접 사용 안 함)

#### 테스트 영향 분석

기존 테스트(`server-build-worker.spec.ts`, `server-build-lint.spec.ts`)는 `vi.mock()`으로 leaf 의존성을 전역 모킹한다:
- `fs` → `generateProductionFiles`의 파일 I/O에 적용
- `../../src/utils/esbuild-config` → `collectAllDependencyExternals`에 적용
- `@simplysm/core-node` → `cpx.spawnSync`에 적용
- `consola` → logger에 적용

새 모듈이 동일한 의존성을 import하므로 전역 모킹이 그대로 적용된다. 테스트 코드 변경 불필요. [근거: D3]

### 대안 검토

1. **ServerBuildInfo를 새 파일로 이동** — utils→workers type-only 의존성을 제거할 수 있으나, `ServerEsbuildEngine`의 `import type * as ServerBuildWorkerModule`에 영향을 주어 범위 초과. 기각.
2. **generateProductionFiles 매개변수를 별도 인터페이스로 추출** — 타입 의존성을 완전히 분리하나 로직 변경에 해당. wbs 경계 위반. 기각.
3. **type-only import 사용 (채택)** — `verbatimModuleSyntax` 하에서 `import type`은 컴파일 시 완전 제거. 런타임 순환 없음. 기존 패턴과 일치.
