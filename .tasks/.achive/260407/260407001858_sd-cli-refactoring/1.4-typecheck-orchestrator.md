## 구현계획

### 배경

`commands/typecheck.ts`(295줄)가 config 로드, 워크스페이스 탐색, 패키지 분류, 엔진 생성/실행, 동시성 제어, 진단 집계, 포맷 출력 등 오케스트레이션 로직을 직접 수행한다. 다른 빌드/개발 커맨드는 `orchestrators/BuildOrchestrator.ts`와 `orchestrators/DevWatchOrchestrator.ts`를 통해 동일한 패턴의 `initialize() → start() → shutdown()` 생명주기를 따른다.

### 목표
- TypecheckOrchestrator 클래스를 신설하여 타입체크 오케스트레이션 로직을 수용한다 [근거: Rule "Orchestrator 생명주기 패턴 준수"]
- commands/typecheck.ts를 commands/build.ts와 동일한 얇은 래퍼로 전환한다 [근거: Rule "레이어 역할 분리"]
- commands/check.ts가 orchestrators/ 레이어를 통해 타입체크를 호출하도록 변경한다 [근거: Rule "import 경로 정합성"]

### 비목표
- CheckOrchestrator 신설 [근거: WBS 제외사항 "P3"]
- BuildOrchestrator 수정 [근거: WBS 경계]
- 타입체크 실행 로직 자체 변경 [근거: WBS 경계]

### 설계

**TypecheckOrchestrator 클래스 구조:**

```typescript
// orchestrators/TypecheckOrchestrator.ts

export interface TypecheckOptions {
  targets: string[];
  options: string[];
  lint?: boolean;
}

export interface TypecheckResult {
  success: boolean;
  errorCount: number;
  warningCount: number;
  formattedOutput: string;
  lint?: { success: boolean; errorCount: number; warningCount: number; formattedOutput: string };
  scriptsPackagePaths?: string[];
}

export class TypecheckOrchestrator {
  private readonly _options: TypecheckOptions;
  private readonly _cwd: string;
  private readonly _logger;
  // initialize()에서 설정되는 내부 상태
  private _typecheckTasks: Array<{name, dir, config, env}>;
  private _scriptsPackagePaths: string[];
  private _includeNonPackage: boolean;

  constructor(options: TypecheckOptions);
  async initialize(): Promise<void>;     // config 로드, 패키지 분류
  async start(): Promise<TypecheckResult>;  // 엔진 실행, 결과 집계
  async shutdown(): Promise<void>;       // no-op (BuildOrchestrator 패턴)
}

// 편의 함수
export async function executeTypecheck(options: TypecheckOptions): Promise<TypecheckResult>;
```

### 대안 검토

| 대안 | 설명 | 미선택 이유 |
|------|------|-------------|
| 타입을 engines/types.ts에 배치 | TypecheckOptions/Result를 엔진 타입과 같은 파일에 | BuildOrchestrator가 자체 타입을 파일 내 정의하는 패턴과 불일치. engines/types.ts는 엔진 레벨 타입(BuildEngine, EngineResult)용 |
| check.ts에서 TypecheckOrchestrator 클래스 직접 사용 | init/start/shutdown 호출 | check.ts는 typecheck/lint/test를 병렬 실행하므로 편의 함수가 더 적합. 불필요한 코드 증가 |
| executeTypecheck를 commands/typecheck.ts에 유지 | Orchestrator가 내부 구현만 담당 | check.ts가 commands/typecheck를 import하면 command→command 참조가 유지되어 레이어 분리 효과 감소 |
