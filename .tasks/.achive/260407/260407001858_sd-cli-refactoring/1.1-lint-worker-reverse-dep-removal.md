## 구현계획

### 배경

sd-cli의 `workers/lint.worker.ts`(line 2)가 `commands/lint`를 import하여 Worker → Command 레이어 역전이 발생한다. sd-cli 아키텍처에서 Worker는 utils 이하 레이어만 참조해야 한다. [근거: CLAUDE.md 아키텍처 다이어그램]

`commands/lint.ts`는 현재 타입 정의(`LintOptions`, `LintResult`), 유틸리티(`ESLINT_CONFIG_FILES`, `isGlobalIgnoresConfig`, `loadIgnorePatterns`), 핵심 로직(`executeLint`), CLI 래퍼(`runLint`)를 모두 포함하고 있다. [근거: commands/lint.ts 224줄 분석]

### 목표

- Worker → Command 역참조를 제거하여 레이어 정합성을 확보한다 [근거: wbs "레이어 역전 해소"]
- lint 핵심 로직을 `utils/lint-core.ts`로 분리하여 올바른 레이어에 배치한다 [근거: wbs "범위"]

### 비목표

- `executeLint`의 내부 로직 변경 [근거: wbs 경계 "코드 이동만"]
- `runLint`의 동작 변경 [근거: wbs 경계]
- lint.worker의 worker 격리 구조 변경 [근거: wbs 경계]

### 설계

**모듈 분리** [근거: wbs "범위" + D1 결정]

`commands/lint.ts` → `utils/lint-core.ts`로 이동할 항목:
- `LintOptions` 인터페이스 (line 13-19)
- `LintResult` 인터페이스 (line 25-34)
- `ESLINT_CONFIG_FILES` 상수 (line 41-46)
- `isGlobalIgnoresConfig()` 함수 (line 51-58)
- `loadIgnorePatterns()` 함수 (line 65-104)
- `executeLint()` 함수 (line 121-203)
- 필요한 import: `ESLint` (eslint), `createJiti` (jiti), `path`, `fsx`/`pathx` (@simplysm/core-node), `env`/`SdError` (@simplysm/core-common), `consola`

**래퍼 유지** [근거: D2 결정]

`commands/lint.ts`에 남길 항목:
- `runLint()` 함수만 유지
- `executeLint`, `LintOptions`를 `../utils/lint-core`에서 import

**import 경로 변경** [근거: wbs "범위" + D3 결정]

| `utils/lint-utils.ts`         | `../commands/lint`      | `./lint-core`             |
| `commands/check.ts`           | `./lint`                | `../utils/lint-core`      |

### 대안 검토

1. **Re-export 패턴**: `commands/lint.ts`에서 `utils/lint-core`를 re-export하여 기존 import 경로 유지. 역참조 문제의 본질적 해결이 아니라 우회에 불과하며, Worker가 여전히 commands 레이어를 경유하게 되어 채택하지 않음.
2. **commands/lint.ts 전체를 utils/로 이동**: lint 관련 모든 것을 utils에 두는 방식. `runLint()`는 stdout 출력 + exitCode 설정 등 CLI 진입점 역할이므로 commands/ 레이어에 남기는 것이 적절하여 채택하지 않음.
