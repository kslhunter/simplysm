## 구현계획

### 배경
sd-cli dev 명령은 DevWatchOrchestrator → BuildEngine(ViteEngine/ServerEsbuildEngine) → Worker Thread 구조로 동작한다.
코드 리뷰에서 리소스 관리, 에러 복원, 네이밍 일관성 관련 이슈가 발견되었다. [근거: review 7건]

### 목표
- esbuild 컨텍스트 실패 후 안전한 fallback [근거: Rule "esbuild 컨텍스트 생성 실패 시 안전한 상태 유지"]
- shutdown/initialize의 리소스 누수 방지 [근거: Rule "shutdown 시 모든 타이머 정리", "initialize 실패 시 replaceDepWatcher 해제"]
- workerKey 네이밍 통일 [근거: Rule "RebuildManager workerKey 네이밍 통일"]
- ResultCollector 타입 안전성 [근거: Rule "ResultCollector.toMap()이 ReadonlyMap을 반환"]
- 독립 클라이언트 감지 효율화 [근거: Rule "독립 클라이언트 감지 최적화"]

### 비목표
- ViteEngine/BaseEngine 이벤트 핸들링 코드 중복 축소 [근거: D1 — 영향 범위 대비 이점 부족]
- dev 명령 이외의 build/watch/check 명령 수정 [근거: wbs 경계]

### 설계

**LOGIC-001 (server-build.worker.ts:434-443)**
esbuild 컨텍스트 교체 시 `esbuildContext = undefined`를 선제 설정하여, 새 컨텍스트 생성 실패 시에도 disposed 참조가 남지 않도록 한다.

**DESIGN-001 (DevWatchOrchestrator.ts:239-277)**
`shutdown()` 상단에 `clearTimeout(this._serverRestartTimer)` + `clearTimeout(this._printServersTimer)` 추가.

**DESIGN-002 (DevWatchOrchestrator.ts:239-277)**
`shutdown()`에서 `_replaceDepWatcher?.dispose()`를 `_hasPackages` 가드 밖으로 이동.

**CONSIST-001 (ViteEngine.ts:113)**
ViteEngine의 workerKey를 `"vite:${name}"` → `"${name}:build"`로 변경. DevWatchOrchestrator의 `_onDevBatchComplete`에서 서버 빌드 감지 로직은 기존 `${p.name}:build` 패턴이 이미 올바르므로 수정 불필요.

**DESIGN-004 (ResultCollector.ts:42)**
`toMap()` 반환 타입을 `ReadonlyMap<string, BuildResult>`로 변경. 소비 코드에서 Map 변경 API를 호출하는 곳이 없으므로 컴파일 호환성 유지.

**PERF-001 (DevWatchOrchestrator.ts:398-413)**
`_startDevMode()`에서 `serverConnectedClients` Set을 한 번 구성하고, 독립 클라이언트 감지 루프에서 `Set.has()`로 O(1) 조회.

### 대안 검토
- CONSIST-001 대안: metadata 기반 필터링 (RebuildManager에 타입 정보 추가) — 변경 범위가 크고 현재 수준에서 과설계이므로 불채택.
- DESIGN-002 대안: initialize()에 try-catch 추가 — shutdown()을 수정하는 것이 방어적이고 누락 위험이 적음.
