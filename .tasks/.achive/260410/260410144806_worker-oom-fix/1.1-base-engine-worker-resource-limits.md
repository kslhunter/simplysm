## 구현계획

### 배경
`BaseEngine._createWorker()`(`packages/sd-cli/src/engines/BaseEngine.ts:103-106`)에서 `Worker.create(workerPath)`를 옵션 없이 호출하여, 워커가 V8 기본 힙 제한(~2-4GB)으로 실행된다. sd-cli의 무거운 TypeScript 컴파일 워크로드에서 3회 리빌드 시 힙 한도를 초과한다.

### 목표
- `Worker.create()` 호출 시 `resourceLimits: { maxOldGenerationSizeMb: 4096 }`를 전달하여 워커 힙 상한을 명시적으로 설정한다 [근거: Rule "Worker 생성 시 V8 힙 메모리 상한 설정"]

### 비목표
- ViteEngine 워커 메모리 설정 [근거: wbs 경계 "ViteEngine은 BaseEngine을 상속하지 않으므로"]
- dev 모드 메인 프로세스 `--max-old-space-size` 설정 [근거: wbs 경계 "현재 메인 프로세스 OOM은 보고되지 않음"]

### 설계
변경 대상: `packages/sd-cli/src/engines/BaseEngine.ts:103-106`

현재 코드:
```typescript
protected _createWorker(): void {
  const workerPath = this._getWorkerPath();
  this._worker = Worker.create<TWorkerModule>(workerPath);
}
```

변경 후:
```typescript
protected _createWorker(): void {
  const workerPath = this._getWorkerPath();
  this._worker = Worker.create<TWorkerModule>(workerPath, {
    resourceLimits: { maxOldGenerationSizeMb: 4096 },
  });
}
```

### 대안 검토
없음 — debug.md에서 방안 A가 유일한 확정 방안으로 선택되었으며, 기존 코드베이스(`protocol-wrapper.ts:38`)에 동일 패턴이 존재한다.
