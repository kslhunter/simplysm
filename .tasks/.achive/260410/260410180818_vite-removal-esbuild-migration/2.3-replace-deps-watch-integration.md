## 구현계획

### 배경

현재 replaceDeps 감시는 두 계층으로 구성:
1. `watchReplaceDeps` (Orchestrator 레벨, `replace-deps.ts:318-407`): 소스 → node_modules 파일 복사
2. `sdScopeWatchPlugin` (Worker/Vite 레벨, `vite-scope-watch-plugin.ts:29-77`): node_modules 감시 → `server.restart()` pre-bundling 캐시 갱신

esbuild 전환 후에는 pre-bundling이 없으므로, `sdScopeWatchPlugin`의 역할이 불필요하다. esbuild `context.watch()`가 import graph의 모든 파일 변경을 자동 감지하여 rebuild한다.

### 목표
- `watchReplaceDeps`에 `onChanged` 콜백 추가 — 복사 완료 후 외부 통지 [근거: Rule "onChanged 콜백으로 변경 사실 통지"]
- esbuild watch의 자동 rebuild와 HMR 파이프라인 연동 확인 [근거: Rule "rebuild 결과는 기존 HMR 파이프라인으로 전달"]

### 비목표
- `sdScopeWatchPlugin` 제거 — Feature 3.1에서 처리 [근거: WBS 경계]
- `replace-deps.ts`의 파일 복사 로직 변경 [근거: WBS "기존 `replace-deps.ts` 재활용"]
- HMR 서비스 변경 [근거: Feature 2.2에서 완료]

### 설계

**`replace-deps.ts` 변경**: `watchReplaceDeps` 함수 시그니처에 optional `options` 파라미터 추가 [근거: D2 결정]

```typescript
// 변경 전
export async function watchReplaceDeps(
  projectRoot: string,
  replaceDeps: Record<string, string>,
): Promise<WatchReplaceDepResult>

// 변경 후
export async function watchReplaceDeps(
  projectRoot: string,
  replaceDeps: Record<string, string>,
  options?: { onChanged?: () => void },
): Promise<WatchReplaceDepResult>
```

`onChange` 핸들러 내부에서 파일 복사 루프 완료 후 `onChanged` 호출:

```typescript
watcher.onChange({ delay: 300 }, async (changeInfos) => {
  for (const { path: changedPath } of changeInfos) {
    // ... 기존 파일 복사 로직 (변경 없음) ...
  }
  // 복사 완료 후 콜백 호출
  options?.onChanged?.();
});
```

**esbuild watch 자동 rebuild 경로** [근거: D1 결정]:
```
watchReplaceDeps 복사 완료
    → esbuild watch가 node_modules 파일 변경 감지
    → 자동 rebuild
    → sd-on-end 플러그인 (esbuild-client-config.ts:216-222)
    → hmrService.onBuildEnd(metafile)
    → WS 메시지 (component-update / css-update / full-reload)
```

### 대안 검토

1. **명시적 `context.rebuild()` 호출**: `onChanged` 콜백에서 `context.rebuild()` 직접 호출. 기각 — `context.watch()`와 동시 사용 시 이중 rebuild 위험. watch가 이미 자동 감지하므로 불필요.
2. **node_modules 별도 감시**: `watchReplaceDeps`와 별도로 node_modules를 FsWatcher로 감시. 기각 — 이중 감시로 복잡도 증가, 기존 300ms 디바운스와 타이밍 충돌.
3. **EventEmitter 패턴**: `WatchReplaceDepResult`에 `on("changed", callback)` 추가. 기각 — 단일 콜백이면 충분, `onScopeRebuild` 패턴과 일관성 유지.
