## 구현계획

### 배경

현재 클라이언트 패키지 빌드는 ViteEngine → client.worker → Vite API (createServer/viteBuild) 경로로 처리된다. Feature 1.x에서 esbuild 기반 빌드 유틸(esbuild-client-config, esbuild-index-html, esbuild-pwa, esbuild-scss-plugin)이 구현되었고, Feature 2.x에서 dev 서버 인프라(dev-http-server, hmr-service, hmr-client-script)가 구현되었다. Feature 3.1은 이 유틸들을 통합하여 Vite 의존을 제거한다.

기존 코드 참조:
- ViteEngine.ts: BuildEngine 인터페이스 독립 구현 (BaseEngine 미상속), Worker 생성/이벤트 구독/port 관리
- client.worker.ts: build(), startWatch(), stopWatch() 3개 메서드, ClientWorkerEvents 5종 (buildStart, build, serverReady, error, scopeRebuild)
- engines/index.ts: target === "client" → ViteEngine 생성 (createBuildEngine 팩토리)

### 목표
- Vite 빌드 파이프라인을 esbuild 기반으로 전환 [근거: WBS "ViteEngine.ts → 새 EsbuildClientEngine.ts로 교체"]
- 기존 BuildEngine 인터페이스 유지 [근거: WBS "BuildOrchestrator, DevWatchOrchestrator의 엔진 호출 인터페이스는 유지"]

- Capacitor/Electron 연동 호환성 유지 [근거: WBS "dist/ 출력 구조 유지, .dev-port 호환성"]

### 설계

#### EsbuildClientEngine.ts [근거: ViteEngine.ts 패턴 유지]

ViteEngine과 동일한 구조로 BuildEngine 인터페이스를 독립 구현한다 (D1).

```typescript
// packages/sd-cli/src/engines/EsbuildClientEngine.ts
interface EsbuildClientEngineOptions {
  cwd: string;
  pkg: ClientPackageInfo;
  resultCollector?: ResultCollector;
  rebuildManager?: RebuildManager;
  outDir?: string;
  base?: string;
}

class EsbuildClientEngine implements BuildEngine {
  port: number | undefined;

  // Worker 생성 → build() 호출 → EngineResult 반환
  async run(output: BuildOutput): Promise<EngineResult>;

  // Worker 생성 → 이벤트 구독 (serverReady, buildStart, build, error)
  // → startWatch() 호출 → 초기 빌드 완료 시 resolve
  async startWatch(output: BuildOutput): Promise<void>;

  // .dev-port 삭제 → Worker 중지
  async stop(): Promise<void>;
}
```

ViteEngine과의 차이:
- `replaceDeps` 옵션 제거 (D2: Feature 2.3으로 위임)
- Worker 이벤트에서 `scopeRebuild` 제거 (D2)
- 나머지 패턴 동일: Worker 생성, 이벤트 구독, ResultCollector/RebuildManager 통합

#### client.worker.ts 재작성 [근거: WBS "client.worker.ts 재작성 (Vite API 제거, esbuild context + HTTP 서버)"]

**ClientBuildInfo 변경:**
```typescript
interface ClientBuildInfo {
  name: string;
  cwd: string;
  pkgDir: string;
  // framework 제거 (D3)
  // exclude 제거 (D4)
  port?: number;
  env?: Record<string, string>;
  configs?: Record<string, unknown>;
  pwa?: false | SdPwaConfig;
  outDir?: string;
  base?: string;
}
```

**ClientWorkerEvents 변경:**
```typescript
interface ClientWorkerEvents extends Record<string, unknown> {
  buildStart: Record<string, never>;
  build: ClientBuildResult;
  serverReady: { port: number };
  error: { message: string };
  // scopeRebuild 제거 (D2)
}
```

**build() 흐름:**
1. `copyPublicFiles(pkgDir, false)` — public/ → dist/ 복사
2. `createClientEsbuildContext()` — esbuild context 생성
3. `context.rebuild()` — 빌드 실행
4. `extractFilesFromMetafile()` + `generateIndexHtml()` — index.html 생성
5. `applyPwa()` — PWA 적용 (pwa !== false)
6. `context.dispose()` + `sourceFileCache.close()` — 리소스 해제
7. `writeConfigJson()` — dist/.config.json 기록
8. Return `ClientBuildResult`

**startWatch() 흐름:**
1. dist/ 초기화 (`fs.rmSync`)
2. `watchPublicFiles(pkgDir, true)` — public/ → dist/ 복사 + 감시 (D5)
3. `createClientEsbuildContext()` — templateUpdates Map + onEnd 콜백
4. `createDevHttpServer()` — hmrService.handleRequest를 onRequest로 전달
5. `createHmrService()` — httpServer로 WebSocket 생성
6. `context.watch()` — esbuild watch 시작
7. 초기 빌드 대기 (onEnd에서 resolve)
8. `generateIndexHtml()` — HMR 스크립트 포함 (`createHmrPostTransform`)
9. `devServer.listen()` → port
10. `sender.send("serverReady", { port })`
11. `writeConfigJson()`, `.dev-port` 기록

**onEnd 콜백 (esbuild watch 빌드 완료 시):**
1. `sender.send("buildStart", {})`
2. `generateIndexHtml()` — 재생성
3. `hmrService.onBuildEnd(metafile)` — HMR 메시지 디스패치
4. `sender.send("build", { success, errors, warnings })`

**stopWatch() 흐름:**
1. esbuild context dispose + sourceFileCache close
2. hmrService.close()
3. devServer.close()
4. publicWatcher?.close()

**legacyModule 통합 (D6):**
- 동일한 esbuild + devHttpServer + hmrService 사용
- esbuild 옵션만 다름: `legacyModule: true` → splitting:false, import.meta 비활성화
- HMR: CSS swap + full-reload만 동작 (Angular component-update 미동작)
- 기존의 legacy 전용 HTTP 서버(createLegacyHttpServer) 및 SSE 방식 제거

### 대안 검토

**EsbuildClientEngine에서 BaseEngine 상속:**
- 장점: Worker 이벤트 처리 코드(buildStart/build/error) 재사용, ~50줄 절감
- 단점: BaseEngine에 serverReady/port 추상화 추가 필요 → ServerEsbuildEngine, TscEngine, NgtscEngine 모두 영향
- 선택하지 않은 이유: 리팩토링 범위가 Feature 3.1을 초과. ViteEngine 패턴이 이미 검증됨

**client.worker.ts를 유지하고 내부만 점진적 교체:**
- 장점: 기존 코드 재활용, 변경 최소화
- 단점: Vite import, legacy HTTP server(SSE), 복잡한 분기가 잔존. 유지보수 부담
- 선택하지 않은 이유: Vite와 esbuild의 API가 근본적으로 다름. 깨끗한 재작성이 더 안전
