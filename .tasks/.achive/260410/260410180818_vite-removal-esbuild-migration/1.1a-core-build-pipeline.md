## 구현계획

### 배경

현재 sd-cli의 client 패키지 빌드는 Vite를 경유한다. `sdAngularPlugin`(Vite 플러그인)이 `AngularBuildPipeline`을 통해 AOT 컴파일을 수행하고, Vite가 esbuild를 호출하여 번들링한다. 이 구조에서 Vite의 pre-bundling이 replaceDeps와 충돌하여 빌드 오류를 유발한다.

Feature 1.1a는 중간 레이어(Vite)를 제거하고 esbuild + `createCompilerPlugin`을 직접 사용하는 코어 빌드 파이프라인을 구축한다. `createCompilerPlugin`은 `@angular/build/private`에서 export되는 래핑 함수로, Angular AOT 컴파일, 컴포넌트 스타일시트 번들링, 증분 캐싱, PostCSS, Web Worker 번들링을 내장한다.

### 목표

- esbuild context를 직접 생성하여 Angular client 패키지를 ESM 번들로 빌드한다 [근거: wbs "esbuild context 생성 및 빌드 실행"]
- `createCompilerPlugin`의 2-param private export로 AOT 컴파일을 통합한다 [근거: wbs "createCompilerPlugin 통합", private.d.ts 확인]
- `SourceFileCache`로 LMDB 기반 증분 빌드를 지원한다 [근거: wbs "SourceFileCache 활용"]
- define으로 Angular 플래그(`ngDevMode`, `ngJitMode`, `ngHmrMode`)와 커스텀 환경변수를 주입한다 [근거: wbs "define 주입"]
- build(일회성)/watch(증분) 두 실행 모드를 지원한다 [근거: wbs "build/watch 실행 모드"]

### 비목표

### 설계

#### 신규 파일: `src/utils/esbuild-client-config.ts`

기존 `vite-config.ts`의 `createClientViteConfig`에 대응하는 함수. esbuild `BuildContext`를 반환한다. [근거: 기존 패턴 `esbuild-config.ts`에 server용 `createServerEsbuildOptions`가 존재]

```typescript
import esbuild from "esbuild";
import {
  createCompilerPlugin,
  SourceFileCache,
  type CompilerPluginOptions,
  type BundleStylesheetOptions,
} from "@angular/build/private";

export interface CreateClientEsbuildOptions {
  /** 패키지 디렉토리 경로 */
  pkgDir: string;
  /** 모노레포 루트 (workspaceRoot) */
  cwd: string;
  /** 빌드 모드 */
  mode: "dev" | "build";
  /** tsconfig 경로 (기본: pkgDir/tsconfig.json) */
  tsconfig?: string;
  /** 빌드 시 치환할 환경변수 */
  env?: Record<string, string>;
  /** 추가 esbuild 플러그인 (Feature 1.1b에서 사용) */
  plugins?: esbuild.Plugin[];
  /** HMR용 templateUpdates Map (Feature 2.2에서 사용) */
  templateUpdates?: Map<string, string>;
  /** watch 모드 빌드 완료 콜백 */
  onEnd?: (result: esbuild.BuildResult) => void;
  /** PostCSS 플러그인 ([name, options] 튜플 배열) */
  postcssPlugins?: [string, (object | string)?][];
  /** PostCSS 설정 기준 경로 */
  postcssConfigPath?: string;
  /** 빌드 출력 경로 (기본: pkgDir/dist) */
  outdir?: string;
}

export interface ClientEsbuildResult {
  context: esbuild.BuildContext;
  sourceFileCache: SourceFileCache;
}

export async function createClientEsbuildContext(
  options: CreateClientEsbuildOptions,
): Promise<ClientEsbuildResult>;
```

#### createCompilerPlugin 통합 [근거: wbs "CompilerPluginOptions, BundleStylesheetOptions, SourceFileCache"]

```typescript
// SourceFileCache 생성 (LMDB 디스크 캐시)
const sourceFileCache = new SourceFileCache(
  path.join(options.pkgDir, ".angular", "cache"),
);

// CompilerPluginOptions
const pluginOptions: CompilerPluginOptions & { browserOnlyBuild?: boolean } = {
  tsconfig: options.tsconfig ?? path.join(options.pkgDir, "tsconfig.json"),
  sourcemap: isDev ? "linked" : false,
  advancedOptimizations: !isDev,
  thirdPartySourcemaps: isDev,
  incremental: true,
  sourceFileCache,
  loadResultCache: sourceFileCache.loadResultCache,
  templateUpdates: options.templateUpdates,
  browserOnlyBuild: true,
};

// BundleStylesheetOptions
const styleOptions: BundleStylesheetOptions & { inlineStyleLanguage: string } = {
  workspaceRoot: options.cwd,
  optimization: !isDev,
  inlineFonts: false,
  sourcemap: isDev ? "linked" : false,
  outputNames: { bundles: "[name]", media: "media/[name]" },
  includePaths: [],
  target: [],  // Feature 1.1b에서 browserslist → esbuild target으로 설정
  cacheOptions: {
    enabled: true,
    path: path.join(options.pkgDir, ".angular", "cache"),
    basePath: path.join(options.pkgDir, ".angular", "cache"),
  },
  // PostCSS (sd.config.ts에서 전달)
  postcssConfiguration: options.postcssPlugins != null
    ? {
        config: { plugins: options.postcssPlugins },
        configPath: options.postcssConfigPath ?? options.pkgDir,
      }
    : undefined,
  inlineStyleLanguage: "scss",  // D2: 고정
};

const angularPlugin = createCompilerPlugin(pluginOptions, styleOptions);
```

### 대안 검토

| 대안 | 설명 | 기각 사유 |
|------|------|----------|
| `buildApplicationInternal` 사용 | Angular CLI의 전체 빌드 파이프라인 사용 | sd-cli 커스텀 요구사항(replaceDeps, HMR, Capacitor 연동)에 맞추기 어려움. 옵션이 NormalizedApplicationBuildOptions로 고정되어 유연성 부족 |
| 내부 3-param `createCompilerPlugin` 사용 | `AngularCompilation`과 `ComponentStylesheetBundler`를 직접 생성하여 더 세밀한 제어 | private export의 2-param 래퍼가 내부적으로 Compilation과 Bundler를 생성·관리하므로 충분. 내부 API 의존성 증가 불필요 |
| PostCSS를 esbuild 후처리로 별도 적용 | createCompilerPlugin 외부에서 빌드 산출물에 PostCSS 적용 | 컴포넌트 인라인 스타일은 createCompilerPlugin이 내부에서 처리하므로 외부 접근 불가. BundleStylesheetOptions.postcssConfiguration 사용이 유일한 방법 |
