# Feature 2.2 HMR 서비스 (template/styles)

### 설계 결정
| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | legacyModule에서 Angular HMR | 미지원 (CSS hot swap + full-reload만) | Angular `compileHmrInitializer`가 `import.meta.hot.on()` + `import()` 사용. legacyModule에서 `import.meta` 비활성화, `import()` 제거로 HMR 초기화 불가 |
| D2 | hmr-candidates.ts 재활용 | 미사용. templateUpdates Map으로 대체 | `createCompilerPlugin`이 NgCompiler를 외부에 노출하지 않음. HMR 후보 판별을 내부 수행하고 결과를 templateUpdates에 기록 |
| D3 | WebSocket 라이브러리 | `ws` 패키지를 sd-cli 직접 의존성으로 추가 | Node.js에 built-in WebSocket 서버 없음. `ws`는 Node.js WebSocket 서버의 de facto 표준 |
| D4 | import.meta.hot 제공 방식 | esbuild `banner` 옵션으로 폴리필 주입 | Angular HMR 런타임이 `import.meta.hot.on('angular:component-update', ...)` 사용. ESM format의 banner는 모듈 스코프에서 실행되어 `import.meta` 접근 가능. `ngHmrMode` 가드로 prod/legacy에서 실행 안됨 |
| D5 | CSS hot swap 감지 메커니즘 | 모든 CSS 파일명을 WS 메시지로 전송, 클라이언트에서 cache-busting refetch | metafile 비교보다 단순. dev 환경에서 CSS refetch 비용 무시 가능 |
| D6 | templateUpdates 클리어 시점 | esbuild `onStart` 플러그인에서 클리어 | Angular `execute-build.js`와 동일 패턴. rebuild 시작 전에 이전 데이터 제거 |

## 구현계획

### 배경

현재 Angular HMR은 Vite의 인프라에 의존한다:
- `import.meta.hot.on('angular:component-update', callback)` — Vite의 HMR API로 업데이트 리스너 등록
- `import('/@ng/component?c=<id>')` — Vite가 모듈 해석 및 서빙
- `server.hot.send()` — Vite의 WebSocket으로 클라이언트에 통지

Vite 제거 후, 이 세 가지를 자체 구현으로 대체한다:
1. `import.meta.hot` 폴리필 (esbuild banner) + `globalThis.__hmr_dispatch` 브릿지
2. `/@ng/component` HTTP 엔드포인트 (dev-http-server 확장)
3. `ws` 기반 WebSocket 서버 + HMR 클라이언트 스크립트

핵심 발견: Angular compiler의 `emitHmrUpdateModule()`이 생성하는 HMR 업데이트 모듈은 **self-contained** (외부 import 없음, 모든 의존성을 함수 파라미터로 수신). 따라서 Vite의 모듈 해석 없이도 `import()`로 직접 로드 가능.

### 목표
- Angular HMR 런타임이 Vite 없이 동작하도록 `import.meta.hot` 폴리필을 제공한다 [근거: Rule "import.meta.hot API 제공"]
- template/styles 변경 시 full-reload 없이 컴포넌트를 핫 업데이트한다 [근거: Rule "template/styles 변경 시 HMR update"]
- CSS 변경 시 `<link>` 태그 교체로 full-reload 없이 스타일을 갱신한다 [근거: Rule "CSS 변경 시 link 태그 교체"]
- 기존 HMR 배칭 패턴(100ms)을 유지한다 [근거: Rule "100ms 디바운싱"]

### 비목표
- TS 로직 HMR (full-reload 처리) [근거: wbs 제외 사항]
- legacyModule에서의 Angular HMR (import.meta + import() 미가용) [근거: D1]
- Vite HMR 프로토콜 호환 [근거: 커스텀 WebSocket 프로토콜 사용]

### 설계

**새 유틸 함수**: `packages/sd-cli/src/utils/hmr-service.ts`

Angular HMR 서비스를 생성하는 `createHmrService()` 함수. WebSocket 서버 관리, 변경 판별, 메시지 디스패치를 담당.

```typescript
// hmr-service.ts

export interface HmrServiceOptions {
  /** HTTP 서버 (WebSocket upgrade 연결용) */
  httpServer: http.Server;
  /** basePath (예: "/my-app/") */
  basePath: string;
  /** templateUpdates Map (createCompilerPlugin과 공유) */
  templateUpdates: Map<string, string>;
}

export interface HmrService {
  /** esbuild onStart에서 호출: templateUpdates 클리어 + 이전 metafile 저장 */
  onBuildStart(): void;
  /** esbuild onEnd에서 호출: 변경 판별 + WS 메시지 디스패치 (100ms 디바운스) */
  onBuildEnd(result: esbuild.BuildResult): void;
  /** 리소스 정리 (WebSocket 서버 종료) */
  close(): void;
  /** HTTP 요청 핸들러 (/@ng/component 엔드포인트). true 반환 시 처리 완료 */
  handleRequest(req: IncomingMessage, res: ServerResponse): boolean;
}

export function createHmrService(options: HmrServiceOptions): HmrService;
```

**esbuild-client-config.ts 확장**: `templateUpdates` 옵션이 제공될 때 [근거: D4, D6]:
- `banner: { js: hmrPolyfill }` — `import.meta.hot` 폴리필 주입

**import.meta.hot 폴리필** (esbuild banner로 주입):

```javascript
// dev 모드 + non-legacy에서만 실행 (ngHmrMode 가드)
if (typeof ngHmrMode !== "undefined" && ngHmrMode) {
  (function() {
    var listeners = {};
    import.meta.hot = {
      on: function(event, callback) {
        if (!listeners[event]) listeners[event] = [];
        listeners[event].push(callback);
      },
      off: function(event, callback) {
        var cbs = listeners[event];
        if (cbs) {
          var idx = cbs.indexOf(callback);
          if (idx !== -1) cbs.splice(idx, 1);
        }
      }
    };
    globalThis.__hmr_dispatch = function(event, data) {
      var cbs = listeners[event];
      if (cbs) for (var i = 0; i < cbs.length; i++) cbs[i](data);
    };
  })();
}
```

**HMR 클라이언트 스크립트** (`</body>` 직전에 주입, Chrome 61 호환):

```javascript
(function() {
  var ws = null;
  var basePath = "{{BASE_PATH}}";
  var port = location.port;

  function connect() {
    ws = new WebSocket("ws://" + location.hostname + ":" + port);
    ws.onmessage = function(e) {
      var msg = JSON.parse(e.data);
      if (msg.type === "component-update" && typeof globalThis.__hmr_dispatch === "function") {
        for (var i = 0; i < msg.ids.length; i++) {
          globalThis.__hmr_dispatch("angular:component-update", {
            id: msg.ids[i],
            timestamp: msg.timestamp
          });
        }
      } else if (msg.type === "css-update") {
        var links = document.querySelectorAll('link[rel="stylesheet"]');
        for (var i = 0; i < links.length; i++) {
          var href = links[i].getAttribute("href");
          if (href) {
            var base = href.split("?")[0];
            links[i].setAttribute("href", base + "?t=" + msg.timestamp);
          }
        }
      } else if (msg.type === "full-reload") {
        location.reload();
      }
    };
    ws.onclose = function() {
      setTimeout(connect, 1000);
    };
  }
  connect();
})();
```

**서버 측 변경 판별 로직** (onBuildEnd 내부):

1. `templateUpdates.size > 0` → `component-update` 메시지 (HMR)
2. `templateUpdates.size === 0` + CSS-only 출력 변경 → `css-update` 메시지
3. `templateUpdates.size === 0` + JS 출력 변경 → `full-reload` 메시지
4. 100ms `setTimeout`으로 디바운싱 — 타이머 내에 추가 onBuildEnd 도착 시 리셋

CSS-only 변경 감지: 이전/현재 metafile의 JS 출력 파일 크기를 비교. 동일하면 CSS-only. [근거: D5]

### 대안 검토

| 대안 | 설명 | 비채택 이유 |
|------|------|------------|
| Vite HMR 프로토콜 구현 | Vite의 `{ type: "update", updates: [...] }` 프로토콜 호환 | Vite 클라이언트 코드(`/@vite/client`)가 필요하여 Vite 의존성 유지. 우리 목적에 비해 과잉 복잡 |
| hmr-candidates.ts 재활용 | NgCompiler 기반 HMR 후보 판별 | createCompilerPlugin이 NgCompiler를 외부에 노출하지 않음. templateUpdates Map으로 동일 목적 달성 |
| EventSource(SSE) 방식 | Server-Sent Events로 단방향 통신 | SSE는 단방향이라 클라이언트→서버 통신 불가. WebSocket이 양방향으로 확장성 높음 |
| legacyModule 전용 HMR 메커니즘 | import() 대신 script 태그 주입 | Angular의 HMR 초기화 코드가 import.meta.hot을 사용하므로 import.meta 자체가 비활성화된 legacyModule에서는 HMR 등록 자체가 불가. 커스텀 구현의 복잡도 대비 가치 부족 |
| esbuild inject 옵션으로 폴리필 | inject 배열에 폴리필 파일 추가 | inject는 export된 심볼을 글로벌 대체하는 용도. import.meta.hot 같은 프로퍼티 설정에는 부적합 |
