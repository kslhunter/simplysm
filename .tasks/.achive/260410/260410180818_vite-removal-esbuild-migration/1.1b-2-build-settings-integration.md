## 구현계획

### 배경

`createClientEsbuildContext()` (`esbuild-client-config.ts`)가 Feature 1.1a에서 구현되었다. 현재 미구현 상태인 설정:
- `target: []` (line 70, 주석 "Feature 1.1b에서 browserslist → esbuild target으로 설정")
- `entryPoints`에 `main.ts`만 포함 (line 109)
- `entryNames`/`chunkNames`/`assetNames` 미설정
- 에셋 복사 호출 미연결

### 목표

- browserslist → esbuild target 변환 통합 [근거: Rule "browserslist → esbuild target 변환"]
- polyfills entryPoints 추가 [근거: Rule "polyfills 자동 감지 및 entryPoints 추가"]
- 출력 네이밍 모드별 분기 [근거: Rule "출력 파일 네이밍은 모드별로 구분"]
- 에셋 복사 호출 패턴 문서화 [근거: Rule "에셋 복사는 호출자가 수행"]

### 비목표

- HTML `<script>` 태그 주입 [근거: WBS 경계 "index.html 생성은 Feature 1.2에서 처리", 설계 결정 D1]
- legacyModule 처리 (splitting, import.meta 치환) [근거: WBS 경계 "Feature 1.4에서 처리"]
- dev server / HMR [근거: WBS 경계 "Epic 2에서 처리"]
- `copyPublicFiles`/`watchPublicFiles` 함수 수정 [근거: 기존 유틸 변경 불필요]

### 설계

**1. `CreateClientEsbuildOptions` 인터페이스 확장** [근거: Rule "browserslist", "polyfills"]

```typescript
// packages/sd-cli/src/utils/esbuild-client-config.ts
export interface CreateClientEsbuildOptions {
  // ... 기존 필드 ...
  /** browserslist 쿼리. 미설정 시 "es2022" 기본값 */
  browserslist?: string | string[];
  /** polyfills 경로 (pkgDir 기준 상대경로, 예: ["src/polyfills.ts"]). entryPoints에 추가됨 */
  polyfills?: string[];
}
```

**2. browserslist → esbuild target 변환 로직** [근거: vite-config.ts:81-87 현재 패턴]

`browserslist-to-esbuild` 라이브러리 임포트 추가. 옵션의 `browserslist`를 `browserslistToEsbuild()`로 변환하여:
- `esbuild.context()` → `target` 필드에 적용
- `BundleStylesheetOptions` → `target` 필드에 적용 (현재 빈 배열 `[]`)
- 미설정 시 기본값 `"es2022"` 사용

**3. polyfills entryPoints 추가** [근거: client.worker.ts:201-203 패턴]

`options.polyfills` 배열이 존재하면 `entryPoints`에 절대경로로 추가:
```typescript
const entryPoints = [path.join(options.pkgDir, "src", "main.ts")];
if (options.polyfills != null) {
  for (const p of options.polyfills) {
    entryPoints.push(path.join(options.pkgDir, p));
  }
}
```

**4. 출력 네이밍 모드별 분기** [근거: 설계 결정 D2, D3]

```typescript
const namingPattern = isDev ? "[name]" : "[name]-[hash]";
// esbuild context options에 추가:
entryNames: namingPattern,
chunkNames: namingPattern,
assetNames: namingPattern,
```

**5. 에셋 복사** [근거: 설계 결정 D4]

`createClientEsbuildContext`는 변경 없음. 호출자(향후 Feature 3.1의 `EsbuildClientEngine` / `client.worker.ts`)에서:
- build 모드: `await copyPublicFiles(pkgDir, false)`
- dev/watch 모드: `const watcher = await watchPublicFiles(pkgDir, true)`

기존 `copy-public.ts`의 `copyPublicFiles`/`watchPublicFiles`는 변경 없이 재활용 가능.

### 대안 검토

**browserslist 변환 위치** — config 함수 내부 vs 호출자에서 변환 후 target 전달:
- 선택: config 함수 내부. 호출자가 `browserslist` 원본만 전달하면 됨. `browserslistToEsbuild` 의존성이 config 모듈에 캡슐화됨.
- 거부: 호출자에서 변환. 호출자마다 중복 변환 로직 발생. 응집도 하락.

**polyfills 감지 위치** — config 함수 내부 자동 감지 vs 호출자가 감지 후 전달:
- 선택: 호출자가 `fs.existsSync`로 감지 후 `polyfills` 배열로 전달. config 함수는 파일시스템 접근을 최소화. 테스트에서 모킹 불필요.
- 거부: 함수 내부 자동 감지. 파일시스템 의존성 증가. 테스트 복잡도 증가.
