## 구현계획

### 배경

현재 client 패키지의 dev 모드는 두 경로로 나뉜다:
- **일반 모드**: Vite `createServer()`로 dev 서버 생성 → Vite가 HTTP 서빙 + HMR 담당
- **legacy 모드**: Vite `build --watch` + `createLegacyHttpServer()`로 자체 HTTP 서빙 + SSE live reload

Vite 제거 후, 모든 모드에서 esbuild `context.watch()` + 자체 HTTP 서버를 사용한다. legacy 모드의 `createLegacyHttpServer()` (`client.worker.ts:105-172`)가 이미 필요한 기능의 대부분을 구현하고 있다.

### 목표
- esbuild watch 결과를 서빙하는 HTTP 정적 파일 서버 함수를 제공한다 [근거: Rule "dist/ 디렉토리의 정적 파일을 HTTP로 서빙"]
- SPA fallback, basePath 라우팅, MIME type 처리를 지원한다 [근거: Rule "SPA fallback", "basePath 접두사"]
- `.dev-port`, `.config.json` 기록 기능을 유지한다 [근거: Rule ".dev-port 파일", ".config.json 파일"]

### 비목표
- HMR WebSocket, live reload 스크립트 주입 (Feature 2.2 범위) [근거: wbs 경계]
- index.html 생성 (Feature 1.2 범위) [근거: wbs 경계]
- esbuild watch 시작/관리 로직 (Feature 3.1 EsbuildClientEngine에서 통합) [근거: wbs Feature 3.1 범위]

### 설계

**새 유틸 함수**: `packages/sd-cli/src/utils/dev-http-server.ts`

기존 `createLegacyHttpServer()` (`client.worker.ts:105-172`)를 기반으로, SSE/live-reload 로직을 제거하고 순수 정적 파일 서버로 추출한다.

```typescript
// dev-http-server.ts

export interface DevHttpServerOptions {
  /** dist/ 디렉토리 경로 */
  distDir: string;
  /** basePath (예: "/my-app/") — 항상 /로 시작하고 /로 끝남 */
  basePath: string;
  /** listen 포트 (0: 자동 할당) */
  port: number;
}

export interface DevHttpServer {
  /** 서버 시작, 실제 할당된 포트 반환 */
  listen(): Promise<number>;
  /** 서버 종료 */
  close(): Promise<void>;
  /** 내부 http.Server 인스턴스 (Feature 2.2에서 WebSocket 연결용) */
  readonly httpServer: http.Server;
}

export function createDevHttpServer(options: DevHttpServerOptions): DevHttpServer;
```

**요청 처리 흐름** (기존 `createLegacyHttpServer` 패턴 유지):
1. URL에서 query string 제거
2. basePath 접두사 확인 → 없으면 404
3. 빈 경로 → `index.html`
4. `fs.existsSync(filePath)` → 존재하면 MIME type으로 서빙
5. 미존재 → `index.html` SPA fallback → 없으면 404

**기존 코드와의 차이점**:
- SSE live-reload 엔드포인트 (`__live-reload`) 제거 — Feature 2.2에서 WebSocket으로 대체
- `injectLiveReloadScript()` 제거 — Feature 2.2에서 HMR 클라이언트 스크립트로 대체
- `httpServer` 인스턴스를 외부에 노출 — Feature 2.2에서 WebSocket 서버 연결용
- 함수가 listen/close를 포함하는 객체를 반환 — 기존은 raw `http.Server` 반환 후 호출자가 직접 listen

**`.dev-port` / `.config.json` 기록**: 기존 `writeConfigJson()` 함수 패턴 유지. listen 후 호출자(worker 또는 engine)가 기록. 이 유틸 함수의 책임은 HTTP 서빙에 한정.

### 대안 검토

| 대안 | 설명 | 비채택 이유 |
|------|------|------------|
| Express/Fastify 사용 | 프레임워크 기반 HTTP 서빙 | 불필요한 의존성 추가. 기존 `http.createServer()` 패턴이 충분하고, 70줄 미만의 단순 로직 |
| `createLegacyHttpServer` 그대로 재활용 | SSE 포함 | SSE는 Feature 2.2의 WebSocket으로 대체되므로 분리가 깔끔 |
| serve-static 미들웨어 | npm 패키지 활용 | 추가 의존성 불필요. `fs.existsSync` + `mime.getType` 조합이 충분 |
