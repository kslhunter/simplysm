## 구현계획

### 배경

Feature 1.1a에서 `createClientEsbuildContext`가 esbuild context를 `createCompilerPlugin`과 함께 생성하는 코어 파이프라인을 구축했다. 그러나 현재 두 가지가 누락되어 있다:

1. **side-effect SCSS 처리**: TypeScript 소스에서 `import "./style.scss"` 형태의 side-effect import가 있을 때, Angular 컴파일러가 이를 컴파일된 JS에 그대로 유지한다. esbuild가 이 `.scss` import를 해석하려면 onLoad 플러그인이 필요하다. (컴포넌트 스타일 `styleUrls`는 `createCompilerPlugin`이 `BundleStylesheetOptions`를 통해 내부 처리하므로 별도)

2. **tsconfig paths 해석**: 모노레포 tsconfig에 `"@simplysm/*": ["packages/*/src/index.ts"]` paths 매핑이 있다. esbuild의 네이티브 `tsconfig` 옵션으로 해석 가능하지만, 현재 `esbuild-client-config.ts`에는 이 옵션이 누락되어 있다.

### 목표

- side-effect SCSS import를 esbuild CSS 번들에 포함한다 [근거: Rule "side-effect SCSS import 처리"]
- tsconfig paths 매핑으로 모노레포 패키지 별칭을 해석한다 [근거: Rule "tsconfig paths 해석"]

### 비목표

- 컴포넌트 인라인 스타일시트 처리 [근거: WBS 경계 — createCompilerPlugin이 BundleStylesheetOptions로 처리]
- browserslist → target, polyfills, 에셋 복사, 출력 네이밍 [근거: WBS 경계 — Feature 1.1b-2]
- index.html 생성 [근거: WBS 경계 — Feature 1.2]

### 설계

#### 신규 파일: `src/utils/esbuild-scss-plugin.ts`

SCSS side-effect import를 처리하는 esbuild 플러그인. [근거: 코드베이스 패턴 — `vite-*-plugin.ts`처럼 플러그인별 파일 분리]

```typescript
import type esbuild from "esbuild";
import { compileScssFileAsync } from "./scss-compiler";

export interface CreateScssPluginOptions {
  loadPaths: string[];
}

export function createScssPlugin(options: CreateScssPluginOptions): esbuild.Plugin;
```

**onLoad 동작:**
1. `filter: /\.scss$/`로 `.scss` 파일 인터셉트
2. `compileScssFileAsync(args.path, options.loadPaths)` 호출 [근거: Rule "scss-compiler.ts 재활용"]
3. 성공 시: `{ contents: result.css, loader: "css", watchFiles: result.dependencies }` 반환
4. 실패 시: sass 에러를 esbuild `errors` 형식으로 변환 (파일 경로, 라인/컬럼 정보 포함)

**loadPaths 구성:** [근거: `ngtsc-build-core.ts:91-96` — `buildScssLoadPaths` 동일 패턴]
- `path.join(pkgDir, "scss")` — 패키지 로컬 SCSS 디렉토리
- `path.join(cwd, "node_modules")` — 외부 SCSS 패키지

#### 수정 파일: `src/utils/esbuild-client-config.ts`

**변경 1 — tsconfig 옵션 추가:** [근거: D1, 서버 빌드 `esbuild-config.ts:94` 동일 패턴]

```typescript
const context = await esbuild.context({
  // ... 기존 옵션
  tsconfig: options.tsconfig ?? path.join(options.pkgDir, "tsconfig.json"),
});
```

**변경 2 — SCSS 플러그인 통합:**

```typescript
import { createScssPlugin } from "./esbuild-scss-plugin";

const scssPlugin = createScssPlugin({
  loadPaths: [
    path.join(options.pkgDir, "scss"),
    path.join(options.cwd, "node_modules"),
  ],
});

// plugins 배열: angularPlugin → scssPlugin → customPlugins → onEndPlugin
plugins: [
  angularPlugin,
  scssPlugin,
  ...(options.plugins ?? []),
  ...(options.onEnd != null ? [onEndPlugin] : []),
],
```

### 대안 검토

| 대안 | 설명 | 기각 사유 |
|------|------|----------|
| tsconfigPaths 커스텀 onResolve 플러그인 | tsconfig 파싱 + onResolve로 paths 직접 구현 (~50줄) | esbuild 네이티브 `tsconfig` 옵션이 동일 기능 제공. 서버 빌드에서 검증 완료. 추가 코드 불필요 (D1) |
| SCSS 동기 컴파일 (`compileScssFile`) | esbuild onLoad에서 동기 sass API 사용 | esbuild onLoad는 async 콜백 지원. 비동기(`compileScssFileAsync`)가 병렬 컴파일에 유리 |
| SCSS 플러그인을 `esbuild-client-config.ts`에 인라인 | 별도 파일 대신 함수 내부에 직접 구현 | 코드베이스 패턴(플러그인별 파일 분리) 위반. 독립 테스트 어려움 |
