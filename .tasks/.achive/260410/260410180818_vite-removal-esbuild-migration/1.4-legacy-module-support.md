## 구현계획

### 배경

Feature 1.1a에서 생성된 `createClientEsbuildContext` 함수(`esbuild-client-config.ts`)는 esbuild 기반 Angular 클라이언트 빌드 설정을 생성한다. 현재 `splitting: true`로 고정되어 있으며 legacyModule 관련 처리가 없다. [근거: esbuild-client-config.ts:143]

현행 Vite 구현(`vite-config.ts:285-320`)은 Rollup의 `inlineDynamicImports`와 esbuild `supported`, Rollup 플러그인(`renderChunk`)으로 legacyModule을 처리한다. esbuild 전환 시 동일한 3가지 메커니즘을 esbuild 네이티브 옵션과 `onEnd` 플러그인으로 대체한다.

### 목표
- legacyModule 활성화 시 Chrome 61 호환 단일 번들 출력 [근거: Rule "코드 스플리팅 비활성화"]
- `import.meta` 구문을 esbuild가 호환 코드로 변환 [근거: Rule "import.meta 변환"]
- 번들링 후 잔여 dynamic `import()` 구문을 no-op으로 치환 [근거: Rule "잔여 dynamic import() 제거"]

### 비목표
- HMR 설정 변경 (`ngHmrMode` 등) — Feature 2.2 범위 [근거: WBS 경계 "HMR은 legacyModule에서도 동작"]
- `format` 변경 — `"esm"` 유지 [근거: D2 설계 결정]
- dev/build 분기 변경 — Feature 3.1(EsbuildClientEngine)에서 처리 [근거: WBS Feature 3.1 범위]

### 설계

#### 1. `CreateClientEsbuildOptions` 확장 [근거: Rule "legacyModule 옵션 인터페이스"]

```typescript
export interface CreateClientEsbuildOptions {
  // ... 기존 옵션 ...
  /** 레거시 모듈 지원 (코드 분할 비활성화 + import.meta 치환 + 잔여 import() 제거) */
  legacyModule?: boolean;
}
```

#### 2. esbuild context 옵션 조건 분기 [근거: Rule "코드 스플리팅 비활성화", Rule "import.meta 변환"]

`createClientEsbuildContext` 함수 내 esbuild context 생성 시:
- `splitting`: `legacyModule ? false : true`
- `supported`: `legacyModule ? { "import-meta": false } : undefined`

#### 3. `sd-legacy-strip-dynamic-import` onEnd 플러그인 [근거: D1 설계 결정]

`legacyModule: true`일 때 plugins 배열에 추가. `onEnd` 콜백에서:
1. `result.metafile.outputs`에서 `.js` 파일 경로 추출
2. 각 파일을 읽어 `import(` 문자열 존재 여부 확인 (early return)
3. `/\bimport\s*\(/g` regex로 no-op 함수 치환
4. 파일에 다시 쓰기

현행 Vite 플러그인(`vite-config.ts:306-319`)과 동일한 regex 및 치환 패턴 사용.

### 대안 검토

| 접근 | 장점 | 단점 | 결정 |
|------|------|------|------|
| **onEnd 디스크 재작성** (선택) | Rollup renderChunk과 동일한 효과. watch 모드에서 rebuild 루프 없음 (esbuild는 소스만 감시) | 디스크 I/O 발생 | 채택 — esbuild에 in-memory chunk 변환 API 없음 |
| `supported: {"dynamic-import": false}` | esbuild 네이티브 옵션 | ESM format에서 dynamic import 변환 시 `require()`로 폴백하며 브라우저에서 동작 불가 | 기각 |
| `write: false` + 메모리 변환 | I/O 최소화 | 기존 `write: true` 전제 변경. onEnd 이후 수동 write 필요. 다른 플러그인/Feature와의 호환성 불확실 | 기각 |
