## 구현계획

### 배경

sd-cli의 client 패키지 빌드가 Vite에서 esbuild로 전환됨에 따라, 기존 `vite-pwa-plugin.ts`의 PWA 기능을 esbuild 파이프라인에서 동작하도록 재구현한다. 현재 `sdPwaPlugin`은 Vite 플러그인 훅(`configResolved`, `transformIndexHtml`, `closeBundle`)에 의존하므로 esbuild 환경에서 직접 사용할 수 없다. [근거: wbs 배경 "Vite 제거 및 esbuild 기반 빌드 시스템 전환"]

### 목표

- Angular 표준 Service Worker(`ngsw-worker.js`)를 `augmentAppWithServiceWorker`로 생성 [근거: wbs "augmentAppWithServiceWorker 활용"]
- manifest.webmanifest 생성 로직을 독립 함수로 추출 [근거: Rule "manifest.webmanifest는 SdPwaManifestConfig에서 구성된다"]
- PWA HTML 주입을 `IndexHtmlTransform`으로 구현 [근거: Feature 1.2의 `esbuild-index-html.ts:29` postTransform 인터페이스 활용]
- ngsw-config.json 자동 생성으로 제로 설정 경험 유지 [근거: D1]

### 비목표

- dev 모드 PWA 지원 [근거: wbs 경계 "build 모드에서만 활성화"]
- Workbox 설정 API 유지 [근거: wbs 경계 "ngsw-config.json으로 제한", D4]
- SSR Service Worker [근거: wbs 제외사항]
- `SdPwaConfig` 타입 변경 [근거: Feature 3.2 범위]

### 설계

**새 파일: `packages/sd-cli/src/utils/esbuild-pwa.ts`**

1. `createPwaHtmlTransform(): IndexHtmlTransform` [근거: Rule "index.html에 manifest link와 SW 등록 스크립트가 주입된다"]
   - `<link rel="manifest" href="manifest.webmanifest">` → `</head>` 앞에 삽입
   - SW 등록 스크립트 → `</body>` 앞에 삽입
   - 등록 대상: `ngsw-worker.js` (기존 `sw.js` 대체)
   - `sd-pwa-update-ready` CustomEvent 패턴 유지 (D3)

2. `applyPwa(options: ApplyPwaOptions): Promise<void>` [근거: wbs 범위 전체]
   - 호출 시점: esbuild 빌드 완료 + index.html 생성 + copy-public 완료 이후
   - 처리 순서:
     a. **아이콘**: `generatePwaIcons(pkgDir)` 호출 → `public/icons/`에 생성된 파일을 `outdir/icons/`에 복사 (D2)
     b. **manifest**: `SdPwaManifestConfig`에서 `manifest.webmanifest` 구성 → `outdir/` 기록
     c. **ngsw-config.json**: 프로젝트에 파일 부재 시 기본 파일 자동 생성 (D1)
     d. **augmentAppWithServiceWorker**: `(pkgDir, cwd, outdir, baseHref)` 호출 → `ngsw.json` + `ngsw-worker.js` + `safety-worker.js` 생성

기본 ngsw-config.json:
```json
{
  "$schema": "./node_modules/@angular/service-worker/config/schema.json",
  "index": "/index.html",
  "assetGroups": [
    {
      "name": "app",
      "installMode": "prefetch",
      "resources": {
        "files": ["/*.html", "/*.css", "/*.js"]
      }
    },
    {
      "name": "assets",
      "installMode": "lazy",
      "updateMode": "prefetch",
      "resources": {
        "files": ["/**/*.{png,jpg,svg,ico,woff2,webmanifest}"]
      }
    }
  ]
}
```

**기존 파일 변경 없음:**
- `generate-pwa-icons.ts`: 그대로 재활용. `applyPwa` 내부에서 호출 후 결과를 dist/에 복사
- `sd-config.types.ts`: 변경 없음 (Feature 3.2로 위임)

### 대안 검토

| 대안 | 불채택 사유 |
|---|---|
| `augmentAppWithServiceWorkerEsbuild` 사용 | esbuild 인메모리 빌드용 (`BuildOutputFile[]` 인자). sd-cli는 `write: true`로 디스크에 출력하므로 파일시스템 시그니처가 적합 |
| 기존 커스텀 sw.js 유지 | WBS에서 Angular 표준 패턴 채택 결정. ngsw의 asset/data groups 구조가 더 정교한 캐싱 정책 지원 |
| `SwUpdate` 서비스 전환 | 소비 프로젝트에서 `ServiceWorkerModule.register()` + `SwUpdate` 주입 필요. 기존 CustomEvent가 동일 기능을 제공하며 마이그레이션 비용 불필요 |
| `generatePwaIcons`에 outDir 파라미터 추가 | 기존 함수 시그니처 변경 불필요. `applyPwa`에서 생성 후 복사로 동일 결과 달성 |
