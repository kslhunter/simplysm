## 구현계획

### 배경

현재 `createClientViteConfig`(`vite-config.ts:153-179`)에서 replaceDeps 패키지를 `optimizeDeps.include`에 등록한다. Vite는 이를 esbuild로 프리번들하여 `.vite/deps/` 캐시에 저장한다. dev server 실행 중 원본 파일이 변경되어도 캐시가 갱신되지 않아, 브라우저에서 변경사항이 반영되지 않는다. [근거: 사용자 보고 + 코드 분석]

### 목표

- replaceDeps 패키지를 `optimizeDeps.exclude`로 전환하여 프리번들 캐시 없이 직접 소스를 서빙한다 [근거: D1]

### 비목표

- server 패키지의 esbuild rebuild 문제 [근거: wbs 경계]
- replaceDeps 복제 메커니즘(watchReplaceDeps) 수정 [근거: wbs 경계]

### 설계

**`vite-config.ts` optimizeDeps 설정 변경:**

현재 (`vite-config.ts:153-179`):
```typescript
// replaceDeps를 include에 추가
const includeList: string[] = [];
for (const dep of (options.replaceDeps ?? [])) {
  // ... package.json 읽기 + main entry 확인
  includeList.push(dep.packageName);
}
const excludeList = options.exclude ?? [];
```

변경 후:
```typescript
// replaceDeps를 exclude에 추가
const excludeList = [...(options.exclude ?? [])];
for (const dep of (options.replaceDeps ?? [])) {
  excludeList.push(dep.packageName);
}
// includeList 관련 로직 제거
```

[근거: Rule "replaceDeps 패키지는 optimizeDeps.exclude에 등록된다"]

### 대안 검토

| 대안 | 선택하지 않은 이유 |
|------|-------------------|
| `server.restart()` | 모든 deps 재번들로 5-15초 소요. replaceDeps 변경 빈도 고려해도 느림 |
| `.vite/deps/` 캐시 직접 교체 | Vite 내부 구현 의존, 유지보수 불가 |
