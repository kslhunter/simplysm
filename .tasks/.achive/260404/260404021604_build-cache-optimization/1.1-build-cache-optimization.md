# Feature 1.1 sd-cli 빌드 캐시 최적화

## 참조 자료

### 캐시 대상 코드

- `packages/sd-cli/src/angular/vite-angular-plugin.ts` — `prebundleTransformer.transformFile()` (optimizeDeps에서 Linker 실행)
- `packages/sd-cli/src/angular/client-transform-stylesheet.ts` — `compileScssFileAsync()` (외부 SCSS 컴파일)
- `packages/sd-cli/src/utils/scss-compiler.ts` — sass 컴파일 API, 의존성 추출

### 기존 캐시 패턴

- `.cache/*.tsbuildinfo` — TypeScript 증분 컴파일 캐시
- `.cache/eslint.cache` — ESLint 캐시

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | Linker 캐시 적용 지점 | optimizeDeps의 prebundleTransformer만 | Vite 캐시 무효화 시 개별 파일 레벨로 스킵. transform 훅은 .ts emit 변경 빈도 높아 효과 제한적 |
| D2 | SCSS 캐시 대상 범위 | 외부 .scss 파일만 | 캐시 히트율 높고 구현 단순. 인라인은 .ts 수정 시마다 변경 |
| D3 | PostCSS 포함 여부 | SCSS 컴파일만 캐시 | PostCSS 플러그인 직렬화 불안정 문제 회피, PostCSS 자체는 빠름 |
| D4 | replace-deps Linker 제외 방식 | sdScopeWatchPlugin의 optimizeDeps.exclude가 이미 처리 | 별도 제외 로직 불필요 |
| D5 | SCSS 캐시 시 파일 이중 읽기 회피 | compileScssStringAsync 사용 | 파일을 직접 읽어 해시 계산 후 string 기반 컴파일 |

  Rule: node_modules .js 파일의 Linker 변환 결과를 디스크에 캐싱한다

      When optimizeDeps가 node_modules .js 파일을 처리한다

    Scenario: 패키지 버전 업데이트로 캐시 미스

      When optimizeDeps가 해당 패키지의 .js 파일을 처리한다
      Then 파일 내용 해시가 달라져 캐시 미스가 발생한다
      And Linker를 실행하고 새 결과를 캐시에 저장한다

    Scenario: Vite optimizeDeps 캐시가 유효한 경우
      Given Vite optimizeDeps 캐시가 유효하다

      Then Vite가 자체 캐시를 사용하고 prebundleTransformer는 호출되지 않는다

  Rule: 외부 SCSS 파일의 컴파일 결과를 해시 기반으로 캐싱한다

    Scenario: 외부 .scss 변경 없음 + 의존성 변경 없음

      And PostCSS는 캐시된 CSS에 매번 적용한다

      When Linker 캐시를 조회한다
      Then 파일 내용의 해시를 키로 사용한다

    Scenario: SCSS 캐시 키 생성
      Given .scss 파일이 2개의 의존성 파일을 @use한다
      When SCSS 캐시를 조회한다
      Then 본 파일 + 2개 의존성 파일의 내용 해시를 합산하여 키로 사용한다

## 구현계획

### 배경

sd-cli의 Angular 클라이언트 빌드에서 Vite `optimizeDeps`의 Angular Linker(`prebundleTransformer`)와 SCSS 컴파일이 매번 전체 재실행된다. Vite는 `optimizeDeps` 결과를 `node_modules/.vite/deps/`에 번들 단위로 캐싱하지만, 캐시 무효화(예: `pnpm install`) 시 모든 .js 파일을 다시 Linker 변환한다. SCSS 컴파일은 캐시가 전혀 없다.

기존 코드베이스에 `createHash("sha256")` 패턴(`angular-compiler.ts:27`)과 `.cache/` 디렉토리 사용 패턴(`tsc-build.ts`, `ngtsc-build-core.ts`)이 있다.

### 목표

- `optimizeDeps`의 `prebundleTransformer`에 파일 해시 기반 디스크 캐시 도입
- 외부 `.scss` 파일의 sass 컴파일 결과에 해시 기반 디스크 캐시 도입

### 비목표

- `transform` 훅의 `jsTransformer` 캐시 (D1: .ts emit 변경 빈도 높아 효과 제한적)
- 인라인 SCSS 캐시 (D2)
- PostCSS 결과 캐시 (D3)
- 캐시 정리/가비지 컬렉션 (stale 파일은 무해, 수동 삭제 가능)

### 설계

#### Linker 디스크 캐시

- **캐시 위치:** `{cwd}/.cache/linker/{optionsKey}/` — `optionsKey`는 `sm` 또는 `nosm` (`enableSourcemap` 기반). Linker 옵션이 출력에 영향을 주므로 옵션별 분리.
- **캐시 키:** 파일 내용 SHA256 해시 (content-addressed)
- **캐시 파일:** `{contentHash}.js` — Linker 변환된 JS 텍스트
- **변경 파일:** `vite-angular-plugin.ts`의 `config()` 훅 내 `angular-vite-optimize-deps` esbuild 플러그인
- **흐름:**
  1. `onLoad` 핸들러에서 파일 내용 읽기 → SHA256 해시 계산
  2. `{cacheDir}/{hash}.js` 존재 확인 → 있으면 캐시 반환
  3. 없으면 `prebundleTransformer.transformFile()` 실행 → 결과를 캐시에 저장 후 반환
  4. 캐시 읽기/쓰기 실패 시 무시하고 정상 변환 진행 (graceful fallback)

#### SCSS 디스크 캐시

- **캐시 위치:** `{pkgDir}/.cache/scss/` — `pkgDir = path.dirname(options.tsconfig)`
- **캐시 파일:** `{pathHash}.json` — `pathHash`는 절대 경로 SHA256 앞 16자
- **캐시 구조:**
  ```json
  {
    "fileHash": "abc...",
    "deps": [{ "path": "/abs/_variables.scss", "hash": "def..." }],
    "css": ".host { color: blue; }"
  }
  ```
- **변경 파일:** `client-transform-stylesheet.ts`의 외부 `.scss` 분기
- **새 옵션:** `ClientTransformStylesheetOptions.cacheDir?: string`
- **흐름:**
  1. 파일 내용 읽기 → SHA256 해시 계산
  2. 캐시 파일 로드 → `fileHash` 일치 확인
  3. 일치하면 각 의존성 파일의 현재 해시를 계산하여 캐시 값과 비교
  4. 모두 일치 → 캐시 히트: `scssDependencies` Map에 의존성 등록 + 캐시된 CSS 반환
  5. 불일치 → 캐시 미스: `compileScssStringAsync(content, filePath, loadPaths)` 실행 → 결과 + 의존성 해시 캐시에 저장
  6. 캐시 읽기/쓰기/파싱 실패 시 무시하고 정상 컴파일 진행 (graceful fallback)
- **`compileScssStringAsync` 사용 이유 (D5):** 파일 내용을 직접 읽어 해시 계산 후, 같은 내용을 `compileScssStringAsync`에 전달하여 파일 이중 읽기 회피

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| Linker: content-addressed 디스크 캐시 | 채택 | 파일 내용이 같으면 경로 무관하게 캐시 히트. 구현 단순 |
| Linker: manifest JSON 파일 기반 | 미채택 | 동시 접근 시 충돌 위험, 파일 단위 캐시가 더 안전 |
| SCSS: mtime 기반 무효화 | 미채택 | git 작업으로 mtime 불안정. content hash가 더 신뢰적 |
| SCSS: 전체 해시 사전 계산 (file + deps) | 미채택 | 의존성을 미리 알아야 하는 chicken-and-egg 문제 |
