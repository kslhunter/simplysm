# Feature 1.1 sd-cli watch 패턴 수정

## 참조 자료

### 현재 상태 분석

- `replaceDeps`는 `SdConfig` 루트 레벨 설정 (`sd-config.types.ts:265`)
- `DevWatchOrchestrator`가 `sdConfig.replaceDeps`를 읽어 `watchReplaceDeps`로 symlink watch는 하지만, 각 engine/worker에는 전달하지 않음
- `ServerWatchInfo`에 `replaceDeps` 필드가 존재하지만 `ServerEsbuildEngine.startWatch()`에서 전달하지 않음
- `LibraryBuildInfo`, `NgtscBuildInfo`에는 `replaceDeps` 필드 자체가 없음
- `collectDeps(pkgDir, cwd, replaceDepsConfig?)` 함수는 이미 replaceDeps 수집을 지원함

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | replaceDeps를 engine에 전달하는 방법 | `createBuildEngine` options에 추가 | `replaceDeps`는 SdConfig 루트 레벨이므로 per-package config가 아닌 engine 공통 옵션으로 전달 |
| D2 | `.tsx`/`.jsx` 제거 | 모든 glob 패턴에서 제거 | Angular 프로젝트이므로 사용하지 않음 |
| D3 | server-build 루트 glob | `src/**/*`만 유지 | config 변경은 dev 서버 재시작 필요, rebuild에서 제대로 반영 안 됨 |

## 구현계획

### 배경

sd-cli의 watch 모드(dev/watch)에서 파일 변경 감지 패턴에 여러 문제가 있다:
1. `.mjs`/`.cjs` 확장자 누락 — glob 패턴이 `.js`만 포함
2. `.tsx`/`.jsx` 불필요 포함 — Angular 프로젝트에서 미사용
3. `replaceDeps` watch 누락 — library-build/ngtsc-build worker가 replaceDeps 패키지의 dist/ 변경을 감지하지 못함
4. `replaceDeps` config 전달 누락 — engine → worker 간 config 전달 경로가 끊어져 있음

### 목표

- 모든 watch/lint glob 패턴에서 `.mjs`/`.cjs` 지원
- `.tsx`/`.jsx` 패턴 제거
- library-build, ngtsc-build worker에 replaceDeps watch 추가
- `createBuildEngine` → engine → worker 간 `replaceDeps` config 전달 경로 구축

### 비목표

- watch 아키텍처 변경 (기존 FsWatcher 기반 유지)
- tsconfig.json/package.json 변경 시 자동 재시작 (dev 서버 수동 재시작 필요)

### 설계

`replaceDeps` config 전달 경로:

```
DevWatchOrchestrator (sdConfig.replaceDeps)
  → createBuildEngine(pkg, { cwd, replaceDeps, ... })
    → Engine constructor (this._replaceDeps)
      → Engine.startWatch() → worker.startWatch({ replaceDeps })
        → worker: collectDeps(pkgDir, cwd, replaceDeps)
          → watch dist/**/*.{js,mjs,cjs}
```

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| `createBuildEngine` options에 replaceDeps 추가 | 채택 | 모든 engine이 동일 경로로 전달, SdConfig 루트 레벨 설정에 적합 |
| `BuildEngine.startWatch(output, replaceDeps)` 파라미터 추가 | 미채택 | `BuildEngine` 인터페이스 변경 필요, output과 관심사 다름 |
| per-package config에 replaceDeps 추가 | 미채택 | replaceDeps는 워크스페이스 전역 설정이므로 부적합 |
