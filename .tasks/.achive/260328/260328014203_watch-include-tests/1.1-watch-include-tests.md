# Feature 1.1 watch 명령어 tests 패키지 포함

## 참조 자료

### 현재 동작
- `check` 명령어: `discoverWorkspacePackages()`로 `packages/` + `tests/` 모두 탐색
- `watch` 명령어: `sd.config.ts`의 `packages`만 사용, 경로를 `path.join(cwd, "packages", name)`으로 하드코딩
- `dev` 명령어: `watch`와 동일한 `DevWatchOrchestrator` 사용

### 관련 파일
- `packages/sd-cli/src/orchestrators/DevWatchOrchestrator.ts` — watch/dev 통합 오케스트레이터
- `packages/sd-cli/src/utils/package-utils.ts` — `discoverWorkspacePackages()`, `filterPackagesByTargets()`
- `packages/sd-cli/src/commands/watch.ts` — watch 진입점
- `packages/sd-cli/src/commands/check.ts` — check 진입점 (참고용)
- `sd.config.ts` — 패키지 빌드 설정

### tests 패키지 특성
- `tests/orm`, `tests/service` 존재
- tsconfig: `"lib": ["ESNext"]`, `"typeRoots": ["./node_modules/@types"]`
- `@angular/core` 의존 없음 → TscEngine 사용
- target `"node"`로 처리 가능 (tsconfig 그대로 유효)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | 이름 충돌 처리 | 에러로 중단 | discoverWorkspacePackages와 동일한 정책, 모호한 상황 방지 |

## 구현계획

### 배경

`DevWatchOrchestrator`는 `sd.config.ts`의 `packages` 필드만 사용하여 watch/dev 대상을 결정한다. 경로도 `path.join(cwd, "packages", name)`으로 하드코딩되어 있어 `tests/` 디렉토리의 패키지를 처리할 수 없다. 반면 `check` 명령어는 `discoverWorkspacePackages()`로 `packages/`와 `tests/`를 모두 탐색한다.

### 목표

- watch 모드에서 `tests/` 패키지를 자동 탐색하여 빌드 대상에 포함
- sd.config.ts 패키지와 tests 패키지의 이름 충돌 시 에러로 중단
- 기존 packages/ 패키지의 동작은 변경 없음

### 비목표

- dev 모드에서 tests 패키지 지원 (tests에는 server/client target이 없으므로 불필요)
- tests 패키지를 sd.config.ts에 수동 등록하는 방식

### 설계

#### 패키지 탐색 및 병합

`DevWatchOrchestrator.initialize()`에서 config 로드 후, `discoverWorkspacePackages()`로 tests 패키지를 탐색하여 config packages에 병합한다.

- tests 패키지는 `{ target: "node" }` 설정으로 자동 생성
- 이름 충돌 시 `SdError` throw

#### 경로 해석 개선

`_classifyWatchPackages`와 `_classifyDevPackages`에서 하드코딩된 `"packages"` 경로 대신, 패키지별 실제 경로(packages/ 또는 tests/)를 사용한다.

- `discoverWorkspacePackages()`의 반환값 `Map<이름, 상대경로>`를 활용
- sd.config.ts 패키지는 기본적으로 `packages/{name}` 경로

#### target 검증 및 validateTargets

`validateTargets()`에 tests 패키지도 포함된 통합 패키지 맵을 전달하여, `pnpm watch orm` 같은 tests 패키지 지정이 유효하도록 한다.

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| DevWatchOrchestrator에서 tests 자동 탐색 | 채택 | check와 동일한 패턴, sd.config.ts 수정 불필요 |
| sd.config.ts에 tests 패키지 수동 등록 | 미채택 | 매번 수동 등록 필요, check와 일관성 없음 |
| package-utils에 새 함수 추가 | 미채택 | discoverWorkspacePackages로 충분 |
