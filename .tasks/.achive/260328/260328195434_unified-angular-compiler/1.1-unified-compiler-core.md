| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | `host.resourceNameToFileName` 구현 여부 | 구현 포함 | AotCompilation과 동일한 완전한 호스트 구현. 외부 스타일시트 경로 해석 + SHA256 ID 부여 지원 |

## 구현계획

### 배경

현재 Angular 빌드는 두 경로로 분리되어 있다:
- **library**: `ngtsc-build-core.ts` — NgtscProgram 직접 사용, standalone 함수. BuilderProgram/SourceFileCache/diagnosticCache 없음
- **client**: `angular-facade.ts` — `@angular/build/private`의 `createAngularCompilation` (AotCompilation) 사용. `#state` private으로 ts.Program 접근 불가

library에는 incremental 최적화가 없고, client에서는 ts.Program을 외부에서 접근할 수 없어 lint 통합이 불가능하다.

### 목표

- NgtscProgram + BuilderProgram 기반 통합 컴파일러 모듈 (`AngularCompiler` class)
- incremental 최적화: affected 파일만 진단, Angular 템플릿 진단 WeakMap 캐싱
- `getTsProgram()` 외부 노출 (Feature 3.x lint 통합의 핵심)
- library/client 양쪽에서 사용 가능한 커스터마이징 옵션 (transformStylesheet, compilerOptionsTransformer, declaration 등)

### 비목표

- emit 기능 (Feature 1.2에서 구현)
- HMR 지원 (Feature 1.3에서 구현)
- `update(modifiedFiles)` 메서드 (Feature 1.2에서 구현)
- NgtscEngine/ViteEngine 마이그레이션 (Feature 2.1, 2.2에서 구현)

### 설계

#### 파일 위치

`packages/sd-cli/src/utils/angular-compiler.ts` — `ngtsc-build-core.ts`와 동일 레벨

#### AngularSourceFileCache class

`Map<string, ts.SourceFile>`를 확장하는 독립 캐시 클래스. `@angular/build/private`의 SourceFileCache를 대체한다.

```typescript
class AngularSourceFileCache extends Map<string, ts.SourceFile> {
  readonly modifiedFiles = new Set<string>();

  invalidate(files: Iterable<string>): void;
  // - Map에서 삭제 (normalize 후)
  // - modifiedFiles에 추가
  // Windows 경로 정규화: backslash → forward slash (TypeScript host 경로와 일치)
}
```

호스트 캐싱 통합은 standalone 함수로 분리:

```typescript
function augmentHostWithCaching(
  host: ts.CompilerHost,
  cache: AngularSourceFileCache,
): void;
// - host.getSourceFile 래핑
// - shouldCreateNewSourceFile=false이면 캐시 반환
// - miss 시 원본 호출 → 캐시 저장
```

#### AngularCompilerOptions interface

```typescript
interface AngularCompilerOptions {
  rootNames: string[];
  compilerOptions: ts.CompilerOptions;
  angularCompilerOptions?: Record<string, unknown>;
  sourceFileCache?: AngularSourceFileCache;
  transformStylesheet?: (
    data: string,
    containingFile: string,
    stylesheetFile?: string,
  ) => Promise<string | null>;
  compilerOptionsTransformer?: (options: ts.CompilerOptions) => ts.CompilerOptions;
  externalStylesheets?: Map<string, string>;  // client only — resourceNameToFileName에서 SHA256 ID 매핑

```

#### AngularCompiler class

```typescript
class AngularCompiler {
  // ── 설정 (불변) ──
  private readonly _options: AngularCompilerOptions;

  // ── 컴파일 상태 (initialize마다 재생성) ──
  private _ngtscProgram?: NgtscProgram;
  private _builderProgram?: ts.EmitAndSemanticDiagnosticsBuilderProgram;
  private _host?: ts.CompilerHost;
  private _affectedFiles = new Set<ts.SourceFile>();

  // ── 영속 상태 (initialize 간 재사용) ──
  private _diagnosticCache = new WeakMap<ts.SourceFile, ts.Diagnostic[]>();
  private _packageJsonCache?: ts.PackageJsonInfoCache;

  constructor(options: AngularCompilerOptions);

  async initialize(): Promise<{ affectedFiles: ReadonlySet<ts.SourceFile> }>;
  *collectDiagnostics(): Iterable<ts.Diagnostic>;
  getTsProgram(): ts.Program;

  // Feature 1.2에서 사용할 접근자
  get ngtscProgram(): NgtscProgram | undefined;
  get compiler(): NgCompiler;  // ngtscProgram.compiler shortcut
}
```

#### initialize() 흐름

```
1. packageJsonCache 관리
   - sourceFileCache.modifiedFiles에 node_modules 파일 포함 시 → clear
   - 없으면 이전 _packageJsonCache 재사용
2. compilerOptionsTransformer 적용
   - 제공 시 compilerOptions를 변환
3. ts.createIncrementalCompilerHost(compilerOptions) 생성
4. Angular 호스트 확장 설정
   - host.readResource = readFile ?? ""
   - host.transformResource = options.transformStylesheet 래핑
   - host.getModifiedResourceFiles = () → sourceFileCache?.modifiedFiles
   - host.resourceNameToFileName = path 해석 + template/stylesheet 분기 + SHA256 ID (D1)
5. 모듈 해석 캐시 생성
   - ts.createModuleResolutionCache(cwd, canonicalize, options, packageJsonCache)
   - host.getModuleResolutionCache = () → cache
6. SourceFileCache 통합
   - sourceFileCache 제공 시 augmentHostWithCaching(host, cache) 호출
7. NgtscProgram 생성
   - new NgtscProgram(rootNames, mergedOptions, host, oldProgram=this._ngtscProgram)
8. ensureSourceFileVersions
   - program.getSourceFiles() 래핑, version 없는 파일에 SHA256 해시 설정
9. BuilderProgram 생성
   - ts.createEmitAndSemanticDiagnosticsBuilderProgram(tsProgram, host, oldBuilder=this._builderProgram)
10. compiler.analyzeAsync()
11. findAffectedFiles
    - getSemanticDiagnosticsOfNextAffectedFile() 루프
    - .ngtypecheck.ts → 원본 .ts 매핑
12. 리소스 의존성 기반 diagnosticCache 무효화
    - compiler.getResourceDependencies(sf) → 리소스 변경 여부 확인
    - 변경 시 diagnosticCache에서 해당 sf 삭제 + affectedFiles에 추가
13. 상태 저장 (다음 initialize에서 재사용)
```

#### collectDiagnostics() 흐름

Generator 함수로 진단을 lazy yield:

```
1. Option 진단: configFileParsingDiagnostics + compiler.getOptionDiagnostics + tsProgram.getOptionsDiagnostics
2. Syntactic: globalDiagnostics + 파일별 syntacticDiagnostics
3. 파일별 루프 (ignoreForDiagnostics 제외):
   a. semanticDiagnostics
   b. Angular 템플릿 진단:
      - affectedFiles에 포함 → getDiagnosticsForFile(sf, optimization) → cache.set
      - affectedFiles에 미포함 → cache.get (캐시 반환)
      - optimization: affectedFiles.size === 1 ? SingleFile : WholeProgram
```

#### resourceNameToFileName 구현

```
1. path.join(dirname(containingFile), resourceName) → resolvedPath
2. fileExists(resolvedPath) 확인 → 없으면 null
3. template 확장자 (.htm, .html, .svg) → resolvedPath 그대로 반환
4. stylesheet → externalStylesheets 옵션 확인:
   - externalStylesheets 미제공 (library) → resolvedPath 그대로 반환
   - externalStylesheets 제공 (client) → SHA256 hash ID + '.css' 반환, 매핑 저장
```

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| AotCompilation 내부를 래핑 (Facade 패턴) | 미채택 | #state private으로 ts.Program 접근 불가. getTsProgram() 노출이 핵심 목표 |
| standalone 함수 (현재 ngtsc-build-core 패턴) | 미채택 | 영속 상태(diagnosticCache, packageJsonCache, SourceFileCache) 관리가 어려움 |
| class + 내부 상태 관리 | **채택** | 영속 상태를 인스턴스 필드로 관리, incremental 재사용 자연스러움 |
| SourceFileCache를 @angular/build/private에서 유지 | 미채택 | esbuild 전용 필드 불필요, 의존성 제거 목표 (D4) |
