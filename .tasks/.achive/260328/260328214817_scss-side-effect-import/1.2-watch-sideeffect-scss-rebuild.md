## 요구명세

Feature: 1.2 Watch 모드에서 side-effect SCSS 변경 감지 및 incremental 재빌드

  Background:
    Given NgtscEngine watch 모드로 Angular 라이브러리를 감시 중이다
    And src/ui/layout/sd-flex.directive.ts에 `import "./sd-flex.scss"` side-effect import가 있다
    And 초기 빌드가 완료되어 dist/ui/layout/sd-flex.css가 존재한다

  Rule: Side-effect SCSS 파일 변경 시 dist CSS가 재컴파일되어 갱신된다

    Scenario: side-effect SCSS 파일 내용 변경
      Given sd-flex.scss에 `display: flex`가 있다
      And sd-flex.directive.ts는 변경되지 않았다
      When sd-flex.scss에서 `display: flex`를 `display: inline-flex`로 변경한다
      Then dist/ui/layout/sd-flex.css에 `display: inline-flex`가 포함된다

    Scenario: 여러 side-effect SCSS 파일 동시 변경
      Given sd-card.directive.ts에도 `import "./sd-card.scss"` side-effect import가 있다
      And 초기 빌드가 완료되어 dist/ui/layout/sd-card.css가 존재한다
      When sd-flex.scss와 sd-card.scss를 동시에 변경한다
      Then dist/ui/layout/sd-flex.css와 dist/ui/layout/sd-card.css가 모두 갱신된다

  Rule: Side-effect SCSS의 transitive 의존성 변경 시에도 dist CSS가 갱신된다

    Scenario: @use 의존성 파일 변경
      Given sd-flex.scss가 `@use "commons/variables"` 를 사용한다
      And commons/_variables.scss에 `$gap: 8px`가 있다
      When commons/_variables.scss에서 `$gap: 8px`를 `$gap: 16px`로 변경한다
      Then dist/ui/layout/sd-flex.css에 갱신된 gap 값이 반영된다

    Scenario: 간접 의존성 변경
      Given sd-flex.scss가 `@use "mixins"` 를 사용한다
      And mixins 파일이 `@use "variables"` 를 사용한다
      When variables 파일을 변경한다
      Then dist/ui/layout/sd-flex.css에 변경이 반영된다

  Rule: Side-effect SCSS 의존성 추적은 연속적인 watch 재빌드에서도 유지된다

    Scenario: 연속 SCSS 변경
      Given sd-flex.scss를 변경하여 재빌드가 완료되었다
      When sd-flex.scss를 다시 변경한다
      Then dist/ui/layout/sd-flex.css가 다시 갱신된다

    Scenario: SCSS에 새 @use 추가 후 해당 의존성 변경
      Given sd-flex.scss에 새로운 `@use "commons/colors"` 를 추가하여 재빌드가 완료되었다
      When commons/_colors.scss를 변경한다
      Then dist/ui/layout/sd-flex.css에 변경이 반영된다

  Rule: Watch 재빌드 중 side-effect SCSS 컴파일 에러가 빌드 결과에 포함된다

    Scenario: SCSS 문법 에러
      When sd-flex.scss에 문법 에러를 도입한다
      Then 재빌드 결과에 SCSS 에러가 포함된다
      And dist/ui/layout/sd-flex.css는 이전 정상 상태를 유지한다

    Scenario: 에러 수정 후 정상 재빌드
      Given sd-flex.scss에 문법 에러가 있어 이전 재빌드가 에러를 보고했다
      When sd-flex.scss의 문법 에러를 수정한다
      Then 재빌드가 성공하고 dist/ui/layout/sd-flex.css가 정상 갱신된다
      And 후속 SCSS 변경도 정상 감지된다

## 구현계획

### 배경

NgtscEngine watch 모드에서 파일 변경 시 incremental rebuild를 수행한다. `@Component` 스타일의 SCSS는 `createLibraryTransformStylesheet` + `scssDependencies` reverse-lookup으로 정상 추적되지만, Feature 1.1에서 추가된 side-effect SCSS import(`import "./x.scss"`)는 `writeEmitResults` 내에서만 처리된다.

문제: TypeScript builder는 TS 파일의 content hash(version)를 비교하여 affected 여부를 판단한다. SCSS만 변경되고 TS 내용이 동일하면 builder가 TS 파일을 재emit하지 않아 `writeEmitResults`가 실행되지 않고, dist CSS가 갱신되지 않는다. 추가로 `scssDependencies`가 매 onChange마다 `.clear()`되고 미emit 파일의 deps가 재수집되지 않아, 후속 변경의 reverse-lookup도 실패한다(복합 문제).

### 목표

- SCSS 파일(직접 또는 transitive 의존성) 변경 시 dist CSS가 항상 갱신
- `scssDependencies`가 rebuild cycle 간 유지되어 연속 변경 감지 가능
- SCSS 컴파일 에러 시 빌드 결과에 포함, 기존 CSS 보존

### 비목표

- Client dev HMR (Feature 1.3)
- SCSS 파일 이동/directive 전환 (Feature 2.1)
- FsWatcher 감시 경로 변경 (이미 `src/**/*.scss` 포함)

### 설계

#### `SideEffectScssEntry` 타입 + `SideEffectScssOptions` 확장 (`ngtsc-build-core.ts`)

```typescript
export interface SideEffectScssEntry {
  scssAbsPath: string;    // 소스 SCSS 파일 절대 경로
  cssAbsPath: string;     // dist CSS 출력 절대 경로
  sourceFileName: string; // import하는 TS 파일 절대 경로 (trackDeps 키)
}
```

`SideEffectScssOptions`에 `registry` 필드 추가:

```typescript
export interface SideEffectScssOptions {
  loadPaths: string[];
  scssErrors: string[];
  scssDependencies: Map<string, Set<string>>;
  registry?: Map<string, SideEffectScssEntry>; // NEW: persistent across rebuilds
}
```

#### `writeEmitResults` 확장

registry 제공 시, 각 emit된 JS 파일 처리 과정에서:

1. 해당 `sourceFileName`의 기존 registry 항목을 제거 (import 삭제 시 stale entry 정리)
2. side-effect SCSS import 발견 시 registry에 등록

#### `compileSideEffectScss` 함수 (NEW)

`compileGlobalScss`와 동일한 패턴. 모든 registry 항목을 순회하며:

1. `compileScssFile(entry.scssAbsPath, loadPaths)` → CSS + dependencies
2. CSS를 `entry.cssAbsPath`에 출력
3. `trackDeps(scssDependencies, entry.sourceFileName, result.dependencies)` — reverse-lookup용 의존성 기록
4. 에러 시 `scssErrors`에 추가 (기존 CSS 파일 보존)

```typescript
export function compileSideEffectScss(
  registry: ReadonlyMap<string, SideEffectScssEntry>,
  loadPaths: string[],
  scssErrors: string[],
  scssDependencies: Map<string, Set<string>>,
): void
```

#### Worker 통합 (`ngtsc-build.worker.ts`)

Worker에 persistent state 추가 (onChange마다 clear하지 않음):

```typescript
const sideEffectScssRegistry = new Map<string, SideEffectScssEntry>();
```

`performWatchBuild`에서 `writeEmitResults` 후 `compileSideEffectScss` 호출:

```typescript
writeEmitResults(emitResults, info.pkgDir, {
  loadPaths, scssErrors, scssDependencies,
  registry: sideEffectScssRegistry,
});
compileSideEffectScss(sideEffectScssRegistry, loadPaths, scssErrors, scssDependencies);
```

`runNgtscBuild`(one-time build)에서는 registry를 전달하지 않음 — `writeEmitResults`가 모든 emit 파일을 처리하므로 불필요.
