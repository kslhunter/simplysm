    And 라이브러리 dist에 side-effect CSS를 import하는 JS 파일이 있다

      Then Vite HMR이 트리거되어 CSS가 갱신된다

  Rule: Side-effect import된 CSS에 PostCSS가 적용된다

    Scenario: css.postcss 설정의 PostCSS 플러그인이 side-effect CSS에 적용된다
      Given css.postcss에 테스트용 PostCSS 플러그인이 설정되어 있다
      And 라이브러리 dist에 side-effect CSS 파일이 있다
      When Client가 해당 CSS를 요청한다
      Then PostCSS 플러그인이 적용된 결과가 반환된다

  Rule: sdAngularPlugin handleHotUpdate가 CSS HMR을 방해하지 않는다

    Scenario: CSS 파일 변경 시 sdAngularPlugin이 Vite default HMR에 위임한다
      Given sdAngularPlugin이 dev 모드로 동작 중이다
      When .css 파일에 대해 handleHotUpdate가 호출된다
      Then sdAngularPlugin은 undefined를 반환한다
      And Vite의 기본 CSS HMR이 동작한다

    Scenario: CSS 변경이 불필요한 Angular recompilation을 트리거하지 않는다
      Given sdAngularPlugin이 dev 모드로 동작 중이다

      Then Angular compiler의 update가 호출되지 않는다

## 구현계획

### 배경

Feature 1.1에서 NgtscEngine 빌드 시 side-effect SCSS → CSS 컴파일 + dist 출력이 구현되었고, Feature 1.2에서 watch 모드 재컴파일이 구현되었다. Client dev 모드(Vite dev server)에서 이 dist CSS가 정상 동작하는지 — HMR 갱신과 PostCSS 적용 — 검증이 필요하다.

현재 코드 분석:
- `sdAngularPlugin.handleHotUpdate` (vite-angular-plugin.ts:211-219): `.css` 파일에 대해 early return (`undefined`) → Vite default CSS HMR에 위임
- `css.postcss` (vite-config.ts:136-139): PostCSS 플러그인이 설정되면 외부 CSS 파일에 적용
- `sdScopeWatchPlugin` (vite-scope-watch-plugin.ts:56-59): dist/ 변경 → Vite watcher에 `change` 이벤트 전파

코드상으로는 문제없어 보이나, 런타임 검증 없이는 확신할 수 없다.

### 목표

- Vite dev server에서 side-effect CSS의 HMR 동작을 통합 테스트로 검증
- PostCSS 적용을 통합 테스트로 검증
- `handleHotUpdate` CSS 호환성을 유닛 테스트로 검증
- 검증 중 발견된 문제가 있으면 수정

### 비목표

- Vite 내부 CSS 파이프라인 자체 테스트 (Vite 책임)
- 실제 Angular 앱 E2E (dev 서버로 돌릴 클라이언트 코드 없음)
- SCSS 파일 이동/directive 전환 (Feature 2.1)

### 설계

#### handleHotUpdate CSS 호환성 유닛 테스트

기존 `vite-angular-plugin-hmr-fallback.spec.ts` 패턴 활용. `.css` 파일 경로로 `handleHotUpdate`를 직접 호출하여:
- `undefined` 반환 확인 (Vite default HMR에 위임)
- Angular compiler `update`가 호출되지 않는 것 확인

#### Vite CSS 통합 테스트 (`tests/vite-css-hmr/`)

기존 `tests/service` 패턴 활용. Vite `createServer`로 dev server를 프로그래밍적으로 구동하여 검증.

**Fixture 구조** (라이브러리 dist를 시뮬레이션):
```
tests/vite-css-hmr/
  fixture/
    lib-dist/
      index.js         # import "./style.css"; export const x = 1;
      style.css        # .sd-flex { display: flex; }
    main.js            # import "./lib-dist/index.js";
  src/
    vite-css-hmr.spec.ts
  package.json
  vitest.setup.ts      # globalSetup: Vite createServer 구동/종료
```

**테스트 PostCSS 플러그인**: CSS에 마커 주석(`/* postcss-applied */`)을 삽입하는 단순 플러그인. 적용 여부를 문자열 검색으로 확인.

**테스트 항목**:
1. `transformRequest`로 CSS를 요청하여 PostCSS 플러그인 적용 확인
2. CSS 파일 수정 → Vite module graph에서 해당 모듈 무효화 확인 (HMR 전제조건)
3. `server.hot.send` 호출 감시로 실제 HMR 메시지 전송 확인

**vitest.config.ts 변경**: `tests/vite-css-hmr` project 추가 (node 환경).
