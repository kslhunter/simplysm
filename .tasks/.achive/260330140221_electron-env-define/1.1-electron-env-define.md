# Feature 1.1 Electron 빌드 env를 esbuild define 패턴으로 전환

## 참조 자료

### 현재 문제

- `electron.ts`의 `run`/`_bundleMainProcess` 메서드가 esbuild를 사용하면서 `define` 옵션을 사용하지 않음
- `NODE_ENV`, `ELECTRON_DEV_URL`, `config.env`를 런타임 환경변수(`execa env`)로 전달
- sd-cli의 다른 빌더(서버: `esbuild-config.ts`, 클라이언트: `vite-config.ts`)는 esbuild/vite `define`으로 빌드 시점 상수화하는 패턴을 사용

### 기존 패턴 (서버 빌더)

- `esbuild-config.ts:75` — `define[process.env.${key}] = JSON.stringify(value)`
- `vite-config.ts:87` — `define["process.env"] = JSON.stringify(options.env)`

### 구조

- Electron 빌드 = Angular 빌드(ViteEngine, 이미 define 사용) + electron-main 빌드(Electron 클래스, define 미사용)
- electron-main 빌드만 기존 패턴과 불일치

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | env 주입 방식 | esbuild define | 기존 서버/클라이언트 빌더 패턴과 일관성 |
| D2 | NODE_ENV 하드코딩 | 제거 | ELECTRON_DEV_URL 유무로 dev/prod 판별 충분 |
| D3 | 프로덕션 빌드에서 ELECTRON_DEV_URL | 미포함 | dead code elimination 활용 |

## 구현계획

### 배경

sd-cli의 Electron 클래스는 `electron-main.ts`를 esbuild로 번들링한다. 서버 빌더(`esbuild-config.ts:69-75`)는 `define[process.env.${key}] = JSON.stringify(value)` 패턴으로 env를 빌드 시점 상수화하지만, Electron은 `execa env`로 런타임 전달하고 있어 패턴이 불일치한다.

### 목표

- Electron esbuild 번들링에 `define` 옵션 추가 (기존 서버 빌더 패턴 따르기)
- `NODE_ENV` 하드코딩 제거
- `runEnv`/`execa env` 전달 제거

### 비목표

- 소비 프로젝트의 `electron-main.ts` 코드 수정
- Angular 빌드(ViteEngine) 수정 (이미 define 사용 중)
- `createServerEsbuildOptions` 함수 재사용 (서버 전용 옵션 포함이라 부적합)

### 설계

`run` 메서드 변경:
- `runEnv` 객체 제거
- `ELECTRON_DEV_URL: url` + `this._config.env`를 esbuild define으로 주입
- `spawnElectron`에서 `env` 옵션 제거 (기본 `process.env` 상속)

`_bundleMainProcess` 변경:
- `this._config.env`만 esbuild define으로 주입
- `ELECTRON_DEV_URL`은 포함하지 않음 → 프로덕션에서 dead code elimination

define 생성 패턴 (서버 빌더와 동일):
```ts
const define: Record<string, string> = {};
for (const [key, value] of Object.entries(envEntries)) {
  define[`process.env.${key}`] = JSON.stringify(value);
}
```

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| esbuild define (서버 빌더 패턴) | 채택 | 기존 패턴과 일관, dead code elimination |
| `createServerEsbuildOptions` 재사용 | 미채택 | 서버 전용 옵션(format: esm, outdir 등) 포함 |
