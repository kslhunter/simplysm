## 구현계획

### 배경

`createClientViteConfig()`은 항상 `sdAngularPlugin()`을 사용한다. Angular 외에 Solid 프레임워크를 선택할 수 있도록 `SdClientPackageConfig`에 `framework` 옵션을 추가하고, `createClientViteConfig()`에서 조건부로 플러그인을 분기한다.

### 목표

- `SdClientPackageConfig`에 `framework?: "angular" | "solid"` 필드 추가
- `createClientViteConfig()`에서 framework에 따라 `sdAngularPlugin` / `solidPlugin` 분기
- 기존 Angular 빌드에 영향 없이 Solid 빌드 지원

### 비목표

- 라이브러리 패키지(target: "node"/"browser"/"neutral")의 Solid JSX 지원
- Solid UI 컴포넌트 라이브러리 빌드 지원

### 설계

#### 타입 변경

```typescript
// sd-config.types.ts
interface SdClientPackageConfig {
  target: "client";
  framework?: "angular" | "solid";  // 추가. 기본값 "angular"
  // ... 기존 필드 유지
}
```

#### 플러그인 분기

```typescript
// vite-config.ts — createClientViteConfig()
if (options.framework === "solid") {
  plugins.push(solidPlugin());
} else {
  plugins.push(sdAngularPlugin({ ... }));
  // sdPostCssInlinePlugin도 Angular일 때만 적용
}
```

#### 데이터 흐름

```
sd.config.ts (framework)
  → SdClientPackageConfig.framework
  → ViteEngine → pkg.config.framework
  → client.worker.ts → ClientBuildInfo.framework
  → createClientViteConfig() → options.framework
  → 조건부 플러그인 선택
```

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| SdClientPackageConfig에 optional field | 채택 | 기존 config 하위 호환, 단순 |
| 별도 타입 SdClientSolidPackageConfig | 미채택 | discriminated union 분리 시 불필요한 복잡도 |
| 새 target "client-solid" | 미채택 | 같은 ViteEngine 사용, target 분리 불필요 |
