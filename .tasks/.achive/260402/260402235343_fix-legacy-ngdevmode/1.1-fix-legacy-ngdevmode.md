# Feature 1.1 legacyModule dev 모드 ngDevMode 수정

## 참조 자료

### 버그 현상

- `legacyModule: true` + `pnpm dev` 실행 시 `ngDevMode`가 `"false"`로 define되어 프로덕션 모드로 동작
- 소비 프로젝트(`oscom/packages/client-pda`)의 `main.ts`에서 "PROD" 로그 출력 확인

### 근본 원인

- `client.worker.ts`의 `startLegacyWatch`가 `mode: "build"`로 `createClientViteConfig` 호출
- `vite-config.ts`에서 `dev: options.mode === "dev"`로 판단 → `mode: "build"` → `dev: false`
- `vite-angular-plugin.ts`에서 `ngDevMode: options.dev ? undefined : "false"` → `"false"`

### 관련 파일

- `packages/sd-cli/src/utils/vite-config.ts` — `createClientViteConfig` 함수, `mode` 분기 7곳
- `packages/sd-cli/src/workers/client.worker.ts` — `startLegacyWatch`, `startWatch`, `build` 함수
- `packages/sd-cli/src/angular/vite-angular-plugin.ts` — `ngDevMode` define
- `packages/sd-cli/tests/utils/vite-config.spec.ts` — vite config 테스트
- `packages/sd-cli/tests/workers/client-worker.spec.ts` — client worker 테스트

### mode 사용처 전수 조사 (vite-config.ts)

| Line | 용도 | 조건 | legacyModule dev 영향 |
|------|------|------|----------------------|
| 105 | Angular plugin dev | `mode === "dev"` | **핵심 수정**: dev: true로 변경 |
| 106 | sourcemap | `mode === "dev" \|\| watch === true` | 영향 없음 (watch: true) |
| 124 | replaceDeps HMR | `mode === "dev" \|\| watch === true` | 영향 없음 (watch: true) |
| 139 | server config | `mode === "dev"` | 불필요한 config 생성, viteBuild가 무시 → 무해 |
| 181 | PWA | `mode === "build" && pwa !== false` | 영향 없음 (pwa: false) |
| 301 | build output | `mode === "build"` → `mode === "build" \|\| legacyModule === true` | **수정 필요**: legacyModule 조건 추가 |

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | mode의 의미 | 환경(dev/build) | 사용자 지시: "mode는 환경을 의미해야지" |
| D2 | line 139 server config | 수정하지 않음 | viteBuild가 server config을 무시하므로 기능적 영향 없음. 불필요한 조건 추가는 복잡도만 증가 |
| D3 | build output 조건 | `mode === "build" \|\| legacyModule === true` | legacyModule dev도 viteBuild 사용하므로 build output 설정 필요 |

## 구현계획

### 배경

`createClientViteConfig`의 `mode` 파라미터가 "환경(dev/build)"과 "빌드 방식(createServer/viteBuild)"을 동시에 의미하고 있어, `legacyModule: true` dev 모드에서 viteBuild를 사용하면서 `mode: "build"`를 전달해야 했다. 이로 인해 `sdAngularPlugin`에 `dev: false`가 전달되어 `ngDevMode: "false"`가 define된다.

### 목표

- `mode`를 환경(dev/build) 의미로 일관되게 사용
- `legacyModule` dev 모드에서 `ngDevMode`가 undefined(Angular dev mode 활성화)
- 기존 동작(프로덕션 빌드, 일반 dev 모드) 무변경

### 비목표

- `vite-config.ts:139` server config 조건 변경 (viteBuild가 무시하므로 기능적 영향 없음)
- `vite-config.ts` 내부 `mode` 전체 리팩토링

### 설계

수정 2곳, 테스트 업데이트 2곳:

1. **`client.worker.ts:278`** — `startLegacyWatch`에서 `mode: "build"` → `mode: "dev"`
2. **`vite-config.ts:301`** — build output 조건: `mode === "build"` → `mode === "build" || legacyModule === true`
3. **`client-worker.spec.ts:231`** — 기대값 `mode: "build"` → `mode: "dev"`
4. **`vite-config.spec.ts`** — `mode: "dev" + legacyModule: true + watch: true` 조합 테스트 추가

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| `mode`를 환경 의미로 변경 + `legacyModule`로 build output 분기 | **채택** | `mode`의 의미가 명확해지고, 최소 수정 |
| 별도 `dev` boolean 옵션 추가 | 미채택 | `mode`와 `dev`가 중복된 의미를 가져 혼란 유발 |
| `mode`를 3개로 확장 (`"dev" \| "build" \| "dev-legacy"`) | 미채택 | 타입 확장으로 기존 호출부 영향 범위 증가 |
