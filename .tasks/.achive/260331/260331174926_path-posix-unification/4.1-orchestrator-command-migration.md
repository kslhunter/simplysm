## 구현계획

### 배경

sd-cli의 경로 처리를 POSIX 슬래시(`/`)로 통일하는 마이그레이션의 일환이다. 엔진(Feature 2.x), FsWatcher(Feature 1.2), Capacitor/Electron(Feature 5.1)은 이미 `posixResolve()`/`posix()`로 마이그레이션 완료되었다. 오케스트레이터와 명령어가 이들에게 경로를 전달할 때 `path.join()`/`path.resolve()`를 사용하고 있어, Windows에서 백슬래시 경로가 전달될 수 있다.

### 목표

- DevWatchOrchestrator, BuildOrchestrator의 `path.join()`/`path.resolve()` → `posixResolve()` 전환
- typecheck 명령어의 `path.join()` → `posixResolve()` 전환
- 불필요해진 `import path from "path"` 제거 및 `pathx` import 추가

### 비목표

- publish, lint, sd-cli-entry의 시스템 경로 마이그레이션 (설계 결정 D1)
- package-utils.ts 마이그레이션 (Feature 4.2 범위)
- `PackageInfo.dir`의 타입을 `PosixPath`로 변경 (타입 변경은 모든 Feature 완료 후 일괄 적용 가능)

### 설계

각 파일에서 `path.join()`/`path.resolve()`를 `posixResolve()`로 기계적 치환한다. `posixResolve`는 `path.resolve`와 동일하게 가변 인자를 받아 절대 경로를 반환하므로, `path.join`을 `posixResolve`로 대체하면 상대 경로가 절대 경로로 변환되는 차이가 있으나, 모든 사용처에서 첫 인자가 `this._cwd`(절대 경로)이므로 결과는 동일하다.

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| `posixResolve()`로 치환 | 채택 | 기존 마이그레이션 패턴과 동일, 일관성 유지 |
| `posix(path.join(...))`으로 감싸기 | 미채택 | 이중 호출 불필요, `posixResolve`가 한 번에 처리 |
