# Feature 3.1 library/server 빌드 워커 마이그레이션

## 참조 자료

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | server-build의 generateProductionFiles/parseLockfileVersions 내 path.join 마이그레이션 여부 | 범위 외 (변경 안 함) | 순수 fs I/O 경로로 비교/매칭에 관여하지 않음. Node.js fs API가 양쪽 구분자 처리. Feature 2.1도 동일 판단 |

| D3 | library-build.worker.ts에서 import path 제거 여부 | 제거 | 마이그레이션 후 path.* 사용처 없음 |

## 구현계획

### 배경

sd-cli의 library-build.worker.ts와 server-build.worker.ts에서 경로 처리 시 `path.join`과 ad-hoc `.replace(/\\/g, "/")` 패턴이 사용되고 있다. Feature 1.1에서 core-node에 `posix()`와 `posixResolve()`가 도입되었으므로, 이 워커 파일들의 경로 처리를 통일한다.

특히 library-build.worker.ts의 `extractSourceFilePaths` 함수는 WBS에 기록된 원래 버그(watch 리빌드 경로 비교 실패)의 수정 지점이다.

### 목표

- library-build.worker.ts의 ad-hoc `.replace(/\\/g, "/")` 패턴을 `pathx.posix()`로 대체
- 양 파일의 watch glob 경로 구성을 `pathx.posixResolve()`로 통일
- server-build.worker.ts의 `mainJsPath` 반환값을 `pathx.posixResolve()`로 통일

### 비목표

- server-build.worker.ts의 `generateProductionFiles`/`parseLockfileVersions` 내 순수 fs I/O `path.join` (D1)
- 인터페이스 타입 변경 (D2)
- Feature 3.2 대상 파일 (ngtsc-build.worker, client.worker)
- Feature 4.1 대상 파일 (오케스트레이터)

### 설계

각 파일의 변경은 기계적 패턴 치환이다.

| 파일 | 변경 패턴 | 건수 |
|------|-----------|------|
| `library-build.worker.ts` | `.replace(/\\/g, "/")` → `pathx.posix()`, `path.join` → `pathx.posixResolve()`, `import path` 제거 | 5+1 |
| `server-build.worker.ts` | `path.join` (watch/mainJsPath) → `pathx.posixResolve()` | 7 |

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| `pathx.posix()`/`pathx.posixResolve()` 네임스페이스 import | 채택 | 두 파일 모두 이미 `@simplysm/core-node`에서 import. server-build는 이미 pathx 보유 |
| 개별 `posix`/`posixResolve` named import | 미채택 | 기존 코드베이스 패턴(pathx 네임스페이스)과 불일치 |
