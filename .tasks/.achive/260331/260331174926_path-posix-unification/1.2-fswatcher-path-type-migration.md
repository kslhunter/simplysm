## 구현계획

### 배경

`packages/core-node/src/features/fs-watcher.ts`의 `FsWatcherChangeInfo.path`가 `NormPath` 타입을 사용하며, 내부에서 `norm()`으로 경로를 생성한다. `norm()`은 `path.resolve()`를 사용하여 플랫폼 네이티브 구분자(Windows: `\`)를 반환하므로, POSIX 슬래시 기반 경로와 비교 시 불일치가 발생한다. Feature 1.1에서 `PosixPath`, `posix()`, `posixResolve()`가 도입되었고, `NormPath`/`norm()`은 `@deprecated`로 표시되어 이 Feature에서 삭제 예정이다.

### 목표

- `FsWatcherChangeInfo.path` 타입을 `NormPath` → `PosixPath`로 변경
- FsWatcher 내부의 경로 정규화를 `posix()`로 통일 (ad-hoc `.replace(/\\/g, "/")` 포함)
- `path.ts`에서 `NormPath`, `NORM`, `norm()` 완전 삭제

### 비목표

- `extractGlobBase`의 `path.sep` 변경 (chokidar watch 경로용, 기능상 변경 불필요)
- FsWatcher 소비자(sd-cli workers) 코드 수정 (Feature 2.x~4.x 범위)

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| `norm()` → `posix()` (슬래시 변환만) | 채택 | chokidar는 절대 경로 watch 시 절대 경로 반환. 설계 결정 D1 |
| `norm()` → `posixResolve()` (절대 경로 보장) | 미채택 | 불필요한 `path.resolve()` 호출. chokidar가 이미 절대 경로 반환 |
| `NormPath`를 deprecation 유지하고 삭제 보류 | 미채택 | 유일한 소비자가 fs-watcher.ts이므로 즉시 삭제 가능 |
