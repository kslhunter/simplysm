## 구현계획

### 배경

`packages/core-node/src/utils/path.ts`에 `norm()`, `NormPath`, `posix()` 등의 경로 유틸리티가 정의되어 있다. Windows 환경에서 `norm()`은 `path.resolve()`를 사용하여 백슬래시 경로를 반환하므로, POSIX 슬래시 기반 경로와 비교 시 불일치가 발생한다 (원래 버그: `library-build.worker.ts`에서 watch 리빌드 스킵). 이를 `PosixPath` 타입과 `posixResolve()` 함수로 통일한다.

### 목표

- `PosixPath` 브랜드 타입 정의, `posix()` 반환 타입을 `PosixPath`로 변경, 단일 인자로 제한
- `posixResolve()` 함수 추가 (절대 경로 resolve + POSIX 슬래시)
- `norm()`, `NormPath`, `NORM` 심볼 삭제
- `isChildPath` 내부를 `posixResolve()` + `/` 구분자로 마이그레이션
- 기존 테스트를 새 API에 맞게 갱신

### 비목표

- `FsWatcherChangeInfo.path` 타입 변경 (Feature 1.2)
- sd-cli 및 기타 패키지의 `norm()`/`NormPath` 사용처 마이그레이션 (Feature 1.2~6.1)

### 설계

#### 타입 및 함수 시그니처

```typescript
const POSIX = Symbol("PosixPath");
type PosixPath = string & { [POSIX]: never };

function posix(p: string): PosixPath;           // p.replace(/\\/g, "/") as PosixPath
function posixResolve(...args: string[]): PosixPath;  // path.resolve(...args).replace(/\\/g, "/") as PosixPath
```

#### isChildPath 변경

```typescript
function isChildPath(childPath: string, parentPath: string): boolean {
  const normalizedChild = posixResolve(childPath);
  const normalizedParent = posixResolve(parentPath);
  if (normalizedChild === normalizedParent) return false;
  const parentWithSep = normalizedParent.endsWith("/") ? normalizedParent : normalizedParent + "/";
  return normalizedChild.startsWith(parentWithSep);
}
```

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| `posix()`를 다중 인자 유지하고 내부에서 `path.join` | 미채택 | 역할 혼재 (슬래시 변환 + 경로 결합). wbs.md에서 단일 인자로 변경 결정 |
| `NormPath`를 `PosixPath`로 rename만 수행 | 미채택 | `norm()`은 `path.resolve()`를 사용하여 플랫폼 경로를 반환. 의미가 다르므로 rename이 아닌 신규 타입 도입 |
