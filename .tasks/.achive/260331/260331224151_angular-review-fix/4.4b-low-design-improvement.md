| # | 결정사항 | 선택 | 근거 |

## 구현계획

### 배경

리뷰에서 발견된 3건의 Low severity 설계 이슈를 수정한다. 각 이슈는 독립적인 파일을 대상으로 하며 상호 의존성이 없다.

- DESIGN-005: `sd-dropdown-popup.control.ts`의 onResize에서 300px 하드코딩이 parent의 viewport 기반 maxHeight와 중복/충돌
- DESIGN-006: `useSheetColumnFixing.ts`에서 fixed column의 px 단위 필수 조건이 문서화되지 않음
- DESIGN-007: `sd-barcode.control.ts`에서 bwip-js SVG를 innerHTML로 직접 삽입하여 Angular sanitization 우회

### 목표

- 드롭다운 팝업 높이가 viewport 가용 공간에 자연스럽게 의존하도록 개선
- Fixed column의 px 단위 제약을 JSDoc으로 명시
- 바코드 SVG 렌더링을 Angular sanitization 파이프라인 내로 이동

### 비목표

- 드롭다운 높이의 새로운 UX 제한 도입 (CSS 변수 기반 최대 높이 등)
- non-px width의 런타임 계산 지원
- bwip-js 외 다른 바코드 렌더링 방식 도입

### 설계

#### DESIGN-005: 드롭다운 팝업 높이 제한 제거

`sd-dropdown-popup.control.ts`에서:
1. `onResize` 메서드의 300px height 로직 제거
2. `(sdResize)` 이벤트 바인딩 제거 (onResize가 유일한 사용처)
3. `SdEventsDirective` import 제거
4. `ISdResizeEvent` import 제거

parent `sd-dropdown.control.ts:212-224`가 `maxHeight: availableHeight + "px"`를 이미 설정하고, 팝업 CSS에 `> div { overflow: auto }`가 있으므로 스크롤은 자연스럽게 동작한다.

#### DESIGN-006: Fixed column px 단위 문서화

`useSheetColumnFixing.ts`의 `useSheetColumnFixing` 함수에 JSDoc 추가:
- `columnDefs`의 fixed column은 `width`가 px 단위여야 정확한 offset 계산이 가능함을 명시
- non-px 단위 시 offset 누적에 반영되지 않음을 명시

#### DESIGN-007: 바코드 innerHTML Angular 바인딩 전환

`sd-barcode.control.ts`에서:
1. `computed`를 추가 import
2. bwip-js SVG 결과를 반환하는 `_svgHtml` computed signal 추가
3. `template`에 `[innerHTML]` 바인딩 사용: `<div [innerHTML]="_svgHtml()"></div>`
4. effect 내 `nativeElement.innerHTML` 직접 조작 제거
5. `ElementRef` inject 제거 (더 이상 필요 없음)

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| DESIGN-005: maxHeight CSS 변수로 높이 제한 | 미채택 | parent가 viewport 기반 maxHeight를 이미 설정하므로 추가 제한 불필요 |
| DESIGN-006: 런타임 경고 추가 | 미채택 | console.* 금지 규칙. 에러 핸들러 경유는 Low severity 대비 과도 |
| DESIGN-007: DomSanitizer.bypassSecurityTrustHtml | 미채택 | sanitization을 우회하므로 방어적 설계 목적에 반함 |
| DESIGN-007: host [innerHTML] 바인딩 | 미채택 | template 내 [innerHTML]이 sd-select.control.ts와 동일한 기존 패턴 |
