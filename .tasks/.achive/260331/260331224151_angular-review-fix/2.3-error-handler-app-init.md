## 구현계획

### 배경

`SdGlobalErrorHandlerPlugin`은 앱의 글로벌 에러 핸들러로, `handleError` 메서드에서 에러 타입별(PromiseRejectionEvent, ErrorEvent, Error, 기타) 분기 처리 후 에러 오버레이를 표시한다. `provideSdAngular`에서 라우터 네비게이션 이벤트를 `effect`로 추적하여 `SdBusyProvider.globalBusyCount`를 증감한다.

### 목표

- LOGIC-010: PromiseRejectionEvent의 else 분기에서 에러 정보 소실 방지
- LOGIC-011: 에러 오버레이 표시 실패 시 폴백 에러 메시지 제공
- LOGIC-016: 네비게이션 busy 카운터 음수 방지

### 비목표

- 에러 핸들러 전체 리팩토링
- busy 카운터를 boolean flag로 전환
- 에러 오버레이 UI 개선

### 설계

#### LOGIC-010: `sd-global-error-handler.plugin.ts:36-38`

else 분기(reason이 Error/object/string이 아닌 경우)에서 `JSON.stringify(event, null, 2)`를 `String(reason)`으로 교체. `String()`은 undefined, number, symbol, bigint 모두 안전하게 문자열로 변환한다.

#### LOGIC-011: `sd-global-error-handler.plugin.ts:74-80`

catch 블록에서 `appRef.destroy()` 후 `document.body.textContent`로 최소한의 에러 정보(원본 에러 + 2차 에러)를 표시한다. `textContent`는 가장 기본적인 DOM API로 실패 확률이 최소다.

#### LOGIC-016: `provideSdAngular.ts:149`

`v - 1`을 `Math.max(0, v - 1)`로 변경하여 카운터가 음수가 되는 것을 방지한다.

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| LOGIC-010: `String(reason)` | 채택 | 모든 primitive 타입을 안전하게 변환 |
| LOGIC-010: `JSON.stringify(reason)` | 미채택 | symbol에서 TypeError 발생 |
| LOGIC-011: `document.body.textContent` | 채택 | 가장 기본적인 DOM API, 실패 확률 최소 |
| LOGIC-011: `document.body.innerHTML` | 미채택 | XSS 위험, 에러 메시지에 HTML이 포함될 수 있음 |
| LOGIC-016: `Math.max(0, v - 1)` | 채택 | 최소 변경, 기존 counter 패턴 유지 |
| LOGIC-016: boolean flag 전환 | 미채택 | 다른 사용처(sd-print.provider)도 counter 패턴 사용, 일관성 유지 |
