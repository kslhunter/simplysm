### 핵심 사실

- 드롭다운 팝업은 `document.body`에 append되며 CSS `position: fixed` 사용 (viewport 기준)
- `getRelativeOffset(document.body)`는 `window.scrollX/Y`를 포함한 document-relative 좌표를 반환 (`core-browser` 유틸)
- `getBoundingClientRect()`는 viewport-relative 좌표를 반환하여 `position: fixed`와 좌표계 일치
- 모달 `._dialog`의 `offsetLeft/offsetTop`은 offsetParent 기준이며, auto-centered 상태에서 CSS `left` 값과 불일치 가능
- `parseInt("", 10)`은 NaN을 반환하며, `NaN >= number`는 항상 false
- `_destroyToast`는 `idx === -1` guard가 있어 이중 호출에 안전하나, `notify()` path의 `resolve`는 중복 호출될 수 있음

## 구현계획

### 배경

Angular overlay 컴포넌트(드롭다운, 모달, 토스트)의 위치 계산과 lifecycle에 리뷰에서 발견된 6건의 Medium severity 이슈가 있다. 모두 기존 로직의 좌표계 불일치, 상태 리셋 누락, 타이머 관리 결함에 해당하며, 각각 1~5줄 수준의 수정이다.

### 목표

- 드롭다운 팝업 위치 계산을 viewport 좌표계로 통일
- 드롭다운 팝업 닫힘 시 모든 인라인 스타일 리셋
- 모달 drag/resize의 좌표계 일관성 확보
- 모달 z-index 파싱의 NaN 안전성 확보
- 토스트 auto-dismiss의 중복 실행 방지
- 토스트 컨테이너의 overlap 반응적 바인딩

### 비목표

- 드롭다운/모달/토스트의 새로운 기능 추가
- CSS 스타일 변경 (인라인 스타일 관리만 수정)
- 다른 overlay 컴포넌트(busy indicator 등) 수정

### 설계

#### LOGIC-022: 드롭다운 팝업 viewport 좌표

`_updatePopupPosition()`에서 `contentEl.getRelativeOffset(document.body)` 대신 `contentEl.getBoundingClientRect()`를 사용한다. `getBoundingClientRect()`가 viewport-relative 좌표를 반환하므로 `position: fixed` 팝업과 좌표계가 일치한다.

변경 전: `windowOffset.top`, `windowOffset.left` (document-relative)
변경 후: `rect.top`, `rect.left`, `rect.bottom`, `rect.right` (viewport-relative)

`availableHeight`/`availableWidth` 계산도 동일하게 변경한다.

#### LOGIC-033: 드롭다운 _removePopup 스타일 리셋

`_removePopup()`의 `Object.assign(popupEl.style, {...})`에 `maxHeight: ""`, `maxWidth: ""`, `overflow: ""`를 추가한다. `_updatePopupPosition()`에서 설정하는 모든 속성이 리셋 대상에 포함되도록 한다.

#### LOGIC-023: 모달 drag/resize 좌표

`onResizeMouseDown()`과 `onHeaderMouseDown()`에서 `dialogEl.offsetLeft/offsetTop` 대신 `dialogEl.getBoundingClientRect()`를 사용하되, offsetParent 기준으로 변환한다. 이를 통해 auto-centered 상태에서도 정확한 초기 위치를 얻는다.

```
const dialogRect = dialogEl.getBoundingClientRect();
const parentRect = (dialogEl.offsetParent as HTMLElement | null)?.getBoundingClientRect()
  ?? { left: 0, top: 0 };
startLeft = dialogRect.left - parentRect.left;
startTop = dialogRect.top - parentRect.top;
```

#### LOGIC-024: 모달 z-index NaN 방어

`_bringToFront()`의 `parseInt(hostEl.style.zIndex, 10)` → `parseInt(hostEl.style.zIndex || "0", 10)`. 이미 L267에서 동일 패턴이 적용되어 있으므로 일관성 확보.

#### LOGIC-031: 토스트 auto-dismiss 중복 방지

`_setupAutoDismiss()`에 `dismissed` flag를 추가한다. `dismiss()` 호출 시 즉시 `dismissed = true`를 설정하고, 모든 dismiss 경로에서 `dismissed` 체크를 선행한다. 이를 통해 hover/leave 반복 시에도 dismiss가 정확히 1회만 실행된다.

#### LOGIC-032: 토스트 overlap 반응적 바인딩

`containerRef` getter에서 `this.overlap()` 읽기를 제거하고, constructor에서 `effect()`를 사용하여 overlap 변경을 반응적으로 컨테이너에 바인딩한다.

```typescript
constructor() {
  effect(() => {
    if (this._containerRef !== undefined) {
      this._containerRef.setInput("overlap", this.overlap());
    }
  });
}
```

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| LOGIC-022: `getRelativeOffset`에서 scroll offset 차감 | 미채택 | 유틸의 범용성을 훼손하고, 호출부에서 좌표계를 명시하는 것이 명확 |
| LOGIC-031: `dismissPending`만 리셋 | 미채택 | 이미 스케줄된 setTimeout은 취소 불가. `dismissed` flag가 모든 경로를 차단 |
| LOGIC-032: 매 `_show()` 호출마다 setInput | 미채택 (현재 방식) | overlap 변경이 다음 toast 표시 전까지 반영 안 됨 |
