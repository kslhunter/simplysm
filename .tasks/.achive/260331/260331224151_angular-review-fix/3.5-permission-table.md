## 구현계획

### 배경

`SdPermissionTableControl`은 계층형 권한 트리를 렌더링하고 use/edit 체크박스 토글 및 cascade 전파를 수행한다. 리뷰에서 3건의 이슈(LOGIC-005, LOGIC-030, PERF-003)가 보고되었으며, 모두 `sd-permission-table.control.ts` 단일 파일 수정이다.

### 목표

- `_changePermCheck` 내 signal stale 읽기를 로컬 value 파라미터 읽기로 교체
- collapse icon의 open 속성 반전 수정
- `arr()` 메서드의 배열 캐싱

### 비목표

- 권한 테이블의 새 기능 추가
- 다른 컴포넌트와의 통합 변경

### 설계

#### LOGIC-005 수정

`_changePermCheck` 332행에서 `!this.getIsPermChecked(item, "use")`를 `!(value[permCode + ".use"] ?? false)`로 교체. `if (item.perms)` 가드 내이므로 item은 leaf 노드이고, `getIsPermChecked`는 단순히 `this.value()[permCode + ".use"] ?? false`를 반환하는 것과 동일하다. value 파라미터에서 읽으면 동일 `value.update()` 콜백 내 선행 수정을 올바르게 반영한다.

#### LOGIC-030 수정

템플릿 155행 `[open]="getIsPermCollapsed(item)"`을 `[open]="!getIsPermCollapsed(item)"`으로 변경. `getIsPermCollapsed`가 true(접힘)일 때 open=false(닫힘 아이콘)이 되어야 한다.

#### PERF-003 수정

`private _arrCache = new Map<number, number[]>()`을 추가하고, `arr(len)` 메서드에서 캐시 lookup/store. 동일 length에 동일 참조를 반환하여 `@for` 재조정을 방지한다.

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| LOGIC-005: value에서 직접 읽기 | 채택 | 단순하고 정확. leaf 노드이므로 재귀 불필요 |
| LOGIC-005: getIsPermChecked에 value 파라미터 추가 | 미채택 | public API 변경 불필요. 호출 지점이 1곳뿐 |
| PERF-003: computed로 변환 | 미채택 | 파라미터(len)를 받으므로 computed 부적합 |
| PERF-003: Map 캐시 | 채택 | 간단하고 length 종류가 소수 |
