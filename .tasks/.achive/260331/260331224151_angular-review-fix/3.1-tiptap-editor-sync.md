## 구현계획

### 배경

`SdTiptapEditorControl`은 Tiptap Editor와 Angular value signal 간의 양방향 동기화를 구현한다. 현재 `updatingFromEditor` boolean flag로 에디터→모델 방향의 변경을 구분하지만, Angular effect의 비동기 실행 특성상 이 flag가 항상 무효화된다. 또한 `colorPickerMode`만 유일하게 signal이 아닌 plain property로 템플릿에 바인딩되어 있다.

### 목표

- editor→model 동기화 시 불필요한 `setContent` 호출을 방지하여 커서 리셋 제거
- `colorPickerMode`를 signal로 전환하여 코드베이스 패턴 통일

### 비목표

- Tiptap editor의 기능 추가/변경
- 다른 컴포넌트의 signal 전환 (이 Feature는 `sd-tiptap-editor.control.ts`만 대상)

### 설계

#### LOGIC-002: 값 비교 기반 동기화 가드

`updatingFromEditor` boolean flag를 제거하고 `lastEditorHtml` 필드를 도입한다.

- `onUpdate` 콜백: `lastEditorHtml = html` 저장 후 `value.set(html)`
- effect: extension 체크 이후, `val === this.lastEditorHtml` 이면 skip (에디터 기원 변경)
- `destroyEditor()`: `lastEditorHtml = undefined` 초기화
- 기존 보조 가드 `if (currentHtml === val) return` 유지 (defense-in-depth)

#### DESIGN-004: colorPickerMode signal 전환

- 필드: `colorPickerMode = signal<"text" | "bg" | undefined>(undefined)`
- 템플릿: `colorPickerMode` → `colorPickerMode()`
- 메서드: 읽기 `this.colorPickerMode()`, 쓰기 `this.colorPickerMode.set()`

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| `lastEditorHtml` 값 비교 | 채택 | 타이밍 독립적, 결정적 |
| boolean flag + 동기 signal API | 미채택 | Angular signal.set → effect는 항상 비동기, 원리적으로 불가 |
| microtask 래핑 | 미채택 | 타이밍 의존성 추가, 복잡도 증가 |
