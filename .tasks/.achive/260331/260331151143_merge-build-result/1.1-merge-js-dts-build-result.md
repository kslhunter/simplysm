# Feature 1.1 js/dts 빌드 결과 통합

## 참조 자료

### 현재 구조

- 워커 이벤트(watch): `{ js: { success, errors, warnings }, dts: { success, errors }, lint? }`
- EngineResult(프로덕션): `{ success, js: { success, errors, warnings }, dts: { success, errors, warnings, diagnostics }, lint? }`
- BuildResult(ResultCollector): `type: "build" | "dts" | "lint" | "server"`
- BaseEngine.startWatch(): js → `type: "build"`, dts → `type: "dts"` 2개 add
- BuildOrchestrator: js/dts 별도 results push

### 문제

- 라이브러리 워커: tsc 1회 결과를 js/dts에 동일 복사 → 에러 중복
- 서버 워커: esbuild(js) + tsc(dts) 분리이나 esbuild는 TS 타입 에러 미감지 → 분리 실익 없음
- watch 모드에서 같은 에러가 `(node)`/`(dts)` 두 줄로 출력됨

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | js/dts 합침 범위 | 전체 (watch + 프로덕션) | 일관성. esbuild는 TS 타입 에러 미감지이므로 분리 실익 없음 |
| D2 | diagnostics 위치 | 합쳐진 build 결과에 포함 | dts에만 있던 diagnostics를 단일 build에 통합 |
| D3 | lint 분리 | 유지 | lint는 별도 도구(ESLint)의 결과이므로 분리 의미 있음 |

## 구현계획

### 배경

sd-cli 빌드 파이프라인에서 워커→엔진→오케스트레이터로 이어지는 결과 보고 구조가 js/dts로 분리되어 있다. 이 분리는 esbuild가 TS 타입 에러를 감지하지 못하므로 실익이 없고, 동일 에러가 중복 출력되는 문제를 야기한다.

### 목표

- 모든 계층(워커, 엔진, 오케스트레이터)에서 js/dts를 단일 build 결과로 통합
- diagnostics를 통합된 build 결과에 포함
- lint는 기존대로 별도 유지

### 비목표

- BuildOutput(입력 제어 플래그 `{ js: boolean, dts: boolean }`)은 변경하지 않는다 — 이는 어떤 산출물을 생성할지 제어하는 플래그이므로 여전히 필요하다

### 설계

#### 새로운 타입 구조

```typescript
// 워커 이벤트 (watch)
interface CombinedBuildEvent {
  build: { success: boolean; errors?: string[]; warnings?: string[] };
  lint?: LintWithProgramResult;
}

// 워커 결과 (one-time build) — diagnostics 포함
interface BuildResultFromWorker {
  build: { success: boolean; errors?: string[]; warnings?: string[]; diagnostics: SerializedDiagnostic[] };
  lint?: LintWithProgramResult;
}

// EngineResult (프로덕션)
interface EngineResult {
  success: boolean;
  build: { success: boolean; errors: string[]; warnings: string[]; diagnostics: SerializedDiagnostic[] };
  lint?: LintWithProgramResult;
}

// ResultCollector BuildResult
interface BuildResult {
  type: "build" | "lint" | "server";  // "dts" 제거
  // ... 나머지 동일
}
```

#### 서버 워커 에러 합산 로직

```typescript
// esbuild 에러 + tsc 에러를 하나로
const allErrors = [...(jsResult.errors ?? []), ...(tscResult.errors ?? [])];
const success = jsResult.success && tscResult.success;
```
