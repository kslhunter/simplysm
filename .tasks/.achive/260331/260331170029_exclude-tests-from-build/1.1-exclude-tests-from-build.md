# Feature 1.1 빌드 명령에서 테스트 파일 제외

## 참조 자료

### 테스트 파일 포함 경로 (탐색 결과)

sd-cli에서 테스트 파일이 빌드에 포함되는 두 가지 카테고리:

**A. workspace-level `tests/*` 패키지**
- `package-utils.ts`의 `discoverWorkspacePackages()` → `mergeTestsPackagesIntoConfig()`로 병합
- `DevWatchOrchestrator.ts`(watch/dev)에서 호출 → 빌드 대상에 포함됨 (버그)
- `typecheck.ts`(check)에서 호출 → 정상

**B. `packages/*/tests/` 디렉토리**
- `tsc-build.ts`의 `runTscPackageBuild()`에서 typecheck-only 모드(`!needsEmit`)일 때 `getPackageFiles()` 호출 → tests/ 포함 (버그)
- server 빌드가 `output: { js: false, dts: false }`로 호출 시 해당

### 핵심 파일

| 파일 | 역할 |
|------|------|
| `packages/sd-cli/src/orchestrators/DevWatchOrchestrator.ts` | watch/dev 오케스트레이터 |
| `packages/sd-cli/src/utils/package-utils.ts` | 패키지 탐색, 병합, 분류 |
| `packages/sd-cli/src/utils/tsc-build.ts` | tsc 빌드 (rootFiles 결정) |
| `packages/sd-cli/src/utils/tsconfig.ts` | `getPackageSourceFiles` (src만), `getPackageFiles` (전체) |
| `packages/sd-cli/src/commands/typecheck.ts` | check 명령의 typecheck 경로 |

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | 테스트 제외 범위 | check 외 모든 명령 | 사용자 요구사항 |

## 요구명세

```gherkin
Feature: 1.1 빌드 명령에서 테스트 파일 제외

  Background:
    Given pnpm 모노레포에 sd-cli가 설정되어 있다
    And sd.config.ts에 빌드 패키지가 정의되어 있다
    And tests/ 워크스페이스 패키지와 packages/*/tests/ 디렉토리가 존재한다

  Rule: check 외 명령은 테스트 파일을 빌드/타입체크하지 않는다

    Scenario: watch 명령에서 workspace-level tests 패키지 제외
      When pnpm watch를 타겟 없이 실행한다
      Then tests/ 워크스페이스 패키지가 빌드 대상에 포함되지 않는다

    Scenario: dev 명령에서 workspace-level tests 패키지 제외
      When pnpm dev를 실행한다
      Then tests/ 워크스페이스 패키지가 빌드 대상에 포함되지 않는다

    Scenario: server 빌드의 typecheck-only 모드에서 packages/*/tests/ 제외
      When server 패키지가 typecheck-only 모드로 tsc를 실행한다
      Then packages/*/tests/ 파일이 rootFiles에 포함되지 않는다

    Scenario: library 빌드에서 packages/*/tests/ 제외
      When library 패키지가 emit 모드로 tsc를 실행한다
      Then packages/*/tests/ 파일이 rootFiles에 포함되지 않는다

  Rule: check 명령은 테스트 파일을 포함한다

    Scenario: check 명령에서 workspace-level tests 패키지 포함
      When pnpm check를 실행한다
      Then tests/ 워크스페이스 패키지가 타입체크 대상에 포함된다

    Scenario: check 명령에서 packages/*/tests/ 포함
      When pnpm check를 실행한다
      Then packages/*/tests/ 파일이 타입체크 대상에 포함된다

  Rule: 모든 빌드 타입에 적용된다

    Scenario: server/client/library 모두 tests 제외
      Given server, client, library 타입의 패키지가 각각 존재한다
      When pnpm dev를 실행한다
      Then 모든 빌드 타입에서 tests/ 파일이 제외된다
```

## 구현계획

### [x] Slice 1: workspace-level `tests/*` 패키지를 watch/dev에서 제외

- **구현 내용:** `DevWatchOrchestrator`에서 `mergeTestsPackagesIntoConfig` 제거, `sdConfig.packages`만 사용
- **의존:** 없음
- **수정 파일:**
  - `packages/sd-cli/src/orchestrators/DevWatchOrchestrator.ts` — import 변경, `mergeTestsPackagesIntoConfig`/`discoverWorkspacePackages` 제거, `buildPathMapFromConfig` 사용
  - `packages/sd-cli/src/utils/package-utils.ts` — `buildPathMapFromConfig()` 함수 추가
  - `packages/sd-cli/tests/orchestrators/dev-watch-orchestrator.spec.ts` — mock/테스트 갱신
- **Scenarios:** watch/dev에서 workspace-level tests 패키지 제외

### [x] Slice 2: `packages/*/tests/`를 build/watch/dev에서 제외하고 check에서만 포함

- **의존:** 없음
- **수정 파일:**

  - `packages/sd-cli/src/workers/server-build.worker.ts` — 동일
  - `packages/sd-cli/src/commands/typecheck.ts` — `engine.run({ js: false, dts: false, includeTests: true })` 전달
  - `packages/sd-cli/src/utils/ngtsc-build-core.ts` — `includeTests` 시 `getPackageFiles` 사용
  - `packages/sd-cli/src/workers/ngtsc-build.worker.ts` — 동일
- **Scenarios:** server typecheck-only에서 tests 제외, check에서 tests 포함
