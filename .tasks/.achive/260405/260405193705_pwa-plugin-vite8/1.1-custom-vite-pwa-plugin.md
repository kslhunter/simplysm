## 구현계획

### 배경

현재 `packages/sd-cli/src/utils/vite-config.ts`의 `createClientViteConfig`에서 `vite-plugin-pwa`의 `VitePWA` 플러그인을 사용하여 PWA 기능을 제공한다 (`vite-config.ts:219-226`). build 모드에서만 활성화되며 (`vite-config.ts:192`), `SdPwaConfig`를 통해 manifest와 workbox 설정을 커스터마이즈한다.

### 목표

- `sdPwaPlugin` Vite 플러그인 팩토리 함수 구현 [근거: wbs 범위]
- build 모드에서 `manifest.webmanifest` + `sw.js` 자동 생성 [근거: Rule "build 모드에서만 활성"]
- `transformIndexHtml`로 HTML 태그/스크립트 주입 [근거: Rule "HTML 주입"]
- 앱 버전 기반 캐시 관리 [근거: Rule "버전 기반 캐시"]

### 비목표

- Workbox 런타임 캐싱 전략 [근거: wbs 경계 "Workbox 런타임 캐싱 전략은 구현하지 않음"]
- 파일별 해시 기반 증분 캐싱 [근거: wbs 경계 "증분 캐싱 없음"]
- `SdPwaConfig` 타입 변경 [근거: Feature 1.2 경계]
- dev 모드 PWA [근거: wbs 경계 "dev 모드에서는 PWA 플러그인 비활성"]

### 설계

**새 파일: `packages/sd-cli/src/utils/vite-pwa-plugin.ts`** [근거: 기존 Vite 플러그인이 `src/utils/`에 위치 (vite-scope-watch-plugin.ts)]

```typescript
export interface SdPwaPluginOptions {
  pkgDir: string;      // package.json 위치, generatePwaIcons 경로
  pkgName: string;     // manifest 기본값 (scope-stripped name)
  pwa?: SdPwaConfig;   // 사용자 PWA 설정
}

export function sdPwaPlugin(options: SdPwaPluginOptions): PluginOption;
```

**플러그인 훅:**

1. **`configResolved(config)`**: `config.base`, `config.build.outDir` 저장 [근거: closeBundle/transformIndexHtml에서 경로 참조 필요]
2. **`transformIndexHtml()`**: `<link rel="manifest">` + SW 등록/업데이트 인라인 스크립트 반환 [근거: Rule "HTML 주입". 기존 sd-polyfills 플러그인 `vite-config.ts:260-271`과 동일 패턴]
3. **`closeBundle()`**:
   - `${pkgDir}/package.json`에서 version 읽기 [근거: Rule "버전 소스"]
   - `generatePwaIcons` 호출 (커스텀 icons 미설정 시) [근거: Rule "아이콘 자동 생성"]
   - `manifest.webmanifest` JSON 파일 생성 (기본값 + SdPwaConfig 오버라이드) [근거: Rule "manifest 기본값"]
   - `glob`으로 outDir 빌드 산출물 수집 → `sw.js`/`manifest.webmanifest` 제외 [근거: Rule "precache", D4]
   - `sw.js` 파일 생성 (version, base, precache URLs, 4개 이벤트 핸들러) [근거: Rule "install/activate/fetch/message"]

**sw.js 생성 방식:** Template literal로 JavaScript 코드 생성. 런타임 변수(version, base, precache URLs)를 문자열 치환으로 주입. [근거: 기존 sd-polyfills 플러그인 `vite-config.ts:237-255` — Vite 플러그인에서 코드 문자열 생성 패턴]

**업데이트 알림:** injected script에서 `window.dispatchEvent(new CustomEvent("sd-pwa-update-ready", { detail: { update } }))` — `update()`는 `worker.postMessage({ type: "SKIP_WAITING" })` 호출. `controllerchange` 이벤트 시 `location.reload()`. [근거: D1]

### 대안 검토

| 대안                                               | 선택하지 않은 이유                                                                               |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Workbox 직접 사용 (`workbox-build`만 유지)          | 외부 의존성 제거 목표에 부합하지 않음. `workbox-build`가 런타임 코드를 생성하므로 의존성 유지 필요 |
| sw.js를 별도 소스 파일로 관리 후 esbuild로 빌드     | sw.js 내용이 단순(~40줄)하여 빌드 파이프라인 추가 비용 대비 이점 없음                             |
