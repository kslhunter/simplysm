# Feature 2.1 NgtscEngine 마이그레이션 (library)

## 참조 자료

- [wbs.md](wbs.md)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | output-path-rewriting 적용 위치 | emitAffectedFiles() 결과를 받아 호출자(ngtsc-build-core)에서 적용 | AngularCompiler는 범용이므로 library 전용 path-rewriting을 내부에 넣지 않음. emitAffectedFiles()가 {filename, contents} iterator를 반환하므로 외부 적용이 자연스러움 |
| D2 | SCSS 의존성 추적 위치 | transformStylesheet 콜백 클로저에서 수집, 워커가 Map을 관리 | AngularCompiler 내부에 SCSS 의존성 추적을 넣으면 library/client 간 차이가 생김. 콜백 외부에서 관리가 명확 |
| D3 | ngtsc-build-core.ts의 기존 함수 처리 | runNgtscBuild 유지 (내부 AngularCompiler로 교체), runNgtscRebuild 제거 (worker가 AngularCompiler.update() 직접 사용) | AngularCompiler가 내부 상태를 관리하므로 runNgtscRebuild의 oldProgram 반환 패턴이 불필요. NgtscBuildResult/NgtscCombinedBuildEvent 타입은 유지 |
| D4 | Global SCSS 컴파일 위치 | ngtsc-build-core에서 별도 호출 유지 | AngularCompiler는 Angular AOT 컴파일만 담당. Global SCSS는 Angular 컴파일과 무관한 별도 작업 |
| D5 | buildCompilerOptions 함수 유지 여부 | ngtsc-build-core에서 유지 | output.js/output.dts에 따른 compilerOptions 계산은 library 빌드 전용 로직. AngularCompiler의 compilerOptionsTransformer로 주입할 수도 있지만, 현재 패턴이 명확하므로 유지 |

## 구현계획

### 배경

현재 Angular library 빌드는 `ngtsc-build-core.ts`에서 NgtscProgram을 직접 생성하고 호스트 확장, 진단 수집, emit을 수동으로 수행한다. Feature 1.1~1.3에서 구현된 통합 `AngularCompiler` 클래스(`angular-compiler.ts`)가 이 모든 기능을 BuilderProgram 기반 incremental 최적화와 함께 제공한다. library 빌드를 AngularCompiler로 마이그레이션하면 코드 중복을 제거하고 incremental 최적화(affected-only emit, diagnostic 캐싱)를 얻는다.

### 목표

- `ngtsc-build-core.ts`의 빌드 로직을 AngularCompiler로 교체
- `ngtsc-build.worker.ts`의 watch 모드를 AngularCompiler.update()로 교체
- library 고유 기능(SCSS 처리, output-path-rewriting, Global SCSS) 유지
- 워커 이벤트 인터페이스(NgtscBuildResult, NgtscCombinedBuildEvent) 유지

### 비목표

- NgtscEngine 자체 변경 (워커 인터페이스가 유지되므로 불필요)
- client 빌드 경로 변경 (Feature 2.2에서 별도 수행)
- lint 통합 (Feature 3.x에서 별도 수행)
- Global SCSS 컴파일 방식 변경

### 설계

#### ngtsc-build-core.ts 변경

제거 대상 함수:
- `createNgtscProgramWithHost` — AngularCompiler.initialize()로 대체
- `collectDiagnostics` — AngularCompiler.collectDiagnostics()로 대체
- `emitFiles` — AngularCompiler.emitAffectedFiles()로 대체
- `runNgtscRebuild` — worker가 AngularCompiler.update()를 직접 호출
- `trackDeps`, `formatScssError` — transformStylesheet 팩토리 내부로 이동

유지 함수:
- `buildCompilerOptions` — output.js/output.dts에 따른 compilerOptions 계산
- `buildScssLoadPaths` — SCSS loadPaths 생성
- `compileGlobalScss` — Global SCSS 컴파일

추가:
- `createLibraryTransformStylesheet(loadPaths, scssErrors, scssDependencies)` — library SCSS 콜백 팩토리
- `writeEmitResults(emitResults, pkgDir)` — emitAffectedFiles 결과를 output-path-rewriting + 파일 쓰기

`runNgtscBuild` 내부 흐름 변경:
1. parseTsconfig + getPackageSourceFiles + buildCompilerOptions (기존과 동일)
2. root tsconfig에서 angularCompilerOptions 읽기 (기존과 동일)
3. scssErrors/scssDependencies 클로저 변수 생성
4. `new AngularCompiler({ rootNames, compilerOptions, angularCompilerOptions, transformStylesheet: createLibraryTransformStylesheet(...) })`
5. `await compiler.initialize()`
6. `collectDiagnostics()` → 진단 수집 + 필터링 (패키지 소스 디렉토리 기준)
7. `emitAffectedFiles({ sourceFilter })` → output-path-rewriting + 파일 쓰기
8. `compileGlobalScss()` → Global SCSS
9. NgtscBuildResult 반환

#### createLibraryTransformStylesheet 팩토리

```
(data, containingFile, stylesheetFile?) => {
  if (stylesheetFile?.endsWith(".scss"))
    → compileScssFile(stylesheetFile, loadPaths) → CSS 반환 + deps 기록
  if (stylesheetFile != null)
    → null 반환 (.css 등은 readResource가 처리)
  인라인
    → compileScssString(data, containingFile, loadPaths) → CSS 반환 + deps 기록
  에러 시 → scssErrors에 추가, "/* SCSS error */" 반환
}
```

#### writeEmitResults 함수

```
for (const { filename, contents } of emitResults) {
  const rewrite = outputPathRewriter(filename, contents)
  if (rewrite == null) continue
  mkdirSync + writeFileSync
}
```

#### ngtsc-build.worker.ts 변경

- `build(info)` — `runNgtscBuild(info)` 호출 유지 (변경 없음)
- `startWatch(info)` — AngularCompiler + AngularSourceFileCache 직접 사용:
  1. AngularCompiler 생성 (sourceFileCache 포함)
  2. initialize() → 진단+emit + Global SCSS → 초기 빌드 이벤트 전송
  3. FsWatcher 시작
  4. 변경 감지 시:
     - 변경 파일 + SCSS 의존성 역추적으로 modifiedFiles 구성
     - compiler.update(modifiedFiles) → 진단+emit + Global SCSS → 빌드 이벤트 전송
- `oldProgram` 제거 → AngularCompiler 인스턴스가 내부 상태 관리
- `currentScssDependencies` 유지 → transformStylesheet 콜백 클로저에서 갱신

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| runNgtscBuild/runNgtscRebuild 모두 유지 (내부만 교체) | 미채택 | runNgtscRebuild가 oldProgram을 반환하는 패턴은 AngularCompiler의 내부 상태 관리와 충돌. 불필요한 래핑 |
| worker에서 runNgtscBuild도 제거하고 모두 직접 AngularCompiler 사용 | 미채택 | one-time build의 boilerplate가 커짐. runNgtscBuild는 stateless이므로 래퍼로 유지가 적절 |
| output-path-rewriting을 AngularCompiler 내부에 구현 | 미채택 | library 전용 로직이므로 범용 AngularCompiler에 넣으면 client에서 불필요한 코드가 됨 |
