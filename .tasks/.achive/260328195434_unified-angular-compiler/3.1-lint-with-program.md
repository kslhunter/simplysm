## 구현계획

### 배경

sd-cli의 빌드 워커들(ngtsc-build, library-build, server-build, client)은 각각 TypeScript typecheck를 수행하면서 ts.Program을 생성한다. 현재 lint는 별도 워커(`lint.worker.ts`)에서 ESLint가 자체 ts.Program을 생성하여 실행한다. 이는 Program 이중 생성 비효율이며, Worker thread 간 ts.Program 공유가 불가능하여 빌드 워커와 lint 워커가 협력할 수 없다.

### 목표

- `lint-with-program` 유틸리티를 생성하여 기존 ts.Program을 ESLint에 주입하는 경로 확보
- 4종 빌드 워커에서 typecheck 후 같은 thread에서 lint 실행
- 워커 이벤트 및 엔진 결과에 lint 결과를 포함하여 상위 계층에서 소비 가능하게 함

### 비목표

- 명령어(check/build/watch/dev) 계층에서의 lint 사용 방식 변경 (Feature 3.2)
- 기존 `lint.worker.ts` / `runLint()` 제거 (Feature 3.2)
- scripts 패키지 lint 처리 (Feature 3.2)
- ESLint rule 변경

### 설계

#### lint-with-program 유틸리티

새 파일: `packages/sd-cli/src/utils/lint-with-program.ts`

**`LintWithProgramRunner` 클래스:**
- ESLint 인스턴스를 내부에 보유, `programs` 옵션은 mutable 배열 참조로 주입
- `lint(options)` 호출 시 배열 내 program 교체 후 `lintFiles()` 실행
- 첫 호출 시 ESLint 인스턴스 생성 (config/plugins 로딩), 이후 재사용
- `overrideConfig`로 `parserOptions: { programs: ref, project: null, projectService: false }` 주입
- ESLint 캐시: `{cwd}/.cache/eslint-{패키지명}.cache`

**파일 추출 로직:**
- `program.getSourceFiles()` → `pkgDir` 하위 필터 → `.d.ts` 제외 → node_modules 경로 제외
- 결과를 절대 경로 배열로 `ESLint.lintFiles()`에 전달

**`LintWithProgramResult` 타입:**

```typescript
interface LintWithProgramResult {
  success: boolean;
  errorCount: number;
  warningCount: number;
  formattedOutput: string;
}
```

#### 타입 변경

| 파일 | 변경 |
|------|------|
| `engines/types.ts` | `BuildOutput.lint: boolean` 추가, `EngineResult.lint?: LintWithProgramResult` 추가 |
| `engines/BaseEngine.ts` | `CommonBuildWorkerEvents.build`에 `lint?` 필드 추가, `startWatch()`에서 lint BuildResult 생성 |
| `engines/ViteEngine.ts` | build 이벤트에서 lint 결과 추출, EngineResult/ResultCollector에 전달 |
| `infra/ResultCollector.ts` | `BuildResult.type`에 `"lint"` 추가 |
| 각 워커 타입 | `NgtscBuildResult.lint?`, `NgtscCombinedBuildEvent.lint?`, `LibraryBuildResult.lint?`, `CombinedBuildEvent.lint?`, `ServerBuildResult.lint?`, `ServerCombinedBuildEvent.lint?`, `ClientBuildResult.lint?` |

#### ts.Program 노출 (library/server)

`tsc-build.ts`의 `TscPackageBuildResult`에 `program?: ts.Program` 필드 추가. 내부에서 이미 생성하는 `ts.createIncrementalProgram()`의 `.getProgram()`을 반환한다.

#### ngtsc-build lint 통합

**one-time build (`runNgtscBuild`):**
`ngtsc-build-core.ts`의 `runNgtscBuild()` 내부에서 AngularCompiler 초기화 + diagnostics 수집 후, `compiler.getTsProgram()`으로 lint 실행. lint 결과를 `NgtscBuildResult.lint`에 포함.

**watch (`performWatchBuild`):**
`ngtsc-build.worker.ts`에서 `LintWithProgramRunner` 인스턴스를 워커 수준에서 보유. `performWatchBuild()` 후 `compiler.getTsProgram()`으로 lint 실행. `NgtscCombinedBuildEvent.lint`에 결과 포함.

#### vite-angular-plugin lint 통합

`SdAngularPluginOptions`에 `enableLint: boolean` 추가. `onBuild` 콜백의 결과 타입에 `lint?: LintWithProgramResult` 추가.

**buildStart 훅:** compilation + emit + diagnostics 후 lint 실행, `onBuild` 콜백에 lint 포함.
**handleHotUpdate:** incremental compilation 후 lint 실행, `onBuild` 콜백에 lint 포함.
**LintWithProgramRunner:** 플러그인 클로저 내 인스턴스 보유 (watch 모드 재사용).

**client.worker:**
- `build()`: `onBuild` 콜백을 프로덕션 빌드에도 추가하여 lint 결과 수집
- `startWatch()`: 기존 `onBuild` → `sender.send("build", result)` 경로에서 lint 필드 자동 전달

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|----------|------|
| ESLint에 ts.Program 주입 (programs 옵션) | 채택 | WBS 검증 완료, Program 중복 생성 제거, 동일 thread 실행 |
| 각 워커에서 executeLint() 그대로 사용 | 미채택 | Program 공유 불가, ts.Program 이중 생성 비효율 유지 |
| ts.Program 직렬화 후 lint 워커에 전달 | 미채택 | ts.Program은 직렬화 불가 (순환 참조, 함수 포함) |
| ESLint 인스턴스 매번 재생성 (함수형) | 미채택 | config/plugins 재로딩 오버헤드, WBS에서 인스턴스 재사용 명시 |
