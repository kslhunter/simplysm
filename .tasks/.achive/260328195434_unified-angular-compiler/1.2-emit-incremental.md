# Feature 1.2 통합 컴파일러 — Emit + Incremental

## 참조 자료

- [wbs.md](wbs.md)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | emit 메서드 위치 | AngularCompiler 클래스 메서드 | Feature 1.1에서 initialize/collectDiagnostics를 같은 클래스에 구현한 패턴과 일치 |
| D2 | emitAffectedFiles 반환 타입 | Iterator<{ filename, contents }> | AotCompilation 참조 구현과 동일, 호출자가 파일 쓰기 방식을 결정 |

| D4 | update() 메서드 설계 | sourceFileCache.invalidate + initialize() 재호출 | AngularFacade.update() 패턴과 동일, 기존 initialize()의 incremental 경로를 활용 |

## 요구명세

```gherkin
Feature: 1.2 통합 컴파일러 — Emit + Incremental

  Background:
    Given AngularCompiler 인스턴스가 생성되어 있다
    And initialize()가 호출되어 AOT 분석이 완료된 상태이다

  Rule: emitAffectedFiles는 영향받은 파일만 emit한다

    Scenario: 변경된 파일만 emit
      Given 파일 A가 변경되어 affectedFiles에 포함되어 있다
      And 파일 B, C는 변경되지 않아 affectedFiles에 없다
      When emitAffectedFiles()를 호출한다
      Then emit 결과에 파일 A만 포함된다
      And 파일 B, C는 emit되지 않는다

    Scenario: 첫 빌드에서 모든 파일 emit
      Given 이전 빌드 상태가 없다 (첫 빌드)
      And 모든 소스 파일이 affectedFiles에 포함되어 있다
      When emitAffectedFiles()를 호출한다
      Then 모든 소스 파일이 emit된다

    Scenario: Angular가 affected로 판단하지만 TypeScript가 판단하지 않은 파일
      Given TypeScript의 emitNextAffectedFile이 파일 X를 emit하지 않았다
      And angularCompiler.incrementalCompilation.safeToSkipEmit(X)가 false이다
      When emitAffectedFiles()의 2차 루프에서 파일 X를 처리한다
      Then 파일 X가 emit된다
      And recordSuccessfulEmit(X)가 호출된다

    Scenario: safeToSkipEmit이 true이고 affectedFiles에 없는 파일은 skip
      Given TypeScript의 emitNextAffectedFile이 파일 Y를 emit하지 않았다
      And safeToSkipEmit(Y)가 true이다
      And Y가 affectedFiles에 없다
      When emitAffectedFiles()의 2차 루프에서 파일 Y를 처리한다
      Then 파일 Y는 emit되지 않는다

    Scenario: emit 성공 시 incremental 추적 기록
      Given 파일 A가 emit 대상이다
      When 파일 A의 emit이 완료된다
      Then angularCompiler.incrementalCompilation.recordSuccessfulEmit(A)가 호출된다
      And 다음 빌드에서 A가 변경되지 않으면 safeToSkipEmit(A)가 true를 반환한다

  Rule: Angular transformers가 emit 시 적용된다

    Scenario: prepareEmit()의 transformers가 emit에 적용
      Given angularCompiler.prepareEmit()이 transformers를 반환한다
      When emitAffectedFiles()를 호출한다
      Then emit 시 transformers.before에 Angular transformers가 포함된다

    Scenario: 추가 transformers를 외부에서 주입 가능
      Given emitAffectedFiles() 호출 시 additionalTransformers 옵션을 전달한다
      When emit이 실행된다
      Then Angular transformers와 추가 transformers가 모두 적용된다

  Rule: output.js/output.dts 옵션에 따라 emit이 분기된다

    Scenario: JS와 .d.ts 모두 emit
      Given compilerOptions에 declaration=true, emitDeclarationOnly=false, noEmit=false가 설정되어 있다
      When emitAffectedFiles()를 호출한다
      Then .js 파일과 .d.ts 파일이 모두 emit된다

    Scenario: JS만 emit
      Given compilerOptions에 declaration=false가 설정되어 있다
      When emitAffectedFiles()를 호출한다
      Then .js 파일만 emit되고 .d.ts 파일은 생성되지 않는다

    Scenario: .d.ts만 emit
      Given compilerOptions에 emitDeclarationOnly=true가 설정되어 있다
      When emitAffectedFiles()를 호출한다
      Then .d.ts 파일만 emit되고 .js 파일은 생성되지 않는다

    Scenario: emit 없음 (typecheck 전용)
      Given compilerOptions에 noEmit=true가 설정되어 있다
      When emitAffectedFiles()를 호출한다
      Then 어떤 파일도 emit되지 않는다

  Rule: update(modifiedFiles)가 incremental rebuild 진입점이다

    Scenario: 파일 변경 후 incremental rebuild
      Given 초기 빌드가 완료된 상태이다
      And 파일 A, B가 변경되었다
      When update(Set{A, B})를 호출한다

      Given 초기 빌드가 완료된 상태이다
      And node_modules/some-package/index.js가 변경되었다
      When update(변경 파일 Set)를 호출한다
      Then packageJsonCache가 clear된다
      And initialize()가 재호출된다

  Rule: 리소스 변경(SCSS/HTML)이 관련 .ts 파일을 affected로 만든다

      Given component.ts가 component.scss를 리소스로 참조한다
      And component.scss가 변경되었다
      When update() 후 initialize()가 실행된다
      Then component.ts의 diagnosticCache가 무효화된다
      And component.ts가 affectedFiles에 추가된다
      And emitAffectedFiles() 시 component.ts가 re-emit된다

    Scenario: 리소스 변경 없으면 diagnosticCache 재사용
      Given component.ts의 리소스 파일이 변경되지 않았다
      And component.ts가 affectedFiles에 없다
      When collectDiagnostics()를 호출한다
      Then component.ts의 Angular 진단은 diagnosticCache에서 반환된다
```

## 구현계획

### 배경

Feature 1.1에서 `AngularCompiler` 클래스가 구현되어 `initialize()` (NgtscProgram 생성, BuilderProgram 기반 affected files 탐색, AOT 분석)와 `collectDiagnostics()` (incremental 진단 수집 + WeakMap 캐싱)를 제공한다. 그러나 emit 기능이 없어, 현재 library 빌드는 `ngtsc-build-core.ts`의 `emitFiles()`가 전체 파일을 순회하며 emit하고 있다 (affected 최적화 없음).

### 목표

- `AngularCompiler`에 `emitAffectedFiles()` 추가 — affected 파일만 emit + incremental skip (safeToSkipEmit/recordSuccessfulEmit)
- `AngularCompiler`에 `update(modifiedFiles)` 추가 — incremental rebuild 진입점
- 외부 transformer 주입 지원 (client 빌드의 replaceBootstrap 등)
- output.js/output.dts 분기는 compilerOptions로 제어 (기존 패턴 유지)

### 비목표

- ngtsc-build-core.ts/AngularFacade 마이그레이션 (Feature 2.1, 2.2)
- HMR 지원 (Feature 1.3)
- client 전용 transformers (replaceBootstrap, webWorkerTransform, lazyRoutesTransformer) 구현 — 호출자가 주입

### 설계

#### AngularCompiler API 확장

```typescript
// emit 결과 타입
interface EmitResult {
  filename: string;
  contents: string;
}

// emit 옵션
interface EmitOptions {
  /** emit 대상 소스 디렉토리 필터 (지정 시 해당 디렉토리의 파일만 emit) */
  sourceFilter?: (fileName: string) => boolean;
  /** Angular transformers 외 추가 transformers */
  additionalTransformers?: {
    before?: ts.TransformerFactory<ts.SourceFile>[];
    after?: ts.TransformerFactory<ts.SourceFile>[];
  };
}

class AngularCompiler {
  // 기존 API (Feature 1.1)
  async initialize(): Promise<{ affectedFiles: ReadonlySet<ts.SourceFile> }>;
  *collectDiagnostics(): Iterable<ts.Diagnostic>;
  getTsProgram(): ts.Program;

  // 신규 API (Feature 1.2)
  *emitAffectedFiles(options?: EmitOptions): Iterable<EmitResult>;
  async update(modifiedFiles: Iterable<string>): Promise<{ affectedFiles: ReadonlySet<ts.SourceFile> }>;
}
```

#### emitAffectedFiles 흐름

```
1. noEmit=true이면 즉시 return (typecheck 전용)
2. prepareEmit() → Angular transformers 획득
3. additionalTransformers가 있으면 transformers.before/after에 추가
4. writeFileCallback 정의 — sourceFile별 {filename, contents}를 수집
5. emitNextAffectedFile 루프 (BuilderProgram이 affected 파일 자동 처리)
   - ignoreForEmit 파일은 skip
   - recordSuccessfulEmit 호출
   - sourceFilter 적용
6. 2차 루프: TypeScript가 affected로 판단하지 않았지만 Angular이 처리해야 할 파일
   - 이미 emit된 파일 skip
   - ignoreForEmit, isDeclarationFile skip
   - safeToSkipEmit=true이고 affectedFiles에 없으면 skip
   - emit 후 recordSuccessfulEmit 호출
   - sourceFilter 적용
7. Iterator로 {filename, contents} yield
```

#### update 흐름

```
1. sourceFileCache가 있으면 invalidate(modifiedFiles) 호출
2. sourceFileCache가 없으면 에러 (incremental rebuild에 필수)
3. initialize() 호출 → 결과 반환
```

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| emitAffectedFiles를 별도 유틸리티 함수로 구현 | 미채택 | AngularCompiler의 내부 상태(_builderProgram, _affectedFiles, _ngtscProgram)에 직접 접근 필요 |
| AotCompilation의 useTypeScriptTranspilation 분기 복제 | 미채택 | sd-cli는 항상 TypeScript transpilation 사용 (isolatedModules 미사용). 불필요한 복잡도 |
| emitAffectedFiles를 async generator로 구현 | 미채택 | emit 자체는 동기 작업 (ts.Program.emit이 동기). sync Iterator가 적절 |
| update()에서 sourceFileCache 없이도 동작 | 미채택 | incremental rebuild에 sourceFileCache가 필수 (modifiedFiles 추적). 없으면 매번 전체 rebuild와 동일 |
