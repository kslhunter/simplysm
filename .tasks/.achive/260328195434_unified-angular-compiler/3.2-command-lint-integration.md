## 구현계획

### 배경

sd-cli의 check/build 명령어는 현재 lint를 별도 워커(`lint.worker.ts`)로 실행한다. `check.ts`는 `executeTypecheck()`와 `runLint()`를 병렬로 호출하고, `BuildOrchestrator`는 빌드 태스크와 `runLint()`를 병렬로 실행한다. watch/dev는 lint를 실행하지 않는다.

Feature 3.1에서 각 빌드 워커에 `lint-with-program`을 통합하고, `BuildOutput.lint`, `EngineResult.lint`, `CommonBuildWorkerEvents.build.lint` 필드를 추가했다. 엔진 레벨에서 lint 결과를 생산/소비하는 인프라가 갖춰졌으나, 명령어 계층에서 아직 이를 활용하지 않는 상태다.

### 목표

- check/build에서 별도 lint 워커 대신 엔진 lint 결과를 사용
- watch/dev에서 lint 활성화 (엔진의 startWatch에 lint: true 전달)
- scripts 패키지는 빌드 엔진이 없으므로 별도 ESLint 유지

### 비목표

- `pnpm lint` 단독 명령어 변경 (기존 동작 유지)
- `lint.worker.ts` / `lint-utils.ts` 삭제 (scripts 패키지 + pnpm lint용 유지)
- ESLint rule 변경

### 설계

#### executeTypecheck 확장

`TypecheckOptions`에 `lint?: boolean` 추가. `TypecheckResult`에 `lint?` 필드(성공 여부, 에러/경고 수, 포매팅 출력)와 `scriptsPackagePaths: string[]` 추가.

`executeTypecheck()`는 이미 sd.config.ts를 로드하고 scripts 패키지를 skip하므로:
- skip한 scripts 패키지 경로를 수집하여 `scriptsPackagePaths`로 반환
- `options.lint === true`이면 `engine.run()`에 `lint: true` 전달
- 각 `EngineResult.lint`를 수집하여 단일 lint 결과로 merge (errorCount/warningCount 합산, formattedOutput 연결, 하나라도 실패하면 success=false)

`lint: true`이고 `typecheck`가 필요 없는 경우("lint만 단독 실행")에도 엔진을 통해 실행한다. 엔진은 항상 내부적으로 typecheck를 수행하므로(ts.Program 생성 필수), lint만 원할 때도 `engine.run({ js: false, dts: false, lint: true })`로 호출한다. check.ts에서 typecheck 결과 표시 여부를 제어한다.

#### check.ts 변경

현재 패턴:
```
if ("typecheck") → tasks.push(executeTypecheck(...))
if ("lint") → tasks.push(runLint(...))
if ("test") → tasks.push(spawnVitest(...))
```

변경 후:
```
if ("typecheck" || "lint") → tasks.push(executeTypecheck({ ..., lint: "lint" 포함 여부 }))
  → typecheck 결과: "typecheck" 포함 시에만 CheckResult로 추가
  → lint 결과: "lint" 포함 시에만 CheckResult로 추가
  → scripts lint: "lint" 포함이고 scriptsPackagePaths 비어있지 않으면 runLint(scripts만) 호출
if ("test") → tasks.push(spawnVitest(...))
```

`runLint` import는 scripts 패키지 lint용으로 유지한다.

#### BuildOrchestrator 변경

각 `engine.run()` 호출에 `lint: true` 추가:
- buildPackages: `engine.run({ js: true, dts: true, lint: true })`
- serverPackages: `engine.run({ js: true, dts: false, lint: true })`
- clientPackages: `engine.run({ js: true, dts: false, lint: true })`

`EngineResult.lint`를 수집하여 `BuildStepResult`에 lint 결과 추가. lint 에러 시 `state.hasError = true`.

기존 `lintTask` (413-418행)와 `runLint` import, `lintOptions` 변수를 제거한다.

결과 출력 섹션에서 lint 결과를 패키지별로 출력한다.

#### DevWatchOrchestrator 변경

watch 모드 (294행):
```
e.startWatch({ js: true, dts: true }) → e.startWatch({ js: true, dts: true, lint: true })
```

dev 모드 — client (351행):
```
engine.startWatch({ js: true, dts: false }) → engine.startWatch({ js: true, dts: false, lint: true })
```

dev 모드 — server (358행):
```
engine.startWatch({ js: true, dts: false }) → engine.startWatch({ js: true, dts: false, lint: true })
```

이미 BaseEngine.startWatch()와 ViteEngine이 lint 결과를 ResultCollector에 보고하므로 (Feature 3.1), printErrors()가 lint 에러를 자동으로 표시한다.

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|----------|------|
| executeTypecheck 확장으로 lint 결과 반환 | 채택 | 기존 인프라 재사용, check.ts 변경 최소화, scripts 패키지 분리 자연스러움 |
| check.ts에서 엔진 직접 생성/사용 | 미채택 | executeTypecheck의 sd.config.ts 로드/패키지 분류 로직 중복 |
| 별도 executeLintWithEngines() 함수 생성 | 미채택 | executeTypecheck와 거의 동일한 엔진 생성/실행 로직 중복 |
| watch/dev에서 lint를 별도 FsWatcher로 실행 | 미채택 | 엔진 내 Program 공유 lint가 이미 존재, 별도 watcher는 Program 이중 생성 |
