## 구현계획

### 배경

`BuildOrchestrator._addClientPackageTasks()` (366-438행, 72줄)은 클라이언트 패키지의 빌드 태스크를 생성한다. 이 메서드의 후반부(394-433행)에 Capacitor/Electron 네이티브 빌드 로직이 인라인되어 있다. 웹 빌드 태스크 생성과 네이티브 빌드 실행이라는 두 가지 책임이 혼재한다.

[근거: 리팩토링 리포트 DESIGN-002]

### 목표

- `_addClientPackageTasks()`에서 네이티브 빌드 로직을 `_runNativeBuilds()` private 메서드로 추출하여 책임 분리 [근거: DESIGN-002 "네이티브 빌드 옵션 확장 시 이 메서드의 책임이 과도하게 커질 수 있다"]

### 비목표

- DevOrchestrator의 Capacitor 초기화 로직은 대상 아님 (initialize만 수행, build 미실행 — 다른 생명주기) [근거: WBS 경계]
- 네이티브 빌드 로직 자체의 변경 [근거: WBS "기존 기능의 동작 변경 없음"]

### 설계

`_runNativeBuilds()` 메서드 시그니처:

```typescript
private async _runNativeBuilds(
  name: string,
  pkgDir: string,
  distPath: string,
  config: SdClientPackageConfig,
  hasUntrackedError: { value: boolean },
): Promise<void>
```

[근거: 394-433행의 코드가 사용하는 외부 변수 분석 — name(로깅), pkgDir(Capacitor/Electron.create), distPath(build), config.capacitor/electron/exclude(설정), hasUntrackedError(에러 추적). this._logger는 인스턴스 멤버로 접근 가능]

메서드 본문은 394-433행의 코드를 그대로 이동한다. 호출부에서는 `if (result.success)` 가드 내에서 `distPath` 계산 후 호출한다.

### 대안 검토

| 접근 방식 | 선택 | 이유 |
|-----------|------|------|
| hasUntrackedError 참조 전달 | 채택 | 원본 패턴 유지, 호출부 변경 최소화 |
| boolean 반환으로 변경 | 미채택 | 호출부에서 결과를 다시 hasUntrackedError에 반영해야 하여 오히려 복잡해짐 |
| config에서 capacitor/electron/exclude만 추출 | 미채택 | 파라미터 3개 추가는 시그니처를 비대하게 만듦. SdClientPackageConfig 전달이 간결 |
