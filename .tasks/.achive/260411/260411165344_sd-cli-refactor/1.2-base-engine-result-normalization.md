## 구현계획

### 배경

BaseEngine의 3개 서브클래스(TscEngine, NgtscEngine, ServerEsbuildEngine)가 `_callBuild()`에서 동일한 result normalization 코드를 반복한다. Worker가 반환하는 `errors?`/`warnings?`(optional)를 EngineResult의 `errors`/`warnings`(required)로 변환하는 8줄 코드이다.

### 목표

- BaseEngine에 `_normalizeResult()` protected 메서드를 추가하여 중복 제거 [근거: Rule "_normalizeResult는 Worker 결과를 EngineResult로 변환한다"]
- 3개 서브클래스의 `_callBuild()` 반환문을 단일 메서드 호출로 단순화 [근거: Rule "3개 서브클래스의 _callBuild는 동일한 _normalizeResult를 사용한다"]

### 비목표

- EsbuildClientEngine 변경 [근거: wbs 경계 "BaseEngine을 상속하지 않으므로 대상 아님"]
- Worker 측 결과 구조 변경 [근거: wbs 경계]

### 설계

BaseEngine에 다음 protected 메서드를 추가한다:

```typescript
protected _normalizeResult(result: {
  build: { success: boolean; errors?: string[]; warnings?: string[]; diagnostics: SerializedDiagnostic[] };
  lint?: LintWithProgramResult;
}): EngineResult {
  return {
    build: {
      success: result.build.success,
      errors: result.build.errors ?? [],
      warnings: result.build.warnings ?? [],
      diagnostics: result.build.diagnostics,
    },
    lint: result.lint,
  };
}
```

- 입력 타입: 인라인 객체 리터럴 [근거: D1]
- `SerializedDiagnostic` import 추가 필요 (BaseEngine에 현재 없음)

### 대안 검토
