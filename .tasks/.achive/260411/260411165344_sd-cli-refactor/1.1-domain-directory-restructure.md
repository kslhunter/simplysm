## 구현계획

### 배경
sd-cli src/utils/에 41파일이 8개 이상의 도메인에 혼재하여 탐색이 어렵다. 27파일을 7개 도메인 디렉토리로 이동하는 순수 리팩토링이다. 기존 angular/ 디렉토리에는 2파일만 있고, runtime/에도 2파일만 있다. [근거: refactor.md STRUCT-001]

### 목표
- 도메인별 파일을 응집된 디렉토리에 배치한다 [근거: Rule "파일은 도메인 디렉토리로만 이동"]
- 모든 import 경로가 정확하게 갱신되어 typecheck + lint가 통과한다 [근거: Rule "이동 파일을 참조하는 모든 import 경로"]
- CLAUDE.md가 새 구조를 반영한다 [근거: Rule "CLAUDE.md 디렉토리 구조"]

### 비목표
- 파일 내용(로직) 변경 [근거: wbs 경계]
- utils/ 잔류 14파일의 이동 [근거: wbs 경계]
- tests/ 디렉토리 구조 변경 [근거: wbs 범위에 미포함]

### 설계
**이동 전략**: `git mv`로 파일을 이동하여 git이 rename으로 추적. 디렉토리가 없으면 `mkdir -p`로 생성 후 이동. [근거: D1]

**import 갱신 전략**: 도메인별로 파일 이동 후, 이전 경로 패턴을 grep으로 찾아 새 경로로 치환. .js 확장자 유무를 보존. [근거: D3]

**검증**: `pnpm typecheck sd-cli` + `pnpm lint sd-cli`로 모든 import가 올바른지 검증. [근거: wbs 전제조건]

### 대안 검토
1. **TypeScript path alias** — 향후 이동 시 경로 변경 불필요하지만, 기존 코드베이스가 상대 경로를 사용하고 있고 alias 도입은 범위 초과. 미채택.
2. **한 번에 전부 이동 vs 도메인별 순차 이동** — 도메인별 순차 이동이 중간 검증 가능하고 에러 추적 용이. 채택. [근거: D2]

### Vertical Slicing

#### [x] Slice 1: 파일 이동 + import 경로 갱신 + 문서 갱신
- **구현 내용:** 7개 도메인별로 순차 처리: (1)angular (2)esbuild (3)dev-server (4)lint (5)typecheck (6)deps (7)runtime. 각 도메인: `mkdir -p` → `git mv` → 이동 파일 내부 교차 도메인 import 갱신 → 외부에서 참조하는 import 갱신 → tests/ import 갱신. 최종 CLAUDE.md 갱신 + typecheck + lint 검증.
- **Scenarios:** Angular 도메인 5파일 이동, 6개 신설 디렉토리로 22파일 이동, src/ 내부 import 경로 갱신, tests/ 내부 import 경로 갱신, 교차 도메인 참조 갱신, .js 확장자 보존, CLAUDE.md Architecture 섹션 갱신
