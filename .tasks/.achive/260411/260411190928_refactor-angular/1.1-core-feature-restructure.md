## 구현계획

### 배경

`packages/angular/src/core/`가 Angular 스타일 가이드에 반하는 종류별(type-based) 디렉토리 구조를 사용하며, 동일 인프라 계층인 modal/, toast/, busy/, print/, navigation/이 feature 디렉토리와 같은 top-level에 혼재한다. import 의존성 분석으로 14개 기능 클러스터가 식별되었다 (refactor.md STRUCT-001). [근거: wbs "배경"]

### 목표

- core/를 14개 기능 클러스터 + loose files로 재구조화 [근거: Rule "core/ 내부는 기능별 클러스터로 구조화"]
- 인프라 5개 디렉토리를 core/ 하위로 이동 [근거: Rule "인프라 디렉토리는 core/ 하위에 위치"]
- provideSdAngular.ts를 core/ 루트로 이동 [근거: Rule "provideSdAngular.ts는 core/ 루트에 위치"]
- tests/ 디렉토리를 src/ 미러링 유지 [근거: 설계 결정 D1]

### 비목표

- 코드 로직 변경 [근거: wbs 경계 "코드 로직 변경 없음"]
- feature 디렉토리(button/, sheet/ 등) 내부 구조 변경 [근거: wbs 경계]
- scss/ 디렉토리 이동 [근거: wbs 제외 사항 "빌드 설정에 영향"]

### 설계

#### 파일 이동 전략

- `git mv`로 파일 이동하여 git 히스토리 보존 [근거: Rule "public API 보존"]
- 각 파일 이동 후 해당 파일 내부의 import 경로 수정
- 이동된 파일을 참조하는 외부 파일의 import 경로 수정

#### 클러스터 내부 cross-dependency (코드베이스에서 확인)

이동 후 클러스터 간 참조 관계 (상대경로 수정 필요):
- routing/ → core/modal/ (injectViewTitle, injectViewType, setupCanDeactivate → SdActivatedModalProvider)
- routing/ → app-structure/ (injectViewTitle → SdAppStructureProvider)
- events/ → events/ (sd-events → sd-resize-event, 동일 클러스터 내)
- validation/ → core/ 루트 (setupInvalid → setSafeStyle)
- error-handler/ → config/ (sd-global-error-handler → sd-system-log)
- service-client/ → core/toast/ (sd-service-client-factory → SdToastProvider)

#### import 경로 수정 범위

1. **core/ 내부 cross-reference** (12개 파일): 클러스터 간 상대경로 갱신
2. **외부 src → core/** (약 40개 파일): feature 디렉토리의 `../core/` 참조 갱신
3. **index.ts** (약 70개 export 문): 경로 갱신
4. **provideSdAngular.ts** (11개 import 문): 새 위치 기준 경로 갱신
5. **tests/**: import 경로 갱신 + 디렉토리 이동
