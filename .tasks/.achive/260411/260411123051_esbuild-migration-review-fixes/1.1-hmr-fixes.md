Feature: 1.1 HMR 수정

    Given esbuild 기반 Angular 클라이언트 빌드 시스템이 구성되어 있다

  Rule: dev 모드에서 HMR 활성화 시 ngHmrMode를 "true"로 define한다

      Then esbuild define에 ngHmrMode가 "true"로 설정된다

    Scenario: build 모드에서는 ngHmrMode가 "false"
      Given mode가 "build"이다
      When createClientEsbuildContext를 호출한다
      Then esbuild define에 ngHmrMode가 "false"로 설정된다

      Given mode가 "dev"이고 templateUpdates가 undefined이다

      Then esbuild define에 ngHmrMode가 포함되지 않는다

  Rule: HmrService 인터페이스에서 미사용 onBuildStart를 제거한다
    # 근거: DESIGN-003, sd-hmr-reset 플러그인이 templateUpdates.clear() 담당

    Scenario: HmrService 반환 객체에 onBuildStart가 없다
      Given createHmrService를 호출한다
      When 반환된 객체의 프로퍼티를 확인한다
      Then onBuildStart 메서드가 존재하지 않는다

  Rule: css-update 메시지 수신 시 변경된 CSS 파일의 link만 업데이트한다
    # 근거: DESIGN-005, 불필요한 네트워크 요청 방지

    Scenario: 변경된 CSS 파일과 매칭되는 link만 cache-busting 적용
      Given link[rel="stylesheet"] 태그가 main.css, vendor.css를 참조한다
      When css-update 메시지가 files: ["main.css"]로 수신된다
      Then main.css link의 href에만 ?t=timestamp가 추가된다
      And vendor.css link의 href는 변경되지 않는다

    # 근거: LOGIC-003, URLSearchParams.get()이 이미 디코딩 수행

      Given templateUpdates에 "AppComponent" 키가 저장되어 있다
      When /@ng/component?c=AppComponent 요청이 들어온다
      Then templateUpdates.get("AppComponent")로 조회하여 응답한다

## 구현계획

### 배경
esbuild 기반 Angular 클라이언트 빌드 시스템의 HMR 관련 이슈 4건을 수정한다. `esbuild-client-config.ts`의 define 설정에서 ngHmrMode가 dev 모드에서 정의되지 않아 Angular HMR이 비작동하는 것이 핵심 이슈이다.

### 목표
- dev 모드에서 Angular HMR 정상 작동 (ngHmrMode define) [근거: LOGIC-001]
- HmrService 인터페이스 정리 (미사용 onBuildStart 제거) [근거: DESIGN-003]
- CSS HMR 최적화 (변경 파일만 link 업데이트) [근거: DESIGN-005]
- componentId 조회 정확성 (불필요한 인코딩 제거) [근거: LOGIC-003]

### 비목표
- 빌드 파이프라인/서버 수정 (Feature 1.2) [근거: wbs 경계]
- 기존 테스트 대폭 변경 [근거: wbs 경계]

### 설계

1. **ngHmrMode define 수정** (`esbuild-client-config.ts:118-124`) [근거: LOGIC-001, D1]
   - 기존: `!isDev` 조건만으로 `"false"` 설정
   - 변경: `isDev && templateUpdates != null && legacyModule !== true` → `"true"`, `!isDev` → `"false"`
   - isDev 체크로 build 모드에서 HMR 활성화 방지

2. **onBuildStart 제거** (`hmr-service.ts`) [근거: DESIGN-003, D2]
   - 인터페이스에서 `onBuildStart(): void` 제거 (line 19)
   - 구현 함수 제거 (line 45-47)
   - 반환 객체에서 제거 (line 183)

3. **css-update link 필터링** (`hmr-client-script.ts:29-36`) [근거: DESIGN-005]
   - link href에서 파일명 추출 (`base.split("/").pop()` 또는 `base.substring(base.lastIndexOf("/") + 1)`)
   - `msg.files`에 포함된 파일명과 매칭되는 link만 timestamp 업데이트
   - Chrome 61+ 호환: `var`, `indexOf`, no `?.`/`??`

4. **encodeURIComponent 제거** (`hmr-service.ts:164`) [근거: LOGIC-003]
   - `encodeURIComponent(componentId)` → `componentId`

### 대안 검토
- LOGIC-001 대안: build 함수에서 templateUpdates 미전달 → Feature 1.2 범위 침범. isDev 추가가 최소 수정
- DESIGN-003 대안: sd-hmr-reset 제거하고 onBuildStart 호출 → client.worker.ts 수정 = Feature 1.2 범위
