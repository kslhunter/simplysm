## 구현계획

### 배경

Feature 1.1에서 provider/component 동거와 provideSdAngular.ts 루트 이동이 완료되었다. 현재 src/에는 core/ (범용 인프라), ui/ (UI 컴포넌트), features/ (도메인 추상) 3-layer가 남아있다. 업계 표준(Angular Material, NG-ZORRO 등)에서는 기능 단위 플랫 구조를 사용하며, 현재 layer 중간 디렉토리(overlay/, form/, data/ 등)는 탐색을 방해하고 provider 배치 혼란을 유발한다. [근거: wbs "3-layer 구조는 provider 배치 혼란을 유발"]

### 목표

- ui/, features/ 하위의 모든 기능 폴더를 src/ 직하로 올려 플랫 구조 전환 [근거: Rule "ui/features 하위를 src/ 직하로 올린다"]
- data-view/ 폴더를 기능별로 3분할 (data-sheet, data-detail, data-select-button) [근거: Rule "data-view 폴더 분배"]
- 테스트 디렉토리를 새 구조에 맞춰 미러링 이동 [근거: D1]
- CLAUDE.md 아키텍처 섹션을 새 구조 반영으로 업데이트

### 비목표

- 파일 내용(로직, 타입, 시그니처) 변경 [근거: wbs 경계]
- 공개 API(index.ts export 이름/타입) 변경 [근거: wbs 경계]
- core/ 내부 구조 변경 [근거: wbs "core/는 범용 인프라만 잔류"]

#### Import 경로 업데이트 규칙

1. **이동 파일 간 같은 폴더 참조:** `./filename`으로 단순화 (예: `../../ui/overlay/toast/sd-toast` → `./sd-toast`)
2. **이동 파일 → core/ 참조:** 상대 경로 재계산 (예: `../../core/utils/` → `../core/utils/`)
3. **이동 파일 → 다른 이동 폴더 참조:** 상대 경로 재계산 (예: `../../ui/overlay/toast/sd-toast.provider` → `../toast/sd-toast.provider`)
4. **core/ 파일 → 이동 파일 참조:** 상대 경로 재계산 (예: `../../ui/overlay/modal/sd-activated-modal.provider` → `../../modal/sd-activated-modal.provider`)
5. **index.ts:** 모든 export 경로를 새 위치에 맞게 업데이트
6. **테스트 파일:** src/ 소스 import 경로를 새 위치에 맞게 업데이트
