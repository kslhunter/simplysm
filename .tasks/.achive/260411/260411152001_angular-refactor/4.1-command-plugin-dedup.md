## 구현계획

### 배경

3개 커맨드 플러그인이 `addEventListener` 내에서 동일한 모달 체크 패턴을 반복한다:

```typescript
const topModal = findTopOpenModalEl(this._document);
if (topModal != null && !topModal.contains(element)) return;
```

이 2줄이 3개 파일에서 동일하게 반복된다. [근거: STRUCT-003]

### 목표

- 모달 체크 로직을 `shouldProcessCommandEvent()` 헬퍼로 추출하여 중복 제거 [근거: Rule "헬퍼 함수는 모달 컨텍스트를 정확히 판단한다"]

### 비목표

- 플러그인의 키 조합 매칭 로직 통합 [근거: wbs 경계 "플러그인의 외부 동작은 변경하지 않음"]
- `preventDefault`/`stopPropagation`/`handler` 호출 추출 [근거: D1 — predicate은 판단만 수행]

### 설계

`findTopOpenModalEl.ts`에 추가할 함수:

```typescript
/**
 * 커맨드 이벤트를 처리해야 하는지 판단한다.
 * 열린 모달이 없거나, element가 최상위 모달 내부에 있으면 true.
 */
export function shouldProcessCommandEvent(doc: Document, element: HTMLElement): boolean {
  const topModal = findTopOpenModalEl(doc);
  return topModal == null || topModal.contains(element);
}
```

각 플러그인의 변경:

```typescript
// Before
const topModal = findTopOpenModalEl(this._document);
if (topModal != null && !topModal.contains(element)) return;

// After
if (!shouldProcessCommandEvent(this._document, element)) return;
```

import 변경: `findTopOpenModalEl` → `shouldProcessCommandEvent`

### 대안 검토

| 대안 | 설명 | 불채택 사유 |
|------|------|------------|
| `processCommandEvent(doc, el, event, handler)` | preventDefault, stopPropagation, handler 호출까지 포함하는 전체 처리 함수 | 단일 책임 위반, 이벤트 처리 흐름이 헬퍼에 숨겨져 가독성 저하, WBS 제안명과 불일치 |
