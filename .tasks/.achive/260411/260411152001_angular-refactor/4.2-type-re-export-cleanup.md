## 구현계획

### 배경

`sd-app-structure.types.ts`는 `@simplysm/service-common`의 `AppStructureItem` 등 5개 타입을 re-export하면서 동시에 `SdMenu`, `SdFlatMenu`, `SdPermission` 로컬 타입을 정의하고 있다. 이 혼합 구조가 타입의 출처를 불명확하게 만든다. [근거: DESIGN-004]

`@simplysm/angular` 패키지는 이미 `@simplysm/service-common`에 의존하고 있어(`package.json:38`), 내부 파일에서 직접 import하는 것이 자연스럽다.

### 목표
- `sd-app-structure.types.ts`에서 외부 패키지 타입 re-export를 제거한다 [근거: Rule "re-export 타입은 원본 패키지에서 직접 import"]
- `index.ts`에서 re-export 타입의 public export를 제거한다 [근거: 코딩 규칙 "다른 패키지의 타입등 re-export 금지"]

### 비목표
- 로컬 타입(`SdMenu`, `SdFlatMenu`, `SdPermission`)의 변경 [근거: wbs 경계]
- `SdAppStructureUtils`나 `SdAppStructureProvider`의 로직 변경

### 설계

**변경 파일 5개:**

1. `src/core/providers/sd-app-structure.types.ts` — re-export 블록(1-7줄) 제거
2. `src/core/providers/sd-app-structure.provider.ts:4` — `AppStructureItem` import를 `@simplysm/service-common`으로 변경
3. `src/core/providers/sd-app-structure.utils.ts:6-11` — `AppStructureItem` import를 `@simplysm/service-common`으로 이동 (기존 import 블록 `1-5`줄에 합침)
4. `src/index.ts:38-44` — `AppStructureItem`, `FlatPermission` export 제거, `SdMenu`, `SdFlatMenu`, `SdPermission`만 유지
5. `tests/core/providers/app-structure-provider.spec.ts:8` — `AppStructureItem` import를 `@simplysm/service-common`으로 변경

### 대안 검토
- **re-export를 유지하되 주석으로 출처 표기**: 타입 혼합 문제 미해결, 코딩 규칙 위배 → 미선택
- **deprecated 표기 후 점진적 제거**: 모노레포 내 외부 소비자 0건이므로 불필요 → 미선택
