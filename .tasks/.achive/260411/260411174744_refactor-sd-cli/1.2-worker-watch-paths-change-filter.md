## 구현계획

### 배경

3개 빌드 워커(library-build, ngtsc-build, server-build)가 `collectDeps()` 호출 후 glob 패턴 기반 watchPaths 배열을 구성하는 ~25줄 코드와, `hasFileAddOrRemove` + `lastSourceFilePaths` 교차 필터링 ~15줄 코드를 각각 반복하고 있다. Feature 1.1에서 추출한 `shared-worker-lifecycle.ts`와 같은 방식으로 workers/ 디렉토리에 공통 유틸리티를 추가한다.

### 목표

- 감시 경로 수집 ~75줄 중복을 단일 함수로 통합 [근거: Rule "collectDeps + glob 조합은 단일 함수 호출로 대체된다"]
- 변경 필터링 ~45줄 중복을 공통 함수로 추출 [근거: Rule "lastSourceFilePaths 기반 건너뜀 필터는 library-build, ngtsc-build에서 공유된다"]

### 비목표

- server-build의 metafile 기반 변경 필터링 수정 [근거: WBS 경계 "server-build의 esbuild metafile 기반 필터링 로직 자체는 변경하지 않음"]
- client.worker.ts 수정 [근거: WBS 경계 "Vite가 자체 감시를 수행"]
- 각 워커의 빌드/리빌드 로직 변경 [근거: WBS 경계]

### 설계

#### `workers/build-watch-paths.ts` 신규 파일

```typescript
import { pathx } from "@simplysm/core-node";
import { collectDeps, type DepsResult } from "../deps/collect-deps";

export interface BuildWatchPathsOptions {
  pkgDir: string;
  cwd: string;
  /** 자체 src 디렉토리 내 glob 패턴 (예: "*.ts", "*.{ts,scss,css}", "*") */
  srcGlobs: string[];
  /** src 외에 추가로 감시할 디렉토리와 해당 glob */
  extraDirs?: Array<{ dir: string; globs: string[] }>;
  /** sd.config.ts의 replaceDeps 설정 */
  replaceDeps?: Record<string, string>;
}

export interface BuildWatchPathsResult {
  watchPaths: string[];
  deps: DepsResult;
}

export function buildWatchPaths(options: BuildWatchPathsOptions): BuildWatchPathsResult {
  const { pkgDir, cwd, srcGlobs, extraDirs, replaceDeps: replaceDepsConfig } = options;
  const deps = collectDeps(pkgDir, cwd, replaceDepsConfig);

  const watchDirs = [
    pkgDir,
    ...deps.workspaceDeps.map((d) => pathx.posixResolve(cwd, "packages", d)),
  ];

  const watchPaths: string[] = [];

  for (const dir of watchDirs) {
    for (const glob of srcGlobs) {
      watchPaths.push(pathx.posixResolve(dir, "src", "**", glob));
    }
    if (extraDirs != null) {
      for (const extra of extraDirs) {
        for (const glob of extra.globs) {
          watchPaths.push(pathx.posixResolve(dir, extra.dir, "**", glob));
        }
      }
    }
  }

  for (const pkg of deps.replaceDeps) {
    watchPaths.push(pathx.posixResolve(cwd, "node_modules", ...pkg.split("/"), "dist", "**", "*.{js,mjs,cjs}"));
    watchPaths.push(pathx.posixResolve(pkgDir, "node_modules", ...pkg.split("/"), "dist", "**", "*.{js,mjs,cjs}"));
  }

  return { watchPaths, deps };
}
```

[근거: Rule "collectDeps + glob 조합은 단일 함수 호출로 대체된다"]

#### `workers/build-change-filter.ts` 신규 파일

```typescript
import type { ConsolaInstance } from "consola";

export interface FsChange {
  event: string;
  path: string;
}

export function hasFileAddOrRemove(changes: FsChange[]): boolean {
  return changes.some((c) => c.event === "add" || c.event === "unlink");
}

export function shouldSkipRebuild(
  filePaths: Iterable<string>,
  hasAddOrRemove: boolean,
  lastSourceFilePaths: Set<string> | undefined,
  logger: ConsolaInstance,
): boolean {
  if (hasAddOrRemove) return false;
  if (lastSourceFilePaths == null) return false;

  for (const p of filePaths) {
    if (lastSourceFilePaths.has(p)) return false;
  }

  logger.debug("변경된 파일이 빌드에 포함되지 않아 리빌드 건너뜀");
  return true;
}
```

[근거: Rule "hasFileAddOrRemove 판단은 공통 함수로 추출된다" + Rule "lastSourceFilePaths 기반 건너뜀 필터"]

### 대안 검토

| 대안 | 선택하지 않은 이유 |
|------|------------------|
| 3개 워커의 변경 필터링도 모두 통합 | server-build는 metafile 기반 전략이 완전히 다르므로 무리한 추상화 |
| `buildWatchPaths`에 `collectDeps`를 내부 호출하지 않고 결과만 받기 | 3개 워커 모두 `collectDeps` 직후 watchPaths를 구성하므로 함께 호출하는 것이 사용 편의성 높음 |
| `extraDirs` 대신 `srcGlobs`를 모든 디렉토리에 적용 | ngtsc의 scss/ 디렉토리는 `*.{scss,css}` glob을 사용하여 src/의 `*.{ts,scss,css}`와 다름 — 정확한 재현 불가 |
