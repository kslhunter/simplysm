## 구현계획

- Utilities (50~260줄): `replaceEnvVariables`, `waitWithCountdown`, `ensureSshAuth` + SSH 헬퍼 3개

**index.ts의 publishPackage 변환:**

기존 단일 함수의 type 분기를 각 publisher 호출로 교체:

```typescript
import { publishNpm } from "./npm-publisher";
import { publishToStorage } from "./storage-publisher";
import { publishToLocal } from "./local-publisher";

async function publishPackage(
  pkgPath: string,
  publishConfig: SdPublishConfig,
  version: string,
  projectPath: string,
  logger: ReturnType<typeof consola.withTag>,
  dryRun: boolean,
): Promise<void> {
  const pkgName = path.basename(pkgPath);

  if (publishConfig.type === "npm") {
    await publishNpm(pkgPath, pkgName, version, logger, dryRun);
  } else if (publishConfig.type === "local-directory") {
    const targetPath = replaceEnvVariables(publishConfig.path, version, projectPath);
    await publishToLocal(pkgPath, pkgName, targetPath, logger, dryRun);
  } else {
    await publishToStorage(pkgPath, pkgName, publishConfig, logger, dryRun);
  }
}
```

**테스트 mock 경로 변경:**

테스트에서 `vi.mock("../../src/commands/publish")` 경로는 사용하지 않음 (직접 import). 
내부적으로 publisher 모듈을 import하므로 기존 mock이 transitive하게 작동:
- `@simplysm/core-node` mock → `publishToLocal`의 `fsx.copy` 커버
- `@simplysm/storage` mock → `publishToStorage`의 `StorageFactory.connect` 커버
- `ssh2` mock → `ensureSshAuth`의 SSH 클라이언트 커버
- `@simplysm/core-node` cpx.spawn mock → `publishNpm`의 `pnpm publish` 커버

### 대안 검토

1. **기능별 더 세밀한 분할 (version.ts, deploy-levels.ts)** — `upgradeVersion`(55줄), `computePublishLevels`(55줄)도 별도 파일로 분할 가능. 하지만 WBS가 "배포 전략별 분할"을 명시하고, 이들은 오케스트레이션 관심사이므로 main에 유지.

2. **publishPackage 디스패치 함수 제거** — `runPublish`에서 직접 각 publisher를 호출. 가능하나, 기존 디스패치 구조를 유지하면 호출부 변경이 최소화되고 재시도 로직과의 결합도 유지됨.
