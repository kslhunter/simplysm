## 구현계획

### 배경

현재 `TypecheckOrchestrator.initialize()`에서 client target 패키지의 config를 `{ target: "browser" }` 로 변환한 후 `createBuildEngine`에 전달한다. 이는 엔진 선택이라는 팩토리의 책임을 오케스트레이터가 일부 수행하는 것이다. [근거: ARCH-001]

### 목표

- `createTypecheckEngine()` 팩토리 함수를 신설하여 typecheck용 엔진 선택 로직을 팩토리에 집중 [근거: Rule "config 변환은 팩토리 내부에서 수행"]
- TypecheckOrchestrator에서 target 변환 로직 제거 [근거: Rule "client target typecheck 시 TscEngine/NgtscEngine으로 라우팅"]
- 기존 빌드 라우팅 동작 불변 [근거: Rule "기존 빌드 라우팅 동작 불변"]

### 비목표

- 엔진 팩토리의 기존 선택 로직 변경 [근거: WBS 경계 "엔진 팩토리의 다른 선택 로직은 변경하지 않음"]
- TypecheckOrchestrator의 기타 로직(패키지 분류, 결과 집계 등) 변경

### 설계

#### `createTypecheckEngine()` 함수 (`engines/index.ts`)

client target을 browser로 재매핑하여 `createBuildEngine`에 위임하는 얇은 래퍼:

```typescript
export function createTypecheckEngine(
  pkg: BuildPackageInfo | ServerPackageInfo | ClientPackageInfo,
  options: { cwd: string },
): BuildEngine {
  if (pkg.config.target === "client") {
    const browserPkg: BuildPackageInfo = {
      ...pkg,
      config: { target: "browser" as const },
    };
    return createBuildEngine(browserPkg, options);
  }
  return createBuildEngine(pkg, options);
}
```

[근거: D1 "createTypecheckEngine() 별도 함수 신설"]

#### `TypecheckOrchestrator` 변경 (`orchestrators/TypecheckOrchestrator.ts`)

1. import를 `createBuildEngine` → `createTypecheckEngine`으로 변경
2. `initialize()`에서 target 변환 로직(line 134-136) 제거, 원본 config를 그대로 task에 저장
3. `_executePackageTypechecks()`에서 `createBuildEngine` → `createTypecheckEngine` 호출로 변경

#### `engines/index.ts` export

`createTypecheckEngine`을 `index.ts`의 export에 추가

### 대안 검토

`createBuildEngine`에 `typecheckOnly` 옵션 추가 방안을 검토했으나, 빌드 함수 시그니처에 typecheck 관심사가 혼입되고 조건 분기 복잡도가 증가하여 채택하지 않음 [근거: D1].
