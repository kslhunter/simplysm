## 구현계획

### 배경
`capacitor.ts`(796줄)는 Capacitor 프로젝트의 초기화, 기기 실행, 프로덕션 빌드, 아이콘 생성을 단일 클래스에서 처리한다. 동일 디렉토리의 `capacitor-android.ts`는 이미 standalone 함수로 분리되어 있어, 이 패턴을 따라 빌드/아이콘 로직을 추출한다. [근거: DESIGN-004]

### 목표
- 빌드 관련 로직(서명 설정, Gradle 실행, 산출물 복사)을 `capacitor-build.ts`로 추출 [근거: wbs "capacitor-build.ts — Gradle 빌드 + 서명 설정 + 출력 복사"]
- 아이콘 생성 로직을 `capacitor-icon.ts`로 추출 [근거: wbs "capacitor-icon.ts — Sharp 아이콘 생성"]
- Capacitor 클래스의 public API 유지 [근거: wbs "외부 API 변경 최소화"]

### 비목표
- `capacitor-android.ts` 변경 [근거: wbs 경계 "현재 구조 유지 (이미 분리됨)"]
- Capacitor 기능의 동작 변경 [근거: wbs 경계 "Capacitor 기능의 동작 변경 없음"]
- 새로운 기능 추가

### 설계

#### capacitor-build.ts 구조

`capacitor-android.ts`와 동일한 standalone 함수 패턴. 각 함수는 필요한 매개변수를 명시적으로 받는다. [근거: D1]

```typescript
// src/capacitor/capacitor-build.ts
import type { SdCapacitorSignConfig } from "../sd-config.types.js";

export async function configureSigningConfig(
  pkgPath: string,
  androidPath: string,
  sign: SdCapacitorSignConfig,
): Promise<void>;

export async function buildAndroid(
  capPath: string,
  buildType: string,
  isBundle: boolean,
): Promise<void>;

export async function copyBuildOutput(
  capPath: string,
  outPath: string,
  buildType: string,
  isBundle: boolean,
  appName: string,
  version: string,
): Promise<void>;
```

- `configureSigningConfig`: keystore 파일 복사 + build.gradle에 signingConfigs 블록 삽입. fsx만 사용 (exec 불필요)
- `buildAndroid`: Windows/Linux 분기 처리, `cpx.spawn`으로 Gradle 직접 실행. 자체 logger 보유 [근거: D3]
- `copyBuildOutput`: glob으로 산출물 검색, fsx.copy로 latest/versioned 파일 복사

#### capacitor-icon.ts 구조

```typescript
// src/capacitor/capacitor-icon.ts
export async function setupIcon(
  pkgPath: string,
  capPath: string,
  iconRelPath: string,
): Promise<void>;
```

- sharp 동적 import → 소스 이미지 리사이즈(60% of 1024) → 1024x1024 투명 캔버스 합성 → `capacitor-assets generate` 실행
- icon 파일 미존재 시 warn 로그 후 return (기존 동작 유지)
- `cpx.spawn`으로 capacitor-assets 직접 실행 [근거: D3]

#### capacitor.ts 변경

`build()` 메서드는 클래스에 유지 [근거: D2]. 내부에서 추출된 함수를 호출:

```typescript
// build() 메서드 변경 전
private async _configureSigningConfig(...) { ... }  // 삭제
private async _buildAndroid(...) { ... }             // 삭제
private async _copyBuildOutput(...) { ... }          // 삭제

// build() 메서드 변경 후
import { configureSigningConfig, buildAndroid, copyBuildOutput } from "./capacitor-build.js";

async build(outPath: string): Promise<void> {
  await this._execCap(["copy"]);
  // ... buildType/isBundle 결정 로직 유지
  if (!isDebug && signConfig != null) {
    await configureSigningConfig(this._pkgPath, androidPath, signConfig);
  }
  await buildAndroid(this._capPath, buildType, isBundle);
  await copyBuildOutput(this._capPath, outPath, buildType, isBundle, this._config.appName, this._npmConfig.version);
}
```

`initialize()` 메서드에서 아이콘 처리 변경:

```typescript
// 변경 전
private async _setupIcon() { ... }  // 삭제

// 변경 후
import { setupIcon } from "./capacitor-icon.js";

async initialize(): Promise<void> {
  // ... 기존 단계 1~3 유지
  // 4. 아이콘 처리
  if (this._config.icon != null) {
    await setupIcon(this._pkgPath, this._capPath, this._config.icon);
  }
  // ... 기존 단계 5~6 유지
}
```

### 대안 검토

| 접근 방식 | 장점 | 단점 | 선택 |
|-----------|------|------|------|
| standalone 함수 (선택) | capacitor-android.ts 패턴 일관성, 테스트 용이 | 매개변수가 많아질 수 있음 | O |
| 별도 클래스 (CapacitorBuilder, CapacitorIcon) | 상태 캡슐화 | 패턴 불일치, 과도한 추상화 | X |
| Capacitor 클래스 내 private 영역 분리만 (region) | 변경 최소 | 파일 크기 미감소, 리팩토링 목표 미달성 | X |
