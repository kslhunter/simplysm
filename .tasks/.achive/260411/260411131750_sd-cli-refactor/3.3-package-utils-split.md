## 구현계획

### 배경

`package-utils.ts`(397줄)에 패키지 분류, 의존성 수집, 워크스페이스 탐색/검증이라는 세 가지 책임이 혼재되어 있다. 이 중 "패키지 분류"와 "의존성 수집"을 별도 파일로 추출하여 단일 책임 원칙을 달성한다.

### 목표
- 패키지 분류 함수를 `package-classify.ts`로 추출 [근거: Rule "패키지 분류 함수들은 package-classify.ts에 집약"]
- 의존성 수집 함수를 `collect-deps.ts`로 추출 [근거: Rule "의존성 수집 함수들은 collect-deps.ts에 집약"]
- 모든 사용처의 import 경로를 정확히 업데이트 [근거: Rule "기존 테스트가 모두 통과"]

### 비목표
- 함수 시그니처, 동작, 반환 타입 변경 [근거: wbs 경계 "기능의 동작 변경 없음"]
- 새로운 유틸리티 함수 추가 [근거: wbs 경계]

### 설계

**분할 후 파일 구조:**


- `collect-deps.ts` → `package-utils.ts`의 `discoverWorkspacePackages`를 import (buildWorkspacePkgMap이 내부에서 호출)

### 대안 검토

**2파일 분할 (분류 + 의존성) vs 분할 안 함:** wbs에서 명시한 목표이므로 분할이 적절. 나머지를 원래 파일에 유지함으로써 변경 범위를 최소화.

**3파일로 완전 분할 (워크스페이스 탐색도 분리) vs 2파일:** 워크스페이스 탐색/검증 함수들은 ~150줄로 단일 파일에 적절한 크기이며, wbs 범위에서도 2그룹 분할만 명시. 과도한 분할은 불필요.
