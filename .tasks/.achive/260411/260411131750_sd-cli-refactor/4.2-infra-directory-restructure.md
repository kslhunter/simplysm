## 구현계획

### 배경

`src/infra/` 디렉토리에는 `ResultCollector.ts`(45줄)와 `SignalHandler.ts`(42줄) 2개 파일만 존재한다. "infra"는 일반적으로 광범위한 인프라를 의미하지만, 실제 내용은 런타임 결과 수집과 프로세스 시그널 처리뿐이다. Feature 1.1에서 `BaseOrchestrator`가 도입되어 두 클래스를 인프라로 사용하고 있으며, engines에서도 `ResultCollector`를 참조한다.

### 목표
- `infra/` → `runtime/`으로 디렉토리명을 변경하여 실제 내용을 반영한다 [근거: Rule "디렉토리명은 실제 내용을 반영"]
- 모든 import 경로를 누락 없이 업데이트한다 [근거: Rule "import 경로 업데이트"]
- `packages/sd-cli/CLAUDE.md`의 디렉토리 구조 설명도 업데이트한다

### 비목표
- 새로운 유틸리티 추가 [근거: wbs 경계 "위치 변경만"]
- ResultCollector, SignalHandler의 코드 변경 [근거: wbs "기능 변경 없이 구조만 개선"]

### 설계

단순 디렉토리 rename + import 경로 일괄 치환이다.

**변경 대상 (총 18개 파일):**

src/ (11개 import 변경):
- `engines/BaseEngine.ts` — `../infra/` → `../runtime/`
- `engines/EsbuildClientEngine.ts` — `../infra/` → `../runtime/`
- `engines/NgtscEngine.ts` — `../infra/` → `../runtime/`
- `engines/ServerEsbuildEngine.ts` — `../infra/` → `../runtime/`
- `engines/TscEngine.ts` — `../infra/` → `../runtime/`
- `engines/index.ts` — `../infra/` → `../runtime/`
- `orchestrators/BaseOrchestrator.ts` — `../infra/` → `../runtime/` (2개 import)
- `orchestrators/ServerRuntimeManager.ts` — `../infra/` → `../runtime/`
- `utils/output-utils.ts` — `../infra/` → `../runtime/`
- `utils/worker-events.ts` — `../infra/` → `../runtime/`

tests/ (5개 import 변경):
- `engines/base-engine.spec.ts` — `../../src/infra/` → `../../src/runtime/`
- `runtime/result-collector.spec.ts` — `../../src/infra/` → `../../src/runtime/`
- `runtime/signal-handler.spec.ts` — `../../src/infra/` → `../../src/runtime/`
- `utils/output-utils.spec.ts` — `../../src/infra/` → `../../src/runtime/`
- `utils/worker-events.spec.ts` — `../../src/infra/` → `../../src/runtime/`

문서 (1개):
- `packages/sd-cli/CLAUDE.md` — 디렉토리 구조에서 `infra/` → `runtime/` 변경

| 대안 | 불채택 사유 |
