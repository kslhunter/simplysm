## 구현계획

### 배경

`SdClientPackageConfig.exclude`는 타입에 정의되어 있으나, `ViteEngine` → `ClientBuildInfo` → `CreateClientViteConfigOptions` → `createClientViteConfig()` 전달 경로가 미구현이다. 기존 코드베이스에서 `env`, `configs`, `browserSupport` 등의 설정이 동일한 경로로 전달되는 패턴이 확립되어 있다.

### 목표

- `sd.config.ts`의 `exclude` 설정을 Vite `optimizeDeps.exclude`에 전달하는 전체 경로 구현

### 비목표

- `exclude`의 build 모드 전용 동작 (optimizeDeps는 dev 전용이며, build에서는 무해하게 무시됨)
- `sdScopeWatchPlugin` 수정 (기존 plugin의 `optimizeDeps.exclude`와 Vite deep merge로 자연스럽게 병합)

### 설계

기존 `env`/`configs`/`browserSupport` 전달 패턴과 동일하게 4개 레이어에 `exclude` 필드를 추가한다:

1. **`ClientBuildInfo`** (`client.worker.ts`): `exclude?: string[]` 필드 추가
2. **`CreateClientViteConfigOptions`** (`vite-config.ts`): `exclude?: string[]` 필드 추가
3. **`createClientViteConfig()`** (`vite-config.ts`): `options.exclude`가 있으면 반환 config에 `optimizeDeps.exclude` 설정
4. **`ViteEngine.run()`/`startWatch()`** (`ViteEngine.ts`): `this._pkg.config.exclude`를 worker 호출에 전달

`sdScopeWatchPlugin`의 `config()` 훅에서도 `optimizeDeps.exclude`를 반환하므로, Vite의 `mergeConfig`가 두 배열을 합친다.

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| createClientViteConfig에서 optimizeDeps.exclude 직접 설정 | 채택 | 기존 패턴과 일관. build/dev 모두 동작 |
| sdScopeWatchPlugin에서 exclude 통합 처리 | 미채택 | SRP 위반. build 모드에서 sdScopeWatchPlugin 미사용으로 누락 위험 |
