# Feature 1.2 legacy dev 모드: vite build --watch 전환

## 참조 자료

- [wbs.md](./wbs.md)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | replaceDeps(sdScopeWatchPlugin) 동작 여부 | 동작해야 함 | replaceDeps를 사용하는 legacy 프로젝트에서도 의존성 변경 시 자동 리빌드 필요 |
| D2 | emptyOutDir 처리 | 첫 빌드만 비움 | 재빌드 시 dist가 비면 Feature 1.3의 HTTP 서버에서 파일 서빙 끊김. 첫 빌드만 비워 깨끗한 초기 상태 보장 |

## 요구명세

```gherkin
Feature: 1.2 legacy dev 모드: vite build --watch 전환

  Background:
    Given sd-cli의 client.worker.ts와 ViteEngine.ts가 존재한다
    And createClientViteConfig 함수가 Vite 설정을 생성한다

  Rule: legacyModule + dev 시 viteBuild --watch를 사용한다

    Scenario: legacyModule 활성화 + startWatch 호출 시 viteBuild watch 모드 실행
      Given legacyModule: true 옵션이 설정되어 있다
      When client.worker의 startWatch()를 호출한다
      Then createServer() 대신 viteBuild({ build: { watch: {} } })가 실행된다
      And RollupWatcher가 반환된다

    Scenario: legacyModule 미설정 + startWatch 호출 시 기존 dev server 실행
      Given legacyModule 옵션이 설정되지 않았다
      When client.worker의 startWatch()를 호출한다
      Then 기존대로 createServer()로 Vite dev server가 실행된다

    Scenario: legacyModule 활성화 + build 호출 시 기존 프로덕션 빌드 실행
      Given legacyModule: true 옵션이 설정되어 있다
      When client.worker의 build()를 호출한다
      Then 기존대로 viteBuild()가 실행된다 (변경 없음)

  Rule: RollupWatcher 이벤트를 worker 이벤트로 변환한다

    Scenario: watcher START 이벤트 수신 시 buildStart 발행
      Given legacy watch 모드로 viteBuild가 실행 중이다
      When RollupWatcher가 event code 'START'를 발행한다
      Then worker가 buildStart 이벤트를 발행한다

    Scenario: watcher END 이벤트 수신 시 build 발행
      Given legacy watch 모드로 viteBuild가 실행 중이다
      When RollupWatcher가 event code 'END'를 발행한다
      Then worker가 build 이벤트를 발행한다 (success: true)

    Scenario: watcher ERROR 이벤트 수신 시 error 발행
      Given legacy watch 모드로 viteBuild가 실행 중이다
      When RollupWatcher가 event code 'ERROR'를 발행한다
      Then worker가 error 이벤트를 발행한다 (에러 메시지 포함)

  Rule: RollupWatcher 생명주기를 관리한다

    Scenario: stopWatch 호출 시 watcher를 닫는다
      Given legacy watch 모드의 RollupWatcher가 실행 중이다
      When stopWatch()를 호출한다
      Then watcher.close()가 실행되어 파일 감시가 중단된다

    Scenario: watcher 없는 상태에서 stopWatch 호출 시 안전하게 무시한다
      Given legacy watch 모드가 시작되지 않았다
      When stopWatch()를 호출한다
      Then 에러 없이 정상 종료된다

  Rule: legacy watch 모드에서 replaceDeps 변경을 감지한다

    Scenario: replaceDeps 설정 시 sdScopeWatchPlugin이 활성화된다
      Given legacyModule: true이고 replaceDeps가 설정되어 있다
      When legacy watch 모드로 startWatch()를 호출한다
      Then sdScopeWatchPlugin이 Vite config에 포함된다
      And replaceDeps 변경 시 자동 리빌드가 트리거된다

  Rule: emptyOutDir은 첫 빌드에서만 활성화한다

    Scenario: 첫 빌드 시 dist 디렉토리를 비운다
      Given legacy watch 모드가 시작된다
      When 최초 빌드가 실행된다
      Then emptyOutDir: true로 dist 디렉토리가 비워진 후 빌드 결과가 기록된다

    Scenario: 재빌드 시 dist 디렉토리를 비우지 않는다
      Given legacy watch 모드에서 첫 빌드가 완료되었다
      When 파일 변경으로 재빌드가 트리거된다
      Then dist 디렉토리를 비우지 않고 변경된 파일만 덮어쓴다

  Rule: ViteEngine이 legacy watch 모드를 올바르게 처리한다

    Scenario: legacyModule 패키지의 startWatch가 serverReady 없이 완료된다
      Given legacyModule: true 패키지이다
      When ViteEngine.startWatch()를 호출한다
      Then serverReady 이벤트 없이 초기 빌드 완료 시 Promise가 resolve된다
      And port 프로퍼티는 설정되지 않는다
```

## 구현계획

### 배경

`client.worker.ts`의 `startWatch()`는 현재 `createServer()`로 Vite dev server를 생성한다. Vite dev server는 `/@vite/client` 내부에 `?.`, `import()`, `import.meta` 등 Chrome 61 미호환 구문을 사용하므로, `legacyModule: true` 프로젝트의 dev 모드에서 실기기 확인이 불가능하다.

`createClientViteConfig`는 `mode: "dev" | "build"`로 설정을 분기하며, `legacyModule` 플래그를 받아 `inlineDynamicImports: true`를 설정한다. `sdScopeWatchPlugin`은 현재 `mode === "dev"`에서만 추가된다.

`ViteEngine.startWatch()`는 worker의 `startWatch()`를 호출하고 `serverReady`, `buildStart`, `build`, `error` 이벤트를 구독한다. `port` 프로퍼티는 `serverReady` 이벤트로 설정되며, null-safe로 접근된다 (`DevWatchOrchestrator._getClientPort`, `output-utils`).

### 목표

- `legacyModule: true` + dev 시 `createServer()` 대신 `viteBuild({ build: { watch: {} } })` 사용
- RollupWatcher 이벤트를 기존 worker 이벤트 체계에 통합
- `sdScopeWatchPlugin`을 legacy watch 모드에서도 활성화
- dist 초기화를 첫 빌드에서만 수행

### 비목표

- HTTP 파일 서버 및 live reload (Feature 1.3)
- ViteEngine 코드 변경 (serverReady 미발생 시 port가 undefined로 남으며, 기존 null-safe 접근으로 정상 동작)
- 프로덕션 build 함수 변경

### 설계

#### vite-config.ts 변경

`CreateClientViteConfigOptions`에 `watch?: boolean` 옵션을 추가한다.

`watch: true`일 때의 동작:
- `build.watch = {}` 설정 (Rollup watcher 활성화)
- `emptyOutDir = false` 설정 (dist 초기화는 worker에서 수동 수행)
- `logLevel`을 `"silent"`로 설정하지 않음 (rebuild 로그 표시)
- `mode === "build"`이어도 `sdScopeWatchPlugin`을 포함 (`replaceDeps` 제공 시)

조건 변경:
- sdScopeWatchPlugin: `mode === "dev"` → `mode === "dev" || options.watch === true`
- build 설정: `emptyOutDir`을 `!options.watch`로 분기
- logLevel: `options.watch !== true`일 때만 `"silent"`

#### client.worker.ts 변경

`startWatch()`에서 `legacyModule` 분기:
- `legacyModule: true` → `startLegacyWatch()` 호출 (새 함수)
- `legacyModule: false/undefined` → 기존 `createServer()` 로직 유지

`startLegacyWatch()` 함수:
1. dist 디렉토리를 수동 삭제 (`fs.rmSync`)
2. `createClientViteConfig({ mode: "build", watch: true, pwa: false, ... })` 호출
3. `onBuildStart`/`onBuild` 콜백으로 `buildStart`/`build` 이벤트 발행 (sdAngularPlugin이 트리거)
4. `viteBuild(config)`를 호출하여 `RollupWatcher` 획득
5. `.config.json` 생성
6. RollupWatcher `event` 이벤트 구독:
   - `code: 'END'` → 첫 빌드 완료 시 Promise resolve
   - `code: 'ERROR'` → `error` 이벤트 발행 + 첫 빌드 시 Promise resolve (실패)
7. 첫 빌드 완료까지 대기 후 `ClientBuildResult` 반환

이벤트 중복 방지:
- `buildStart`/`build` 이벤트는 `onBuildStart`/`onBuild` 콜백으로만 발행 (sdAngularPlugin 경유)
- RollupWatcher `START`/`END` 이벤트는 첫 빌드 감지와 생명주기 관리에만 사용
- RollupWatcher `ERROR` 이벤트는 watcher 레벨 에러 처리에 사용

모듈 변수:
- `let rollupWatcher: RollupWatcher | undefined` 추가 (기존 `viteServer`와 병렬)

`stopWatch()` 변경:
- 기존 `viteServer?.close()` 후 `rollupWatcher?.close()` 추가

`import type { RollupWatcher } from "rollup"` 추가

#### ViteEngine.ts — 변경 없음

- `serverReady` 이벤트 미발생 시 `port`가 undefined로 남음 → 기존 null-safe 접근으로 정상 동작
- `buildStart`/`build`/`error` 이벤트 처리 로직 변경 불필요

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| `createClientViteConfig`에 3번째 모드 `"legacy-watch"` 추가 | 미채택 | mode 열거형 변경은 영향 범위가 크고, `watch` boolean 플래그가 더 조합적 |
| RollupWatcher 이벤트로 buildStart/build 발행 | 미채택 | sdAngularPlugin `onBuildStart`/`onBuild`와 중복. Angular 컴파일 상세 결과(lint 등)를 포함하는 기존 콜백이 더 적합 |
| `emptyOutDir: true`로 Vite에 위임 | 미채택 | Vite build --watch에서 매 rebuild마다 dist를 비울 수 있어 파일 서빙 끊김 위험 |
