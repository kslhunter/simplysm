# Feature 1.3 legacy dev 모드: HTTP 파일 서버 + live reload

## 참조 자료

- [wbs.md](./wbs.md)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | live reload 트리거 시점 | RollupWatcher `END` 이벤트 | 파일이 디스크에 기록 완료된 시점이므로 브라우저가 최신 파일을 받을 수 있음 |
| D2 | legacy HTTP 서버 대상 범위 | standalone + server-connected 모두 | 모든 legacy client가 dev 모드에서 동작해야 함 |

```gherkin
Feature: 1.3 legacy dev 모드: HTTP 파일 서버 + live reload

  Background:
    Given legacyModule: true 옵션이 설정되어 있다
    And Feature 1.2에 의해 vite build --watch로 dist/ 에 빌드 결과가 생성된다

  Rule: legacy dev 모드에서 dist/ 파일을 HTTP로 서빙한다

    Scenario: HTTP 서버로 index.html 접속
      Given startLegacyWatch()가 완료되어 HTTP 서버가 listen 중이다
      When 브라우저에서 http://localhost:{port}/{name}/ 에 접속한다
      Then dist/index.html 내용이 반환된다

    Scenario: 정적 파일(JS, CSS, 이미지) 요청
      Given HTTP 서버가 listen 중이다
      When 브라우저에서 http://localhost:{port}/{name}/main.js 를 요청한다
      Then dist/main.js 파일이 올바른 Content-Type으로 반환된다

    Scenario: 존재하지 않는 파일 요청 시 SPA fallback
      Given HTTP 서버가 listen 중이다
      When 브라우저에서 http://localhost:{port}/{name}/some/route 를 요청한다
      And dist/some/route 파일이 존재하지 않는다
      Then dist/index.html 내용이 반환된다

  Rule: 빌드 완료 시 브라우저에 live reload 신호를 전송한다

    Scenario: RollupWatcher END 이벤트 시 연결된 브라우저가 reload
      Given HTTP 서버가 listen 중이고 브라우저가 SSE로 연결되어 있다
      When RollupWatcher가 event code 'END'를 발행한다
      Then 연결된 모든 브라우저에 reload 신호가 전송된다
      And 브라우저가 페이지를 자동 새로고침한다

    Scenario: RollupWatcher ERROR 이벤트 시 reload 미전송
      Given HTTP 서버가 listen 중이고 브라우저가 SSE로 연결되어 있다
      When RollupWatcher가 event code 'ERROR'를 발행한다
      Then reload 신호가 전송되지 않는다

  Rule: HTML 서빙 시 live reload 클라이언트 스크립트를 주입한다

    Scenario: index.html 서빙 시 reload 스크립트 자동 삽입
      Given HTTP 서버가 listen 중이다
      When 브라우저에서 index.html을 요청한다
      Then 응답 HTML의 </body> 직전에 SSE 연결 및 reload 로직이 포함된 <script> 태그가 삽입된다

    Scenario: 비-HTML 파일 서빙 시 스크립트 미주입
      Given HTTP 서버가 listen 중이다
      When 브라우저에서 main.js를 요청한다
      Then 파일 내용이 그대로 반환되며 스크립트가 주입되지 않는다

  Rule: HTTP 서버가 serverReady 이벤트를 발행하여 기존 흐름과 통합된다

    Scenario: HTTP 서버 listen 완료 시 serverReady 이벤트 발행
      Given startLegacyWatch()가 실행 중이다
      When HTTP 서버가 listen을 완료한다
      Then worker가 serverReady 이벤트를 발행한다 (port 포함)
      And ViteEngine.port에 해당 포트가 설정된다

    Scenario: DevWatchOrchestrator가 legacy client 포트를 수집하여 proxy 등록
      Given legacyModule client의 HTTP 서버가 serverReady를 발행했다
      And 해당 client가 server-connected이다
      When 서버 runtime이 시작된다
      Then @fastify/http-proxy가 /{name} prefix로 legacy HTTP 서버에 프록시를 등록한다

  Rule: HTTP 서버 생명주기를 관리한다

    Scenario: stopWatch 호출 시 HTTP 서버와 RollupWatcher 모두 정리
      Given legacy watch 모드의 HTTP 서버와 RollupWatcher가 실행 중이다
      When stopWatch()를 호출한다
      Then HTTP 서버가 닫히고 RollupWatcher도 닫힌다

    Scenario: HTTP 서버 없는 상태에서 stopWatch 호출 시 안전하게 무시
      Given legacy watch 모드가 시작되지 않았다
      When stopWatch()를 호출한다
      Then 에러 없이 정상 종료된다
```

## 구현계획

### 배경

Feature 1.2에서 `legacyModule: true` + dev 시 `viteBuild({ build: { watch: {} } })`로 `dist/`에 빌드 결과를 생성하도록 전환했다. 그러나 빌드된 파일을 브라우저에서 확인하려면 HTTP 서버가 필요하고, 파일 변경 시 자동 새로고침이 되어야 개발 편의성이 확보된다.

기존 비-legacy dev 모드에서는 Vite dev server가 파일 서빙과 HMR을 모두 담당하며, `serverReady` 이벤트로 포트를 알리고, `DevWatchOrchestrator`가 이 포트를 server runtime에 전달하여 `@fastify/http-proxy`로 프록시를 등록한다.

### 목표

- `dist/` 빌드 결과물을 서빙하는 HTTP 서버 구현 (SPA fallback 포함)
- RollupWatcher `END` 이벤트 시 SSE로 브라우저에 live reload 신호 전송
- `serverReady` 이벤트 발행으로 기존 ViteEngine/DevWatchOrchestrator 흐름과 통합
- HTTP 서버 생명주기 관리 (`stopWatch()`에서 정리)

### 비목표

- HMR (모듈 단위 핫 리로드) — build --watch 방식이므로 full reload만 지원
- 프로덕션 빌드 변경
- ViteEngine/DevWatchOrchestrator 코드 변경 (기존 `serverReady` 이벤트 체계 그대로 활용)

### 설계

#### HTTP 서버 (`node:http`)

`client.worker.ts`의 `startLegacyWatch()` 내에서 `node:http`로 HTTP 서버를 생성한다. 외부 의존성 없이 내장 모듈만 사용한다.

요청 처리 흐름:
1. URL에서 `/{name}/` prefix를 제거하여 상대 경로 추출
2. `/{name}/__live-reload` → SSE 엔드포인트 (아래 별도 섹션)
3. 상대 경로로 `dist/` 내 파일 탐색
4. 파일 존재 → 확장자 기반 Content-Type으로 응답
5. 파일 미존재 → `dist/index.html` 반환 (SPA fallback)
6. HTML 파일 응답 시 `</body>` 직전에 live reload 클라이언트 스크립트 주입

Content-Type 매핑 (확장자 기반):
- `.html` → `text/html`, `.js` → `application/javascript`, `.css` → `text/css`
- `.json` → `application/json`, `.svg` → `image/svg+xml`, `.png` → `image/png`
- `.ico` → `image/x-icon`, `.woff2` → `font/woff2`, `.woff` → `font/woff`
- 기본값 → `application/octet-stream`

포트: `ClientBuildInfo.port`를 사용하되, 0이면 OS가 자동 할당.

#### SSE Live Reload

SSE 엔드포인트: `/{name}/__live-reload`
- `Connection: keep-alive`, `Content-Type: text/event-stream`, `Cache-Control: no-cache`
- 연결된 클라이언트를 `Set<ServerResponse>`로 관리
- RollupWatcher `END` 이벤트 시 모든 연결에 `data: reload\n\n` 전송
- 클라이언트 연결 해제 시(`close` 이벤트) Set에서 제거

클라이언트 스크립트 (HTML 주입):
```javascript
(function() {
  var source = new EventSource("/__live-reload");
  source.onmessage = function() { location.reload(); };
})();
```
- `EventSource`는 Chrome 6부터 지원 (Chrome 61 호환)
- SSE 경로는 `/{name}/__live-reload`이지만, server-connected 모드에서 proxy를 통해 접근할 때도 동일 경로로 프록시되므로 스크립트에서는 상대경로 `/__live-reload`를 사용

#### RollupWatcher 이벤트 연동

기존 `startLegacyWatch()`의 watcher 이벤트 핸들러를 확장:
- `END` 이벤트: 기존 첫 빌드 감지 로직 유지 + SSE 클라이언트들에 reload 신호 전송 (첫 빌드 이후에만)
- `ERROR` 이벤트: 기존 에러 처리 유지, reload 신호 미전송

#### serverReady 이벤트 발행

HTTP 서버 `listen` 완료 후 `sender.send("serverReady", { port })` 호출. 이렇게 하면:
- `ViteEngine.port`가 설정됨
- `DevWatchOrchestrator._getClientPort()`가 포트 반환
- server-connected client의 경우 `_collectClientPorts()`로 수집되어 server runtime에 전달
- standalone client의 경우 `ResultCollector`에 직접 등록

#### stopWatch() 변경

기존 `rollupWatcher?.close()` 후 HTTP 서버 close 추가. 모듈 변수 `let legacyHttpServer: HttpServer | undefined` 추가.

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| `node:http` 내장 모듈 | 채택 | 외부 의존성 없음, 단순 파일 서빙에 충분 |
| `sirv`/`serve-static` 패키지 | 미채택 | 추가 의존성 필요, 기능 대부분 불필요 |
| WebSocket live reload | 미채택 | 양방향 통신 불필요, SSE가 더 단순하고 Chrome 6부터 지원 |
| `vite preview` 명령 활용 | 미채택 | preview 서버는 watch 모드 미지원, live reload 없음 |
