# Feature 1.1 sd-legacy-import-meta 플러그인 제거

## 참조 자료

- [wbs.md](./wbs.md)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | `inlineDynamicImports: true` 유지 여부 | 유지 | Chrome 61은 dynamic import 미지원(Chrome 63부터). Rollup이 chunk을 분리하면 `import()` 구문이 남으므로 단일 번들 필요 |
| D2 | `legacyModule` 타입 프로퍼티 유지 여부 | 유지 | Feature 1.2, 1.3에서 dev 모드 분기 기준으로 사용 |
| D3 | `vite-engine.spec.ts` 수정 여부 | 미수정 | legacyModule passthrough 테스트이며 플러그인 자체를 검증하지 않음 |

## 요구명세

```gherkin

  Background:

    Scenario: legacyModule 활성화 시 import.meta 치환 플러그인이 없다
      Given legacyModule: true 옵션이 설정되어 있다
      When createClientViteConfig를 호출한다
      Then 반환된 config.plugins에 "sd-legacy-import-meta" 플러그인이 없다
      And esbuild target이 browserslist에 따라 설정되어 import.meta를 자동 치환한다

    Scenario: legacyModule 미설정 시 기존과 동일하게 플러그인이 없다
      Given legacyModule 옵션이 설정되지 않았다
      When createClientViteConfig를 호출한다
      Then 반환된 config.plugins에 "sd-legacy-import-meta" 플러그인이 없다

  Rule: legacyModule: true는 여전히 inlineDynamicImports를 활성화한다

    Scenario: legacyModule 활성화 시 단일 번들 설정이 유지된다
      Given legacyModule: true 옵션이 설정되어 있다
      When createClientViteConfig를 호출한다
      Then config.build.rollupOptions.output.inlineDynamicImports가 true이다

    Scenario: legacyModule 미설정 시 코드 분할이 기본 동작한다
      Given legacyModule 옵션이 설정되지 않았다
      When createClientViteConfig를 호출한다
      Then config.build.rollupOptions가 설정되지 않는다

  Rule: sd-legacy-import-meta 플러그인 코드와 테스트를 제거한다

    Scenario: vite-config.ts에서 transform 플러그인 코드를 제거한다
      Given vite-config.ts에 sd-legacy-import-meta 플러그인이 존재한다
      When 플러그인 코드를 제거한다
      Then sd-legacy-import-meta 이름의 플러그인 정의가 없다
      And pkgDir, base 변수 등 플러그인 전용 코드도 제거된다
      And legacyModule 조건 블록 내 inlineDynamicImports 설정은 유지된다

    Scenario: vite-config.spec.ts에서 플러그인 테스트를 제거한다
      Given vite-config.spec.ts에 sd-legacy-import-meta 관련 테스트가 존재한다
      When 플러그인 테스트를 제거한다
      Then sd-legacy-import-meta 플러그인의 enforce, transform 등을 검증하는 테스트가 없다
      And inlineDynamicImports 관련 테스트는 유지된다
```

## 구현계획

### 배경

`createClientViteConfig` 함수(`vite-config.ts`)는 `legacyModule: true` 시 두 가지를 설정한다:
1. `inlineDynamicImports: true` — Chrome 61이 dynamic import를 지원하지 않으므로 단일 번들 생성
2. `sd-legacy-import-meta` Vite transform 플러그인 — `import.meta`를 커스텀 변수로 치환

esbuild target이 `browserslist`로부터 설정되어(`vite-config.ts:72-78`) `import.meta`를 자동 치환하므로, 2번 플러그인은 불필요하다.

### 목표

- `sd-legacy-import-meta` 플러그인 코드 및 전용 import 제거
- 관련 테스트 정리 (플러그인 테스트 제거, `inlineDynamicImports` 테스트 유지)

### 비목표

- `legacyModule` 타입 프로퍼티 제거 (Feature 1.2, 1.3에서 사용)
- `inlineDynamicImports` 제거 (Chrome 61 dynamic import 미지원)
- `vite-engine.spec.ts` 수정 (passthrough 테스트이므로 무관)

### 설계

#### vite-config.ts 변경

`legacyModule === true` 블록에서:
- **유지:** `inlineDynamicImports: true` 설정 (lines 229-236)
- **제거:** `pkgDir`, `base` 변수 및 플러그인 push (lines 238-259)
- **제거:** `import { pathx } from "@simplysm/core-node"` (line 3, 플러그인에서만 사용)
- **수정:** JSDoc에서 Feature 1.1 설명 갱신 (line 64)

#### vite-config.spec.ts 변경

- **유지:** `inlineDynamicImports` + 플러그인 존재 확인 테스트 → `inlineDynamicImports`만 확인하도록 수정 (lines 225-237)
- **유지:** `legacyModule 미설정` 테스트 → 플러그인 비존재 단언 제거 (lines 239-249)
- **유지:** `splitting replacement` 테스트 → 플러그인 단언 제거 (lines 251-264)
- **제거:** `enforce: post` 테스트 (lines 266-276)
- **제거:** `import.meta.url 치환` 테스트 (lines 278-296)
- **제거:** `import.meta.hot 치환` 테스트 (lines 298-314)
- **제거:** `/@vite/client import.meta 치환` 테스트 (lines 316-332)
- **제거:** `import.meta 없는 모듈 무변환` 테스트 (lines 334-349)

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| 플러그인을 dev 모드에서만 유지 | 미채택 | Feature 1.2에서 dev도 build --watch로 전환되므로 불필요 |
| `legacyModule` 블록 전체 제거 | 미채택 | `inlineDynamicImports`는 여전히 필요 |
