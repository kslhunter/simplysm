# Feature 1.1 FsWatcher EPERM 복구

## 참조 자료

- [debug.md](./debug.md)

### 근본 원인

Windows 네이티브 `fs.watch`(`ReadDirectoryChangesW`)가 감시 대상 하위 디렉토리의 삭제/재생성으로 핸들이 무효화되어 `EPERM: operation not permitted, watch` 발생. `watchReplaceDeps`에서 chokidar에 `ignored` 옵션을 전달하지 않아 `node_modules/`, `.cache`, `tests/` 등 불필요한 디렉토리까지 감시하여 EPERM 노출 면적 증가.

### 대상 파일

- `packages/core-node/src/features/fs-watcher.ts` — FsWatcher 클래스
- `packages/sd-cli/src/utils/replace-deps.ts` — watchReplaceDeps 함수
- `packages/core-node/tests/utils/fs-watcher.spec.ts` — FsWatcher 테스트
- `packages/core-node/tests/utils/fs-watcher-error.spec.ts` — FsWatcher 에러 테스트

## 구현계획

### 배경

`FsWatcher`는 chokidar 기반 파일 감시 래퍼로, sd-cli의 replace-deps, copy-src, copy-public, build workers, DevWatchOrchestrator 등 10곳 이상에서 사용된다. Windows에서 감시 대상 하위 디렉토리가 삭제/재생성되면 네이티브 `fs.watch` 핸들이 무효화되어 `EPERM` 에러가 발생하지만, 현재는 에러를 로깅만 하고 복구하지 않아 감시가 중단된다.

### 목표

- FsWatcher에 EPERM 에러 시 자동 재생성 로직을 추가하여 모든 사용처에서 Windows EPERM 복구 지원
- watchReplaceDeps에서 chokidar `ignored` 옵션으로 불필요한 디렉토리 감시를 제외하여 EPERM 발생 면적 감소

### 비목표

- 다른 에러 코드(EACCES, ENOSPC 등)에 대한 복구
- chokidar를 다른 파일 감시 라이브러리로 교체

### 설계

#### FsWatcher 변경사항

**새 인스턴스 필드:**
- `_paths: string[]` — 감시 경로 (재생성 시 필요)
- `_options: chokidar.ChokidarOptions` — chokidar 옵션 (재생성 시 필요)
- `_allHandlers: Array<(event: string, path: string) => void>` — "all" 이벤트 핸들러 목록 (재등록 시 필요)
- `_retryCount: number` — 현재 연속 재시도 횟수
- `_isRecovering: boolean` — 복구 진행 중 플래그 (중복 복구 방지)

**`_watcher` 필드:** `readonly` 제거 → mutable로 변경

**`_recreateWatcher()` 메서드:**
1. `_isRecovering = true`
2. 기존 watcher 닫기 (`this._watcher.close()`)
3. 1초 대기
4. 새 chokidar watcher 생성 (동일 `_paths`, `_options`)
5. 에러 리스너 재등록 (EPERM 감지 포함)
6. `_allHandlers`의 모든 핸들러를 새 watcher에 재등록
7. ready 이벤트 대기
8. `_isRecovering = false`, `_retryCount = 0`

**에러 핸들러 변경 (line 140):**
- EPERM 에러 감지: `(err as NodeJS.ErrnoException).code === "EPERM"`
- `_retryCount < 3` && `!_isRecovering` → `_recreateWatcher()` 호출, `_retryCount++`
- `_retryCount >= 3` → 기존처럼 로깅만, 재시도 중단 메시지 추가

**`onChange()` 메서드 변경:**
- 기존: `this._watcher.on("all", handler)` 직접 등록
- 변경: `this._allHandlers.push(handler)` 저장 후 `this._watcher.on("all", handler)` 등록

#### watchReplaceDeps 변경사항

```typescript
const watcher = await FsWatcher.watch([entry.resolvedSourcePath], {
  followSymlinks: false,
  ignored: [...EXCLUDED_NAMES].map((name) => `**/${name}`),
});
```
