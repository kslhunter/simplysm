## 구현계획

### 배경

sd-cli의 `tests/workers/` 디렉토리에 6개 빌드 워커 테스트 파일(총 ~2692줄)이 존재한다. Feature 1.1에서 `ngtsc-build-worker.spec.ts`와 `ngtsc-build-lint.spec.ts`의 리팩토링 패턴(top-level await import, `vi.hoisted`, 불필요 모킹 제거)이 확립되었다. [근거: `ngtsc-build-lint.spec.ts` 코드 확인]

### 목표

- `@simplysm/core-common` 불필요 모킹 제거 [근거: sd-testing.md Rule "모킹이 실제 로직을 복제하면 불필요"]
- `client-worker.spec.ts` legacy 테스트 분리 [근거: D2 "실제 네트워크 I/O와 순수 mock 테스트 분리"]
- `server-build-worker.spec.ts` production artifacts describe 그룹화 [근거: D3 "내부 정리"]
- `library-build-worker.spec.ts` 초기화 패턴 통일 [근거: 5/6 파일 일관성]

### 비목표

- `*-lint.spec.ts` 파일명 변경 [근거: D1 "Feature 1.1 패턴 일관성"]
- lint 파일을 본 spec에 병합 [근거: Feature 1.1에서 분리 유지 패턴 확립]
- 소스 코드(`src/workers/*.worker.ts`) 변경 [근거: wbs 제외사항 "테스트 코드만 리팩토링"]
- 신규 테스트 케이스 추가 [근거: wbs 제외사항]

### 설계

#### 1. `@simplysm/core-common` 모킹 제거

현재 4개 파일에서 동일한 패턴으로 실제 로직을 복제하는 모킹이 존재한다:

```typescript
// library-build-worker.spec.ts:43-45, server-build-worker.spec.ts:62-64, client-worker.spec.ts:67-69
vi.mock("@simplysm/core-common", () => ({
  err: { message: (e: any) => e?.message ?? String(e) },
}));

// server-runtime-worker.spec.ts:19-28 — env도 함께 모킹
vi.mock("@simplysm/core-common", () => ({
  env: vi.fn((key: string, value?: string) => {
    if (value !== undefined) { process.env[key] = value; return; }
    return process.env[key];
  }),
  err: { message: (e: any) => e?.message ?? String(e) },
}));
```

실제 구현 확인:
- `err.message` (`core-common/src/utils/error.ts:9`): `err instanceof Error ? err.message : String(err)` — 모킹과 기능적으로 동일
- `env` (`core-common/src/env.ts:25`): Node.js에서 `process.env` get/set — 모킹과 기능적으로 동일

**변경:** 4개 파일 모두에서 `vi.mock("@simplysm/core-common")` 호출 전체 삭제. 실제 모듈이 로드되며, 순수 유틸 함수이므로 테스트에 부작용 없음.

#### 2. `client-worker.spec.ts` Legacy 분리 [근거: D2]

- lines 302-330: `describe("stopWatch — legacy mode")` — 2개 테스트
- lines 332-503: `describe("startWatch — legacy HTTP server")` — 5개 테스트
- lines 505-580: `describe("startWatch — legacy HTTP server MIME type")` — 2개 테스트
- lines 630-799: `describe("startWatch — legacy live reload")` — 4개 테스트

`client-worker.spec.ts`에 잔류:
- lines 161-179의 dev mode startWatch 테스트 (현재 legacy mode describe 내부에 위치, 분리 시 독립 describe로 승격)
- lines 582-628: `describe("dev port file")` — 단, legacy mode dev-port 테스트(line 605-627)는 legacy 파일로 이동

**mock setup 분리:**

- legacy 전용: 없음 (현재 모든 mock이 공유)
- 각 파일에 필요한 mock을 독립적으로 선언

### 대안 검토

- **client-worker.spec.ts 3파일 분할 (build/dev/legacy)**: mock setup 3중 중복 과다. 2분할(legacy/non-legacy)이 비용 대비 효과적. [기각]
- **server-build-worker.spec.ts build/watch 2파일 분할**: 모든 테스트가 순수 mock으로 성격 동일. mock setup(157줄) 중복 비용 > 분할 이점. [기각]
- **env 모킹만 유지, err 모킹만 제거**: env도 실제 로직 복제이며 vi.fn() 추적 기능도 미사용. 전체 제거가 일관적. [기각]
