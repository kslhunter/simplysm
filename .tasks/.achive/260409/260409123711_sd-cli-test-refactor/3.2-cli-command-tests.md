#### sd-cli-entry.spec.ts monkey-patching 개선

Before (line 30-51):
```typescript
const origExit = process.exit;
const origError = console.error;
const origLog = console.log;
console.error = () => {};
console.log = () => {};
process.exit = (() => { errorThrown = true; }) as never;
try { ... } finally {
  process.exit = origExit;
  console.error = origError;
  console.log = origLog;
}
```

After:
```typescript
const exitSpy = vi.spyOn(process, "exit").mockImplementation(() => { errorThrown = true; } as never);
const errorSpy = vi.spyOn(console, "error").mockImplementation(() => {});
const logSpy = vi.spyOn(console, "log").mockImplementation(() => {});
try { ... } finally {
  exitSpy.mockRestore();
  errorSpy.mockRestore();
  logSpy.mockRestore();
}
```

### 대안 검토

1. **파일 분할 (publish/typecheck)**: mock 공유 파일(_test-setup.ts) 추출 필요. vi.mock은 파일별 호이스팅이므로 각 파일에서 재선언 필수. 내부 정비 대비 이점 부족하여 기각 (D1, D2).
2. **consola mock 공유 헬퍼 추출**: vi.mock 호이스팅 제약으로 공유 불가. 각 파일의 미세 차이(withTag 라우팅 등)도 있어 기각. 현행 파일별 독립 유지.
3. **@simplysm/core-node mock에 importOriginal 적용**: 현재 전체 모듈 교체 방식이지만, 테스트 대상 함수가 fsx/cpx만 사용하므로 다른 export 누락 영향 없음. 변경 불필요.
