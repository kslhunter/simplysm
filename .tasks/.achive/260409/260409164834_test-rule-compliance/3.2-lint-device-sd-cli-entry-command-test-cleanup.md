## 구현계획

### 배경
sd-cli 패키지의 command/entry 테스트 3개 파일을 sd-testing.md 규칙에 맞게 정비한다. lint.spec.ts는 이미 준수 상태이므로 device.spec.ts와 sd-cli-entry.spec.ts만 변경한다.

### 목표
- device.spec.ts의 Capacitor/Electron/loadSdConfig vi.mock → vi.spyOn 전환 [근거: Rule "네이티브 툴체인은 vi.spyOn으로 전환"]
- sd-cli-entry.spec.ts의 잘못된 테스트 수정 [근거: 설계 결정 D1]
- 변경 후 전체 테스트 통과 유지

### 비목표
- lint.spec.ts 수정 [근거: 설계 결정 D2 — 이미 sd-testing.md 준수]
- sd-cli-entry.spec.ts의 vi.mock 제거 [근거: 설계 결정 D4 — ESM 정적 import 제약]
- 테스트 커버리지 확장 (기존 시나리오 동일 유지)

### 설계

#### 1. device.spec.ts 모킹 전환 [근거: sd-testing.md "vi.spyOn()" 권장]

**현재 (vi.mock — 모듈 전체 교체):**
```typescript
// device.spec.ts:3-18 — vi.hoisted로 mock 인스턴스 생성
const mocks = vi.hoisted(() => ({
  capacitorInstance: { initialize: vi.fn(), run: vi.fn(), build: vi.fn() },
  electronInstance: { initialize: vi.fn(), run: vi.fn(), build: vi.fn() },
  loadSdConfig: vi.fn(),
  readFileSync: vi.fn(),
  existsSync: vi.fn(),
  httpGet: vi.fn(),
}));

// device.spec.ts:20-24 — 전체 모듈 교체
vi.mock("../../src/capacitor/capacitor", () => ({
  Capacitor: { create: vi.fn().mockResolvedValue(mocks.capacitorInstance) },
}));
```

**변경 후 (vi.spyOn — 메서드만 spy):**
```typescript
import { Capacitor } from "../../src/capacitor/capacitor";
import { Electron } from "../../src/electron/electron";
import * as sdConfigModule from "../../src/utils/sd-config";
import { runDevice } from "../../src/commands/device";

// node:fs, node:http만 vi.mock 유지 (물리적 I/O)
const mocks = vi.hoisted(() => ({
  readFileSync: vi.fn(),
  existsSync: vi.fn().mockReturnValue(false),
  httpGet: vi.fn(),
}));

vi.mock("node:fs", () => ({...}));  // 현재와 동일
vi.mock("node:http", () => ({...})); // 현재와 동일

// describe 내 beforeEach에서 spy 설정
const mockCapacitorInstance = { run: vi.fn(), initialize: vi.fn(), build: vi.fn() };
const mockElectronInstance = { run: vi.fn(), initialize: vi.fn(), build: vi.fn() };

beforeEach(() => {
  vi.spyOn(Capacitor, "create").mockResolvedValue(mockCapacitorInstance as any);
  vi.spyOn(Electron, "create").mockResolvedValue(mockElectronInstance as any);
  vi.spyOn(sdConfigModule, "loadSdConfig");
});

afterEach(() => {
  vi.restoreAllMocks();
});
```

**전환 근거:**
- `capacitor.ts`, `electron.ts` 모듈은 클래스 정의만 있고 import side effect 없음 (코드 확인: 모듈 레벨에 함수 호출 없음)
- ESM 모듈 싱글턴: device.ts와 테스트가 같은 Capacitor/Electron 클래스 객체 참조 → vi.spyOn이 양쪽에 적용
- vitest ESM 지원: `vi.spyOn(module, 'export')`가 live binding에 반영됨

**영향 범위:** `packages/sd-cli/tests/commands/device.spec.ts` 1개 파일

#### 2. sd-cli-entry.spec.ts 테스트 수정 [근거: 설계 결정 D1]

**2a. "does not include device command" 테스트 삭제**

현재 (`sd-cli-entry.spec.ts:24-49`):
```typescript
it("does not include device command", async () => {
  // device IS registered → 파싱 성공 → 핸들러에서 unmocked runDevice 호출
  // → loadSdConfig 실패 → 에러 → errorThrown = true → 잘못된 이유로 통과
});
```
→ `sd-cli-entry.ts:24`에서 `COMMAND_NAMES`에 `"device"` 포함, `sd-cli-entry.ts:183-215`에서 device 커맨드 등록됨. 테스트 전제가 틀림 → 삭제.

**2b. "includes expected commands" 테스트 수정**

현재 (`sd-cli-entry.spec.ts:51-63`):
```typescript
const expectedCommands = ["lint", "typecheck", "check", "watch", "dev", "build", "init", "publish", "replace-deps"];
// ↑ lint, typecheck, init은 미등록 (lint/typecheck는 check --type 옵션 값)
// ↑ device 누락

const parser = createCliParser([cmd, "--help"]).exitProcess(false);
expect(parser).toBeDefined(); // ← 항상 true, 실제 검증 없음
```

변경:
```typescript
const expectedCommands = ["check", "watch", "dev", "device", "build", "publish", "replace-deps"];
// 실제 파싱을 수행하여 커맨드 등록 여부 검증 (--help로 핸들러 미실행)
```

**vi.mock 6개는 유지** — ESM 정적 import(`sd-cli-entry.ts:8-13`)에서 vi.spyOn 불가. device 커맨드는 dynamic import(`sd-cli-entry.ts:208`)이므로 mock 불필요.

**영향 범위:** `packages/sd-cli/tests/sd-cli-entry.spec.ts` 1개 파일
