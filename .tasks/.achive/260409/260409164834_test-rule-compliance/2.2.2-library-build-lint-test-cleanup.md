## 구현계획

### 배경
`library-build-lint.spec.ts`는 `library-build.worker`의 lint 통합 동작을 테스트한다. 현재 5개 vi.mock + 1개 vi.hoisted를 사용하며, tsc-build 모듈을 vi.mock으로 전체 대체하고 있다. 생성자/호출 인자 검증으로 구현에 결합된 검증이 3건 존재한다.

### 목표
- tsc-build vi.mock → vi.spyOn 전환으로 모듈 전체 대체 방지 [근거: sd-testing.md "vi.mock은 모듈 전체를 대체하므로 순수 함수까지 가짜로 바뀐다"]
- 구현 결합 검증 3건 제거 → 동작 결과 검증 [근거: sd-testing.md "구현 결합 검증 금지"]

### 비목표
- lint-with-program mock 구조 변경 [근거: wbs 경계 "lint-with-program mock 유지"]
- @simplysm/core-node, worker-utils, package-utils mock 변경 [근거: wbs 경계]
- 테스트 시나리오 추가/삭제 [근거: wbs "불필요한 mock 제거 후에도 테스트가 동일 시나리오를 커버하는지 검증"]

### 설계

#### 1. tsc-build vi.mock → vi.spyOn 전환 [근거: sd-testing.md "spyOn 우선"]

**현재 (제거):**
```typescript
vi.mock("../../src/utils/tsc-build", () => ({
  runTscPackageBuild: vi.fn(() => mockTscResult),
}));
```

**변경 후:**
```typescript
import * as tscBuildModule from "../../src/utils/tsc-build";

const runTscSpy = vi.spyOn(tscBuildModule, "runTscPackageBuild")
  .mockReturnValue(mockTscResult as any);
```

- 정적 import로 실제 모듈 로드 (top-level side-effect: logger 생성만, 실행 코드 없음)
- vi.spyOn + mockReturnValue로 함수만 대체, 모듈 구조는 실제 유지
- worker의 `await import(...)` 시점에 이미 spy 설정 완료

#### 2. beforeEach spy 재설정 [근거: vi.clearAllMocks()가 mockReturnValue를 초기화]

```typescript
beforeEach(() => {
  vi.clearAllMocks();
  runTscSpy.mockReturnValue(mockTscResult as any);
  // ... 기존 mockLintFn, mockTscResult 재설정
});
```

#### 3. 구현 결합 검증 → 결과 검증 [근거: sd-testing.md "동작의 결과를 검증"]

**lint 활성화 테스트 (L83-90):**
```typescript
// 제거:
expect(MockLintWithProgramRunner).toHaveBeenCalledWith({ cwd: "/workspace", pkgName: "my-lib" });
expect(mockLintFn).toHaveBeenCalledWith({ program: mockTscResult.program });
expect(result).toHaveProperty("lint");

// 추가:
expect(result.lint).toEqual({
  success: true,
  errorCount: 0,
  warningCount: 0,
  formattedOutput: "",
});
```

**lint 비활성화 테스트 (L104):**
```typescript
// 제거:
expect(mockLintFn).not.toHaveBeenCalled();

// 유지:
expect(result.lint).toBeUndefined();
```

### 대안 검토

| 접근 | 장점 | 단점 | 결론 |
|------|------|------|------|
| vi.spyOn + mockReturnValue | 모듈 구조 유지, sd-testing.md 원칙 부합 | spy 재설정 필요 | **채택** |
| vi.mock + importOriginal | tsc-build 모듈 다른 export 보존 | vi.mock 특성상 모듈 전체를 factory로 감싸야 해서 장황, sd-testing.md "spyOn 우선"에 부합하지 않음 | 불채택 |
