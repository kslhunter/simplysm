## 구현계획

### 배경

`ngtsc-build-lint.spec.ts`는 `ngtsc-build.worker`의 lint 통합 동작을 테스트한다. 현재 9개 `vi.mock()`을 사용하며, 그 중 4개(`typecheck-serialization`, `angular-compiler`, `tsconfig`, `package-utils`)가 sd-testing.md 원칙을 위반한다. 또한 2개 테스트에서 생성자/메서드 인자를 직접 검증하는 구현 결합 검증이 있다. [근거: WBS Feature 2.2.1 리뷰 결과]

### 목표

- 불필요한 `vi.mock()` 3개 제거 (`typecheck-serialization`, `angular-compiler`, `package-utils`) [근거: Rule "순수 유틸 모듈은 실제 구현을 사용한다"]
- `tsconfig` `vi.mock()`에 `importOriginal` 적용 (`parseTsconfig`만 stub) [근거: Rule "혼합 모듈은 importOriginal로 실제 구현을 최대한 살린다"]
- 구현 결합 검증 3건을 동작 결과 검증으로 전환 [근거: Rule "동작 결과를 검증한다"]

### 비목표

- `lint-with-program`, `angular-build-pipeline`, `ngtsc-build-core`, `worker-utils`, `@simplysm/core-node` mock 변경 [근거: WBS 경계 "물리적으로 필수"]
- `startWatch` 테스트 추가 [근거: WBS 경계]
- `beforeEach` mock 리셋 로직 변경 [근거: 유지 대상 mock의 리셋은 그대로 필요]

### 설계

**1. Mock 제거 (3개)** [근거: Rule "순수 유틸 모듈은 실제 구현을 사용한다"]

삭제 대상:
- `vi.mock("../../src/utils/typecheck-serialization", ...)` (L57-59)
- `vi.mock("../../src/utils/angular-compiler", ...)` (L61-65)
- `vi.mock("../../src/utils/package-utils", ...)` (L80-82)

**2. tsconfig importOriginal** [근거: Rule "혼합 모듈은 importOriginal로 실제 구현을 최대한 살린다"]

변경 전 (L67-72):
```typescript
vi.mock("../../src/utils/tsconfig", () => ({
  parseTsconfig: vi.fn(() => ({ options: {}, fileNames: [] })),
  getPackageSourceFiles: vi.fn(() => []),
  getPackageFiles: vi.fn(() => []),
  getCompilerOptionsForEnv: vi.fn((opts: unknown) => opts),
}));
```

변경 후:
```typescript
vi.mock("../../src/utils/tsconfig", async (importOriginal) => {
  const original = await importOriginal<typeof import("../../src/utils/tsconfig")>();
  return {
    ...original,
    parseTsconfig: vi.fn(() => ({ options: {}, fileNames: [], errors: [] })),
  };
});
```

- `parseTsconfig`: stub 유지 (디스크 접근 필요) [근거: sd-testing.md "물리적으로 돌아갈 수 없는 것만 mock"]
- `getPackageSourceFiles`: 실제 실행. `fileNames: []` → 빈 배열 필터링 → `[]` 반환. `pathx.isChildPath` 호출 안 됨 (빈 배열이므로 콜백 미실행) [근거: 코드 분석 `tsconfig.ts:106-118`]
- `getPackageFiles`, `getCompilerOptionsForEnv`: 실제 실행. 테스트 데이터(`includeTests` 미설정, `env` 미설정)에서 호출되지 않음

**3. 검증 전환** [근거: Rule "동작 결과를 검증한다"]

변경 전 (lint 활성화 테스트, L125-141):

### 대안 검토

| 대안 | 설명 | 기각 사유 |
|------|------|----------|
| tsconfig에 `vi.spyOn()` 사용 | `import * as tsconfigModule` + `vi.spyOn(tsconfigModule, "parseTsconfig")` | 기존 worker 테스트에서 사용된 적 없는 새 패턴. sd-testing.md의 `importOriginal` 가이드가 더 적합 |
| angular-compiler mock 유지 | `@angular/compiler-cli` import chain 방지 | `AngularSourceFileCache`는 `build()`에서 미사용. sd-testing.md 원칙에 따라 제거가 맞음. 성능 영향은 vitest 모듈 캐싱으로 미미 |
| package-utils `vi.spyOn()` 전환 | 향후 `startWatch` 테스트 추가 대비 | `collectDeps`가 호출되지 않으므로 spy도 불필요. 완전 제거가 가장 깔끔 |
