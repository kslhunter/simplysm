## 구현계획

### 배경

`packages/core-node/tests/utils/cp.acc.spec.ts`는 `getSystemEncoding()` 함수를 테스트하는 acceptance test 파일이다. 현재 `vi.mock("child_process")`로 모듈 전체를 대체하고 있어, `.acc.spec.ts`(acceptance test) 파일명과 의도가 불일치한다.

소스 코드 분석 결과:
- **win32 경로** (`cp.ts:31-37`): `execSync("chcp")` 호출 → 코드페이지 파싱 → 인코딩 반환
- **non-win32 경로** (`cp.ts:38-47`): `process.env.LANG` / `LC_ALL` 읽기 → 인코딩 파싱 (execSync 미호출)
- **fallback** (`cp.ts:50-53`): 감지 실패 시 `"utf-8"` 반환

핵심 인사이트: Linux/fallback 테스트는 `process.platform = "linux"` 설정 시 `execSync`가 호출되지 않으므로, mock 없이 환경 변수 조작만으로 동작한다. [근거: cp.ts:38 `} else {` 분기]

### 목표

- `vi.mock("child_process")` 제거하여 진정한 acceptance test로 전환 [근거: D1, sd-testing.md]
- 기존 테스트 시나리오의 커버리지를 최대한 유지 [근거: WBS "불필요한 mock 제거 후에도 테스트가 동일 시나리오를 커버하는지 검증"]

### 비목표

- `cp.spec.ts`에 추가 유닛 테스트 작성 [근거: WBS 경계 — `codePageToEncoding` 유닛 테스트가 이미 존재]
- 다른 core-node 테스트 수정 [근거: WBS "다른 core-node 테스트(fs-watcher-recovery, fs-watcher-error)는 이미 양호"]

### 설계

변경 대상: `packages/core-node/tests/utils/cp.acc.spec.ts` 1개 파일

1. **vi.mock 제거** [근거: D1 결정]
   - `vi.mock("child_process", ...)` 블록 삭제
   - `import { execSync } from "child_process"` 삭제
   - vitest import에서 `vi` 제거 (더 이상 사용하지 않음)

2. **Windows 테스트 변경** [근거: Rule "acceptance test는 실제 시스템 명령을 실행"]
   - 기존: `vi.mocked(execSync).mockReturnValue("활성 코드 페이지: 949\n")` → `expect(...).toBe("euc-kr")`
   - 변경: `getSystemEncoding()` 실제 호출 → 반환값이 `CODE_PAGE_MAP`의 값 + `"utf-8"` 목록에 포함되는지 검증
   - CP949 고정 검증 상실은 `cp.spec.ts:4-7`의 `codePageToEncoding(949) → "euc-kr"` 유닛 테스트가 커버

3. **Linux/fallback 테스트 유지** [근거: Rule "non-win32 경로는 환경 변수 조작으로 테스트 가능"]
   - `process.platform = "linux"` + `process.env.LANG` 조작은 mock이 아님 (실제 프로세스 상태 변경)
   - `execSync` 미호출 경로이므로 mock 불필요

4. **afterEach 유지** [근거: Rule "테스트 후 원래 상태 복원"]
   - `process.platform`, `LANG`, `LC_ALL` 복원 로직 유지
   - `vi.mocked(execSync).mockReset()` 삭제

### 대안 검토

- **Option B (unit test 전환)**: `.spec.ts`로 이름 변경 + `vi.spyOn()` 전환. `mockReturnValue` 사용으로 실질적 mock이 유지되어 sd-testing.md 원칙에 덜 부합. D1 결정으로 제외.
