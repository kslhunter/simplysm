# Feature 4.2 Angular Plugin + Engine + Capacitor/Electron 테스트 정비

## 참조 자료
- WBS: [wbs.md](./wbs.md)
- sd-testing.md 규칙: `.claude/references/sd-testing.md`
- 대상 패키지: `packages/sd-cli/tests/` 하위 angular, engines, capacitor, electron 디렉토리

### 설계 결정
| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | Angular Plugin sd-config mock 유지/제거 | 유지 | loadSdConfig은 SUT가 아닌 config 제공자. fixture 기반 전환 대비 mock이 테스트별 override(browserSupport 등)에 더 유연함. 7개 파일 수정 + jiti 런타임 의존성 부담 회피 |
| D2 | Capacitor/Electron fsx mock 유지/제거 | 유지 + 검증 패턴 정비 | cpx.spawn(Gradle, adb 등) mock은 물리적 필수. fsx만 실제 전환 시 혼합 구조로 복잡도 증가. mock.calls 내용 검증은 유지하면서 불필요한 호출 횟수/여부 검증만 제거 |

## 구현계획

### 배경

sd-cli 패키지의 Angular Plugin(7개), Engine(6개), Capacitor(6개), Electron(1개) 테스트가 물리적으로 필요한 mock(Worker, sharp, esbuild)을 사용하지만, `toHaveBeenCalledWith`/`toHaveBeenCalledTimes`/`mock.calls` 패턴으로 구현에 강하게 결합되어 있다. [근거: 코드 탐색 결과 Engine 테스트에서 ~60건 이상의 mock 인자/횟수 검증 발견]

관련 코드 구조:
- Engine: `BaseEngine.run()` → `_callBuild()` → Worker.build() → EngineResult 반환 [근거: `src/engines/BaseEngine.ts:111-117`]
- Engine: `BaseEngine.startWatch()` → Worker 이벤트 핸들링 → ResultCollector.add() / RebuildManager.registerBuild() [근거: `src/engines/BaseEngine.ts:123-209`]
- ViteEngine: run()이 Worker.build() 응답을 EngineResult로 변환 [근거: `src/engines/ViteEngine.ts:65-91`]
- ResultCollector/RebuildManager: BaseEngineOptions로 주입되는 외부 협력자 [근거: `src/engines/BaseEngine.ts:41-47`]

### 목표

- Engine build/startWatch `toHaveBeenCalledWith` → EngineResult/ResultCollector 결과 검증으로 전환 [근거: Rule "Engine build 인자 검증을 결과 검증으로 전환"]
- `Worker.create().toHaveBeenCalledTimes(1)`, `mockWorker.on.toHaveBeenCalledWith(...)` 제거 [근거: Rule "Worker.create 횟수 검증 제거", "이벤트 등록 검증 제거"]
- engine-selection `vi.mock("package-utils")` → `vi.spyOn` 전환 [근거: Rule "engine-selection vi.mock → vi.spyOn"]
- Capacitor/Electron 불필요한 단순 호출 검증 제거 [근거: Rule "내용 없는 단순 호출 검증 제거"]

### 비목표

- sd-config mock 구조 변경 [근거: D1]
- fsx/cpx mock 구조 변경 [근거: D2]
- mock.calls 파일 내용/설정값 검증 제거 [근거: mock 유지 시 유일한 결과 검증 수단]
- Angular Plugin callback(onBuild/onBuildStart) 검증 제거 [근거: 동작 검증으로 허용]
- 테스트 커버리지 확대나 신규 테스트 추가

### 설계

#### 1. Engine build 인자 검증 → EngineResult 검증 전환

**Before** (`ngtsc-engine.spec.ts:59-62`):
```typescript
expect(Worker.create).toHaveBeenCalledTimes(1);
expect(mockWorker.build).toHaveBeenCalledWith(
  expect.objectContaining({ name: "test-pkg", pkgDir: "/packages/test-pkg", output: { js: true, dts: true } })
);
```

**After**:
```typescript
const result = await engine.run({ js: true, dts: true });
expect(result.build.success).toBe(true);
expect(result.build.errors).toEqual([]);
```

동일 패턴 적용 대상: `tsc-engine.spec.ts`, `server-esbuild-engine.spec.ts`, `vite-engine.spec.ts` [근거: 각 파일에서 동일한 `Worker.create().toHaveBeenCalledTimes(1)` + `build.toHaveBeenCalledWith(...)` 패턴 확인]

#### 2. Engine startWatch 설정 전달 테스트 전환

vite-engine.spec.ts의 "설정 전달" describe 블록에서 `startWatch.toHaveBeenCalledWith(...)` 검증 제거. Worker가 mock이므로 config 전달을 직접 검증할 수 없는 한계를 수용하고, 이벤트 핸들링 결과(ResultCollector, RebuildManager) 검증으로 전환.

**Before** (`vite-engine.spec.ts:339-343`):
```typescript
expect(mockWorker.startWatch).toHaveBeenCalledWith(
  expect.objectContaining({ env: { MY_VAR: "value" }, configs: { ... } })
);
```

**After**: 해당 검증 구문 제거. "설정 전달" 테스트는 startWatch 호출이 정상 완료되는지(`await`가 reject하지 않는지)와 이벤트 핸들링이 정상 동작하는지로 전환.

#### 3. 이벤트 등록 검증 제거

**Before** (`base-engine.spec.ts:100-102`):
```typescript
expect(mockWorker.on).toHaveBeenCalledWith("buildStart", expect.any(Function));
expect(mockWorker.on).toHaveBeenCalledWith("build", expect.any(Function));
expect(mockWorker.on).toHaveBeenCalledWith("error", expect.any(Function));
```

**After**: 해당 3줄 제거. 이벤트 핸들러 추출(`mock.calls.find`)은 시뮬레이션 설정으로 유지.

동일 패턴: `vite-engine.spec.ts:278-279` (serverReady/error), `vite-engine.spec.ts:314-315` (buildStart/build)

#### 4. engine-selection spyOn 전환

**Before** (`engine-selection.spec.ts:3-19`):
```typescript
vi.mock("@simplysm/core-node", () => ({ ... }));
vi.mock("../../src/utils/package-utils", () => ({
  hasAngularCoreDependency: mockHasAngularCoreDependency,
}));
const mockHasAngularCoreDependency = vi.fn(() => false);
// 테스트:
expect(mockHasAngularCoreDependency).toHaveBeenCalledWith("/packages/test");
```

**After**:
```typescript
vi.mock("@simplysm/core-node", () => ({ ... }));  // Worker mock 유지
import * as packageUtils from "../../src/utils/package-utils";
// beforeEach:
vi.spyOn(packageUtils, "hasAngularCoreDependency").mockReturnValue(false);
// 테스트:
vi.mocked(packageUtils.hasAngularCoreDependency).mockReturnValue(true);
const engine = createBuildEngine({ target: "node", ... });
expect(engine).toBeInstanceOf(NgtscEngine);
// toHaveBeenCalledWith 제거
```

[근거: package-utils 모듈 전체를 교체하지 않고 단일 함수만 spyOn. mockReturnValue 사용은 fixture에 적절한 package.json이 없기 때문]

#### 5. Capacitor/Electron 불필요한 호출 검증 제거

제거 대상:
- `capacitor-build.spec.ts:258` — `expect(mockFsxCopy).toHaveBeenCalled()` (내용 미검증)
- `capacitor-run.spec.ts:205` — `expect(capRunCallCount).toBe(1)` (횟수 검증)

유지 대상 (mock.calls 내용 검증):
- `capacitor-init.spec.ts` 전체: `mockFsxWrite.mock.calls.find()`로 build.gradle/AndroidManifest/styles.xml 내용 검증
- `capacitor-build.spec.ts`: `mockFsxWrite.mock.calls`로 signingConfigs 내용 검증
- `capacitor-android.spec.ts`: `mockFsxWrite.mock.calls`로 versionCode 계산 검증
- `electron.spec.ts`: `mockEsbuildBuild.mock.calls[0][0]`로 banner/platform 설정 검증
- `capacitor-icon.spec.ts`: `mockSharp.toHaveBeenCalled()` (아이콘 생성 여부 = 동작 검증, 유지)

### 대안 검토

1. **fsx → 실제 temp fs** (D2에서 기각): cpx.spawn mock과 혼합 구조 발생, 6+1개 파일 대규모 리팩토링 필요. 테스트 내성 향상(9점)이 변경 리스크(4점)를 상쇄하지 못함
2. **sd-config → fixture** (D1에서 기각): jiti 런타임 의존성, 테스트별 config override 유연성 저하. 점수 차이(7.3 vs 7.0) 대비 7개 파일 수정 부담
3. **Engine startWatch 설정 전달 테스트 유지**: `startWatch.toHaveBeenCalledWith`는 Worker 계약 검증으로 볼 수 있으나, sd-testing.md의 "mock으로 호출 인자를 검증하는 것은 구현 세부사항" 원칙에 따라 제거. config 전달 정확성은 통합 테스트에서 검증
