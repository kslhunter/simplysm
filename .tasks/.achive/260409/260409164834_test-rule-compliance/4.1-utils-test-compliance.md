## 구현계획

### 배경

sd-cli 패키지의 `tests/utils/` 디렉토리에 17개 테스트 파일이 sd-testing.md 규칙을 위반한다. 주요 위반 유형은 mock 호출 인자/횟수 검증(구현 결합)이다. 대부분의 mock은 I/O 경계(파일시스템, ESLint, sharp, Worker 등)에 있어 mock 자체는 유지하되, 검증 방식을 전환한다. [근거: 16개 파일 코드 분석]

### 목표

- mock 인자 검증 → 반환값/결과 검증 전환 (반환값이 있는 함수) [근거: sd-testing.md "동작의 결과를 검증"]
- 호출 횟수 검증(toHaveBeenCalledTimes) 제거 [근거: sd-testing.md "몇 번 호출됐는가보다 올바른 결과가 나왔는가"]
- I/O 경계 mock 인자 검증은 사이드이펙트 검증으로 유지 [근거: D1 결정]

### 비목표

- mock 자체 제거 — 대부분 I/O 경계로 물리적 필요 [근거: sd-testing.md]
- vi.mock() → vi.spyOn() 전환 — 대부분 I/O 경계로 실제 구현 실행 불가 [근거: 코드 분석]
- 테스트 커버리지 변경 — 기존 시나리오 유지 [근거: WBS 경계]
- serializeDiagnostic mock 제거 — 실제 구현이 항등함수가 아님 [근거: D2 결정]

### 설계

#### 변경 전략 분류

**A. 반환값 검증 전환** — 함수가 의미 있는 반환값을 가진 경우 [근거: Rule "반환값 검증 우선"]

| 파일 | 함수 | 반환 타입 | 전환 대상 assertion |
|------|------|----------|-------------------|
| vite-config.spec.ts | `createClientViteConfig()` | `InlineConfig` | plugin factory toHaveBeenCalledWith → config.plugins 구조 검증 |
| orchestrator-utils.spec.ts | `loadAndValidateConfig()` | `SdConfig` | loadSdConfig/validateTargets toHaveBeenCalledWith → 반환 config 검증 |
| lint-core.spec.ts | `executeLint()` | `LintResult` | mockLintFiles toHaveBeenCalledWith → success/errorCount/warningCount 검증 |
| lint-utils.spec.ts | `runLintInWorker()` | `LintResult` | lintFn/terminateFn toHaveBeenCalledWith → 결과 검증 |
| lint-with-program.spec.ts | `LintWithProgramRunner.run()` | `LintResult` | mockLintFiles toHaveBeenCalledWith → 결과 검증 |
| typecheck-non-package.spec.ts | `typecheckNonPackageFiles()` | `NonPackageTypecheckResult` | rootNames 인자 검증 → diagnostics 배열 검증 |
| esbuild-config.spec.ts | `createServerEsbuildOptions()` | `BuildOptions` | 이미 결과 검증 중심 (일부 writeFile 인자 검증은 전략 C) |
| sd-config.spec.ts | `loadSdConfig()` | `SdConfig` | configFn 호출 인자 검증 1건 → 반환값 검증 |

**B. 호출 횟수 검증 제거** — toHaveBeenCalledTimes, toHaveBeenCalled (결과 검증으로 대체) [근거: Rule "호출 횟수 검증 제거"]

**D. 변경 불필요** [근거: 코드 분석 결과]

| 파일 | 사유 |
