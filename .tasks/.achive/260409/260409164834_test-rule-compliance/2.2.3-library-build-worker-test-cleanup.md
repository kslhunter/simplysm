## 구현계획

### 배경

`library-build.worker.ts`는 라이브러리 빌드용 Worker Thread 모듈이다. `runTscPackageBuild`(TSC 빌드 실행)와 `collectDeps`(워크스페이스 의존성 수집)를 사용하여 빌드/watch 기능을 제공한다. 현재 테스트는 이 두 함수를 `vi.mock`으로 모듈 전체를 대체하고, mock 호출 인자를 `toHaveBeenCalledWith`로 직접 검증하여 구현에 강하게 결합되어 있다. [근거: `library-build-worker.spec.ts` L47-60 vi.mock, L96-279 toHaveBeenCalledWith 8건]

### 목표

- tsc-build, package-utils를 vi.spyOn + mockReturnValue로 전환하여 개별 함수만 모킹 [근거: Rule "vi.spyOn 전환"]
- mock 호출 인자 검증 8건(mockRunTscPackageBuild 7건 + mockCollectDeps 1건) 제거 → 동작 결과 검증 유지 [근거: Rule "구현 결합 검증 제거"]
- 의미를 잃는 5개 테스트 삭제 [근거: D1 결정]

### 비목표

- Worker, FsWatcher, worker-utils mock 변경 [근거: WBS 경계 "Worker mock은 유지"]
- tsc-build, package-utils 실제 구현 테스트 추가 [근거: WBS 경계 — 각 모듈 자체 테스트에서 담당]
- 다른 테스트 파일 수정 [근거: WBS "Feature 2.2.3은 library-build-worker.spec.ts만 대상"]

### 설계

변경 대상: `packages/sd-cli/tests/workers/library-build-worker.spec.ts` 1개 파일

#### 1. vi.spyOn 전환 [근거: Rule "tsc-build/package-utils는 vi.spyOn으로 전환"]

**Before (tsc-build):**
```typescript
const mockRunTscPackageBuild = vi.fn(() => ({...}));
vi.mock("../../src/utils/tsc-build", () => ({
  runTscPackageBuild: mockRunTscPackageBuild,
}));
```

**After (tsc-build):**
```typescript
import * as tscBuild from "../../src/utils/tsc-build";
const mockRunTscPackageBuild = vi.spyOn(tscBuild, "runTscPackageBuild").mockReturnValue({
  success: true,
  errors: undefined,
  diagnostics: [],
  errorCount: 0,
  warningCount: 0,
  program: {
    getSourceFiles: () => [{ fileName: "/pkg/src/index.ts" }],
  },
} as any);
```

**Before (package-utils):**
```typescript
const mockCollectDeps = vi.fn((...) => ({...}));
vi.mock("../../src/utils/package-utils", () => ({
  collectDeps: (pkgDir, cwd, replaceDeps) => mockCollectDeps(pkgDir, cwd, replaceDeps),
}));
```

**After (package-utils):**
```typescript
import * as packageUtils from "../../src/utils/package-utils";
const mockCollectDeps = vi.spyOn(packageUtils, "collectDeps").mockReturnValue({
  workspaceDeps: [],
  replaceDeps: [],
});
```

`beforeEach`의 `mockReturnValue` 재설정 로직은 그대로 유지한다. `vi.clearAllMocks()`는 구현을 지우지 않으므로 안전하다.

#### 2. build() 구현 결합 검증 제거 [근거: Rule "mock 호출 인자 검증 제거"]

3개 테스트에서 `expect(mockRunTscPackageBuild).toHaveBeenCalledWith(...)` 라인만 제거:
- "runs tsc with output flags and returns combined result" (L96-98) — `result.build.success` 검증 유지
- "passes dts-only output to tsc" (L106-108) — `result.build.success` 검증 유지
- "runs typecheck only when both false" (L116-118) — `result.build.success` 검증 유지

2개 테스트 삭제 (검증이 남지 않음):
- "passes env from output to runTscPackageBuild" (L142-151)
- "passes undefined env when output.env is not set" (L154-163)

#### 3. startWatch() 구현 결합 검증 제거 [근거: Rule "mock 호출 인자 검증 제거"]

3개 테스트 삭제 (검증이 남지 않음):
- "does not require esbuild for watch mode" (L206-213)
- "calls collectDeps with pkgDir and cwd" (L246-249)
- "passes env to runTscPackageBuild on watch rebuild" (L266-280)

#### 4. 유지되는 테스트 목록 (14개)

### 대안 검토

- **vi.mock 유지 + toHaveBeenCalledWith만 제거**: vi.mock이 모듈 전체를 대체하므로 다른 export까지 가짜로 바뀌는 부작용 유지. sd-testing.md "호출 여부만 확인하려면 vi.spyOn"에 위배. 기각.
