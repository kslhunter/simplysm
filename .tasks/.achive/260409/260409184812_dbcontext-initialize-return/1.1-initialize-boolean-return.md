## 요구명세

```gherkin
Feature: 1.1 initialize() boolean 반환
  Background:
    Given DbContext에 migrations가 정의되어 있다

  Rule: initialize()는 마이그레이션 적용 여부를 boolean으로 반환한다
    # 근거: issue #21 "boolean으로 반환"

    Scenario: pending migration이 있는 기존 환경
      Given _migration 테이블에 일부 migration만 등록되어 있다

    Scenario: pending migration이 없는 기존 환경
      Given _migration 테이블에 모든 migration이 등록되어 있다
      When initialize()를 호출한다
      Then migration up()이 실행되지 않는다
      And false를 반환한다

    Scenario: force=true로 전체 재생성
      Given 데이터베이스가 존재한다
      When initialize({ force: true })를 호출한다
      Then 스키마가 초기화되고 객체가 재생성된다
      And migration up()이 실행되지 않는다
      And false를 반환한다

    Scenario: 새 환경 (migration 테이블 없음)
      Given _migration 테이블이 존재하지 않는다
      When initialize()를 호출한다
      Then 전체 객체가 생성된다
      And migration up()이 실행되지 않는다
      And false를 반환한다
```

## 구현계획

### 배경
`initializeImpl()` (initialize.ts:39-115)는 이미 내부에서 pending migration 여부를 계산하고 실행한다.
반환 타입을 `void`에서 `boolean`으로 변경하고, pending migration 실행 여부에 따라 값을 반환하면 된다.
[근거: initialize.ts 라인 107-112에서 pendingMigrations 계산 및 실행]

### 목표
- `initializeImpl()`이 `Promise<boolean>`을 반환한다 [근거: Rule "boolean으로 반환"]
- `DbContext.initialize()`가 그 값을 그대로 반환한다 [근거: Rule "boolean으로 반환"]

### 비목표
- 마이그레이션 적용 상세 목록 반환 [근거: wbs 경계 "상세 정보는 범위 외"]

### 설계

**initialize.ts 변경:**
- `initializeImpl` 반환 타입: `Promise<void>` → `Promise<boolean>`
- `force=true` 분기 (66-81행): `return false`
- 새 환경 분기 (94-103행): `return false`
- 기존 환경 분기 (104-113행): `return pendingMigrations.length > 0`

**db-context.ts 변경:**
- `DbContext.initialize()` 반환 타입: `Promise<void>` → `Promise<boolean>`
- `return await initializeImpl(this, options)` 으로 변경

### 대안 검토
- `{ migrated: boolean; count: number }` 반환 — issue에서 boolean만 요청했고, 향후 필요시 확장 가능. 현재는 과도한 설계.
