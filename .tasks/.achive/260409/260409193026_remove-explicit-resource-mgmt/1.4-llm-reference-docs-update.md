## 구현계획

### 배경

Feature 1.1과 1.3에서 `Symbol.dispose`/`Symbol.asyncDispose` 메서드와 `await using` 구문이 소스코드에서 제거되었다. LLM 참조 문서에 남아있는 이 패턴의 참조를 갱신하지 않으면, LLM이 소비자에게 제거된 패턴을 안내하여 동일한 파싱 에러를 유발한다. [근거: wbs "소비자가 LLM 문서를 참조하여 await using을 사용하면 동일 에러 발생"]

### 목표

- 모든 LLM 참조 문서에서 `await using`/`using`/`Symbol.dispose`/`Symbol.asyncDispose` 참조를 제거하여 소비자가 잘못된 패턴을 사용하지 않도록 한다 [근거: wbs Feature 1.4 범위]

### 비목표

- 코드 변경 없음 (문서만 수정) [근거: wbs 경계 "코드 변경 없음"]
- WBS/Feature 작업 문서 내의 히스토리 참조는 변경하지 않음

### 설계

변경 유형 3가지: [근거: Rule별 분류]

1. **코드 예시 변환**: `await using wb = new X()` → `const wb = new X(); try { ... } finally { await wb.close(); }`, `using x = new X()` → `const x = new X(); try { ... } finally { x.dispose(); }`
2. **API 시그니처/설명 제거**: 클래스 시그니처에서 `[Symbol.dispose](): void`/`async [Symbol.asyncDispose](): Promise<void>` 행 삭제, 메서드 테이블에서 해당 행 삭제
3. **안내 문구 변경**: `await using` 또는 `using` 문 언급을 `try-finally` + `close()`/`dispose()` 안내로 교체

### 대안 검토

없음. 순수 텍스트 대체 작업으로 기술적 대안이 없다.
