## 구현계획

### 배경

core-common 패키지의 5개 클래스에 Explicit Resource Management(`Symbol.dispose`/`Symbol.asyncDispose`) 래퍼 메서드가 존재한다. 이 메서드들은 esbuild에 의해 다운레벨 컴파일되지 않고 dist에 그대로 노출되어, Node.js 20 기반 소비앱에서 `using`/`await using` 구문 미지원으로 파싱 에러를 유발한다. [근거: wbs 배경]

각 Symbol 메서드는 기존 `dispose()`/`close()` 메서드에 단순 위임하는 래퍼이므로, 제거해도 기능 손실이 없다. [근거: 코드 확인]

### 목표

- `Symbol.dispose`/`Symbol.asyncDispose` 래퍼 메서드 완전 제거 [근거: Rule "래퍼 메서드 완전 제거"]
- JSDoc의 `await using` 예시를 try-finally 패턴으로 변경 [근거: Rule "try-finally 패턴으로 대체"]

### 비목표

- `dispose()`/`close()` 메서드 변경 [근거: wbs 경계 "기존 메서드 유지"]
- 테스트 코드 변경 [근거: Feature 1.2에서 별도 처리]
- LLM 참조 문서 변경 [근거: Feature 1.4에서 별도 처리]

### 설계

단순 삭제 작업. 각 클래스에서 `[Symbol.dispose]()`/`[Symbol.asyncDispose]()` 메서드와 관련 JSDoc 주석을 제거한다. ZipArchive의 클래스 JSDoc에서 `await using` 예시를 try-finally + `close()` 패턴으로 변경한다. [근거: D1, D2]

상속 관계 고려: DebounceQueue/SerialQueue는 EventEmitter를 상속하며 `override [Symbol.dispose]()`를 사용한다. EventEmitter에서 기반 메서드를 제거하므로 하위 클래스의 override도 반드시 함께 제거해야 한다. [근거: 코드 확인 — override 키워드 사용]

### 대안 검토

해당 없음. Symbol 래퍼 메서드 삭제는 유일한 접근 방식이다. polyfill이나 다운레벨 컴파일은 `using`/`await using` 구문 자체가 Node.js 20에서 미지원이므로 소비앱에서 호출 불가능한 dead code를 남기게 된다.
