## 구현계획

### 배경

코드 리뷰에서 발견된 Layout(kanban, dock) + Navigation(pagination, sidebar) 영역의 5건 이슈를 수정한다. 각 이슈는 독립적이며, 기존 컴포넌트의 로직 수정만 필요하다.

### 목표

- 칸반 전체선택/해제에서 selectable 플래그 일관성 확보
- 페이지네이션의 0 나누기 및 음수 페이지 경계값 방어
- 사이드바 백드롭 클릭의 의미 명확화 (toggle → close)
- sd-dock 리사이즈 시 document 이벤트 리스너 누수 방지

### 비목표

- 컴포넌트의 기능 변경 및 UI 변경
- 새로운 API 추가

### 설계

#### LOGIC-013: 칸반 selectable 필터링

파일: `packages/angular/src/ui/layout/kanban/sd-kanban-lane.control.ts`

- `isAllSelected` (line 139): `kanbanControls()`를 `ctrl.selectable()`로 필터링한 후 `every()` 적용
- `onSelectAllButtonClick(true)` (line 161): selectable 칸반만 순회하여 selectedValues에 추가
- `onSelectAllButtonClick(false)` (line 172): selectable 칸반의 값만 수집하여 selectedValues에서 제거

#### LOGIC-014: visiblePageCount 0 나누기 방지

파일: `packages/angular/src/ui/navigation/pagination/sd-pagination.control.ts`

- `groupIndex` (line 70): `this.visiblePageCount()` → `Math.max(this.visiblePageCount(), 1)`
- `hasNext`의 `lastGroupIndex` (line 85): 동일한 Math.max 적용

#### CONSIST-002: 백드롭 클릭 의미 명확화

파일: `packages/angular/src/ui/navigation/sidebar/sd-sidebar-container.control.ts`

- `onBackdropClick` (line 90): `this.toggle.update((v) => !v)` → `this.toggle.set(false)`

#### LOGIC-022: 네비게이션 메서드 경계값 가드

파일: `packages/angular/src/ui/navigation/pagination/sd-pagination.control.ts`

- `goToPrevGroup` (line 114): 시작부에 `if (!this.hasPrev()) return;` 가드 추가
- `goToLast` (line 122): 시작부에 `if (this.totalPageCount() === 0) return;` 가드 추가

#### DESIGN-004: Dock 리사이즈 cleanup

파일: `packages/angular/src/ui/layout/dock/sd-dock.control.ts`

- `DestroyRef` 주입
- `_dragCleanup` 클래스 필드 추가 (현재 드래그의 cleanup 함수 참조)
- `onResizeBarMousedown`에서 cleanup 함수를 `_dragCleanup`에 저장
- `stopDrag`에서 `_dragCleanup = undefined`로 초기화
- constructor에서 `DestroyRef.onDestroy(() => this._dragCleanup?.())`로 cleanup 등록

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| LOGIC-014: input transform에서 visiblePageCount 최소값 강제 | 미채택 | 호출자 API 변경이 발생하며, 0 입력 시 무시되는 동작이 혼란 유발 |
| LOGIC-014: Math.max를 나누기 연산에서 인라인 적용 | 채택 | 기존 API 동작 유지, 방어적 프로그래밍으로 충분 |
| DESIGN-004: AbortController signal 방식 | 미채택 | Chrome 66+에서 addEventListener signal 지원이므로 Chrome 61 호환성에 위배 |
| DESIGN-004: DestroyRef.onDestroy + 클래스 필드 참조 | 채택 | Angular 표준 패턴, Chrome 61 호환 |
