## 구현계획

### 배경

Feature 1.1에서 `check --type lint`의 독립 실행 경로를 구현했다. 그러나 로그 메시지는 아직 정리되지 않은 상태다:
- `typecheck.ts`의 `executeTypecheck()`는 `options.lint`를 받아 lint를 실행하지만, 로그 메시지에 lint 포함 여부가 반영되지 않는다 ("타입체크 실행 중..."만 출력)
- `lint-with-program.ts`는 시작 debug 로그 1줄만 출력하고 완료 로그가 없다
- `BuildOrchestrator.ts`와 `output-utils.ts`의 `typeLabel` 로직에서 `result.type === "lint"`가 누락되어, lint 에러가 target 이름(예: "node")으로 표시된다

### 목표

- typecheck.ts의 진행/완료/결과 로그에 lint 포함 여부 반영
- lint-with-program.ts에 완료 debug 로그 추가 (tsc-build.ts와 동등한 수준)
- build/watch/dev 결과 출력에서 lint 에러를 "lint" 라벨로 구분

### 비목표

- lint 실행 로직 변경 (로깅만 개선)
- check.ts의 결과 출력 섹션 변경 (이미 정확하게 동작)
- consola 로그 레벨 구조 변경

### 설계

#### typecheck.ts 변경

`executeTypecheck()` 함수 상단에 `phaseLabel` 변수를 도입하여, lint 포함 여부에 따라 로그 메시지를 분기한다.

```
const phaseLabel = options.lint === true ? "타입체크/린트" : "타입체크";
```

적용 위치:
- debug 시작 로그: `"${phaseLabel} 시작"` + `{ targets, lint: options.lint }`
- 대상 없음 로그: `"${phaseLabel} 대상 없음"`
- start 로그: `"${phaseLabel} 실행 중... (N개 작업, 동시성: M)"`
- success 로그: `"${phaseLabel} 실행 완료"`
- 결과 요약 로그: `"${phaseLabel} 완료"` or `"${phaseLabel} 에러 발생"` + lint 결과 필드 추가

결과 요약 로그의 메타 객체에 lint 정보를 조건부 추가:
```
{ errorCount, warningCount, ...(options.lint === true ? { lintErrorCount, lintWarningCount } : {}) }
```

#### lint-with-program.ts 변경

`LintWithProgramRunner.lint()` 메서드에서:
1. 기존 시작 로그 문구: `"린트 실행"` → `"린트 시작"` (D4 결정, tsc-build 패턴 통일)
2. 결과 반환 직전에 완료 로그 추가: `"[pkgName] 린트 완료 (에러: N, 경고: N)"`

#### BuildOrchestrator.ts + output-utils.ts 변경

typeLabel 로직에 lint 분기 추가:

```
// 기존
const typeLabel = result.type === "dts" ? "dts" : result.target;
// 변경
const typeLabel = result.type === "dts" ? "dts" : result.type === "lint" ? "lint" : result.target;
```

BuildOrchestrator.ts line 460과 output-utils.ts line 24 두 곳에 동일하게 적용.

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| phaseLabel 변수로 로그 메시지 분기 | 채택 | 단순하고 기존 코드 구조 유지. 한 곳에서 정의하여 일관성 보장 |
| 별도 logger 태그 ("sd:cli:typecheck-lint") 사용 | 미채택 | 태그는 모듈 식별용. 작업 내용은 메시지에 반영하는 것이 관례 |
| lint 결과를 별도 섹션으로 분리 (build) | 미채택 | build 출력 구조 대폭 변경 필요. typeLabel 수정만으로 충분한 구분 달성 |
| lint-with-program 로그를 info 레벨로 격상 | 미채택 | 다수 패키지 병렬 빌드 시 로그 과잉. debug 레벨이 워커 로그 관례 |
