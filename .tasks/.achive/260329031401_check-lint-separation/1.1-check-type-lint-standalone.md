## 구현계획

### 배경

현재 `check.ts`의 `runCheck()`에서 `needsTypecheck || needsLint` 조건으로 lint 요청도 `executeTypecheck()` 경로를 거친다. `executeTypecheck()`는 sd.config.ts를 로드하고 BuildEngine을 생성하여 워커를 통해 typecheck + lint를 실행하므로, lint만 필요한 경우에도 불필요한 typecheck 인프라가 초기화된다. `executeLint()` 함수가 `lint.ts`에 이미 독립 실행 가능하게 존재하므로, lint-only 시 이를 직접 호출하도록 분기한다.

### 목표

- `check --type lint` 실행 시 `executeLint()`를 직접 호출하여 `executeTypecheck()` 경로를 우회
- scripts 패키지 특수 처리 없이 모든 패키지를 `executeLint()` 단일 호출로 처리
- `LintResult` → `CheckResult` 변환으로 기존 결과 출력 형식 유지

### 비목표

- `executeTypecheck()` 내부 로직 변경 (기존 typecheck+lint 경로는 그대로 유지)
- `executeLint()` 함수 자체 변경
- build/watch/dev 명령어의 lint 동작 변경

### 설계

`check.ts`의 `runCheck()` 함수에서 분기 조건을 변경한다:

```
기존: if (needsTypecheck || needsLint) → executeTypecheck()
변경: if (needsTypecheck) → executeTypecheck({ lint: needsLint })
      else if (needsLint) → executeLint({ targets, fix, timing: false })
```

lint-only 분기에서:
1. `executeLint({ targets: normalizedTargets, fix: options.fix, timing: false })` 호출
2. 반환된 `LintResult`를 `CheckResult` 형식으로 변환: `{ name: "LINT", success, errorCount, warningCount, formattedOutput }`
3. scripts 패키지 별도 처리 없음 — `executeLint()`가 targets 필터링으로 모든 패키지 통합 처리

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| `executeLint()` 직접 호출 (in-process) | 채택 | 단순함, wbs 명세와 일치, lint 작업 규모에 워커 오버헤드 불필요 |
| `runLint()` 워커 경유 (lint-utils) | 미채택 | 워커 생성/종료 오버헤드, lint-only에서는 메인 스레드 블로킹이 문제되지 않음 |
