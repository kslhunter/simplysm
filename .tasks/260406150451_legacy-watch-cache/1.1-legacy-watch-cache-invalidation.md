## 구현계획

### 배경
`sdAngularPlugin`의 `buildStart()` 훅은 Rolldown watch 모드에서 파일 변경 시 매번 재호출된다. 현재 코드는 매번 새 `AngularCompiler`를 생성하면서 `sourceFileCache`는 `??=`로 재사용하지만 `invalidate()`를 호출하지 않아 캐시가 stale한 SourceFile을 반환한다. [근거: 디버그 분석 ACH 결과]

### 목표
- Rolldown watch 재빌드 시 변경된 파일의 캐시를 선택적으로 무효화한다 [근거: Rule "재빌드 시 선택적 캐시 무효화"]
- 기존 compiler를 재사용하여 증분 컴파일한다 [근거: D2 설계 결정]

### 비목표
- modern 모드(Vite dev server)의 handleHotUpdate 경로 변경 [근거: wbs 경계]
- legacy 모드 HMR 지원 [근거: wbs 제외 사항]

### 설계

**변경 파일:** `packages/sd-cli/src/angular/vite-angular-plugin.ts`

1. 플러그인 클로저에 `pendingWatchChanges: Set<string>` 추가
2. `watchChange(id, event)` 훅 추가 — `pendingWatchChanges.add(pathx.posix(id))`
3. `buildStart()` 분기:
   - **첫 빌드** (`compiler == null`): 기존 로직 그대로
   - **재빌드** (`compiler != null && pendingWatchChanges.size > 0`):
     1. `sourceFileCache.invalidate(pendingWatchChanges)` 호출
     2. `pendingWatchChanges.clear()`
     3. `compiler.update()` 대신 `compiler.initialize()` 호출 (update는 invalidate+initialize이므로, 이미 invalidate했으니 initialize만 호출)
     4. `emittedFiles.clear()` 후 `compiler.emitAffectedFiles()`로 재수집
     5. 진단 수집 및 보고

### 대안 검토

1. **sourceFileCache 전체 clear**: 구현은 단순하지만 모든 파일을 다시 파싱하므로 성능 저하. 선택하지 않음.
2. **compiler.update() 직접 호출**: `update()`가 내부적으로 `invalidate()` + `initialize()`를 하므로, `watchChange`에서 수집한 파일을 `update()`에 넘기는 것도 가능. 하지만 `buildStart()`에서 `scssDependencies`, `transformStylesheet` 등 설정을 매번 재생성하는 현재 구조상, 설정이 stale해질 수 있어 `initialize()` 경로를 택함.
