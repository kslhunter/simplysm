## 구현계획

### 배경

`ts-no-unused-protected-readonly` 규칙은 `@Component` 데코레이터가 붙은 클래스의 미사용 `protected readonly` 필드를 감지하고 autofix 로 제거한다. `collectTemplateNodeIdentifiers` 는 `parseTemplate` 결과 AST 를 순회하며, `@if`/`@for`/`@switch`/`@defer` 는 각각 명시 분기로 처리한다. 그러나 `TmplAstLetDeclaration` 은 공통 `node.value?.ast` 경로(`ts-no-unused-protected-readonly.ts:115-117`)에 암묵적으로 의존하는데, 이는 `@angular/compiler` d.ts 선언(`LetDeclaration.value: AST`)과 실제 런타임 형상(`.ast` 래퍼) 사이의 불일치에 기대는 위태로운 경로이다. Angular 가 이 래핑을 제거하거나 타입 선언에 맞춰 런타임을 정리하면 `items` 같은 참조가 조용히 누락되어 autofix 가 false positive 로 해당 필드를 삭제한다.

또한 `collectExprIdentifiers` (`:65-67`) 의 재귀 가드 `typeof val.constructor === "function"` 은 plain object 도 생성자가 `Object`(`typeof "function"`)이므로 실질적 필터링 효과가 없고 독자에게 의도를 오해시킨다.

### 목표

- `TmplAstLetDeclaration` 명시 분기로 Angular 내부 런타임 형상 변경에 대한 내성 확보 [근거: Rule "@let value 표현식 내 클래스 필드 참조는 명시 분기로 수집된다"]
- 공통 경로에서 LetDeclaration 스킵 가드로 이중 수집 방지 [근거: Rule "공통 node.value?.ast 경로는 LetDeclaration 을 처리하지 않는다"]
- `collectExprIdentifiers` 재귀 가드 단순화로 오해 유발 조건 제거 [근거: Rule "collectExprIdentifiers 재귀 가드는 단순화된 null/object 조건만 사용한다"]
- 기존 테스트 16건 회귀 보증 + 신규 테스트 2건으로 명시 분기 실증 [근거: wbs "기존 테스트 16건 통과 보장", "신규 테스트"]

### 비목표

- `traverseNode`(ESLint AST 순회 헬퍼) 변경 [근거: wbs 경계]
- `collectSiblingNodes` 스코프 전파 로직 변경 [근거: wbs 경계 — 이미 1차 후속에서 확립]
- `@if`/`@for`/`@switch`/`@defer` 블록 처리 변경 [근거: wbs 경계 — 1차 후속에서 완료]
- `@angular/compiler` 버전 변경 [근거: wbs 경계]

#### 변경 1: `collectExprIdentifiers` 가드 단순화 (L65-67)

Before:
```ts
} else if (val != null && typeof val === "object" && typeof val.constructor === "function") {
```

After:
```ts
} else if (val != null && typeof val === "object") {
  collectExprIdentifiers(val, localVars, ids);

```

- 근거: review.md DESIGN-001 A안. span/sourceSpan/nameSpan 스킵(`:57`)만으로 무한 루프 방지는 충분하다.

#### 변경 2: `collectTemplateNodeIdentifiers` 에 LetDeclaration 명시 분기 추가

기존 L93-95 (currentLocals 에 name 추가) 직후에 이어서 value 표현식을 명시 순회한다. 공용 헬퍼 `collectExprIdentifiers` 재사용.

추가 블록 (L95 직후 삽입):
```ts
// @let value 표현식: 타입 선언은 AST 이지만 런타임에는 ASTWithSource 유사체(.ast 래퍼)가 들어온다.
// 공통 node.value?.ast 경로에 의존하지 않고 명시 분기로 처리하여 @angular/compiler 내부 변경에 대한 내성 확보.
if (node instanceof TmplAstLetDeclaration) {
  const expr = (node.value as { ast?: unknown }).ast ?? node.value;
  collectExprIdentifiers(expr, currentLocals, ids);
}
```

- `TmplAstLetDeclaration` 은 이미 import 되어 있음 (L12)
- `node.value` 는 d.ts 상 `AST` 이지만 런타임 형상에 `.ast` 가 존재 → 안전 접근 패턴으로 둘 다 지원
- 근거: review.md LOGIC-002 A안 + 다른 블록 노드(IfBlockBranch, ForLoopBlock, SwitchBlock, DeferredBlock)의 명시 분기 패턴과 일관

#### 변경 3: 공통 `node.value?.ast` 경로에 LetDeclaration 스킵 가드 + 주석 명확화 (L114-117)

Before:
```ts
// 보간 / BoundText
if (node.value?.ast != null) {
  collectExprIdentifiers(node.value.ast, currentLocals, ids);
}
```

After:
```ts
// 보간 / BoundText / BoundAttribute 등 ASTWithSource 노드용 공통 경로.
// LetDeclaration 은 위에서 명시 분기로 처리되므로 여기서 제외한다 (이중 수집 방지).

  collectExprIdentifiers(node.value.ast, currentLocals, ids);
}
```

- 근거: wbs 1.2 범위 "LetDeclaration 에 대해서도 node.value.ast 경로가 걸리지 않도록 instanceof TmplAstLetDeclaration 가드로 스킵 처리"

#### 신규 테스트 (tests/ts-no-unused-protected-readonly.spec.ts 내 describe 추가)

기존 파일 패턴(`ruleTester.run` + `describe` 중첩) 그대로 따른다.

1. **`@let value 가 단순 필드 참조일 때 해당 필드는 사용된 것으로 인식`** (valid only)
   ```ts
   @Component({
     template: `@let a = someRef; {{ a }}`
   })
   class MyComponent {
     protected readonly someRef = "v";
   }
   ```

2. **`중첩 @let 에서 첫 번째 @let 의 name 은 이후 형제에서 로컬로 인식되어 동명 필드가 미사용으로 감지`** (invalid + autofix)
   ```ts
   // code
   @Component({
     template: `@let x = 1; @let y = x + foo; {{ y }}`
   })
   class MyComponent {
     protected readonly x = 99;   // 미사용으로 감지
     protected readonly foo = 0;  // @let y 의 value 에서 참조됨
   }

   // output — x 만 제거됨
   @Component({
     template: `@let x = 1; @let y = x + foo; {{ y }}`
   })
   class MyComponent {
     protected readonly foo = 0;
   }
   ```
   errors: `[{ messageId: "unusedField", data: { name: "x" } }]`

### 대안 검토

- **대안 A: LetDeclaration 만 타입 캐스팅으로 공통 경로 유지** — 런타임 형상 우연한 일치에 계속 의존하므로 LOGIC-002 의 핵심 결함(타입 선언과 런타임 불일치)이 해소되지 않음. 기각.
- **대안 B: `collectExprIdentifiers` 가드를 `val instanceof AST` 로 강화** — review.md 에서 언급된 정확한 검사 방식. 그러나 `AST` 는 `@angular/compiler` 의 추상 클래스이고 현재 코드가 이미 `PropertyRead instanceof` 검사를 내부에서 수행하므로, 재귀 가드를 강화해도 동작은 동일. 반면 `AST` import 추가와 오용 가능성(내부 프로퍼티 중 plain object 가 있을 경우 탐색 누락)을 감수해야 함. 단순화(`val != null && typeof val === "object"`)가 최소 변경으로 오해만 제거하므로 우선.
- **대안 C: `@angular/compiler` 타입 선언과 런타임 정합화 PR 업스트림** — wbs 경계 외, 소요 기간 긴. 기각.
