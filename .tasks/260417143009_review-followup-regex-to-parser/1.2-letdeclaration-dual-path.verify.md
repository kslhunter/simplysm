# Feature 1.2 공통 경로의 LetDeclaration 스킵 가드 — LLM 검증

## 배경

설계 결정 D3(공통 `node.value?.ast` 경로에 `!(node instanceof TmplAstLetDeclaration)` 가드 추가) 는
외부 동작으로 드러나지 않는 구조적 변경이다. 자동 테스트로 "중복 순회 여부"를 검증하면
`collectExprIdentifiers` 호출 횟수를 세는 구현 결합 검증이 되므로, 정적 코드 확인으로 실증한다.

## 검증 항목

- [x] 공통 `node.value?.ast` 경로에 `!(node instanceof TmplAstLetDeclaration)` 가드가 적용되어 있다.
  - 파일: `packages/lint/src/rules/ts-no-unused-protected-readonly.ts:121-125`
  - 확인 코드:
    ```ts
    // 보간 / BoundText / BoundAttribute 등 ASTWithSource 노드용 공통 경로.
    // LetDeclaration 은 위에서 명시 분기로 처리되므로 여기서 제외한다 (이중 수집 방지).
    if (!(node instanceof TmplAstLetDeclaration) && node.value?.ast != null) {
      collectExprIdentifiers(node.value.ast, currentLocals, ids);
    }
    ```
  - 결과: 가드 존재 확인됨. LetDeclaration 은 공통 블록에서 no-op 처리된다.

- [x] `TmplAstLetDeclaration` 명시 분기가 공통 경로보다 **앞서** 수행된다 (순서 보장).
  - 파일: `packages/lint/src/rules/ts-no-unused-protected-readonly.ts:97-102` (명시 분기) vs `:121-125` (공통 경로)
  - 확인 내용: 명시 분기는 `collectTemplateNodeIdentifiers` 함수 상단(L97-102)에, 공통 경로는
    그 아래(L121-125)에 위치한다. 함수가 순차 실행되므로 동일 노드에 대해 명시 분기가 먼저
    호출되고 공통 경로 가드에서 스킵된다.
  - 결과: 순서 보장 확인됨.

- [x] 가드 단순화(`val != null && typeof val === "object"`)가 적용되었고 `typeof val.constructor === "function"` 조건이 제거되었다.
  - 파일: `packages/lint/src/rules/ts-no-unused-protected-readonly.ts:65-67`
  - 확인 코드:
    ```ts
    } else if (val != null && typeof val === "object") {
      collectExprIdentifiers(val, localVars, ids);
    }
    ```
  - `grep "typeof val.constructor"` 로 잔존 여부 확인 → 매치 없음.
  - 결과: 단순화 완료.

- [x] `TmplAstLetDeclaration` import 가 유지되어 명시 분기와 공통 경로 가드가 동일 심볼을 참조한다.
  - 파일: `packages/lint/src/rules/ts-no-unused-protected-readonly.ts:12`
  - 확인 내용: 기존 L12 의 `TmplAstLetDeclaration` import 가 변경 없이 유지됨.
  - 결과: import 유지 확인됨.

- [x] 기존 16건 + 신규 3건 총 19건 회귀 없이 통과한다.
  - 실행: `pnpm test packages/lint/tests/ts-no-unused-protected-readonly.spec.ts`
  - 결과: `Tests 19 passed (19)` — 회귀 없음.
