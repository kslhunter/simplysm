## 구현계획

### 배경

`client.worker.ts`의 `startWatch()` 함수 내 `sd-build-start` esbuild 플러그인은 `onStart`에서 `loadResultCache.watchFiles`를 순회하며 파일 변경을 감지한다. Angular `createCompilerPlugin`이 TypeScript 파일을 `loadResultCache`에 등록하지 않아 TS 파일 변경이 감지되지 않는다. [근거: debug.md]

### 목표

- `onStart`/`onEnd`에서 `typeScriptFileCache.keys()`를 추가 감시하여 TS 파일 변경 시 `sourceFileCache.invalidate()` 호출 [근거: Rule "TS 파일 변경 시 invalidate에 포함"]
- 기존 JS 파일 감시 동작 보존 [근거: Rule "JS 파일 변경도 기존처럼 동작"]

### 비목표

- Angular `createCompilerPlugin` 내부 수정 [근거: wbs 경계 "외부 패키지"]
- HMR 메시지 디스패치 변경 [근거: wbs 경계]

### 설계

`sd-build-start` 플러그인의 `onStart`/`onEnd`에서 감시 대상 파일 목록을 확장한다:

```typescript
// onStart: JS + TS 파일 모두 감시
const { loadResultCache, typeScriptFileCache } = esbuildResult.sourceFileCache;
const watchTargets = [...loadResultCache.watchFiles, ...typeScriptFileCache.keys()];
for (const file of watchTargets) { /* mtime 비교 */ }

// onEnd: prevMtimes에 JS + TS 파일 모두 기록
const watchTargets = [
  ...esbuildResult.sourceFileCache.loadResultCache.watchFiles,
  ...esbuildResult.sourceFileCache.typeScriptFileCache.keys(),
];
for (const file of watchTargets) { /* mtime 기록 */ }
```

### 대안 검토

- `sourceFileCache.keys()` (SourceFileCache가 Map 상속) 사용 → 키가 posix 경로로 변환되어 있어 (`source-file-cache.js:71`) Windows에서 `fs.statSync`와 경로 불일치 발생 가능. `typeScriptFileCache.keys()`는 `path.normalize()` 적용된 OS-native 경로이므로 안전.
