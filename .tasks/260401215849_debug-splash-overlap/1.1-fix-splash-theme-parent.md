# Feature 1.1 스플래시 테마 parent 변경

## 참조 자료

- [debug.md](./debug.md)

### 근본 원인

Capacitor 7 기본 `styles.xml`에서 `AppTheme.NoActionBarLaunch`의 parent가 `Theme.SplashScreen`으로 설정됨. `Theme.SplashScreen`은 `android:windowBackground`에 `@drawable/compat_splash_screen` (아이콘+배경 layer-list)을 설정하고, 자식 테마의 `android:background`에 `@drawable/splash`(로고)가 별도 설정되어 두 레이어가 동시에 렌더링됨.

### 대상 코드

- `packages/sd-cli/src/capacitor/capacitor.ts` — `_configureAndroid` 메서드
- 기존 패턴: `_configureAndroidManifest`에서 정규식 기반 XML 수정

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | parent 변경 대상 | `Theme.SplashScreen` → `Theme.AppCompat.DayNight.NoActionBar` | `installSplashScreen()` 미호출이므로 `Theme.SplashScreen` 기능 미사용. `compat_splash_screen` 레이어 제거가 목적 |

## 구현계획

### 배경

`_configureAndroid` 메서드는 Android 네이티브 설정을 구성하는 private 메서드들을 순차 호출한다 (`_configureAndroidManifest`, `_configureAndroidBuildGradle` 등). 각 메서드는 파일 존재 확인 → 내용 읽기 → 정규식/문자열 치환 → 저장의 공통 패턴을 따른다. 현재 `styles.xml`은 수정하지 않아 `Theme.SplashScreen`의 `compat_splash_screen` 레이어가 그대로 남아 로고 겹침이 발생한다.

### 목표

- `styles.xml`의 `AppTheme.NoActionBarLaunch` parent를 `Theme.SplashScreen` → `Theme.AppCompat.DayNight.NoActionBar`로 변경

### 비목표

- splash drawable 생성 방식 변경
- `installSplashScreen()` 호출 추가
- `capacitor-assets generate` 에러 처리 개선 (별도 Feature)

### 설계

`_configureAndroidStyles` private 메서드를 추가하고, `_configureAndroid`에서 기존 메서드들과 동일하게 호출한다.

- 경로: `{androidPath}/app/src/main/res/values/styles.xml`
- 치환: `parent="Theme.SplashScreen"` → `parent="Theme.AppCompat.DayNight.NoActionBar"`
- 멱등성: `Theme.SplashScreen`이 포함된 경우에만 치환 (이미 변경된 경우 무변경)
- 미존재 시: warn 로그 출력 후 return

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| parent 변경 (채택) | 채택 | 가장 단순. `installSplashScreen()` 미사용이므로 기능 손실 없음 |
| `android:background` 제거 + `windowSplashScreenAnimatedIcon` 설정 | 미채택 | `Theme.SplashScreen` 기능을 사용하지 않는 상태에서 불필요한 복잡성 |
