## 구현계획

### 배경

sd-cli 코드 리뷰에서 발견된 8건의 이슈를 수정한다. 모든 수정은 기존 동작을 유지하면서 정확성, 안전성, 성능을 개선한다. [근거: review.md]

### 목표

- versionCode 충돌 제거 [근거: Rule "versionCode는 semver 범위 내에서 유일"]
- dist 삭제 감지를 모든 라이브러리 패키지로 일반화 + 리소스 정리 [근거: Rule "dist 삭제 감지 watcher", D1]
- esbuild context dispose 안전성 확보 [근거: Rule "esbuild context 재생성 실패 시에도 dispose"]
- 인용부호 보존 [근거: Rule "PostCSS 인라인 처리 시 원본 인용부호 보존"]
- catch-all 에러 필터링 [근거: Rule "replaceDeps 로딩에서 예상 가능한 에러만 무시"]
- symlink 테스트 임시 파일 정리 [근거: Rule "symlink 테스트에서 임시 파일 정리"]
- AndroidManifest.xml XML 파서 전환 [근거: Rule "XML 파서를 사용", D2]
- 배포 실패 패키지 검색 Set 사용 [근거: Rule "Set을 사용"]

### 비목표

- 기능 추가나 구조 리팩토링 [근거: wbs 경계 "기능 추가나 리팩토링 없음"]
- XML 파서 전환은 `_configureManifest` 함수에만 적용 [근거: wbs 경계]

### 설계

**LOGIC-001 (capacitor-android.ts:260-263)**: versionCode 공식을 `major*1000000 + minor*1000 + patch`로 변경. [근거: Rule "versionCode 유일성"]

**DESIGN-001 (DevWatchOrchestrator.ts:282-292)**: 기존 angular 전용 디버그 블록을 제거하고, `_libraryPackages`를 순회하여 모든 라이브러리 패키지의 `dist/` 디렉토리를 감시하는 watcher를 클래스 필드 `_distDeleteWatchers: FsWatcher[]`에 저장. `shutdown()`에서 close(). [근거: D1, 기존 `_copySrcWatchers` 패턴과 동일]

**DESIGN-002 (server-build.worker.ts:434-440)**: `const oldContext = esbuildContext; try { esbuildContext = await create...; } finally { await oldContext?.dispose(); }` 패턴으로 변경. [근거: Rule "실패 시에도 dispose"]

**LOGIC-002 (vite-postcss-inline-plugin.ts:115-123)**: else 분기에서 `origChar`(`'` 또는 `"`)를 그대로 사용하여 이스케이프 + 래핑. [근거: Rule "원본 인용부호 보존"]

**DESIGN-003 (sd-cli.ts:37-38)**: catch 블록에서 에러 코드가 `MODULE_NOT_FOUND` 또는 `ERR_MODULE_NOT_FOUND`이면 무시, 그 외는 `console.warn`으로 경고. [근거: Rule "예상 가능한 에러만 무시"]

**DESIGN-004 (electron.ts:343-358)**: try-catch-finally 구조로 변경. finally에서 testLink, testTarget을 각각 try-catch로 감싸 unlink. [근거: Rule "임시 파일 정리"]

**DESIGN-005 (capacitor-android.ts:147-217)**: `@simplysm/core-common`의 `xml.parse()`/`xml.stringify()`를 사용하여 `_configureManifest`를 재작성. fast-xml-parser의 `format: true` 옵션으로 포맷 유지. [근거: D2]

**PERF-001 (publish.ts:773)**: `const publishedSet = new Set(publishedPackages);` 후 `publishedSet.has(n)` 사용. [근거: Rule "Set.has()로 O(1) 조회"]

### 대안 검토

- DESIGN-005에서 regex 기반 유지 + 경고 로그를 고려했으나, 사용자가 XML 파서 도입을 선택. core-common에 이미 유틸이 있어 추가 의존성 불필요.
- DESIGN-001에서 디버그 코드 제거를 고려했으나, 사용자가 아직 미해결 문제를 추적 중이므로 일반화하여 유지.
