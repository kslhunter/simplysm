# 디버그: sd-modal 컴포넌트에 스타일 누락

## 출처

- **origin:** `direct` — 사용자 직접 입력
- **완료 시 참고:** 해당 없음

## 문제 증상

- **유형:** 동작 이상
- **증상:** 기대: sd-modal에 backdrop, dialog, header, content 등 시각적 스타일이 존재 / 실제: styles 속성 자체가 없고, 전역 SCSS에도 모달 스타일 미정의
- **위치:** `packages/angular/src/ui/overlay/modal/sd-modal.control.ts`
- **재현 절차:** sd-modal.control.ts 파일에서 `styles` 속성 부재 확인. scss/ 디렉토리에서 modal 관련 스타일 검색 시 z-index 변수만 존재.

## 근본 원인 추적 (ACH)

### ACH 매트릭스

|            | E1: styles 속성 없음 | E2: 전역 SCSS에도 없음 | E3: 표준 패턴과 불일치 | E4: CSS 클래스만 존재 |
| ---------- | -------------------- | ---------------------- | ---------------------- | --------------------- |
| H1: 스타일 누락 (추가 필요) | C(code) | C(code) | C(code) | C(code) |
| H2: 외부 소비 프로젝트에서 스타일 제공 의도 | C(infer) | C(infer) | I | I |

### 결과: 확정 — H1

H2는 E3(동일 overlay 카테고리의 모든 형제 컴포넌트가 인라인 스타일 보유), E4(template CSS 클래스명이 `_` prefix 내부 규칙을 따름)와 불일치. 스타일 누락 확정.

## 해결 방안

### 방안 A: 인라인 SCSS 추가 (표준 패턴)

- **설명:** `sd-modal.control.ts`에 `styles: [/* language=SCSS */ '...']`를 추가하여 backdrop, dialog, header, content, resize-handle 스타일 정의
- **장점:** 프로젝트 표준 패턴과 일치, 컴포넌트 자체 완결성 확보
- **반론:** 기존 소비 프로젝트에서 커스텀 스타일 사용 시 충돌 가능성 (현재 스타일 없으므로 낮음)
- **점수:** 일관성 9/10, 안정성 8/10, 완결성 9/10 → **평균 8.7/10**

### 방안 B: 전역 SCSS에 `_sd-modal.scss` 추가

- **설명:** `scss/controls/` 아래에 별도 partial 파일로 모달 스타일 정의
- **장점:** 스타일 오버라이드가 쉬움
- **반론:** 프로젝트 표준 패턴(인라인 SCSS)과 불일치
- **점수:** 일관성 4/10, 안정성 7/10, 완결성 8/10 → **평균 6.3/10**

### 방안 C: 수행 안 함

- **장점:** 기존 동작에 영향 없음
- **반론:** 모달이 스타일 없이 렌더링됨
- **점수:** 일관성 3/10, 안정성 10/10, 완결성 1/10 → **평균 4.7/10**

## 선택 결과

**방안 A** (평균 8.7/10)

sd-modal.control.ts에 인라인 SCSS styles를 추가하여 프로젝트 표준 패턴과 일치시킨다.
