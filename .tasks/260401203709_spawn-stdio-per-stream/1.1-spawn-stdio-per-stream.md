# Feature 1.1 cpx.spawn stdio 스트림별 개별 판단

## 참조 자료

### 대상 파일
- `packages/core-node/src/utils/cp.ts` — `spawn()` (121행), `spawnSync()` (173행)

### 현재 문제
- `hasPipe` 변수가 `opts.stdio === "pipe" || opts.stdio === undefined`로만 비교
- 배열 stdio(예: `["ignore","inherit","inherit"]`)를 전혀 처리하지 못함
- 배열일 때 항상 `hasPipe=false` → pipe인 개별 스트림도 수집하지 않음

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | 판단 단위 | stdout/stderr 개별 판단 | 배열 stdio에서 스트림마다 다른 모드를 쓸 수 있으므로 |

## 구현계획

### 배경

`cpx.spawn`/`cpx.spawnSync`의 stdio 처리가 문자열 전체 비교(`=== "pipe"`)만 지원하여, 배열 stdio에서 스트림별로 다른 모드를 지정해도 개별 판단이 불가능하다.

### 목표

- `spawn()`과 `spawnSync()` 모두 배열 stdio에서 stdout/stderr을 개별 판단
- 기존 문자열 stdio 동작은 그대로 유지

### 비목표

- stdin(index 0) 처리 변경 — 현재도 수집하지 않으며 변경 불필요

### 설계

`hasPipe` 단일 boolean을 `stdoutIsPipe`/`stderrIsPipe` 두 개로 분리한다.

헬퍼 함수:
```typescript
function resolveStdioPipe(stdio: SpawnOptions["stdio"]): { stdout: boolean; stderr: boolean } {
  if (Array.isArray(stdio)) {
    return { stdout: stdio[1] === "pipe", stderr: stdio[2] === "pipe" };
  }
  const isPipe = stdio === "pipe" || stdio == null;
  return { stdout: isPipe, stderr: isPipe };
}
```

`spawn()`:
- `stdoutIsPipe`이면 `cp.stdout!.on("data", ...)` 등록
- `stderrIsPipe`이면 `cp.stderr!.on("data", ...)` 등록
- close 시 pipe인 스트림만 decode, 나머지는 빈 문자열

`spawnSync()`:
- `stdoutIsPipe`이면 `result.stdout`을 decode, 아니면 빈 문자열
- `stderrIsPipe`이면 `result.stderr`를 decode, 아니면 빈 문자열

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| 헬퍼 함수로 분리 | 채택 | spawn/spawnSync 양쪽에서 재사용, 단일 책임 |
