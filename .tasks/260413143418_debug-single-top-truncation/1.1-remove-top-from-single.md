## 구현계획

### 배경

`Queryable.single()` 메서드(`queryable.ts:1044`)가 `this.top(2).execute()`를 호출하여, 1:N JOIN이 있는 경우 raw SQL 행이 2개로 제한되어 관계 데이터가 잘린다. [근거: debug.md ACH 분석]

### 목표

- `single()`에서 `top(2)` 호출을 제거하여 1:N include 조합에서 데이터 잘림을 해결한다 [근거: Rule "1:N include + single은 관계 데���터를 누락 없이 반환"]
- 기존 0/1/2+ 건 검증 동작을 유지한다 [근거: Rule "single()은 0-1건 반환, 2건 이상은 에러"]

### 비목표

- `exists()` 메서드의 `top(1)` 변경 [근거: wbs 경계]
- `top()` 메서드 자체의 로직 변경 [근거: wbs 경계]

### 설계

**변경**: `packages/orm-common/src/exec/queryable.ts:1045`

```typescript
// Before
const result = await this.top(2).execute();

// After
const result = await this.execute();
```

나머지 로직(result.length > 1 검증, ArgumentError throw)은 그대로 유지.

**테스트**: `packages/orm-common/tests/errors/queryable-errors.spec.ts`에 `single()` 테스트 추가

- MockExecutor의 `executeDefs`를 `vi.spyOn`으��� 오버라이드하여 반환값을 제어
- 0건/1건/2건 각각의 동작 검증
- 1:N include + single 시 생성되는 SelectQueryDef에 `top` 속성이 없음을 검증 (회귀 방지)
