## 구현계획

### 배경

`electron.ts`의 `run()`과 `_bundleMainProcess()`에서 `format: "cjs"`를 사용 중. 서버 패키지(`esbuild-config.ts:77-96`)에서는 이미 `format: "esm"` + `createRequire` 배너 패턴을 사용하고 있어, 동일한 패턴을 적용.

### 목표

- Electron main process 번들링을 ESM으로 전환 [근거: Rule "ESM 포맷 출력"]
- CJS 의존성 호환성 유지 [근거: Rule "CJS 호환 배너"]

### 비목표

- 소비앱 코드 변경 [근거: wbs 경계]
- Electron builder 설정 변경 [근거: wbs 경계]

### 설계

1. **ESM 배너 구성**: `createRequire` shim + envBanner (서버 패키지 패턴)
   - `"import { createRequire } from 'module'; const require = createRequire(import.meta.url);" + envBanner`
   - [근거: Rule "CJS 호환 배너" 처리를 위해]

2. **esbuild format 변경**: `format: "cjs"` → `format: "esm"`
   - `run()` (line 135)과 `_bundleMainProcess()` (line 302) 모두 변경
   - [근거: Rule "ESM 포맷 출력" 처리를 위해]

3. **package.json type 추가**: `_setupNpmConf()`에서 `"type": "module"` 설정
   - [근거: Rule "package.json ESM 인식" 처리를 위해]

### 대안 검토

- `createElectronEsbuildOptions()` 유틸 함수 분리 — 두 곳(run/build)에서만 사용하므로 과도한 추상화. 기각.
