# Feature 1.1 mark signal utility

## 참조 자료

### 개요

Angular `WritableSignal`의 객체/배열 값을 in-place mutation한 뒤, signal consumer(computed, effect, 템플릿 바인딩)에게 변경을 수동 알리는 유틸리티 함수.

### 배경

- Angular 팀은 `mutate()` 메서드를 의도적으로 제거했고 복원 계획 없음 (angular/angular#51821, #58429)
- `signal.update(v => ({...v}))` immutable 패턴은 중첩 객체 two-way binding에서 코드 폭발 유발
- `mark(sig)` 한 줄로 mutation 후 알림이 가능하여 `[(value)]="a().b" (valueChange)="mark(a)"` 패턴 지원

### 참조 구현 (12버전)

- 파일: `D:\workspaces-12\simplysm\packages\sd-angular\src\core\utils\bindings\utils\$mark.ts`
- `@angular/core/primitives/signals`의 `SIGNAL`, `producerIncrementEpoch`, `producerNotifyConsumers`, `runPostSignalSetFn` 사용
- 12버전에는 `clone` 옵션이 있었으나, 14버전에서는 제거 (mutation + mark 패턴에 불필요)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | 함수명 | `mark` (`$` 접두어 제거) | 일반 유틸리티 함수에 `$` 불필요 |
| D2 | clone 옵션 | 유지 (optional param) | 배열을 자식 컴포넌트에 전달할 때 referential equality 문제로 새 참조가 필요한 경우 존재 |

## 구현계획

### 배경

`packages/angular/src/core/utils/`에 signal 관련 유틸리티 함수들이 위치한다 (`withBusy.ts`, `setSafeStyle.ts` 등). Angular 21의 `@angular/core/primitives/signals` 모듈에서 signal 내부 노드 조작 API가 export되어 있음을 확인했다.

### 목표

- `mark(sig: WritableSignal<any>): void` 함수 구현
- `packages/angular/src/index.ts`에서 export
- 단위 테스트 작성

### 비목표

- clone 옵션 (D2에서 제거 결정)
- 템플릿 바인딩 통합 테스트 (단위 테스트로 signal consumer 알림만 검증)

### 설계

```typescript
// packages/angular/src/core/utils/mark.ts
import type { WritableSignal } from "@angular/core";
import {
  producerIncrementEpoch,
  producerNotifyConsumers,
  producerUpdatesAllowed,
  runPostSignalSetFn,
  SIGNAL,
} from "@angular/core/primitives/signals";

export function mark(sig: WritableSignal<any>): void {
  if (!producerUpdatesAllowed()) {
    throw new Error();
  }

  const node = sig[SIGNAL] as any;
  node.version++;
  producerIncrementEpoch();
  producerNotifyConsumers(node);
  runPostSignalSetFn(node);
}
```

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| Angular 내부 primitives 직접 사용 | 채택 | clone 없이 변경 알림만 트리거. Angular 16부터 유지된 API |
| `signal.update(v => v)` + `equal: () => false` | 미채택 | 모든 signal 생성 시 equal 옵션 필요, downstream computed도 동일 설정 필요 |
| `signal.update(v => ({...v}))` immutable 패턴 | 미채택 | 중첩 객체 two-way binding에서 코드 폭발 |
