## 구현계획

### 배경
Feature 1.1~2.2에서 서버 빌드 파이프라인을 esbuild tsc 플러그인 통합 구조로 변경하고, 관련 단위/수락 테스트를 업데이트했다. 이 Feature는 변경으로 인한 회귀가 없는지 전체 파이프라인 수준에서 검증한다. [근거: wbs "빌드 인프라 변경이므로 회귀 검증 필수"]

### 목표
- 통합 테스트(tests/sd-cli-server/) 회귀 없음 확인 [근거: Rule "통합 테스트 회귀 없음"]
- sd-cli 전체 검사(typecheck + lint + test) 통과 확인 [근거: Rule "sd-cli 전체 검사 통과"]
- dev 모드 수동 검증 기준 제공 [근거: Rule "dev 모드 watch 정상 동작"]

### 비목표
- 다른 패키지(angular, core-common 등) 테스트 [근거: wbs 경계 "다른 패키지의 테스트는 이 범위에 포함하지 않음"]
- 새 통합 테스트 작성 [근거: wbs 범위가 "실행 및 통과 확인"으로 한정]
- tests/sd-cli-server/의 banner env 테스트 수정 [근거: tsc 플러그인은 banner 메커니즘과 독립적]

### 설계

**자동 검증 (Slice 1-2):**
1. `npx vitest run --project sd-cli-server` — 통합 테스트 프로젝트 실행 [근거: vitest.config.ts:78-85]
2. `pnpm check -t sd-cli` — 전체 검사 실행 [근거: CLAUDE.md 명령어 섹션]
3. 실패 시 에러 메시지 분석 → Feature 1.1~2.2 관련 코드/테스트 수정 후 재실행

**수동 검증 (Slice 3):**
4. 사용자에게 dev 모드 검증 기준 안내:
   - 외부 프로젝트(target: "server" 패키지 포함)에서 `pnpm dev -t {서버패키지}` 실행
   - 확인 항목: 초기 빌드 성공, 파일 변경 시 watch rebuild, tsc 에러 리포팅
   - [근거: sd.config.ts에 server 패키지 없음 → 외부 프로젝트 필요]
