## 구현계획

### 배경

Feature 1.1~1.3에서 서버 빌드 파이프라인이 수동 병렬(esbuild ‖ tsc) 구조에서 esbuild tsc 플러그인 통합 구조로 변경되었다. 이에 따라 기존 테스트 파일의 모킹 구조와 검증 로직을 업데이트해야 한다. [근거: wbs "build/rebuildAll 호출 구조 변경 반영"]

### 목표

- 기존 서버 빌드 테스트가 새 tsc 플러그인 통합 구조를 정확히 반영한다 [근거: Rule "server-build-worker.spec.ts는 새 빌드 구조를 반영한다"]
- lint 테스트가 tscPlugin.getProgram() 경로를 검증한다 [근거: Rule "server-build-lint.spec.ts는 lint 연결 경로 변경을 반영한다"]
- esbuild-context 테스트가 tsc 옵션, delegation 메서드, 에러 병합을 검증한다 [근거: Rule "server-esbuild-context.spec.ts는 tsc 관련 확장을 반영한다"]
- 변경 불필요한 테스트(watch-manager, engine)가 현재 상태로 통과함을 확인한다 [근거: Rule "server-watch-manager 테스트는 변경 불필요하다"]

### 비목표

- `tests/utils/tsc-build.spec.ts` 변경 (runTscPackageBuild 자체는 불변) [근거: wbs 경계]
- `tests/utils/esbuild-config.spec.ts` 변경 (createServerEsbuildOptions 불변) [근거: wbs 경계]

### 설계

**공통 모킹 패턴:**

각 테스트 파일에 동일한 mockTscPlugin 객체를 정의하고 `vi.mock("../../src/esbuild/esbuild-tsc-plugin")`으로 모듈을 mock한다:

```typescript
const mockTscPlugin = {
  plugin: { name: "sd-tsc", setup: vi.fn() },
  getProgram: vi.fn(),
  getAffectedFiles: vi.fn(),
  getDiagnostics: vi.fn((): unknown[] => []),
  getErrors: vi.fn((): string[] | undefined => undefined),
  resetBuilderProgram: vi.fn(),
};

vi.mock("../../src/esbuild/esbuild-tsc-plugin", () => ({
  createTscPlugin: vi.fn(() => mockTscPlugin),
}));
```

beforeEach/afterEach에서 mockTscPlugin의 각 getter를 개별 리셋한다. [근거: 기존 테스트의 mock 리셋 패턴]

**파일별 변경:**

1. `server-build-worker.spec.ts`: mockTscPlugin 추가, js=true 테스트를 tsc 플러그인 getter 기반으로 전환, js=false 분기 테스트 추가, startWatch의 rebuildAll/createContext tsc 옵션 테스트 추가
2. `server-build-lint.spec.ts`: mockTscPlugin 추가, js=true lint 경로(tscPlugin.getProgram()) 테스트 추가
3. `server-esbuild-context.spec.ts`: mockTscPlugin 추가, tsc 플러그인 옵션 전달/delegation/에러 병합/dispose/recreateContext 리셋 테스트 추가
4. `server-esbuild-context.acc.spec.ts`: mockTscPlugin 추가, tsc 통합 생명주기 테스트 추가

### 대안 검토

별도 검토 사항 없음. 기존 테스트 패턴을 그대로 확장하는 방식이 유일한 합리적 접근.

### Vertical Slicing

#### Slice 1: server-esbuild-context 테스트 업데이트
- **구현 내용:** mockTscPlugin 추가, tsc 옵션 전달/delegation/에러 병합/dispose/recreateContext 리셋 단위/통합 테스트
- **Scenarios:** createContext tsc 플러그인, delegation 메서드, rebuild 에러 병합, dispose tsc 참조 해제, recreateContext tsc 리셋, tsc 통합 생명주기, LOGIC-001 tsc 보장

#### Slice 2: server-build-worker 테스트 업데이트
- **의존:** Slice 1 (esbuild-context mock이 worker 테스트에 영향)
- **구현 내용:** mockTscPlugin 추가, build js=true/false 분기, 에러 병합, startWatch rebuildAll 단일 호출, tsc 옵션 전달 테스트
- **Scenarios:** build js=true tsc 플러그인, build js=false 직접 호출, esbuild+tsc 에러 병합, rebuildAll 단일 호출, startWatch tsc 옵션

#### Slice 3: server-build-lint 테스트 업데이트
- **의존:** Slice 2 (동일 worker 테스트 구조)
- **구현 내용:** mockTscPlugin 추가, js=true lint 경로 테스트
- **Scenarios:** js=true lint tscPlugin.getProgram(), js=false lint tscResult.program

#### Slice 4: 변경 불필요 테스트 검증
- **의존:** 없음
- **구현 내용:** watch-manager, engine 테스트가 현재 상태로 통과하는지 확인
- **Scenarios:** watch-manager 통과, engine 통과
