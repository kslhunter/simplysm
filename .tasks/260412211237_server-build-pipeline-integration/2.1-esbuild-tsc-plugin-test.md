## 구현계획

### 배경

Feature 1.1에서 구현된 `createTscPlugin()`의 단위/인수 테스트. esbuild 플러그인 라이프사이클(onStart/onEnd)을 mock build 객체로 시뮬레이션하여, 스케줄링, 결과 처리, 에러 핸들링, 상태 관리를 검증한다. [근거: WBS "runTscPackageBuild는 모킹하여 단위 테스트에 집중"]

### 목표

- createTscPlugin의 모든 외부 인터페이스(plugin, getters, resetBuilderProgram) 동작 검증 [근거: WBS "외부 인터페이스"]
- microtask 스케줄링 메커니즘 검증 [근거: WBS "onStart에서 tsc가 microtask로 스케줄링"]
- esbuild result.errors 미사용 검증 [근거: WBS "result.errors에 push하지 않음"]

### 비목표

- 실제 esbuild 빌드 실행 [근거: WBS "실제 esbuild 빌드 실행 테스트는 통합 테스트(Feature 2.3)에서 수행"]
- runTscPackageBuild 자체의 동작 검증 [근거: WBS "tests/utils/tsc-build.spec.ts는 수정 불필요"]

### 설계

**테스트 구조:** [근거: sd-cli CLAUDE.md "src/ 구조를 미러링"]

- `tests/esbuild/esbuild-tsc-plugin.spec.ts` — 단위 테스트 (개별 동작 검증)
- `tests/esbuild/esbuild-tsc-plugin.acc.spec.ts` — 인수 테스트 (시나리오 기반 검증)

**모킹 전략:** [근거: sd-testing "물리적으로 실행 불가능한 것만 모킹"]

- `runTscPackageBuild`: vi.mock — 실제 TypeScript 컴파일러 실행 필요. 반환값 제어로 다양한 시나리오 테스트 [근거: WBS "모킹하여 단위 테스트에 집중"]
- `parseTsconfig`: vi.mock + importOriginal — 파일시스템 읽기 필요, 나머지 export(TypecheckEnv 등) 보존 [근거: tsc-build.spec.ts 패턴]

**플러그인 라이프사이클 시뮬레이션:** [근거: WBS "실제 esbuild는 통합 테스트"]

### 대안 검토

- **esbuild.build() 실제 실행**: 더 현실적이지만 unit test 범위 초과. 통합 테스트(Feature 2.3)에서 커버. 미채택.
- **vi.mock("esbuild")으로 esbuild 자체 모킹**: 플러그인은 esbuild를 직접 호출하지 않으므로 불필요. 미채택.
