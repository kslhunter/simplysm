## 구현계획

### 배경

`createClientViteConfig()`에서 `vite-plugin-pwa`의 `VitePWA`를 사용하여 PWA를 구성한다 (`vite-config.ts:192-227`). manifest 조합, 아이콘 생성, workbox 설정을 직접 수행한 뒤 VitePWA에 전달하는 구조다. Feature 1.1에서 동일 기능의 `sdPwaPlugin`이 구현되었으므로 (`vite-pwa-plugin.ts`), import를 교체하고 관련 코드를 간소화한다.

### 목표

- VitePWA → sdPwaPlugin 교체 [근거: Rule "올바른 옵션 전달"]
- vite-plugin-pwa 의존성 제거 [근거: Rule "의존성 정리"]
- 테스트 업데이트 — 중복 테스트는 vite-pwa-plugin.spec.ts로 위임 [근거: Rule "기존 활성화 조건 유지"]
- VitePWA 참조 문서 정리 [근거: Rule "VitePWA 참조 정리"]

### 비목표

- SdPwaConfig 타입(인터페이스 필드) 변경 [근거: wbs 경계 "SdPwaConfig 타입은 변경하지 않음"]
- sdPwaPlugin 내부 동작 변경 [근거: Feature 1.1에서 완성]
- sd.config.ts 설정 인터페이스 변경 [근거: wbs 경계]

### 설계

**vite-config.ts 변경** [근거: Rule "올바른 옵션 전달", "기존 활성화 조건 유지"]

Import 교체:
- 제거: `import { VitePWA } from "vite-plugin-pwa";` (line 13)
- 추가: `import { sdPwaPlugin } from "./vite-pwa-plugin.js";`

PWA 블록 (lines 192-227) 간소화:
- 기존 35줄 (pwaConfig 추출, iconsConfig 조합, pwaManifest 조합, pwaWorkbox 조합, VitePWA 호출) 전체 제거
- sdPwaPlugin 호출로 대체 (~5줄)
- TypeScript 타입 내로잉: `options.pwa !== false` guard 이후 `options.pwa` 타입이 `SdPwaConfig | undefined`로 좁혀짐. `SdPwaPluginOptions.pwa`가 동일 타입이므로 직접 전달 가능
- `generatePwaIcons` import도 제거 (sdPwaPlugin 내부에서 호출)

**package.json 변경** [근거: Rule "의존성 정리"]

- workbox-build, workbox-window은 vite-plugin-pwa의 transitive dependency로 자동 제거됨

**vite-config.spec.ts 변경** [근거: Rule "기존 활성화 조건 유지"]

Mock 교체:
- 제거: `mockVitePWA` + `vi.mock("vite-plugin-pwa", ...)` (lines 38-41)

유지 (assertion 수정):
- 플러그인 존재/부재 4개: 이름 `"vite-plugin-pwa"` → `"sd-pwa"`
- 설정 전달 3개: `mockVitePWA` 인자 → `mockSdPwaPlugin` 인자 (`pkgDir`, `pkgName`, `pwa`)

제거 (vite-pwa-plugin.spec.ts로 위임):
- "uses default workbox globPatterns" — workbox 동작은 sdPwaPlugin 내부
- "uses custom workbox globPatterns" — 동일

- "does not include icons in manifest when no source icon exists" — 동일
