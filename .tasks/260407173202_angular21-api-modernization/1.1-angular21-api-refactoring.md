# Feature 1.1 Angular 21 최신 API 리팩토링

## 참조 자료
- WBS: [wbs.md](./wbs.md)
- angular-cli MCP best practices: `computed()` for derived state, `inject()` function, signal-based APIs
- Angular 19+ API: `linkedSignal()` — source signal 의존 + 로컬 쓰기 가능한 WritableSignal
- Angular 19+ API: `resource()` — signal 기반 비동기 데이터 로딩

### 설계 결정

## 구현계획

### 배경

`packages/angular/src`에 6개 파일이 Angular 19+ 이전 스타일의 `signal()` + `effect()` 동기화 패턴을 사용 중이다. Angular 21에서 제공하는 `linkedSignal()`, `resource()`, `computed()` API로 더 선언적으로 표현할 수 있다. [근거: angular-cli MCP best practices "Use computed() for derived state", "Use signals for state management"]

### 목표

- `effect()` 내에서 `signal.set()`하는 비권장 패턴 제거 [근거: Rule "linkedSignal은 source signal에 의존하면서..."]
- 순수 파생값을 `computed()`로 전환하여 glitch-free 동기식 업데이트 보장 [근거: Rule "사이드이펙트 없는 순수 파생값은..."]
- 비동기 로딩을 `resource()`로 전환하여 자동 취소, 로딩 상태 등 내장 기능 활용 [근거: Rule "비동기 데이터 로딩은..."]

### 비목표

- 기존 public API(input/output/model 시그니처) 변경 [근거: wbs 경계]
- 테스트 커버리지가 없는 파일에 대한 포괄적 테스트 추가 (변경 관련 테스트만 작성)

### 설계

#### 1. linkedSignal 전환 (3건)

**useDataSheetFilterManager.ts:**
```typescript
// Before: signal + effect
const filter = signal<TFilter>({} as TFilter);
const lastFilter = signal<TFilter>({} as TFilter);
effect(() => { filter.set(f); lastFilter.set(obj.clone(f)); });

// After: linkedSignal
const filter = linkedSignal({ source: options.bindFilter, computation: (f) => f });
const lastFilter = linkedSignal({ source: options.bindFilter, computation: (f) => obj.clone(f) });
```
[근거: Rule "linkedSignal..." — effect 내 signal set 제거]

**sd-sheet-config.modal.ts:**
```typescript
// Before: signal(undefined) + computed(edit ?? initial)
private readonly _editItems = signal<IConfigItem[] | undefined>(undefined);
_items = computed(() => this._editItems() ?? this._initialItems());
// 핸들러에서: this._editItems.set(items)

// After: linkedSignal
_items = linkedSignal<IConfigItem[]>(() => this._initialItems());
// 핸들러에서: this._items.set(items)
```
`_editItems` 필드 제거. `standalone: true`도 제거 (Angular 20+ 기본값, D4). [근거: D2, D4]

**sd-numpad.control.ts:**
```typescript
// Before: signal + 2 effects
text = signal<string | undefined>(undefined);
effect(() => { /* text → value */ });
effect(() => { /* value → text */ });

// After: linkedSignal + 1 effect
text = linkedSignal({ source: this.value, computation: (v) => v?.toString() });
effect(() => { /* text → value 유지 */ });
```
value→text 방향 effect 제거. signal 등치 비교로 불필요한 업데이트 방지. [근거: Rule "linkedSignal..."]

#### 2. computed 전환 (2건)

**sd-select.control.ts:**
```typescript
// Before: signal + effect (순수 변환)
_flatItems = signal<{...}[]>([]);
effect(() => { /* walk 로직 */ this._flatItems.set(flat); });

// After: computed
_flatItems = computed(() => { /* 동일 walk 로직 */ return flat; });
```
[근거: Rule "사이드이펙트 없는 순수 파생값..."]

**sd-gap.control.ts:**
```typescript
// Before: effect + ElementRef 직접 조작
effect(() => { this._elRef.nativeElement.style.display = "none"; });

// After: computed + host binding
_displayStyle = computed(() => { return "none"; /* 동일 조건 */ });
// host: { "[style.display]": "_displayStyle()" }
```
`_elRef` inject 제거. [근거: D2, best practices "host 객체 사용"]

#### 3. resource 전환 (1건)

**sd-data-select-button.control.ts:**
```typescript
// Before: effect + queueMicrotask + async
effect(() => { queueMicrotask(async () => { this.selectedItems.set(await this.load(...)); }); });

// After: resource + computed
private readonly _selectedItemsResource = resource({ request: ..., loader: ... });
selectedItems = computed(() => this._selectedItemsResource.value() ?? []);
```
`selectedItems`가 `WritableSignal` → `Signal`로 변경 (D3). [근거: Rule "비동기 데이터 로딩..."]

### 대안 검토

| 대안 | 선택하지 않은 이유 |
|------|-------------------|
| sd-numpad: linkedSignal 대신 현행 유지 | signal 등치 비교로 안전하게 동작. effect 내 signal set 패턴 제거가 목표에 부합 |
| sd-data-select-button: resource + linkedSignal(writable 유지) | 2개 API 도입은 과도. selectedItems는 파생 상태이므로 read-only가 개념적으로 정확 |
| sd-gap: effect 유지하면서 조건만 정리 | ElementRef 직접 조작 자체가 비권장 패턴. host binding이 Angular 렌더링과 통합됨 |
