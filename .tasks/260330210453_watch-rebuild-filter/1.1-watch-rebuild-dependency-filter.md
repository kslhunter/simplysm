# Feature 1.1 watch 리빌드 의존성 필터

## 참조 자료

### 현재 동작

- `server-build.worker.ts`는 esbuild metafile.inputs로 변경 파일이 빌드 입력인지 필터링 후 buildStart를 발행한다 (line 628-643). 이것이 올바른 패턴이다.
- `library-build.worker.ts`는 onChange에서 무조건 buildStart를 발행한다 (line 166-168).
- `ngtsc-build.worker.ts`는 onChange에서 무조건 buildStart를 발행한다 (line 236-238).
- `vite-angular-plugin.ts` handleHotUpdate는 `.endsWith(".ts")` 필터만 있어 .d.ts도 통과하여 onBuildStart를 발행한다 (line 219-235).

### 관련 파일

- `packages/sd-cli/src/workers/server-build.worker.ts` — 올바른 패턴 (참조)
- `packages/sd-cli/src/workers/library-build.worker.ts` — 수정 대상
- `packages/sd-cli/src/workers/ngtsc-build.worker.ts` — 수정 대상
- `packages/sd-cli/src/angular/vite-angular-plugin.ts` — 수정 대상

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|

## 구현계획

### 배경

빌드 워치 시스템에 4개의 워커가 있다. `server-build.worker.ts`는 esbuild `metafile.inputs`로 변경 파일이 빌드 입력인지 확인한 뒤에만 `buildStart`를 발행한다. 나머지 3개(`library-build`, `ngtsc-build`, `vite-angular-plugin`)는 watch 경로 내 모든 변경에 무조건 `buildStart`를 발행하여, 의존하지 않는 패키지(예: sd-cli) 변경에도 불필요한 리빌드가 트리거된다.

### 목표

- `library-build.worker.ts`, `ngtsc-build.worker.ts`, `vite-angular-plugin.ts`에 `server-build.worker.ts`와 동일한 "빌드 입력 확인 후 이벤트 발행" 패턴을 적용한다
- TypeScript `program.getSourceFiles()`를 빌드 입력 파일 목록으로 사용한다

### 비목표

- watch 경로 범위 변경 (watch 경로는 그대로 유지)
- `sdScopeWatchPlugin`의 `replaceDeps` 목록 필터링 (handleHotUpdate 수정으로 충분)

### 설계

#### 공통 패턴

각 워커에서 다음 패턴을 적용한다:

1. 초기/증분 빌드 후 `program.getSourceFiles()`에서 파일 경로를 `Set<string>`으로 추출 (정규화)
2. `onChange` 핸들러:
   - `event`가 `add` 또는 `unlink` → 항상 리빌드 (새 의존성 가능)
   - `event`가 `change` → 변경 파일이 `Set`에 포함되는지 확인
   - 관련 변경 없음 → `logger.debug("변경된 파일이 빌드에 포함되지 않아 리빌드 건너뜀")` 출력, `buildStart` 미발행
3. 리빌드 후 `Set` 갱신
4. `program`이 `undefined`인 경우(빌드 실패 시) → "항상 리빌드" 폴백

#### vite-angular-plugin 특화

`handleHotUpdate`에서 확장자 필터 통과 후 `compiler.getTsProgram().getSourceFiles()`로 파일이 program에 포함되는지 확인한다. 미포함 시 `onBuildStart` 호출 없이 즉시 `return`.

### 대안 검토

| 접근 방식 | 선택 | 이유 |
|-----------|------|------|
| watch 경로 자체를 좁힘 (의존 패키지만 watch) | 미채택 | add/unlink 감지 불가, server-build가 이미 "넓게 watch + 이벤트 시점 필터링" 패턴 사용 |
| 패키지 수준 의존성 그래프로 필터링 | 미채택 | 패키지 내부 파일 수준 필터링 불가, 너무 거침 |
| 빌드 입력 파일 수준 필터링 (program/metafile) | **채택** | 정밀, server-build.worker.ts에서 검증된 패턴 |
