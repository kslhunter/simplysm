## 구현계획

### 배경

`client-protocol-wrapper.ts`는 neutral 패키지에서 DOM `Worker`를 직접 사용하여 node typecheck 실패. browser/node 양쪽에서 Worker 오프로딩을 지원하면서 esbuild 플러그인 호환성을 유지해야 한다.

기존 코드는 commit 2369f3be0에서 `createBrowserWorker()` 래퍼를 제거하고 직접 `new Worker(...)` 사용으로 변경했으나, neutral 이중 typecheck를 고려하지 않아 발생한 문제이다.

### 목표

- node/browser 환경별 Worker 생성 분기 [근거: Rule "환경별 Worker 생성 분기"]

- 양쪽 typecheck 0 에러 [근거: Rule "양쪽 typecheck 통과"]

### 설계

#### 1. `browser-compat.ts` — 환경 감지 함수 분리

기존 `isWorkerSupported()`를 browser/node 개별 함수로 분리하고, 통합 함수는 두 결과의 OR로 변경한다.

```typescript
export function isBrowserWorkerSupported(): boolean {
  return "Worker" in globalThis;
}

export function isNodeWorkerSupported(): boolean {
  return typeof globalThis.process !== "undefined"
    && globalThis.process.versions?.node != null;
}

export function isWorkerSupported(): boolean {
  return isBrowserWorkerSupported() || isNodeWorkerSupported();
}
```

[근거: 기준 코드 `browser-compat.ts:30-32` 패턴 확장]

#### 2. `client-protocol-wrapper.ts` — Worker 생성 분기

**2a. `declare const Worker` 모듈 선언**

node env에서 `Worker` 값 부재를 해결한다. 컴파일 시 제거되므로 런타임 영향 없음.

```typescript
declare const Worker: {
  new(scriptURL: string | URL, options?: { type?: string }): BrowserWorker;
};
```

[근거: 설계 결정 D2]

**2b. 비동기 Worker 초기화**

`getWorker()`를 async로 변경하고, 초기화 Promise를 캐싱한다.

```typescript
let workerInitPromise: Promise<BrowserWorker | undefined> | undefined;

async function initWorker(): Promise<BrowserWorker | undefined> {
  if (isBrowserWorkerSupported()) {
    const w: BrowserWorker = new Worker(
      new URL("../workers/client-protocol.worker.js", import.meta.url),
      { type: "module" },
    );
    setupWorkerHandlers(w);
    return w;
  }

  if (isNodeWorkerSupported()) {
    const workerUrl = import.meta.resolve("../workers/client-protocol.worker.js");
    const { Worker: NodeWorker } = await import("worker_threads");
    const nodeWorker = new NodeWorker(new URL(workerUrl));
    const adapter = createNodeWorkerAdapter(nodeWorker);
    setupWorkerHandlers(adapter);
    return adapter;
  }

  return undefined;
}

async function getWorker(): Promise<BrowserWorker | undefined> {
  if (!isWorkerAvailable()) return undefined;
  if (workerInitPromise == null) {
    workerInitPromise = initWorker();
  }
  return workerInitPromise;
}
```

[근거: 기준 코드 `client-protocol-wrapper.ts:40-89` 패턴]

**2c. Node Worker 어댑터**

`worker_threads.Worker`의 이벤트 기반 API를 `BrowserWorker` 콜백 인터페이스로 래핑한다.

```typescript
function createNodeWorkerAdapter(nodeWorker: import("worker_threads").Worker): BrowserWorker {
  const adapter: BrowserWorker = {
    onmessage: null,
    onerror: null,
    postMessage(message: unknown, transfer?: unknown[]) {
      nodeWorker.postMessage(message, transfer as import("worker_threads").TransferListItem[]);
    },
    terminate() { nodeWorker.terminate(); },
  };
  nodeWorker.on("message", (data: unknown) => {
    adapter.onmessage?.({ data } as MessageEvent);
  });
  nodeWorker.on("error", (err: Error) => {
    adapter.onerror?.(err as unknown as Event);
  });
  return adapter;
}
```

[근거: 기준 코드 `browser-compat.ts:22-27` BrowserWorker 인터페이스]

**2d. `setupWorkerHandlers` 추출**

기존 `getWorker()` 내부의 `onmessage`/`onerror` 핸들러 설정을 별도 함수로 추출한다.

**2e. `runWorker` 호출부 대응**

`getWorker()`가 async이므로 `runWorker` 내에서 `await getWorker()`로 변경.

#### 3. `client-protocol.worker.ts` — 환경별 메시지 패싱

기존 `self.onmessage` 핸들러의 encode/decode 로직을 함수로 추출하고, 환경에 따라 메시지 수신/응답 방식을 분기한다.

```typescript
function handleRequest(msgData: { id: string; type: "encode" | "decode"; data: unknown }) {
  // 기존 try/catch + encode/decode 로직 그대로
  // return { response, transferList } 또는 throw
}

// 환경별 메시지 패싱
if (typeof self !== "undefined" && typeof self.postMessage === "function") {
  // Browser Worker
  self.onmessage = (event: MessageEvent) => { ... handleRequest(event.data) ... self.postMessage(...) };
} else {
  // Node.js worker_threads
  import("worker_threads").then(({ parentPort }) => {
    parentPort!.on("message", (data) => { ... handleRequest(data) ... parentPort!.postMessage(...) });
  });
}
```
