## 구현계획

### 배경

v12의 `sd-dropdown-popup`은 `(sdResize)` 이벤트를 사용하여 내부 컨텐츠 높이가 300px를 초과하면 호스트 요소 높이를 300px로 고정했다. v14 마이그레이션 시 이 로직이 누락되었고, 대신 `sd-dropdown`의 `_updatePopupPosition()`에서 뷰포트 기반 `maxHeight`/`maxWidth`/`overflow` 계산이 추가되었다. [근거: v12 `sd-dropdown-popup.control.ts:70-79`, v14 `sd-dropdown.ts:212-229`]

### 목표
- popup 컨텐츠가 300px를 초과할 때 높이를 300px로 제한하는 v12 동작을 복원한다 [근거: Rule "popup 내부 컨텐츠가 300px를 초과하면 호스트 높이를 300px로 제한한다"]
- v14의 `sd-dropdown`에서 추가된 maxHeight/maxWidth/overflow 설정을 제거한다 [근거: 설계 결정 D1]

### 비목표
- keydown 이벤트 호스트 바인딩, CSS 단위 변경(px→rem), 모바일 bottom sheet 스타일, SCSS 변수 참조 등 v14 개선사항은 변경하지 않음 [근거: wbs 경계]

### 설계

**sd-dropdown-popup.ts 변경:**
- 템플릿: 내부 `<div>`에 `(sdResize)="onResize()"` 이벤트 바인딩 추가
- 클래스: `ElementRef<HTMLElement>` inject 추가, `onResize()` 메서드 추가
  - `divEl.clientHeight > 300`이면 `el.style.height = "300px"`, 아니면 `delete (el.style as any).height`

**sd-dropdown.ts 변경:**
- `_updatePopupPosition()`: `maxHeight`, `maxWidth`, `overflow` 3개 속성 제거
- `_removePopup()`: `maxHeight`, `maxWidth`, `overflow` 리셋 3개 속성 제거

v14에서 `sdResize`는 `SdResizeEventPlugin`(EventManagerPlugin)으로 등록되어 있어, 별도 import 없이 `(sdResize)` 바인딩만으로 동작한다. [근거: `sd-resize-event.plugin.ts:12`]
