## 구현계획

### 배경

sd-data-sheet과 sd-data-detail은 `SdDataSheetBase`/`SdDataDetailBase` 추상 클래스를 상속하는 CRUD 패턴 컴포넌트이다. v12→v14 마이그레이션 과정에서 템플릿 일부가 누락/변경됨. [근거: wbs Feature 4.3 범위]

### 목표

- sd-data-sheet: isDeleted 컬럼에 `#headerTpl` (삭제 아이콘 헤더) 복원 [근거: Rule "isDeleted 컬럼은 삭제 아이콘 헤더를 표시해야 한다"]
- sd-data-detail: `modalActionTpl`을 `@if (parent.canEdit())` 블록 안으로 이동 [근거: Rule "modalActionTpl은 canEdit() 조건 내에서만 렌더링되어야 한다"]

### 비목표

- 아이콘 객체화, `(formSubmit)` 이벤트명, `let-item="item"` 명시적 바인딩, non-null assertion 등 v14 개선 사항 변경 [근거: wbs 경계]

### 설계

#### sd-data-sheet (`packages/angular/src/data/data-sheet/sd-data-sheet.ts`)

v14 line 216-217의 isDeleted `sd-sheet-column` 내부에 `#headerTpl`을 추가:

```html
<sd-sheet-column [fixed]="true" [key]="parent.itemPropInfo.isDeleted!">
  <ng-template #headerTpl>
    <div class="p-xs-sm tx-center">
      <ng-icon [svg]="icons.tablerEraser" />
    </div>
  </ng-template>
  <ng-template [cell]="parent.items()" let-item="item">
    ...
  </ng-template>
</sd-sheet-column>
```

참고: v12에서는 `deleteIcon()` input signal을 사용하지만, v14에서도 동일하게 `deleteIcon()` 사용. 단, v14의 `icons.` prefix 패턴은 v14에서 사용하지 않는 패턴 — v14에서는 `deleteIcon()` input signal을 사용함 (line 385). [근거: v14 sd-data-sheet.ts:385, v12 sd-data-sheet.control.ts:237]

#### sd-data-detail (`packages/angular/src/data/data-detail/sd-data-detail.ts`)

v14 line 174-183의 `<ng-template #modalActionTpl>`을 line 146의 `@if (parent.canEdit()) {` 블록 안으로 이동:

```html
@if (parent.canEdit()) {
  <ng-template #modalBottomTpl>
    ...
  </ng-template>

  <ng-template #modalActionTpl>
    ...
  </ng-template>
}
```
