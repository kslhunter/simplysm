## 구현계획

### 배경

sd-toast와 sd-toast-container는 `SdToastProvider`에 의해 프로그래밍 방식으로 생성·관리되는 오버레이 컴포넌트이다. `SdToastProvider._show()`가 텍스트 메시지 토스트를, `notify()`가 커스텀 컨텐츠 토스트를 생성한다. v12→v14 마이그레이션 시 템플릿 구조와 CSS 클래스 네이밍이 변경되었다.

### 목표

- sd-toast 템플릿에서 message/ng-content 배타적 표시 복원 [근거: Rule "message와 ng-content는 배타적으로 표시"]
- sd-toast CSS 클래스명 `_sd-toast-*` 접두사 복원 [근거: Rule "내부 클래스명은 _sd-toast- 접두사 사용"]
- sd-toast-container 빈 템플릿 복원 [근거: Rule "sd-toast-container는 빈 템플릿 사용"]

### 비목표

- ARIA 속성(`ariaRole`, `ariaLive`) 변경 [근거: wbs 경계 "v14 개선이므로 유지"]
- `word-break: break-all; white-space: pre-wrap` 제거 [근거: wbs 경계 "v14 개선이므로 유지"]
- SCSS 변수 참조 방식 변경 [근거: wbs 경계 "v14 개선이므로 유지"]
- `model()` → `input()` 되돌리기 [근거: wbs 경계 "v14 API 패턴 유지"]

### 설계

**sd-toast.ts 템플릿 변경:**

현재 (v14):
```html
<div class="_block">
  @if (message() !== undefined) {
    <div class="_message">{{ message() }}</div>
  }
  <ng-content />
  @if (useProgress()) {
    <div class="_progress">
      <div class="_progress-bar" [style.width.%]="progress()"></div>
    </div>
  }
</div>
```

복원 후:
```html
<div class="_sd-toast-block">
  <div class="_sd-toast-message">
    @if (message() != null) {
      {{ message() }}
    } @else {
      <ng-content />
    }
  </div>
  @if (useProgress()) {
    <div class="_sd-toast-progress">
      <div class="_sd-toast-progress-bar" [style.width.%]="progress()"></div>
    </div>
  }
</div>
```

핵심 변경:
1. `_sd-toast-message` 래퍼가 항상 존재 (message 유무와 무관)
2. `@if/@else`로 message/ng-content 배타적 렌더링
3. 모든 클래스명에 `_sd-toast-` 접두사

**sd-toast.ts SCSS 변경:**

모든 CSS 셀렉터의 클래스명을 `_*` → `_sd-toast-*`로 변경:
- `._block` → `._sd-toast-block`
- `._message` → `._sd-toast-message`
- `._progress` → `._sd-toast-progress`
- `._progress-bar` → `._sd-toast-progress-bar`

v14의 `word-break: break-all; white-space: pre-wrap`은 `._sd-toast-message`에 유지한다. [근거: D1]

**sd-toast-container.ts 변경:**

`template: \`<ng-content />\`` → `template: ""`

**테스트 파일 셀렉터 업데이트:**

| 파일 | 변경 |
|---|---|
| `toast-control.spec.ts` | `._message` → `._sd-toast-message`, `._progress-bar` → `._sd-toast-progress-bar` |
| `toast-provider.spec.ts` | `._message` → `._sd-toast-message` |
| `toast-custom-try.spec.ts` | `._message` → `._sd-toast-message` |

### 대안 검토

**클래스명 접두사 vs 현행 유지:**

v14의 다른 컴포넌트들(`sd-busy-container`, `sd-progress` 등)은 짧은 `_*` 네이밍을 사용하지만, `ViewEncapsulation.None`이므로 글로벌 스코프에서 클래스 충돌 가능성이 있다. v12의 `_sd-toast-*` 접두사가 더 안전하며, WBS에서 명시적으로 복원을 요구한다.
