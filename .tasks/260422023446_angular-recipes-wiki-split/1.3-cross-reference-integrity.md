## 구현계획

### 배경

Feature 1.1/1.2에서 crud-list.md(2,190줄)와 crud-detail.md(1,741줄)를 wiki 스타일로 분해했다. 진입점에 §5~§11 / §5~§10 헤딩을 요약+링크 형태로 유지하여 기존 앵커 호환을 보장하는 전략을 취했다 [근거: `crud-list.md:357-425`, `crud-detail.md:297-355`]. 이제 이 전략이 모든 역링크에서 실제로 유효한지 체계적으로 검증한다.

### 목표

- 모든 문서 간 Markdown 링크(파일 경로 + 앵커)가 유효함을 검증 [근거: Rule 8개]
- 깨진 링크 발견 시 수정 [근거: Rule "깨진 링크 수정"]

### 비목표

- recipes 내용(코드 스니펫, 설명 텍스트) 수정 [근거: wbs 경계]
- docs 파일의 본문 내용 수정 [근거: wbs 경계]

### 설계

검증을 3단계로 수행:

1. **파일 존재 검증**: 모든 상대 경로 링크의 대상 파일이 실제 존재하는지 확인
2. **앵커 유효성 검증**: `#앵커` 포함 링크의 대상 파일 내 해당 헤딩 slug 존재 확인 (CommonMark 앵커 생성 규칙: 소문자화, 공백→`-`, 특수문자 제거)
3. **깨진 링크 수정**: 발견된 깨진 링크를 올바른 경로/앵커로 수정
