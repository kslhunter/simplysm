  Background:

      When 컴포넌트가 초기화된다

      And initialized가 true로 설정된다

    Scenario: 변경사항이 있는 상태에서 새로고침한다

## 구현계획

### 배경

Feature 7.2a에서 `SdDataSheetControl`(목록 뷰)이 v14로 마이그레이션 완료되었다. 7.2b는 동일한 데이터 뷰 패턴의 상세 폼 버전이다. v12 `SdDataDetailControl` + `AbsSdDataDetail`을 v14 API(`signal()`, `effect()`, `obj.clone()`/`obj.equal()`)로 마이그레이션한다.

모든 의존성이 v14에서 이미 사용 가능하다: `SdBaseContainerControl`, `SdFormControl`, `SdButtonControl`, `SdAnchorControl`, `SdToastProvider`, `SdSharedDataProvider`, `ISdModal`, `FormatPipe`, `injectParent`, `setupCanDeactivate`, `useViewTypeSignal`, `TXT_CHANGE_IGNORE_CONFIRM`.

### 목표

- `AbsSdDataDetail<T, R>` 추상 디렉티브, `SdDataDetailControl` 컴포넌트, `ISdDataDetailDataInfo` 인터페이스를 v14로 마이그레이션
- v14 코딩 컨벤션과 SdDataSheetControl 패턴에 일관되게 구현
- 단위 테스트 작성

### 비목표

- SCSS 스타일 변경 (이 컴포넌트는 자체 스타일이 없음)
- 소비자 측 코드 변경

#### AbsSdDataDetail\<T extends object, R = boolean\>

ISdModal\<R\>을 구현한다.

추상 멤버:
- `canUse: Signal<boolean>` — 조회 권한
- `canEdit: Signal<boolean>` — 편집 권한
- `canDelete?: Signal<boolean>` — 삭제 권한 (선택)
- `prepareRefreshEffect?(): void` — effect 내부에서 호출, 외부 signal 의존성 추가용
- `load(): Promise<{ data: T; info: ISdDataDetailDataInfo }> | { data: T; info: ISdDataDetailDataInfo }` — 데이터 로드
- `toggleDelete?(del: boolean): Promise<R | undefined> | R | undefined` — 삭제/복원
- `submit?(data: T): Promise<R | undefined> | R | undefined` — 저장

상태 signal:
- `viewType = useViewTypeSignal(() => this)` — "page" | "modal" | "control"
- `busyCount = signal(0)`
- `busyMessage = signal<string | undefined>(undefined)`
- `initialized = signal(false)`
- `close = output<R>()` — ISdModal 구현
- `actionTplRef?: TemplateRef<any>` — ISdModal 구현
- `data = signal<T>({} as T)`
- `dataInfo = signal<ISdDataDetailDataInfo | undefined>(undefined)`

변경 감지 (v12 `$obj` 대체):
- `private _dataSnapshot?: T` — refresh 후 `obj.clone(result.data)` 저장
- `checkIgnoreChanges()`: `this._dataSnapshot == null || obj.equal(this.data(), this._dataSnapshot) || confirm(TXT_CHANGE_IGNORE_CONFIRM)`

생성자:
```typescript
constructor() {
  effect(() => {
    this.prepareRefreshEffect?.();
    queueMicrotask(async () => {
      if (!this.canUse()) { this.initialized.set(true); return; }
      this.busyCount.update(v => v + 1);
      await this.__sdToast.try(async () => {
        await this.__sdSharedData.wait();
        await this.refresh();
      });
      this.busyCount.update(v => v - 1);
      this.initialized.set(true);
    });
  });
  setupCanDeactivate(() => this.viewType() === "modal" || this.checkIgnoreChanges());
}
```

#### SdDataDetailControl

`injectParent<AbsSdDataDetail<any>>()`로 부모 접근. SdDataSheetControl과 동일한 패턴.

템플릿 구조:
- `SdBaseContainerControl` 래핑 (`busy`, `busyMessage`, `viewType`, `initialized`, `restricted`)
- pageTopbarTpl: 저장/새로고침 버튼 (page 모드)
- contentTpl: toolbar (control 모드) + prevTpl + SdFormControl + lastModified + nextTpl
- modalBottomTpl: 삭제/복구 + 확인 버튼 (modal 모드, canEdit 시)
- modalActionTpl: 새로고침 앵커 (modal 모드, canEdit 시)

호스트 바인딩: `(sdRefreshCommand)`, `(sdSaveCommand)`

v14 import 경로 (v12 대비):
- `@simplysm/sd-core-common` → `@simplysm/core-common`
- `../../core/utils/bindings/$signal` → `signal` from `@angular/core`
- `../../core/utils/bindings/$effect` → `effect` from `@angular/core`
- `../../core/utils/bindings/wrappers/$obj` → `obj` from `@simplysm/core-common`
- `../../core/utils/injections/injectParent` → `../../core/utils/injectParent`
- `../../core/utils/signals/useViewTypeSignal` → `../../core/utils/useViewTypeSignal`
