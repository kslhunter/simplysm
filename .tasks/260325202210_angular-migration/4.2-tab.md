## 요구명세

```gherkin
Feature: 4.2 탭

  Background:
    Given Angular 애플리케이션이 실행 중이다

  Rule: 탭 헤더로 컨텐츠를 선택한다

    Scenario: 탭 헤더 클릭으로 value 변경
      Given sd-tab에 sd-tab-item "A"와 "B"가 있다
      When "A" 탭 헤더를 클릭한다
      Then sd-tab의 value가 "A"로 설정된다

    Scenario: 이미 선택된 탭 재클릭
      Given sd-tab의 value가 "A"이다
      When "A" 탭 헤더를 다시 클릭한다
      Then sd-tab의 value는 "A"로 유지된다

  Rule: 선택된 탭은 시각적으로 구분된다

    Scenario: 선택된 탭 아이템의 스타일
      Given sd-tab의 value가 "A"이다
      Then "A" sd-tab-item에 data-sd-selected="true" 속성이 설정된다
      And primary 색상 하단 테두리와 텍스트 색상이 적용된다

    Scenario: 선택되지 않은 탭 아이템의 스타일
      Given sd-tab의 value가 "A"이다
      Then "B" sd-tab-item에 data-sd-selected="true" 속성이 없다
      And 회색 텍스트와 투명 하단 테두리가 적용된다

  Rule: sd-tab/sd-tab-item은 독립적으로 사용할 수 있다

    Scenario: 탭 헤더 바만 사용
      Given sd-tab과 sd-tab-item만으로 탭 헤더 바를 구성한다
      When 탭을 클릭하여 value를 변경한다
      Then 소비자가 value를 읽어 컨텐츠 전환을 직접 처리한다

  Rule: sd-tabview는 탭 선택에 따라 컨텐츠를 자동 전환한다

    Scenario: 선택된 탭뷰 아이템만 표시
      Given sd-tabview에 value="A", value="B"인 sd-tabview-item이 있다
      And sd-tabview의 value가 "A"이다
      Then value="A"인 sd-tabview-item만 표시된다
      And value="B"인 sd-tabview-item은 숨겨진다

    Scenario: header가 지정된 탭뷰 아이템의 탭 헤더
      Given sd-tabview-item에 value="settings" header="설정"이 지정되어 있다
      Then 탭 헤더에 "설정" 텍스트가 표시된다

    Scenario: header가 미지정된 탭뷰 아이템의 탭 헤더
      Given sd-tabview-item에 value="settings"만 지정되어 있다
      Then 탭 헤더에 "settings" 텍스트가 표시된다

  Rule: sd-tabview value는 양방향 바인딩된다

    Scenario: 외부에서 value 설정
      Given sd-tabview에 value="A", value="B"인 sd-tabview-item이 있다
      When 외부에서 sd-tabview의 value를 "B"로 설정한다
      Then "B" 탭이 선택되고 해당 컨텐츠가 표시된다

    Scenario: 탭 클릭으로 외부 바인딩 갱신
      Given sd-tabview의 value가 외부 signal에 바인딩되어 있다
      When "B" 탭 헤더를 클릭한다
      Then 외부 signal의 값이 "B"로 갱신된다
```

## 구현계획

### 배경

v14 `@simplysm/angular` 패키지의 `ui/navigation/` 디렉토리에 collapse, pagination이 이미 마이그레이션되어 있다. 탭 컴포넌트는 v12에서 4개 파일(sd-tab, sd-tab-item, sd-tabview, sd-tabview-item)로 구성되며, 저수준(탭 헤더 바)과 고수준(자동 컨텐츠 전환) 두 계층으로 분리되어 있다.

### 목표

- v12의 탭 컴포넌트 4개를 v14 패턴(네이티브 `computed`, `model`, `input`, `contentChildren`)으로 마이그레이션
- index.ts에 export 등록

### 비목표

- 탭에 새로운 기능 추가 (닫기 버튼, 드래그 재정렬 등)
- sidebar, topbar 등 다른 navigation 컴포넌트 (별도 Feature)

### 설계

#### 컴포넌트 구조

| 컴포넌트 | 역할 | API |
|----------|------|-----|
| `SdTabControl` | 탭 헤더 컨테이너 | `value: model<any>()` |
| `SdTabItemControl` | 개별 탭 헤더 | `value: input<any>()`, 부모 `SdTabControl` inject |
| `SdTabviewControl` | 탭뷰 컨테이너 (탭+컨텐츠) | `value: model<T>()`, `contentChildren(SdTabviewItemControl)` |
| `SdTabviewItemControl` | 탭뷰 개별 패널 | `value: input.required<T>()`, `header: input<string>()` |

#### 변경사항 (v12 → v14)

- `$computed()` → Angular 네이티브 `computed()`
- import 경로에서 `../../../core/utils/bindings/$computed` 제거
- 그 외 API, 템플릿, 스타일은 v12와 동일하게 유지

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| v12 코드 그대로 복사 후 `$computed`만 교체 | 채택 | v12 구조가 단순하고 v14 패턴과 거의 동일 |
| 탭/탭뷰를 단일 컴포넌트로 통합 | 미채택 | 저수준(탭만)/고수준(탭뷰) 분리가 유연성 제공 |
