# Feature 2.4 텍스트 입력 (sd-textfield)

## 참조 자료

- [wbs.md](./wbs.md)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | 컴포넌트 설계 | 내부 전략 패턴 (공개 API는 sd-textfield [type] 유지) | sd-range 동적 타입 전달 호환, 단일 컴포넌트 분리 시 안정성 4/10 vs 전략 패턴 8/10 |
| D2 | maxlength 검증 버그 (원본 L430) | 마이그레이션 시 수정 (`maxlength > value.length` → `maxlength < value.length`) | 명백한 조건 방향 오류, 기존에 작동 안 했으므로 호환성 영향 없음 |
| D3 | 주석 clipboard 코드 (원본 L592-604) | Feature 2.4에서 제외 | sd-sheet 의존 clipboard 기능은 Feature 6.x 데이터 그리드 영역 |
| D4 | handler 인터페이스 | ITextfieldTypeHandler (parse/toControlValue/toDisplayText/validate + controlType/getControlStep) | 원본 6개 hot spot 직접 대응, Record map으로 exhaustiveness 보장 |
| D4a | handler 파일 구조 | 단일 파일 sd-textfield-type-handlers.ts + 타입 그룹별 factory 함수 | 타겟 코드 파일 구조 패턴, 과도한 분리 방지 |
| D4b | toControlValue/toDisplayText 분리 | 별도 메서드 (input용 vs display div용) | datetime의 "T" 구분자 vs "tt" AM/PM 등 출력 포맷이 다름 |
| D5 | transformBoolean 대체 | booleanAttribute (Angular native) | Feature 2.3 D4 계승, v14 워크스페이스 기존 패턴 |
| D6 | $computed 대체 | Angular native computed() | 타겟 코드베이스 기존 패턴 |
| D7 | Feature 분리 | 2.4(sd-textfield) + 2.4.1(sd-textarea + sd-form) | 전략 패턴 리팩토링과 단순 포팅의 이질적 작업 성격 분리 |

## 구현계획

### 배경

원본 sd-textfield(669줄)은 13종 타입을 if-else 체인으로 처리하는 단일 컴포넌트이다. 타겟 워크스페이스(Angular 21)에 이미 마이그레이션된 컴포넌트들(sd-button, sd-anchor 등)이 booleanAttribute, native computed(), setupInvalid 등의 패턴을 사용 중이다.

### 목표

- sd-textfield을 Angular 21 standalone 컴포넌트로 마이그레이션
- 내부 전략 패턴으로 타입별 handler 분리 (공개 API 불변)
- 원본 maxlength 검증 버그 수정
- TDD로 모든 Gherkin Scenario 커버

### 비목표

- sd-textarea, sd-form (Feature 2.4.1)
- sd-numpad, sd-range, sd-date-range (Feature 5.2)
- sd-sheet-cell-copy/paste clipboard (Feature 6.x)
- ControlValueAccessor / Angular Forms 통합 (별도 Feature 필요 시 추후)

#### Handler 인터페이스

```typescript
export interface ITextfieldTypeHandler {
  readonly controlType: string;
  getControlStep(explicitStep: number | undefined): number | string;
  parse(raw: string, opts: { format?: string }): unknown;
  toControlValue(value: unknown, opts: { useNumberComma?: boolean; format?: string }): string;
  toDisplayText(value: unknown, opts: { minDigits?: number }): string | undefined;
  validate(value: unknown, opts: {
    required?: boolean; min?: unknown; max?: unknown;
    minlength?: number; maxlength?: number; pattern?: string; format?: string;
  }): string[];
}
```

- value 타입은 `unknown` — Record map에서 타입 소거됨. 외부 타입 안전성은 컴포넌트의 제네릭 K가 보장
- opts는 superset — 각 handler가 필요한 필드만 사용

#### Handler Map

```typescript
export const textfieldTypeHandlers: Record<keyof TSdTextfieldTypes, ITextfieldTypeHandler> = {
  text: createStringHandler("text"),
  password: createStringHandler("password"),
  email: createStringHandler("email"),
  color: createStringHandler("color"),
  number: createNumberHandler(),
  format: createFormatHandler(),
  date: createDateOnlyHandler("date"),
  month: createDateOnlyHandler("month"),
  year: createDateOnlyHandler("year"),
  datetime: createDateTimeHandler(false),
  "datetime-sec": createDateTimeHandler(true),
  time: createTimeHandler(false),
  "time-sec": createTimeHandler(true),
};
```

- 타입 그룹별 factory 함수로 중복 제거
- `Record<keyof TSdTextfieldTypes, ...>`로 누락 타입 컴파일 에러 보장

#### 컴포넌트 구조 (sd-textfield.control.ts)

핵심 변경점:
- `$computed` → `computed()`
- `transformBoolean` → `booleanAttribute`
- if-else 체인 → `textfieldTypeHandlers[this.type()]` 위임
- `_setControlValue` → `handler.parse()`
- `_convertToControlValue` → `handler.toControlValue()`
- `controlValueText` → `handler.toDisplayText()` (undefined 시 toControlValue fallback)
- `setupInvalid` 내 검증 → `handler.validate()` + `validatorFn` 결합
- password masking은 템플릿에서 controlType === "password" 조건으로 유지 (handler와 무관)

SCSS는 원본 그대로 포팅 (CSS 변수 기반이므로 변경 불필요).

#### Export (index.ts)

```typescript
export { SdTextfieldControl, type TSdTextfieldTypes, sdTextfieldTypes } from "./ui/form/input/sd-textfield.control";
```

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| 현행 유지 (if-else 그대로 포팅) | 미채택 | 669줄 if-else 체인 유지, 확장성/유지보수성 5/10 |
| 타입별 별도 컴포넌트 분리 | 미채택 | sd-range 동적 타입 전달 `[type]="type()"` 불가, 파괴적 변경 |
| Record map + handler 인터페이스 | **채택** | 공개 API 불변, exhaustiveness 보장, handler별 테스트 가능 |
