# Feature 2.6 표시 컴포넌트

## 참조 자료

- [wbs.md](./wbs.md)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | boolean input 변환 방식 | Angular `booleanAttribute` | v14 기존 컴포넌트(sd-switch 등) 패턴 일관성 |
| D2 | computed 유틸리티 | Angular 내장 `computed()` | v12의 `$computed` 래퍼 불필요, v14 패턴 일관성 |
| D3 | 파일 배치 | `src/ui/visual/`에 직접 배치 | 독립적 단일 컴포넌트, 하위 디렉토리 불필요 (layout/ 패턴 동일) |

## 요구명세

```gherkin
Feature: 2.6 표시 컴포넌트

  Background:
    Given v12 소스의 표시 컴포넌트를 v14 Angular 21 환경으로 마이그레이션한다

  Rule: Label은 테마/커스텀 색상의 인라인 라벨을 표시한다

      When theme="primary"를 지정한다
      Then data-sd-theme="primary" 속성이 설정되고 primary 배경색이 적용된다

    Scenario: 커스텀 색상 라벨 표시
      Given sd-label 컴포넌트를 렌더링한다
      When color="#ff0000"를 지정한다
      Then style.background에 "#ff0000"이 적용된다

    Scenario: 기본 배경색
      Given sd-label에 theme과 color를 지정하지 않는다
      Then gray-darker 기본 배경색이 적용된다

  Rule: Label은 clickable 상태에서 hover 효과를 제공한다

    Scenario: clickable 라벨 hover
      Given sd-label에 clickable을 지정한다
      When 마우스를 올린다
      Then cursor: pointer이고 darker 배경으로 변경된다

    Scenario: 기본(non-clickable) 라벨
      Given sd-label에 clickable을 지정하지 않는다
      When 마우스를 올린다
      Then hover 효과가 없다

  Rule: Note는 테마 색상의 블록 안내 영역을 표시한다

    Scenario: 테마 색상 Note 표시
      Given sd-note 컴포넌트를 렌더링한다
      When theme="info"를 지정한다
      Then info-lightest 배경과 테두리가 적용된다

    Scenario: 작은 크기 Note
      Given sd-note에 size="sm"를 지정한다
      Then 작은 폰트와 줄어든 패딩이 적용된다

    Scenario: 큰 크기 Note
      Given sd-note에 size="lg"를 지정한다
      Then 늘어난 패딩이 적용된다

    Scenario: inset Note
      Given sd-note에 inset을 지정한다
      Then border-radius가 제거된다

  Rule: Progress는 0~1 값을 퍼센트 텍스트와 비율 바로 표시한다

    Scenario: 50% 진행률 표시
      Given sd-progress에 value=0.5, theme="primary"를 지정한다
      Then "50%" 텍스트와 50% 너비의 primary 바가 표시된다

    Scenario: 0% 진행률
      Given sd-progress에 value=0, theme="success"를 지정한다
      Then "0%" 텍스트와 0% 너비의 바가 표시된다

    Scenario: 100% 진행률
      Given sd-progress에 value=1, theme="info"를 지정한다
      Then "100%" 텍스트와 100% 너비의 바가 표시된다

    Scenario: 작은 크기 Progress
      Given sd-progress에 size="sm"를 지정한다
      Then 줄어든 패딩이 적용된다

    Scenario: inset Progress
      Given sd-progress에 inset을 지정한다
      Then border-radius와 border가 제거되고 control-color 배경이 적용된다

  Rule: Calendar는 지정 월의 날짜를 6×7 그리드로 표시하고 아이템을 날짜별로 매핑한다

    Scenario: 월별 달력 그리드 표시
      Given sd-calendar에 yearMonth=2026-03-01을 지정한다
      Then 3월의 날짜가 6행 7열 테이블로 표시된다
      And 요일 헤더가 weekStartDay 기준으로 표시된다

    Scenario: 현재 월 외 날짜 스타일
      Given 3월 달력을 표시한다
      When 2월 말이나 4월 초 셀이 있다
      Then .not-current 스타일(회색 배경, 회색 텍스트)이 적용된다

    Scenario: 아이템을 날짜별로 매핑
      Given items 배열과 getItemDateFn을 지정한다
      When 3/15에 해당하는 아이템이 있다
      Then 3/15 셀에 itemOf 템플릿이 렌더링된다

    Scenario: 주 시작 요일 변경
      Given weekStartDay=1(월요일)을 지정한다
      Then 요일 헤더가 월요일부터 시작하고 그리드가 이에 맞춰 조정된다
```

## 구현계획

### 배경

v14 @simplysm/angular에는 layout/과 form/ 하위에 다수의 UI 컴포넌트가 마이그레이션되어 있다. 표시(visual) 컴포넌트는 아직 없으며, `src/ui/visual/` 디렉토리를 새로 생성한다. 4개 컴포넌트(sd-label, sd-note, sd-progress, sd-calendar)는 모두 표시 전용으로 사용자 입력을 받지 않는다.

### 목표

- sd-label, sd-note, sd-progress, sd-calendar를 v14 패턴(standalone, booleanAttribute, computed, host binding)으로 마이그레이션
- 각 컴포넌트의 test fixture + spec 작성
- public API(index.ts)에 등록

### 비목표

- sd-barcode, sd-echarts (Feature 2.7에서 처리)
- 컴포넌트 기능 변경/개선 — 소스 동작을 그대로 유지

### 설계

#### 마이그레이션 변환 규칙

| v12 | v14 |
|-----|-----|
| `transformBoolean` (커스텀) | `booleanAttribute` (`@angular/core`) |
| `$computed(() => ...)` (커스텀) | `computed(() => ...)` (`@angular/core`) |
| `@simplysm/sd-core-common` | `@simplysm/core-common` |
