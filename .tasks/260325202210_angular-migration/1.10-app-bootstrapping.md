# Feature 1.10 앱 부트스트래핑

## 참조 자료

- [wbs.md](./wbs.md)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | Cordova 감지 로직 | 제거 | v14에서 Capacitor v7.6.1로 완전 전환, Cordova 참조 0건. Capacitor는 deviceready 불필요 |
| D2 | ɵresetCompiledComponents | 유지 | Angular 21에 공개 API 대안 없음, ɵ-prefixed가 유일한 방법 |
| D3 | 라우터 네비게이션 busy | Feature 3.4로 이관 | SdBusyProvider(3.4) 미존재, forward dependency 이관 패턴(1.9→3.5 선례) |
| D4 | Service Worker 업데이트 확인 | v14에 포함 | 원본과 동일하게 provideSdAngular에 포함 (SwUpdate optional inject) |
| D5 | 테마 persistence 위치 | provideSdAngular initializer | v14 SdThemeProvider가 SdLocalStorageProvider 미의존, initializer에서 읽기+쓰기 모두 처리 |
| D6 | sdHmrBootstrapAsync console.error | 제거 | console.* 금지 규칙. throw로 에러 전파 시 devtools에서 확인 가능 |

## 요구명세

```gherkin
Feature: 1.10 앱 부트스트래핑

  Background:
    Given Angular 21 애플리케이션 프로젝트가 있다

  Rule: provideSdAngular가 플러그인·프로바이더·설정을 일괄 등록한다

    Scenario: 앱 부트스트랩 시 모든 프로바이더와 플러그인이 등록된다
      Given provideSdAngular({clientName: "myApp"})를 ApplicationConfig에 포함한다
      When 앱이 부트스트랩된다
      Then SdAngularConfigProvider.clientName이 "myApp"이다
      And EVENT_MANAGER_PLUGINS에 5개 플러그인이 등록된다: SdSaveCommandEventPlugin, SdRefreshCommandEventPlugin, SdInsertCommandEventPlugin, SdResizeEventPlugin, SdOptionEventPlugin
      And ErrorHandler가 SdGlobalErrorHandlerPlugin으로 등록된다
      And provideZonelessChangeDetection이 활성화된다
      And IMAGE_CONFIG.disableImageSizeWarning이 true이다
      And IMAGE_CONFIG.disableImageLazyLoadWarning이 true이다
      And NgIconsConfig.strokeWidth가 1.5이다
      And NgIconsConfig.size가 "1.33em"이다

    Scenario: provideSdAngular 미호출 시 커스텀 이벤트가 동작하지 않는다
      Given provideSdAngular를 ApplicationConfig에 포함하지 않는다
      When 템플릿에서 (sdResize) 이벤트를 바인딩한다
      Then SdResizeEventPlugin이 미등록이므로 이벤트가 동작하지 않는다

    Scenario: clientName이 SdLocalStorageProvider의 키 프리픽스로 사용된다
      Given provideSdAngular({clientName: "myApp"})로 앱을 부트스트랩한다
      When SdLocalStorageProvider.set("key", "value")를 호출한다
      Then localStorage에 "myApp.key"로 저장된다

  Rule: sdHmrBootstrapAsync가 HMR 지원 앱 부트스트랩을 수행한다

    Scenario: 개발 모드에서 HMR 파괴 함수가 등록된다
      Given ngDevMode가 활성화되어 있다
      When sdHmrBootstrapAsync(AppComponent, config)를 호출한다
      Then bootstrapApplication이 호출되어 ApplicationRef가 반환된다
      And window.__sd_hmr_destroy 함수가 등록된다

    Scenario: 프로덕션 모드에서 HMR 파괴 함수가 등록되지 않는다
      Given ngDevMode가 비활성화되어 있다
      When sdHmrBootstrapAsync(AppComponent, config)를 호출한다
      Then bootstrapApplication이 호출되어 ApplicationRef가 반환된다
      And window.__sd_hmr_destroy가 undefined이다

    Scenario: HMR 트리거 시 앱이 완전히 파괴된다
      Given 개발 모드에서 앱이 부트스트랩되어 있다
      When window.__sd_hmr_destroy()를 호출한다
      Then ɵresetCompiledComponents()로 컴포넌트 캐시가 리셋된다
      And appRef.destroy()가 호출된다
      And destroyPlatform()이 호출된다

    Scenario: 부트스트랩 실패 시 에러가 전파된다
      Given bootstrapApplication이 에러를 throw한다
      When sdHmrBootstrapAsync를 호출한다
      Then alert로 에러가 표시된다
      And 에러가 re-throw된다

  Rule: 앱 시작 시 localStorage에서 다크모드를 복원하고 변경을 자동 저장한다

    Scenario: localStorage에 다크모드 설정이 있으면 복원한다
      Given localStorage "sd-theme-dark"에 true가 저장되어 있다
      When provideSdAngular로 앱이 초기화된다
      Then SdThemeProvider.dark()이 true이다
      And document.body.className이 "sd-theme-dark"이다

    Scenario: localStorage에 다크모드 설정이 없으면 기본값을 유지한다
      Given localStorage "sd-theme-dark"에 값이 없다
      When provideSdAngular로 앱이 초기화된다
      Then SdThemeProvider.dark()이 false이다
      And document.body.className이 ""이다

    Scenario: 다크모드 변경 시 localStorage에 자동 저장된다
      Given 앱이 초기화된 상태이다
      When SdThemeProvider.dark.set(true)를 호출한다
      Then localStorage "sd-theme-dark"에 true가 저장된다

  Rule: 전역 에러 리스너가 window-level 에러를 ErrorHandler로 전달한다

    Scenario: unhandled promise rejection이 ErrorHandler로 전달된다
      Given provideSdAngular로 앱이 초기화된 상태이다
      When window에서 unhandledrejection 이벤트가 발생한다
      Then event.preventDefault()가 호출된다
      And ErrorHandler.handleError(event)가 호출된다

    Scenario: uncaught error가 ErrorHandler로 전달된다
      Given provideSdAngular로 앱이 초기화된 상태이다
      When window에서 error 이벤트가 발생한다
      Then event.preventDefault()가 호출된다
      And ErrorHandler.handleError(event)가 호출된다

    Scenario: 앱 파괴 시 에러 리스너가 정리된다
      Given provideSdAngular로 앱이 초기화된 상태이다
      When 앱이 파괴된다 (DestroyRef.onDestroy)
      Then window의 unhandledrejection 리스너가 제거된다
      And window의 error 리스너가 제거된다

  Rule: provideSdAngular가 Service Worker 업데이트를 주기적으로 확인한다

    Scenario: 업데이트 있음 + 사용자 확인 → 새로고침
      Given SwUpdate가 활성화된 상태이다
      And 서버에 새 버전이 배포되어 있다
      When 업데이트 확인이 실행된다
      Then 사용자에게 업데이트 확인 다이얼로그가 표시된다
      And 사용자가 확인하면 activateUpdate 후 페이지가 새로고침된다

    Scenario: 업데이트 없음 → 5분 후 재확인
      Given SwUpdate가 활성화된 상태이다
      And 서버에 새 버전이 없다
      When 업데이트 확인이 실행된다
      Then 5분 후 다시 확인을 예약한다

    Scenario: SwUpdate 미제공 시 아무 동작 안 함
      Given @angular/service-worker가 제공되지 않는다
      When 앱이 초기화된다
      Then SwUpdate가 null이므로 업데이트 확인을 수행하지 않는다

    Scenario: 사용자가 업데이트를 거부하면 이후 재확인
      Given SwUpdate가 활성화된 상태이다
      And 서버에 새 버전이 배포되어 있다
      When 사용자가 확인 다이얼로그에서 취소를 선택한다
      Then 업데이트가 적용되지 않는다
      And 5분 후 다시 확인을 예약한다
```

## 구현계획

### 배경

v14 Angular 패키지에 이미 구현된 프로바이더(Feature 1.8, 1.9), 이벤트 플러그인(Feature 1.5), 에러 핸들러(Feature 1.5), 테마 프로바이더(Feature 1.2)가 있다. 이들을 하나의 진입점 함수(`provideSdAngular`)로 통합하고, 개발 모드 HMR을 지원하는 부트스트랩 함수(`sdHmrBootstrapAsync`)를 제공한다.

### 목표

- `provideSdAngular` 함수로 모든 프로바이더/플러그인/설정/initializer를 일괄 등록
- `sdHmrBootstrapAsync` 함수로 개발 모드 HMR 지원 부트스트랩 제공
- 다크모드 localStorage 복원·저장
- 전역 window-level 에러 리스너 등록
- Service Worker 업데이트 주기적 확인

### 비목표

- 라우터 네비게이션 busy 표시 (Feature 3.4로 이관 — SdBusyProvider 미존재)
- Cordova 지원 (v14에서 Capacitor로 완전 전환)

### 설계

#### provideSdAngular 함수

```typescript
function provideSdAngular(opt: { clientName: string }): EnvironmentProviders
```

`makeEnvironmentProviders`로 아래 항목을 등록한다 (순서대로):

| # | 항목 | 방식 |
|---|------|------|
| 1 | IMAGE_CONFIG | `{ provide: IMAGE_CONFIG, useValue: { disableImageSizeWarning: true, disableImageLazyLoadWarning: true } }` |
| 2 | NgIconsConfig | `provideNgIconsConfig({ strokeWidth: 1.5, size: "1.33em" })` |
| 3 | 테마 초기화 + persistence | `provideEnvironmentInitializer` — localStorage에서 dark 복원, `effect()`로 변경 시 저장 |
| 4 | 전역 에러 리스너 | `provideEnvironmentInitializer` — window unhandledrejection/error → ErrorHandler 전달 |
| 5 | SdAngularConfigProvider | `{ provide: ..., useFactory: () => { ... clientName 설정 } }` |
| 6 | EventManagerPlugin × 5 | `{ provide: EVENT_MANAGER_PLUGINS, useClass: ..., multi: true }` |
| 7 | ErrorHandler | `{ provide: ErrorHandler, useClass: SdGlobalErrorHandlerPlugin }` |
| 8 | ZonelessChangeDetection | `provideZonelessChangeDetection()` |
| 9 | SW 업데이트 | `provideAppInitializer` — SwUpdate optional inject, 5분 주기 체크 |

**테마 initializer 흐름:**
1. (동기) `SdLocalStorageProvider.get("sd-theme-dark")` → 값 있으면 `SdThemeProvider.dark.set()`
2. (effect) `SdThemeProvider.dark()` 변경 감지 → `SdLocalStorageProvider.set("sd-theme-dark", ...)`

SdAngularConfigProvider의 `useFactory`가 `clientName`을 설정하므로, SdLocalStorageProvider가 injection 시 올바른 키 프리픽스를 사용한다.

#### sdHmrBootstrapAsync 함수

```typescript
async function sdHmrBootstrapAsync(
  rootComponent: Type<unknown>,
  options?: ApplicationConfig,
): Promise<ApplicationRef>
```

원본 대비 변경점:
- Cordova 감지 분기 제거 (D1) → 단일 경로만 유지
- `console.error` 제거 (D6) → `alert` + `throw`만 유지
- `ɵresetCompiledComponents` 유지 (D2)

#### commons.ts

```typescript
export const TXT_CHANGE_IGNORE_CONFIRM = `...`;
```

Feature 1.11(setupCanDeactivate)에서 사용할 상수. 4줄 단순 export.

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| SdThemeProvider에 SdLocalStorageProvider 직접 의존 | 미채택 | SdThemeProvider의 관심사를 상태+UI로 제한, persistence는 앱 레벨 관심사 |
| setInterval로 SW 업데이트 폴링 | 미채택 | recursive setTimeout이 체크 완료 후 다음 예약으로 겹침 방지 |
| 전역 에러 리스너를 SdGlobalErrorHandlerPlugin에 통합 | 미채택 | Angular ErrorHandler는 Angular 내부 에러만 처리, window-level은 별도 리스너 필요 |
