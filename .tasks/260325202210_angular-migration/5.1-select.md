# Feature 5.1 셀렉트

## 참조 자료

- [wbs.md](./wbs.md)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | v12 API 호환성 | v12 공개 API를 그대로 유지 | 마이그레이션 목적이므로 동작 변경 없이 내부 구현만 v14 패턴으로 전환 |
| D2 | v12 유틸 래퍼 제거 | `$computed` → `computed`, `$signal` → `signal`, `afterEveryRender` → `afterRender`, `transformBoolean` → `booleanAttribute`, `injectElementRef` → `inject(ElementRef)` | v14 코드베이스가 네이티브 Angular API를 직접 사용하는 패턴 |
| D3 | contentClass/contentStyle 처리 | `effect()`로 popup 요소에 직접 적용 | v14 `SdDropdownControl`에 해당 input 없음 |
| D4 | findFocusableAll 대체 | `tabbable` 라이브러리의 `tabbable()` 함수 사용 | v14 core-browser에 해당 메서드 없음, `tabbable`은 이미 의존성 |

## 구현계획

### 배경

v12 `sd-angular`의 셀렉트 UI 컴포넌트 3개(SdSelectControl, SdSelectItemControl, SdSelectButtonControl)를 v14 `@simplysm/angular`로 마이그레이션한다. v14는 Angular 21 네이티브 시그널 API를 직접 사용하며, v12 커스텀 래퍼를 제거한다. 의존 컴포넌트(Dropdown, Checkbox, Anchor, Gap 등)는 모두 v14에 구현 완료 상태이다.

### 목표

- v12 공개 API를 유지하면서 v14 패턴으로 내부 구현 전환
- 3개 컴포넌트 + `TSelectModeValue` 타입 export

### 비목표

- `setupCloserWhenSingleSelectionChange`, `setupCumulateSelectedKeys` — Feature 5.3
- `SdSelectionManager` — Feature 6.1
- `SdModalSelectButtonControl` — Feature 5.3

### 설계

#### 컴포넌트 구조

```
sd-select (SdSelectControl)
├── sd-dropdown (기존)
│   ├── ._sd-select-control (trigger area)
│   │   ├── ._sd-select-control-content (선택값 표시)
│   │   └── ._sd-select-control-icon (caret)
│   ├── sd-select-button (SdSelectButtonControl, optional)
│   └── sd-dropdown-popup (기존)
│       ├── headerTpl (optional)
│       ├── 전체선택/전체해제 (multi only)
│       ├── beforeTpl (optional)
│       └── sd-select-item (SdSelectItemControl, N개)
│           ├── sd-checkbox (multi only)
│           └── ._content (projected content)
```

#### API 변환 (v12 → v14)

| v12 | v14 | 비고 |
|-----|-----|------|
| `$computed()` | `computed()` | `@angular/core` |
| `$signal()` | `signal()` | `@angular/core` |
| `afterEveryRender()` | `afterRender()` | `@angular/core`, 매 렌더 후 DOM 읽기 |
| `$afterRenderEffect()` | `effect()` | 시그널 의존성 기반 재실행 |
| `transformBoolean` | `booleanAttribute` | `@angular/core` |
| `injectElementRef()` | `inject(ElementRef)` | `@angular/core` |
| `findFocusableAll()` | `tabbable()` | `tabbable` 라이브러리 |

#### contentClass/contentStyle 처리

v14 `SdDropdownControl`에 해당 input이 없으므로, `effect()`에서 popup ElementRef에 직접 class/style 적용:

```typescript
effect(() => {
  const popupEl = this._dropdownPopupElRef().nativeElement;
  const cls = this.contentClass();
  if (cls) popupEl.classList.add(...cls.split(" ").filter(Boolean));
  const style = this.contentStyle();
  if (style) popupEl.style.cssText += ";" + style;
});
```

#### 키보드 네비게이션 (ArrowUp/Down in popup)

`tabbable` 라이브러리의 `tabbable()` 함수로 popup 내 모든 탭 가능 요소를 조회하여 순차 탐색:

```typescript
import { tabbable } from "tabbable";

onPopupKeydown(event: KeyboardEvent) {
  if (event.key === "ArrowDown" || event.key === "ArrowUp") {
    const focusableEls = tabbable(this._dropdownPopupElRef().nativeElement);
    // currIndex 기반 이동
  }
}
```

#### 선택값 표시 (contentHTML 미러링)

1. `SdSelectItemControl`: `afterRender()` 콜백으로 매 렌더 후 `._content` innerHTML → `contentHTML` 시그널 갱신
2. `SdSelectControl`: `effect()`로 선택된 아이템의 `contentHTML()` 읽어 표시 영역 innerHTML 업데이트

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| `SdDropdownControl`에 `contentClass`/`contentStyle` input 추가 | 미채택 | 이미 완성된 dropdown 컴포넌트 수정은 범위 밖 |
| popup에 `effect()`로 직접 적용 | 채택 | 기존 컴포넌트 변경 없이 같은 효과 |
| `findFocusableAll()`을 core-browser에 추가 | 미채택 | core-browser 확장은 별도 이슈 |
| `tabbable()` 함수 직접 사용 | 채택 | 이미 의존성, 같은 결과 |
