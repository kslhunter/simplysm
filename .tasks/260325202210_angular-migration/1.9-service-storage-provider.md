## 구현계획

### 배경

v14 Angular 21 마이그레이션의 일환으로, 파일 선택 다이얼로그, 로컬 스토리지, 시스템 설정 프로바이더를 포팅한다. 소스는 v12 sd-angular의 `core/providers/` 및 `core/utils/signals/`에 있다. v14에는 이미 5개 Provider(SdAngularConfigProvider, SdAppStructureProvider, SdNavigateWindowProvider, SdSystemLogProvider, SdThemeProvider)가 동일한 패턴(`@Injectable({providedIn: 'root'})`, `inject()`)으로 마이그레이션되어 있다.

### 목표

- SdFileDialogProvider, SdLocalStorageProvider, SdSystemConfigProvider, useSdSystemConfigResource를 v14 패턴으로 마이그레이션
- `injectSdLocalStorage` 헬퍼 제거
- `$resource` → `resource()`, `injectElementRef` → `inject(ElementRef)` 교체
- src/index.ts에 export 추가

### 비목표

- SdServiceClientFactoryProvider, SdPrintProvider, SdSharedDataProvider (Feature 3.5)
- Provider를 사용하는 UI 컴포넌트 (각 Epic에서 구현)

### 설계

#### 파일 구조

```
packages/angular/src/core/providers/
  sd-file-dialog.provider.ts     (신규)
  sd-local-storage.provider.ts   (신규)
  sd-system-config.provider.ts   (신규)
packages/angular/src/core/utils/
  useSdSystemConfigResource.ts   (신규)
```

#### SdFileDialogProvider

소스와 동일한 구조. 변경 없음.

- `@Injectable({providedIn: 'root'})`
- `showAsync(multiple?, accept?)` — 오버로드 3개 (단일/복수/내부)
- 숨겨진 `input[type=file]`을 DOM에 추가 → click() → change/focus 이벤트 처리
- 취소 감지: `focus` 이벤트 후 `Wait.time(1000)` 대기 (WebKit 61 cancel 이벤트 미지원으로 유지)

#### SdLocalStorageProvider

- `@Injectable({providedIn: 'root'})`
- `SdAngularConfigProvider.clientName` 기반 키 네임스페이스
- `set<K>(key, value)` / `get<K>(key)` / `remove(key)` — JsonConvert로 직렬화/역직렬화
- `injectSdLocalStorage()` 헬퍼 함수 **제거** (D2)

#### SdSystemConfigProvider

소스와 동일한 구조.

- `@Injectable({providedIn: 'root'})`
- `SdLocalStorageProvider` 주입
- `fn?` — 커스텀 get/set 함수 (외부 저장소 연동용)
- `setAsync(key, data)` / `getAsync(key)` — fn 존재 시 fn 사용, 없으면 localStorage fallback

#### useSdSystemConfigResource

`$resource` → Angular 21 네이티브 `resource()` + wrapper 패턴으로 교체.

Angular 21의 `resource()` 반환 타입 `ResourceRef<T>`는 `WritableResource<T>`를 상속하여 `.set()`/`.update()`를 지원하지만, saver(자동 저장) 기능은 없다. 따라서 `.set()` 호출 시 로컬 값 갱신 + 비동기 저장을 결합하는 wrapper 객체를 반환한다.

```
반환 타입: {
  value:     WritableSignal<T | undefined>  — resource의 value signal
  isLoading: Signal<boolean>                — 로딩 상태
  status:    Signal<ResourceStatus>         — resource 상태
  hasValue:  () => boolean                  — 값 존재 여부
  reload:    () => boolean                  — 강제 재로드
  set:       (value: T | undefined) => void — 로컬 갱신 + 비동기 저장
  update:    (fn) => void                   — set의 functional 변형
}
```

- `inject(ElementRef)` → `nativeElement.tagName.toLowerCase()`로 네임스페이스
- `resource({ params, loader })` — params 변경 시 loader 자동 호출
- `set(value)` — `res.set(value)` (로컬) + `queueMicrotask(() => sdSystemConfig.setAsync(...))` (비동기 저장)

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| resource() + wrapper (set에 저장 로직 포함) | 채택 | resource()의 params 반응성 + 명시적 저장 로직. monkey-patch 불필요 |
| linkedSignal로 writable 계층 추가 | 미채택 | resource().value가 이미 WritableSignal이므로 불필요한 추가 계층 |
| effect로 value 변경 감지 + 자동 저장 | 미채택 | loader 완료와 수동 set을 구분할 수 없어 불필요한 round-trip 발생 |
| set() monkey-patch | 미채택 | 편법 — wbs.md에서 setupModelHook의 monkey-patch가 주의사항으로 기록됨 |
