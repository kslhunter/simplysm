## 구현계획

### 배경

Feature 1.5 (이벤트 시스템)와 1.6 (DOM 효과 디렉티브) 마이그레이션이 완료되어, `packages/angular/src/core/` 하위에 directives, plugins, providers, utils 구조가 확립되었다. Feature 1.7은 나머지 코어 유틸리티(템플릿 디렉티브, 파이프, 라우터 디렉티브, 모델 훅)를 마이그레이션한다.

### 목표

- 6개 모듈 마이그레이션: SdTypedTemplateDirective, SdItemOfTemplateDirective, FormatPipe, SdNavigateWindowProvider, SdRouterLinkDirective, setupModelHook
- Angular 21 최신 API 적용 (`@Input` → `input()`, `querystring` → `URLSearchParams`)
- `src/index.ts` barrel export 추가

### 비목표

- 바인딩 유틸리티 ($signal, $computed 등) — 네이티브 API 대체 결정 (wbs.md)
- TDirectiveInputSignals — Feature 3.2로 이관
- 나머지 integration provider — Feature 1.9에서 마이그레이션

#### API 변경 사항

| 모듈 | 변경 |
|------|------|
| SdTypedTemplateDirective | `@Input({ required: true }) typed!: T` → `typed = input.required<T>()`. `ngTemplateContextGuard` 유지 (Angular 컴파일러가 signal input 제네릭 추론 지원) |
| SdItemOfTemplateDirective | `@Input({ required: true }) itemOf!: TItem[]` → `itemOf = input.required<TItem[]>()`. `SdItemOfTemplateContext` 인터페이스 그대로 export |
| SdRouterLinkDirective | `import * as querystring` 제거 → `URLSearchParams` 사용. `ParsedUrlQuery` 타입 제거 → `Record<string, string>` 단순화. `input()` signal API 유지 (소스에서 이미 사용) |
| FormatPipe | `@simplysm/sd-core-common` → `@simplysm/core-common` import 경로 변경. 나머지 동일 |
| SdNavigateWindowProvider | 소스 그대로 포팅 (이미 `@Injectable({ providedIn: 'root' })`, `URLSearchParams` 사용) |
| setupModelHook | 소스 그대로 포팅 (이미 Angular Signal API 사용) |

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| querystring 폴리필 번들 포함 | 미채택 | 불필요한 번들 크기 증가, URLSearchParams가 브라우저 표준 |
| SdNavigateWindowProvider를 providers/integration/ 서브디렉토리에 배치 | 미채택 | 현재 1개 파일, Feature 1.9에서 서브디렉토리 구조 결정 |
| ngTemplateContextGuard 대신 Angular 21의 다른 타입 가드 메커니즘 | 미채택 | Angular 21에서도 ngTemplateContextGuard가 유일한 표준 메커니즘 |
