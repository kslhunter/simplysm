# Feature 1.6 DOM 효과 디렉티브

## 참조 자료

- [wbs.md](./wbs.md)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | setSafeStyle export 범위 | public export 유지 | v12에서 public API였고, 향후 다른 Feature에서 Renderer2 스타일 설정 시 재사용 가능 |
| D2 | $effect([], ...) 대체 패턴 | effect() + untracked() | effect()의 onCleanup이 afterNextRender보다 간결. 필요 시 untracked()로 signal 추적 방지 |
| D3 | setupRipple rAF | 유지 (CSS transition 표준 패턴) | WAAPI 전환은 scope 외 개선. rAF는 타이밍 회피가 아닌 의도적 프레임 분리 |
| D4 | Renderer2 일관성 | 현행 유지 (혼합) | setupRipple(transient DOM)과 setupInvalid(persistent DOM)은 용도가 다름 |
| D5 | isFocusable 소스 | tabbable 패키지 직접 의존 | core-browser가 re-export하지 않으므로 angular에 직접 추가 |

### 구현 시 참고 (INFERRED High)

| # | 항목 | 근거 |
|---|------|------|
| I1 | `$effect` → 네이티브 `effect()` + `onCleanup` | v14 setupBgTheme 패턴 |
| I2 | `injectElementRef` → `inject(ElementRef)` | WBS 결정: 1줄 인라인 |
| I3 | `transformBoolean` → `booleanAttribute` | WBS 결정: 네이티브 대체 |
| I4 | `Uuid.new()` → `Uuid.generate()` | v14 core-common API 변경 |
| I5 | `entries.first()` → `entries[0]` | v14 core-common에 Array.first() 확장 없음 |
| I6 | `hostEl.isFocusable()` → `isFocusable(hostEl)` (tabbable import) | v14 core-browser에서 Element 프로토타입 메서드 제거됨 |
| I7 | `hostEl.findFocusableFirst()` → `hostEl.findFirstFocusableChild()` | v14 core-browser 메서드명 변경 |
| I8 | setupRevealOnShow: `observer.disconnect()` cleanup 추가 | v12 소스에 누락, 리소스 누수 |
| I9 | setupRipple의 `requestAnimationFrame`: CSS transition 시작을 위한 표준 패턴. Web Animations API 대안 검토 가능 | 타이밍 회피가 아닌 의도적 프레임 분리 |

## 요구명세

```gherkin
Feature: 1.6 DOM 효과 디렉티브

  Background:
    Given @simplysm/angular 패키지의 standalone 디렉티브가 DOM 요소에 적용되어 있다

  Rule: 클릭 피드백 효과 (Ripple)

    Scenario: enabled 상태에서 pointerdown 시 원형 물결 생성
      Given sd-ripple 디렉티브가 enabled 상태로 적용된 요소가 있다
      When 요소에 pointerdown 이벤트가 발생한다
      Then 포인터 위치에 원형 물결 요소가 생성된다
      And 물결은 scale 0.1에서 1로 transition 된다

    Scenario: pointerup 시 물결 페이드아웃
      Given 물결이 진행 중이다
      When pointerup 이벤트가 발생한다
      Then 물결의 opacity가 0으로 transition 된다
      And transition 완료 후 물결 요소가 DOM에서 제거된다

    Scenario: disabled 상태에서 pointerdown 시 아무 효과 없음
      Given sd-ripple 디렉티브가 disabled 상태로 적용된 요소가 있다
      When 요소에 pointerdown 이벤트가 발생한다
      Then 물결이 생성되지 않는다

    Scenario: pointercancel 또는 pointerleave 시 물결 페이드아웃
      Given 물결이 진행 중이다
      When pointercancel 또는 pointerleave 이벤트가 발생한다
      Then 물결의 opacity가 0으로 transition 된다

    Scenario: host 요소에 position과 overflow 자동 설정
      Given sd-ripple 디렉티브가 적용된 요소가 있다
      When 디렉티브가 초기화된다
      Then host 요소의 position이 relative로 설정된다
      And host 요소의 overflow가 hidden으로 설정된다

    Scenario: 연속 pointerdown 시 이전 물결 교체
      Given 물결이 진행 중이다
      When 새로운 pointerdown 이벤트가 발생한다
      Then 이전 물결 요소가 즉시 제거된다
      And 새 포인터 위치에 새 물결이 생성된다

  Rule: 표시 애니메이션 (ShowEffect)

    Scenario: 초기 상태 설정
      Given sd-show-effect 디렉티브가 적용된 요소가 있다
      When 디렉티브가 초기화된다
      Then 요소의 opacity가 0으로 설정된다
      And type이 "t2b"이면 translateY(-1em), "l2r"이면 translateX(-1em)이 설정된다

    Scenario: viewport 진입 시 위에서 아래로 슬라이드+페이드 인
      Given sd-show-effect가 enabled이고 type="t2b"인 요소가 viewport 밖에 있다
      When 요소가 viewport에 진입한다
      Then 요소가 위에서 아래로 슬라이드하며 페이드 인된다

    Scenario: viewport 진입 시 왼쪽에서 오른쪽으로 슬라이드+페이드 인
      Given sd-show-effect가 enabled이고 type="l2r"인 요소가 viewport 밖에 있다
      When 요소가 viewport에 진입한다
      Then 요소가 왼쪽에서 오른쪽으로 슬라이드하며 페이드 인된다

    Scenario: disabled 시 즉시 표시
      Given sd-show-effect가 disabled인 요소가 viewport 밖에 있다
      When 요소가 viewport에 진입한다
      Then transition 없이 즉시 표시된다

    Scenario: viewport 이탈 후 재진입 시 재애니메이션 없음
      Given sd-show-effect로 이미 표시된 요소가 있다
      When 요소가 viewport를 이탈했다가 재진입한다
      Then 재애니메이션 없이 표시 상태를 유지한다

    Scenario: 기본값
      Given sd-show-effect 디렉티브가 옵션 없이 적용되었다
      When type과 enabled가 명시되지 않았다
      Then type의 기본값은 "t2b"이다
      And enabled의 기본값은 true이다

  Rule: 유효성 표시 (Invalid)

    Scenario: 유효하지 않은 상태에서 인디케이터 표시
      Given sd-invalid 디렉티브가 적용된 요소가 있다
      When invalidMessage가 비어있지 않은 문자열이다
      Then host 좌상단에 빨간 원형 인디케이터가 표시된다

    Scenario: 유효한 상태에서 인디케이터 숨김
      Given sd-invalid 디렉티브가 적용된 요소가 있다
      When invalidMessage가 빈 문자열이다
      Then 인디케이터가 숨겨진다

    Scenario: form submit 시 validity 갱신
      Given sd-invalid 디렉티브가 form 내부에 적용되어 있다
      When form submit 이벤트가 발생한다
      Then hidden input의 customValidity가 갱신된다
      And 인디케이터 상태가 반영된다

    Scenario: hidden input focus 시 포커스 리다이렉트
      Given sd-invalid 디렉티브가 적용된 요소가 있다
      When 내부 hidden input이 focus를 받는다
      Then host가 focusable이면 host로 포커스가 이동한다
      And host가 focusable이 아니면 첫 번째 focusable 자식으로 이동한다
      And 자식도 없으면 가장 가까운 focusable 부모로 이동한다

    Scenario: form 없는 환경
      Given sd-invalid 디렉티브가 form 외부에 적용되어 있다
      When invalidMessage가 변경된다
      Then submit 이벤트 연동 없이 인디케이터만 동작한다

  Rule: 안전한 다중 스타일 설정 (setSafeStyle)

    Scenario: 스타일 객체로 다중 스타일 설정
      Given Renderer2 인스턴스와 HTMLElement가 있다
      When 스타일 객체를 전달하여 setSafeStyle을 호출한다
      Then 각 스타일 속성별로 Renderer2.setStyle이 호출된다
```

## 구현계획

### 배경

v14 `@simplysm/angular` 패키지에 DOM 효과 디렉티브를 마이그레이션한다. Feature 1.5(이벤트 시스템)에서 확립된 v14 패턴(standalone directive, native effect/signal API, vitest browser 테스트) 위에 구축한다. v12의 커스텀 래퍼(`$effect`, `injectElementRef`, `transformBoolean`)를 v14 네이티브 API로 기계적 교체한다.

### 목표

- 3 standalone 디렉티브 + 3 setup 함수 + setSafeStyle 유틸 마이그레이션
- v12 동작 보존 + observer cleanup 버그 수정 (I8)
- v14 코딩 컨벤션 준수

### 비목표

- 동작 변경 (rAF→WAAPI 등 추가 개선)
- 다른 Feature 디렉티브/컴포넌트 마이그레이션

#### API 변환 매핑

| v12 | v14 | 적용 파일 |
|-----|-----|----------|
| `$effect([], fn)` | `effect(() => { untracked(fn) })` | setupRipple, setupRevealOnShow |
| `$effect(fn)` | `effect(fn)` | setupInvalid |
| `injectElementRef<T>()` | `inject<ElementRef<T>>(ElementRef)` | 3 setup 함수 |
| `transformBoolean` | `booleanAttribute` | SdRippleDirective, SdShowEffectDirective |
| `Uuid.new()` | `Uuid.generate()` | setupInvalid |
| `entries.first()` | `entries[0]` | setupRevealOnShow |
| `hostEl.isFocusable()` | `isFocusable(hostEl)` (tabbable) | setupInvalid |
| `hostEl.findFocusableFirst()` | `hostEl.findFirstFocusableChild()` | setupInvalid |

#### 디렉티브 API

| Directive | Selector | Inputs |
|-----------|----------|--------|
| SdRippleDirective | `[sd-ripple]` | `sd-ripple: boolean` (required, transform: booleanAttribute) |
| SdShowEffectDirective | `[sd-show-effect]` | `sd-show-effect: boolean` (required, transform: booleanAttribute), `sd-show-effect-type: "l2r" \| "t2b"` (default "t2b") |
| SdInvalidDirective | `[sd-invalid]` | `sd-invalid: string` (required) |

#### setup 함수 signal 추적 전략

| 함수 | effect 패턴 | 이유 |
|------|------------|------|
| setupRipple | `effect((onCleanup) => { ... })` | body에 signal 읽기 없음 → 1회 실행, onCleanup으로 리스너 제거 |
| setupRevealOnShow | `effect((onCleanup) => { ... untracked(() => optFn?.()) ... })` | optFn이 directive signal을 읽으므로 untracked 필요 → 1회 실행, onCleanup으로 observer.disconnect() |
| setupInvalid | `effect(() => { ... getInvalidMessage() ... })` | invalidMessage signal 추적 → 변경 시 재실행. DOM 생성은 effect 밖에서 1회 |

#### 의존성 추가

```json
// package.json dependencies에 추가
"tabbable": "^6.2.0"
```

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|----------|------|
| setupRipple rAF → Web Animations API | 미채택 | rAF는 CSS transition 시작을 위한 표준 패턴. WAAPI 전환은 동작 변경 없이 구현만 변경하므로 scope 외 |
| $effect([], ...) → afterNextRender() | 미채택 | afterNextRender는 onCleanup 미지원 → DestroyRef 필요 → 더 장황. effect()가 간결 |
| Renderer2 일관 통일 | 미채택 | setupRipple(transient 물결 요소)과 setupInvalid(persistent indicator/input)은 용도가 다름. v12 패턴 유지 |
| isFocusable 네이티브 구현 | 미채택 | tabbable이 이미 workspace에 존재 (core-browser 의존), 표준 구현 활용 |
