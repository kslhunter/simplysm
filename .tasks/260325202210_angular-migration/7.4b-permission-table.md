## 요구명세

```gherkin
Feature: 7.4b 권한 매트릭스 편집

  Background:
    Given SdPermissionTableControl이 렌더링되어 있다
    And ISdPermission 배열이 items로 전달되어 있다

  Rule: 계층형 권한 트리를 테이블로 렌더링한다

    Scenario: 2단계 계층 렌더링
      Given items에 부모 1개, 자식 2개가 포함된 2단계 계층이 전달된다
      When 컴포넌트가 렌더링된다
      Then 부모 행과 자식 2개 행이 모두 표시된다

    Scenario: 빈 배열 렌더링
      Given items에 빈 배열이 전달된다
      When 컴포넌트가 렌더링된다
      Then 테이블 본문이 비어있다

    Scenario: 깊이별 테마 색상 적용
      Given items에 3단계 이상 중첩 계층이 전달된다
      When 컴포넌트가 렌더링된다
      Then depth 0은 "first" 테마, 이후 depth % 3에 따라 "info", "warning", "success" 테마가 적용된다

  Rule: 접기/펼치기로 하위 항목을 관리한다

    Scenario: 자식이 있는 항목 접기
      Given 자식이 있는 항목이 펼쳐진 상태이다
      When 해당 항목의 제목을 클릭한다
      Then 하위 항목들이 숨겨진다

    Scenario: 접힌 항목 펼치기
      Given 자식이 있는 항목이 접힌 상태이다
      When 해당 항목의 제목을 클릭한다
      Then 하위 항목들이 표시된다

    Scenario: 접기 시 손자 항목도 함께 접힘
      Given 부모 > 자식 > 손자 3단계 구조이다
      When 부모 항목을 접는다
      Then 자식과 손자 항목 모두 접힌 상태가 된다

  Rule: use/edit 체크박스로 권한을 토글한다

    Scenario: use 권한 체크
      Given 항목의 perms에 "use"가 포함되어 있다
      When use 체크박스를 체크한다
      Then value에 "코드체인.use": true가 기록된다

    Scenario: edit 권한 체크
      Given 항목의 perms에 "edit"가 포함되어 있다
      And use가 이미 체크되어 있다
      When edit 체크박스를 체크한다
      Then value에 "코드체인.edit": true가 기록된다

    Scenario: perms에 use만 있으면 use 체크박스만 표시
      Given 항목의 perms가 ["use"]이다
      When 컴포넌트가 렌더링된다
      Then use 체크박스만 표시되고 edit 체크박스는 표시되지 않는다

      When 부모의 use를 체크한다
      Then 모든 자식의 use도 체크된다

    Scenario: 부모 use 해제 시 자식 전파
      Given 부모와 자식 모두 use가 체크되어 있다
      When 부모의 use를 해제한다
      Then 모든 자식의 use도 해제된다

    Scenario: 부모 edit 체크 시 자식 전파
      Given 부모와 자식 모두 use가 체크되어 있다
      When 부모의 edit를 체크한다
      Then 모든 자식의 edit도 체크된다

  Rule: use 해제 시 edit 자동 해제

    Scenario: use 해제 시 edit도 해제
      Given 항목의 use와 edit가 모두 체크되어 있다
      When use를 해제한다
      Then edit도 자동으로 해제된다

    Scenario: use 미체크 상태에서 edit 체크 불가
      Given 항목의 use가 체크되어 있지 않다
      When edit 체크박스를 확인한다
      Then edit 체크박스가 disabled 상태이다

  Rule: disabled 상태에서 모든 체크박스 비활성화

    Scenario: disabled 시 전체 비활성화
      Given disabled가 true로 설정되어 있다
      When 컴포넌트가 렌더링된다
      Then 모든 use/edit 체크박스가 disabled 상태이다
```

## 구현계획

### 배경

v12의 `SdPermissionTableControl`을 v14 Angular 21로 마이그레이션한다. v14에는 `ISdPermission` 인터페이스가 이미 `sd-app-structure.provider.ts`에 정의되어 있으며, `SdCollapseIconControl`, `SdCheckboxControl`, `SdAnchorControl` 등 의존 컴포넌트도 v14에 구현 완료 상태이다.

### 목표

- `SdPermissionTableControl` 컴포넌트를 v14 패턴으로 마이그레이션
- `packages/angular/src/index.ts`에 export 추가

### 비목표

- `ISdPermission` 인터페이스 변경 (이미 존재)
- 권한 데이터 로딩/저장 로직 (소비 프로젝트 영역)

### 설계

#### 컴포넌트 구조

- **파일:** `packages/angular/src/features/permission-table/sd-permission-table.control.ts`
- **셀렉터:** `sd-permission-table`
- **입력/출력:**
  - `items: input<ISdPermission<TModule>[]>([])` — 권한 트리 데이터
  - `value: model<Record<string, boolean>>({})` — 권한 체크 상태 (양방향)
  - `disabled: input(false, { transform: booleanAttribute })` — 전체 비활성화

#### v12 → v14 변환 매핑

| v12 | v14 |
|-----|-----|
| `$signal(new Set())` | `signal(new Set())` |
| `$computed(() => ...)` | `computed(() => ...)` |
| `transformBoolean` | `booleanAttribute` |
| `ObjectUtils.clone(v)` | `obj.clone(v)` |
| `tablerChevronRight` import + template 전달 | `SdCollapseIconControl`이 자체 아이콘 보유, `icon` prop 제거 |

#### 템플릿 구조

재귀 `NgTemplateOutlet` + `SdTypedTemplateDirective`로 트리 렌더링 (v14 `sd-sidebar-menu` 패턴과 동일). `@for`/`@if` 제어 흐름 사용.

#### 스타일

원본 SCSS를 그대로 유지. v14 CSS 변수명과 동일 (`--gap-sm`, `--gap-lg`, `--theme-*`, `--text-trans-*`).

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| 원본 로직 유지 + API만 v14로 변환 | 채택 | 검증된 로직, 최소 위험 |
| Angular CDK Tree 사용 | 미채택 | 원본의 커스텀 테이블 레이아웃과 호환 불가, 과도한 변경 |
