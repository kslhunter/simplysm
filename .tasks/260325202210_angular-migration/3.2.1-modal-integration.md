|---|---------|------|------|
| D1 | 최상위 모달 내 커맨드 핸들러 부재 시 동작 | 무시 (소멸) | 모달이 격리 컨텍스트로 동작하여 예측 가능, 뒤쪽 페이지 의도치 않은 동작 방지 |

## 구현계획

### 배경

Feature 3.2(모달)에서 SdModalProvider, SdModalControl, SdActivatedModalProvider가 구현되었다. 그러나 기존 유틸(커맨드 플러그인, 뷰 시그널, 라우터 가드)은 모달 컨텍스트를 인식하지 못한다. 또한 드롭다운은 모바일에서도 데스크톱과 동일한 팝업으로 표시된다 (v12 TODO 미구현).

wbs.md에 순환 의존 주의사항이 기록되어 있다: 커맨드 플러그인(`core/plugins/commands/`)이 SdModalProvider(`ui/overlay/modal/`)를 import하면 순환 의존이 발생한다.

### 목표

- 커맨드 플러그인 3개에 모달 컨텍스트 필터링 추가 (DOM 기반, 순환 의존 회피)
- useViewTypeSignal이 모달 내부에서 "modal" 반환
- useViewTitleSignal이 모달 내부에서 모달 제목 반환
- setupCanDeactivate가 모달 내부에서 SdActivatedModalProvider.canDeactivefn 설정
- 드롭다운이 모바일(≤520px)에서 bottom sheet로 표시

### 비목표

- SdModalProvider 자체 변경 (3.2에서 완성)
- 드롭다운 bottom sheet의 swipe-down-to-close (향후 개선 가능)
- SdBusyProvider 연동 (Feature 3.4)

### 설계

#### 커맨드 플러그인 모달 필터링 — DOM 기반 감지

순환 의존을 회피하기 위해 SdModalProvider를 import하지 않고, DOM에서 직접 모달 상태를 감지한다.

공유 유틸리티 `findTopOpenModalEl()`:
- `document.querySelectorAll<HTMLElement>("sd-modal[data-sd-open]")`로 열린 모달 수집
- 모달이 없으면 `null` 반환
- 있으면 `style.zIndex`가 가장 큰 요소 반환

각 커맨드 플러그인의 `addEventListener` listener에서:
1. `findTopOpenModalEl()` 호출
2. 결과가 null이면 기존 동작 (handler 호출)
3. 결과가 non-null이면 `topModal.contains(element)` 확인
4. 포함되지 않으면 return (이벤트 소멸, D1)

파일: `packages/angular/src/core/plugins/commands/findTopOpenModalEl.ts` (신규)

#### 뷰 시그널 + 라우터 가드 모달 통합 — SdActivatedModalProvider inject

3개 함수 모두 동일 패턴: `inject(SdActivatedModalProvider, { optional: true })`로 모달 컨텍스트 감지.

**useViewTypeSignal** — 모달 체크를 최우선 분기로 추가:
- `activatedModal != null` → "modal" 반환
- 기존 분기 (page/control) 유지

**useViewTitleSignal** — 모달 제목 반환:
- `activatedModal != null` → `activatedModal.modalComponent()?.title() ?? ""` 반환
- 기존 로직 (SdAppStructureProvider) 유지
- `modalComponent()`는 signal이므로 computed 내에서 반응적 추적

**setupCanDeactivate** — 모달 canDeactivefn 설정:
- `activatedModal != null` → `activatedModal.canDeactivefn = fn` 후 return
- 기존 로직 (ActivatedRoute.routeConfig.canDeactivate) 유지

#### 드롭다운 모바일 Bottom Sheet

**SdDropdownControl** 변경:
- `window.matchMedia("(max-width: 520px)")` 기반 모바일 감지 signal
- matchMedia change 이벤트로 반응적 업데이트
- open effect 내 분기:
  - 데스크톱: 기존 팝업 동작 유지
  - 모바일: backdrop 요소 생성 + popup에 `data-sd-mobile` 속성 설정 + backdrop click → close
- cleanup에서 backdrop 제거 + `data-sd-mobile` 속성 제거

**SdDropdownPopupControl** CSS 추가:
- `[data-sd-mobile]` 선택자: `position: fixed; left: 0; right: 0; bottom: 0; top: auto; max-height: 80vh; border-radius: (top-only); animation: slide-up`
- backdrop: `position: fixed; inset: 0; background: rgba(0,0,0,0.3); z-index: var(--z-index-dropdown)`

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| SdModalProvider import로 모달 감지 | 미채택 | wbs.md 경고: 순환 의존 발생 |
| 별도 모달 레지스트리 서비스 | 미채택 | DOM 기반 감지로 충분, 추가 서비스 불필요 |
| 커맨드 플러그인 코드 중복 | 미채택 | 3개 플러그인에 동일 로직 → findTopOpenModalEl 유틸리티 추출 |
| CSS-only 모바일 bottom sheet | 미채택 | backdrop 생성/이벤트 처리에 JS 필요 |
| matchMedia 대신 ResizeObserver | 미채택 | 뷰포트 크기 판단은 matchMedia가 표준이고 효율적 |
