# Feature 5.2 숫자·범위·날짜 입력

## 참조 자료

- [wbs.md](./wbs.md)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | v12 API 호환성 | v12 공개 API를 그대로 유지 | 마이그레이션 목적이므로 동작 변경 없이 내부 구현만 v14 패턴으로 전환 (Feature 5.1 D1과 동일) |
| D2 | v12 유틸 래퍼 제거 | `$signal` → `signal`, `$effect` → `effect`, `transformBoolean` → `booleanAttribute` | v14 코드베이스 네이티브 Angular API 사용 패턴 |

## 구현계획

### 배경

v14 Angular 21 패키지에 고급 입력 컴포넌트 3종(SdNumpadControl, SdRangeControl, SdDateRangePicker)을 v12에서 마이그레이션한다. 이 컴포넌트들이 의존하는 SdTextfieldControl, SdButtonControl, SdSelectControl, SdSelectItemControl, NgIcon은 이미 v14에 존재한다.

### 목표

- SdNumpadControl: v12 동작 동일한 숫자 패드 컴포넌트 (v14 signal 패턴)
- SdRangeControl: generic dual-textfield 범위 입력 컴포넌트
- SdDateRangePicker: 기간 유형별 날짜 범위 선택 컴포넌트
- `src/index.ts`에 3개 컴포넌트 export 추가

### 비목표

- ControlValueAccessor 구현 (v14 form 컴포넌트와 동일하게 model() 직접 바인딩)
- 접근성(ARIA) 개선 (v12 동작 유지 범위)
- 새로운 기간 유형 추가 (주, 분기 등)

### 설계

#### SdNumpadControl

- **파일:** `src/ui/form/input/sd-numpad.control.ts`
- **v12→v14 변환:**
  - `$signal<string>()` → `signal<string | undefined>(undefined)`
  - `$effect([this.text], ...)` → `effect(() => { const text = this.text(); ... untracked(() => this.value()) ... })` — `untracked()`로 순환 의존 방지
  - `$effect([this.value], ...)` → `effect(() => { const value = this.value(); ... untracked(() => this.text()) ... })`
  - `transformBoolean` → `booleanAttribute`
  - `NumberUtils.parseFloat()` → `num.parseFloat()` from `@simplysm/core-common`
  - `StringUtils.isNullOrEmpty()` → `str.isNullOrEmpty()` from `@simplysm/core-common`
- **template:** v12 table 레이아웃 유지
- **SCSS:** v12 인라인 SCSS 유지

#### SdRangeControl

- **파일:** `src/ui/form/input/sd-range.control.ts`
- **v12→v14 변환:**
  - `transformBoolean` → `booleanAttribute`
  - `TSdTextfieldTypes` import → `./sd-textfield-type-handlers`
  - `SdTextfieldControl` import → `./sd-textfield.control`
- **template:** v12 구조 유지 (두 textfield + "~" 구분자)
- **SCSS:** v12 인라인 SCSS 유지 (`mixins.flex-direction()`)

#### SdDateRangePicker

- **파일:** `src/ui/form/input/sd-date-range.picker.ts`
- **v12→v14 변환:**
  - `transformBoolean` → `booleanAttribute`
  - `DateOnly` import → `@simplysm/core-common`
  - `SdRangeControl` import → `./sd-range.control` (Slice 1에서 생성)
  - `host: { class: "flex-row gap-sm" }` → inline SCSS로 변환 (v14 패턴)
- **template:** v12 구조 유지 (기간 유형 select + 조건부 range/textfield)
- **이벤트 핸들러:** v12 event handler 방식 유지 (`handleDatePeriodTypeChanged`, `handleFromDateChanged`)

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| SdNumpadControl에 CSS Grid 레이아웃 | 미채택 | v12 table 레이아웃이 단순하고 검증됨. D1 결정(v12 API 유지)과 일관 |
| SdNumpadControl의 effect → event handler 전환 | 미채택 | v12 동작 유지. effect + untracked 패턴이 양방향 동기화에 적합 |
| SdDateRangePicker의 event handler → effect 전환 | 미채택 | v12 동작 유지. event handler가 기간 유형 전환 로직에 명시적이고 예측 가능 |
