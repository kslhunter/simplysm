Feature: 2.4.1 다중행 입력 및 폼 컨테이너 (sd-textarea, sd-form)

  Background:
    Given Angular 21 standalone 컴포넌트 환경이다

  # sd-textarea

  Rule: 다중행 텍스트를 양방향 바인딩한다

    Scenario: 텍스트 입력 시 value에 반영
      Given sd-textarea 컴포넌트가 렌더링되어 있다
      When "hello\nworld"를 입력한다
      Then value()가 "hello\nworld" (string)이다

    Scenario: value 설정 시 textarea에 표시
      Given sd-textarea 컴포넌트가 렌더링되어 있다
      And value()에 "abc"가 설정되어 있다
      Then textarea에 "abc"가 표시된다

    Scenario: 빈 입력 시 undefined
      Given sd-textarea 컴포넌트가 렌더링되어 있다
      When 입력 필드를 비운다
      Then value()가 undefined이다

  Rule: 표시 행 수는 내용 줄 수와 minRows 중 큰 값이다

    Scenario: 내용 줄 수가 minRows보다 많을 때
      Given sd-textarea 컴포넌트가 렌더링되어 있다
      And minRows=1이다
      And value()가 "a\nb\nc" (3줄)이다
      Then textarea의 rows 속성이 3이다

    Scenario: 내용 줄 수가 minRows보다 적을 때
      Given sd-textarea 컴포넌트가 렌더링되어 있다
      And minRows=5이다
      And value()가 "a" (1줄)이다
      Then textarea의 rows 속성이 5이다

    Scenario: value가 undefined일 때
      Given sd-textarea 컴포넌트가 렌더링되어 있다
      And minRows=1이다
      And value()가 undefined이다
      Then textarea의 rows 속성이 1이다

  Rule: required 및 커스텀 검증을 수행한다

    Scenario: required에 값 없음
      Given sd-textarea 컴포넌트가 렌더링되어 있다
      And required=true이다
      And value()가 undefined이다
      Then 유효성 에러 "값을 입력하세요."가 발생한다

    Scenario: required에 값 있음
      Given sd-textarea 컴포넌트가 렌더링되어 있다
      And required=true이다
      And value()가 "abc"이다
      Then 유효성 에러가 없다

    Scenario: 커스텀 validatorFn 에러
      Given sd-textarea 컴포넌트가 렌더링되어 있다
      And validatorFn이 "10자 이상 입력하세요"를 반환한다
      And value()가 "abc"이다
      Then 유효성 에러 "10자 이상 입력하세요"가 발생한다

    Scenario: required와 validatorFn 에러 동시 발생
      Given sd-textarea 컴포넌트가 렌더링되어 있다
      And required=true이다
      And validatorFn이 항상 에러를 반환한다
      And value()가 undefined이다
      Then 유효성 에러가 "\r\n"으로 구분되어 모두 표시된다

      Given sd-textarea 컴포넌트가 렌더링되어 있다

      And value()가 "내용"이다
      Then textarea가 렌더링되지 않는다
      And 표시 div의 pre 요소에 "내용"이 표시된다

      Given sd-textarea 컴포넌트가 렌더링되어 있다
      And readonly=true이다
      And value()가 "내용"이다
      Then textarea가 렌더링되지 않는다
      And 표시 div의 pre 요소에 "내용"이 표시된다

    Scenario: 편집 가능 상태에서 placeholder 표시
      Given sd-textarea 컴포넌트가 렌더링되어 있다
      And disabled=false, readonly=false이다
      And value()가 undefined이다
      And placeholder="입력하세요"이다
      Then 표시 div에 "입력하세요"가 연한 색으로 표시된다
      And textarea에 placeholder "입력하세요"가 표시된다

      Given sd-textarea 컴포넌트가 렌더링되어 있다
      And disabled=true이다
      And value()가 undefined이다
      And placeholder="입력하세요"이다
      Then 표시 div에 "입력하세요"가 연한 색으로 표시된다

      Given sd-textarea 컴포넌트가 렌더링되어 있다
      And disabled=true이다
      And value()가 undefined이다
      And placeholder가 없다

      Given sd-textarea 컴포넌트가 렌더링되어 있다
      And inline=true이다
      Then host에 data-sd-inline="true"가 설정된다
      And 컴포넌트가 inline-block으로 표시된다

    Scenario: inset 모드
      Given sd-textarea 컴포넌트가 렌더링되어 있다
      And inset=true이다
      Then host에 data-sd-inset="true"가 설정된다
      And 테두리 없이 렌더링된다

    Scenario: size 변형
      Given sd-textarea 컴포넌트가 렌더링되어 있다
      And size="sm"이다
      Then host에 data-sd-size="sm"이 설정된다

    Scenario: theme 변형
      Given sd-textarea 컴포넌트가 렌더링되어 있다
      And theme="primary"이다
      Then host에 data-sd-theme="primary"가 설정된다
      And 배경색이 해당 테마의 lightest로 변경된다

      Given sd-form 컴포넌트가 렌더링되어 있다
      And 폼 내부의 모든 입력이 유효하다
      When 폼을 제출한다
      Then formSubmit 이벤트가 방출된다
      And 브라우저 기본 폼 제출은 방지된다 (preventDefault)

    Scenario: 유효하지 않은 폼 제출
      Given sd-form 컴포넌트가 렌더링되어 있다
      And 폼 내부에 유효하지 않은 입력이 있다
      When 폼을 제출한다
      Then formInvalid 이벤트가 방출된다
      And 브라우저 유효성 메시지가 표시된다 (reportValidity)

    Scenario: requestSubmit()으로 프로그래밍 제출

      When requestSubmit()을 호출한다
      Then 폼 제출 프로세스가 시작된다

      Given sd-form 컴포넌트가 렌더링되어 있다
      And 폼 내부에 hidden type="submit" 버튼이 존재한다
      When 폼 내부 input에서 Enter 키를 누른다
      Then 폼 제출이 트리거된다

## 구현계획

### 배경

v12 sd-angular 패키지의 `sd-textarea.control.ts`와 `sd-form.control.ts`를 v14 워크스페이스로 마이그레이션한다. sd-textarea는 `sd-textfield.control.ts`와 동일한 디렉토리에 위치하며 비슷한 구조(표시 div + 입력 요소, host data-sd-* 바인딩, setupInvalid 검증)를 따르지만, 타입 시스템 없이 순수 문자열 다중행 입력만 지원한다. sd-form은 HTML form 래퍼로 유효성 검증/제출 기능을 제공하며 스타일이 없다.

### 목표

- sd-textarea: 다중행 텍스트 입력 컴포넌트 (value model, dynamic rows, validation, visual variants, SCSS)
- sd-form: 폼 래퍼 컴포넌트 (submit/invalid events, requestSubmit, hidden submit button)
- 두 컴포넌트의 테스트 fixture 및 spec

### 비목표

- sd-textfield와의 기능 통합 (별개 컴포넌트로 유지)
- 원본에 없는 추가 검증 규칙 (maxlength, pattern 등)

### 설계

#### sd-textarea

- **파일:** `packages/angular/src/ui/form/input/sd-textarea.control.ts`
- **셀렉터:** `sd-textarea`
- **템플릿:** 표시 div(`._contents`, pre 요소) + `<textarea>` 요소. disabled/readonly 시 textarea 미렌더링
- **입력:** value(model\<string\>), placeholder, title, minRows(기본값 1), disabled, readonly, required, inline, inset, size, theme, validatorFn, inputStyle, inputClass
- **행 수:** `computed(() => Math.max(this.minRows(), this.value()?.split("\n").length ?? 1))`
- **검증:** setupInvalid — required 에러 "값을 입력하세요." + validatorFn 에러를 `\r\n`으로 결합
- **이벤트:** `onInput(event)` — 빈 문자열은 undefined, 그 외는 문자열 그대로 설정
- **host 바인딩:** data-sd-disabled, data-sd-readonly, data-sd-inline, data-sd-inset, data-sd-size, data-sd-theme
- **SCSS:** sd-textfield 패턴 (form-control-base mixin, 테마 루프, size/inline/inset/disabled 변형). `<textarea>` + `._contents`에 공통 적용. resize: none

#### sd-form

- **파일:** `packages/angular/src/ui/form/sd-form.control.ts`
- **셀렉터:** `sd-form`
- **템플릿:** `<form #formEl novalidate (submit)="handleSubmit($event)">` + `<ng-content />` + `<button hidden type="submit">`
- **출력:** `submit = output<SubmitEvent>()`, `invalid = output()`
- **메서드:** `requestSubmit()` — `formEl.requestSubmit()` 호출
- **handleSubmit:** preventDefault + stopPropagation → checkValidity → 유효: submit.emit / 무효: reportValidity + invalid.emit
- **formEl 접근:** `viewChild.required<ElementRef<HTMLFormElement>>("formEl", { read: ElementRef })`
- **스타일 없음**

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| 원본 구조 그대로 마이그레이션 | 채택 | 두 컴포넌트 모두 단순 구조, 아키텍처 변경 불필요 |
| sd-textarea를 sd-textfield에 통합 | 미채택 | 타입 시스템 불필요, 별도 컴포넌트가 단순 (Feature 2.4 D7) |
