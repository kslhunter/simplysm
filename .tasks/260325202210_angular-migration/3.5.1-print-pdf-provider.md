## 요구명세

```gherkin
Feature: 3.5.1 인쇄·PDF 프로바이더

  Background:
    Given Angular 21 앱이 실행 중이다
    And SdBusyProvider가 제공된다

  Rule: 컴포넌트를 브라우저 프린터로 인쇄한다

    Scenario: 기본 옵션으로 인쇄
      Given ISdPrint을 구현한 컴포넌트 템플릿이 있다
      When 기본 옵션으로 printAsync()를 호출한다
      Then 컴포넌트가 동적 생성되어 DOM에 추가된다
      And @page size "A4 auto", margin "0"으로 인쇄 다이얼로그가 표시된다

    Scenario: 커스텀 size로 인쇄
      Given ISdPrint을 구현한 컴포넌트 템플릿이 있다
      When size "A3"으로 printAsync()를 호출한다
      Then @page size "A3"으로 인쇄 다이얼로그가 표시된다

    Scenario: 커스텀 margin으로 인쇄
      Given ISdPrint을 구현한 컴포넌트 템플릿이 있다
      When margin "10mm"으로 printAsync()를 호출한다
      Then @page margin "10mm"으로 인쇄 다이얼로그가 표시된다

    Scenario: 인쇄 후 정리
      Given printAsync()가 완료되었다
      Then 동적 생성된 컴포넌트가 DOM에서 제거된다
      And 인쇄 스타일 요소가 DOM에서 제거된다

  Rule: 컴포넌트를 PDF 바이트 배열로 생성한다

    Scenario: 기본 옵션으로 PDF 생성
      Given ISdPrint을 구현한 컴포넌트 템플릿이 있다
      When 기본 옵션으로 getPdfBufferAsync()를 호출한다
      Then A4 portrait PDF가 생성된다
      And Uint8Array로 반환된다

    Scenario: landscape 방향으로 PDF 생성
      Given ISdPrint을 구현한 컴포넌트 템플릿이 있다
      When orientation "landscape"로 getPdfBufferAsync()를 호출한다
      Then 가로 방향 PDF가 생성된다

    Scenario: 커스텀 페이지 크기로 PDF 생성
      Given ISdPrint을 구현한 컴포넌트 템플릿이 있다
      When pageSize "a3"으로 getPdfBufferAsync()를 호출한다
      Then A3 크기 PDF가 생성된다

    Scenario: 멀티 페이지 PDF 생성
      Given .page 클래스 요소 3개를 가진 컴포넌트 템플릿이 있다
      When getPdfBufferAsync()를 호출한다
      Then 3페이지 PDF가 생성된다
      And 각 .page 요소가 별도 페이지로 렌더링된다
      And 각 페이지 이미지의 가로 폭이 PDF 페이지 폭에 맞춰지고 높이는 비율 유지된다

    Scenario: 단일 페이지 PDF 생성
      Given .page 클래스 요소가 없는 컴포넌트 템플릿이 있다
      When getPdfBufferAsync()를 호출한다
      Then 전체 컴포넌트가 1페이지 PDF로 생성된다

    Scenario: PDF 생성 후 정리
      Given getPdfBufferAsync()가 완료되었다
      Then 동적 생성된 컴포넌트가 DOM에서 제거된다
      And 스타일 요소가 DOM에서 제거된다

  Rule: 작업 중 busy 상태를 관리한다

    Scenario: 작업 시작 시 busy 카운트 증가
      When printAsync() 또는 getPdfBufferAsync()가 시작된다
      Then globalBusyCount가 1 증가한다

    Scenario: 작업 성공 시 busy 카운트 감소
      Given 작업이 실행 중이다
      When 성공적으로 완료된다
      Then globalBusyCount가 1 감소한다

    Scenario: 작업 실패 시 busy 카운트 감소
      Given 작업이 실행 중이다
      When 에러가 발생한다
      Then globalBusyCount가 1 감소한다

  Rule: 렌더링 완료를 대기한 후 작업을 수행한다

    Scenario: 컴포넌트 초기화 대기
      Given 동적 컴포넌트가 생성되었다
      And initialized() 시그널이 false이다
      When initialized()가 true로 변경된다
      Then 인쇄 또는 PDF 생성 작업이 진행된다

    Scenario: 이미지 로드 대기
      Given 컴포넌트에 미로드 이미지가 있다
      When 모든 이미지의 load 또는 error 이벤트가 발생한다
      Then 작업이 진행된다

    Scenario: 이미지 로드 실패 시 진행
      Given 컴포넌트에 이미지가 있다
      When 이미지 로드가 실패한다
      Then 에러로 간주하지 않고 작업이 진행된다

    Scenario: 이미지 없는 컴포넌트
      Given 컴포넌트에 img 요소가 없다
      Then 이미지 대기 없이 즉시 작업이 진행된다
```

## 구현계획

### 배경

Feature 1.9에서 forward dependency(SdBusyProvider 미존재)로 이관된 SdPrintProvider를 v14 환경에 맞게 마이그레이션한다. v12 원본 코드(`/d/workspaces-12/simplysm/packages/sd-angular/src/core/providers/integration/sd-print.provider.ts`)가 source of truth이며, v14 API로 치환한다.

### 목표

- SdPrintProvider: 동적 컴포넌트 기반 브라우저 인쇄 + PDF 생성
- v14 API 완전 치환 (Buffer→Uint8Array, requestAnimationFrame→ApplicationRef.tick, 빈 catch 제거)
- pageSize 옵션 추가 (D1)

### 비목표

- 인쇄 템플릿 컴포넌트 구현 (앱별 구현)
- PDF 뷰어/다운로드 UI
- features/shared-data 컨트롤 (Epic 7)

#### SdPrintProvider API

| 멤버 | 시그니처 | 설명 |
|------|---------|------|
| printAsync | `<T>(template: ISdPrintInput<T>, options?: { size?: string; margin?: string }) => Promise<void>` | 동적 컴포넌트를 브라우저 프린터로 인쇄 |
| getPdfBufferAsync | `<T>(template: ISdPrintInput<T>, options?: { orientation?: "portrait" \| "landscape"; pageSize?: string }) => Promise<Uint8Array>` | 동적 컴포넌트를 PDF Uint8Array로 생성 |

inject 의존:
- `ApplicationRef` — 동적 뷰 관리 + change detection tick
- `SdBusyProvider` — busy 카운트

v12 대비 변경:
- `Buffer` → `Uint8Array` (CLAUDE.md)
- `requestAnimationFrame(() => ...)` → `ApplicationRef.tick()` + 직접 await (CLAUDE.md)
- `new Promise` wrapper + 빈 `catch {}` → `try-finally` 직접 구조 (CLAUDE.md)
- `Wait.until()` → `wait.until()` (v14 namespace export)
- `pageSize` 옵션 추가 (D1), `new jsPDF(orientation, "pt", pageSize)` + `doc.addPage(pageSize, orientation)`
- `compEl.remove()` 추가 (v12 DOM 누수 수정 — `compRef.destroy()`는 DOM element 미제거)

#### ISdPrint / ISdPrintInput 인터페이스

```typescript
export interface ISdPrint {
  initialized: Signal<boolean>;
}

export interface ISdPrintInput<T, X extends keyof any = ""> {
  type: Type<T>;
  inputs: Omit<TDirectiveInputSignals<T>, X>;
}
```

v12와 동일. 변경 없음.

#### 렌더링 대기 흐름

v12: `requestAnimationFrame → Wait.until(initialized) → waitForImages → action`
v14: `ApplicationRef.tick() → wait.until(initialized) → waitForImages → action`

`tick()`은 change detection을 즉시 트리거하여 컴포넌트의 lifecycle hooks 실행을 보장한다. `wait.until()`은 `initialized()` 시그널이 true가 될 때까지 polling한다.

#### cleanup 흐름

```
finally {
  globalBusyCount.update(v => v - 1);  // signal update — 안전
  styleEl.remove();                     // DOM remove — 안전
  compEl.remove();                      // DOM remove — 안전 (v12 누수 수정)
  compRef.destroy();                    // Angular destroy — 안전
}
```

### 대안 검토

| 접근 | 선택 | 이유 |
|------|------|------|
| afterNextRender for rendering wait | 미채택 | injection context(생성자)에서만 호출 가능, 메서드 내 사용 불가 |
