## 구현계획

### 배경

`sdAngularPlugin`의 `transform` 훅(line 307-323)이 `.ts` 파일만 처리한다. `@angular/common` 등의 fesm2022 `.mjs` 파일은 partial compilation 출력(`ɵɵngDeclareFactory`)을 포함하지만, `JavaScriptTransformer`(Angular Linker)를 거치지 않아 브라우저에서 JIT fallback 에러가 발생한다.

### 목표

- transform 훅에서 `.mjs`/`.js` 파일도 `JavaScriptTransformer`를 통과하도록 수정
- TS 컴파일(emit 교체)과 JS 변환(링킹)을 논리적 Phase로 분리

### 비목표

- `optimizeDeps` 설정 변경 (D1)
- `buildStart`, `handleHotUpdate`, `configureServer`, `buildEnd` 훅 변경
- `vite-config.ts` 변경

### 설계

`transform` 훅을 두 Phase로 구조화:

```
Phase 1 (TS 컴파일): .ts → emittedFiles에서 컴파일된 JS 조회·교체
Phase 2 (JS 변환):   .ts/.mjs/.js → JavaScriptTransformer.transformData(skipLinker=false)
```

Phase 1은 `.ts` 파일에만 적용. Phase 2는 `.ts`/`.mjs`/`.js` 모든 파일에 적용. 기타 확장자는 early return.

### 대안 검토

| 접근 방식 | 선택 | 이유 |
|-----------|------|------|
| 단일 플러그인 내 논리 분리 | 채택 | jsTransformer/emittedFiles 인스턴스 공유 용이, 최소 변경 |
| 별도 Vite 플러그인으로 분리 | 미채택 | 인스턴스 공유 복잡, enforce 우선순위 관리 추가 필요 |
| optimizeDeps.exclude + transform | 미채택 | dev 서버 성능 치명적 저하 (D1) |
