## 구현계획

### 배경

AbsSdDataSheet(`sd-data-sheet.control.ts:83-433`, ~350줄)는 14개 독립 책임을 보유한 God Class이다. SdDataSheetControl 프레젠테이션 컴포넌트는 `injectParent()`를 통해 AbsSdDataSheet의 public 메서드를 호출한다. [근거: refactor.md DESIGN-001]

기존 코드베이스의 `use*` composable 패턴(options 객체 → signal+method 반환)을 활용하여 분해한다. Feature 3.1에서 SdSheetControl에 동일 패턴을 적용한 선례가 있다. [근거: CLAUDE.md "Composable Utilities", Feature 3.1]

### 설계

#### 공유 자원 관리 (D1, D2)

AbsSdDataSheet가 소유하는 공유 상태 및 메서드:
- `busyCount`, `busyMessage`, `initialized` signals — 모든 composable에 options으로 전달 [D1]
- `checkIgnoreChanges()` 메서드 — refresh manager의 `getDiffs()`를 사용하여 변경사항 확인 [D2]
- `doRefresh()` 메서드 — `checkIgnoreChanges()` 가드 후 lastFilter mark [D2]
- `_getOrmDataEditToastErrorMessage()` — private 에러 메시지 포매터, composable에 callback으로 전달

#### Composable 간 의존 관계

```
AbsSdDataSheet (orchestrator)
  ├── useDataSheetFilterManager     ← checkIgnoreChanges (lazy callback)
  ├── useDataSheetRefreshManager    → getDiffs, refresh 반환
  ├── useDataSheetInlineEditManager ← getDiffs, refresh, errorMessageFn
  ├── useDataSheetModalEditManager  ← refresh, errorMessageFn
  └── useDataSheetExcelManager      ← refresh, errorMessageFn
```

생성 순서: filter → refresh → inline/modal/excel (병렬 가능)

lazy callback 패턴으로 순환 의존 회피:
- filter manager는 `checkIgnoreChanges: () => this.checkIgnoreChanges()` 로 수신
- `this.checkIgnoreChanges()`는 `this._refreshMgr.getDiffs()` 사용
- filter manager 생성 시점에 checkIgnoreChanges는 아직 미정의이나, 호출 시점(사용자 액션)에는 정의 완료

#### Optional 메서드 접근 패턴

AbsSdDataSheet의 optional 메서드(`newItem`, `submit`, `editItem`, `toggleDeleteItems`, `downloadExcel`, `uploadExcel`)는 소비 프로젝트의 class field로 정의될 수 있어 `super()` 시점에 미설정일 수 있다. lazy getter 패턴으로 해결: [근거: TypeScript class field는 super() 반환 후 설정]

```typescript
// composable options에 lazy getter 전달:
getNewItemFn: () => this.newItem?.bind(this),
getSubmitFn: () => this.submit?.bind(this),

// composable 내부에서 호출 시점에 평가:
async function doAddItem() {
  const newItemFn = options.getNewItemFn();
  if (!newItemFn) return;
  // ...
}
```

@Directive()
export abstract class AbsSdDataSheet<TFilter, TItem, TKey> implements ISdSelectModal<TItem> {
  //-- abstract (~30줄)
  abstract canUse, canEdit, editMode, selectMode, bindFilter, itemPropInfo, getItemInfoFn, search;
  hideTool?, diffsExcludes?, prepareRefreshEffect?;
  editItem?, toggleDeleteItems?, newItem?, submit?, downloadExcel?, uploadExcel?;

  //-- composable instances (~5줄)
  private _filter!: ReturnType<typeof useDataSheetFilterManager<TFilter>>;
  private _refreshMgr!: ReturnType<typeof useDataSheetRefreshManager<TItem, TKey>>;
  private _inlineEdit!: ReturnType<typeof useDataSheetInlineEditManager<TItem, TKey>>;
  private _modalEdit!: ReturnType<typeof useDataSheetModalEditManager<TItem, TKey>>;
  private _excel!: ReturnType<typeof useDataSheetExcelManager<TItem>>;

  //-- shared state (D1: class 소유) (~25줄)
  key, viewType, busyCount, busyMessage, initialized, close, submitted, selectedItemKeys, actionTplRef;
  autoSelect, items, summaryData, selectedItems, trackByFn, page, pageLength, sortingDefs;

  //-- filter state (composable 반환값 재할당) (~2줄)
  filter!: WritableSignal<TFilter>;
  lastFilter!: WritableSignal<TFilter>;

  //-- computed (~15줄)
  isSelectedItemsHasDeleted, isSelectedItemsHasNotDeleted;
  getItemCellStyleFn, getItemSelectableFn;

  //-- constructor (~70줄)
  constructor() {
    setupCumulateSelectedKeys({ ... });
    setupCloserWhenSingleSelectionChange({ ... });

    this._filter = useDataSheetFilterManager({ ..., checkIgnoreChanges: () => this.checkIgnoreChanges() });
    this.filter = this._filter.filter;
    this.lastFilter = this._filter.lastFilter;

    this._refreshMgr = useDataSheetRefreshManager({ ..., lastFilter: this.lastFilter });

    this._inlineEdit = useDataSheetInlineEditManager({ ..., getDiffs: () => this._refreshMgr.getDiffs(), refresh: () => this._refreshMgr.refresh() });
    this._modalEdit = useDataSheetModalEditManager({ ..., refresh: () => this._refreshMgr.refresh() });
    this._excel = useDataSheetExcelManager({ ..., refresh: () => this._refreshMgr.refresh() });

    setupCanDeactivate(() => this.viewType() === "modal" || this.checkIgnoreChanges());
  }

  //-- D2: class 메서드 (~15줄)
  checkIgnoreChanges() { return this._refreshMgr.getDiffs().length === 0 || confirm(TXT_CHANGE_IGNORE_CONFIRM); }
  doRefresh() { if (busyCount() > 0) return; if (!canUse()) return; if (!checkIgnoreChanges()) return; mark(this.lastFilter); }
  doFilterSubmit() { this._filter.doFilterSubmit(); }

  //-- delegation methods (~25줄)
  async refresh() { await this._refreshMgr.refresh(); }
  async doAddItem() { await this._inlineEdit.doAddItem(); }
  async doSubmit(opt?) { await this._inlineEdit.doSubmit(opt); }
  doToggleDeleteItem(item) { this._inlineEdit.doToggleDeleteItem(item); }
  async doEditItem(item?) { await this._modalEdit.doEditItem(item); }
  async doToggleDeleteItems(del) { await this._modalEdit.doToggleDeleteItems(del); }
  doModalConfirm() { this._modalEdit.doModalConfirm(); }
  doModalCancel() { this._modalEdit.doModalCancel(); }
  async doDownloadExcel() { await this._excel.doDownloadExcel(); }
  async doUploadExcel() { await this._excel.doUploadExcel(); }

  //-- private (~10줄)
  private _getOrmDataEditToastErrorMessage(err) { ... }
}

### 대안 검토

1. **composable 대신 Mixin 패턴**: TypeScript mixin은 class 기반이며 signal composable 패턴과 불일치. 코드베이스에 mixin 사용례 없음. 기각.
2. **2개 composable만 추출 (filter + refresh)**: 상태 캡슐화 가치는 높으나, ~45줄만 감소하여 250줄 목표 미달성. 기각. [근거: wbs "5개 composable" 명시]
3. **composable에서 직접 optional 메서드 참조**: `super()` 시점에 subclass class field 미설정으로 런타임 오류 가능. lazy getter 패턴 채택. [근거: TypeScript class field 초기화 순서]
4. **AbsSdDataSheet에서 delegation 없이 직접 할당 (`this.doAddItem = this._inlineEdit.doAddItem`)**: 가능하나, 소비 프로젝트에서 메서드 오버라이드 불가. D2 결정(커스터마이징 가능성)과 불일치. 기각.
