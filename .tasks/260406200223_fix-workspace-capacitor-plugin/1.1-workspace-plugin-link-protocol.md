## 구현계획

### 배경

`capacitor.ts`의 `_setupNpmConf()`는 `.capacitor/package.json`을 구성한다. 현재 workspace:* 플러그인을 dependencies에서 제거하고, `_linkWorkspacePlugins()`로 수동 symlink를 생성한다. Capacitor CLI는 `package.json` dependencies에서 플러그인을 발견하므로 workspace 플러그인이 누락된다. [근거: 디버그 분석 H1 확정]

### 목표

- workspace:* 플러그인을 `link:` 프로토콜로 `.capacitor/package.json` dependencies에 추가 [근거: Rule "workspace:* 플러그인은 link: 프로토콜로 추가"]
- 중복된 `_linkWorkspacePlugins()` 메서드 및 관련 코드 제거 [근거: Rule "수동 symlink 생성 로직은 제거"]

### 비목표

- Capacitor CLI의 플러그인 발견 메커니즘 수정 [근거: WBS 경계]
- `cap sync`/`cap copy` 호출 로직 변경 [근거: WBS 경계]

### 설계

#### `_setupNpmConf()` 변경

workspace:* 플러그인 감지 시:
1. `createRequire()`로 플러그인의 실제 패키지 경로를 resolve
2. `path.relative(this._capPath, pluginDir)`로 상대경로 계산 (Windows `\` → `/` 변환)
3. `capNpmConf.dependencies[plugin] = "link:{상대경로}"` 설정
4. 반환 타입에서 `workspacePlugins` 제거 → `depChanged: boolean`만 반환

#### `_initCap()` 변경

- `workspacePlugins` 디스트럭처링 제거
- `_linkWorkspacePlugins()` 호출 2곳 제거

#### 삭제 항목

- `_linkWorkspacePlugins()` 메서드
- `import { symlink } from "fs/promises"`

### 대안 검토

- `capacitor.config.ts`의 `includePlugins` 사용: Capacitor 공식 메커니즘이나, 모든 플러그인을 명시해야 하는 부담. 원래 의도된 설계(`link:` 방식)를 완성하는 것이 더 자연스러움.

### Vertical Slicing

#### [x] Slice 1: _setupNpmConf()에서 workspace 플러그인을 link: 프로토콜로 추가 + 불필요한 코드 제거

- **구현 내용:** `_setupNpmConf()`의 workspace 분기를 `link:` 프로토콜로 변경. `_linkWorkspacePlugins()` 삭제. `_initCap()` 정리. `import { symlink }` 제거.
- **Scenarios:** workspace:* 플러그인이 link: 프로토콜로 등록된다, link: 경로는 상대경로이다, 일반 npm 플러그인은 버전 문자열로 등록된다, _linkWorkspacePlugins() 호출이 없다
