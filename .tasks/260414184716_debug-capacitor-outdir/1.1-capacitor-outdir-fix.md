## 구현계획

### 배경

`copyPublicFiles`/`watchPublicFiles` (`copy-public.ts`)는 출력 디렉토리를 `path.join(pkgDir, "dist")`로 하드코딩한다. `client.worker.ts`의 `build()` 함수는 `outdir` 변수를 올바르게 계산하지만(`info.outDir ?? path.join(info.pkgDir, "dist")`), `copyPublicFiles` 호출과 `writeConfigJson` 호출에서 이를 활용하지 않는다. [근거: debug.md 근본 원인 분석]

### 목표

- `copyPublicFiles`/`watchPublicFiles`가 `outDir` 매개변수를 지원한다 [근거: Rule "outDir 지정 시 해당 경로에 출력"]
- 기존 호출부(outDir 미지정)의 동작이 변경되지 않는다 [근거: Rule "outDir 미지정 시 기존 동작 유지"]

### 비목표

- server-build.worker.ts의 호출 변경 [근거: wbs 경계 "서버 빌드는 Capacitor 미사용"]
- dev watch 모드의 outDir 동적 지정 [근거: wbs 제외사항]

### 설계

**`copy-public.ts` 시그니처 변경:**
- `copyPublicFiles(pkgDir: string, includeDev: boolean, outDir?: string)` — `outDir ?? path.join(pkgDir, "dist")` 사용
- `watchPublicFiles(pkgDir: string, includeDev: boolean, outDir?: string)` — 동일 패턴. `distDir` 로컬 변수와 `onChange` 핸들러 내부의 `distDir` 참조 모두 적용
- `watchPublicFiles` 내부의 `copyPublicFiles` 호출에도 `outDir` 전달

**`client.worker.ts` `build()` 호출 수정:**
- line 102: `copyPublicFiles(info.pkgDir, false)` → `copyPublicFiles(info.pkgDir, false, outdir)`
- line 164: `writeConfigJson(path.join(info.pkgDir, "dist"), info.configs)` → `writeConfigJson(outdir, info.configs)`

### 대안 검토

- `copyPublicFiles`의 두 번째 매개변수를 options 객체로 변경하는 방안 — 기존 호출부 6곳 모두 수정 필요, 변경 범위 과대. 옵셔널 매개변수 추가가 최소 변경.
