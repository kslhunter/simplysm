## 구현계획

### 배경

Feature 1.1에서 `engine-watch-events.ts`의 `build` 이벤트 핸들러가 warnings를 ResultCollector에 저장하도록 구현되었다. 그러나 EsbuildClientEngine의 초기 빌드는 `build` 이벤트를 발행하지 않고 `worker.startWatch()` 반환값으로 결과를 전달하는 별도 경로를 사용한다. 이 경로에서 warnings가 누락되어 있다. [근거: 리뷰 LOGIC-001]

### 목표

- 초기 빌드의 warnings를 worker → engine → ResultCollector → printErrors() 경로로 전달한다 [근거: Rule "초기 빌드의 warnings는 startWatch 반환값에 포함"]
- 초기 빌드 성공이더라도 warnings가 있으면 ResultCollector에 저장한다 [근거: Rule "EsbuildClientEngine은 초기 빌드 결과의 warnings를 ResultCollector에 저장"]

### 비목표

- 후속 빌드의 warnings 전달 변경 [근거: wbs 경계 "Feature 1.1에서 이미 완료"]
- 프로덕션 빌드 경로 변경 [근거: wbs 경계 "이미 정상 전달"]

### 설계

| 파일 | 변경 | 근거 |
|------|------|------|
| `client.worker.ts:305-311` | `initialBuildResolve`에 `warnings` 필드 추가 (후속 빌드 line 295-298과 동일 패턴) | Rule: 초기 빌드 반환값에 warnings 포함 |
| `EsbuildClientEngine.ts:129-138` | 초기 빌드 결과에서 warnings 추출 → ResultCollector에 저장. 실패 시 기존 에러 저장에 warnings 추가, 성공+warnings 시 새 저장 추가 | Rule: ResultCollector에 warnings 저장 [D2] |

### 대안 검토

- **초기 빌드도 build 이벤트로 전달**: worker의 초기 빌드 완료 흐름을 변경하여 build 이벤트를 발행하면 setupWatchEvents가 자동 처리. 그러나 EsbuildClientEngine의 초기 빌드는 `startWatch()` 반환값으로 성공/실패를 판단하는 구조가 확립되어 있어, 이벤트 기반으로 변경하면 영향 범위가 크다. 기각.
