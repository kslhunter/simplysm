## 요구명세

### Rule / Example / Question

**Equivalence Partitioning** 적용 — 타입을 7개 파티션으로 분류:

#### Rule: I prefix 제거 (충돌 없음) [근거: CLAUDE.md "I/T prefix 사용하지 않는다"]

- Example: `ISdMenu` → `SdMenu`
- Example: `IAddress` → `Address`
- Example: `ISortingDef` → `SortingDef`

#### Rule: I prefix 제거 (충돌 — Def 접미사) [근거: CLAUDE.md "충돌 시 대상을 서술하고 Def 접미사"]

- Example: `ISdModal<O>` → `SdModalContentDef<O>` — SdModal 컴포넌트와 충돌
- Example: `ISdToast<O>` → `SdToastContentDef<O>` — SdToast 컴포넌트와 충돌
- Example: `ISdStatePreset` → `SdStatePresetDef` — SdStatePreset 컴포넌트와 충돌

#### Rule: T prefix 제거 [근거: CLAUDE.md "I/T prefix 사용하지 않는다"]

- Example: `TSdBusyType` → `SdBusyType`
- Example: `TBarcodeType` → `BarcodeType`
- Example: `TDirectiveInputSignals` → `DirectiveInputSignals`

#### Rule: Sd prefix 누락 교정 [근거: 설계 결정 D2]

- Example: `ISidebarUserMenu` → `SdSidebarUserMenu` — SdTopbarUserMenu와 일관성

#### Rule: 내부 전용 타입도 일관성 위해 변경 [근거: WBS 경계 "내부 전용 타입도 일관성을 위해 함께 변경"]

- Example: `IDaumPostcodeData` → `DaumPostcodeData`
- Example: `TSdModalExcludeKeys` → `SdModalExcludeKeys`

#### Rule: 파일명 변경 [근거: 설계 결정 D3]

- Example: `TDirectiveInputSignals.ts` → `directive-input-signals.ts`

#### Rule: 테스트 파일도 I/T prefix 제거 [근거: WBS "테스트 파일 업데이트" + "내부 전용 타입도 일관성을 위해 함께 변경"]

- Example: `ITestUser` → `TestUser`
- Example: `IItem` (spec 로컬) → `Item`

#### Rule: 기존 prefix 없는 타입은 대상 외 [근거: WBS 경계]

- Example: `SdItemOfTemplateContext` → 변경 없음
- Example: `SharedDataHandle` → 변경 없음

**Perspective-Based Reading** 적용:

- 테스터 관점: 76개 전체 rename 완료 여부 → typecheck + test로 검증
- 개발자 관점: 제네릭 제약/inter-type 참조 정확성 → typecheck로 검증
- 사용자 관점: 소비앱 없으므로 해당 없음

## 구현계획

### 배경

@simplysm/angular 패키지의 인터페이스/타입 76개가 I/T prefix 헝가리안 표기법을 사용 중이다. Feature 1.1~1.3에서 컴포넌트/디렉티브/추상 클래스의 네이밍이 표준화되었고, 이번 Feature에서 인터페이스/타입의 prefix를 제거한다. [근거: CLAUDE.md Naming Conventions]

타입 간 의존 관계가 존재한다: [근거: sd-modal.provider.ts, sd-toast.provider.ts, sd-modal-select-button.ts 코드 확인]
- `ISdModalInfo<T extends ISdModal<any>>` → `ISdModal` rename 시 제약 업데이트 필요
- `TSdSelectModalInfo<T extends ISdSelectModal<any>> = ISdModalInfo<...>` → 양쪽 모두 업데이트
- `ISdToastInput<T extends ISdToast<any>>` → `ISdToast` rename 시 제약 업데이트 필요
- `TSdToastTheme = ... | TSdToastSeverity | ...` → 상호 참조 업데이트
- `ISharedDataInfo<T extends ISharedDataBase<...>>` → 상호 참조 업데이트

### 목표

- 모든 인터페이스에서 I prefix 제거 (43개 exported + 8개 internal) [근거: Rule "I prefix 제거"]
- 모든 타입에서 T prefix 제거 (12개 exported + 3개 internal) [근거: Rule "T prefix 제거"]
- 충돌 3건에 Def 접미사 적용 [근거: Rule "충돌 — Def 접미사"]
- ISidebarUserMenu → SdSidebarUserMenu (Sd prefix 추가) [근거: 설계 결정 D2]
- TDirectiveInputSignals.ts → directive-input-signals.ts [근거: 설계 결정 D3]
- 테스트 파일 I/T prefix 제거 (15개) [근거: Rule "테스트 파일 I/T prefix 제거"]

### 비목표

- selector 변경 [근거: WBS 경계 "selector는 변경하지 않음"]
- Provider/Pipe/Plugin 클래스 rename [근거: WBS 제외 사항]
- 변수명/메서드명/프로퍼티명 변경 [근거: WBS 경계 "변수명, 메서드명, 프로퍼티명은 변경하지 않음"]
- 주석 외 문서 업데이트 [근거: WBS Feature 1.6에서 별도 수행]

### 설계

기계적 rename 작업. 각 타입에 대해: [근거: 모든 Rule 처리를 위해]

1. **선언부** — `interface`/`type` 키워드 뒤의 이름 변경
2. **동일 파일 참조** — extends, implements, 제네릭 제약, 타입 참조
3. **타 파일 import** — `import type { OldName }` → `import type { NewName }`
4. **타 파일 사용처** — 함수 파라미터, 변수 선언, 제네릭 인자
5. **index.ts** — export 심볼명 갱신
