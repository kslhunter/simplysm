## 구현계획

### 배경

`SdWorkerPathPlugin`은 esbuild 번들 과정에서 `import.meta.resolve("...worker")` 호출을 탐지하여, 워커 파일을 별도로 번들하고 호출을 경로 문자열로 치환한다. 현재 치환 결과가 상대 경로 문자열(`"./workers/name-hash.js"`)이어서, 런타임에 `SdWorker`가 `fileURLToPath()`를 호출할 때 `TypeError: Invalid URL`이 발생한다.

### 목표

- Plugin 치환 결과가 `import.meta.resolve()`와 동일한 계약(file:// URL)을 유지하도록 수정

### 비목표

- `SdWorker` 생성자 수정
- 클라이언트 측 이중 `new URL()` 래핑 최적화

### 설계

`SdWorkerPathPlugin.ts:56`의 반환값을 변경:

```typescript
// 변경 전
return `${quote}./workers/${outputFileName}${quote}`;

// 변경 후
return `new URL(${quote}./workers/${outputFileName}${quote}, import.meta.url).href`;
```

이로써 런타임에 `new URL("./workers/name-hash.js", import.meta.url).href`가 평가되어 `file:///absolute/path/dist/workers/name-hash.js` 형태의 file:// URL이 반환된다.

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| Plugin 치환을 `new URL(...).href`로 변경 | 채택 | 원래 계약 유지, 변경 최소 |
| SdWorker에서 입력 형식 자동 감지 | 미채택 | 증상 측 수정 (근본성 7/10) |
