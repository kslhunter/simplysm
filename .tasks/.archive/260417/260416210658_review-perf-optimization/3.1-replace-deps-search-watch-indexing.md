## 구현계획

### 배경

`replace-deps`는 개발 시점에 node_modules의 패키지를 로컬 소스로 교체하는 기능이다. `resolveAllReplaceDepEntries`가 교체 대상을 탐색하고, `watchReplaceDeps`가 소스 변경을 감시하여 대상에 복사한다. [근거: replace-deps.ts, replace-deps-resolve.ts]

### 목표

- `resolveAllReplaceDepEntries`의 중복 검사를 O(n)→O(1)로 전환 [근거: Rule "actualTargetPath 중복 검사"]
- `resolveAllReplaceDepEntries`의 glob 호출을 순차→병렬로 전환 [근거: Rule "glob 병렬화"]
- `watchReplaceDeps`의 onChange에서 전체 entries 순회→사전 필터링으로 전환 [근거: Rule "사전 필터링"]

### 비목표

- `setupReplaceDeps`의 복사 로직(copyWithUnlink)은 변경하지 않음 [근거: wbs 경계]
- `resolveReplaceDepEntries`의 정규식 매칭 로직은 변경하지 않음 [근거: wbs 경계]

### 설계

#### 1. Set 기반 중복 검사 (`replace-deps-resolve.ts`)

`resolveAllReplaceDepEntries` 함수 내에서 `entries.some()` 대신 `Set<string>`을 사용한다:

```typescript
// 기존
if (entries.some((e) => e.actualTargetPath === actualTargetPath)) continue;

// 변경
const seenTargetPaths = new Set<string>(); // while 루프 바깥에 선언
// ...
if (seenTargetPaths.has(actualTargetPath)) continue;
seenTargetPaths.add(actualTargetPath);
entries.push({ ... });
```

[근거: entries 배열이 누적될수록 `some()`은 O(n), Set.has()는 O(1)]

#### 2. glob 병렬화 (`replace-deps-resolve.ts`)

패턴별 순차 glob을 `Promise.all` + `map`으로 병렬 실행한다:

```typescript
// 기존
const targetNames: string[] = [];
for (const pattern of Object.keys(replaceDeps)) {
  const matches = await glob(pattern, { cwd: nodeModulesDir });
  targetNames.push(...matches.map((m) => m.replaceAll("\\", "/")));
}

// 변경
const globResults = await Promise.all(
  Object.keys(replaceDeps).map((pattern) =>
    glob(pattern, { cwd: nodeModulesDir }),
  ),
);
const targetNames = globResults.flatMap((matches) =>
  matches.map((m) => m.replaceAll("\\", "/")),
);
```

[근거: 각 glob은 독립적인 I/O 작업이므로 병렬 실행 가능. `Array.prototype.flatMap`은 Chrome 69+ API이지만 sd-cli는 Node.js 전용이므로 문제없음]

#### 3. onChange entries 사전 필터링 (`replace-deps.ts`)

watcher 생성 시 해당 `resolvedSourcePath`에 해당하는 entries를 미리 필터링하여 클로저에 캡처한다:

```typescript
// 기존: onChange 내부에서 전체 entries 순회
for (const e of entries) {
  if (e.resolvedSourcePath !== entry.resolvedSourcePath) continue;
  // ...
}

// 변경: watcher 생성 시점에 필터링
const sourceEntries = entries.filter(
  (e) => e.resolvedSourcePath === entry.resolvedSourcePath,
);
// onChange 내부에서는 sourceEntries만 순회
for (const e of sourceEntries) {
  // ... (resolvedSourcePath 비교 불필요)
}
```

[근거: watcher는 resolvedSourcePath별로 생성되므로, 해당 소스의 entries만 필요]

### 대안 검토

**Map 인덱싱 vs 필터링 캡처 (세부 기능 3)**
- Map 인덱싱 (`Map<resolvedSourcePath, ReplaceDepEntry[]>`): 중앙 집중식 인덱스. entries 변경 시 인덱스도 갱신 필요.
- 필터링 캡처: 단순 `Array.filter()`로 클로저에 캡처. entries는 `resolveAllReplaceDepEntries` 이후 불변이므로 캡처가 더 단순.
- **선택: 필터링 캡처** — entries가 불변이므로 Map 인덱스의 추가 복잡성이 불필요하다.

#### [x] Slice 1: Set 중복 검사 + glob 병렬화

- **구현 내용:** `resolveAllReplaceDepEntries`에 `Set<string>` 중복 검사를 도입하고, 패턴별 glob 호출을 `Promise.all`로 병렬화한다.

- **파일:** `packages/sd-cli/src/deps/replace-deps/replace-deps.ts`
- **Scenarios:** watcher가 해당 소스의 entries만 처리, 최적화 전후 결과 동일
