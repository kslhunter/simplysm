## 구현계획

### 배경

Angular 라이브러리 watch 모드에서 SCSS 관련 3개의 성능 병목이 존재한다:

1. `library-build.worker.ts`의 onChange에서 `combinedScssDeps` 전체 순회 (PERF-002) [근거: `library-build.worker.ts:269-276`]
2. `compileSideEffectScss`의 전체 재컴파일 (PERF-003) [근거: `ngtsc-build-core.ts:96-114`]
3. `writeEmitResults`의 레지스트리 O(n) 순회 삭제 (PERF-004) [근거: `ngtsc-build-core.ts:178-184`]

현재 구조:
- `combinedScssDeps`: `Map<소유파일, Set<의존성>>` — `library-build.worker.ts` 모듈 스코프
- `sideEffectScssRegistry`: `Map<scssAbsPath, SideEffectScssEntry>` — `SdTsCompiler` 인스턴스 필드
- `compileSideEffectScss`: stateless 함수 (ngtsc-build-core.ts)
- `writeEmitResults`: stateless 함수 (ngtsc-build-core.ts)

### 목표

- onChange SCSS 역방향 탐색을 O(1)로 전환 [근거: Rule "O(1)로 조회"]
- side-effect SCSS 재컴파일을 증분 방식으로 전환 [근거: Rule "영향받는 항목만 재컴파일"]
- writeEmitResults 레지스트리 삭제를 O(1)로 전환 [근거: Rule "역방향 인덱스로 O(1)"]

### 비목표

- sass 컴파일러 내부 성능 [근거: wbs 경계 "compileScssFile/compileScssString 자체의 성능은 다루지 않음"]
- client(Vite) 빌드의 SCSS 처리 [근거: wbs 경계 "client(Vite) 빌드의 SCSS 처리는 이 Feature에서 다루지 않음"]
- `compileGlobalScss` 최적화 [근거: wbs 경계 "단일 파일이므로 최적화 대상 아님"]

### 설계

#### 1. 역방향 SCSS 인덱스 (PERF-002)

**library-build.worker.ts** 모듈 스코프에 `reverseScssDeps: Map<string, Set<string>>` 추가.

`updateCombinedScssDeps`에서 정방향 맵 갱신과 동시에 역방향 맵 구축:

```typescript
let reverseScssDeps = new Map<string, Set<string>>();

function updateCombinedScssDeps(result: ISdTsCompilerResult): void {
  combinedScssDeps = new Map();
  reverseScssDeps = new Map();
  for (const [file, deps] of result.scssDependencies) {
    combinedScssDeps.set(file, new Set(deps));
    for (const dep of deps) {
      let owners = reverseScssDeps.get(dep);
      if (owners == null) {
        owners = new Set();
        reverseScssDeps.set(dep, owners);
      }
      owners.add(file);
    }
  }
}
```

`compileSideEffectScss` 호출 후 `combinedScssDeps`에 side-effect 의존성이 추가되므로, `buildWatchEvent` 종료 후 역방향 인덱스를 재구축한다. 헬퍼 함수 `rebuildReverseScssDeps()`를 분리하여 두 곳(updateCombinedScssDeps, buildWatchEvent 후)에서 호출. [근거: Rule "정방향 맵과 항상 동기화"]

onChange 핸들러에서 O(1) 조회:

```typescript
if (isAngular && (f.path.endsWith(".scss") || f.path.endsWith(".css"))) {
  const normalizedPath = pathx.posix(f.path);
  const owners = reverseScssDeps.get(normalizedPath);
  if (owners != null) {
    for (const owner of owners) {
      modifiedFiles.add(owner);
    }
  }
}
```

cleanup 함수에서 `reverseScssDeps = new Map()` 초기화 추가.

#### 2. compileSideEffectScss 증분 컴파일 (PERF-003)

**ngtsc-build-core.ts의 `compileSideEffectScss` 시그니처 변경:**

```typescript
export function compileSideEffectScss(
  registry: ReadonlyMap<string, SideEffectScssEntry>,
  loadPaths: string[],
  scssErrors: string[],
  scssDependencies: Map<string, Set<string>>,
  changedScssFiles?: ReadonlySet<string>,
  sideEffectScssDeps?: Map<string, Set<string>>,
): void
```

- `changedScssFiles`: 변경된 SCSS/CSS 파일 경로 Set. 미제공 시 전체 재컴파일 (초기 빌드 호환).
- `sideEffectScssDeps`: `Map<scssAbsPath, Set<depPath>>` — 이전 컴파일에서 기록된 각 side-effect SCSS의 의존성. 컴파일 후 in-place 갱신.

증분 판별 로직:

```typescript
for (const entry of registry.values()) {
  if (changedScssFiles != null && sideEffectScssDeps != null) {
    const isDirectHit = changedScssFiles.has(entry.scssAbsPath);
    const deps = sideEffectScssDeps.get(entry.scssAbsPath);
    const isDepsHit = deps != null && [...deps].some((d) => changedScssFiles.has(d));
    if (!isDirectHit && !isDepsHit) continue; // 영향 없음 → 건너뜀
  }
  // ... 기존 컴파일 로직 ...
  // 컴파일 후 의존성 기록
  if (sideEffectScssDeps != null) {
    sideEffectScssDeps.set(entry.scssAbsPath, new Set(result.dependencies));
  }
}
```

**library-build.worker.ts에서 호출부 수정:**

모듈 스코프에 `sideEffectScssDeps = new Map<string, Set<string>>()` 추가. cleanup에서 초기화.

`buildWatchEvent` 시그니처를 `hasScssChanges: boolean` → `changedScssFiles: ReadonlySet<string>` 로 변경.

onChange 핸들러에서:

```typescript
const changedScssFiles = new Set(
  changedFiles
    .filter((f) => f.path.endsWith(".scss") || f.path.endsWith(".css"))
    .map((f) => pathx.posix(f.path)),
);
const event = buildWatchEvent(info, result, changedScssFiles);
```

`buildWatchEvent` 내부에서 `changedScssFiles.size > 0` 일 때만 `compileSideEffectScss` 호출하고, `changedScssFiles`와 `sideEffectScssDeps`를 전달.

초기 빌드(`build` 함수)에서는 `changedScssFiles` 없이 호출하여 전체 컴파일 + `sideEffectScssDeps` 초기 구축.

#### 3. writeEmitResults 레지스트리 역방향 인덱스 (PERF-004)

**SideEffectScssOptions 확장:**

```typescript
export interface SideEffectScssOptions {
  loadPaths: string[];
  scssErrors: string[];
  scssDependencies: Map<string, Set<string>>;
  registry?: Map<string, SideEffectScssEntry>;
  registryReverseIndex?: Map<string, Set<string>>; // sourceFileName → Set<scssAbsPath(=registryKey)>
}
```

**writeEmitResults 내부 — 삭제 로직 교체:**

```typescript
// Before (O(n)):
for (const [key, entry] of scss.registry) {
  if (entry.sourceFileName === sourceFileName) {
    scss.registry.delete(key);
  }
}

// After (O(1)):
if (scss.registryReverseIndex != null) {
  const keys = scss.registryReverseIndex.get(sourceFileName);
  if (keys != null) {
    for (const key of keys) {
      scss.registry!.delete(key);
    }
    scss.registryReverseIndex.delete(sourceFileName);
  }
} else {
  // registryReverseIndex 미제공 시 기존 O(n) 폴백 (하위 호환)
  for (const [key, entry] of scss.registry) {
    if (entry.sourceFileName === sourceFileName) {
      scss.registry.delete(key);
    }
  }
}
```

**writeEmitResults 내부 — 등록 시 역방향 인덱스 갱신:**

```typescript
if (scss.registry != null) {
  scss.registry.set(scssAbsPath, { scssAbsPath, cssAbsPath, sourceFileName });
  // 역방향 인덱스 갱신
  if (scss.registryReverseIndex != null) {
    let keys = scss.registryReverseIndex.get(sourceFileName);
    if (keys == null) {
      keys = new Set();
      scss.registryReverseIndex.set(sourceFileName, keys);
    }
    keys.add(scssAbsPath);
  }
}
```

**library-build.worker.ts에서 전달:**

모듈 스코프에 `registryReverseIndex = new Map<string, Set<string>>()` 추가. cleanup에서 초기화.
`SideEffectScssOptions` 구성 시 `registryReverseIndex`를 포함하여 전달.

### 대안 검토

1. **역방향 인덱스를 SdTsCompiler 내부에서 관리** — `writeEmitResults`가 registry를 직접 조작(delete/set)하므로 SdTsCompiler가 변경을 감지할 수 없어 동기화 불가. 기각.
2. **compileSideEffectScss에서 combinedScssDeps의 역방향 인덱스를 활용하여 증분 판별** — `updateCombinedScssDeps`가 combinedScssDeps를 전체 교체하여 side-effect deps가 소실됨. 별도 `sideEffectScssDeps` 맵이 필요. 기각.
3. **Proxy/Observer 패턴으로 registry 변경 자동 추적** — 과도한 복잡성, 성능 오버헤드. 기각.
