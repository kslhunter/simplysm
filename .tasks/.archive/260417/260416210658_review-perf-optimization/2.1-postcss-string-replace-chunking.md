## 구현계획

### 배경

`esbuild-postcss-plugin.ts`의 JS 파일 처리 로직(라인 91-100)에서, ɵɵdefineComponent의 styles 배열 내 CSS 문자열을 PostCSS 처리 후 교체할 때 역순 `slice` + 연결을 반복한다. 교체 1회마다 전체 문자열이 복사되어 O(replacements × fileSize)의 메모리 비용이 발생한다. [근거: PERF-005]

### 목표

- 문자열 교체를 청크 배열 + `join('')` 방식으로 전환하여 문자열 복사를 1회로 감소 [근거: Rule "청크 배열 방식으로 문자열 교체"]
- 최종 산출물은 기존과 동일해야 함 [근거: Rule "PostCSS 처리 결과는 동일해야 함"]

### 비목표

- CSS 파일 처리 로직 변경 [근거: wbs 경계]
- PostCSS processor 자체의 성능 개선 [근거: wbs 경계]
- AST 파싱/수집 로직 변경 [근거: wbs 경계]

### 설계

`esbuild-postcss-plugin.ts:91-100`의 교체 로직만 변경:

**현재 (역순 slice 반복):**

```typescript
// packages/sd-cli/src/esbuild/esbuild-postcss-plugin.ts:91-100
let modified = code;
const sorted = replacements.sort((a, b) => b.start - a.start);
for (const rep of sorted) {
  const processed = await processor.process(rep.text, { from: file });
  const escaped = JSON.stringify(processed.css);
  modified = modified.slice(0, rep.start) + escaped + modified.slice(rep.end);
}
```

**변경 후 (정방향 청크 배열 + join):**

```typescript
const sorted = replacements.sort((a, b) => a.start - b.start);
const chunks: string[] = [];
let cursor = 0;
for (const rep of sorted) {
  chunks.push(code.slice(cursor, rep.start));
  const processed = await processor.process(rep.text, { from: file });
  chunks.push(JSON.stringify(processed.css));
  cursor = rep.end;
}
chunks.push(code.slice(cursor));
const modified = chunks.join("");
```

### 대안 검토

| 대안 | 설명 | 미선택 사유 |
|---|---|---|
| `MagicString` 라이브러리 사용 | source-map 지원 내장 라이브러리로 교체 처리 | 외부 의존성 추가 불필요. 소스맵이 필요 없는 상황이며 청크 방식으로 충분 |
| `Buffer` 기반 바이너리 연결 | Buffer.concat 으로 바이트 수준 결합 | 프로젝트 규칙상 Buffer 사용 금지. 문자열 join으로 충분한 성능 |
