## 구현계획

### 배경

현행 `transformWorkerPatterns(content, filePath, build)`는 `filePath` 확장자가 `/\.[cm]?ts$/`이면 **content 내용과 무관하게** `esbuild.transformSync(content, { loader: "ts" })`로 재변환한다 [근거: `esbuild-worker-plugin.ts:225-231`].

Angular 컴파일러 플러그인의 emit 후 처리 경로(`esbuild-angular-compiler-plugin.ts:341-343`)는 다음과 같이 호출한다:

```typescript
for (const { contents, sourceFileName } of compileResult.emitResults ?? []) {
  const normalized = path.normalize(sourceFileName);
  const workerResult = transformWorkerPatterns(contents, normalized, build);
```

여기서 `contents`는 ngtsc가 이미 JS로 방출한 결과이고(`SdTsCompiler.ts:608`) `sourceFileName`은 원본 `.ts` 경로이다. 결과적으로:
1. 이미 JS인 `contents`를 TS 로더로 재파싱하는 불필요한 `transformSync`가 매 emit 파일마다 발생 (Angular 프로젝트에서 수백 번 누적)
2. 일부 JS 문법이 TS 파서 엄격성과 충돌하면 `errors`를 반환하고 이를 빌드에 전파 — 조용한 빌드 실패 회귀 위험
3. 이미 ngtsc가 처리한 decorator/enum 등이 재변환될 위험

또한 현재 사전 필터 `content.includes("Worker")`는 식별자·타입 용도의 `Worker`를 가진 TS 파일(`const w: Worker`, `import type { Worker }` 등)도 전부 통과시켜 `transformSync` 오버헤드를 발생시킨다.

### 목표

- Angular 컴파일러 플러그인 경로(`:343`)에서 emit 결과 JS를 TS 로더로 재변환하지 않는다 [근거: Rule "skipTsTransform 옵션이 true이면 TS 확장자여도 transformSync를 호출하지 않는다"]
- `transformWorkerPatterns`의 기존 시그니처·기본 동작을 깨지 않는다 (후방 호환) [근거: Rule "skipTsTransform이 생략·false이면 기존 동작을 유지한다"]
- 식별자·타입 용도의 `Worker` 키워드만 존재하는 파일은 `transformSync`를 호출하지 않는다 [근거: Rule "사전 필터는 Worker·SharedWorker·import.meta.resolve의 단어 경계 호출만 통과시킨다"]
- `findWorkerPatterns`를 외부에서 직접 호출할 때 오용을 예방하는 JSDoc 컨벤션을 제공한다 [근거: Rule "findWorkerPatterns JSDoc은 JS 전제 호출 컨벤션을 명시한다"]
- 기존 58건 테스트 전부 통과 [근거: Rule "기존 58건 테스트 동작을 모두 유지한다"]

### 설계

**A. `transformWorkerPatterns` 시그니처 확장 및 분기** (`packages/sd-cli/src/esbuild/esbuild-worker-plugin.ts:209`)

```typescript
export interface TransformWorkerOptions {
  /**
   * true이면 .ts/.cts/.mts 확장자여도 esbuild.transformSync(loader: "ts")를 스킵한다.
   * 호출자가 content가 이미 JS임을 보장하는 경우에만 사용한다 (예: ngtsc emit 결과).
   */
  skipTsTransform?: boolean;
}

export function transformWorkerPatterns(
  content: string,
  filePath: string,
  build: esbuild.PluginBuild,
  options?: TransformWorkerOptions,
): TransformWorkerResult | undefined {
  // 빠른 사전 필터 — 단어 경계 기반 (LOGIC-003 A안, D2)
  if (!/\b(new\s+Worker|new\s+SharedWorker|import\.meta\.resolve)\b/.test(content)) {
    return undefined;
  }

  const errors: esbuild.PartialMessage[] = [];
  const warnings: esbuild.PartialMessage[] = [];

  // TS → JS 변환 (skipTsTransform이 true이면 스킵, D1)
  let effectiveContent = content;
  if (options?.skipTsTransform !== true && /\.[cm]?ts$/.test(filePath)) {
    try {
      const transformed = build.esbuild.transformSync(content, {
        loader: "ts",
        sourcemap: false,
      });
      effectiveContent = transformed.code;
      warnings.push(...transformed.warnings);
    } catch (e) {
      const failure = e as {
        errors?: esbuild.PartialMessage[];
        warnings?: esbuild.PartialMessage[];
      };
      return {
        contents: content,
        errors: failure.errors ?? [
          { text: `TS transform failed: ${String(e)}`, location: null },
        ],
        warnings: failure.warnings ?? [],
      };
    }
  }

  // 이후 findWorkerPatterns + processWorkerBundle + chunks 조립은 기존과 동일
  // (effectiveContent 사용)
}
```

`TransformWorkerOptions` 인터페이스를 `TransformWorkerResult` 바로 아래에 정의한다 [근거: D1, D6].

- `import\.meta\.resolve`: 점 이스케이프로 정확한 메서드 호출 매치

   - `skipTsTransform: true` + `.ts` 경로 + 실제 TS 구문(`import type`) + Worker 패턴 → `transformSync` 호출 없음, undefined 반환 (acorn 파싱 실패 → 빈 matches, 계약 위반 시 기존 동작)
   - 옵션 생략(`undefined`) + `.ts` + `import type` + Worker 패턴 → 정상 감지 (기존 동작)
   - `skipTsTransform: false` + `.ts` + `import type` + Worker 패턴 → 정상 감지
   - `{}` (빈 객체) + `.ts` + `import type` + Worker 패턴 → 정상 감지 (skipTsTransform undefined → falsy)

2. `describe("transformWorkerPatterns — 사전 필터 정규식 경계", ...)`
   - `const x: Worker = 1;` (타입 어노테이션만) → undefined, `transformSync` 미호출
   - `interface WorkerLike { ... }` (interface 선언만) → undefined
   - `import type { Worker } from "./types";` (import type만) → undefined
   - `// new Worker(...)` (주석 내) → 사전 필터 통과하지만 AST가 차단 → undefined
   - `const w = new Worker(new URL("./worker.js", import.meta.url));` → 정상 감지
   - `const sw = new SharedWorker(new URL("./sw.js", import.meta.url));` → 정상 감지
   - `const p = import.meta.resolve("./node-worker.js");` + platform "node" → 정상 감지

### 대안 검토

| 대안 | 불채택 사유 |
|------|-------------|
| LOGIC-001 B안: Angular 플러그인에서 `normalized`의 확장자를 `.js`로 바꿔 전달 | 가장 작은 변경이지만 호출자 의도가 파일 경로 조작으로 숨어 오해 유발. `.ts` 경로가 다른 용도로 사용될 때 깨질 위험 |
| LOGIC-001 C안: content에 TS 고유 구문(`import type`, 타입 어노테이션) 패턴 포함 여부로 분기 | 정규식 기반 heuristic이므로 오탐 위험. 주석·문자열 내부에서 반드시 깨짐 |
| 사전 필터를 더 엄격히 (주석/문자열까지 제거 후 매칭) | 정확성은 이미 AST가 담당. 사전 필터의 목적은 `transformSync` 호출 최소화일 뿐 과도한 비용은 의미 없음 |
| `TransformWorkerOptions`를 별도 파일로 분리 | 단일 `boolean` 옵션 하나뿐이라 과도한 파일 분할 |
| JSDoc에 `@throws` 등 다른 태그 추가 | DOC-001의 사용자 결정(A안)은 "한 줄 추가" 수준. 과범위 변경 금지 |
