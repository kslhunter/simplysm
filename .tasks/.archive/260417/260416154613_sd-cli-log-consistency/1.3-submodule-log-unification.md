## 구현계획

### 배경
sd-cli 하위 모듈 5개 파일에서 severity 혼용과 에러 포맷 불일치가 발견되었다. 공개 메서드 단위로 start/success 패턴을 도입하고, 내부 세부 단계는 debug로 유지하며, 에러 포맷을 인라인 보간으로 통일한다.

### 목표
- lint-core.ts 세부 단계를 debug로 내리고 전체 완료를 success로 통일 [근거: D1]
- electron.ts/capacitor.ts 공개 메서드에 start/success 패턴 도입 [근거: wbs]
- electron.ts 번들링 실패 로그를 error로 변경 [근거: D2]
- 에러 메시지 포맷을 인라인 보간으로 통일 [근거: D4]

### 비목표
- 상위 호출자(device.ts, BuildOrchestrator.ts)와의 start/success 중복 조정 [근거: wbs 경계 "Feature 1.2에서 처리"]
- capacitor 하위 유틸 모듈 수정 [근거: wbs 경계 "debug만 사용하므로 수정 불필요"]
- 로그 메시지 내용 변경 [근거: wbs 제외사항]

### 설계

**1. lint-core.ts severity 변경** [근거: D1]
- 세부 단계 `start()`/`success()` (133,136,139,148,154,160행) → `debug()`로 변경
- 전체 완료 `info("린트 완료", ...)` (183행) → `success("린트 완료", ...)`로 변경
- `error("린트 에러 발생", ...)` (181행) → 유지 (에러는 error로 적절)

**2. electron.ts 공개 메서드 start/success** [근거: wbs]
- `debug("initialize 시작"/"완료")` (63,86행) → `start("initialize 중...")`/`success("initialize 완료")`
- `debug("run 시작"/"완료")` (90,184행) → `start("run 중...")`/`success("run 완료")`
- `debug("build 시작"/"완료")` (188,208행) → `start("build 중...")`/`success("build 완료")`
- `warn("번들링 실패...")` (129행) → `error("번들링 실패...")` [근거: D2]
- `info("종료"/"재시작")` (114,145행) → 유지 [근거: D3]

**3. capacitor.ts 공개 메서드 start/success** [근거: wbs]
- `debug("initialize 시작"/"완료")` (98,155행) → `start("initialize 중...")`/`success("initialize 완료")`
- `run()` 메서드 진입/완료에 `start("run 중...")`/`success("run 완료")` 추가
- `debug("build 시작"/"완료")` (339,383행) → `start("build 중...")`/`success("build 완료")`
- warn 3곳(241,295,363행) → 유지

**4. rebuild-manager.ts 에러 포맷 통일** [근거: D4]
- `this._logger.error("리빌드 에러 발생", { error: String(result.reason) })` (66행)
  → `this._logger.error(`리빌드 에러 발생: ${String(result.reason)}`)`

**5. replace-deps.ts** [근거: 코드 확인]
- 에러 포맷은 이미 인라인 보간 사용 중 → 변경 불필요

### 대안 검토
- 구조화 객체 포맷 통일(D4-B): CLI 도구 특성상 터미널 가독성이 우선이므로 채택하지 않음
- lint-core.ts 세부 success 유지(D1-B): Electron/Capacitor 규칙과 불일치하므로 채택하지 않음
