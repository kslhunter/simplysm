#### severity 선택 기준 (D2)

이 기준은 Feature 1.2, 1.3에서도 동일하게 적용한다.

| Severity | 용도 | 예시 |
|----------|------|------|
| `debug` | 내부 동작 상세. `--debug` 시에만 표시 | 파일 경로 해석, 설정 로드 상세 |
| `start` | 사용자 인지가 필요한 장시간 작업 시작 (spinner) | 빌드 시작, 배포 시작 |
| `success` | `start`와 쌍. 해당 작업 성공 완료 | 빌드 완료, 배포 완료 |
| `info` | 사용자에게 전달할 일반 정보 | 서버 URL, DRY-RUN 메시지, 상태 |
| `warn` | 비치명적 문제. 작업은 계속 진행 | 설정 실패(fallback 가능), 사전 조건 경고 |
| `error` | 치명적 에러. 작업 실패/중단 | 빌드 실패, 필수 파일 누락 |

**폐기:** `fail` → `error`로 통일 (Feature 1.2에서 적용)

## 구현계획

### 배경

sd-cli의 로그 출력에서 `consola` 직접 사용(태그 없음), `console.warn` 사용, 수동 `[sd-cli]` prefix, 영어 에러 메시지 등 비일관성이 존재한다. CLI 진입점(`sd-cli.ts`, `sd-cli-entry.ts`)과 공통 유틸리티(`output-utils.ts`, `worker-utils.ts`)를 `consola.withTag` 패턴으로 통일한다. [근거: wbs "비일관성 #1, #7"]

### 목표

- 모든 대상 파일의 로그 출력을 `consola.withTag` 패턴으로 통일 [근거: Rule "모든 로그 출력은 consola.withTag를 통해야 한다"]
- 수동 `[sd-cli]` prefix 제거 [근거: Rule "수동 prefix는 태그로 대체"]
- `console.warn` → `consola` 전환 [근거: Rule "console.* 직접 사용 금지"]
- 영어 에러 메시지 → 한국어 전환 [근거: Rule "에러 메시지는 한국어로 작성"]
- severity 선택 기준 확립 [근거: wbs 경계 "severity 선택 기준의 정의는 이 Feature에서 확립"]

### 비목표

- output-utils.ts 호출자(WatchOrchestrator, DevOrchestrator) 수정 [근거: wbs 경계 "호출자 수정은 Feature 1.2에서 수행"]
- severity 변경 — 기존 severity 유지, 채널만 전환 [근거: wbs 범위]
- 로그 메시지 내용 변경 (영어→한국어 전환 대상 제외) [근거: wbs 제외사항]

#### 테스트 영향

**`tests/utils/output-utils.spec.ts`:**

`consola.withTag`가 모듈 로드 시 실행되므로, 기존 `vi.spyOn(consola, "error")` 방식으로는 태그 로거의 호출을 캡처할 수 없다. `consola.withTag`가 `consola` 자체를 반환하도록 mock하여 기존 스파이가 작동하도록 한다:

```typescript
// 추가 (vi.mock은 hoisting되므로 import보다 먼저 실행됨)
vi.mock("consola", async (importOriginal) => {
  const mod = await importOriginal<typeof import("consola")>();
  const orig = mod.consola;
  orig.withTag = (() => orig) as typeof orig.withTag;
  return { consola: orig };
});
```

기존 `vi.spyOn(consola, "error/warn/info")` 및 모든 테스트 케이스는 변경 없이 동작한다.

**`tests/utils/worker-utils.spec.ts`:**

에러 메시지 매칭 문자열을 한국어로 변경:

```typescript
// Before: expect(() => guard()).toThrow("startWatch can only be called once per Worker");
// After:  expect(() => guard()).toThrow("Worker당 한 번만 호출할 수 있습니다: startWatch");
```

### 대안 검토

**output-utils.ts 로거 파라미터 방식:**
- 각 함수에 `logger: ConsolaInstance` 파라미터 추가
- 장점: 호출자의 태그가 로그에 표시되어 출처 추적이 더 정확
- 단점: 함수 시그니처 변경 → 모든 호출자 수정 필요 (Feature 1.2 부담 증가), 코드베이스 지배적 패턴과 불일치
- 선택하지 않은 이유: printDiagnostics/printServers는 여러 패키지의 집계 결과를 출력하는 범용 함수이므로 특정 호출자의 태그를 상속할 이유 없음. 메시지 자체에 패키지명/타겟 정보가 이미 포함됨
