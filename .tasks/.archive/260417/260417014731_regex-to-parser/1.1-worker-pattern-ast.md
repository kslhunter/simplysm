## 구현계획

### 배경

`esbuild-worker-plugin.ts`는 JS/TS 소스 코드에서 Worker 생성 패턴을 감지하여 Worker 파일을 별도 ESM 번들로 빌드하고, 원본 코드의 URL 경로를 번들된 파일 경로로 치환한다. 현재 정규식(`WORKER_PATTERN`, `NODE_WORKER_PATTERN`)으로 패턴을 매칭하는데, 주석/문자열 내 오탐 및 여러 줄 코드 누락의 위험이 있다. [근거: wbs 건 1 근거]

같은 패키지의 `esbuild-postcss-plugin.ts`에서 이미 `acorn` + `acorn-walk`를 사용하여 AST 파싱 → 위치 기반 문자열 치환 패턴을 구현하고 있다. [근거: `esbuild-postcss-plugin.ts:52-103`]

### 목표

- 정규식 `WORKER_PATTERN`, `NODE_WORKER_PATTERN`을 acorn AST 기반 탐지로 교체 [근거: Rule "브라우저 Worker 패턴을 AST로 정확히 탐지"]
- 주석, 문자열 리터럴 내 오탐을 구조적으로 제거 [근거: Rule "주석 내 Worker 패턴은 무시"]

### 비목표

- `bundleWorker()`, `processWorkerBundle()`, `createWorkerBundlePlugin()` 변경 [근거: wbs 경계]
- 출력 파일명 매칭 정규식, 파일 확장자 판별 정규식 변경 [근거: wbs 경계]

### 설계

**AST 탐지 함수**: `findWorkerPatterns(content: string)` — acorn으로 소스를 파싱하고 walk.simple로 AST를 순회하여 Worker 패턴을 수집한다. 파싱 실패 시 빈 배열을 반환한다.

반환 타입:
```typescript
interface WorkerMatch {
  type: "browser" | "node";
  /** 전체 표현식의 start/end (치환 범위) */
  start: number;
  end: number;
  /** Worker/SharedWorker 이름 (browser만) */
  workerType?: string;
  /** URL 경로 문자열 값 */
  urlPath: string;
  /** 옵션 객체의 원본 소스 텍스트 (browser만, 없으면 undefined) */
  existingOpts?: string;
}
```

**브라우저 Worker AST 매칭 조건** (`NewExpression` 노드):
1. `callee`가 `Worker` 또는 `SharedWorker` `Identifier`
2. 첫 번째 인자가 `NewExpression`: `callee`가 `URL` `Identifier`
3. URL의 첫 번째 인자가 `Literal` (문자열 — 경로)
4. URL의 두 번째 인자가 `MemberExpression`: `import.meta.url`
5. Worker의 두 번째 인자(선택): 존재하면 `content.slice(arg.start, arg.end)`로 원본 보존

**Node.js import.meta.resolve AST 매칭 조건** (`CallExpression` 노드):
1. `callee`가 `MemberExpression`: object가 `MetaProperty`(import.meta), property가 `resolve` `Identifier`
2. 첫 번째 인자가 `Literal` (문자열)
3. 값이 `./` 또는 `../`로 시작

**치환 방식**: 정방향 chunks 패턴 (`esbuild-postcss-plugin.ts` 동일). 매치를 start 오름차순 정렬 → cursor로 순회하며 chunks 배열 조립.

**`transformWorkerPatterns` 변경**:
- 사전 필터(`content.includes("Worker")`, `content.includes("import.meta.resolve")`)는 유지
- 사전 필터 통과 시 `findWorkerPatterns(content)` 호출
- 빈 배열이면 undefined 반환
- 각 매치에 대해 `processWorkerBundle()` 호출 → 치환 텍스트 생성 → chunks 조립

### 대안 검토

| 대안 | 불채택 사유 |
|------|-----------|
| `es-module-lexer` | import/export만 분석 가능, Worker `new` 표현식은 탐지 불가 |
| 정규식 개선 (멀티라인 등) | 주석/문자열 오탐 문제를 근본적으로 해결 불가 |
| TypeScript compiler API | JS 파일도 대상이며 과도하게 무거움 |
