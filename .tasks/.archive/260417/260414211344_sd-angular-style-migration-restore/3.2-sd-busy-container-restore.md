## 구현계획

### 배경

`sd-busy-container`는 비동기 작업 중 UI를 오버레이로 가리는 컴포넌트로, spinner/bar/cube 3가지 타입을 지원한다.
v14에서 마이그레이션하면서 템플릿 구조(조건부 렌더링 방식), 각 타입별 CSS 애니메이션, progress/message 레이아웃이 v12와 다르게 변경되었다. [근거: v12/v14 코드 비교]

### 목표

- v12의 시각적·기능적 동작을 100% 복원한다 [근거: WBS Goal]
- 3가지 타입(spinner, bar, cube)의 CSS 애니메이션과 레이아웃을 v12 기준으로 복원한다 [근거: Rule별 상세 사양]
- Screen 표시 방식을 `@if` 조건부 렌더링에서 CSS visibility/opacity transition으로 전환한다 [근거: Rule "Screen은 항상 DOM에 존재"]

### 비목표

- v14 API 패턴(signal, booleanAttribute, computed, addEventListener keydown capture) 변경 [근거: WBS 경계]
- `data-sd-busy` 속성의 `|| undefined` 패턴 변경 [근거: WBS 경계 "v14 개선이므로 유지"]
- SCSS 경로 변경 [근거: WBS 경계]
- z-index 방식 변경 (v14의 `map.get(variables.$vars, ...)` 유지) [근거: v14 SCSS 패턴]

### 설계

#### 템플릿 변경

- `@if (busy())` 래퍼 제거 → `_screen`을 항상 렌더링
- `_progress`를 `_rect` 내부에서 `_screen` 직접 자식으로 이동
- `_progress-bar`의 `[style.width.%]` → `[style.transform]="'scaleX(' + progressPercent()! / 100 + ')'"` 변경
- `_message` 내부에 `<pre>` 태그 래핑 추가
- spinner: 기존 `._spinner` div 유지 (CSS로 스타일링)
- bar: 기존 `._bar` div 유지 (CSS ::before/::after로 스타일링)
- cube: `._cube > ._cube-face-*` → `._cube1`, `._cube2`, `._cube4`, `._cube3` 클래스 (v12 순서: 1,2,4,3)

[근거: v12 template :24-48, v14 template 비교]

#### CSS 변경

**Host:**
- `overflow: auto` 추가
- `top: 0; left: 0` 추가

**Screen:**
- `right: 0; bottom: 0` → `width: 100%; height: 100%`
- `background: var(--busy-overlay-bg)` 제거 [근거: D2]
- `display: flex; align-items: center; justify-content: center` 제거
- `visibility: hidden; pointer-events: none; opacity: 0; transition: opacity var(--animation-duration); transition-timing-function: linear` 추가
- `[data-sd-busy="true"] > ._screen` 셀렉터에 `visibility: visible; pointer-events: auto; opacity: 1` 추가

**Spinner 타입:** `&[data-sd-type="spinner"]` 블록 전체를 v12 스타일로 교체
- `_rect`: `translateY(-100%)` 슬라이드인 transition
- `_indicator`: 30x30px, 6px border, box-shadow, border-bottom-color primary
- `_indicator > div`: `display: none` (자식 숨김)
- `_message`: absolute 위치, background-color 색상, text-shadow
- `[data-sd-busy="true"]` 상태: `transform: none; transition: 0.1s ease-out`

**Bar 타입:** `&[data-sd-type="bar"]` 블록 전체를 v12 스타일로 교체
- `min-height: 4px`
- `_indicator`: absolute 위치, 4px height, ::before/::after scaleX 애니메이션
- `_indicator > div`: `display: none`
- `_message`: absolute, top: 4px, right: 0

**Cube 타입:** `&[data-sd-type="cube"]` 블록 전체를 v12 스타일로 교체
- `_indicator`: absolute 중앙, 40x40px, rotateZ(45deg)
- `_cube1~4`: float:left, 50%, ::before로 perspective 3D 플립
- `_message`: absolute, top: 4px, right: 0

**Progress:**
- `_screen > ._progress` (직접 자식): absolute top:0, height: 4px, width: 100%
- `_progress-bar`: scaleX transform, transform-origin: left

**Keyframes:**
- `sd-busy-spin`: 유지 (from rotate(0deg) to rotate(360deg)으로 v12 형식 복원)
- `sd-busy-bar-indicator-before/after`: v12 scaleX 애니메이션 추가
- `sd-busy-cube`: v12 perspective rotateX/Y 3D 플립 추가
- v14의 `sd-busy-bar`, `sd-busy-cube-rotate`, `sd-busy-cube-fold` 제거

**`_rect` 공통 스타일 제거:**
- v14의 `_rect > _indicator/message/progress` flex 레이아웃 제거 (각 타입이 자체 레이아웃 사용)

[근거: v12 CSS :55-351, v14 CSS 비교]

#### 기존 테스트 영향

기존 테스트(`busy-container.spec.ts`)에서 변경이 필요한 항목:
- `busy=false → ._indicator가 null` 테스트: screen이 항상 렌더링되므로 `_indicator`도 존재할 수 있음 → busy 속성 기반으로 검증 방식 변경 필요
- `progressPercent → style.width` 테스트: `scaleX` transform 방식으로 변경
- `._cube > ._cube-face` 셀렉터: `._cube1~4` 셀렉터로 변경
- `._screen` 배경색 CSS 변수 테스트: 배경색 제거에 따라 제거 또는 수정 필요

### 대안 검토

**`@if` 유지 + CSS animation으로 페이드 구현:**
- Angular `@if`와 CSS `@starting-style` / animation을 결합하여 페이드 효과 구현 가능
- 그러나 v12의 동작은 명확히 "항상 DOM에 존재 + visibility/opacity 토글"이므로, v12 복원이라는 목표에 맞지 않음
- Chrome 61 호환성: `@starting-style`은 Chrome 117+에서 지원하므로 사용 불가
