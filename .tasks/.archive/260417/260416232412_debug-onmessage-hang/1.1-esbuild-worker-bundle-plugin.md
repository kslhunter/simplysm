## 구현계획

### 배경

현재 Worker 감지는 TypeScript AST transformer(`web-worker-transformer.ts`)를 통해 `.ts` 파일에서만 동작한다. 이 방식은 `dist/.js` 파일(node_modules에서 참조되는 컴파일된 패키지)의 Worker 패턴을 감지하지 못한다. [근거: wbs "현재 TypeScript transformer는 .ts AST에서만 동작"]

esbuild onLoad 단계에서 정규식 기반으로 `.js`/`.ts` 파일 모두를 검사하는 범용 플러그인이 필요하다. [근거: wbs "esbuild onLoad에서 .js/.ts 파일 내용을 검사"]

### 목표

- `new Worker(new URL("path", import.meta.url))` / `new SharedWorker(...)` 패턴을 `.js`/`.ts` 파일에서 정규식으로 감지 [근거: Rule "Worker/SharedWorker + new URL + import.meta.url 패턴만 감지"]
- 감지된 Worker 파일을 `esbuild.buildSync()`로 별도 ESM 번들 빌드 [근거: Rule "Worker 파일은 별도 ESM 번들로 빌드"]
- 원본 코드의 URL 경로를 번들된 파일 경로로 치환 [근거: Rule "번들된 경로로 원본 코드의 URL 치환"]
- `{ type: "module" }` 옵션이 없으면 자동 추가 [근거: Rule "Worker 옵션에 type: module 보장"]
- esbuild 플러그인 + transform 함수 모두 export [근거: D2]

### 비목표

- Angular/서버 특화 로직 포함 [근거: wbs 경계 "범용 esbuild 플러그인"]
- Worker 내부 런타임 에러 처리 [근거: wbs 경계 "이미 수정 적용됨"]
- 기존 TS transformer / bundleWebWorker 원본 제거 [근거: Feature 1.2 범위]

#### 패턴 감지 정규식

```typescript
const WORKER_PATTERN = /\bnew\s+(Worker|SharedWorker)\s*\(\s*new\s+URL\s*\(\s*["']([^"']+)["']\s*,\s*import\.meta\.url\s*\)\s*(?:,\s*(\{[^}]*\}))?\s*\)/g;
```

캡처 그룹:
- Group 1: `Worker` 또는 `SharedWorker`
- Group 2: URL 경로 (예: `"./worker.ts"`)
- Group 3: 옵션 객체 (예: `{ type: "module" }`) — 없으면 undefined

빠른 사전 필터: `content.includes("Worker")`가 false면 즉시 `undefined` 반환 [근거: web-worker-transformer.ts:111 동일 최적화]

#### Worker 번들 빌드

기존 `bundleWebWorker` 로직을 재사용한다 (`esbuild-angular-compiler-plugin.ts:167-197`). 변경점:

```typescript
function bundleWebWorker(
  build: esbuild.PluginBuild,
  workerFile: string,
): esbuild.BuildResult {
  const sourcemap = build.initialOptions.sourcemap != null && build.initialOptions.sourcemap !== false;
  const write = build.initialOptions.write !== false; // D1: 메인 빌드와 동일

  return build.esbuild.buildSync({
    ...build.initialOptions,
    platform: "browser",
    write,              // D1: 메인 빌드의 write 옵션 계승
    bundle: true,
    metafile: true,
    format: "esm",
    entryNames: "worker-[hash]",
    entryPoints: [workerFile],
    sourcemap,
    supported: undefined,
    plugins: undefined,
  });
}
```

[근거: D1 — esbuild 위임, `esbuild-angular-compiler-plugin.ts:173-186` 기존 로직]

#### URL 치환 + type: "module"

`content.replace(WORKER_PATTERN, ...)` 콜백에서:
1. Group 2(경로)를 resolve하여 Worker 번들 빌드
2. 번들 출력 파일 중 `worker-[HASH].js` 찾기
3. outdir 기준 상대경로 계산
4. Group 3(옵션)이 없으면 `, { type: "module" }` 추가

[근거: `esbuild-angular-compiler-plugin.ts:349-359` 경로 계산, `web-worker-transformer.ts:93-100` type: module 추가]

#### 플러그인 구조

```typescript
export function createWorkerBundlePlugin(): esbuild.Plugin {
  return {
    name: "sd-worker-bundle",
    setup(build) {
      const pendingWorkerResults: Array<{
        outputFiles?: esbuild.OutputFile[];
        metafile?: esbuild.Metafile;
      }> = [];

      build.onLoad({ filter: /\.[cm]?[jt]sx?$/ }, (args) => {
        const content = fs.readFileSync(args.path, "utf-8");
        const result = transformWorkerPatterns(content, args.path, build);
        if (result == null) return undefined;

        // write: false일 때 Worker outputFiles를 모아뒀다가 onEnd에서 병합
        if (result.workerOutputFiles != null) {
          pendingWorkerResults.push({
            outputFiles: result.workerOutputFiles,
            metafile: result.workerMetafile,
          });
        }

        return {
          contents: result.contents,
          loader: /\.[cm]?tsx?$/.test(args.path) ? "ts" : "js",
          errors: result.errors.length > 0 ? result.errors : undefined,
          warnings: result.warnings.length > 0 ? result.warnings : undefined,
        };
      });

      build.onEnd((result) => {
        // write: false일 때만 outputFiles/metafile 병합
        for (const wr of pendingWorkerResults) {
          if (wr.outputFiles != null) {
            result.outputFiles?.push(...wr.outputFiles);
          }
          if (result.metafile != null && wr.metafile != null) {
            Object.assign(result.metafile.inputs, wr.metafile.inputs);
            Object.assign(result.metafile.outputs, wr.metafile.outputs);
          }
        }
        pendingWorkerResults.length = 0;
      });
    },
  };
}
```

#### Angular 클라이언트 빌드에서의 동작

- `.ts` 파일: Angular 컴파일러 플러그인의 onLoad가 먼저 처리하여 컴파일된 JS를 반환. Worker 플러그인의 onLoad는 실행되지 않음. → Feature 1.2에서 Angular 플러그인 내부에서 `transformWorkerPatterns()`를 호출하여 처리.
- `.js` 파일: Angular 플러그인이 `undefined`를 반환하여 통과. Worker 플러그인의 onLoad가 실행됨.

#### 서버 빌드에서의 동작

Angular 컴파일러 플러그인이 없으므로 `.ts`/`.js` 파일 모두 Worker 플러그인의 onLoad가 처리함.

### 대안 검토

| 접근 방식 | 장점 | 단점 | 선택하지 않은 이유 |
|-----------|------|------|-------------------|
| TypeScript AST transformer (현재 방식) | 정확한 AST 파싱 | `.js` 파일 미처리 | 근본 원인 — dist/.js 참조 시 동작 안 함 |
| onEnd 단계에서 출력 파일 후처리 | esbuild 번들링 후 작업 | `new URL()` 패턴이 이미 esbuild에 의해 처리됨 | esbuild가 URL을 asset reference로 처리하여 Worker 파일을 복사(번들 아님)해버림 |
| onResolve로 URL 가로채기 | esbuild resolve 파이프라인 활용 | esbuild의 `new URL()` 처리는 플러그인 파이프라인을 거치지 않음 | 기술적 불가 |
