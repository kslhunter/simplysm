# Feature 1.2 클라이언트 빌드에 플러그인 적용 및 기존 TS transformer 제거

## 참조 자료

- WBS: [wbs.md](./wbs.md)
- `packages/sd-cli/src/esbuild/esbuild-worker-plugin.ts` — Feature 1.1에서 생성된 Worker 번들링 플러그인 (`transformWorkerPatterns()` 함수)
- `packages/sd-cli/src/esbuild/esbuild-angular-compiler-plugin.ts` — Angular 컴파일러 esbuild 플러그인 (수정 대상)
- `packages/sd-cli/src/angular/web-worker-transformer.ts` — 기존 TS transformer (삭제 대상)
- `packages/sd-cli/tests/angular/web-worker-transformer.spec.ts` — 기존 TS transformer 테스트 (삭제 대상)
- `packages/sd-cli/src/esbuild/esbuild-client-config.ts` — 클라이언트 esbuild 설정 (변경 없음 — A안 결정)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | Worker 플러그인 client config 추가 여부 | Angular 플러그인 내부에 `transformWorkerPatterns()` 통합. client config에 Worker 플러그인 미추가. | esbuild onLoad 충돌: Worker 플러그인이 Angular 앞이면 .ts AOT 컴파일 누락, 뒤면 onLoad 미실행. Angular 플러그인 내부 통합이 유일한 정상 동작 방식. |
| D2 | .js 파일 Worker 패턴 처리 위치 | Angular 플러그인 JS onLoad에서 JavaScriptTransformer 후 `transformWorkerPatterns()` 호출 | JavaScriptTransformer의 최적화(advanced optimizations, linker, source map)를 보존하면서 Worker 패턴도 변환 |

## 구현계획

### 배경

현재 Angular 클라이언트 빌드에서 `.ts` 파일의 Worker 패턴은 TypeScript AST transformer(`createWorkerTransformer`)를 통해 처리된다. 이 방식은 TS 컴파일 단계에서 AST를 변환하여 Worker URL을 치환하고, `bundleWebWorker`로 Worker를 별도 번들로 빌드한다. [근거: `esbuild-angular-compiler-plugin.ts:427-434`]

Feature 1.1에서 생성된 `esbuild-worker-plugin.ts`의 `transformWorkerPatterns()` 함수는 정규식 기반으로 `.js`/`.ts` 모두에서 동일한 패턴 감지 + 번들링 + URL 치환을 수행한다. [근거: `esbuild-worker-plugin.ts:77-177`]

### 목표

- 기존 TS transformer 기반 Worker 처리를 `transformWorkerPatterns()` 호출로 대체 [근거: Rule "기존 TS transformer 코드가 완전 제거됨"]
- `.ts` 파일: onStart에서 TS 컴파일 후 적용 [근거: Rule "Angular 플러그인 onStart에서 .ts 파일 처리"]
- `.js` 파일: JS onLoad에서 JavaScriptTransformer 후 적용 [근거: Rule "Angular 플러그인 JS onLoad에서 .js 파일 처리"]
- Worker metafile 병합 및 referencedFileTracker 통합 유지 [근거: Rule "Worker 번들 metafile 병합", Rule "Worker 의존성 referencedFileTracker 등록"]

### 비목표

- `esbuild-client-config.ts` 변경 [근거: D1 결정 — Angular onLoad 충돌으로 Worker 플러그인 추가 불가]
- `esbuild-worker-plugin.ts` 자체 로직 변경 [근거: Feature 1.1에서 완성]
- Angular compiler plugin의 비-Worker 기능 변경 [근거: wbs 경계]

#### onStart 수정 — `.ts` Worker 패턴 처리

기존 `emitResults → typeScriptFileCache` 루프 수정:

```typescript
// 기존:
for (const { contents, sourceFileName } of compileResult.emitResults ?? []) {
  typeScriptFileCache.set(path.normalize(sourceFileName), contents);
}

// 변경 후:
pendingWorkerResults.length = 0;
for (const { contents, sourceFileName } of compileResult.emitResults ?? []) {
  const normalized = path.normalize(sourceFileName);

  const workerResult = transformWorkerPatterns(contents, normalized, build);
  if (workerResult != null) {
    typeScriptFileCache.set(normalized, workerResult.contents);
    errors.push(...workerResult.errors);
    warnings.push(...workerResult.warnings);

    if (workerResult.workerMetafile != null) {
      referencedFileTracker.add(
        normalized,
        Object.keys(workerResult.workerMetafile.inputs).map((input) =>
          path.join(cwd, input),
        ),
      );
      pendingWorkerResults.push({ metafile: workerResult.workerMetafile });
    }
    if (workerResult.workerOutputFiles != null) {
      pendingWorkerResults.push({ outputFiles: workerResult.workerOutputFiles });
    }
  } else {
    typeScriptFileCache.set(normalized, contents);
  }
}
```

[근거: Feature 1.1 D2, 기존 `createWebWorkerProcessor`의 referencedFileTracker 패턴 유지]

#### JS onLoad 수정 — `.js` Worker 패턴 처리

`createCachedLoad` 콜백 내부에서 JavaScriptTransformer 후 `transformWorkerPatterns()` 적용:

```typescript
build.onLoad(
  { filter: /\.[cm]?js$/ },
  createCachedLoad(pluginOptions.loadResultCache, async (args) => {
    const request = path.normalize(args.path);
    const sideEffects = await hasSideEffects(request);
    const contents = await javascriptTransformer.transformFile(
      request,
      false,
      sideEffects,
    );

    // Worker 패턴 처리
    const textContents = new TextDecoder().decode(contents);
    const workerResult = transformWorkerPatterns(textContents, request, build);
    if (workerResult != null) {
      if (workerResult.workerMetafile != null) {
        referencedFileTracker.add(
          request,
          Object.keys(workerResult.workerMetafile.inputs).map((input) =>
            path.join(cwd, input),
          ),
        );
        pendingWorkerResults.push({ metafile: workerResult.workerMetafile });
      }
      if (workerResult.workerOutputFiles != null) {
        pendingWorkerResults.push({ outputFiles: workerResult.workerOutputFiles });
      }
      return {
        contents: workerResult.contents,
        loader: "js" as const,
        resolveDir: path.dirname(request),
      };
    }

    return {
      contents,
      loader: "js" as const,
      resolveDir: path.dirname(request),
    };
  }),
);
```

[근거: D1, D2 결정]

#### onEnd 수정

```typescript
build.onEnd((result: esbuild.BuildResult) => {
  for (const wr of pendingWorkerResults) {
    if (wr.outputFiles != null && wr.outputFiles.length > 0) {
      result.outputFiles?.push(...wr.outputFiles);
    }
    if (result.metafile != null && wr.metafile != null) {
      Object.assign(result.metafile.inputs, wr.metafile.inputs);
      Object.assign(result.metafile.outputs, wr.metafile.outputs);
    }
  }
  pendingWorkerResults.length = 0;
});
```
