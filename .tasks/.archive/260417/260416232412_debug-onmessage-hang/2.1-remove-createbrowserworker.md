## 구현계획

### 배경

`client-protocol-wrapper.ts`는 `createBrowserWorker` 래퍼 함수를 통해 Worker를 생성한다. 이 래퍼는 `WorkerLike` 인터페이스를 반환하며, Node.js 환경에서의 타입 호환성을 위해 존재했다. 그러나 esbuild Worker 번들링 플러그인(Feature 1.1)은 `new Worker(new URL(...))` 패턴만 감지하므로, 표준 패턴으로 전환해야 한다. [근거: wbs "web-worker-transformer.ts:17-23에서 new Worker 또는 new SharedWorker 패턴만 감지"]

### 목표

- `createBrowserWorker` 래퍼를 제거하고 `new Worker` 직접 생성으로 전환 [근거: Rule "Worker 생성 패턴은 표준 형태여야 한다"]
- Worker URL 확장자를 `.ts` → `.js`로 변경 [근거: Rule "Worker URL 확장자는 .js여야 한다"]
- `WorkerLike` 인터페이스 제거, DOM `Worker` 타입 사용 [근거: 설계 결정 D1]

### 비목표

- Worker 내부 로직(`client-protocol.worker.ts`) 변경 [근거: wbs 경계]
- `worker.onerror`, decode try-catch 등 에러 처리 수정 [근거: wbs 경계 "이미 적용된 에러 처리 수정은 유지"]

### 설계

**`client-protocol-wrapper.ts` 변경:**
- import: `WorkerLike` 타입 import 제거, `createBrowserWorker` import 제거
- `let worker: WorkerLike | undefined` → `let worker: Worker | undefined`
- `getWorker(): WorkerLike | undefined` → `getWorker(): Worker | undefined`
- `createBrowserWorker(new URL(...), { type: "module" })` → `new Worker(new URL("../workers/client-protocol.worker.js", import.meta.url), { type: "module" })`
- `if (worker == null) return undefined;` 제거 (`new Worker`는 항상 인스턴스 반환, null 불가)

**`browser-compat.ts` 변경:**
- `WorkerLike` 인터페이스 제거 (25-29행)
- `createBrowserWorker` 함수 제거 (38-48행)
- `BlobInput`, `FileCollection`, `isWorkerSupported` 유지

### 대안 검토

- **WorkerLike 유지 + 캐스팅**: `new Worker()`를 `as unknown as WorkerLike`로 캐스팅. Node.js 호환성을 명시적으로 유지하지만, 이중 캐스팅이 필요하고 tsconfig에 이미 DOM이 있으므로 불필요한 간접 계층. → 불채택 (설계 결정 D1)
