## 구현계획

### 배경

현재 `sdRefreshCommand`(Ctrl+Alt+L), `sdSaveCommand`(Ctrl+S), `sdInsertCommand`(Ctrl+Insert) 3개 커맨드가 각각 독립 `EventManagerPlugin`으로 구현되어 있다. 이를 Angular public API인 standalone directive + `output()`으로 전환한다. [근거: WBS "Angular 내부 API(EventManagerPlugin) 의존성 제거"]

### 목표

- 3개 커맨드 EventManagerPlugin을 단일 `SdCommandDirective`로 통합 [근거: WBS "sdRefreshCommand/sdSaveCommand/sdInsertCommand를 묶어 하나의 directive"]
- 기존 호스트 바인딩 사용처를 `hostDirectives` 패턴으로 마이그레이션 [근거: Rule "hostDirectives를 통해 컴포넌트 호스트에 적용"]
- 3개 plugin 파일 및 관련 등록 코드 제거

### 비목표

- `findTopOpenModalEl.ts`, `shouldProcessCommandEvent()` 리팩토링 [근거: WBS 경계 "기존 유틸 함수를 그대로 활용"]
- `SdOptionEventPlugin` 전환 [근거: WBS 제외 사항]
- `sdInsertCommand` 사용처 추가 [근거: WBS "현재 사용처 없으나, directive output으로는 유지"]

### 설계

#### SdCommandDirective (신규)

파일: `packages/angular/src/core/commands/sd-command.ts` [근거: D1]

```typescript
@Directive({
  selector: "[sdRefreshCommand],[sdSaveCommand],[sdInsertCommand]",
  standalone: true,
})
export class SdCommandDirective {
  // inject: ElementRef, DestroyRef, DOCUMENT
  // output: sdRefreshCommand, sdSaveCommand, sdInsertCommand (KeyboardEvent)
  // constructor: 단일 document keydown 리스너 등록 [근거: D2]
  //   - Ctrl+Alt+L → sdRefreshCommand.emit()
  //   - Ctrl+S → sdSaveCommand.emit()
  //   - Ctrl+Insert → sdInsertCommand.emit()
  //   - 각 emit 전 shouldProcessCommandEvent() 체크
  //   - 매칭 시 preventDefault() + stopPropagation()
  // destroyRef.onDestroy: removeEventListener
}
```

#### 호스트 바인딩 마이그레이션 [근거: D3]

**sd-data-detail.ts** — `hostDirectives` 추가, host 바인딩 유지:
```typescript
hostDirectives: [{ directive: SdCommandDirective, outputs: ["sdRefreshCommand", "sdSaveCommand"] }],
host: {
  "(sdRefreshCommand)": "onRefreshButtonClick()",
  "(sdSaveCommand)": "onSubmitButtonClick()",
},
```

**sd-data-sheet.ts** — 동일 패턴:
```typescript
hostDirectives: [{ directive: SdCommandDirective, outputs: ["sdRefreshCommand", "sdSaveCommand"] }],
host: {
  "(sdRefreshCommand)": "onRefreshButtonClick()",
  "(sdSaveCommand)": "onSubmitButtonClick()",
},
```

### 대안 검토

| 대안 | 설명 | 불채택 사유 |
|------|------|------------|
| 3개 개별 directive | 각 커맨드를 독립 directive로 생성 | 3개 plugin이 동일 구조(document keydown + 키 체크 + 모달 스코핑)이므로 불필요한 중복. WBS에서도 "하나의 directive"로 명시 |
| HostListener 데코레이터 | `@HostListener('document:keydown')` 사용 | `@HostListener`는 레거시 패턴. 현재 코드베이스에서 사용하지 않음. constructor + addEventListener가 기존 패턴 |
