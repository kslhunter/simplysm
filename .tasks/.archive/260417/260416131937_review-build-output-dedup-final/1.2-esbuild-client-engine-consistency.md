## 구현계획

### 배경

EsbuildClientEngine은 `setupWatchEvents`를 호출하지만 `waitForInitialBuild`/`resolveInitialBuild` 반환값을 사용하지 않는다. client.worker는 초기 빌드에 "build" 이벤트를 발행하지 않으므로, setupWatchEvents 내부의 `isInitialBuild` 플래그가 첫 후속 빌드까지 true로 남는다. [근거: 리뷰 DESIGN-001]

### 목표

- setupWatchEvents 호출 직후 `resolveInitialBuild()`를 호출하여 내부 상태를 정리한다 [근거: Rule "resolveInitialBuild를 호출하여 상태를 정리"]

### 비목표

- setupWatchEvents 함수 내부 로직 변경 [근거: wbs 경계]
- CONSIST-001 수정 [근거: 이미 이전 작업에서 수정됨]

### 설계

변경 대상: `EsbuildClientEngine.ts:104-111` — setupWatchEvents 호출부 1곳

현재:
```typescript
setupWatchEvents(this._worker!, {
  name: this._pkg.name,
  target: "client",
  resultCollector: this._resultCollector,
  rebuildManager: this._rebuildManager,
  normalizeBuild: (data) => data as NormalizedBuildInfo,
});
// waitForInitialBuild 미사용 — worker.startWatch() await로 완료 감지
```

변경 후:
```typescript
const { resolveInitialBuild } = setupWatchEvents(this._worker!, {
  name: this._pkg.name,
  target: "client",
  resultCollector: this._resultCollector,
  rebuildManager: this._rebuildManager,
  normalizeBuild: (data) => data as NormalizedBuildInfo,
});
resolveInitialBuild(); // EsbuildClientEngine은 worker.startWatch() await로 초기 빌드 완료를 감지하므로 즉시 정리
```
