## 구현계획

### 배경

`_include()` (queryable.ts:772-881)는 관계 체인을 순회하며 `join()`/`joinSingle()`을 호출하여 columns를 확장한다. 현재 `joinSingle("children.detail", ...)`처럼 dotted alias를 사용하여 최상위에 flat key로 저장한다.

### 목표

- `_include()` 내부에서 flat dotted key를 부모 관계 내부에 nested로 배치하여, columns 구조를 TypeScript 타입 구조와 일치시킨다
- downstream 함수들의 출력(SQL, ResultMeta)이 불변

### 비목표

- `join()`/`joinSingle()` 메서드 자체 수정
- downstream 함수(`_buildSelectDef`, `getResultMeta`, `transformColumnsAlias`, `result-parser`) 수정

### 설계

**변경 1: nested path traversal 헬퍼**

`parentCols[parentChain]` flat key 접근을 대체. parentChain을 `.`으로 분할하여 nested 구조를 탐색. 배열(1:N)은 `[0]` 접근.

적용 위치: queryable.ts 라인 815, 857

**변경 2: flat key를 부모 내부로 이동**

각 iteration에서 join/joinSingle 호출 후 (`parentChain !== ""`인 경우):
1. flat dotted key의 값을 parentChain을 따라 부모 내부에 배치 (shallow clone으로 immutability 유지)
2. flat dotted key 삭제
3. 새 Queryable 생성

### 대안 검토

| 대안 | 기각 사유 |
|------|----------|
| A안: for 루프 끝에서 후처리 restructuring (flat key 유지) | flat key + nested 공존으로 데이터 중복 |
| B안: select() 진입 시 Proxy 감싸기 | 모든 콜백 수정 필요, Proxy 충돌 위험 |
