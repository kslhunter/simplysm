## 구현계획

### 배경

sd-cli의 watch/dev 모드에서 빌드 결과를 `ResultCollector`로 중앙 수집 후 `printErrors()`로 출력하는 구조가 이미 존재한다. 그러나 현재 `BuildResult`에는 warnings 필드가 없어 경고가 수집되지 않고, 엔진에서 `logger.warn()`으로 즉시 출력되거나 무시된다. [근거: wbs "ResultCollector.ts의 BuildResult 인터페이스에 warnings 필드 없음"]

### 목표

- `BuildResult`에 warnings 필드를 추가하여 경고를 중앙 수집한다 [근거: Rule "BuildResult는 에러/경고를 별도 필드로 저장"]
- `engine-watch-events`에서 warnings를 `BuildResult`에 전달한다 [근거: Rule "build 핸들러는 warnings를 BuildResult에 저장"]
- `printErrors()`에서 에러와 경고를 구분하여 출력한다 [근거: Rule "에러와 경고를 구분된 포맷으로 출력"]

### 비목표

- 프로덕션 빌드(BuildOrchestrator) 출력 형식 변경 [근거: wbs 경계 "이미 중복 없음"]

### 설계

1. **`ResultCollector.ts`** — `BuildResult` 인터페이스에 `warnings?: string` 추가 [근거: D1]
2. **`engine-watch-events.ts`** — `worker.on("build")` 핸들러에서 `info.warnings?.join("\n")` → `BuildResult.warnings` 저장
3. **`output-utils.ts`** — `printErrors()` 함수 내에서:
   - 기존 에러 출력 로직 유지
   - 에러 출력 후, warnings가 있는 결과를 순회하며 `consola.warn(formatBuildMessages(...))` 호출 [근거: D2]

### 대안 검토

- **warnings를 message 필드에 합치기**: 에러와 경고를 구분할 수 없어 출력 포맷 제어 불가. 기각.
- **별도 WarningCollector 클래스 도입**: 과도한 추상화. 기존 ResultCollector에 필드 추가가 더 단순. 기각.
