## 구현계획

### 배경

Feature 1.1에서 ResultCollector에 warnings 필드가 추가되고, engine-watch-events가 warnings를 저장하며, printErrors()가 에러와 경고를 모두 출력하는 인프라가 구축되었다. 현재 esbuild 네이티브 출력, EsbuildClientEngine의 별도 error 핸들러, BaseEngine의 logger.warn()/logger.error()가 동일 정보를 중복 출력하고 있다.

### 목표

- esbuild → ResultCollector → printErrors() 단일 출력 경로로 통합 [근거: Rule "esbuild 네이티브 출력은 silent로 억제"]
- 엔진별 logger.error()/logger.warn() 중복 호출 제거 [근거: Rule "중복 에러/경고 핸들러 제거"]
- 디버그 목적 로그는 logger.debug()로 보존 [근거: Rule "startWatch 실패 로깅을 debug로 변경"]

### 비목표

- 프로덕션 빌드(BuildOrchestrator) 출력 변경 [근거: wbs 경계 "이미 logLevel: 'silent'이고 EngineResult로 반환하여 중복 없음"]
- BaseEngine의 lint 결과 보고 로직(line 174-183) 변경 [근거: wbs 경계 "lint는 별도 type으로 ResultCollector에 저장됨"]

### 설계

변경은 순수 삭제/수정으로, 새 코드 추가 없음:

| 파일 | 변경 | 근거 |
|------|------|------|
| `esbuild-client-config.ts:191` | `logLevel: isDev ? "warning" : "silent"` → `logLevel: "silent"` | esbuild 네이티브 출력 억제 [Rule: esbuild silent 억제] |
| `EsbuildClientEngine.ts:114-117` | `worker.on("error", ...)` 핸들러 전체 제거 | setupWatchEvents와 중복 [Rule: 중복 에러 핸들러 제거] |
| `EsbuildClientEngine.ts:137` | `logger.error(...)` 줄 제거 | resultCollector.add()와 중복 [Rule: 초기 빌드 실패 단일 보고] |
| `BaseEngine.ts:170-172` | `if (warnings) logger.warn(...)` 블록 제거 | setupWatchEvents가 ResultCollector에 저장 [Rule: 경고 즉시 출력 제거] |
| `BaseEngine.ts:187` | `logger.error(...)` → `logger.debug(...)` | resultCollector.add()와 중복 [Rule: startWatch 실패 debug 로깅] |

### 대안 검토

logLevel을 `"silent"` 대신 `"error"`로 설정하여 경고만 억제하는 방안을 검토하였으나, `"error"` 레벨에서도 에러 출력이 ResultCollector 경로와 중복됨. `"silent"`가 깔끔한 해결.
