## 구현계획

### 배경

리뷰(DESIGN-002)에서 기존 정규식 방식(파싱 실패 시 조용한 기본값 폴백)과 파서 방식(예외 전파)의 차이가 의도적 결정인지 불분명하다는 지적이 있었다. B안(현행 유지 + 주석)을 통해 **"명시적 크래시가 의도"**라는 점을 코드에 명시하고, 추후 유지보수자가 try-catch로 "개선"을 시도하는 퇴행을 예방한다.

### 목표

- `TOML.parse()` 호출부에 명시적 크래시의 의도를 한 줄 주석으로 기술 [근거: Rule "파싱 실패 시 명시적 크래시 의도를 WHY 주석으로 문서화"]

### 비목표

- try-catch 래핑 [근거: wbs 경계 "TOML.parse() 호출 자체는 변경하지 않음"]
- 다른 YAML 파싱 로직(`parseLockfileVersions`)의 주석 추가 [근거: wbs 경계 "다른 YAML 파싱 로직은 변경 범위 밖"]
- 기능 추가/리팩토링 [근거: CLAUDE.md "Feature 범위 준수"]

### 설계

**변경 후 모습** (`server-production-files.ts:108-121` 예시):

```typescript
// dist/mise.toml
if (info.packageManager === "mise") {
  const rootMiseTomlPath = path.join(info.cwd, "mise.toml");
  let nodeVersion = "20";
  if (fs.existsSync(rootMiseTomlPath)) {
    const miseContent = fs.readFileSync(rootMiseTomlPath, "utf-8");
    // mise.toml은 저장소 관리 설정 파일이므로, 파싱 실패 시 폴백하지 않고 예외를 전파하여 설정 오류를 즉시 드러낸다.
    const miseConfig = TOML.parse(miseContent) as { tools?: { node?: string } };
    if (miseConfig.tools?.node != null) {
      nodeVersion = miseConfig.tools.node;
    }
  }
  fs.writeFileSync(path.join(distDir, "mise.toml"), `[tools]\nnode = "${nodeVersion}"\n`);
}
```

- 주석 1줄 추가 외 변경 없음
- 주석은 `TOML.parse()` 호출 라인 직상단에 배치 [근거: D4]
- 한국어, `//` 스타일 [근거: D2, D3]

### 대안 검토

- **A안 (try-catch + 경고 폴백)**: 파싱 실패를 감춰 설정 오류가 배포 후 드러남. `엄격한 완벽주의` 원칙에 반함 — 기각 (wbs D1)
- **JSDoc 블록 주석**: 함수 단위가 아닌 구문 단위이므로 과함. 파일 내 JSDoc은 모두 함수 단위(`:12, :36, :64, :83`) — 기각
- **수행 안 함**: 리뷰 발견사항 DESIGN-002의 "의도적 결정인지 명시되지 않았다" 지적이 해소되지 않아 추후 유지보수자가 try-catch로 퇴행시킬 위험 — 기각
