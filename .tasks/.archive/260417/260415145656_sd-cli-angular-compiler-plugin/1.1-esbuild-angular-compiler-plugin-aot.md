## 구현계획

### 배경

현재 `esbuild-client-config.ts`는 `@angular/build/private`의 `createCompilerPlugin`을 사용하여 AOT 컴파일을 수행한다. 이 함수는 Angular AOT 컴파일, 스타일시트 번들링, JS 변환을 하나의 불투명한 esbuild 플러그인으로 래핑한다. sd-cli는 이미 `AngularCompiler` 클래스(`src/angular/angular-compiler.ts`)를 보유하고 있으며, 이를 Library 빌드와 Vitest에서 사용 중이다. [근거: wbs 배경]

### 목표

- `createCompilerPlugin` 대체용 esbuild 플러그인 `createAngularCompilerPlugin` 구현 [근거: wbs "createCompilerPlugin을 대체하는 자체 esbuild Angular Compiler Plugin"]
- 기존 `AngularCompiler`를 재사용하여 AOT 컴파일 수행 [근거: wbs "AngularCompiler 기반 AOT 컴파일 수행"]
- `FileReferenceTracker` 자체 구현으로 리소스 의존성 추적 [근거: wbs "간단한 유틸리티이므로 자체 구현"]
- `LmdbCacheStore` + `Cache` 자체 구현으로 JS 변환 persistent cache 제공 [근거: D1]
- HMR `templateUpdates` 수집 및 전파 [근거: wbs "HMR templateUpdates 전파 지원"]

#### Plugin onStart 흐름

```
onStart() {
  1. 첫 빌드 여부 판단 (angularCompiler === undefined)

  2. [증분 빌드] staleSourceFiles 캡처 (HMR용)
     - 이전 ts.Program에서 modifiedFiles의 소스 파일 추출

  3. [증분 빌드] modifiedFiles 확장
     - FileReferenceTracker.update(sourceFileCache.modifiedFiles)
     - sourceFileCache.invalidate(expandedFiles)
     - stale additionalResults 제거

  4. AngularCompiler 초기화 또는 update
     - 첫 빌드: new AngularCompiler({...}) + initialize()
     - 증분: angularCompiler.update(expandedFiles)
     - compilerOptionsTransformer 적용 (ES2022, noEmitOnError:false, ...)

  5. emitAffectedFiles → typeScriptFileCache 저장
     - path.normalize(filename) → contents

  6. [증분 + HMR] templateUpdates 수집
     - collectHmrCandidates() + emitHmrUpdateModule()
     - templateUpdates Map에 전파

  7. collectDiagnostics → esbuild PartialMessage 변환
     - errors, warnings 분리

  8. hasCompilationErrors 플래그 갱신

  return { errors, warnings }
}
```

```typescript
function createCompilerOptionsTransformer(
  options: AngularCompilerPluginOptions,
  preserveSymlinks: boolean | undefined,
): (compilerOptions: ts.CompilerOptions) => ts.CompilerOptions {
  return (compilerOptions) => ({
    ...compilerOptions,
    target: 9, // ES2022
    module: 7, // ES2022
    useDefineForClassFields: compilerOptions.useDefineForClassFields ?? false,
    noEmitOnError: false,
    composite: false,
    inlineSources: !!options.sourcemap,
    inlineSourceMap: !!options.sourcemap,
    sourceMap: undefined,
    mapRoot: undefined,
    sourceRoot: undefined,
    preserveSymlinks,
    incremental: options.persistentCachePath != null,
    tsBuildInfoFile: options.persistentCachePath != null
      ? path.join(options.persistentCachePath, ".tsbuildinfo")
      : undefined,
    _enableHmr: !!options.templateUpdates,
    supportTestBed: !!options.includeTestMetadata,
    supportJitMode: !!options.includeTestMetadata,
  });
}

function convertDiagnostic(
  diagnostic: ts.Diagnostic,
  cwd: string,
): esbuild.PartialMessage {
  const text = ts.flattenDiagnosticMessageText(diagnostic.messageText, "\n");
  const location = diagnostic.file != null && diagnostic.start != null
    ? {
        file: path.relative(cwd, diagnostic.file.fileName),
        line: diagnostic.file.getLineAndCharacterOfPosition(diagnostic.start).line + 1,
        column: diagnostic.file.getLineAndCharacterOfPosition(diagnostic.start).character,
      }
    : null;
  return { text, location };
}
```

### 대안 검토

1. **AngularBuildPipeline 재사용 vs AngularCompiler 직접 사용**
   - AngularBuildPipeline은 emit 결과를 파일로 쓰는 `writeEmitResults`를 포함하며, esbuild 플러그인에서는 메모리 캐시(typeScriptFileCache)에 저장해야 함
   - AngularCompiler를 직접 사용하면 emit → 캐시 저장 로직을 커스터마이즈 가능
   - **선택: AngularCompiler 직접 사용** — esbuild 플러그인의 요구사항에 맞는 유연한 제어

2. **HMR 후보 수집 — 외부 import vs 자체 구현**
   - `@angular/build/src/.../hmr-candidates.js`는 private export 미제공
   - 직접 import 시 Angular 업그레이드에 취약
   - **선택: 자체 구현** — NgCompiler 공개 API만 사용, 원본 로직 이식
