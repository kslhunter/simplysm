## 구현계획

### 배경

Feature 1.1에서 `esbuild-angular-compiler-plugin.ts`에 onStart(AOT 컴파일)/onEnd/onDispose 훅이 구현되었다. 그러나 esbuild가 TS/JS 파일을 로드할 때 컴파일된 결과를 가져오는 onLoad 훅이 없어, 실제 번들링에서 AOT 컴파일 결과가 사용되지 않는다. [근거: wbs Feature 1.2 범위]

원본 `createCompilerPlugin`의 onLoad는 두 단계로 구성된다:
1. **TS onLoad** (`/\.[cm]?[jt]sx?$/`): `typeScriptFileCache`에서 AOT 컴파일 결과를 조회하고, `string` 타입이면 `JavaScriptTransformer.transformData()`로 추가 변환
2. **JS onLoad** (`/\.[cm]?js$/`): `JavaScriptTransformer.transformFile()`로 변환하되, `MemoryLoadResultCache`로 결과를 캐싱하여 증분 빌드 성능 확보

[근거: compiler-plugin.js:332-434]

### 목표

- `typeScriptFileCache`의 AOT 컴파일 결과를 esbuild 번들에 제공하는 TS onLoad 훅 구현 [근거: Rule "TS onLoad는 typeScriptFileCache에서 컴파일 결과를 조회한다"]
- JS 파일에 대한 Angular 링킹 + 최적화 변환을 캐싱하는 JS onLoad 훅 구현 [근거: Rule "JS onLoad는 LoadResultCache로 래핑되어 변환 결과를 캐싱한다"]
- `MemoryLoadResultCache` + `createCachedLoad` 자체 구현 [근거: D1]
- `shouldTsIgnoreJs` / `useTypeScriptTranspilation` 플래그를 onStart에서 결정하여 onLoad에서 사용 [근거: D2]

#### onLoad 훅 통합 (esbuild-angular-compiler-plugin.ts 변경)

```typescript
// setup 스코프에 추가할 변수
let shouldTsIgnoreJs = true;       // [근거: compiler-plugin.js:113]
let useTypeScriptTranspilation = true; // [근거: compiler-plugin.js:115]

// onStart 내에서 초기화 후 플래그 결정
// angularCompiler.getTsProgram().getCompilerOptions()로 접근
const co = angularCompiler.getTsProgram().getCompilerOptions();
shouldTsIgnoreJs = !co.allowJs;
useTypeScriptTranspilation =
  !co.isolatedModules || !!co.sourceMap || !!co.inlineSourceMap;

// TS onLoad 훅 (filter: /\.[cm]?[jt]sx?$/)
build.onLoad({ filter: /\.[cm]?[jt]sx?$/ }, async (args) => {
  const request = path.normalize(args.path);
  const isJS = /\.[cm]?js$/.test(request);

  if (shouldTsIgnoreJs && isJS) return undefined;

  let contents = typeScriptFileCache.get(request);
  if (contents === undefined) {
    if (hasCompilationErrors) return { contents: "", loader: "js" as const };
    if (!shouldTsIgnoreJs && isJS) return undefined;

    // Angular 데코레이터 검사
    const directContents = await fs.promises.readFile(request, "utf-8");
    if (!requiresAngularCompiler(directContents)) {
      return {
        warnings: [createMissingFileDiagnostic(request, args.path, cwd, false)],
        contents: undefined,
        loader: "ts" as const,
        resolveDir: path.dirname(request),
      };
    }
    return {
      errors: [createMissingFileDiagnostic(request, args.path, cwd, true)],
    };
  }

  if (typeof contents === "string" && (useTypeScriptTranspilation || isJS)) {
    const sideEffects = await hasSideEffects(request);
    contents = await javascriptTransformer.transformData(request, contents, true, sideEffects);
    typeScriptFileCache.set(request, contents);
  }

  const loader = (useTypeScriptTranspilation || isJS)
    ? "js" as const
    : request.at(-1) === "x"
      ? "tsx" as const
      : "ts" as const;

  return { contents, loader, resolveDir: path.dirname(request) };
});

// JS onLoad 훅 (filter: /\.[cm]?js$/)
build.onLoad(
  { filter: /\.[cm]?js$/ },
  createCachedLoad(pluginOptions.loadResultCache, async (args) => {
    const request = path.normalize(args.path);
    const sideEffects = await hasSideEffects(request);
    const contents = await javascriptTransformer.transformFile(request, false, sideEffects);
    return {
      contents,
      loader: "js" as const,
      resolveDir: path.dirname(request),
    };
  }),
);
```

// hasSideEffects — setup 스코프 내부
async function hasSideEffects(filePath: string): Promise<boolean | undefined> {
  if (!pluginOptions.advancedOptimizations) return undefined;
  const { sideEffects } = await build.resolve(filePath, {
    kind: "import-statement",
    resolveDir: cwd,
  });
  return sideEffects;

### 대안 검토

1. **MemoryLoadResultCache를 @angular/build 내부에서 import vs 자체 구현**
   - `@angular/build/private`에서 `MemoryLoadResultCache`를 export하지 않음 (private.d.ts 확인)
   - deep import(`@angular/build/src/tools/esbuild/load-result-cache`)는 패키지 내부 경로이며 버전 업그레이드에 취약
   - **선택: 자체 구현** — ~80줄의 간단한 Map 래퍼이며, `client.worker.ts`에서 `watchFiles`/`invalidate()` API를 직접 사용하므로 안정적인 자체 인터페이스 필요

2. **플래그 결정을 AngularCompiler.initialize() 반환에 포함 vs getTsProgram()으로 접근**
   - `AngularCompiler.initialize()`는 현재 `{ affectedFiles }` 만 반환
   - 반환 타입을 확장하면 AngularCompiler의 API 변경이 필요
   - `getTsProgram().getCompilerOptions()`로 동일 정보 접근 가능
   - **선택: getTsProgram()으로 접근** — AngularCompiler API 변경 불필요, 원본도 `initializationResult.compilerOptions`에서 읽되 이는 compilation wrapper의 반환
