## 구현계획

### 배경

현재 `esbuild-angular-compiler-plugin.ts`는 AOT 컴파일(onStart), 증분 빌드, HMR templateUpdates를 구현하고 있으나, Web Worker 번들링은 아직 구현되지 않았다. Angular 프로젝트에서 `new Worker(new URL('./worker.ts', import.meta.url))` 패턴을 사용하면, TypeScript emit 시 Worker 파일을 별도로 번들링하고 URL을 번들된 경로로 치환해야 한다. [근거: wbs Feature 2.2 범위]

`@angular/build`에서 이 기능은 두 부분으로 구현된다:
1. `createWorkerTransformer` — TypeScript before transformer로 `new Worker(new URL(...))` AST 패턴을 감지
2. `bundleWebWorker` — `esbuild.buildSync()`로 Worker 파일을 별도 번들링

우리 `AngularCompiler`는 `emitAffectedFiles(options?: EmitOptions)`에서 `additionalTransformers.before`를 지원하므로, 여기에 worker transformer를 주입하면 된다. [근거: D1 설계 결정, angular-compiler.ts:394-496]

### 목표

- `createWorkerTransformer` 자체 구현 [근거: Rule "createWorkerTransformer는 new Worker(new URL...) 패턴을 감지"]
- `bundleWebWorker` 함수 구현 [근거: Rule "bundleWebWorker는 esbuild.buildSync로 Worker를 별도 ESM 번들로 빌드"]
- esbuild 플러그인에 processWebWorker 콜백 + transformer 주입 통합 [근거: D1]

### 비목표

- AngularCompiler / AngularCompilerOptions 수정 [근거: D1 — transformer 주입 방식으로 불필요]
- Worker 내부 Zone.js 처리 [근거: wbs 경계]
- Worker에 Angular 플러그인 체인 적용 [근거: wbs 경계 — esbuild.buildSync는 plugins 미지원]

#### createWorkerTransformer

```typescript
// web-worker-transformer.ts
import ts from "typescript";

export function createWorkerTransformer(
  fileProcessor: (workerFile: string, containingFile: string) => string,
): ts.TransformerFactory<ts.SourceFile> {
  return (context) => {
    const nodeFactory = context.factory;
    const visitNode = (node: ts.Node): ts.Node => {
      // 1. new Worker / new SharedWorker 감지
      // 2. 첫 인자가 new URL(stringLiteral, import.meta.url)인지 확인
      // 3. fileProcessor(filePath, importer) 호출
      // 4. URL 인자 치환 + options 인자 없으면 { type: 'module' } 추가
      ...
    };
    return (sourceFile) => {
      if (!sourceFile.text.includes("Worker")) return sourceFile;
      return ts.visitEachChild(sourceFile, visitNode, context);
    };
  };
}
```

#### bundleWebWorker 함수

```typescript
// esbuild-angular-compiler-plugin.ts에 추가
function bundleWebWorker(
  build: esbuild.PluginBuild,
  sourcemap: boolean,
  workerFile: string,
): esbuild.BuildResult {
  try {
    return build.esbuild.buildSync({
      ...build.initialOptions,
      platform: "browser",
      write: false,
      bundle: true,
      metafile: true,
      format: "esm",
      entryNames: "worker-[hash]",
      entryPoints: [workerFile],
      sourcemap,
      supported: undefined,
      plugins: undefined,
    });
  } catch (error) {
    if (error != null && typeof error === "object" && "errors" in error && "warnings" in error) {
      return error as esbuild.BuildResult;
    }
    throw error;
  }
}
```

#### processWebWorker 콜백 (onStart 내부)

```typescript
// onStart 내부에서 생성하여 workerTransformer에 주입
const processWebWorker = (workerFile: string, containingFile: string): string => {
  const fullWorkerPath = path.join(path.dirname(containingFile), workerFile);
  const workerResult = bundleWebWorker(build, pluginOptions.sourcemap, fullWorkerPath);

  warnings.push(...workerResult.warnings);

  if (workerResult.errors.length > 0) {
    errors.push(...workerResult.errors);
    // 에러 파일 경로 추적
    referencedFileTracker.add(
      containingFile,
      workerResult.errors
        .map((e) => e.location?.file)
        .filter((f): f is string => f != null)
        .map((f) => path.join(cwd, f)),
    );
    additionalResults.set(fullWorkerPath, { errors: workerResult.errors });
    return workerFile;
  }

  additionalResults.set(fullWorkerPath, {
    outputFiles: workerResult.outputFiles,
    metafile: workerResult.metafile,
  });

  // metafile.inputs → FileReferenceTracker
  referencedFileTracker.add(
    containingFile,
    Object.keys(workerResult.metafile!.inputs).map((input) => path.join(cwd, input)),
  );

  // worker-[HASH].js 파일 찾기
  const workerCodeFile = workerResult.outputFiles!.find((file) =>
    /^worker-[A-Z0-9]{8}\.[cm]?js$/.test(path.basename(file.path)),
  );
  const outdir = build.initialOptions.outdir ?? "";
  const workerCodePath = path.relative(outdir, workerCodeFile!.path);
  return workerCodePath.replaceAll("\\", "/");
};
```

### 대안 검토

1. **AngularCompiler host 확장 vs TypeScript transformer 주입**
   - host 확장: NgtscProgram이 processWebWorker를 인식하지 않아 동작 불가
   - transformer 주입: Angular build 원본과 동일한 방식, 기존 인프라 활용
   - **선택: transformer 주입** (D1)

2. **createWorkerTransformer — @angular/build import vs 자체 구현**
   - `@angular/build/private`에서 export되지 않음 (private.d.ts 검색 확인)
   - 내부 경로 직접 import는 Angular 업그레이드에 취약
   - ~60줄의 순수 TypeScript AST 조작 코드로 자체 구현 용이
   - **선택: 자체 구현**

3. **bundleWebWorker — build.esbuild.buildSync vs esbuild 직접 import**
   - `build.esbuild`는 esbuild PluginBuild에서 제공하는 esbuild 인스턴스 참조로, 동일 esbuild 버전 보장
   - 직접 import도 가능하나, 원본 패턴을 따르면 버전 불일치 방지
   - **선택: build.esbuild.buildSync 사용** (원본 패턴)
