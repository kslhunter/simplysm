## 구현계획

### 배경

SdTsCompiler 통합 (Epic 1, 2) 이후, `library-build.worker.ts`와 `ngtsc-build.worker.ts`의 구조가 거의 동일해졌다. 두 워커 모두 SdTsCompiler 인스턴스를 생성하고 `compileAsync()`를 호출하는 동일한 패턴을 사용한다. 차이점은 ngtsc 워커의 Angular 전용 로직(writeEmitResults, SCSS deps, side-effect SCSS)뿐이며, 이는 `result.isForAngular` / `result.emitResults` 조건으로 통합 가능하다. [근거: 코드 분석 — 양쪽 워커의 구조 비교]

### 목표

- `ngtsc-build.worker.ts`를 `library-build.worker.ts`로 흡수하여 watch+build+타입 중복 완전 제거 [근거: D1]
- `BuildOutput`에 `globalScss?: boolean` 추가로 Angular SCSS 활성화를 명시적 제어 [근거: D2]
- 기존 테스트 시나리오 100% 유지

### 비목표

- 엔진 클래스(TscEngine + NgtscEngine) 통합 [근거: wbs 제외사항]
- `ngtsc-build-core.ts`의 함수/타입 제거 [근거: wbs Feature 3.1 범위]
- 서버/클라이언트 워커 변경 [근거: wbs 경계 "esbuild 기반이므로 범위 아님"]

### 설계

#### 1. BuildOutput 확장

`packages/sd-cli/src/engines/types.ts`의 `BuildOutput` 인터페이스에 `globalScss?: boolean` 추가.

```typescript
export interface BuildOutput {
  js: boolean;
  dts: boolean;
  lint?: boolean;
  env?: TypecheckEnv;
  includeTests?: boolean;
  globalScss?: boolean; // Angular 라이브러리의 글로벌 SCSS 컴파일 여부
}
```

[근거: D2 — BuildOutput이 빌드 동작 제어 단일 창구]

#### 2. 통합 워커 타입

`library-build.worker.ts`의 타입을 통합:

- `LibraryBuildInfo`: `config` 필드 제거 (SdTsCompiler 통합 후 미사용). `output` 필드의 타입은 `BuildOutput` 그대로 사용 (globalScss 포함).
- `LibraryBuildResult`: SCSS 에러도 `errors`에 병합하는 구조 유지 (ngtsc와 동일).
- `CombinedBuildEvent`: 변경 없음 (이미 ngtsc와 구조 동일).

```typescript
export interface LibraryBuildInfo {
  name: string;
  cwd: string;
  pkgDir: string;
  output: BuildOutput;
  replaceDeps?: Record<string, string>;
}
```

[근거: 코드 분석 — `LibraryBuildInfo.config`는 워커에서 미사용, `NgtscBuildInfo.env`도 `output.env`로 대체됨]

#### 3. 통합 build() 함수

Angular 조건 분기 추가:

- `result.emitResults != null`: `writeEmitResults` 호출 (src/ 필터, build 모드에서 scss 옵션 미전달)
- `result.scssErrors.length > 0`: errors에 병합, success 판정에 영향
- try-catch 래핑 (ngtsc 패턴 — 예외 시 에러 결과 반환)

[근거: ngtsc-build.worker.ts:54-102 패턴 통합]

#### 4. 통합 startWatch() 함수

Angular 조건 분기 추가:

- `output.globalScss`: watch 글로브에 SCSS 추가 (`["*.{ts,scss,css}"]` + `extraDirs`)
- `combinedScssDeps` 상태 관리: Angular일 때만 활성화
- SCSS 역방향 탐색: onChange에서 SCSS 변경 시 combinedScssDeps로 소유자 파일 추가
- `buildWatchEvent()` 로직: Angular일 때 writeEmitResults + compileSideEffectScss 수행
- `extractSourceFilePaths()`: 통합 시그니처 (program이 있으면 추출, 없으면 이전 값 유지 — 현재 library 패턴)

[근거: ngtsc-build.worker.ts:183-268 패턴 통합]

#### 5. NgtscEngine 업데이트

- `_getWorkerPath()`: `library-build.worker` 경로로 변경
- `_callBuild()`, `_callStartWatch()`: `LibraryBuildInfo` 타입 사용, `output`에 `globalScss: true` 추가
- import: `NgtscBuildWorkerModule` → `LibraryBuildWorkerModule`

[근거: D1 — 단일 워커로 통합]

#### 6. ngtsc-build.worker.ts 삭제

모든 로직 이동 후 파일 삭제. `NgtscBuildInfo`, `NgtscBuildResult` 등의 타입은 `ngtsc-build-core.ts`에 정의되어 있으므로 이 Feature에서는 삭제하지 않음 (Feature 3.1 범위).

#### 7. 테스트 통합

- `ngtsc-build-worker.spec.ts`의 시나리오를 `library-build-worker.spec.ts`로 이동 (Angular 조건 분기 테스트로 변환)
- `ngtsc-build-lint.spec.ts`의 시나리오를 `library-build-lint.spec.ts`로 이동
- 기존 library 테스트는 유지 (non-Angular 경로)
- `ngtsc-build-worker.spec.ts`, `ngtsc-build-lint.spec.ts` 삭제

### 대안 검토

**공통 watch 유틸 추출 (선택지 B)**:
watch 루프를 `shared-watch-loop.ts`로 추출하는 방식. 양쪽 워커 유지하면서 공통 부분만 공유. 변경 리스크는 낮으나 build() 및 타입 중복이 잔존하고 파일 수가 증가(2→3)하여 유지보수성이 떨어짐. D1에서 기각.
