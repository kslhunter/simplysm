## 구현계획

### 배경

`NullableQueryableRecord<TData>`는 LEFT JOIN 결과를 표현하며, 모든 컬럼에 `| undefined`를 추가한다. 현재 이 타입에서 원본 `TData`로 역추적하는 방법이 없어, `nn()` 함수로 타입 레벨 변환을 제공한다.

### 목표

- `NullableQueryableRecord`에 phantom type을 추가하여 원본 `TData`를 타입 레벨에서 보존 [근거: Rule "phantom type은 원본 TData를 보존한다"]
- `nn()` 함수로 `NullableQueryableRecord` → `QueryableRecord` 타입 변환 제공 [근거: Rule "nn()은 단일/배열 변환"]
- 런타임 오버헤드 제로 (identity function) [근거: Rule "nn()은 런타임에서 identity function"]

### 비목표

- `QueryableRecord` 타입 변경 [근거: wbs 경계]
- `UnwrapQueryableRecord` 타입 변경 [근거: wbs 경계]
- `ExprUnit.n` getter 변경 [근거: wbs 경계]

### 설계

1. **unique symbol 선언** (`queryable.ts`):

```typescript
declare const __nnOriginalData: unique symbol;
```

- `declare`로 선언하여 런타임 코드 생성 없음
- export하지 않아 패키지 내부 전용 [근거: Rule "unique symbol은 패키지 내부 전용"]

2. **`NullableQueryableRecord` phantom 필드 추가** (`queryable.ts:1881`):

```typescript
export type NullableQueryableRecord<TData extends DataRecord> = {
  readonly [__nnOriginalData]?: TData;
  // 기존 매핑 유지
  [K in keyof TData]: ...
};
```

- `?`(optional)로 선언하여 실제 값 할당 불필요 [근거: Rule "phantom type은 원본 TData를 보존한다"]
- `readonly`로 외부 수정 방지

3. **`nn()` 함수** (`queryable.ts`, `NullableQueryableRecord` 정의 이후):

```typescript
export function nn<TData extends DataRecord>(
  value: NullableQueryableRecord<TData>[] | undefined,
): QueryableRecord<TData>[];
export function nn<TData extends DataRecord>(
  value: NullableQueryableRecord<TData> | undefined,
): QueryableRecord<TData>;
export function nn(value: any): any {
  return value;
}
```

- 배열 overload를 먼저 선언 [근거: D3 — 배열이 단일 overload에 매칭되는 것을 방지]
- 런타임은 identity function [근거: Rule "nn()은 런타임에서 identity function"]

### 대안 검토

| 접근 방식 | 장점 | 단점 | 결정 |
|-----------|------|------|------|
| phantom type + `nn()` 함수 | 컬럼명 충돌 없음, 타입 안전 | phantom 필드 추가 필요 | **채택** |
| `.n` 프로퍼티 방식 | 간결한 문법 | 컬럼명 `n`과 충돌 가능 | 기각 [근거: wbs 제외사항] |
