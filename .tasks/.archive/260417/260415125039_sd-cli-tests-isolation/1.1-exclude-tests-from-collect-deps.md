## 구현계획

### 배경

`buildWorkspacePkgMap()` (collect-deps.ts:18-28)은 `discoverWorkspacePackages()`를 호출하여 모든 워크스페이스 패키지(packages/ + tests/)를 맵에 포함한다. 이 맵은 `collectDeps()`에서 의존성을 workspace dep으로 분류할 때 사용되며, `build-watch-paths.ts:26`에서 `workspaceDeps`를 `packages/` 경로로 하드코딩 변환한다. tests/ 패키지가 포함되면 잘못된 경로(`packages/orm` 대신 `tests/orm`)가 생성되는 구조적 문제가 있다. [근거: WBS 근거 섹션]

### 목표

- `buildWorkspacePkgMap()`에서 tests/ 패키지를 필터링하여 워크스페이스 의존성 맵에서 제외한다 [근거: Rule "buildWorkspacePkgMap은 packages/ 패키지만 포함한다"]

### 비목표

- `discoverWorkspacePackages()` 함수 자체 수정 [근거: WBS 경계 "check 경로에서 사용"]
- `collectDeps()` 시그니처 변경 [근거: 설계 결정 D1 — API 변경 없는 필터링 방식 채택]

### 설계

`buildWorkspacePkgMap()` 함수의 for 루프에서 `relDir`이 `"tests/"`로 시작하면 `continue`로 건너뛴다. 이는 `mergeTestsPackagesIntoConfig` (package-utils.ts:85)에서 사용하는 동일한 필터링 패턴이다. [근거: Rule "buildWorkspacePkgMap은 packages/ 패키지만 포함한다" 처리를 위해]

### 대안 검토

config 기반 교체 (Option A): `discoverWorkspacePackages()` 호출을 sd.config.ts의 packages 목록으로 교체하는 방식. `collectDeps` 시그니처 변경 및 호출처(build-watch-paths, worker) 수정이 필요하여 변경 리스크가 높아 채택하지 않음.
