## 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|----------|------|------|
| D1 | 독자 관점 선행 체인 | 확장 A + 확장 B 유지 | 코드 블록이 A(canEdit·_checkIgnoreChanges)·B(selectedItems·getItemCellStyleFn·isDeleted·multi)를 그대로 재사용. 체인 변경 시 재서술 분량 과다 |
| D2 | "modal = 선택 모달 반사 단정" anti-pattern 배치 | 진입점과 중복 배치하지 않고 확장 E 링크 + 구현 관점 1줄 요약만 | 진입점(crud-list.md)에 이미 수록됨. 여기선 확장 D 도입 시의 혼동 방지에 집중 |
| D3 | 고유 anti-pattern 추출 | 3건을 명시 블록화 | (a) multi 모드에서 "선택 해제"가 close emit까지 수행 (b) `selectedItemKeys` index fallback (c) `<sd-dock>` `[position]` 생략 |
| D4 | `setupCanDeactivate` 완화 설명 위치 | 포인트 섹션 유지 | anti-pattern은 아님(구현 관점 주의사항). 포인트 1줄이면 충분 |
| D5 | `cumulativeSelection` 조건 설명 | 본문 포인트로 유지 | "왜 multi && modal에만" 근거가 소스에 없는 도메인 정보 — 문서 가치 큼 |
