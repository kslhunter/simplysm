## 기준 코드

(이 Feature는 문서 재작성이므로 "기준 코드"는 T1 템플릿과 Feature 1.1 재작성 산출물, 소스 시그니처이다.)

### 유사 기능: Feature 1.1 `_common-rules.md` (T3) 재작성 결과

- Feature 1.1이 `✅ Always / ⚠️ Ask first / 🚫 Never / 예외 케이스` 뼈대 + 각 규칙 ❌/✅ 코드블록 + `**근거**:` 1줄 구성을 확정.
- Feature 4.1은 T1(Recipe) 템플릿을 사용하므로 섹션 순서가 다르지만, **❌/✅ 대비 블록과 `**근거**:` 1줄**, **3인칭 서술**, **1-level deep 링크**, **소스 경로 인용** 형식은 동일하게 따른다.

### 유사 기능: `_common-rules.md`의 "시트 셀 내부 컨트롤 inset/size" 규칙

- 현행 `data-select-button.md:288-303`의 "§5.1 시트 셀 안에 삽입" 섹션이 시트 셀 내부 사용 지침을 담고 있음. 공통 규칙과 중복되므로 재작성 시 **공통 규칙으로 위임(1-level 링크)**하고 본문은 `<app-lot-select-button [inset]="true" [size]="'sm'">` 1-줄 예시만 남긴다.

### 유사 기능: 현행 `data-select-button.md` 패턴 3개

- 패턴 1 `<sd-modal-select-button>` 직접 사용: 1회성 모달, 모달 컴포넌트가 `SdSelectModal<T>`를 직접 `implements`.
- 패턴 2 `<sd-shared-data-select-button>`: 메모리 상주 `SharedDataBase` 데이터, `items` 기반 자동 매칭.
- 패턴 3 사용자 정의 wrapper: 도메인별 select button을 `<sd-modal-select-button>` 컴포지션 + `effect` 비동기 `load(keys)`로 구성.

## 🚫 흔한 실수 (Anti-patterns)

### 1. `SdDataSelectButton` / `SdDataSelectButtonBase` 재도입

```typescript
// ❌ 과거 추상 클래스 상속 패턴 복원
export class MySelectButton extends SdDataSelectButtonBase<IItem> { /* ... */ }

// ✅ <sd-modal-select-button> 컴포지션 wrapper
{LotSelectButton 요약}
```

**근거**: 공통 부모를 재도입하면 도메인별 분기가 상속 트리에 고이고 변경 전파가 불투명해진다.

### 2. modal = 선택 모달로 반사 단정

```typescript
// ❌ 조회 전용 modal에도 SdSelectModal<T> 강제 구현
export class ReadonlyHistoryModal implements SdSelectModal<...> { /* 불필요한 selectMode/selectedItemKeys */ }

// ✅ 선택 계약이 필요한 경우에만 implements, 조회 전용은 SdModalContentDef만 구현
{링크: ./crud-list/extension-d-select-modal.md}
```

**근거**: `SdSelectModal<T>`는 선택 결과 반환 계약(`SelectModalOutputResult<T>`)을 강제한다. 조회 전용 모달은 이 계약이 불필요하다.

### 3. effect 콜백을 async로 선언

```typescript
// ❌ cleanup 시점이 어긋남
effect(async () => {
  const v = this.value();
  const items = await this._load([v]);
  this._selectedItems.set(items);
});

// ✅ void IIFE 또는 void untracked(async)로 비동기 격리
effect(() => {
  const v = this.value();
  if (v == null) { this._selectedItems.set([]); return; }
  void (async () => {
    const items = await this._load([v]);
    this._selectedItems.set(items);
  })();
});
```

**근거**: `effect`의 cleanup은 다음 tick에 실행되는데, async 콜백은 반환 Promise가 해소되기 전 cleanup이 호출되어 취소 로직이 불안정해진다. 관련: [_common-rules.md의 input 의존 로딩 규칙](./_common-rules.md#input-의존-데이터-로딩에-void-this_initasync를-사용하지-않는다).

### 4. `<sd-shared-data-select-button>`에 `[(selectedItems)]` 외부 바인딩

```typescript
// ❌ 외부에서 selectedItems를 set하려는 시도 — 소스에 바인딩 지점 없음
<sd-shared-data-select-button [(value)]="shopId" [(selectedItems)]="shops()" ... />

// ✅ value + items만 set. 외부 set이 필요하면 패턴 3 wrapper로 전환
<sd-shared-data-select-button [(value)]="shopId" [items]="shops()" ... />
```

**근거**: `SdSharedDataSelectButton`의 `_selectedItems`는 `protected readonly signal`이며 `items` + `value`로부터 effect로 자동 파생된다 (`sd-shared-data-select-button.ts:79-96`).
