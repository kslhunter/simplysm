# Feature 3.1 crud-detail.md 진입점 재작성 — LLM 검증

대상: `packages/angular/docs/recipes/crud-detail.md`

## 검증 항목

### 구조 (T1 템플릿 준수)

- 섹션 순서: `# Recipe: …` → 1~2문장 요약 → `## When to use / When NOT to use` → `## 전제조건` → `## 기본 레시피` → `## 변형` → `## 🚫 흔한 실수` → `## 관련 Entry`
- "When to use / When NOT to use"에 ✅ 사례 ≥2개, ❌ 사례 ≥3개 (crud-list·page-modal-container·data-select-button 각 1줄)
- "변형" 섹션: 상황 → 확장 조합 표 (8행 이상) + "### 각 확장 요약" A~F 불릿 6개
- "🚫 흔한 실수" 섹션: 항목 3개 (3뷰 박기, effect untracked, setupCanDeactivate 제약), 각 항목에 ❌/✅ 코드블록 + 근거 1줄

### 내용 정합

- 기본 레시피 코드가 **page 전용**이다 (viewType 분기 없음, close output 없음, `<sd-dock>` 없음)
- `AppOrmProvider`가 "앱별 대체 — `@simplysm/angular`가 아니라 각 앱이 소유한다"로 주석됨
- `ICustomer` 인터페이스에 `lastModifiedAt`·`lastModifiedBy`·`id: number | undefined` 포함
- `effect` 내부 `void untracked(async () => { ... })` 패턴 사용
- `SdCommandDirective` host directive 사용, `outputs: ["sdRefreshCommand"]` 노출
- `injectPermsSignal(["sales.customer"], ["use"])` 형식
- `injectViewTitleSignal()` 사용, `injectViewTypeSignal()` **미사용** (기본 레시피는 page 전용)

### 소스 API 시그니처 일치

| 대상 | 검증 |
|---|---|
| `<sd-form>` | 기본 레시피는 `(formSubmit)` 미사용 — 소스 `packages/angular/src/controls/form/sd-form.ts:32-51`과 일치 (편집은 확장 A) |
| `SdCommandDirective` selector | `[sdRefreshCommand],[sdSaveCommand],[sdInsertCommand]` — 소스 `packages/angular/src/core/commands/sd-command.ts:6`과 일치. 기본 레시피는 `sdRefreshCommand`만 사용 |
| `injectViewTypeSignal` | anti-pattern의 ❌ 예시에서만 등장. 실제 사용은 확장 C/D로 위임 — 소스 `packages/angular/src/core/routing/injectViewTypeSignal.ts:7` |

### 공통 규칙 중복 제거

- `mark` 오용, `injectViewTypeSignal()` 호출 위치, `_sdSharedData.wait()` 조건, 시트 셀 `[inset]/[size]`, soft-delete 선택 기준은 본문에 **재수록되지 않음**
- "🚫 흔한 실수" 섹션 상단에 `_common-rules.md` 참조 안내 1줄 존재

### 반-기법 회피

- 1·2인칭 서술 부재 (`you`, `I can`, `저희가`, `당신이` 검색 결과 없음)
- 최상단 `> **CRITICAL:**` 인용 블록 제거, 그 의미는 "지원할 뷰를 확인하지 않고 3뷰 분기를 미리 박는다" anti-pattern으로 이관
- CRITICAL / ALWAYS / NEVER 키워드 2회 이하 등장
- 부록 B "확장 매트릭스 표" 제거
- §4 "블록 역할 / 상태 분해 / 메서드 분해" 3개 테이블 제거 (조건부 요소 포함 기준 1개만 유지)
- §11 "뷰 타입 분기" 설명 제거

### 링크 정합성

- 상대 경로 `./crud-detail/extension-{a-f}-*.md` 6개 모두 실제 파일명과 일치
- `./_common-rules.md`, `./crud-list.md`, `./page-modal-container.md`, `./data-select-button.md` 존재
- 1-level deep: 확장 파일에서 또 다른 recipe로 체이닝하지 않음 (각 확장은 "상세" 링크 하나만)
