### 공통 규칙 반영

- `_common-rules.md` "삭제 방식은 DB 스키마에 따라 결정한다" — 본 확장은 soft-delete 경로 전담. 본문에 재서술하지 않고 `> **적용 조건:**` 블록쿼트에서 1-hop 링크(`../_common-rules.md#삭제-방식은-db-스키마에-따라-결정한다`)로 위임.
- `_common-rules.md` "시트 셀 내부 컨트롤에 `[inset]="true" [size]="'sm'"` 명시" — 본 확장은 시트 셀 편집 컨트롤을 추가하지 않음. 필터의 `<sd-checkbox>`는 시트 셀 외부이므로 해당 규칙 비적용.
- `_common-rules.md` "`mark(sig)`를 '저장 감지' 수단으로 사용하지 않는다" — 본 확장은 `mark(filter)`를 체크박스 valueChange에서 사용하는데 용도는 OnPush 통지. 본문 재서술 없이 필요 시 1-hop 링크만.

## 구현계획

### 배경

현행 `packages/angular/docs/recipes/crud-list/extension-b-selection.md`(181줄)는 이미 diff 스타일 템플릿을 쓰고 있으나, (a) 본 확장의 실제 흔한 실수(`selectedItems` 내 신규 행 포함 시 DB update 오류)가 "신규 행(id == null)은 선택 삭제 대상에서 제외된다"는 포인트 1문장에 숨어 있고, (b) `🚫 흔한 실수` 서브섹션이 없어 sibling 확장 A와 템플릿 정렬이 깨져 있다. Feature 2.1 재작성본(진입점 T1), 공통 규칙 T3, sibling 확장 A를 기준으로 `🚫 흔한 실수` 서브섹션 신설과 포인트 불릿의 3인칭 정돈, 공통 규칙 링크 일관화를 정비한다. 코드 diff 본문(`selectedItems`·`hasSelected*`·`getItemCellStyleFn`·`onToggleDeleteItemsButtonClick`·`_refresh` 페이지 이동 선택 유지·`_upsertItem` `isDeleted`)은 소스 정합 재검증 후 **보존**한다.

#### 파일 구조 (sibling 템플릿 정렬)

```markdown
← [CRUD 리스트 레시피 진입점](../crud-list.md)

# 확장 B: 선택 기능 + 선택 삭제/복구

> **선행:** [확장 A: inline 편집/저장](./extension-a-inline-edit.md)

시트에 체크박스 기반 선택 기능을 추가하고, 선택된 행에 대한 "선택 삭제 / 선택 복구" 버튼 바를
상단에 배치한다. 확장 A(inline 편집)가 도입한 `canEdit` / `SHARED_DATA_KEY` / `_appAuth` 등을 재사용하며,
본 확장이 `isDeleted` 플래그 / `isIncludeDeleted` 필터 / `getItemCellStyleFn`(삭제 취소선)을 도입한다.

> **적용 조건:** DB Table에 `isDeleted` 컬럼이 있는 경우에만 사용한다. 컬럼이 없는 테이블은
> 물리 삭제로 처리하며 이 확장을 사용하지 않는다 → [공통 규칙: 삭제 방식](../_common-rules.md#삭제-방식은-db-스키마에-따라-결정한다).

**이 확장이 도입하는 요소:**

- **imports:** `SdCheckbox`, `tablerEraser`, `tablerRestore`
- **타입 확장:** `IFilter.isIncludeDeleted: boolean`, `ICustomer.isDeleted: boolean`
- **상태:** `selectedItems = signal<ICustomer[]>([])`, `filter`/`lastFilter` 기본값에 `isIncludeDeleted: false`
- **파생:** `hasSelectedDeleted`, `hasSelectedNotDeleted`, `getItemCellStyleFn`
- **메서드:** `onToggleDeleteItemsButtonClick(del)` — confirm → DB update → `emitAsync` → 토스트 → `_refresh`
- **템플릿:** 필터 dock에 "삭제항목 포함" 체크박스, 확장 A 도구 dock에 "선택 삭제 / 선택 복구" 버튼, `<sd-sheet>` 에 `[selectMode]="'multi'"` + `[(selectedItems)]` + `[getItemCellStyleFn]` 바인딩
- **_search 변경:** `isIncludeDeleted` 분기 + select `isDeleted`
- **_upsertItem 변경:** upsert 데이터에 `isDeleted`, 중복 검사에 `expr.eq(c.isDeleted, false)`
- **onAddItemButtonClick 변경:** 신규 행 리터럴에 `isDeleted: false`
- **_refresh 변경:** 말미에 "현재 페이지에 남아 있는 항목만 selectedItems 유지" 추가

> 상세: [`<sd-sheet> selectMode/selectedItems`](../../ui-data/sd-sheet.md)

\`\`\`typescript
// 0) imports 추가 + 타입 확장 (IFilter / ICustomer)
// 1) 상태·파생 추가 (selectedItems / hasSelected* / getItemCellStyleFn)
// 2) onAddItemButtonClick — 신규 행에 isDeleted: false 포함
// 3) _search / _upsertItem 변경 (isDeleted 필터·select·중복검사·upsert)
// 4) onToggleDeleteItemsButtonClick 메서드 + _refresh 선택 유지 로직 + template diff
\`\`\`

**포인트:**

- 선택 삭제/복구는 confirm 후 즉시 DB 반영 경로 (확장 A의 일괄 저장 경로와 별도)
- `selectMode` 기본값은 `"multi"` — 단일 선택 필요 시 `"single"`
- 페이지 이동/정렬/필터 제출 후 `_refresh` 내부에서 `selectedItems`를 현재 페이지 항목으로만 유지. 페이지 누적 선택이 필요하면 [확장 D: 선택 모달](./extension-d-select-modal.md)의 `[cumulativeSelection]` 참조 (선택 모달 전용)

**🚫 흔한 실수**

> 공통 규칙(`mark` 저장 감지 오해, 시트 셀 `[inset]/[size]`, 삭제 방식 등)은 [레시피 공통 규칙](../_common-rules.md)을 참조한다. 본 섹션은 **선택 삭제/복구 확장 고유 실수**만 다룬다.

### 신규 행(id == null)을 선택 삭제 대상에 포함한다

\`\`\`typescript
// ❌ selectedItems() 전체를 DB update 대상으로 사용 — 신규 행은 DB에 존재하지 않아
//    update 조건(expr.eq(c.id, undefined))이 예상과 다른 row를 스캔하거나 조용히 실패한다.
for (const item of this.selectedItems()) {
  await db.customer()
    .where((c) => [expr.eq(c.id, item.id)])
    .update(() => ({ isDeleted: del }));
}

// ✅ id != null 만 통과시켜 실제로 DB에 저장된 row만 대상으로 한다.
const targets = this.selectedItems().filter((it) => it.id != null);
for (const item of targets) {
  await db.customer()
    .where((c) => [expr.eq(c.id, item.id!)])
    .update(() => ({ isDeleted: del }));
}
\`\`\`

**근거**: 확장 A의 신규 행(`id == null`)은 DB에 insert되기 전 상태이므로 "선택 삭제"의 의미가 성립하지 않는다. 신규 행 제거는 확장 A의 [`onRemoveNewItemButtonClick`](./extension-a-inline-edit.md)으로 처리한다. `emitAsync`에 넘기는 `ids`도 `it.id!` non-null 단정을 위해 동일 필터가 선행되어야 한다.
```

### 대안 검토

- **대안 1: `useSelectionManager` 외부 중복 인스턴스화 anti-pattern을 `🚫` 블록으로 추가**
  - 기각 사유(사용자 결정): 본 확장은 `useSelectionManager`를 직접 사용하지 않으며, `<sd-sheet>`의 selection 계약만 바인딩한다. "외부 중복 인스턴스화" 전제 자체가 독자에게 인위적이고, WBS의 해당 문구는 본 확장의 실제 흔한 실수 1건을 지칭하는 넓은 레이블로 해석함.
- **대안 2: `[trackByFn]` 생략 anti-pattern을 ❌/✅ 블록으로 추가**
  - 기각 사유: 진입점 2.1의 최소 뼈대가 이미 `trackByFn = (item) => item.id`를 도입한다 (`crud-list.md:211`). 확장 B 고유 실수로 볼 근거가 약함.
- **대안 3: 포인트를 모두 ❌/✅ 블록으로 승격**
  - 기각 사유: 포인트의 "경로 설명" / "selectMode 기본값" / "페이지 선택 유지"는 규칙보다 서술에 가까움. 섹션 남발은 매뉴얼 반-기법.
