## 구현계획

### 배경

현 파일 `extension-c-inline-delete.md`(60줄)은 개정 지침 이전 포맷이다. sibling 확장 B(`extension-b-selection.md`)가 신 지침에 맞춰 번호 단계 diff + 1건 ❌/✅ 승격 포맷으로 재작성되어 있어, 본 확장도 동일 포맷으로 정렬해야 횡단 탐색 시 LLM이 혼란 없이 패턴을 습득한다. 현 파일의 주요 문제:

1. 선행 블록쿼트는 정확하나(L5), 요약이 "확장 B와 공존"이라는 독립 세트 암시 (L7)
2. 적용 조건의 공통 규칙 anchor가 깨짐(`#삭제-방식-soft-delete-vs-물리-삭제` → 현 공통 규칙은 `#삭제-방식은-db-스키마에-따라-결정한다`)
3. 코드 블록이 단일 번호 단계(1→2)만 표기 — sibling B의 0→1→2→3→4 세분 구조와 불일치
4. 🚫 흔한 실수 섹션 부재 — sibling 전반과 불일치
5. 포인트 불릿의 `[inset]/[size]` 언급이 없음 (실제로 본 확장은 `<sd-anchor>`만 사용해 셀 컨트롤 규칙 불해당 — 포인트 재정렬 필요)

### 목표

- 선행 관계(A + B 필수)와 B에 얹는 보완 관계를 선행 블록쿼트·요약·포인트 3지점에 일관되게 분산 [근거: Rule "선행 블록쿼트 필수", Rule "요약 보완 관계", D2·D3]

```
← [CRUD 리스트 레시피 진입점](../crud-list.md)

# 확장 C: inline 삭제/복구 열

> **선행:** [확장 A: inline 편집/저장] + [확장 B: 선택 기능 + 선택 삭제/복구]
  (`isDeleted` 플래그·`selectedItems`·`getItemCellStyleFn` 취소선은 확장 B가 도입)

[요약 문단: B의 다건 일괄 토글 위에 row별 빠른 토글을 추가]

> **적용 조건:** … → [공통 규칙: 삭제 방식](../_common-rules.md#삭제-방식은-db-스키마에-따라-결정한다)

**이 확장이 도입하는 요소:**
- 메서드 `onToggleDeleteItemButtonClick(item)`
- template: 시트 맨 앞에 `[fixed]="true" [key]="'_isDeleted'"` 고정 컬럼 + `#headerTpl`(아이콘 헤더) + `[cell]`(`<sd-anchor>` 토글)
- imports: (필요시 tablerEraser/tablerRestore — 확장 B가 이미 imports에 포함함을 주석)

```typescript
// 1) 메서드 추가
protected onToggleDeleteItemButtonClick(item: ICustomer): void {
  item.isDeleted = !item.isDeleted;
  mark(this.items);
}

// 2) template — <sd-sheet> 가장 앞에 _isDeleted 고정 컬럼 삽입
//    canEdit() && viewType() === "page" 조건부
<sd-sheet ...>
  @if (canEdit() && viewType() === "page") {
    <sd-sheet-column [fixed]="true" [key]="'_isDeleted'">
      <ng-template #headerTpl>…</ng-template>
      <ng-template [cell]="items()" let-item="item">
        <sd-anchor [theme]="'danger'" (click)="onToggleDeleteItemButtonClick(item)">
          <ng-icon [svg]="item.isDeleted ? tablerRestore : tablerEraser" />
          {{ item.isDeleted ? '복구' : '삭제' }}
        </sd-anchor>
      </ng-template>
    </sd-sheet-column>
  }
  <!-- 나머지 컬럼은 확장 A/B와 동일 -->
</sd-sheet>
```

**포인트:**
- row 삭제는 `isDeleted` 플래그 토글 (확장 A/B와 동일 원리). DB 반영은 저장 버튼(확장 A의 `onSaveButtonClick`) 클릭 시 일괄 처리
- **확장 B와의 관계**: B의 상단 바(다건 일괄 토글) + 본 확장의 셀 아이콘(row별 빠른 토글)이 같은 `isDeleted` 플래그를 조작. B의 `getItemCellStyleFn` 취소선이 본 확장의 토글 결과에도 그대로 반영됨
- **`canEdit() && viewType() === "page"` 조건부**: modal/control 뷰·권한 없음이면 열 자체 숨김. 시트 셀 컨트롤 inset/size 규칙 비해당 (`<sd-anchor>`만 사용)
- `mark(this.items)` 호출 이유: [공통 규칙: `mark(sig)`](../_common-rules.md#marksig를-저장-감지-수단으로-사용하지-않는다) 참조

**🚫 흔한 실수**

> 공통 규칙(`mark` 저장 감지 오해, 삭제 방식, modal 뷰 소유 주체 등)은 [레시피 공통 규칙](../_common-rules.md)을 참조한다. 본 섹션은 **inline 삭제/복구 확장 고유 실수**만 다룬다.
