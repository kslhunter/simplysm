### 진입점 2.1 최소 뼈대와 얹기 지점

- `packages/angular/docs/recipes/crud-list.md:39-302` — 확장 F는 이 최소 뼈대에 **얹는 diff**로 기술한다. 단, 확장 A가 덧씌우는 inline 편집 파이프라인을 **혼재 적용하지 않는다**는 점이 확장 F의 고유 성격이다.
- 진입점 L97-102 `hostDirectives: [{ directive: SdCommandDirective, outputs: ["sdRefreshCommand"] }]` — 확장 F는 여기에 **변경 없음**(저장 경로 없으므로 `sdSaveCommand` 추가하지 않음)
- 진입점 L167-178 이름 컬럼 셀 — 확장 F는 이 셀을 `<sd-anchor>` + `tablerEdit` 아이콘으로 교체하여 행 클릭 시 편집 모달을 연다

### 상호 배타 관계 (확장 A와)

- 확장 A(`extension-a-inline-edit.md`)가 도입하는 `diffs` / `_itemsSnapshot` / `onSubmit` / `setupCanDeactivate` / `hostDirectives.sdSaveCommand` / `<sd-form #formCtrl>` 파이프라인은 확장 F에서는 **부착하지 않는다** (이미 부착되어 있다면 제거한다).
- 두 확장이 가진 "편집" 목적은 같으나 경로가 달라, 혼합 적용은 Ctrl+S가 어느 폼을 submit할지 모호해지고 `setupCanDeactivate`가 모달 open 중에 이중 발동한다.

### 공통 규칙 반영

- `_common-rules.md` "시트 셀 내부 컨트롤에 `[inset]="true" [size]="'sm'"` 명시" — 확장 F의 이름 셀은 `<sd-anchor>`이므로 해당 규칙과 무관(inset 컨트롤이 아님). 재서술하지 않는다.
- `_common-rules.md` "`mark(sig)`를 '저장 감지'로 오해하지 않는다" — 확장 F는 diff 개념이 없으므로 본 섹션 해당사항 없음. 재서술 금지.

## 구현계획

### 배경

현행 `packages/angular/docs/recipes/crud-list/extension-f-modal-edit.md`(111줄)는 diff 스타일 템플릿을 이미 충족하지만, (a) `_common-rules.md`와의 링크 위임이 아직 없고, (b) `🚫 흔한 실수` 서브섹션이 부재하며, (c) 상호 배타 명시가 한 문장(L7)에만 집중되어 있다. 본 Feature는 **파일 구조를 sibling 재작성본(`crud-detail/extension-b-delete-restore.md`) 및 Feature 3.2 확정 패턴과 완전 일치**시키고, WBS 2.7 범위가 요구하는 "❌/✅ 확장 A와 동시 적용 금지" 안티패턴을 신설한다.

### 목표

- sibling과 동일한 diff 스타일 템플릿 정합 [근거: Rule "diff 스타일 템플릿"]
- 진입점 2.1 최소 뼈대와 정합하는 diff(이름 컬럼 교체, imports/DI 추가, 메서드 교체) [근거: Rule "진입점 2.1 최소 뼈대와 정합"]
- 상호 배타 관계를 **3회 이상** 명시 (선행 블록쿼트 · 요약 · Anti-patterns) [근거: Rule "상호 배타 관계"]

- **시트 `[cell]` 템플릿에 `let-edit="edit"` / `[readonly]="!edit"`는 불필요** — inline 편집이 아니며 읽기 전용 표시만 한다.
- **"선택 삭제/복구"를 남길 경우 (확장 B와 병용)** `onToggleDeleteItemsButtonClick(del)` 내부를 diff 방식 대신 **bulk API 호출 + `_refresh()`** 로 구현한다:
  \`\`\`typescript
  protected async onToggleDeleteItemsButtonClick(del: boolean): Promise<void> {
    if (this.busyCount() > 0) return;
    const ids = this.selectedItems().map((it) => this.trackByFn(it)).filterExists();
    if (ids.length === 0) return;

    this.busyCount.update((v) => v + 1);
    await this._sdToast.try(async () => {
      await this._appOrm.connectAsync((db) =>
        db.customer().where((c) => [expr.in(c.id, ids)])
          .updateAsync(() => ({ isDeleted: del })));
      await this._appSharedData.emitAsync(this.SHARED_DATA_KEY, ids);
      this._sdToast.success(\`${del ? "삭제" : "복구"}되었습니다.\`);
      await this._refresh();
    });
    this.busyCount.update((v) => v - 1);
  }
  \`\`\`
- **`itemId: item?.id`**: `item`이 undefined이면 "등록", id가 있으면 "수정"으로 위임한다. `CustomerEditModal` 내부에서 id 유무로 분기한다.
