### 공통 규칙 반영

- `_common-rules.md` "⚠️ Ask first — 공유 데이터 사용 화면은 `_refresh()` 선두에서 `_sdSharedData.wait()`를 호출한다" — 본 확장은 `useSharedSignal` / `getHandle`을 **도입**하므로 판정 결과가 '호출한다'로 전환된다. 본문에 재서술하지 않고 1-hop 링크로 위임하되, 포인트에서 1줄 주의 서술.

## 구현계획

### 배경

현행 `packages/angular/docs/recipes/crud-detail/extension-e-auxiliary.md`(78줄)는 이미 sibling diff 스타일 템플릿 골격을 따르고 있고, 보조 `<sd-form>`의 메인 폼 분리·`_checkIgnoreChanges` 재호출·읽기 전용 대안 3가지 포인트를 정확히 담고 있다. 개정 필요한 부분은 (a) 진입점/확장 A가 Feature 3.1·3.2에서 재작성된 뒤 도입 요소 명세(예: `canEdit`, `_checkIgnoreChanges`, `formCtrl`)가 확정되었으므로 그 표기와 정합화, (b) `useSharedSignal` 도입으로 공통 규칙 "`_sdSharedData.wait()` 조건"을 1-hop 링크로 반영, (c) 3인칭 서술 정돈, (d) 불필요한 경로(`../../ui-form/sd-shared-data-select.md` 존재 여부 불명) 링크 재검증으로 한정된다. 본문 동작(보조 form 분리, 권한 복사 예시, 읽기 전용 패턴)은 보존한다.

### 목표

- sibling extension-b와 동일한 diff 스타일 템플릿(브레드크럼 / 제목 / 선행 / 요약 / 도입 요소 / 번호 코드 / 포인트) 일치 [근거: Rule "sibling과 동일한 diff 스타일 템플릿"]
- 확장 A와 diff 정합(메인 `#formCtrl`과 분리, `_checkIgnoreChanges` 재사용, `canEdit` 재사용) [근거: Rule "확장 A / 최소 뼈대와 정합"]
- `_sdSharedData.wait()` 조건을 공통 규칙 링크로 1-hop 위임 [근거: Rule "공유 데이터 대기 조건을 공통 규칙으로 위임"]
- `🚫 흔한 실수` 서브섹션 생성하지 않음, 주의사항은 포인트 불릿만 [근거: 설계 결정 D2]
- 소스 시그니처(SdSharedDataSelect, SdForm.formSubmit) 재검증 [근거: Rule "시그니처 정합성"]
- 78줄 → 대략 90~110줄 범위 (포인트 1~2항목 보강 상쇄)

- modal 하단 바·control 상단 바의 뷰 분기 본문 확장 — 각 Feature 3.4(확장 C) / 3.5(확장 D) 범위
- 복합 상세(내부 시트) 보조 영역 — Feature 3.7(확장 F) 범위
- `SdSharedDataProvider` 자체 문서 개정 — 본 Feature 범위 외
- 새로운 Anti-patterns 섹션 신설 — 설계 결정 D2로 기각

### 설계

#### 파일 구조 (sibling extension-b와 동일 템플릿)

```markdown
← [CRUD 상세폼 레시피 진입점](../crud-detail.md)

# 확장 E: 보조 기능 영역

> **선행:** [확장 A: 편집/저장](./extension-a-edit-save.md)

{1~2문장 요약 — 메인 submit과 별개인 보조 기능을 보조 `<sd-form>`으로 분리하여
추가한다. 배치는 control 뷰 상단 바 / modal 뷰 하단 바 옆 / main 영역 내 중 하나를 선택한다.
뷰별 UI는 [확장 C](./extension-c-modal-view.md) / [확장 D](./extension-d-control-view.md)
에서 처리한다.}

**이 확장이 도입하는 요소:**

- **imports:** `SdSharedDataSelect` (`@simplysm/angular`), 앱 공용 `useSharedSignal` (예: `@adtek/client-common`)
- **상태:** `permCopySourceId = signal<number | undefined>(undefined)`, `sharedUsers = useSharedSignal("사용자")`
- **메서드:** `onImportFormSubmit` — `_checkIgnoreChanges()` 선점 + 권한·busy 가드 + 앱별 ORM 조회/병합
- **템플릿 추가:** 보조 `<sd-form (formSubmit)="onImportFormSubmit()">` 블록을 control 뷰 `<sd-dock>` 내부에 배치(예시). 메인 `<sd-form #formCtrl>`과 **별도**
- **공유 데이터 대기:** `_refresh()` 선두에 `await this._sdSharedData.wait();` → [공통 규칙: `_sdSharedData.wait()`](../_common-rules.md#공유-데이터-사용-화면은-_refresh-선두에서-_sdshareddatawait를-호출한다)

```typescript
// 1) imports 추가
// 2) 상태 추가 (permCopySourceId, sharedUsers)
// 3) template — 보조 <sd-form> 블록 (control 뷰 <sd-dock> 내부 예시)
// 4) onImportFormSubmit 메서드 추가
\```

**포인트:**

- **보조 `<sd-form>`은 메인 `<sd-form #formCtrl>`과 별도 인스턴스**다. `SdCommandDirective.sdSaveCommand` → `formCtrl()?.requestSubmit()` 경로는 메인 form 한 곳에만 연결된다. 보조 form의 submit 버튼은 Ctrl+S와 연동되지 않고 버튼 클릭(또는 Enter 제출)만 발동한다.
- **보조 작업 전에도 `_checkIgnoreChanges()`를 호출**하여 메인 폼의 미저장 변경사항을 보호한다. 보조 form이 메인 `data()`를 덮어쓰는 경우(권한 복사 등) 필수.
- **공유 데이터 도입으로 `_refresh()` 선두에 `await this._sdSharedData.wait();`가 필요해진다.** 판정 기준·코드 예시는 [공통 규칙: `_sdSharedData.wait()`](../_common-rules.md#공유-데이터-사용-화면은-_refresh-선두에서-_sdshareddatawait를-호출한다) 참조.
- **`<sd-shared-data-select>`는 시트 셀이 아니더라도 `[inset]="true" [size]="'sm'"`으로 `<sd-dock>` 내부 치수에 맞춘다** — `<sd-dock>` 도구 바 안에서는 sm 크기가 기본 간격과 정합한다.
- **배치 위치 선택:** control 뷰는 상단 `<sd-dock>` 안, modal 뷰는 하단 바(`<sd-dock [position]="'bottom'">`) 옆, main 영역에서는 메인 form과 나란한 별도 블록. 뷰 분기 본문 UI는 [확장 C](./extension-c-modal-view.md) / [확장 D](./extension-d-control-view.md)에서 정의한다.
- **읽기 전용 보조(출력·엑셀 다운로드 등)는 `<sd-form>` 래핑 없이 버튼 `(click)`으로 처리 가능**하다. 입력 값을 수집하지 않는 단일 액션은 form submit 절차가 불필요하다.
- **`useSharedSignal`은 `@simplysm/angular` 제공이 아님** — `SdSharedDataProvider` 위에서 각 앱이 정의하는 공용 훅이다. 배포 패키지가 다르므로 import 경로 혼동에 주의.
\```

#### 수정 · 축약 내역 (원문 78줄 대비)

- **상단 헤더 블록:** 원문 동일(브레드크럼 / 제목 / 선행). 유지.
- **요약 문장 2~3인칭 정돈:** "추가한다 / 배치한다" 중심. 뷰 분기 1-hop 링크 추가(`확장 C` / `확장 D`).
- **도입 요소 블록:** 확장 A와 중복되는 요소(예: `busyCount`, `perms`, `_sdToast`, `_checkIgnoreChanges`)는 열거하지 않는다. 보조 `<sd-form>`과 "공유 데이터 대기" 한 줄 추가.
- **코드 블록:** 원문 4단계 유지. 각 단계 주석을 3인칭 서술로 미세 조정. `<sd-shared-data-select>` 입력(`[items] [(value)] [inset] [size]`) 소스와 재정합. `@if (viewType() === "control" && canEdit())` 분기는 예시임을 명시(뷰 배치 1종).
- **포인트 불릿:** 원문 3항목에 (a) `_sdSharedData.wait()` 링크, (b) `<sd-shared-data-select> [inset][size]` 정합, (c) `useSharedSignal`의 앱 공용 소속, (d) 뷰별 배치 옵션 1-hop 4항목을 추가해 총 7항목. sibling extension-b(6항목) 수준 유지.
- **`> 상세: [...]` 링크:** 원문의 `../../ui-form/sd-shared-data-select.md` 링크는 실제 파일 존재 여부 확인 후, 없으면 제거하거나 유효 경로로 교체한다.
- **Anti-patterns 서브섹션:** 생성하지 않음 (설계결정 D2).

### 대안 검토

- **대안 1: `🚫 흔한 실수` 섹션 신설 (포인트 중 1~2건을 ❌/✅ 블록으로 승격)**
  - 기각 사유: 사용자 결정(2026-04-23)으로 포인트 유지 선택. WBS 3.6 범위에 `❌/✅` 명시 없음. sibling extension-b와 구조 일관성 유지.
- **대안 2: `useSharedSignal`을 `@simplysm/angular` 재수출 제안**
  - 기각 사유: 본 Feature는 문서 재작성. 패키지 API 변경은 범위 외. `useSharedSignal`은 도메인별 키("사용자")에 의존하므로 앱 공용 훅 성격이 맞다.
- **대안 3: 3가지 배치 위치(control/modal/main)를 모두 코드 예시로 나열**
  - 기각 사유: 뷰 분기 본문은 확장 C/D가 담당. 예시 3배는 중복 증가 + 반-기법 "죽은 코드" 유도. 포인트 불릿 1-hop 링크로 충분.
