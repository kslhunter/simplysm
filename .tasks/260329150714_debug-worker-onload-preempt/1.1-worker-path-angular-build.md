## 구현계획

### 배경

`SdWorkerPathPlugin`은 esbuild `onLoad`에서 `import.meta.resolve("...worker")` 패턴을 감지하여 워커 파일을 별도 빌드하고 경로를 치환하는 플러그인이다. Angular 빌드에서는 `createSdNgPlugin`의 `onLoad`가 모든 `.ts` 파일을 선점하여 이 플러그인이 실행되지 않는다. 또한 치환 결과가 런타임 `import.meta.resolve()` 호출을 유지하여, esbuild의 Chrome >= 61 target polyfill에서 `resolve` 메서드가 누락되는 문제가 있다.

### 목표

- 워커 경로 변환 로직을 순수 함수로 추출하여 Angular/서버 빌드 모두에서 재사용
- 변환 결과에서 `import.meta.resolve()` 제거 → string literal 출력
- Angular 빌드에서 워커 파일 정상 빌드 및 경로 변환

### 비목표

- 브라우저 target 변경 (Chrome >= 61 유지)
- 워커 로딩 아키텍처 변경 (Web Worker / Worker Threads 패턴 유지)
- `SdServiceClientProtocolWrapper.ts` 소스 코드 변경

### 설계

#### 추출할 함수: `transformWorkerPaths`

```typescript
// SdWorkerPathPlugin.ts에서 export
export async function transformWorkerPaths(
  source: string,
  filePath: string,
  outdir: string,
  buildOptions: esbuild.BuildOptions,
): Promise<string>
```

- `source`: 소스 텍스트 (JS/TS)
- `filePath`: 소스 파일 경로 (상대 경로 해석용)
- `outdir`: 워커 빌드 출력 디렉토리
- `buildOptions`: esbuild.build()에 전달할 기본 옵션 (build.initialOptions)
- **반환값:** 변환된 소스 텍스트 (매칭 없으면 원본 그대로)

#### 변환 출력 변경

```
// Before (현재)
import.meta.resolve("./workers/client-protocol.worker-{hash}.js")

// After (수정)
"./workers/client-protocol.worker-{hash}.js"
```

#### createSdNgPlugin 통합

```typescript
// createSdNgPlugin.ts onLoad 내부 (line 93 이후)
const contents = emittedFiles?.last()?.text ?? "";
const workerContents = await transformWorkerPaths(contents, args.path, workerOutdir, build.initialOptions);
// ... 이후 workerContents를 Angular transform에 전달
```

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| 변환 함수 추출 + createSdNgPlugin 통합 | 채택 | onLoad 선점 문제를 근본적으로 해결, 서버 빌드와 함수 공유 |
| 플러그인 순서 변경 (SdWorkerPathPlugin을 앞으로) | 미채택 | SdWorkerPathPlugin이 파일을 claim하면 Angular TS 컴파일이 누락됨 |
| 소스 코드에서 import.meta.resolve() 제거 | 미채택 | 플러그인의 regex 매칭 기반 워커 자동 감지/빌드 메커니즘이 무력화됨 |
