### 기술 컨텍스트

- 대상 파일: `packages/sd-excel/src/legacy/SdExcelReader.ts`
- xlsx 버전: 0.20.3 (CDN tgz)
- xlsx의 `set_cptable()` API로 codepage 테이블을 등록해야 ESM 환경에서 codepage 디코딩이 동작함
- xlsx 패키지 내 `dist/cpexcel.full.mjs`에 codepage 테이블이 포함되어 있음
- `$cptable`은 xlsx 모듈 스코프 변수이므로 `set_cptable()`을 한 번 호출하면 이후 모든 `XLSX.read()` 호출에 적용됨

## 구현계획

### 배경

`SdExcelReader`는 xlsx 라이브러리의 `XLSX.read()`를 `codepage: 949` 옵션과 함께 호출한다. xlsx의 codepage 디코딩은 내부 `$cptable` 변수에 의존하는데, ESM 환경에서는 이 변수가 자동 설정되지 않아 `set_cptable()`을 명시적으로 호출해야 한다.

### 목표

- ESM 환경에서 codepage 테이블을 자동 로드하여 경고 제거 및 정상 디코딩 보장

### 비목표

- xlsx 라이브러리 교체 또는 업그레이드
- SdExcelReader의 다른 기능 변경

### 설계

`SdExcelReader.ts` 모듈 최상위에서 cpexcel을 import하고 `XLSX.set_cptable()`을 호출한다:

```typescript
import * as XLSX from "xlsx";
import * as cpexcel from "xlsx/dist/cpexcel.full.mjs";
XLSX.set_cptable(cpexcel);
```

모듈 스코프에서 한 번 호출되므로, 이후 모든 `XLSX.read()` 호출에 자동 적용된다.

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| cpexcel 명시적 import + set_cptable() | 채택 | xlsx 공식 권장 방법 |
| codepage 옵션 제거 | 미채택 | 비-ASCII 문자 깨짐 발생 |
