## 구현계획

### 배경

Feature 1.1에서 생성된 `SdTsCompiler`(`src/ts-compiler/SdTsCompiler.ts`)는 tsconfig 파싱, rootNames 필터링, 프로그램 생성(Angular/Non-Angular)을 통합했다. 현재 SCSS 처리와 lint는 각 워커(`library-build.worker.ts:73-82`, `ngtsc-build.worker.ts:114-123`)에서 개별 관리되어 거의 동일한 코드가 중복 존재한다. [근거: WBS "lint 통합 패턴이 두 워커에서 거의 동일하게 중복"]

### 목표

- `SdTsCompiler.compileAsync()`에서 SCSS 번들링과 lint를 통합 실행 [근거: Rule "lint 옵션이 lint 실행 제어"]
- SCSS 의존성/에러를 내부에서 일관 관리 [근거: Rule "SCSS 상태는 매 compileAsync마다 리셋"]
- 라이브러리 모드에서 SCSS 콜백 자동 생성으로 호출부 중복 제거 [근거: Rule "transformStylesheet 미제공 시 내부 생성"]

### 비목표

- 클라이언트의 PostCSS 통합 — 외부 주입 유지 [근거: WBS 경계]
- emit 통합 — Feature 1.2 범위 [근거: WBS Feature 1.2]
- 워커 호출부 변경 — Epic 2 범위 [근거: WBS Epic 2]
- ESLint 설정/규칙 변경 [근거: WBS 경계]

**5. compileAsync 흐름 변경**

```

 2. (기존) tsconfig 파싱
 3. (기존) rootNames 필터링
 4. (기존) compilerOptions 구성
 5. (신규) SCSS 상태 리셋: _scssErrors.length = 0, _scssDependencies.clear()
 6. (신규) transformStylesheet 결정:
         isForAngular + 미제공 → createLibraryTransformStylesheet(loadPaths, _scssErrors, _scssDependencies)
         loadPaths = [path.join(pkgDir, "scss"), path.join(cwd, "node_modules")]
 7. (기존) host 생성 (6에서 결정된 콜백 → _extendHostForAngular 전달)
 8. (기존) program 생성 + analyzeAsync
 9. (신규) 병렬 실행:
         Promise.all([
           globalScss ? compileGlobalScss(pkgDir, loadPaths) 에러를 _scssErrors에 병합 : Promise.resolve(),
           lint ? this._runLint(program) : Promise.resolve(undefined),
         ])
10. (신규) 결과 구성: { ...기존, lint, scssErrors: [..._scssErrors], scssDependencies: new Map(_scssDependencies) }
```
