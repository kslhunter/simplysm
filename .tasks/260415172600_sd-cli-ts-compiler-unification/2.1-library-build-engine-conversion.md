## 구현계획

### 배경

`library-build.worker.ts`는 non-Angular 라이브러리 패키지(node/browser/neutral)의 빌드를 담당하는 Worker Thread 모듈이다. 현재 `runTscPackageBuild()` 함수를 직접 호출하고(`library-build.worker.ts:64,119`), lint를 별도 `LintWithProgramRunner`로 실행하며(`library-build.worker.ts:77-81,136-146`), watch 모드에서 `lastBuilderProgram`을 수동 관리한다(`library-build.worker.ts:104,127`). [근거: 소스코드 확인]

Epic 1(Feature 1.1~1.3)에서 생성된 `SdTsCompiler`는 tsconfig 파싱, 프로그램 생성, emit, 진단, lint를 모두 `compileAsync()` 하나로 통합하며, builderProgram을 내부에서 관리한다(`SdTsCompiler.ts:64,288`). [근거: 소스코드 확인]

### 목표

- `library-build.worker.ts`의 컴파일 로직을 `SdTsCompiler`로 교체한다 [근거: Rule "build()/startWatch()는 SdTsCompiler를 통해 컴파일"]
- `lastBuilderProgram` 수동 관리를 제거한다 [근거: Rule "lastBuilderProgram은 SdTsCompiler 내부에서 관리"]
- `LintWithProgramRunner` 직접 사용을 제거한다 [근거: Rule "lint는 SdTsCompiler options.lint로 제어"]
- 워커 외부 인터페이스를 유지한다 [근거: Rule "워커 외부 인터페이스는 변경하지 않는다"]

### 비목표

- `TscEngine.ts` 구조 변경 [근거: WBS 경계 "TscEngine.ts 자체의 구조 변경은 최소화"]
- `runTscPackageBuild` 함수 제거 [근거: WBS Feature 3.1 범위]
- `build-change-filter.ts`, `build-watch-paths.ts` 변경 [근거: WBS 경계]

### 설계

**모듈 스코프 변수 변경:**

| 변수 | 현재 | 전환 후 |
|---|---|---|
| `lastBuilderProgram` | `ts.EmitAndSemanticDiagnosticsBuilderProgram` | **제거** (SdTsCompiler 내부 관리) |
| `watchLintRunner` | `LintWithProgramRunner` | **제거** (SdTsCompiler 내부 관리) |
| `lastSourceFilePaths` | `Set<string>` | **유지** (shouldSkipRebuild에서 사용) |
| `fsWatcher` | `FsWatcher` | **유지** |
| `watchInfo` | `LibraryBuildInfo` | **유지** |
| (신규) `compiler` | — | `SdTsCompiler \| undefined` |

**build() 전환:**

```typescript
async function build(info: LibraryBuildInfo): Promise<LibraryBuildResult> {
  compiler = new SdTsCompiler({
    pkgDir: info.pkgDir,
    cwd: info.cwd,
    output: { js: info.output.js, dts: info.output.dts },
    includeTests: info.output.includeTests,
    env: info.output.env,
    lint: info.output.lint,
  });
  const result = await compiler.compileAsync();
  return { build: { ... }, lint: result.lint };
}
```

**rebuildAll() 전환:**

```typescript
async function rebuildAll(modifiedFiles?: ReadonlySet<string>): Promise<CombinedBuildEvent> {
  const result = await compiler!.compileAsync(modifiedFiles);
  lastSourceFilePaths = extractSourceFilePaths(result.program) ?? lastSourceFilePaths;
  return { build: { ... }, lint: result.lint };
}
```

**onChange 콜백 변경:**

```typescript
fsWatcher.onChange({ delay: 300 }, async (changes) => {
  // ... shouldSkipRebuild 체크 (기존과 동일)
  const modifiedFiles = new Set(changes.map((c) => c.path));
  const result = await rebuildAll(modifiedFiles);
  // ...
});
```

### 대안 검토

| 대안 | 설명 | 미선택 사유 |
|---|---|---|
| build()에서 로컬 SdTsCompiler 사용 | build() 내부 로컬 변수로 생성, 모듈 스코프 미사용 | watch와 패턴 통일을 위해 모듈 스코프 사용. 기능적 차이 없으나 일관성 우선 |
| modifiedFiles 미전달 | rebuildAll()에서 compileAsync(undefined) 고정 호출 | packageJsonCache 클리어 누락 가능. API 계약 존중 |
