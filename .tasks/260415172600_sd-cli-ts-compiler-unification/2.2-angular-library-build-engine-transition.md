## 구현계획

### 배경

`ngtsc-build.worker.ts`는 현재 `AngularBuildPipeline`을 사용하여 Angular AOT 컴파일을 수행한다. Feature 1.x에서 `SdTsCompiler`가 tsconfig 파싱, rootNames 필터링, 프로그램 생성(Angular 자동 감지), 진단 수집, emit, SCSS 번들링, lint를 모두 통합했다. 이 Feature에서는 워커 내부 구현을 `SdTsCompiler`로 교체한다. [근거: WBS "AngularBuildPipeline 전체가 SdTsCompiler로 대체"]

### 목표

- `ngtsc-build.worker.ts`의 `build()` 함수에서 `AngularBuildPipeline` → `SdTsCompiler` 전환 [근거: Rule "build()에서 SdTsCompiler가 대체"]
- `startWatch()` 함수에서 `AngularBuildPipeline` → `SdTsCompiler` 전환 + watch 루프 단순화 [근거: Rule "startWatch()에서 SdTsCompiler가 처리"]
- 워커 API (NgtscBuildInfo, NgtscBuildResult, NgtscCombinedBuildEvent) 유지 [근거: Rule "워커 API 유지"]

### 비목표

- `NgtscEngine.ts` 구조 변경 [근거: WBS 경계 "워커 내부만 변경"]
- `angular-build-pipeline.ts`의 `writeEmitResults` 함수 이동 [근거: D3, Feature 3.1 범위]
- `TscEngine`/`library-build.worker.ts` 변경 [근거: Feature 2.1 범위]
- `build-change-filter.ts` 변경 [근거: WBS 경계]

### 설계

**1. NgtscBuildInfo → ISdTsCompilerOptions 매핑** [근거: Rule "build()에서 SdTsCompiler가 대체"]

```typescript
// build(), startWatch() 공통 매핑
function createCompiler(info: NgtscBuildInfo): SdTsCompiler {
  return new SdTsCompiler({
    pkgDir: info.pkgDir,
    cwd: info.cwd,
    output: { js: info.output.js, dts: info.output.dts },
    includeTests: info.output.includeTests,
    env: info.output.env,
    lint: info.output.lint,
    globalScss: true, // Angular 라이브러리는 항상 글로벌 SCSS 컴파일 [근거: D4]
  });
}
```

**2. build() 함수 전환** [근거: Rule "build()에서 SdTsCompiler가 대체"]

현재 흐름:
```
parseTsconfig → getPackageSourceFiles → buildCompilerOptions → AngularBuildPipeline 생성
→ pipeline.initialize() → pipeline.writeEmitResults() → compileGlobalScss
→ pipeline.collectRawDiagnostics() → serializeDiagnostic → lint
```

전환 후:
```
SdTsCompiler 생성 → compiler.compileAsync()
→ writeEmitResults(result.emitResults) → 결과 NgtscBuildResult로 변환
```

- tsconfig 파싱, rootNames, compilerOptions, Angular 감지, globalScss, lint는 모두 `compileAsync()` 내부에서 처리
- `result.diagnostics`는 이미 직렬화됨 → 별도 `serializeDiagnostic` 불필요
- `result.errors`에 ts 에러, `result.scssErrors`에 SCSS 에러 → 병합하여 `NgtscBuildResult.build.errors` 구성
- emit 디스크 쓰기: `writeEmitResults(result.emitResults, pkgDir)` — build에서는 scss 옵션 미전달 [근거: Scenario "build() 모드에서 side-effect SCSS 미처리"]

**3. startWatch() 함수 전환** [근거: Rule "startWatch()에서 SdTsCompiler가 처리"]

현재 상태 관리:
```typescript
// 제거 대상
let _watchPipeline: AngularBuildPipeline | undefined;
let watchLintRunner: LintWithProgramRunner | undefined;
const sideEffectScssRegistry = new Map<string, SideEffectScssEntry>();
// AngularSourceFileCache 직접 생성
```

전환 후 상태:
```typescript
let watchCompiler: SdTsCompiler | undefined;
// 통합 SCSS deps 맵 (compile-time + side-effect)
let combinedScssDeps = new Map<string, Set<string>>();
```

`AngularSourceFileCache`, `LintWithProgramRunner`, `sideEffectScssRegistry`는 `SdTsCompiler` 내부에서 관리.

**4. buildWatchEvent 단순화** [근거: Rule "startWatch()에서 SdTsCompiler가 처리"]

현재: pipeline.writeEmitResults + compileSideEffectScss + compileGlobalScss + pipeline.getDiagnostics + lint (약 60줄)

전환 후:
```typescript
async function buildWatchEvent(
  info: NgtscBuildInfo,
  compiler: SdTsCompiler,
  result: ISdTsCompilerResult,
  hasScssChanges: boolean,
): Promise<NgtscCombinedBuildEvent> {
  const normalizedSrcDir = pathx.posix(path.join(info.pkgDir, "src"));
  const loadPaths = [path.join(info.pkgDir, "scss"), path.join(info.cwd, "node_modules")];
  const sideEffectScssErrors: string[] = [];

  // 1. emit 결과 디스크 쓰기 (side-effect SCSS 등록 포함)
  if (result.emitResults != null) {
    writeEmitResults(
      result.emitResults.filter(r => pathx.posix(r.sourceFileName).startsWith(normalizedSrcDir + "/")),
      info.pkgDir,
      { loadPaths, scssErrors: sideEffectScssErrors, scssDependencies: combinedScssDeps, registry: compiler.sideEffectScssRegistry },
    );
  }

  // 2. SCSS 변경 시 side-effect SCSS 재컴파일
  if (hasScssChanges) {
    compileSideEffectScssEntries(compiler.sideEffectScssRegistry, loadPaths, sideEffectScssErrors, combinedScssDeps);
  }

  // 3. 모든 에러 통합
  const allErrors = [...(result.errors ?? []), ...result.scssErrors, ...sideEffectScssErrors];

  return {
    build: {
      success: (result.errorCount === 0) && result.scssErrors.length === 0 && sideEffectScssErrors.length === 0,
      errors: allErrors.length > 0 ? allErrors : undefined,
    },
    lint: result.lint,
  };
}
```

**5. onChange 핸들러의 SCSS 역방향 탐색** [근거: D1, Rule "통합 deps 맵"]

```typescript
// 통합 deps 맵 갱신: compileAsync 결과의 compile-time deps 반영
function updateCombinedScssDeps(result: ISdTsCompilerResult): void {
  // compile-time deps로 초기화 (writeEmitResults/compileSideEffectScss가 추가)
  combinedScssDeps = new Map();
  for (const [file, deps] of result.scssDependencies) {
    combinedScssDeps.set(file, new Set(deps));
  }
}

// onChange에서:
for (const f of changedFiles) {
  modifiedFiles.add(f.path);
  if (f.path.endsWith(".scss") || f.path.endsWith(".css")) {
    // 통합 deps 맵에서 역방향 탐색
    const normalizedPath = pathx.posix(f.path);
    for (const [ownerFile, deps] of combinedScssDeps) {
      if (deps.has(normalizedPath)) {
        modifiedFiles.add(ownerFile);
      }
    }
  }
}
```

**6. rootNames 자동 재스캔** [근거: Scenario "파일 추가/삭제 시 rootNames 자동 재스캔"]

현재:
```typescript
if (addOrRemove) {
  const newParsedConfig = parseTsconfig(watchInfo!.pkgDir);
  const newSourceFiles = ...;
  pipeline.updateRootNames(newSourceFiles);
}
```

전환 후: `SdTsCompiler.compileAsync()`가 매 호출 시 `parseTsconfig` + `_filterRootNames`를 실행하므로 별도 처리 불필요. `addOrRemove` 체크는 `shouldSkipRebuild`용으로만 유지.

### 대안 검토

| 접근 | 선택 | 이유 |
|---|---|---|
| SdTsCompiler의 _scssDependencies를 외부에 노출 (getter) | 미선택 | 캡슐화 위반, SdTsCompiler가 compileAsync마다 리셋하므로 외부에서 추가한 값도 소실 |
| compiler.compileSideEffectScss() 사용 | 미선택 | compileAsync 이후에 호출하면 에러가 이미 스냅샷된 result.scssErrors에 반영 안 됨. 워커가 직접 수집하는 것이 안전 |
| 워커가 통합 deps 맵 관리 (compile-time + side-effect) | **선택** | 현재 pipeline.getScssDependencies() 패턴과 동일. 역방향 탐색이 모든 SCSS 의존성을 포괄 |
