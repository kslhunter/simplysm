| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|

## 구현계획

### 배경

Angular AOT 빌드 파이프라인이 3곳에 분산되어 동일 패턴을 별도 구현하고 있다:

1. `vite-angular-plugin.ts` buildStart (client dev/build) — SCSS async 콜백 + AngularCompiler + memory emit + 진단
2. `vitest-plugin.ts` buildStart (test) — SCSS sync 콜백 + NgtscProgram 직접 사용 + memory emit (Linker 누락, PostCSS 누락)
3. `ngtsc-build-core.ts` runNgtscBuild + `ngtsc-build.worker.ts` startWatch (library) — SCSS sync 콜백 + AngularCompiler + disk emit + 진단

중복 코드:
- `findAffectedByScss` — `vite-angular-plugin.ts:60-71`과 `ngtsc-build.worker.ts:268` 동일 로직
- `scssDependencies Map<string, Set<string>>` — 3곳 동일 구조
- 진단 수집 (isWorkspaceDiagnostic 필터 → 에러/경고 분류) — 2곳 동일 패턴
- SCSS 콜백 생성 + AngularCompiler 초기화 — 3곳 동일 흐름

### 목표

- SCSS 콜백 생성, AngularCompiler 라이프사이클, emit 수집, 진단, SCSS 의존성 추적을 `AngularBuildPipeline` 클래스로 통합 [근거: WBS "통합된 Angular 빌드 파이프라인 클래스"]
- `mode: "client" | "library"`로 SCSS 동작(async/sync, PostCSS 유무, 캐시 유무)을 자동 선택 [근거: WBS "모드에 따라"]
- `getPackageSourceFiles()`에 `includeFixtures` 옵션 추가하여 `.fixture.ts` 파일 포함 지원 [근거: WBS "getPackageSourceFiles() 확장"]

### 비목표

- watch/HMR 전략 변경 — 호출자가 `update()` 직접 호출 [근거: WBS 경계]
- `JavaScriptTransformer` 통합 — Vite 플러그인 고유 기능 [근거: WBS 경계]
- global SCSS 컴파일 — NgtscEngine worker 고유 기능 [근거: WBS 경계]
- `createLibraryTransformStylesheet`/`writeEmitResults` 함수의 물리적 이동 — Feature 1.3에서 수행 [근거: WBS Feature 1.3 범위]

### 설계

#### 1. AngularBuildPipelineOptions 인터페이스 [근거: D2 "mode enum"]

```typescript
interface AngularBuildPipelineOptions {
  /** Pipeline 모드. SCSS 콜백 동작을 결정한다. */
  mode: "client" | "library";
  /** 패키지 디렉토리 (tsconfig.json 위치) */
  pkgDir: string;
  /** workspace 루트 */
  cwd: string;
  /** 소스 파일 목록 */
  rootNames: string[];
  /** TypeScript 컴파일러 옵션 */
  compilerOptions: ts.CompilerOptions;
  /** Angular 컴파일러 옵션 */
  angularCompilerOptions?: Record<string, unknown>;

  // AngularCompiler 전달 옵션
  sourceFileCache?: AngularSourceFileCache;
  externalStylesheets?: Map<string, string>;
  enableHmr?: boolean;
  compilerOptionsTransformer?: (opts: ts.CompilerOptions) => ts.CompilerOptions;

  // client 모드 전용
  postCssPlugins?: unknown[];
  scssCacheDir?: string;
}
```

호출자가 `rootNames`를 직접 제공한다. `getPackageSourceFiles()` (확장 후 `includeFixtures` 옵션 포함)로 계산.

#### 2. PipelineResult / PipelineDiagnosticResult [근거: D4 "통합 포맷"]

```typescript
interface PipelineDiagnosticMessage {
  file?: string;
  line?: number;
  message: string;
}

interface PipelineDiagnosticResult {
  errors: PipelineDiagnosticMessage[];
  warnings: PipelineDiagnosticMessage[];
}

interface PipelineResult {
  affectedFiles: ReadonlySet<ts.SourceFile>;
  templateUpdates?: Map<string, string>;
  diagnostics: PipelineDiagnosticResult;
  scssErrors: string[];
}
```

`PipelineDiagnosticMessage`는 `vite-angular-plugin.ts`의 `DiagnosticMessage`와 동일 구조. `ngtsc-build-core.ts`의 호출처는 `errors.map(e => e.message)` 또는 `formatDiagnosticError()`로 변환.

#### 3. AngularBuildPipeline 클래스

```typescript
class AngularBuildPipeline {
  private _compiler: AngularCompiler | undefined;
  private readonly _scssDependencies = new Map<string, Set<string>>();
  private readonly _scssErrors: string[] = [];
  private readonly _emittedFilesBySource = new Map<string, string>();
  private _latestEmitResults: EmitResult[] = [];

  constructor(private readonly _options: AngularBuildPipelineOptions) {}

  async initialize(): Promise<PipelineResult>;
  async update(modifiedFiles: Iterable<string>): Promise<PipelineResult>;
  getEmittedFile(sourcePath: string): string | undefined;
  getEmittedFiles(): ReadonlyMap<string, string>;
  writeEmitResults(options?: WriteEmitResultsOptions): void;
  findAffectedByScss(scssPath: string): string[];
  getDiagnostics(): PipelineDiagnosticResult;
  getScssErrors(): readonly string[];
  getTsProgram(): ts.Program;
  clearScssDependencies(): void;
}
```

**initialize() 흐름:**
1. `scssErrors.length = 0` (in-place 클리어, 콜백 클로저 유지)
2. SCSS 콜백 생성 (최초 1회):
   - client: `createClientTransformStylesheet({ loadPaths, postCssPlugins, scssErrors, scssDependencies, cacheDir })`
   - library: `createLibraryTransformStylesheet(loadPaths, scssErrors, scssDependencies)`
   - `loadPaths = [pkgDir/scss, cwd/node_modules]` [근거: D5 "자동 파생"]
3. AngularCompiler 생성 (최초 1회): rootNames, compilerOptions, angularCompilerOptions, sourceFileCache, transformStylesheet, externalStylesheets, enableHmr, compilerOptionsTransformer 전달
4. `compiler.initialize()` → affectedFiles, templateUpdates 획득
5. `compiler.emitAffectedFiles()` → 결과를 `_latestEmitResults`와 `_emittedFilesBySource`에 수집
6. 진단 수집: `compiler.collectDiagnostics()` → `isWorkspaceDiagnostic` 필터 → 에러/경고 분류
7. `PipelineResult` 반환

**update() 흐름:**
1. `scssErrors.length = 0` (in-place 클리어)
2. `compiler.update(modifiedFiles)` (내부적으로 sourceFileCache 무효화 + 재초기화)
3. emit 재수집 (`_emittedFilesBySource`는 클리어하지 않음, 추가/갱신만) [근거: sdAngularPlugin HMR 패턴]
4. 진단 재수집
5. `PipelineResult` 반환

**writeEmitResults() 옵션:**
```typescript
interface WriteEmitResultsOptions {
  /** 출력 대상 패키지 디렉토리 */
  pkgDir: string;
  /** emit 결과 필터 (src/ 하위만 등) */
  sourceFilter?: (fileName: string) => boolean;
  /** side-effect SCSS 옵션 (ngtsc-build-core.writeEmitResults에 전달) */
  scss?: SideEffectScssOptions;
}
```

`_latestEmitResults`에서 `sourceFilter` 적용 후 기존 `writeEmitResults` 유틸 호출 [근거: Feature 1.1에서는 유틸 호출, Feature 1.3에서 함수 이동].

**clearScssDependencies():** [근거: D6]
`_scssDependencies.clear()` 호출. library watch 모드에서 매 리빌드 전 호출자가 사용.

#### 4. getPackageSourceFiles 확장 (`tsconfig.ts`)

```typescript
// 기존
export function getPackageSourceFiles(
  pkgDir: string,
  parsedConfig: ts.ParsedCommandLine,

// 확장 후
export function getPackageSourceFiles(
```

`includeFixtures: true` 시 `src/` 하위 파일 + `*.fixture.ts` 파일 포함. `parsedConfig.fileNames` 중에서 `pathx.isChildPath(f, srcDir) || f.endsWith(".fixture.ts")` 조건.

### 대안 검토

| 접근 방식 | 장점 | 단점 | 결론 |
|-----------|------|------|------|
| `mode: "client" \| "library"` enum | WBS와 일치, 간결한 API, 잘못된 조합 방지 | client 전용 옵션이 library에서 무시됨 | **채택** |
| 개별 옵션 (`scssAsync`, `emitMode`) | 최대 유연성 | 유효하지 않은 조합 가능 (async+disk), WBS 의도와 불일치 | 기각 |
| 상속 (`ClientPipeline extends BasePipeline`) | 모드별 명확한 타입 분리 | 공통 로직 대비 차이점이 SCSS 콜백 하나뿐, 과도한 추상화 | 기각 |
