## 구현계획

### 배경
vite-angular-plugin.ts의 `sdAngularPlugin`은 현재 AngularCompiler를 직접 생성·관리하고, SCSS 콜백, emit, 진단 수집을 buildStart/handleHotUpdate 내부에서 직접 수행한다. Feature 1.1에서 이 공통 파이프라인을 `AngularBuildPipeline` 클래스로 추출했으므로, 이제 플러그인이 Pipeline을 사용하도록 교체한다. [근거: wbs Feature 1.2 범위]

### 목표
- sdAngularPlugin의 buildStart/handleHotUpdate/transform이 AngularBuildPipeline을 통해 동작한다 [근거: Rule "buildStart는 Pipeline.initialize()를 사용한다"]
- 독립 findAffectedByScss 함수와 scssDependencies Map이 제거된다 [근거: Rule "독립 findAffectedByScss 함수와 scssDependencies Map이 제거된다"]
- 기존 테스트가 모두 통과한다 (동작 변경 없음)

### 비목표
- SdAngularPluginOptions 인터페이스 변경 [근거: wbs Feature 2.1 범위]
- JavaScriptTransformer, config(), configureServer 로직 변경 [근거: wbs 경계]

### 설계

**변경 파일:**
- `packages/sd-cli/src/angular/vite-angular-plugin.ts` — Pipeline 도입, 중복 코드 제거
- `packages/sd-cli/tests/angular/find-affected-by-scss.spec.ts` — 삭제

**sdAngularPlugin 내부 변수 변경:**

| 현재 | Pipeline 도입 후 |
|---|---|
| `compiler: AngularCompiler` | `pipeline: AngularBuildPipeline` |
| `sourceFileCache: AngularSourceFileCache` | 유지 (외부, pipeline에 전달) |
| `emittedFiles: Map<string, string>` | 제거 (pipeline.getEmittedFile() 사용) |
| `scssDependencies: Map<string, Set<string>>` | 제거 (pipeline 내장) |
| `templateUpdates: Map<string, string>` | 유지 (middleware용) |
| `jsTransformer`, `prebundleTransformer` | 유지 (Vite 고유) |
| `hmrLock`, `pendingWatchChanges`, `devServer` | 유지 |
| `lintRunner` | 유지 |

**buildStart 교체 로직:**
1. tsconfig 로드 (유지)
2. sourceFileCache 생성/재사용 + pendingWatchChanges 무효화 (유지)
3. ~~SCSS 콜백 생성~~ → Pipeline이 처리
4. ~~AngularCompiler 생성~~ → Pipeline 생성 (최초) 또는 재사용
5. Pipeline.initialize() 호출
6. ~~emit 루프~~ → pipeline 결과에서 자동 처리
7. templateUpdates 수집 → pipeline 결과에서 추출
8. ~~collectAndFormatDiagnostics~~ → pipeline.getDiagnostics()
9. reportDiagnostics (유지 — pipeline 결과를 인자로)
10. lint + onBuild 콜백 (유지)

**handleHotUpdate 교체 로직:**
1. ~~findAffectedByScss(normalizedFile, scssDependencies)~~ → pipeline.findAffectedByScss(normalizedFile)
2. ~~compiler.getTsProgram()~~ → pipeline.getTsProgram()
3. ~~compiler.update()~~ → pipeline.update()
4. ~~compiler.emitAffectedFiles()~~ → pipeline.getEmittedFiles() (update 후 자동 수집됨)
5. ~~emittedFiles.set()~~ → pipeline이 내부 관리
6. templateUpdates 수집 → pipeline 결과에서 추출
7. diagnostics → pipeline.getDiagnostics()

**transform 교체:**
- ~~emittedFiles.get(normalizedId)~~ → pipeline.getEmittedFile(normalizedId)

**buildEnd 교체:**
- prod 모드: ~~compiler = undefined; emittedFiles.clear()~~ → pipeline = undefined

**제거 항목:**
- `findAffectedByScss` 독립 함수 + export (line 60-71)
- `collectAndFormatDiagnostics` 내부 함수 (line 535-561)
- import: `AngularCompiler` (AngularSourceFileCache는 유지), `createClientTransformStylesheet`, `getPackageSourceFiles`, `isWorkspaceDiagnostic`
