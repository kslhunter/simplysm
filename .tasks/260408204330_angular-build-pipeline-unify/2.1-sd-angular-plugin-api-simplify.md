## 구현계획

### 배경

현재 `sdAngularPlugin`은 11개 옵션(`tsconfig`, `dev`, `legacyModule`, `sourcemap`, `onBuildStart`, `onBuild`, `enableLint`, `browserslist`, `postCssPlugins`, `linkerCacheDir`, `replaceDepDistPaths`)을 받는다. 이 옵션들은 `createClientViteConfig` (`vite-config.ts:133-144`)에서 조립되어 전달되는데, 대부분 sd.config.ts에서 읽거나 Vite config에서 파생 가능한 값이다. [근거: wbs "패키지명만 받아서 sd.config.ts에서 읽어야 맞는거 아닐까?"]

### 목표

- `SdAngularPluginOptions`를 `pkg`, `onBuildStart`, `onBuild` 3개로 축소한다 [근거: wbs 범위]
- 플러그인이 sd.config.ts를 직접 로딩하여 나머지 설정을 자동 resolve한다 [근거: wbs 범위]
- Vite config에서 dev/sourcemap/HMR을 자동 파생한다 [근거: wbs 범위]
- 죽은 코드(browserslist, enableLint, linkerCacheDir)를 제거한다 [근거: wbs 범위]

### 비목표

- `createClientViteConfig` 옵션 조립 코드 정리 — Feature 3.1 범위 [근거: wbs 경계]
- `client.worker.ts` / `ViteEngine` 옵션 전달 경로 정리 — Feature 3.2 범위 [근거: wbs 경계]
- `onBuild` 콜백 시그니처의 `lint?` 필드 제거 — Feature 3 범위 [근거: 설계 결정 D2]
- `loadSdConfig` 유틸 수정 — 필요 시 최소한으로 [근거: wbs 경계]

### 설계

**1. SdAngularPluginOptions 인터페이스 변경** [근거: Rule "플러그인 옵션 축소"]

```typescript
export interface SdAngularPluginOptions {
  /** sd.config.ts packages 키 (패키지 디렉토리명) */
  pkg: string;
  /** rebuild 시작 콜백 (CLI 상태 보고용) */
  onBuildStart?: () => void;
  /** rebuild 완료 콜백 (CLI 상태 보고용) */
  onBuild?: (result: {
    success: boolean;
    errors?: string[];
    warnings?: string[];
    lint?: LintWithProgramResult; // D2: 필드 유지, 항상 undefined
  }) => void;
}
```

**2. Vite 훅 기반 설정 수집** [근거: Rule "Vite config 파생"]

플러그인 내부에 설정 수집용 mutable 상태를 둔다:

```typescript
let isDev = false;           // config() 훅에서 설정
let enableSourcemap = false; // configResolved() 훅에서 설정
let isDevServer = false;     // configureServer() 훅에서 설정
let sdConfig: SdConfig;      // config() 훅에서 로딩
let pkgConfig: SdClientPackageConfig; // config() 훅에서 추출
let replaceDepDistPaths: string[] | undefined; // config() 훅에서 계산
```

- `config(config, env)`: Vite `env.mode`에서 `isDev` 파생. `loadSdConfig()` 비동기 호출. `resolveReplaceDepEntries()`로 dist 경로 계산. define/optimizeDeps 반환.
- `configResolved(resolved)`: `resolved.build.sourcemap` 또는 `isDev`에서 sourcemap 파생. prebundleTransformer와 jsTransformer 생성 (sourcemap 확정 후).
- `configureServer(server)`: `isDevServer = true` 설정. 미들웨어 등록.
- `buildStart()`: 수집된 설정으로 Pipeline 초기화. `enableHmr = isDevServer && !legacyModule`.

**3. sd.config.ts 로딩** [근거: Rule "sd.config.ts 자동 resolve"]

`config()` 훅에서 `loadSdConfig({ cwd: process.cwd(), dev: isDev, opt: [] })`을 호출한다.
- `pkg` 옵션을 키로 `sdConfig.packages[pkg]`에서 `SdClientPackageConfig`를 추출
- `pkgConfig.browserSupport?.postCss?.plugins` → `postCssPlugins`
- `pkgConfig.browserSupport?.legacyModule` → `legacyModule`
- tsconfig 경로: `packages/{pkg}/tsconfig.json` (cwd 기준)

**4. replaceDepDistPaths 자동 계산** [근거: 설계 결정 D1]

sd.config.ts의 `replaceDeps: Record<string, string>` (glob 패턴)에서 계산:
1. `packages/{pkg}/node_modules` 하위의 scoped/unscoped 패키지명 목록 수집
2. `resolveReplaceDepEntries(replaceDeps, targetNames)`로 매칭
3. 매칭된 패키지의 dist 디렉토리를 `fs.realpathSync()`로 resolve

**5. 죽은 코드 제거** [근거: Rule "죽은 코드 제거", 설계 결정 D2]

- `browserslist` 옵션 및 관련 코드 제거 (참조 없음)
- `enableLint` 옵션 제거 + `LintWithProgramRunner` import/사용 코드 제거 (getOrCreateLintRunner, lint 실행 블록)
- `linkerCacheDir` 옵션 제거 (기본값만 사용)

**6. 하위 호환** [근거: wbs 경계 "Feature 3에서 정리"]

Feature 2.1 완료 후, `createClientViteConfig`는 여전히 이전 옵션들을 조립하여 sdAngularPlugin에 전달한다. 하지만 sdAngularPlugin은 이제 `pkg`만 사용하고 나머지는 무시한다. `createClientViteConfig`의 정리는 Feature 3.1에서 수행한다.

→ **이 과도기를 처리하기 위해**: `createClientViteConfig`가 새 API(`pkg`)로 호출하도록 변경한다. 단, `CreateClientViteConfigOptions`에서 제거되는 필드(`tsconfigPath`, `browserslist`, `postCssPlugins`, `legacyModule`)는 Feature 3.1에서 정리하므로, 여기서는 sdAngularPlugin 호출 부분만 변경한다.

### 대안 검토

| 대안 | 설명 | 불채택 이유 |
|------|------|------------|
| sdConfig 객체 직접 주입 | 이미 로딩된 config를 옵션으로 전달 | API 단순화 목표에 부합하지 않음. vitest.config.ts에서는 config를 직접 로딩해야 함 |
| env 변수로 opt 전달 | process.env를 통해 CLI opt을 플러그인에 전달 | 전역 상태 오염. opt가 client config에 영향주는 경우 거의 없음 |
