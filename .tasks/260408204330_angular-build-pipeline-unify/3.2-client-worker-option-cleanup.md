## 구현계획

### 배경

Feature 3.1에서 `createClientViteConfig`가 sd.config.ts를 직접 로딩하도록 변경되면서, `browserSupport`와 `enableLint`를 ViteEngine → client.worker → createClientViteConfig로 전달하는 중간 경로가 불필요해졌다. 또한 `onBuild` 콜백의 `lint?` 필드는 `vite-angular-plugin.ts`의 3개 호출 지점(lines 321-325, 409-413, 433) 모두에서 전달되지 않는 dead 타입이다. [근거: Feature 3.1 비목표 → Feature 3.2]

### 목표

- `ClientBuildInfo`에서 `browserSupport`, `enableLint` 필드를 제거한다 [근거: wbs 범위]
- `ViteEngine`에서 해당 필드 전달 코드를 제거한다 [근거: wbs 범위]
- `startWatch()`의 `legacyModule` 분기를 worker 내부 sd.config.ts 로딩으로 대체한다 [근거: 설계 결정 D1]
- `ClientBuildResult.lint?`, `onBuild` 콜백의 `lint?`, ViteEngine의 lint 이벤트 처리를 제거한다 [근거: 설계 결정 D2]

### 비목표

- Worker 구조(createWorker, sender, events) 변경 [근거: wbs 경계]
- `EngineResult.lint?` 제거 — 다른 엔진(NgtscEngine, TscEngine 등)이 실제로 lint를 수행 [근거: 범위 한정]
- `SdBrowserSupportConfig` 타입 정의 제거 — sd-config.types.ts에서 다른 곳에서 사용 [근거: 범위 한정]

### 설계

**1. `ClientBuildInfo` 인터페이스 변경** [근거: Rule "browserSupport/enableLint 제거"]

제거: `browserSupport?: SdBrowserSupportConfig`, `enableLint?: boolean`

유지 (10개): `name`, `cwd`, `pkgDir`, `framework`, `port`, `env`, `configs`, `replaceDeps`, `pwa`, `exclude`, `outDir`, `base`

**2. `ClientBuildResult` 인터페이스 변경** [근거: Rule "lint dead code 제거"]

제거: `lint?: LintWithProgramResult`

유지: `success`, `errors`, `warnings`

**3. `ClientWorkerEvents.build` 타입 변경** [근거: Rule "lint dead code 제거"]

`build: ClientBuildResult`에서 `lint`가 제거되므로 이벤트 타입 자동 반영.

**4. `resolvePackageInfo()` 확장** [근거: 설계 결정 D1]

현재:
```typescript
function resolvePackageInfo(info: ClientBuildInfo): { pkgName: string } {
  const pkgJsonPath = path.join(info.pkgDir, "package.json");
  const pkgName = (JSON.parse(fs.readFileSync(pkgJsonPath, "utf-8")) as { name: string }).name;
  return { pkgName };
}
```

변경 후:
```typescript
async function resolvePackageInfo(info: ClientBuildInfo): Promise<{
  pkgName: string;
  legacyModule: boolean;
}> {
  const pkgJsonPath = path.join(info.pkgDir, "package.json");
  const pkgName = (JSON.parse(fs.readFileSync(pkgJsonPath, "utf-8")) as { name: string }).name;
  const name = pkgName.replace(/^@[^/]+\//, "");
  const sdConfig = await loadSdConfig({ cwd: info.cwd, dev: true, opt: [] });
  const pkgConfig = sdConfig.packages[name];
  const legacyModule = pkgConfig?.target === "client" ? pkgConfig.browserSupport?.legacyModule === true : false;
  return { pkgName, legacyModule };
}
```

`startWatch()`, `startLegacyWatch()`, `build()`의 호출부를 `await resolvePackageInfo(info)`로 변경.
`loadSdConfig` import 추가.

**5. `startWatch()` legacyModule 분기 변경** [근거: 설계 결정 D1]

현재: `if (info.browserSupport?.legacyModule === true)`
변경: `const { pkgName, legacyModule } = await resolvePackageInfo(info);` → `if (legacyModule)`

### 대안 검토

| 대안 | 설명 | 불채택 이유 |
|------|------|------------|
| ClientBuildInfo에 `legacyModule?: boolean` 필드 유지 | browserSupport 전체 대신 단일 boolean만 남기기 | sd.config.ts 로딩 패턴으로 통일하는 것이 createClientViteConfig과 일관적. 추가 필드가 하나라도 남으면 ViteEngine이 config를 읽어 전달하는 패턴이 유지됨 |
| lint 타입만 유지하고 코드 제거 | 향후 lint 기능 추가에 대비하여 타입만 남기기 | dead 타입은 코드 이해를 방해. 향후 필요 시 재추가가 간단 |
