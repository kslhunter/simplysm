## 구현계획

### 배경

현재 `createClientViteConfig`(vite-config.ts)는 18개 옵션을 받는다. Feature 2.1에서 `sdAngularPlugin`이 sd.config.ts를 직접 읽도록 변경된 후, `tsconfigPath`, `browserslist`, `postCssPlugins`, `legacyModule`, `enableLint`는 중간 조립 레이어로서의 역할을 잃었다. 그러나 `browserslist`(esbuild target), `postCssPlugins`(css.postcss), `legacyModule`(polyfills, inlineDynamicImports)은 Vite config 생성에도 사용되므로, 함수 내부에서 sd.config.ts를 직접 로딩해야 한다. [근거: wbs "플러그인이 sd.config.ts에서 직접 읽으므로 중간 조립 레이어 불필요"]

### 목표

- `CreateClientViteConfigOptions`에서 `tsconfigPath`, `browserslist`, `postCssPlugins`, `legacyModule`, `enableLint` 5개 옵션을 제거한다 [근거: wbs 범위 + 설계 결정 D2]
- 함수 내부에서 `loadSdConfig()`를 호출하여 `browserSupport` 값을 자체 resolve한다 [근거: 설계 결정 D1]
- `replaceDepDistPaths` 계산 dead code를 제거한다 [근거: 코드 분석]
- `client.worker.ts`의 호출부를 새 인터페이스에 맞게 업데이트한다 [근거: TypeScript 컴파일 에러 방지]

### 비목표

- `ClientBuildInfo`에서 `browserSupport`/`enableLint` 제거 — Feature 3.2 범위 [근거: wbs Feature 3.2]
- `ViteEngine`에서 `ClientBuildInfo` 전달 코드 정리 — Feature 3.2 범위 [근거: wbs Feature 3.2]
- `onBuild.lint?` 필드 제거 — Feature 3.2 범위 [근거: Feature 2.1 D2, 타입 연쇄 범위]

### 설계

**1. `CreateClientViteConfigOptions` 인터페이스 변경** [근거: Rule "5개 옵션 제거"]

제거: `tsconfigPath`, `browserslist`, `postCssPlugins`, `legacyModule`, `enableLint`

유지 (13개): `framework`, `pkgDir`, `pkgName`, `mode`, `serverPort`, `env`, `onBuildStart`, `onBuild`, `replaceDeps`, `onScopeRebuild`, `polyfills`, `pwa`, `exclude`, `watch`, `outDir`, `base`

**2. sd.config.ts 로딩 + browserSupport 추출** [근거: 설계 결정 D1]

함수 시작부에서 `loadSdConfig({ cwd: process.cwd(), dev: mode === "dev", opt: [] })` 호출:

```typescript
const sdConfig = await loadSdConfig({ cwd: process.cwd(), dev: options.mode === "dev", opt: [] });
const pkgConfig = sdConfig.packages[name];
if (pkgConfig == null) {
  throw new Error(`sd.config.ts에 패키지 "${name}"가 정의되어 있지 않습니다.`);
}
const browserSupport = pkgConfig.target === "client" ? pkgConfig.browserSupport : undefined;
const browserslist = browserSupport?.browserslist;
const postCssPlugins = browserSupport?.postCss?.plugins;
const legacyModule = browserSupport?.legacyModule === true;
```

이후 로직에서 `options.browserslist` → `browserslist`, `options.postCssPlugins` → `postCssPlugins`, `options.legacyModule` → `legacyModule`로 교체.

**3. tsconfigPath 자동 derive** [근거: Rule "tsconfigPath 자동 derive"]

```typescript
const tsconfigPath = path.join(options.pkgDir, "tsconfig.json");
```

기존 `tsconfigPaths({ projects: [options.tsconfigPath] })` → `tsconfigPaths({ projects: [tsconfigPath] })`

**4. dead code 제거** [근거: Rule "dead code 제거"]

- `replaceDepDistPaths` 계산 로직 (현재 line 98-114) 전체 제거 — 변수를 계산하지만 사용처 없음
- `enableLint` 관련 옵션 선언 제거 — 함수 body에서 미참조

**5. `client.worker.ts` 호출부 업데이트** [근거: Rule "호출부 업데이트"]

- `resolvePackageInfo()`: `tsconfigPath` 반환 제거. 함수가 `pkgName`만 반환하도록 변경 (또는 인라인화)
- `startWatch()`: `createClientViteConfig` 호출에서 `tsconfigPath`, `browserslist`, `postCssPlugins`, `legacyModule`, `enableLint` 삭제
- `startLegacyWatch()`: 동일하게 삭제
- `build()`: 동일하게 삭제
- `SdBrowserSupportConfig` import는 `ClientBuildInfo`에서 여전히 사용하므로 유지

**6. 테스트 업데이트**

`vite-config.spec.ts`:
- `loadSdConfig` 모킹 추가 (`vi.mock("../../src/utils/sd-config.js", ...)`)
- `createDefaultOptions()`에서 `tsconfigPath` 제거
- `browserslist` 관련 테스트: 옵션 전달 대신 `loadSdConfig` 모킹의 `browserSupport.browserslist` 설정으로 변경
- `postCssPlugins` 관련 테스트: 동일하게 모킹 기반으로 변경
- `legacyModule` 관련 테스트: 동일하게 모킹 기반으로 변경
- 새 테스트: sd.config.ts에 패키지가 없을 때 에러 throw

`client-worker.spec.ts`:
- `createClientViteConfig` 호출 인자 검증에서 `legacyModule` assertion 제거 (예: line 229-235의 `expect.objectContaining({ legacyModule: true })`)

### 대안 검토

| 대안 | 설명 | 불채택 이유 |
|------|------|------------|
| sdAngularPlugin의 `config()`에서 Vite 설정도 반환 | 플러그인이 esbuild target, css.postcss, legacyModule 설정을 `config()` 반환값에 포함 | Angular 전용 플러그인이 범용 빌드 설정을 담당하면 책임 경계 모호. framework "solid"에서 동작 불가 |
| `browserSupport` 옵션으로 통합 (개별 필드 → 단일 객체) | `browserslist`/`postCssPlugins`/`legacyModule` 대신 `browserSupport` 하나로 전달 | wbs가 옵션 제거를 명시하여 sd.config.ts 자체 로딩 방향과 불일치. 중간 레이어가 여전히 남음 |
