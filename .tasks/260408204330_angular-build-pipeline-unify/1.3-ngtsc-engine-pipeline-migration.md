## 구현계획

### 배경

`ngtsc-build.worker.ts`는 Angular 라이브러리 빌드를 수행하는 Worker Thread이다. 현재 `AngularCompiler`를 직접 생성/관리하고, SCSS 콜백·emit·진단·의존성 추적을 수동으로 조립한다. Feature 1.1에서 생성한 `AngularBuildPipeline`이 이 모든 것을 캡슐화하므로, worker가 Pipeline을 사용하도록 교체한다.

관련 구조:
- `build()` → `runNgtscBuild()` 호출 (ngtsc-build-core.ts:313-406)
- `startWatch()` → AngularCompiler 직접 생성 (worker:187-318)
- `performWatchBuild()` → 진단/emit/SCSS 수동 처리 (worker:113-185)
- `onChange` → SCSS 역방향 탐색 `currentScssDependencies` Map 순회 (worker:252-274)

### 목표

- worker의 build/watch 로직을 `AngularBuildPipeline` 호출로 교체 [근거: WBS "빌드 로직을 AngularBuildPipeline 호출로 교체"]
- Pipeline에 `collectRawDiagnostics()` 추가하여 `SerializedDiagnostic` 직렬화 지원 [근거: D2]
- `createLibraryTransformStylesheet`, `writeEmitResults`를 Pipeline 모듈로 이동 [근거: WBS "Pipeline으로 이동된 함수 정리"]
- `runNgtscBuild()` 제거 [근거: 호출처 소멸]

### 비목표

- global SCSS / side-effect SCSS 로직 이동 — worker 유지 [근거: WBS 경계]
- `buildCompilerOptions()` / `buildScssLoadPaths()` 이동 — ngtsc-build-core 유지 [근거: D4]
- `NgtscBuildInfo` / `NgtscBuildResult` 타입 변경 [근거: WBS 제외사항 "typecheck 경로 변경 않음"]

### 설계

#### 1. Pipeline `collectRawDiagnostics()` 메서드 [근거: D2]

```typescript
// angular-build-pipeline.ts
collectRawDiagnostics(): ts.Diagnostic[] {
  if (this._compiler == null) return [];
  return [...this._compiler.collectDiagnostics()].filter(
    (d) => isWorkspaceDiagnostic(d, this._options.cwd),
  );
}
```

#### 3. Worker `build()` 교체 [근거: WBS 범위]

```typescript
async function build(info: NgtscBuildInfo): Promise<NgtscBuildResult> {
  const parsedConfig = parseTsconfig(info.pkgDir);
  const sourceFiles = info.output.includeTests === true
    ? getPackageFiles(info.pkgDir, parsedConfig)
    : getPackageSourceFiles(info.pkgDir, parsedConfig);
  const baseOptions = info.env != null
    ? getCompilerOptionsForEnv(parsedConfig.options, info.env, info.pkgDir)
    : parsedConfig.options;
  const compilerOptions = buildCompilerOptions(baseOptions, info.pkgDir, info.output);
  const angularOptions = (parsedConfig.raw?.angularCompilerOptions ?? {}) as Record<string, unknown>;

  const pipeline = new AngularBuildPipeline({
    mode: "library",
    pkgDir: info.pkgDir,
    cwd: info.cwd,
    rootNames: sourceFiles,
    compilerOptions,
    angularCompilerOptions: angularOptions,
  });

  const pipelineResult = await pipeline.initialize();

  // emit → 디스크 쓰기 (src/ 하위만)
  const normalizedSrcDir = pathx.posix(path.join(info.pkgDir, "src"));
  pipeline.writeEmitResults({
    pkgDir: info.pkgDir,
    sourceFilter: (fileName) => pathx.posix(fileName).startsWith(normalizedSrcDir + "/"),
  });

  // global SCSS
  const globalScssErrors = compileGlobalScss(info.pkgDir, buildScssLoadPaths(info));

  // diagnostics 직렬화
  const rawDiags = pipeline.collectRawDiagnostics();
  const serialized = rawDiags.map(serializeDiagnostic);
  const errors = pipelineResult.diagnostics.errors.map((e) => e.message);
  const allErrors = [...errors, ...pipelineResult.scssErrors, ...globalScssErrors];

  const result: NgtscBuildResult = {
    build: {
      success: pipelineResult.diagnostics.errors.length === 0
        && pipelineResult.scssErrors.length === 0
        && globalScssErrors.length === 0,
      errors: allErrors.length > 0 ? allErrors : undefined,
      diagnostics: serialized,
    },
  };

  // lint
  if (info.output.lint === true) {
    const lintRunner = new LintWithProgramRunner({ cwd: info.cwd, pkgName: info.name });
    result.lint = await lintRunner.lint({ program: pipeline.getTsProgram() });
  }

  return result;
}
```

#### 4. Worker `startWatch()` / `performWatchBuild()` / `onChange` 교체 [근거: WBS 범위]

- `startWatch()`: Pipeline 생성 (sourceFileCache 포함) → `initialize()` → `writeEmitResults()` → FsWatcher 시작
- `performWatchBuild()` 제거: Pipeline.writeEmitResults() + compileSideEffectScss + compileGlobalScss로 인라인
- `onChange`: `pipeline.clearScssDependencies()` → SCSS 역방향 탐색을 `pipeline.findAffectedByScss()` 로 교체 → `pipeline.update()` → emit/진단/SCSS
- `currentScssDependencies` 모듈 변수 제거 (Pipeline 내장)
- `extractSourceFilePaths()` 유지 (`pipeline.getTsProgram()` 사용)

### 대안 검토

| 접근 방식 | 장점 | 단점 | 결론 |
|-----------|------|------|------|
| `trackDeps`/`formatScssError` export하여 공유 | 순환 의존성 없음, 코드 중복 없음 | private이었던 함수를 export | **채택** |
| 함수 복제 (Pipeline + ngtsc-build-core 각각) | 의존성 단순 | DRY 위반, 2곳 동기화 필요 | 기각 |
| 별도 `scss-build-utils.ts` 모듈 추출 | 깔끔한 분리 | 파일 수 증가, 2개 함수를 위한 모듈은 과도 | 기각 |
