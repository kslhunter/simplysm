### 프로젝트 컨벤션

- **파일 구조 패턴** (recipes/*.md): `# Recipe: {이름}` 헤더 → 상단 CRITICAL blockquote → 본문 리드 문단 → `## {번호}. {섹션명}` 순차적 섹션. [근거: `crud-list.md:1-8`, `crud-detail.md:1-8`]
- **레시피 내 코드 예제 컨벤션** (TypeScript): `@Component({ changeDetection: ChangeDetectionStrategy.OnPush, encapsulation: ViewEncapsulation.None, standalone: true, imports: [...], hostDirectives: [...], host: {...}, template: `...` })` + DI → 계약(input/output) → viewChild → 식별/권한 → 공유 데이터 → 상태 → 파생 → 시트 fn → constructor(effect + setupCanDeactivate) → 핸들러 → internals → 아이콘. [근거: `packages/angular/CLAUDE.md` "Component Structure", `crud-list.md:123-654`]
- **Signal 입력/양방향 패턴**: `input()`, `input.required<T>()`, `input<T>(defaultValue)`, `model<T>()` + `<sd-sheet [(selectedItems)]>` 양방향. [근거: `packages/angular/CLAUDE.md` "Component Structure", `crud-list.md:370-372`]
- **코드 블록 표기 규칙**: ```` ```typescript ```` 시작, import 블록 먼저 배치, 같은 소스는 한 번에 묶음. [근거: `crud-list.md:48-108`, `crud-detail.md:43-111`]
- **링크 앵커 형식**: Markdown 자동 생성 앵커 (kebab-case, 백틱 제거). 예: `## 3. 완성 예제` → `#3-완성-예제`, `### \`SdSheet\`` → `#sdsheet`. [근거: `crud-list.md:37`의 `#8-변형-조회-전용-modal` 링크 형태]
- **확장 섹션 명명**: WBS는 "확장 A~G"로 기호화 명시. 실제 섹션 제목은 "확장 A: inline 편집/저장" 같이 기호 + 콜론 + 한글 이름. [근거: wbs.md:75-81]
- **MOVE 표식 형식**: `<!-- MOVE: docs/{파일}.md#{앵커} -->` HTML 주석 형식, 해당 블록 직상단. [근거: wbs.md:13, wbs.md:86-94]
- **이관 후보 목록 섹션 포맷**: 파일 말미 `## 이관 후보 목록` + 대상 파일별 그룹화된 체크리스트(`- [ ] ...`). 2차 Feature 3.x에서 `[x]`로 체크. [근거: wbs.md:13, wbs.md:95]

constructor() {

    if (!this.perms().includes("use")) {
      this.initialized.set(true);
      return;

    this.sortingDefs();

#### 확장 섹션 작성 원칙

각 확장 섹션은 다음 3부 구조:

1. **섹션 헤더**: `## N. 확장 X: {이름}`
2. **도입 1문단**: 무엇을/언제 얹는가를 1~2문장으로 설명
3. **"추가/교체 스니펫"**: TypeScript 코드 블록 내에서 주석 번호(`// 1)`, `// 2)`, ...)로 각 변경점 설명. "imports 추가 → DI 추가 → 상태/computed 추가 → 메서드 추가 → template 변경" 순서
4. **"포인트" bullet 목록**: 각 확장 특유의 주의·의도·제약을 3~6개 bullet로 요약. §10에서 이관된 주의사항도 여기에 포함

### 대안 검토

- **§3을 풀옵션 그대로 두고 상단에 "최소 시작점: 확장 없이 시작하려면 부록 C 참조" 링크만 추가** — 거절. WBS "최소 → 확장 누적"의 목표는 §3 자체를 최소로 만드는 것. 풀옵션 §3을 두면 LLM이 여전히 풀옵션 §3을 복사 시작점으로 사용한다. [근거: wbs.md:40 "풀 옵션 baseline에서 '빼야 할 코드'를 추적하는 부담을 제거"]
- **확장 섹션을 diff patch 형식(± 기호)으로 표현** — 거절. TypeScript 코드 블록 내 diff는 문법 하이라이팅을 깨고, LLM이 주석 번호(`// 1)`)로 단계별 설명받는 기존 crud-list.md §5~§8 패턴이 더 가독성 높다. [근거: `crud-list.md:721-756` 기존 패턴]
- **부록 A를 삭제하고 확장 섹션만 유지** — 거절. WBS는 부록 A(풀 스택 합본) + 부록 B(매트릭스) 둘 다 포함으로 명시. 부록 A는 "복사 시작점" 역할로 확장을 모두 누적한 결과를 보여줌으로써 LLM이 확장 A~G 전체 조립 결과를 한 번에 검증할 수 있게 해준다. [근거: wbs.md:82]
- **이관 후보 목록을 별도 파일(`crud-list.move.md`)로 분리** — 거절. WBS가 "파일 말미"에 포함으로 명시. 단일 파일에 자기완결된 체크리스트가 있어야 2차 Feature 3.x가 파일 하나만 열어도 진행 가능. [근거: wbs.md:13, wbs.md:95]
- **테스트 추가** — 거절. 설계 결정 D4로 명시적으로 배제. 문서 작업이므로 테스트 러너 실행 없음. [근거: 사용자 답변 2026-04-21]

### Vertical Slicing

각 Slice는 독립적으로 적용 가능하며, 이후 Slice가 앞 Slice의 구조 위에 순차적으로 덧씌워진다. 모든 Slice 완료 시 최종 재설계 파일이 완성된다.

#### [x] Slice 1: 상단 CRITICAL + §1 + §2 + §3 + §4 (최소 뼈대 골격 확립)

- **구현 내용:**
  - 상단 CRITICAL blockquote 수정: 기존 톤 유지 + "선택 모달 계약은 확장 D / 조회 전용 modal은 확장 E에서 다룬다" 안내 보강
  - §1 Overview: 최소 뼈대 기준으로 조립 요소 목록 축약 (D1)
  - §2 언제 사용하는가: 최소 뼈대 + 확장 A~G 매핑 비교표로 재작성
  - §3 완성 예제 → `§3. 최소 뼈대: 조회 전용 page`로 제목 변경 + 코드를 최소 뼈대로 전면 교체
  - §4 분해 설명: 최소 뼈대 §3의 블록/상태/메서드 표로 재작성 (D2)
  - §3 코드 블록 내 기본 MOVE 표식 적용 (`<sd-busy-container>`, `<sd-topbar-container>`, `<sd-topbar>`, `<sd-dock-container>`, `<sd-dock>`, `<sd-form>`, `<sd-sheet>`, `<sd-sheet-column>`, `injectViewTypeSignal`, `injectPermsSignal`, `injectViewTitleSignal`, `mark`, `SdToastProvider.try`, `SdCommandDirective`)
- **Scenarios:** Rule "상단 CRITICAL 블록..." / Rule "§1 Overview..." / Rule "§2 비교표..." / Rule "§3는 조회 전용 page 최소 뼈대로 교체한다" / Rule "§4 분해 설명..."

- **의존:** Slice 1
- **구현 내용:**

  - 확장 B (선택 기능 + 선택 삭제/복구) 섹션 신규 작성
  - 확장 C (inline 삭제 열) 섹션 — 현행 §5 내용을 하이브리드 포맷으로 재구성

  - 확장 E (조회 전용 modal) 섹션 — 현행 §8 내용을 하이브리드 포맷으로 재구성
  - 확장 F (모달 편집 모드) 섹션 — 현행 §6 내용을 하이브리드 포맷으로 재구성
