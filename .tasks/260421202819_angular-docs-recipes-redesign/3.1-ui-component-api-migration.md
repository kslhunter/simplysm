### 프로젝트 컨벤션

- **docs 파일 구조**: 각 컴포넌트별 개별 `.md` 파일 — 타입 시그니처 > Input/Output 표 > 사용 패턴 > 주의사항 > 실사용 예 [근거: `docs/ui-data/sd-sheet.md` 등 전체 구조]
- **역링크 경로**: docs에서 recipes는 `../recipes/{파일}#{앵커}`, recipes에서 docs는 `../{카테고리}/{컴포넌트}.md#{앵커}` [근거: `docs/utils/mark.md` vs `crud-list.md`의 Cross-reference]
- **MOVE 주석 형식**: `<!-- MOVE: docs/{카테고리}/{컴포넌트}.md#{앵커} — {설명} -->` [근거: `crud-list.md:45-55`]

## 구현계획

### 배경

Feature 3.2(utils.md)��� 3.3(providers.md, provider-types.md)의 이관이 이미 완료되어, 역링크 형식·사용법 확장 수준·MOVE 축약 방식의 기준 패턴이 존재한다 [근거: `utils.md:39-43`, `providers.md:138-140`]. Feature 3.1은 이 패턴을 ui-*.md 5개 파일에 동일하게 적용한다.

### 목표

- 5개 UI docs 파일에 recipes의 사용법 맥락을 이관하여, 개별 API 단독 사용법을 docs에서 바로 찾을 수 있게 한다 [근거: WBS Deliverable D4]
- recipes ↔ docs 양방향 위키 링크를 완성한다 [근거: WBS 공통 수행 원칙 3번]
- MOVE 표식을 축약하여 이관 완료를 표시한다 [근거: WBS 공통 수행 원칙 4-5번]

### 비목표

- MOVE 비대상 컴포넌트(SdList, SdKanban, SdSidebar, SdPagination, SdTab, SdCollapse, SdModal, SdToast, SdDropdown 등) 수정 [근거: WBS Feature 3.1 경계]
- utils.md / providers.md / provider-types.md 대상 MOVE 처리 [근거: Feature 3.2/3.3 범위]
- recipes 코드 스니펫 자체 수정 [근거: WBS "코드 수정 범위 외"]
- 컴포넌트 내부 구현 서술 [근거: WBS Feature 3.1 경계 "외부 사용법만"]
