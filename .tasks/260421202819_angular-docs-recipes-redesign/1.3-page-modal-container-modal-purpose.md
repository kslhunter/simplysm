## 구현계획

### 배경

`page-modal-container.md`는 공통 분기 뼈대 레시피로 `viewType() === "modal"` 분기를 단일 블록으로 제시한다. 그러나 실제 modal 용도는 (a) 선택 모달과 (b) 조회 전용 modal로 계약이 다르며, LLM이 두 용도를 구분하지 못하고 선택 계약(`SdSelectModal<T>`·하단 액션 바·`close.emit`)을 반사적으로 이식하는 실수가 잦다 (Feature 1.1 완료 결과 `crud-list.md:1356-1360` §13.1 주의사항 참조). 이 레시피에도 용도 구분 안내를 반영하여 독자가 §2 → §3 → §7 흐름 중 **최소 한 곳**에서 용도 확정 지점을 만나도록 한다.

### 목표

- §2 비교표에서 modal 용도 2종을 독립 행으로 표기하여 독자가 표 스캔만으로 분기 선택을 마칠 수 있게 한다 [근거: Rule "§2 비교표"]
- §3 완성 예제의 `@else if (modal)` 블록이 복사될 때 용도 경고 주석이 함께 따라가도록 한다 [근거: Rule "§3 안내 주석", D2]
- §7 주의사항에 요약 + crud-list.md §13.1 크로스 링크로 실수 방지 경고를 남긴다 [근거: Rule "§7 주의사항", D6]
- crud-list.md의 재설계 후 앵커(§8/§9/§13.1)로 정확히 링크한다 [근거: Rule "크로스 참조 앵커"]

### 비목표

- **전면 재설계 아님**. §1 Overview, §4 분해 설명, §5 뷰 타입 결정, §6 타이틀 우선순위는 변경하지 않는다. §3의 TypeScript 코드 본문(클래스 필드·computed·inject)도 변경하지 않고 템플릿 내 HTML 주석만 추가한다 [근거: wbs.md:183, Rule "변경 규모"]
- **편집 모달 용도 분류 아님**. crud-detail.md를 modal로 띄우는 경우(편집 모달)는 분류 대상에서 제외하고 Feature 2.1에 위임 [근거: D4]
- **crud-detail.md 링크 추가/갱신 아님**. 178라인의 기존 파일 수준 참조만 유지하고 앵커 수준 링크는 추가하지 않음. Feature 2.1에 위임 [근거: D5]
- **테스트 미작성**. 문서 작업 [근거: D1]
