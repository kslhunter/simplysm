## 구현계획

### 배경

@simplysm/angular의 core 영역(directives, providers, plugins, utils)에서 리뷰로 발견된 13건의 이슈를 수정한다. 기존 코드베이스의 패턴(`inject`, `DestroyRef.onDestroy`, `ErrorHandler`)을 따르며, 외부 API 변경은 CONSIST-003(`canDeactivefn` → `canDeactiveFn` 리네임) 1건이다.

### 목표

- Critical 3건: 네비게이션 수식키 버그(LOGIC-001), 에러 삼킴(LOGIC-002), 가드 누적(LOGIC-003)
- Medium 4건: RAF 미취소(LOGIC-006), TypeError(LOGIC-007), unhandled rejection(LOGIC-008), DOM 미제거(LOGIC-009)
- Low 6건: 팝업 추적(LOGIC-020), 권한 로직(LOGIC-021), 오타(CONSIST-003), 오버레이 중복(DESIGN-002), transitionend(DESIGN-003), Set 최적화(PERF-001)

### 비목표

- Feature 1.2~1.4 이슈 (Form, Layout, Data+Overlay+Visual)
- 새 기능 추가 또는 아키텍처 변경

### 설계

#### LOGIC-001 + LOGIC-020: 네비게이션 수식키 + 팝업 관리

**sd-router-link.directive.ts:**
- `event.altKey` → `preventDefault()`/`stopPropagation()` 전에 early return
- `event.ctrlKey || event.shiftKey` → `_navWindow.open(url, params)` (features 없이 호출 → else 분기 → 새 탭)
- `isWindow=true` → 기존 팝업 동작 유지

**sd-navigate-window.provider.ts:**
- `_beforeUnloadController: AbortController` → `_openedWindows: Set<Window>` 교체
- 첫 팝업 open 시 단일 `beforeunload` 핸들러 등록, Set 순회하여 모든 윈도우 close

#### LOGIC-002 + LOGIC-008: 에러 전파

**setupModelHook.ts:**
- `inject(ErrorHandler)` 추가
- `.catch(() => {})` → `.catch((err) => errorHandler.handleError(err))`

**useSdSystemConfigResource.ts:**
- `inject(ErrorHandler)` 추가
- `queueMicrotask` 내 async 호출에 `.catch((err) => errorHandler.handleError(err))`

#### LOGIC-003 + CONSIST-003: 가드 cleanup + 리네임

**setupCanDeactivate.ts:**
- `inject(DestroyRef)` 추가
- `destroyRef.onDestroy`에서 `routeConfig.canDeactivate`에서 해당 가드를 `splice`로 제거
- `canDeactivefn` → `canDeactiveFn` 리네임

**sd-modal.provider.ts, sd-modal.control.ts:** `canDeactivefn` → `canDeactiveFn` 리네임

#### LOGIC-006: RAF 취소

**sd-resize-event.plugin.ts:** cleanup 함수에서 `cancelAnimationFrame(animationFrameId)` 추가 (`animationFrameId != null` 가드 포함)

#### LOGIC-009: DOM cleanup

**setupInvalid.ts:** `formEl` 조건 분기 **전에** `destroyRef.onDestroy(() => { indicatorEl.remove(); inputEl.remove(); })` 추가 (formEl 유무와 무관하게 DOM 정리)

#### LOGIC-007 + LOGIC-021: 경계값 처리

**sd-app-structure.provider.ts:**
- `getTitleByFullCode`: `itemChain` 빈 배열 가드 → descriptive Error throw
- `getPermsByFullCode`: `!item || !("perms" in item)` → `item != null && !("perms" in item)` (미발견 item = 권한 거부)

#### DESIGN-002: 오버레이 중복 방지

**sd-global-error-handler.plugin.ts:** `_hasDisplayedError = false` 필드 추가, `_displayErrorMessage` 시작부 가드, `appRef.destroy()` 후 true 설정

#### DESIGN-003: ripple transitionend

**setupRipple.ts:** `getComputedStyle(indicatorEl).opacity === "0"` → `TransitionEvent.propertyName === "opacity"` 검사로 교체

#### PERF-001: Set 최적화

**useExpandingManager.ts:** `isVisible` 내 `binding.expandedItems().includes()` → `new Set()` 변환 후 `.has()` 사용

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| LOGIC-001: directive에서 window.open() 직접 호출 | 미채택 | URL 구성 로직이 provider에 있으므로 provider.open() 활용이 일관적 |
| LOGIC-020: AbortController 배열로 각 팝업 관리 | 미채택 | Set\<Window\> + 단일 beforeunload 핸들러가 더 단순 |
| LOGIC-002: onError 콜백 파라미터 추가 | 미채택 | ErrorHandler 패턴이 코드베이스 표준 |
| LOGIC-003: routeConfig.canDeactivate를 교체(replace) | 미채택 | splice가 다른 가드에 영향을 주지 않아 안전 |
