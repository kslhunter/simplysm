## 구현계획

### 배경

sd-textfield 및 sd-date-range-picker 컴포넌트의 5건 리뷰 이슈 수정. 대상 파일: `sd-date-range.picker.ts` (to 정규화), `sd-textfield.control.ts` (paste 핸들링), `sd-textfield-type-handlers.ts` (validate/parse 보강).

### 목표

- "월" 기간에서 to 날짜가 항상 정규화된 from(월 1일) 기준으로 계산됨
- onInputPaste에서 브라우저 기본 paste 동작 차단
- DateTime/Time min/max 검증 추가
- password/email에도 minlength/maxlength/pattern 검증 적용
- format 핸들러의 regex 이스케이프에서 `\d`, `\s` 등 regex shorthand 충돌 방지

### 비목표

- 새 기능 추가
- textfield UI/UX 변경

### 설계

#### LOGIC-010: handleDatePeriodTypeChanged / handleFromDateChanged

`handleDatePeriodTypeChanged`에서 `firstOfMonth`를 먼저 계산한 뒤 from과 to 모두 이 값 기준으로 계산. `handleFromDateChanged`에서도 방어적으로 `setDay(1)` 정규화 적용.

#### LOGIC-011: onInputPaste

메서드 시작부에 `event.preventDefault()` 호출. 파싱 성공/실패/빈값 모든 경로에서 기본 paste를 차단.

#### CONSIST-001: DateTime/Time validate에 min/max 추가

DateOnly 패턴(`instanceof DateOnly && tick 비교`)을 따라:
- DateTime: `min instanceof DateTime && min.tick > value.tick`
- Time: `min instanceof Time && min.tick > value.tick`

#### CONSIST-004: createStringHandler validate 확장

`if (type === "text")` → `if (type !== "color")`로 조건 변경. text, password, email에 minlength/maxlength/pattern 적용.

#### LOGIC-023: format 핸들러 regex 이스케이프

현재 `"\\" + item`은 모든 문자에 `\` prefix를 붙여 `\d`, `\s` 등 regex shorthand를 생성하는 버그가 있음. 수정: regex 문자 클래스 특수문자(`]`, `\`, `^`, `-`)만 이스케이프하고, 나머지는 그대로 사용.

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| regex 유틸리티 함수 별도 생성 | 미채택 | 문자 클래스 전용 이스케이프는 4개 문자만 대상, 인라인 처리로 충분 |
| 모든 비포맷 문자에 `\\` prefix 유지 | 미채택 | `\d`, `\s` 등 regex shorthand 충돌 위험 |
