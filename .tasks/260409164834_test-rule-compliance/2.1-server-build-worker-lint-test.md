## 구현계획

### 배경

`server-build.worker.ts`의 테스트 파일 두 개가 sd-testing.md 규칙을 위반한다. 주요 위반 사항:
- vi.mock으로 모듈 전체를 대체한 후 mock 호출 횟수/인자를 검증하는 구현 결합 검증 약 18건 [근거: sd-testing.md "구현 결합 검증 금지"]
- createOnceGuard의 가드 로직을 mock 내에서 수동 복제 [근거: sd-testing.md "모킹이 실제 로직을 복제하면 모킹이 불필요하다는 증거다"]
- esbuild-config, worker-utils 혼합 모듈의 전체 mock으로 순수 함수까지 가짜화 [근거: sd-testing.md "혼합 모듈은 importOriginal"]

### 목표

- 구현 결합 검증을 제거하여 리팩토링 내성 있는 테스트로 전환 [근거: Rule "구현 결합 검증 금지"]
- importOriginal로 순수 함수(createOnceGuard, createServerEsbuildOptions)를 실제 실행 [근거: Rule "혼합 모듈은 importOriginal"]
- LintWithProgramRunner 인자 검증 → 결과 검증 전환 [근거: Rule "구현 결합 검증 금지"]

### 비목표

- esbuild, fs, @simplysm/core-node mock 제거 (물리적 필수) [근거: WBS 경계 "esbuild, @simplysm/core-node Worker, fs mock은 유지"]
- 새로운 테스트 시나리오 추가 (기존 커버리지 유지만 목표)
- server-production-files.ts의 테스트 수정 (별도 파일, 이 Feature 범위 외)

### 대안 검토

**vi.spyOn + mockImplementation 전환**: WBS 원안. vi.spyOn은 실제 코드 실행이 전제인데, 대상 함수들이 파일시스템에 접근하여 mockImplementation 없이는 실행 불가. mockImplementation을 추가하면 vi.mock과 기능적으로 동일하여 전환 의미 없음. 기각.
