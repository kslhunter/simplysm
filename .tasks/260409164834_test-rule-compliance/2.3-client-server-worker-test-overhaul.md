# Feature 2.3 client-worker + client-worker-legacy + server-runtime-worker 테스트 정비

## 참조 자료

- WBS: [wbs.md](./wbs.md)
- sd-testing.md 규칙: `.claude/references/sd-testing.md`
- 대상 테스트 파일:
  - `packages/sd-cli/tests/workers/client-worker.spec.ts` (vi.mock 8개)
  - `packages/sd-cli/tests/workers/client-worker-legacy.spec.ts` (vi.mock 8개)
  - `packages/sd-cli/tests/workers/server-runtime-worker.spec.ts` (vi.mock 4개)
- 소스 파일:
  - `packages/sd-cli/src/workers/client.worker.ts`
  - `packages/sd-cli/src/workers/server-runtime.worker.ts`
- 코드 분석 결과:
  - worker는 `createWorker()`로 생성한 `sender.send(eventName, data)`가 유일한 외부 통신 수단
  - client-worker-legacy는 이미 실제 HTTP 서버 테스트(fetch 기반)를 포함
  - server-runtime은 이미 실제 파일시스템(tmpdir) 사용, process.env 직접 검증 등 양호한 패턴 사용

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | .dev-port 파일 기록 검증 방식 | serverReady 이벤트 검증으로 대체 | .dev-port 기록은 구현 세부사항, serverReady 이벤트가 관찰 가능한 출력 |
| D2 | legacyModule 분기 검증 방식 | mock 호출 검증 완전 제거 | 이벤트/HTTP 서버 테스트로 이미 경로 구분됨. sd-testing.md 구현 결합 금지 |
| D3 | 콜백 캡처 패턴 | 패턴 유지, 검증만 개선 | vite mock 필수 상황에서 콜백 캡처 불가피. client-worker-legacy의 mock.calls 직접 접근만 제거, mockViteBuild 내 자동 호출로 전환 |
| D4 | server-runtime mockRegister 검증 | 유지 | Fastify mock 환경에서 프록시 설정 정확성 검증의 유일한 방법 |
| D5 | worker-utils mock | 유지 | registerCleanupHandlers의 process signal handler가 테스트 러너(vitest)와 충돌 가능 |

## 구현계획

### 배경

sd-cli의 worker 테스트는 `createWorker()`로 생성한 `sender.send()`를 통해 이벤트를 발행하는 구조. 현재 테스트는 `vi.mock()`으로 모듈을 전체 대체하고 mock 호출 인자/횟수로 구현 세부사항을 검증하여 sd-testing.md 규칙에 위반. [근거: 코드 분석]

### 목표

- mock 호출 검증 → sender.send 이벤트/반환값/HTTP 응답 검증 전환 [근거: Rule "구현 결합 검증 금지"]
- client-worker-legacy의 mock.calls 직접 접근 제거 [근거: D3 "콜백 패턴 개선"]
- 기존 테스트 시나리오 커버리지 유지 [근거: wbs 전제조건]

### 비목표

- vite/node:fs/Worker/net mock 제거 [근거: wbs 경계 "유지"]
- 소스 코드(client.worker.ts, server-runtime.worker.ts) 변경 [근거: 테스트 코드만 정비]
- server-runtime mockRegister 검증 제거 [근거: D4]
- worker-utils mock 전환 [근거: D5]
