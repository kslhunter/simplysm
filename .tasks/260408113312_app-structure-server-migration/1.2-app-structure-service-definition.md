### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | TModule 제네릭 처리 | `unknown` 기본값 사용 (비제네릭 팩토리) | WBS에서 `Record<string, TSdAppStructureItem[]>`로 타입 파라미터 없이 명시. AutoUpdateService 패턴도 비제네릭. 클라이언트 타입은 어차피 `unknown`으로 추론됨 |
| D2 | 서비스 이름 | `"AppStructure"` | AutoUpdateService→"AutoUpdate" 네이밍 패턴 준용 |
| D3 | 인증 | auth 래퍼 없음 | items는 앱 구조 설정 데이터. WBS에 auth 요구 없음. permission 초기화에 서버 내부적으로도 사용하므로 공개 접근 적합 |
| D4 | ServiceType 추출 | `ServiceMethods<ReturnType<typeof AppStructureService>>` | AppStructureService가 함수(팩토리)이므로 `ReturnType`으로 `ServiceDefinition`을 먼저 추출 후 `ServiceMethods` 적용 |

## 구현계획

### 배경

Feature 1.1에서 `service-common`에 `AppStructureItem` 타입과 유틸 함수가 추출되었다. 이제 서버에서 items를 보유하고 API로 제공하는 서비스를 정의해야 한다. [근거: wbs "서버가 items를 소유하고 API로 제공하는 구조로 정상화"]

### 목표

- `AppStructureService` 팩토리 함수를 정의하여 `itemsMap`을 클로저로 캡처하고 `getItems()` 메서드를 제공한다 [근거: wbs "AppStructureService(itemsMap) 팩토리 함수 제공"]
- `AppStructureServiceType` 타입을 export하여 클라이언트에서 타입 안전하게 서비스를 호출할 수 있게 한다 [근거: wbs "ServiceMethods 사용"]

### 비목표

- permission 초기화 로직 [근거: wbs 경계 "소비 프로젝트의 영역"]
- items 필터링 [근거: wbs 경계 "소비 측 책임"]

### 설계

**파일 구조:**

```
packages/service-server/src/services/
  app-structure-service.ts   ← 신규
```

**서비스 정의 패턴:** [근거: auto-update-service.ts 패턴 준용]

```typescript
// app-structure-service.ts
import type { AppStructureItem } from "@simplysm/service-common";
import { defineService, type ServiceMethods } from "../core/define-service";

export function AppStructureService(
  itemsMap: Record<string, AppStructureItem[]>,
) {
  return defineService("AppStructure", () => ({
    getItems(): Record<string, AppStructureItem[]> {
      return itemsMap;
    },
  }));
}

export type AppStructureServiceType = ServiceMethods<ReturnType<typeof AppStructureService>>;
```

- `AutoUpdateService`는 `const = defineService(...)` 패턴이지만, `AppStructureService`는 런타임 인자(`itemsMap`)를 받아야 하므로 함수로 래핑 [근거: wbs "인자: itemsMap"]
- `ctx`는 사용하지 않으므로 파라미터에서 생략 [근거: getItems()는 클로저된 itemsMap만 반환]
- auth 래퍼 없음 → `authPermissions`는 `undefined` [근거: 설계 결정 D3]

**export 추가:** [근거: wbs "service-server/src/index.ts에 export 추가"]

```typescript
// index.ts에 추가
export * from "./services/app-structure-service";
```

### 대안 검토

**A. 제네릭 팩토리 (`AppStructureService<TModule>`):**
- 장점: 서버 측에서 타입 안전한 itemsMap 전달
- 단점: `AppStructureServiceType` 추출 시 기본값이 `unknown`으로 고정되어 클라이언트 측 이점 없음. AutoUpdateService 패턴과 불일치.
- 판정: 불채택 — 실질적 이점 없이 복잡성만 증가
