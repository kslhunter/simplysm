## 구현계획

### 배경

client.worker.ts의 `build()` 함수는 `onBuild` 콜백으로 Angular 컴파일 결과를 수신하지만, lint 결과만 캡처하고 success/errors/warnings를 무시한다. dev 모드(`startWatch`)에서는 `sender.send("build", result)`로 전체 결과를 전달하여 정상 동작한다. [근거: 코드 리뷰 LOGIC-001]

### 목표
- 프로덕션 빌드에서 Angular 컴파일 에러를 build 결과에 반영하여 CI/CD 파이프라인이 올바르게 실패 [근거: Rule "프로덕션 빌드 결과는 Angular 컴파일 결과를 반영해야 한다"]
- duck-typing 제거로 타입 안전성 확보 [근거: Rule "BuildEngine.port 접근은 타입 안전해야 한다"]
- 불필요한 타입 단언 제거 [근거: Rule "esbuildTarget 타입은 실제 값과 일치해야 한다"]

### 비목표
- dev 모드 에러 처리 변경 [근거: wbs 경계 "dev 모드는 이미 정상 동작"]
- BuildEngine 인터페이스의 구조적 변경 [근거: wbs 경계]

### 설계

1. **client.worker.ts `build()`**: `onBuild` 콜백에서 `success`, `errors`, `warnings`를 모두 캡처하여 반환값에 반영 [근거: Rule "프로덕션 빌드 결과는 Angular 컴파일 결과를 반영해야 한다"]

2. **engines/types.ts**: `BuildEngine`에 `readonly port?: number` 추가 [근거: D1 설계 결정]

3. **DevWatchOrchestrator.ts `_getClientPort()`**: `as { port?: number }` 캐스팅 제거, `BuildEngine.port` 직접 접근 [근거: Rule "BuildEngine.port 접근은 타입 안전해야 한다"]

4. **vite-config.ts**: `esbuildTarget as string[]` 제거 [근거: D2 설계 결정]

### 대안 검토
- **port를 별도 Map으로 관리**: 오케스트레이터에 `_clientPorts` Map을 두는 방안. Worker 이벤트를 오케스트레이터 레벨에서 직접 수신해야 하므로 복잡도 증가. BuildEngine에 optional property 추가가 더 단순.
