# Feature 1.1 Windows에서 gradlew.bat spawn EINVAL 수정

## 참조 자료

- [debug.md](./debug.md)
- 에러 위치: `packages/sd-cli/src/capacitor/capacitor.ts` `_buildAndroid` 메서드
- 근본 원인: `cpx.spawn`(`core-node/src/utils/cp.ts`)이 `shell: true` 없이 `.bat` 파일을 실행하여 Windows에서 `EINVAL` 발생
- `cpx.spawn`은 Node.js 네이티브 `child_process.spawn`을 래핑하며, `.bat` 파일은 `cmd.exe` 해석이 필요

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | 수정 위치 | `_buildAndroid` 메서드 | `_exec`는 범용 메서드이므로 호출 측에서 플랫폼 분기 처리가 적절 |
| D2 | 수정 방법 | `cmd /c gradlew.bat` | `.bat` 실행의 정석적 방법, 이미 Windows 분기가 존재하는 메서드 |

## 구현계획

### 배경

`capacitor.ts`의 `_buildAndroid` 메서드는 이미 Windows/Unix 분기로 `gradlew.bat`과 `gradlew`를 구분한다. 그러나 Windows에서 `.bat` 파일을 `child_process.spawn`으로 직접 실행하면 `EINVAL` 에러가 발생한다.

### 목표

- Windows에서 `gradlew.bat`을 `cmd /c`를 통해 실행하여 `EINVAL` 해결

### 비목표

- `cpx.spawn` 자체의 수정 (범용 유틸이므로 이 이슈에서 변경하지 않음)
- Linux/macOS 동작 변경

### 설계

`_buildAndroid`에서 Windows일 때 `cmd`를 command로, `/c gradlew.bat`을 args 앞에 추가한다.

```typescript
// Before (Windows)
await this._exec(gradlew, [gradleTask, "--no-daemon"], androidPath);

// After (Windows)
await this._exec("cmd", ["/c", "gradlew.bat", gradleTask, "--no-daemon"], androidPath);
```

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| `_buildAndroid`에서 `cmd /c` 사용 | 채택 | 호출 측 플랫폼 분기, 기존 분기와 자연스러움 |
| `_exec`에서 `.bat` 감지 시 `shell: true` | 미채택 | 범용 메서드에 `.bat` 감지 로직 혼재 |
