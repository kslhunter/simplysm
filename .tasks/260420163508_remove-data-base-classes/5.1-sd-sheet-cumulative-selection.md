## 구현계획

### Tech Design Doc

#### 배경

기존 `useSelectionManager`는 `Set<T>` reference equality 기반(`useSelectionManager.ts:29, 92`)으로 동작한다. 서버 페이지네이션·검색처럼 같은 논리적 item이 다른 reference로 재공급되는 시나리오에서 체크 표시 복원이 불가능하다. 또한 items 변경 시 `selectedItems` 자동 정리 로직은 현재 `SdDataSheetBase`의 `setupCumulateSelectedKeys`(sd-data-sheet.base.ts:145)로만 존재하며, Feature 6.1에서 삭제 예정이다. 본 Feature는 이 두 책임을 `<sd-sheet>` 본체와 `useSelectionManager`로 정식 이관한다.

#### 목표

- `<sd-sheet>`에 `cumulativeSelection = input(false, { transform: booleanAttribute })` 추가 [근거: Rule "cumulativeSelection 기본값은 false"]
- `useSelectionManager`의 비교 로직을 `trackByFn` + `obj.equal` 기반 key 비교로 전환 [근거: Rule "체크 표시는 trackByFn + obj.equal 기반"]
- `cumulativeSelection=false` 시 items 변경 감지 후 `selectedItems.set([])`로 초기화 [근거: D1, Rule "기본값 false면 items 변경 시 초기화"]
- `cumulativeSelection=true` 시 items 변경 시 selectedItems를 건드리지 않음 (자연 누적) [근거: Rule "true면 selectedItems는 건드리지 않음"]
- select/deselect/toggleAll/isAllSelected/isSelected 전체를 key 비교 기반으로 일관 전환 [근거: D7, Rule "select/deselect 중복 방지"]
- tests/sheet에 누적/초기화/key 비교 회귀 spec 추가 [근거: wbs 247-251]
- docs/ui-data.md 및 docs/utils.md 업데이트 [근거: wbs 252-254, docs 섹션]

#### 설계

**1) `packages/angular/src/core/selection/useSelectionManager.ts` 수정**

- 옵션 인터페이스에 `trackByFn: Signal<(item: T, index: number) => unknown>` 필수 추가
- 내부 구현 전환:
  ```ts
  import { obj } from "@simplysm/core-common";

  // 표시 아이템의 index 매핑 (key 호출 시 정확한 index 전달용)
  const displayItemIndexMap = computed(() => {
    const map = new Map<T, number>();
    options.displayItems().forEach((it, i) => map.set(it, i));
    return map;
  });

  function keyOf(item: T): unknown {
    const idx = displayItemIndexMap().get(item) ?? 0;
    return options.trackByFn()(item, idx);
  }

  function isKeyEqual(a: unknown, b: unknown): boolean {
    if (a === b) return true;
    return obj.equal(a, b);
  }

  const selectedKeys = computed(() => {
    const fn = options.trackByFn();
    return options.selectedItems().map((it, i) => fn(it, i));
  });

  function isSelected(item: T): boolean {
    const key = keyOf(item);
    return selectedKeys().some((k) => isKeyEqual(k, key));
  }
  ```
- `select(item)`: single 모드면 기존대로 `selectedItems.set([item])`. multi 모드는 key 기반 중복 검사로 전환.
- `deselect(item)`: `selectedItems.update(arr => arr.filter(..., key !== target key))`
- `isAllSelected`: `selectableItems().every(it => selectedKeys에 it의 key 포함)`
- `toggleAll`: displayItems의 selectable을 key 기준으로 add/remove (누적 모드에서 다른 페이지 선택 유지)
- 기존 `selectedItemsSet` computed 제거

**2) `packages/angular/src/data/sheet/sd-sheet.ts` 수정**

(a) Input 추가 (파일 570줄 부근, boolean input 그룹에 추가):
```ts
cumulativeSelection = input(false, { transform: booleanAttribute });
```

(b) `useSelectionManager` 호출(694~699줄)에 `trackByFn` 전달:
```ts
selection = useSelectionManager<T>({
  displayItems: this.displayItems,
  selectedItems: this.selectedItems,
  selectMode: this.selectMode,
  getItemSelectableFn: this.getItemSelectableFn,
  trackByFn: this.trackByFn,
});
```

(c) `effect()` 설치로 `cumulativeSelection=false` 시 items 변경 감지 후 초기화. `effect`는 생성자 혹은 클래스 필드 이니셜라이저에서 설치(`inject(DestroyRef)` 없이 Angular injection context 내에서 호출 가능). 기존 코드 스타일(필드 이니셜라이저에서 composable 호출)과 정합되도록 클래스 필드에 할당:
```ts
private readonly _resetOnItemsChange = effect(() => {
  if (this.cumulativeSelection()) return;
  this.items(); // track
  untracked(() => {
    if (this.selectedItems().length > 0) {
      this.selectedItems.set([]);
    }
  });
});
```

imports 추가: `effect`, `untracked`

#### 대안 검토

- **대안 A (플래그 분기만, items 변경 처리 없음)**: 거부. 사용자 결정(옵션 C). 플래그 의미 모호 + 기본 모드의 기대 동작(페이지 이동 시 선택 해제) 미충족.
