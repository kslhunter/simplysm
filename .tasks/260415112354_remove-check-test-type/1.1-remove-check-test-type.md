    Given sd-cli check 명령이 존재한다

    # 근거: wbs 범위 "spawnVitest 함수 삭제"
    Scenario: check.ts에서 vitest 관련 코드 없음

      And cpx import가 존재하지 않는다
      And formatSection에 TEST 전용 분기가 없다

  Rule: 기존 typecheck/lint 동작 유지
    # 근거: 변경 리스크 최소화
    Scenario: typecheck+lint 조합 정상 동작
      Given --type typecheck --type lint 옵션으로 실행한다
      When 실행이 완료된다
      Then TYPECHECK과 LINT 섹션이 순서대로 출력된다

    Scenario: lint만 실행
      Given --type lint 옵션으로 실행한다
      When 실행이 완료된다
      Then LINT 섹션만 출력된다

## 구현계획

### 배경

`check.ts`의 `spawnVitest()`는 `pnpm vitest ...targets --run`의 단순 래퍼. typecheck/lint는 sd-cli가 TypeScript 컴파일러/ESLint 통합, 결과 포매팅 등 부가가치를 제공하지만, test는 단순 프로세스 위임만 수행. [근거: 대화에서 코드 분석]

### 목표

- `CheckType`에서 `"test"` 제거하여 CLI 책임 명확화 [근거: Rule "CheckType에서 test 제거"]
- vitest 관련 코드 완전 삭제로 코드 단순화 [근거: Rule "spawnVitest 및 관련 코드 완전 삭제"]

### 비목표

- `sdAngularPlugin` 변경 [근거: wbs 경계]
- `pnpm test` 스크립트 변경 [근거: wbs 경계]

### 설계

**check.ts 변경:**
- `CheckType` 유니언에서 `"test"` 제거
- `spawnVitest()` 함수 삭제 (31-64행)
- `formatSection()`의 TEST 분기 삭제 (71-73행)
- `needsTest` 변수 및 관련 `if` 블록 삭제 (105행, 180-183행)
- `order` 배열에서 `"TEST"` 제거 (204행)
- `cpx` import 제거 (1행) — spawnVitest에서만 사용

**sd-cli-entry.ts 변경:**
- 기본값: `["typecheck", "lint", "test"]` → `["typecheck", "lint"]` (101행)
- `validTypes`: `["typecheck", "lint", "test"]` → `["typecheck", "lint"]` (113행)

**check.spec.ts 변경:**
- test 관련 테스트 케이스 삭제
- test를 포함하는 기존 케이스에서 test 부분 제거
- `execa` mock 제거 (미사용)

### 대안 검토

test를 기본값에서만 제외하고 `--type test` 옵션은 유지하는 방안 → 불필요한 래퍼 코드가 남으므로 기각. 사용자가 "vitest run이면 충분"하다고 판단.
