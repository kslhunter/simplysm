## 구현계획

### 배경

1차 후속 Feature 1.1(`260417132441_.../1.1-worker-ts-parsing.md`)의 설계 결정 D2("findWorkerPatterns export")에 대한 참조가 프로덕션 코드 주석 2곳에 `(D2)`로 남아 있다. 그러나 2차 후속 Feature 1.1(`260417143009_.../1.1-worker-plugin-contract-and-filter.md`)에서 D2가 "사전 필터 강화"로 **재부여**되어, 같은 기호가 서로 다른 결정을 가리키게 되었다. 새 독자가 현재 설계 문서에서 D2를 찾으면 설명과 맞지 않아 혼선을 겪는다.

또한 2차 후속에서 도입한 사전 필터 정규식 `/\b(new\s+Worker|new\s+SharedWorker|import\.meta\.resolve)\b/`는 `new /* c */ Worker(...)` 같이 `new`와 `Worker` 사이에 주석이 낀 호출을 탈락시킨다. 실발생 가능성은 희박하지만 1차 수정 이전의 단순 부분문자열 필터 대비 놓치는 케이스가 새로 생긴 것은 사실이다. 이 트레이드오프가 코드 주석에 남아 있지 않아 장래 정규식을 건드리는 사람이 판단 근거 없이 되돌릴 위험이 있다.

### 목표

- 프로덕션 코드의 `(D2)` 참조 2건 제거 + 주석 문구 자연화 [근거: Rule "프로덕션 코드 주석에 과거 설계 문서의 결정 번호가 남지 않는다"]
- 사전 필터 주석 블록에 트레이드오프 2줄 추가 [근거: Rule "사전 필터 정규식의 의도된 트레이드오프는 해당 주석 블록에 명시한다"]
- 기존 78건 테스트 회귀 없음 [근거: Rule "주석 수정 후 회귀 없음"]

### 비목표

- 정규식 본문·`transformWorkerPatterns` 시그니처·`findWorkerPatterns` 동작 변경 [근거: wbs 경계]
- 신규 테스트 추가 [근거: wbs 제외사항, D4]
- 다른 `(D숫자)` 참조 전수 점검 (현재 범위는 `packages/sd-cli/src/esbuild`로 한정) [근거: wbs 제외사항]
- 1차/2차 Feature 설계 문서의 결정 번호 재부여 [근거: wbs 제외사항]
