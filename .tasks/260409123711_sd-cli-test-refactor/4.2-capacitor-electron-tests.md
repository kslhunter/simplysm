## 구현계획

### 배경

sd-cli의 `tests/capacitor/` 6개 + `tests/electron/` 1개 테스트 파일(총 ~2859줄)이 존재한다. WBS에서 3개 파일(capacitor-build, capacitor-init, capacitor-run)이 "mixed"로 분류되었으나, 실제 코드 확인 결과 모든 I/O가 vi.mock으로 대체된 순수 unit 테스트임을 확인했다. "혼재 분리" 작업은 불필요하다. [근거: 코드 확인 — 3개 파일에서 실제 파일시스템/프로세스 접근 0건]

7개 파일 모두에서 `pathx.posixResolve`와 `pathx.posix`의 mock이 실제 구현(`core-node/src/utils/path.ts:27-39`)과 동일한 로직을 복제하고 있다. 이는 sd-testing.md 원칙 위반이다. [근거: `capacitor-build.spec.ts:33-36` ≡ `path.ts:27-39`]

### 목표

- pathx 불필요 모킹 제거 — `importOriginal` 패턴으로 실제 pathx 유지 [근거: sd-testing.md Rule "실제 로직 복제 모킹 제거"]
- capacitor-init.spec.ts "Android 네이티브 설정" 하위 describe 정비 [근거: D1 "내부 정리"]
- WBS "mixed" → "unit" 분류 정정 [근거: 코드 확인]

### 설계

#### 1. pathx 불필요 모킹 제거 (7개 파일)

현재 7개 파일의 vi.mock("@simplysm/core-node") 패턴:

```typescript
// capacitor-build.spec.ts:17-37 (다른 6개 파일도 동일)
vi.mock("@simplysm/core-node", () => ({
  fsx: { exists: mockFsxExists, read: mockFsxRead, /* ... */ },
  cpx: { spawn: mockCpxSpawn, /* ... */ },
  pathx: {
    posixResolve: (...args: string[]) => path.resolve(...args).replace(/\\/g, "/"),
    posix: (p: string) => p.replace(/\\/g, "/"),
  },
}));
```

실제 구현 확인:
- `posix` (`core-node/src/utils/path.ts:27-28`): `p.replace(/\\/g, "/") as PosixPath` — mock과 기능적으로 동일
- `posixResolve` (`core-node/src/utils/path.ts:38-39`): `path.resolve(...args).replace(/\\/g, "/") as PosixPath` — mock과 기능적으로 동일

**변경:** `importOriginal` 패턴을 사용하여 실제 pathx를 유지하면서 fsx/cpx만 오버라이드. 이 패턴은 이미 `check.spec.ts:45-46`, `publish.spec.ts:97-98` 등 8+ 파일에서 사용되고 있다.

```typescript
// 변경 후
vi.mock("@simplysm/core-node", async (importOriginal) => {
  const original = await importOriginal<typeof import("@simplysm/core-node")>();
  return {
    ...original,  // pathx 등 실제 구현 유지
    fsx: { exists: mockFsxExists, read: mockFsxRead, /* ... */ },
    cpx: { spawn: mockCpxSpawn, /* ... */ },
  };
});
```

대상 파일:
- `capacitor-android.spec.ts:11-22`
- `capacitor-build.spec.ts:17-37`
- `capacitor-icon.spec.ts:16-36`
- `capacitor-init.spec.ts:16-36`
- `capacitor-run.spec.ts:16-36`
- `capacitor-workspace.spec.ts:16-36`
- `electron/electron.spec.ts:16-35`
