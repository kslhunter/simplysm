## 구현계획

### 배경

tests/engines/ 디렉토리에 7개 빌드 엔진 테스트 파일(2140줄)이 존재한다. BaseEngine은 TscEngine, NgtscEngine, ServerEsbuildEngine의 템플릿 메서드 기반 클래스이며, ViteEngine은 BuildEngine 인터페이스를 독자 구현한다. [근거: 소스 코드 BaseEngine.ts (220줄), ViteEngine.ts (199줄)]

기존 엔진 테스트는 Worker Thread를 `vi.mock("@simplysm/core-node")`으로 모킹하는 패턴을 공유하며, 이는 sd-testing.md 원칙(물리적으로 실행 불가능한 것만 모킹)에 부합한다. [근거: sd-testing.md, Worker Thread는 물리 인프라]

### 목표

- engine-lint-integration.spec.ts를 base-engine.spec.ts에 편입하여 파일 수 감소 [근거: D1]
- engine-selection.spec.ts에서 architectural 테스트를 분리하여 유형 구분 명확화 [근거: D2]
- BaseEngine 공유 동작 중복(stop, ResultCollector, RebuildManager, 이벤트)을 base-engine.spec.ts에 통합하고 개별 엔진에서 제거 [근거: D3]
- vite-engine.spec.ts 내부에 하위 describe 그룹을 추가하여 시나리오 탐색성 향상 [근거: D4]
- 패턴 통일: createMockPkg overrides 패턴, afterEach 제거 [근거: wbs 전체 목표]

### 비목표

- 소스 코드(src/) 변경 [근거: wbs 경계 "테스트 코드만 리팩토링"]
- ViteEngine의 stop/watch 테스트를 base-engine으로 이동 [근거: ViteEngine은 BaseEngine 미상속]
- 새 테스트 작성으로 커버리지 확대 [근거: wbs 제외사항]

**base-engine.spec.ts 편입 후 구조:** [근거: D1, D3]
```
describe("BaseEngine")
├── is abstract class that TscEngine extends
├── stop() is inherited from BaseEngine
├── describe("shared stop() behavior")
│   ├── stopWatch + terminate in watch mode
│   └── handles stop without prior run
├── describe("shared startWatch() event handling")
│   ├── registers buildStart, build, error handlers
│   ├── reports build result to ResultCollector
│   ├── calls resolver from registerBuild on rebuild
│   ├── emits batchComplete via RebuildManager
│   ├── calls registerBuild on initial buildStart
│   ├── calls resolver on error event
│   └── uses _getTarget() for BuildResult target
└── describe("lint 통합")                        ← D1 편입
    ├── BuildOutput.lint flag 수용
    ├── EngineResult에 lint 필드 포함
    ├── startWatch에서 lint BuildResult 보고
    └── ResultCollector에서 lint 타입 지원
```

```
describe("TscEngine")
└── describe("run()")
    ├── creates worker, calls build, returns EngineResult
    ├── maps worker result to EngineResult with build field
    ├── reflects failure when tsc reports errors
    └── passes output flags to worker
└── describe("stop()")
    └── skips stopWatch in run mode  ← run mode는 TscEngine 고유
```

ngtsc-engine.spec.ts:
```
describe("NgtscEngine")
└── describe("run()")
    ├── creates worker, calls build, returns EngineResult with js/dts
    ├── passes dts:false output flag
    ├── includes diagnostics in result
    ├── returns result even when build has errors
    ├── reflects build failure
    └── maps worker warnings
└── describe("stop()")
    ├── terminates worker on stop  ← terminate 직접 호출 검증 (고유)
    └── skips stopWatch in run mode  ← run mode 고유
```

server-esbuild-engine.spec.ts:
```
describe("ServerEsbuildEngine")
└── describe("run()")

    ├── maps worker result to EngineResult
    └── reflects build failure
└── describe("startWatch()")
    └── passes server config to worker startWatch  ← 서버 설정 전달 (고유)
└── describe("stop()")
    └── skips stopWatch in run mode  ← run mode 고유
```

### 대안 검토

- **base-engine.spec.ts 삭제 + 개별 엔진에 중복 유지**: 각 엔진이 자기 완결적이지만, 동일 BaseEngine 동작이 3곳에서 반복. 유지보수 비용 증가로 기각 [근거: D3]
- **vite-engine.spec.ts 파일 분할 (vite-engine-watch.spec.ts)**: mock 설정 중복 발생, 다른 엔진은 단일 파일이므로 불일치. 기각 [근거: D4]
