## 구현계획

### 배경

`output-path-rewriter.ts`의 `addJsExtensionToImports`와 `rewriteScssImports`, `esbuild-config.ts`의 `writeChangedOutputFiles`는 정규식으로 ESM import/export 경로를 매칭하여 확장자를 추가/변환한다. 정규식은 주석/문자열 내 `from "..."` 패턴을 오탐할 수 있다. [근거: wbs 건 2 근거]

### 목표

- 3개 함수의 import 경로 정규식을 es-module-lexer로 교체 [근거: Rule "확장자 없는 상대 import에 .js를 추가"]
- writeChangedOutputFiles의 인라인 중복 로직을 addJsExtensionToImports 호출로 통합 [근거: D2]
- 함수 시그니처(동기) 유지 [근거: Rule "함수 시그니처를 유지"]

### 비목표

- adjustMapSources, createOutputPathRewriter 변경 [근거: wbs 경계]

### 설계

**es-module-lexer 초기화**: `output-path-rewriter.ts` 모듈 최상위에서 `await init`(top-level await). ESM 프로젝트이므로 지원됨. `parse()` 이후 동기적으로 사용 가능하여 함수 시그니처 변경 불필요.

**`addJsExtensionToImports` 구현**:
1. `parse(text)`로 모든 import 추출 (static + dynamic + re-export 포함)
2. 각 import에서 specifier(`n`)를 확인
3. 상대 경로(`./`, `../`)이면서 확장자 없는 것에 `.js` 추가
4. 역순으로 `text.slice()` 치환 (위치 밀림 방지)

**`rewriteScssImports` 구현**:
1. `parse(text)`로 모든 import 추출
2. 상대 경로이면서 `.scss`로 끝나는 specifier를 `.css`로 변환
3. 원본 경로 수집 (역순 처리 후 reverse)

**`writeChangedOutputFiles` 변경**:
1. `addJsExtensionToImports`를 import
2. 인라인 정규식 제거, `addJsExtensionToImports(file.text)` 호출

### 대안 검토

| 대안 | 불채택 사유 |
|------|-----------|
| acorn (이미 설치) | 전체 AST 파싱은 import specifier 추출에 과도, es-module-lexer가 특화됨 |
| writeChangedOutputFiles에서 es-module-lexer 직접 사용 | 동일 로직 중복, 유지보수 비용 증가 |
