### 설계 결정
| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | 병렬화 vs 단일 watcher | 단일 watcher | 15개 chokidar 인스턴스 자체가 메모리/CPU 부담. ready 1회 대기로 축소 |
| D2 | 변경 경로 → source 매핑 방식 | longest-prefix 매칭 | nested source 경로 케이스에서 안전. O(N) 정렬 후 매칭 |
| D3 | source 그룹화 자료구조 | `Map<string, ReplaceDepEntry[]>` (key: `resolvedSourcePath`) | 기존 `sourceEntries = entries.filter(...)`와 등가, 조회 O(1) |
| D4 | watchPaths 중복 제거 | `Set<PosixPath>` | 동일 source를 여러 entry가 참조해도 1회 감시 |

## 구현계획

### 배경
`watchReplaceDeps`(L195-315)가 entry별로 `FsWatcher.watch()`를 순차 await한다. chokidar는 `ready` 이벤트까지 대상 경로를 재귀 스캔하므로, 15개 × ready 대기 ≈ 10초. `FsWatcher.watch`는 이미 다중 경로 배열을 받으므로(`fs-watcher.ts:137-159`), API 변경 없이 단일 인스턴스로 통합 가능.

### 목표
- 단일 `FsWatcher.watch()` 호출로 ready 대기를 1회로 축소 [근거: Rule "단일 FsWatcher"]
- 기존 복사/삭제/로그/옵션 동작 유지 [근거: Rule "엣지케이스 100% 유지"]

### 비목표
- `FsWatcher` API 변경 [근거: WBS 경계]
- `setupReplaceDeps` 변경 [근거: WBS 경계]
- `replace-deps-resolve.ts` 변경 [근거: WBS 경계]

### 설계

**1. source 그룹화 및 watchPaths 수집**

```ts
// resolvedSourcePath(posix) → entries 매핑
const sourceMap = new Map<string, ReplaceDepEntry[]>();
for (const entry of entries) {
  const key = pathx.posix(entry.resolvedSourcePath);
  const arr = sourceMap.get(key) ?? [];
  arr.push(entry);
  sourceMap.set(key, arr);
}

// source별 watchPaths 수집 (files 필드 없는 source는 경고 후 제외)
const allWatchPaths = new Set<string>();
for (const [sourcePath, sourceEntries] of sourceMap) {
  const files = await loadFilesField(sourcePath);
  if (files == null) {
    logger.warn(`[${sourceEntries[0].targetName}] package.json에 files 필드가 없어 감시 건너뜀`);
    sourceMap.delete(sourcePath);
    continue;
  }
  for (const f of files) {
    allWatchPaths.add(pathx.posix(path.join(sourcePath, f)));
  }
  // npm 기본 파일
  try {
    const rootEntries = await fs.promises.readdir(sourcePath);
    for (const name of rootEntries) {
      if (NPM_DEFAULT_FILE_PATTERN.test(name)) {
        allWatchPaths.add(pathx.posix(path.join(sourcePath, name)));
      }
    }
  } catch {
    // readdir 실패 무시
  }
}
```

**2. longest-prefix 매칭용 정렬**

```ts
const sortedSources = [...sourceMap.keys()].sort((a, b) => b.length - a.length);

function findSource(changedPath: string): string | undefined {
  for (const src of sortedSources) {
    if (changedPath === src || changedPath.startsWith(src + "/")) return src;
  }
  return undefined;
}
```

**3. 단일 watcher 생성 + onChange**

```ts
logger.start(`replace-deps 워치 시작 중... (${entries.length}개 대상)`);

const watcher = await FsWatcher.watch([...allWatchPaths], { followSymlinks: false });

watcher.onChange({ delay: 300 }, async (changeInfos) => {
  let hasActualCopy = false;
  for (const { path: changedPath } of changeInfos) {
    const src = findSource(changedPath);
    if (src == null) continue;
    const sourceEntries = sourceMap.get(src)!;

    for (const e of sourceEntries) {
      const relativePath = pathx.posix(path.relative(e.resolvedSourcePath, changedPath));
      const destPath = pathx.posix(path.join(e.actualTargetPath, relativePath));
      try {
        let sourceExists = false;
        try { await fs.promises.access(changedPath); sourceExists = true; } catch {}

        if (sourceExists) {
          const stat = await fs.promises.stat(changedPath);
          if (stat.isDirectory()) {
            await fsx.mkdir(destPath);
          } else {
            if (await isFileContentSame(changedPath, destPath)) continue;
            await fsx.mkdir(pathx.posix(path.dirname(destPath)));
            await fsx.copy(changedPath, destPath);
            hasActualCopy = true;
          }
        } else {
          await fsx.rm(destPath);
          hasActualCopy = true;
        }
      } catch (err) {
        logger.error(
          `[${e.targetName}] 복사 실패 (${relativePath}): ${err instanceof Error ? err.message : err}`,
        );
      }
    }
  }
  if (hasActualCopy) options?.onChanged?.();
});

logger.success("replace-deps 워치 준비 완료");

return {
  entries,
  dispose: () => { void watcher.close(); },
};
```

**변경 요약:**
- `watchers: FsWatcher[]` / `watchedSources: Set<string>` / `for (const entry of entries)` 루프 제거
- `sourceMap` + `sortedSources` + `findSource` 도입
- `FsWatcher.watch` / `onChange` 1회 호출
- `dispose`는 단일 watcher `close()`

### 대안 검토

- **A. Promise.all로 entry 병렬화**: 최소 수정이나 chokidar 인스턴스 15개 유지. 메모리/watch fd 소비 지속. 기각.
- **B. 단일 watcher + longest-prefix 매칭**: 채택. ready 1회, 인스턴스 1개.
- **C. FsWatcher에 "경로→메타" 연결 기능 추가**: API 확장 필요, 과설계. 기각.
