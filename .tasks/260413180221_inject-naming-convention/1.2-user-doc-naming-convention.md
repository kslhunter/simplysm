## 구현계획

### 배경

`usage.md`는 `@simplysm/angular`의 소비앱 개발자용 API 문서이다. "컴포넌트 비동기 초기화 규칙" 섹션(319행)과 "Usage Examples" 섹션(341행) 사이에 규칙성 콘텐츠가 위치하는 패턴이 존재한다.

### 목표

- 소비앱 개발자가 Sd* Provider inject 시 변수명 규칙을 문서에서 즉시 확인 가능 [근거: Rule "소비앱 inject 네이밍 컨벤션 섹션"]
- 라이브러리/소비앱 동일 규칙 안내 [근거: D1 결정 — sd prefix 유지로 규칙 통일]

### 비목표

- 라이브러리 내부 개발자용 상세 규칙 문서화 [근거: wbs 경계 "소비앱 개발자용 문서"]
- 기존 예제 보정 [근거: D1 - 보정 불필요 확인]

### 설계

"컴포넌트 비동기 초기화 규칙" 섹션 뒤, "Usage Examples" 섹션 앞에 새 `## inject 네이밍 컨벤션` 섹션 추가. 내용 구성:

1. 규칙 요약: Sd 접두어 유지, Provider 접미어 제거, camelCase (축약 없이 풀네임)
2. 클래스 필드 / 로컬 변수 예시 표

### 대안 검토

- usage.md 상단(API Overview 전)에 배치 → 문서 구조상 규칙은 API 목록 뒤에 위치하는 것이 자연스러우므로 채택하지 않음
