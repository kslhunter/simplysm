# Feature 1.1 device URL 자동 탐지

## 참조 자료

### 이슈

- GitHub 이슈 #18: sd-cli device에서 server가 패키지명(string)일 때 --url 옵션 필수 오류

### 디버그 결과

- [debug.md](./debug.md)
- 근본 원인: `device.ts:60-68`에서 server가 string일 때 URL resolve 로직 누락
- ViteEngine.port는 메모리에만 저장, 프로세스 경계를 넘어 공유 불가

### 관련 코드

- `packages/sd-cli/src/commands/device.ts` — device 명령어 (URL 결정 로직)
- `packages/sd-cli/src/workers/client.worker.ts` — Vite dev server 워커 (serverReady 이벤트)
- `packages/sd-cli/src/engines/ViteEngine.ts` — Vite 엔진 (port 프로퍼티, stop 메서드)
- `packages/sd-cli/src/sd-config.types.ts` — SdClientPackageConfig.server: string | number

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | stale 포트 파일 처리 | HTTP 헬스체크 | dev 서버 비정상 종료 시 잘못된 포트로 접속 시도 방지 |

      When sd-cli device를 --url 없이 실행한다
      Then dist/.dev-port에서 포트를 읽어 HTTP 헬스체크를 수행한다
      And 헬스체크가 실패한다
      And "dev 서버가 응답하지 않습니다. pnpm dev를 다시 실행해주세요." 에러가 발생한다

  Rule: dev 서버 시작 시 포트 파일을 기록한다

    Scenario: Vite dev server 포트 확정 시 포트 파일 기록
      Given client 패키지의 Vite dev server가 시작된다
      When serverReady 이벤트로 포트가 확정된다
      Then packages/{name}/dist/.dev-port 파일에 포트 번호가 텍스트로 기록된다

  Rule: dev 서버 종료 시 포트 파일을 삭제한다

    Scenario: 정상 종료 시 포트 파일 삭제
      Given dist/.dev-port 파일이 존재한다
      When ViteEngine.stop()이 호출된다
      Then dist/.dev-port 파일이 삭제된다

## 구현계획

### 배경

sd-cli device 명령어에서 server가 string(패키지명)일 때, 실행 중인 Vite dev server의 포트를 알 수 없어 에러가 발생한다. DevWatchOrchestrator에서는 ViteEngine.port를 메모리에서 직접 접근하지만, device 명령어는 별도 프로세스이므로 파일 기반 공유가 필요하다.

### 목표

- Vite dev server 포트를 파일로 기록하여 프로세스 경계를 넘어 공유
- device 명령어에서 포트 파일을 읽어 URL 자동 생성
- stale 포트 파일을 HTTP 헬스체크로 감지

### 비목표

- `--port` CLI 옵션 추가
- Orchestrator 수준의 상태 JSON

### 설계

#### 포트 파일

- 경로: `packages/{name}/dist/.dev-port`
- 형식: 포트 번호 텍스트 (예: `5173\n`)
- 기록 시점: client.worker의 serverReady 직후 (`writeConfigJson`과 동일 패턴)
- 삭제 시점: ViteEngine.stop()에서 worker terminate 전

#### HTTP 헬스체크

- device.ts에서 포트 파일을 읽은 후 `http://localhost:{port}/{targetName}/`에 GET 요청
- 타임아웃: 3초
- 성공 → URL 사용, 실패 → 에러

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| dist/.dev-port 파일 | 채택 | 기존 dist/.config.json 패턴과 일관, 변경 최소 |
| .dev-state.json (Orchestrator 수준) | 미채택 | 새로운 패턴, lock 관리 복잡 |
| TCP 포트 확인 | 미채택 | HTTP 헬스체크가 더 정확 |
