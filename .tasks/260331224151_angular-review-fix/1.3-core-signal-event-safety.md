## 구현계획

### 배경

`setupModelHook`은 Angular의 `WritableSignal`에 변경 가드(`canFn`)를 적용하는 유틸리티다. 현재 `set`만 오버라이드하여 `update` 경로가 가드를 우회할 수 있다. `SdIntersectionEventPlugin`은 IntersectionObserver의 콜백에서 `entries.single()`을 사용하는데, batch 전달 시 예외가 발생한다.

### 목표

- `model.update` 호출 시에도 `canFn` 검증이 동작하도록 한다
- IntersectionObserver batch 콜백에서 예외 없이 최신 엔트리를 처리한다

### 비목표

- `setupModelHook`의 canFn 비동기 처리 패턴 변경 (기존 set 경로의 패턴 유지)
- IntersectionObserver의 threshold/rootMargin 등 옵저버 설정 변경

### 설계

#### LOGIC-001: model.update 오버라이드

`model.update`를 오버라이드하여, 내부에서 `fn(model())`로 새 값을 계산한 뒤 오버라이드된 `model.set`을 호출한다. canFn 검증 로직은 `set`에만 존재하므로 중복 없이 일관된 검증이 보장된다.

```typescript
model.update = (fn) => {
  model.set(fn(model()));
};
```

#### LOGIC-009: entries batch 안전 처리

`entries.single()`을 `entries[entries.length - 1]`로 교체한다. IntersectionObserver 스펙상 entries는 시간 순으로 정렬되므로 마지막 항목이 최신 상태다. `Array.prototype.at()`은 Chrome 92+이므로 사용하지 않는다.

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| update 내부에서 set 호출 | 채택 | canFn 로직 중복 없음, set 변경 시 update도 자동 반영 |
| update에도 canFn 로직 복사 | 미채택 | 로직 중복, 유지보수 시 불일치 위험 |
| `entries.last()` 사용 | 미채택 | `last()`도 `single()`처럼 core-common 확장 메서드이고, 배열이 비었을 때 throw 가능성을 확인해야 함 |
| `entries[entries.length - 1]` 사용 | 채택 | 표준 문법, 빈 배열 시 undefined, Chrome 61 호환 |
