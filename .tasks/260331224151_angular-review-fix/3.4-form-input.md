## 구현계획

### 배경

sd-select의 single 모드 contentHTML 동기화 effect와 sd-date-range-picker의 handleFromDateChanged 핸들러에 각각 일관성 누락이 있다. 두 수정 모두 동일 파일 내의 기존 패턴(multi 모드 처리, handleDatePeriodTypeChanged)을 따르면 되는 단순 수정이다.

### 목표

- Single 모드에서 contentHTML이 빈 문자열일 때 stale 표시 텍스트 방지
- "월" 모드에서 handleFromDateChanged가 handleDatePeriodTypeChanged와 동일한 정규화 수행

### 비목표

- sd-numpad 소수점 입력 (LOGIC-021, false positive로 제외)
- select/date-range의 기존 정상 동작 변경

### 설계

#### LOGIC-019: sd-select single mode stale 방지

현재 코드 (sd-select.control.ts:356-362):
```typescript
for (const item of items) {
  if (item.value() === currentValue) {
    const html = item.contentHTML();
    if (html !== "") {
      this._selectedItemContentHTML.set(html);
    }
    return;
  }
}
```

수정: `html === ""` 일 때 `_selectedItemContentHTML.set(undefined)` 호출. multi 모드(340-352)의 "htmlParts가 비어있으면 undefined 설정" 패턴과 동일.

#### LOGIC-020: sd-date-range handleFromDateChanged 정규화

현재 코드 (sd-date-range.picker.ts:84-87):
```typescript
handleFromDateChanged(): void {
  if (this.periodType() === "월") {
    const fromDate = this.from();
    this.to.set(fromDate?.setDay(1).addMonths(1).addDays(-1));
  }
```

수정: `from`도 `setDay(1)`로 정규화. handleDatePeriodTypeChanged(69-78)와 동일 패턴.

| LOGIC-019: html 빈 문자열 가드 자체 제거 | 미채택 | 빈 html을 표시 영역에 설정하면 빈 innerHTML이 되어 동작은 같지만 undefined가 의미적으로 정확 |
