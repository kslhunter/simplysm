# Feature 3.3 Sheet 컴포넌트 로직 및 성능

## 참조 자료

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | LOGIC-025 fixed header z-index 값 | z-index:3 (inline) | CSS `<th>` sticky-top이 z-index:2, resizer가 z-index:3이므로 fixed header도 z-index:3으로 설정. resizer는 header 내부이므로 stacking context가 분리되어 충돌 없음 |
| D2 | PERF-001 최적화 범위 | column-level 스타일만 pre-compute | `_getColDefStyle`/`_getFixedStyle`는 column-level이므로 computed로 캐싱 가능. custom style fn은 사용자 제공 함수라 캐싱 불가 |
| D3 | PERF-002 Set 캐싱 방식 | computed signal로 추출 | `expandedItems` signal 의존이므로 computed가 자동 무효화하여 정합성 보장 |
| D4 | LOGIC-025 footer fixed cell z-index | z-index:3 (header와 동일) | footer도 sticky-bottom z-index:2와 경쟁하므로 header와 동일한 규칙 적용 |
| D5 | PERF-001 pre-compute 분리 | header용 / body용 두 개의 computed Map | LOGIC-025 때문에 fixed header(z-index:3)와 fixed body(z-index:1)의 z-index가 다르므로 별도 캐싱 필요 |

## 구현계획

### 배경

sd-sheet 컴포넌트와 useExpandingManager에 리뷰에서 발견된 로직 버그 3건(LOGIC-006, LOGIC-025, LOGIC-026)과 성능 이슈 2건(PERF-001, PERF-002)이 있다. 모든 이슈가 독립적인 코드 영역에 위치하여 순차적으로 수정 가능하다.

### 목표

- stale DOM 참조로 인한 포커스 실패 방지 (LOGIC-006)
- fixed column의 z-index 계층 정상화 (LOGIC-025)
- width/collapse 동시 설정 시 스타일 모순 제거 (LOGIC-026)
- column-level 스타일 pre-compute로 per-cell 계산 절감 (PERF-001)
- expandedItems Set 캐싱으로 N번 생성을 1번으로 축소 (PERF-002)

### 비목표

- 템플릿 메서드 중 custom style fn(`getItemCellStyleFn`)의 캐싱 — 사용자 제공 함수라 불가
- `isCellEditMode`의 캐싱 — signal read + 비교로 이미 O(1)
- `getItemDef`의 캐싱 — `defMap()` computed Map lookup으로 이미 O(1)

### 설계

#### PERF-002: expandedItems Set 캐싱

`useExpandingManager`에 `_expandedSet` computed 추가:

```typescript
const _expandedSet = computed(() => new Set(binding.expandedItems()));
```

`isVisible()`과 `isAllExpanded`에서 `new Set(binding.expandedItems())` 대신 `_expandedSet()` 사용.

#### LOGIC-026: collapse 우선 early return

`_getColDefStyle()`에서 `collapse=true`일 때 width 블록을 건너뛰도록 조건 순서 변경:

```
if (collapse) → collapse 스타일 반환 (width 무시)
if (width) → width 스타일 반환
```

#### LOGIC-025: fixed header/footer z-index

`_getFixedStyle()`에 z-index 파라미터 추가:

```typescript
private _getFixedStyle(colDef: ISdSheetColumnDef, zIndex: number = 1): string | null
```

- `getHeaderCellStyle` → `_getFixedStyle(colDef, 3)` 호출
- `getFixedCellStyle` (footer) → `_getFixedStyle(colDef, 3)` 호출
- `getCellStyle` (body) → `_getFixedStyle(colDef, 1)` 유지

z-index 계층:

| 요소 | z-index | position |
|------|---------|----------|
| body fixed cell | 1 | sticky left |
| header/footer non-fixed | 2 | sticky top/bottom (CSS) |
| header/footer fixed | 3 | sticky left + top/bottom (inline) |
| resizer | 3 | absolute 내부 (별도 stacking context) |
| resize indicator | 10 | absolute |

#### LOGIC-006: _enterEditMode DOM 재조회

`_enterEditMode`에서 signal set 전 cell 캡처를 제거하고, queueMicrotask 내부에서 DOM 재조회:

```typescript
function _enterEditMode(r: number, c: number): void {
  editModeCellAddr.set({ r, c });
  queueMicrotask(() => {
    const cell = options.domAccessor.getCell(r, c);
    if (cell == null) return;
    const focusable = cell.findFirstFocusableChild();
    if (focusable !== undefined) {
      focusable.focus();
    }
  });
}
```

#### PERF-001: column-level 스타일 pre-compute

두 개의 computed Map 생성:

- `_headerColumnStyles`: header/footer용 (fixed z-index:3)
- `_dataColumnBaseStyles`: body용 (fixed z-index:1)

`getHeaderCellStyle`, `getCellStyle`, `getFixedCellStyle`에서 Map lookup으로 대체.

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| LOGIC-025: `_getFixedStyle`에 z-index 파라미터 | 채택 | 최소 변경, 기존 시그니처 하위 호환 (default=1) |
| LOGIC-025: getHeaderCellStyle에서 z-index override | 미채택 | 문자열 치환이 필요하여 취약 |
| PERF-001: per-cell computed | 미채택 | Angular 템플릿에서 동적 개수의 computed 생성 불가 |
| PERF-001: `@defer` / virtual scroll | 미채택 | 범위 초과, 별도 Feature 필요 |
