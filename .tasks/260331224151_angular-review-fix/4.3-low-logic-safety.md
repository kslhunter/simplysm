# Feature 4.3 Low - 로직 안전성 일괄 수정

## 참조 자료

- [wbs.md](./wbs.md)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | 12개 Rule을 단일 Feature로 처리 | 그대로 진행 | 모두 Low severity 단순 수정이므로 오버헤드 최소화 |
| D2 | SW backoff 전략 | exponential backoff (5m→10m→20m→max 1h) | 무한 등간격 폴링 방지, 최대 1시간으로 제한 |
| D3 | 테마 effect write 방지 | 값 비교 후 변경 시에만 write | storage 이벤트 동기화는 과도, 값 비교가 단순하고 충분 |

```gherkin

  Rule: localStorage 파싱은 손상 데이터에도 안전해야 한다

    Scenario: 유효한 JSON을 파싱한다

    Scenario: 세미콜론과 window=true가 있으면 true

      When isWindow를 확인한다

      Given SW checkForUpdate가 첫 번째로 실패한다

      Then 5분 후 재시도한다

      Then 간격이 5m → 10m → 20m으로 증가한다

    Scenario: 최대 간격 제한
      Given SW checkForUpdate가 다수 회 연속 실패한다
      When 폴링 주기가 설정된다
      Then 최대 1시간을 초과하지 않는다

    Scenario: 성공 후 간격 리셋
      Given SW checkForUpdate가 성공한다
      When 폴링 주기가 설정된다

      When effect가 초기 실행된다
      Then localStorage.setItem이 호출되지 않는다

    Scenario: dark 토글 시 write 수행
      Given dark signal이 false에서 true로 변경된다
      When effect가 실행된다
      Then localStorage에 true를 저장한다

  Rule: 모달 widthPx/heightPx가 undefined로 변경 시 inline style을 제거한다

      Given 모달이 열려 있다
      When widthPx가 300으로 설정된다

      Given dock의 position이 "right"이다
      When drag로 width가 200px로 계산된다
      Then style.width가 "200px"로 설정된다

    Scenario: drag로 음수 크기 계산 시 0으로 클램프
```

## 구현계획

### 배경

@simplysm/angular v14 코드 리뷰에서 발견된 Low severity 이슈 12건(LOGIC-036~047)을 수정한다. 모두 edge case 방어 코드 누락으로, 각각 1~5줄 수준의 단순 수정이다.

### 목표

- 12개 Low severity 로직 이슈를 수정하여 edge case에서도 안전하게 동작
- 각 수정에 대한 단위 테스트 추가

### 비목표

- 새로운 기능 추가
- 성능 최적화 (Feature 4.4 범위)
- 아키텍처 변경

### 설계

각 이슈별 수정 방법:

| 이슈 | 파일 | 수정 방법 |
|------|------|-----------|
| LOGIC-036 | sd-local-storage.provider.ts | `JSON.parse`를 try-catch로 감싸고 실패 시 `undefined` 반환 |
| LOGIC-037 | sd-navigate-window.provider.ts | `indexOf(";")`가 -1이면 early return `false` |
| LOGIC-038 | provideSdAngular.ts | `failCount` 변수 추가, catch에서 증가, 간격 = `Math.min(BASE * 2^failCount, MAX)`, 성공 시 리셋 |
| LOGIC-039 | provideSdAngular.ts | `let prev` 변수로 이전 값 추적, 변경 시에만 `set()` 호출 |
| LOGIC-040 | sd-modal.control.ts | `if (w !== undefined)` 뒤에 `else { dialogEl.style.width = "" }` 추가, height도 동일 |
| LOGIC-041 | sd-dock.control.ts | 4개 분기의 계산식에 `Math.max(0, ...)` 적용 |
| LOGIC-042 | sd-dropdown.control.ts | `_isMobile`을 `signal()`로 변환, MQL 콜백에서 `.set()`, effect에서 `()` 호출 |
| LOGIC-043 | sd-address-search.modal.ts | `/[동로가]$/g` → `/[동로가]$/` (g 제거) |
| LOGIC-044 | sd-shared-data-select-list.control.ts | `_filteredItems` computed 추출 (hidden+search+filterFn 적용), `pageLength`와 `displayItems`가 이를 공유 |
| LOGIC-045 | sd-progress.control.ts | `Math.min(v * 100, 100)` → `Math.min(Math.max(v * 100, 0), 100)` |
| LOGIC-046 | sd-router-link.directive.ts | `"[style.cursor]": "'pointer'"` → `"[style.cursor]": "option() ? 'pointer' : ''"` |
| LOGIC-047 | format.pipe.ts | `if (fullLength == null) continue;` 추가 (기존 `if (fullLength === value.length)` 앞) |

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| LOGIC-039: storage 이벤트로 multi-tab 동기화 | 미채택 | 과도한 복잡도. 값 비교만으로 초기 write 방지 충분 |
| LOGIC-044: displayItems 내에서 pageLength 인라인 계산 | 미채택 | computed 분리가 재사용성 높고 단일 책임 원칙 준수 |
| LOGIC-042: _isMobile을 computed로 구현 | 미채택 | MQL은 이벤트 기반이므로 signal + addEventListener가 적합 |
