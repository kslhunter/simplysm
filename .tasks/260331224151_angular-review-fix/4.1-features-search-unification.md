## 구현계획

### 배경

@simplysm/angular의 features 디렉토리에 있는 5개 컴포넌트/컨트롤에서 리뷰 이슈 5건(LOGIC-027/028/029/035, CONSIST-001)이 발견되었다. 각 이슈는 서로 다른 파일에 위치하며, 검색 통일(CONSIST-001)만 2개 파일에 걸친다.

### 목표

- 외부 스크립트 로드 실패 시 무한 spinner 방지
- dataInfo null 상태의 논리적 모순 해소
- effect 이중 트리거 방어
- 드롭다운 닫힘 감지의 초기 실행 보호
- shared-data 검색 로직 통일

### 비목표

- UI 동작 변경 (기존 정상 동작은 유지)
- 테스트 인프라 변경 (기존 테스트 프레임워크 그대로 사용)
- Feature 4.2~4.4에 해당하는 이슈 수정

### 설계

#### LOGIC-027: scriptEl.onerror 추가

`sd-address-search.modal.ts`의 `initAsync()`에서 script 엘리먼트 생성 시:
- `scriptEl.onerror` 핸들러 추가
- `reject(new Error("..."))` 호출로 Promise 종료
- `void this.initAsync()`의 unhandled rejection → `SdGlobalErrorHandlerPlugin`이 처리

#### LOGIC-028: dataInfo null 가드

`sd-data-detail.control.ts`의 `doSubmit()`에서:
- 기존: `!this.dataInfo()?.isNew` — undefined일 때 `!undefined === true`
- 변경: `dataInfo() == null` 일 때 조기 리턴 (submit 불가 상태)

#### LOGIC-029: onCleanup 기반 stale guard

`sd-data-sheet.control.ts`의 refresh effect에서:
- `effect(() => ...)` → `effect((onCleanup) => ...)`
- effect 본문에 `let cancelled = false; onCleanup(() => { cancelled = true; });`
- `queueMicrotask` 콜백 진입 시 `if (cancelled) return;`
- Angular scheduler가 동기 배치를 coalesce하므로 실제 이중 트리거 가능성은 낮지만, 코드 의도가 명확해짐

#### LOGIC-035: 이전 값 기반 전환 감지

`sd-shared-data-select.control.ts` constructor의 effect에서:
- effect 외부에 `let prevOpen = false;` 선언
- effect 본문에서 `dropdownOpen()` 읽은 후 이전 값(`prevOpen`)과 비교
- `prevOpen === true && currentOpen === false` 일 때만 `searchText.set(undefined)`
- 매 실행 후 `prevOpen = currentOpen` 갱신

#### CONSIST-001: 공통 검색 유틸 추출

`features/shared-data/matchesSearchText.ts` 신규 파일:
```typescript
export function matchesSearchText(itemText: string, searchQuery: string | undefined): boolean
```
- `searchQuery`를 trim → 공백 split → 빈 문자열 제거
- 각 term에 대해 `itemText.toLowerCase().includes(term.toLowerCase())` AND 매칭
- 빈 terms → true 반환

적용:
- `sd-shared-data-select-list.control.ts`: `displayItems` computed에서 `matchesSearchText(item.__searchText, this.searchText())` 사용
- `sd-shared-data-select.control.ts`: `isIncludeSearchText`에서 term 분리 + 매칭 로직을 `matchesSearchText` 호출로 교체 (트리 재귀는 유지)

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| LOGIC-029: signal 합치기 (`{page, filter}`) | 미채택 | page와 lastFilter를 분리한 기존 설계 전체를 변경해야 하며 침습적 |
| LOGIC-029: `untracked`로 page.set 격리 | 미채택 | `untracked`는 signal read 추적만 제어하며 write notification은 막지 못함 |
| LOGIC-035: `linkedSignal` / `computed` | 미채택 | dropdownOpen의 "전환"을 감지해야 하므로 이전 값 비교가 직접적 |
| CONSIST-001: core/utils에 유틸 배치 | 미채택 | 사용처가 shared-data 2곳뿐. 과잉 추상화 |
