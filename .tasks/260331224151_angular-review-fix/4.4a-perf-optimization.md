## 구현계획

### 배경

sd-select의 contentHTML 추적 effect와 sd-sheet의 isExpanded 메서드에 성능 이슈가 있다. sd-select effect는 모든 item의 `value()` signal을 구독하여 불필요한 재실행이 발생하고, sd-sheet의 `isExpanded()`는 `Array.includes()`로 O(n) 선형 탐색을 수행한다.

### 목표

- PERF-004: sd-select effect의 signal 구독 수를 O(N)→O(K)로 감소 (K=선택된 item 수)
- PERF-005: sd-sheet isExpanded를 O(1) Set.has() lookup으로 변환

### 비목표

- PERF-006 (data-sheet diff 캐싱): items가 in-place mutation되어 signal 기반 캐싱 불가, 제외

### 설계

#### PERF-004: sd-select contentHTML effect 최적화

`sd-select.control.ts`의 effect(line 322-368)에서 `item.value()` 읽기를 `untracked`로 감싸고, 선택된 item의 `contentHTML()`만 tracked로 읽는다.

현재: `_itemControls()`, `value()`, 모든 item의 `value()`, 선택된 item의 `contentHTML()` 구독 → O(N) 구독
변경: `_itemControls()`, `value()`, 선택된 item의 `contentHTML()`만 구독 → O(K) 구독

`_itemControls()`가 item 추가/제거를 감지하고, `value()`가 선택 변경을 감지하므로, 개별 item의 `value()` 구독은 불필요하다.

#### PERF-005: sd-sheet isExpanded Set lookup

`sd-sheet.control.ts`에 `private readonly _expandedSet = computed(() => new Set(this.expandedItems()))` 추가. `isExpanded()` 메서드를 `this._expandedSet().has(item)` 으로 변경.

동일 패턴이 `useExpandingManager.ts` line 53에 이미 존재한다.

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| PERF-004: untracked로 value() 감싸기 | 채택 | 최소 변경으로 구독 수 O(N)→O(K) 감소 |
| PERF-004: computed로 selectedItems 분리 | 미채택 | effect 구조 변경이 크고, untracked 방식으로 충분 |
| PERF-005: useExpandingManager에서 isExpanded 노출 | 미채택 | 공개 API 변경 필요, sd-sheet 내부 computed이 더 단순 |
| PERF-005: sd-sheet에 computed Set 추가 | 채택 | 기존 패턴과 일치, 최소 변경 |
