# Feature 4.2a Provider 및 유틸리티 안전성

## 참조 자료

- [wbs.md](./wbs.md)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | 인쇄 폴링 타임아웃 값 | 300회 × 100ms = 30초 | 복잡한 인쇄 템플릿도 30초면 충분. 리뷰 제안값 |
| D2 | useSdSystemConfigResource undefined 키 방어 위치 | Angular resource API 의존 | Angular 21의 resource()가 params()=undefined일 때 loader를 호출하지 않으며, TypeScript 타입이 이를 강제함. LOGIC-017은 Angular 21에서 false positive |
| D3 | update 메서드 this 바인딩 수정 방식 | set을 로컬 함수로 추출 | closure로 set을 직접 캡처하여 this 의존 제거 |
| D4 | 파일 다이얼로그 cancel 감지 개선 방식 | cancel 이벤트(Chrome 77+) primary + focus 폴백(Chrome 61+) | 점진적 향상. 기존 race condition도 함께 수정 |

```gherkin
      Given const { update } = useSdSystemConfigResource(...)로 destructuring했다
```

## 구현계획

### 배경

Feature 4.2a는 4개의 리뷰 이슈(LOGIC-015, LOGIC-017, LOGIC-018, DESIGN-002)를 수정한다.
모두 기존 코드의 edge case 방어 강화로, 새로운 기능 추가가 아니다.
각 이슈는 서로 다른 파일에 위치하여 독립적으로 수정 가능하다.

### 목표

- 인쇄 폴링에 타임아웃을 추가하여 무한 busy 방지
- 시스템 설정 리소스의 undefined 키 요청 방지 및 this 바인딩 안전성 확보
- 파일 다이얼로그 cancel 감지의 안정성 향상

### 비목표

- `queueMicrotask` 교체 (Feature 1.1 범위)
- 인쇄 UI/기능 변경
- 파일 다이얼로그의 UX 변경

### 설계

#### LOGIC-015: sd-print.provider.ts

`wait.until`에 `maxCount: 300` (30초) 추가. 초과 시 `TimeoutError`가 상위 try-finally로 전파되어 busy 해제.

#### LOGIC-017 + LOGIC-018: useSdSystemConfigResource.ts

- loader 내부에 `key == null` 가드 추가 → undefined 키 시 즉시 `undefined` 반환
- `set`을 객체 메서드에서 로컬 함수로 추출 → `update`가 `this.set` 대신 클로저의 `set`을 직접 호출

#### DESIGN-002: sd-file-dialog.provider.ts

- `cancel` 이벤트 리스너 추가 (Chrome 77+에서 활성화, 미지원 브라우저에서 무시)
- `resolve(undefined)`를 `if (inputEl)` 블록 안으로 이동 → onchange가 먼저 실행된 경우 중복 resolve 방지

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| LOGIC-017: params에서 undefined 반환으로 loader 방지 | 미채택 | Angular resource의 undefined params 동작이 버전마다 다를 수 있음 |
| LOGIC-018: 반환 객체에 화살표 함수 사용 | 미채택 | 객체 리터럴의 화살표 함수는 this가 외부 스코프를 가리킴. 로컬 함수 추출이 더 명확 |
| DESIGN-002: visibilitychange 이벤트 사용 | 미채택 | 파일 다이얼로그는 같은 탭에서 열리므로 visibility 변경이 발생하지 않음 |


#### Slice 2: 시스템 설정 리소스 안전성
