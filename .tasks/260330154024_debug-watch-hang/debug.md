# 디버그: watch 명령 "초기 빌드 실행 중..."에서 멈춤

## 출처

- **origin:** `direct`
- **완료 시 참고:** 해당 없음

## 에러 증상

- **에러 메시지:** 없음 (행 현상)
- **위치:** `packages/sd-cli/src/orchestrators/DevWatchOrchestrator.ts:292-296`
- **재현:** `pnpm sd-cli --debug watch` 실행 후 "초기 빌드 실행 중..."에서 진행 없음

## 근본 원인 추적 (ACH)

### ACH 매트릭스

|    | E1: "초기 빌드 실행 중..." 이후 출력 없음 | E2: 메인 프로세스 디버그 로그(⚙) 정상 출력 | E3: allSettled 미완료 |
|----|------------------------------------------|------------------------------------------|---------------------|
| H1: 17개+ 패키지 tsc 병렬 빌드가 오래 걸림 (정상 동작) | C | C | C |
| H2: Worker 스레드 생성 실패/데드락 | C | C | I → 폐기 |
| H3: consola .start() 스피너가 후속 로그 덮어씀 | C | C | I → 폐기 |

### 결과: 확정 — H1

`sd.config.ts`에 정의된 17개 라이브러리 패키지(+ tests/ 하위 패키지)가 각각 별도 Worker 스레드에서 tsc 초기 빌드를 병렬 실행한다. `Promise.allSettled`가 모든 빌드 완료를 대기하므로, 완료까지 진행 표시 없이 대기하는 것이 원인이다.

H2 폐기: `BaseEngine.startWatch`는 error 이벤트와 catch 모두에서 resolve 처리하므로 워커 실패로 인한 무한 대기는 불가능.
H3 폐기: consola `.start()`는 정적 로그이며 Promise 해소와 무관.
