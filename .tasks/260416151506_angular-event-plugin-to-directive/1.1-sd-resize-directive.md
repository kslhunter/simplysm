## 구현계획

### 배경

`@simplysm/angular`의 커스텀 이벤트 `sdResize`는 Angular 내부 API인 `EventManagerPlugin`을 통해 구현되어 있다 (`SdResizeEventPlugin`). 이는 비공식 API이므로 향후 Angular 버전 업그레이드 시 breaking change 리스크가 있다. 이를 standalone directive로 전환하여 공식 API만 사용한다.

### 목표

- `SdResizeEventPlugin`을 `SdResizeDirective`로 전환 [근거: Rule "SdResizeDirective는 호스트 엘리먼트의 크기 변화를 감지"]
- 7개 사용처 마이그레이션 [근거: Rule "기존 (sdResize) 템플릿 바인딩 문법이 유지된다"]
- 기존 plugin 및 관련 등록 제거 [근거: Rule "SdResizeEventPlugin과 관련 등록이 완전히 제거된다"]

### 비목표

- `SdOptionEventPlugin`(.capture/.passive/.once) 전환 [근거: wbs 경계]
- `SdIntersectionEventPlugin`, 커맨드 plugin 전환 [근거: wbs 경계]

### 설계

**SdResizeDirective** (`packages/angular/src/core/events/sd-resize.ts`):

```typescript
@Directive({
  selector: "[sdResize]",
  standalone: true,
})
export class SdResizeDirective {
  private readonly _elRef = inject(ElementRef);
  private readonly _destroyRef = inject(DestroyRef);

  sdResize = output<SdResizeEvent>();

  constructor() {
    let prevWidth = 0;
    let prevHeight = 0;
    let animationFrameId: number | undefined;

    const resizeObserver = new ResizeObserver(([entry]) => {
      if (animationFrameId != null) {
        cancelAnimationFrame(animationFrameId);
      }
      animationFrameId = requestAnimationFrame(() => {
        const contentRect = entry.contentRect;
        const heightChanged = contentRect.height !== prevHeight;
        const widthChanged = contentRect.width !== prevWidth;
        prevHeight = contentRect.height;
        prevWidth = contentRect.width;

        this.sdResize.emit({
          heightChanged,
          widthChanged,
          target: entry.target,
          contentRect: entry.contentRect,
        });
      });
    });

    resizeObserver.observe(this._elRef.nativeElement);

    this._destroyRef.onDestroy(() => {
      if (animationFrameId != null) {
        cancelAnimationFrame(animationFrameId);
      }
      resizeObserver.disconnect();
    });
  }
}

export interface SdResizeEvent {
  heightChanged: boolean;
  widthChanged: boolean;
  target: Element;
  contentRect: DOMRectReadOnly;
}
```

### 대안 검토

1. **afterNextRender로 ResizeObserver 초기화 지연**: SSR 환경에서 `ResizeObserver`가 없을 수 있으나, 이 프로젝트는 브라우저 전용(`provideZonelessChangeDetection()`)이므로 불필요. 기각.

2. **setup 함수 패턴 (`setupResize`)**: 기존 코드베이스에 `setupRipple()`, `setupInvalid()` 등의 패턴이 있으나, 이들은 output을 갖지 않는 부수효과 설치 패턴. `(sdResize)="..."` 템플릿 바인딩 패턴을 유지하려면 directive가 적합. 기각.
