## 구현계획

### 배경

`SdIntersectionEventPlugin`은 Angular 내부 API `EventManagerPlugin`을 확장하여 `sdIntersection` 커스텀 이벤트를 처리한다. Feature 1.1에서 `SdResizeEventPlugin`을 `SdResizeDirective`로 성공적으로 전환한 패턴이 존재하며, 이를 그대로 따른다. [근거: `sd-resize.ts` 패턴 확인]

### 목표

- `SdIntersectionEventPlugin`을 standalone directive로 전환하여 Angular 내부 API 의존성 제거 [근거: Rule "IntersectionObserver를 directive로 전환"]
- 기존 `SdIntersectionEvent` 타입 인터페이스 유지 [근거: Rule "기존 이벤트 타입 유지"]

### 비목표

- 사용처 마이그레이션 (0건) [근거: WBS 경계]
- `SdEvents` 수정 (sdIntersection 미포함) [근거: WBS 경계]
- `SdOptionEventPlugin` 전환 [근거: WBS 제외사항]

### 설계

`SdIntersectionDirective` — `sd-resize.ts`의 `SdResizeDirective` 패턴을 따름:

- `selector: "[sdIntersection]"`, `standalone: true`
- `inject(ElementRef)`, `inject(DestroyRef)` 사용
- constructor에서 `IntersectionObserver` 생성, `observe(nativeElement)` 호출
- 콜백에서 마지막 entry를 `SdIntersectionEvent` 형태로 output emit
- `_destroyRef.onDestroy()`에서 `observer.disconnect()`

[근거: Feature 1.1 `SdResizeDirective` 구현 패턴, 기존 plugin 로직]

### 대안 검토

| 접근 | 선택 여부 | 사유 |
|---|---|---|
| EventManagerPlugin 유지 | X | Angular 내부 API — 프로젝트 목표와 상반 |
| hostDirectives 패턴 | X | 사용처 0건이므로 과도한 설계 |
| Standalone directive | O | Feature 1.1과 동일 패턴, 단순 명확 |
