## 구현계획

### 배경

`createSourceFileCachePlugin`은 esbuild dev watch 모드에서 파일 변경을 감지하여 `sourceFileCache`를 무효화하는 플러그인이다. 현재 `onEnd`에서 매 빌드마다 `prevMtimes.clear()` 후 전체 watchTargets를 순회하며 `fs.statSync`를 호출하고, `onStart`에서도 전체 순회하여 변경을 감지한다. 대규모 프로젝트(1000~2000+ 파일)에서 빌드 사이클마다 수천 회의 동기 I/O가 발생한다. [근거: `client.worker.ts:199-248`, review.md PERF-001]

### 목표

- `onEnd`의 stat 호출을 변경/신규 파일로 한정하여 I/O를 최소화한다 [근거: Rule "onEnd에서 prevMtimes를 증분 갱신한다"]
- 삭제된 파일의 prevMtimes 항목을 정리하여 메모리 누수를 방지한다 [근거: Rule "삭제된 파일의 prevMtimes 항목을 정리한다"]
- `onStart`의 변경 감지 결과는 기존과 동일해야 한다 [근거: Rule "onStart의 변경 감지는 동작적으로 동일하다"]

### 비목표

- esbuild sourceFileCache 무효화 로직 변경 [근거: wbs 경계]
- `onStart`/`onEnd` 이외의 빌드 파이프라인 변경 [근거: wbs 경계]
- `fs.statSync`를 비동기(`fs.promises.stat`)로 전환 [근거: esbuild onEnd는 void 반환이므로 비동기 불가 — D1]

### 설계

**변경 대상**: `createSourceFileCachePlugin()` 함수 내부 (`client.worker.ts:193-251`)

**1. 클로저 변수 추가**

`changedFiles`를 `onStart`/`onEnd` 간 공유할 클로저 변수로 끌어올린다.

```typescript
const prevMtimes = new Map<string, number>();
let lastChangedFiles = new Set<string>(); // 추가
```

**2. onStart 핸들러 (변경 없음)**

기존 로직 그대로 유지. 단, `changedFiles`를 클로저 변수 `lastChangedFiles`에 할당.

```typescript
pluginBuild.onStart(() => {
  if (esbuildResult != null) {
    const { loadResultCache, typeScriptFileCache } = esbuildResult.sourceFileCache;
    const changedFiles = new Set<string>();
    const watchTargets = [
      ...loadResultCache.watchFiles,
      ...typeScriptFileCache.keys(),
    ];
    for (const file of watchTargets) {
      try {
        const mtime = fs.statSync(file).mtimeMs;
        const prev = prevMtimes.get(file);
        if (prev != null && prev !== mtime) {
          changedFiles.add(file);
        }
      } catch {
        if (prevMtimes.has(file)) {
          changedFiles.add(file);
        }
      }
    }
    if (changedFiles.size > 0) {
      esbuildResult.sourceFileCache.invalidate(changedFiles);
    }
    lastChangedFiles = changedFiles; // 추가
  }
  // ...
});
```

**3. onEnd 핸들러 (핵심 변경)**

`prevMtimes.clear()` + 전체 순회를 3단계 증분 갱신으로 교체:

```typescript
pluginBuild.onEnd(() => {
  if (esbuildResult == null) return;

  const currentWatchTargets = new Set([
    ...esbuildResult.sourceFileCache.loadResultCache.watchFiles,
    ...esbuildResult.sourceFileCache.typeScriptFileCache.keys(),
  ]);

  // 1) 삭제된 파일 정리: prevMtimes에 있지만 watchTargets에 없는 파일 제거
  for (const file of prevMtimes.keys()) {
    if (!currentWatchTargets.has(file)) {
      prevMtimes.delete(file);
    }
  }

  // 2) 변경된 파일 mtime 재조회
  for (const file of lastChangedFiles) {
    try {
      prevMtimes.set(file, fs.statSync(file).mtimeMs);
    } catch {
      prevMtimes.delete(file);
    }
  }

  // 3) 신규 파일만 stat (prevMtimes에 없는 파일)
  for (const file of currentWatchTargets) {
    if (!prevMtimes.has(file)) {
      try {
        prevMtimes.set(file, fs.statSync(file).mtimeMs);
      } catch {
        // 삭제된 파일
      }
    }
  }

  lastChangedFiles = new Set();
});
```

### 대안 검토

| 대안 | 이유 (미채택) |
|---|---|
| `fs.promises.stat` + `Promise.all` 비동기 병렬화 | esbuild `onEnd`는 void 반환(비동기 불가). 증분 방식이 I/O 횟수 자체를 줄여 더 효과적 |
| `onStart`에서만 처리하고 `onEnd` 제거 | `onStart`에서 현재 watchTargets를 알 수 없음(이전 빌드의 watchTargets 필요). `onEnd`에서 신규 파일을 등록해야 다음 `onStart`에서 변경 감지 가능 |

### Slice

#### [x] Slice 1: onEnd 증분 갱신 + 삭제 파일 정리

- **구현 내용:** `onEnd`의 `prevMtimes.clear()` + 전체 순회를 증분 갱신으로 전환. `lastChangedFiles` 클로저 변수 추가. 삭제된 파일 정리 로직 추가.
- **Scenarios:** 변경된 파일만 mtime 갱신, 새로 추가된 파일만 stat 호출, 변경도 신규도 없으면 stat 호출 0회, 삭제된 파일이 prevMtimes에서 제거된다, 첫 빌드 시 onStart가 아무 것도 하지 않는다, mtime 변경된 파일이 changedFiles에 포함, 삭제된 파일이 changedFiles에 포함, 신규 파일은 changedFiles에 포함되지 않음
