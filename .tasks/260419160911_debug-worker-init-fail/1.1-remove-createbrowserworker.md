## 구현계획

### 배경

`client-protocol-wrapper.ts`의 `getWorker()` 함수에서 Worker를 생성할 때 `createBrowserWorker()` 래퍼를 사용하고 있으나, esbuild Worker 플러그인은 `new Worker(new URL(...))` AST 패턴만 인식한다 [근거: `esbuild-worker-plugin.ts:61-106`]. `isWorkerAvailable()` 가드가 이미 `globalThis.Worker` 존재를 보장하므로 래퍼의 안전 검사는 불필요하다 [근거: `client-protocol-wrapper.ts:32-37`].

### 목표

- Worker 생성을 표준 `new Worker()` 패턴으로 변경하여 esbuild 플러그인이 인식하도록 한다 [근거: Rule "Worker 생성은 반드시 new Worker(new URL(...)) 직접 패턴 사용"]
- 코드 주석과 참조 문서로 재발을 방지한다 [근거: 설계 결정 D2]

### 비목표

- esbuild Worker 플러그인 자체의 패턴 인식 확장 [근거: wbs 제외 사항]
- Worker 파일 내용 변경 [근거: wbs 경계]

### 설계

1. **`client-protocol-wrapper.ts:48-51`**: `createBrowserWorker()` → `new Worker()` 직접 사용. `isWorkerAvailable()`가 true이므로 `globalThis.Worker`가 존재함이 보장됨. 반환 타입을 `BrowserWorker`로 캐스팅 [근거: 기준 코드 `browser-compat.ts:40-44` — 래퍼 내부에서도 동일한 `new WorkerCtor()` 호출]
2. **import 정리**: `createBrowserWorker` import 제거, `isWorkerSupported`는 value import로 유지 [근거: `client-protocol-wrapper.ts:34`에서 사용]
3. **주석 추가**: Worker 생성부에 래퍼 사용 금지 이유를 명시하는 주석 [근거: 설계 결정 D2]
4. **`browser-compat.ts:34-45`**: `createBrowserWorker` 함수 삭제. 나머지 export 유지 [근거: Rule "나머지 export 유지"]
5. **참조 문서**: `.claude/references/sd-simplysm14/service-client/docs/protocol.md`에 Worker 생성 제약 추가 [근거: 설계 결정 D2]
