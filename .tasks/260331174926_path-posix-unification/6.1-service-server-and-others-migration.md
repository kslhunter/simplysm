## 구현계획

### 배경

Feature 1.1에서 `posix()`가 multi-arg에서 single-arg로 변경되고, `posixResolve()`/`PosixPath`가 도입되었다. `norm()`/`NormPath`는 deprecated 상태이다. service-server와 기타 패키지의 호환성을 검증해야 한다.

### 목표

- service-server의 `pathx.posix()`, `pathx.isChildPath()` 사용이 새 API와 호환되는지 검증
- sd-cli/core-node 외 패키지에 마이그레이션 대상이 없음을 확인

### 비목표

- service-server 내 `path.resolve`/`path.join` 호출의 `posixResolve()` 대체 (WBS 제외 사항: fs API 직접 사용이므로 POSIX 통일 불필요)
- FsWatcher의 NormPath→PosixPath 타입 변경 (Feature 1.2 범위)

### 설계

코드 변경 없음. 코드베이스 탐색 결과 service-server의 2개 사용처 모두 이미 새 API와 호환된다:
- `auto-update-service.ts:45` — `pathx.posix(path.join(...))` → single-arg 호환
- `static-file-handler.ts:18` — `pathx.isChildPath(...)` → 내부적으로 `posixResolve()` 사용

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| 변경 없이 호환성 검증만 수행 | 채택 | 코드가 이미 새 API 패턴과 호환됨 |
| PosixPath 타입을 명시적으로 사용하도록 리팩토링 | 미채택 | 타입 브랜드가 `"/" +` 연결 시 소실되고, 반환 타입이 `string`이므로 실익 없음 |
