## 구현계획

### 배경

sd-cli의 유틸리티 모듈 중 `output-path-rewriter.ts`는 `pathx.norm()`과 `path.sep`을 사용하여 경로를 정규화한다. `vite-config.ts`는 `.replace(/\\/g, "/")`로 ad-hoc 변환을 수행한다. Feature 1.1에서 도입된 `posix()`와 `posixResolve()`로 통일하여 Windows 경로 불일치 문제를 근본적으로 제거한다.

### 목표

- `output-path-rewriter.ts`의 `pathx.norm()` → `posixResolve()`, `path.sep` → `"/"` 마이그레이션
- `output-path-rewriter.ts`의 `adjustMapSources` 내 소스맵 상대 경로를 POSIX로 변환
- `vite-config.ts`의 ad-hoc `.replace(/\\/g, "/")` → `posix()` 통일

### 비목표

- `esbuild-config.ts` 변경 (fs/esbuild API 직접 전달이므로 불필요)
- `vite-scope-watch-plugin.ts` 변경 (fs API 직접 전달이므로 불필요)
- `vite-angular-plugin.ts` 변경 (Feature 2.2 범위)

### 설계

#### output-path-rewriter.ts 변경

import 변경: `{ pathx } from "@simplysm/core-node"` → `{ posix, posixResolve } from "@simplysm/core-node"`

`createOutputPathRewriter`:
- `pathx.norm(path.join(pkgDir, "dist"))` → `posixResolve(pkgDir, "dist")`
- `distDir + path.sep` → `distDir + "/"`
- `pathx.norm(path.join(distDir, pkgName, "src")) + path.sep` → `posixResolve(distDir, pkgName, "src") + "/"`
- `pathx.norm(fileName)` → `posixResolve(fileName)`
- `relFromDist.split(path.sep)` → `relFromDist.split("/")`

`adjustMapSources`:
- `path.relative(newDir, absoluteSource)` → `posix(path.relative(newDir, absoluteSource))`

`path` import: `path.join`이 더 이상 사용되지 않으므로 `path.basename`, `path.dirname`, `path.resolve`, `path.relative`만 남긴다. 실제로 `path.join`은 `createOutputPathRewriter`의 `path.join(distDir, fileName.slice(ownNestedPrefix.length))`에서 사용되므로 유지한다.

#### vite-config.ts 변경

import 추가: `import { posix } from "@simplysm/core-node";`

`sd-legacy-import-meta` 플러그인 내:
- `path.relative(pkgDir, id).replace(/\\/g, "/")` → `posix(path.relative(pkgDir, id))`

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| output-path-rewriter에서 `posix(fileName)` 사용 (resolve 없이) | 미채택 | fileName이 이미 절대 경로이므로 `posix()`만으로 충분하나, `posixResolve()`가 절대 경로 보장을 명시적으로 표현하여 의도가 명확 |
| adjustMapSources 변경 안 함 | 미채택 | Windows에서 `path.relative`가 백슬래시를 반환하므로 소스맵 내 경로 불일치 발생 가능. POSIX 변환 필요 |
