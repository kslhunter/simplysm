# Feature 5.1 Capacitor/Electron 빌드 마이그레이션

## 참조 자료

- [wbs.md](./wbs.md)

### 설계 결정

| # | 결정사항 | 선택 | 근거 |
|---|---------|------|------|
| D1 | cpx.exec cwd에 PosixPath 전달 | 허용 | cpx.exec은 Node.js child_process.spawn()에 cwd를 직접 전달하며, Node.js는 Windows에서 POSIX 경로("D:/...") 정상 처리 |
| D2 | Java 경로 이스케이프 처리 | 변환 대상 아님 (유지) | wbs.md 주의사항에 명시: `\\` → `\\\\`는 gradle.properties용 이스케이프이지 경로 정규화가 아님 |
| D3 | SDK 경로 forward slash 변환 | `posix()` 사용 | `sdkPath.replace(/\\/g, "/")` 패턴을 `posix(sdkPath)`로 통합 |

```gherkin
      Then 모든 경로가 POSIX 슬래시로 통일된다
      And fsx, cpx.exec 등에 전달되는 경로가 PosixPath 타입이다

      When path.resolve() 호출을 posixResolve()로 교체한다
      Then 모든 경로가 POSIX 슬래시로 통일된다
      And fsx, cpx.exec, esbuild 등에 전달되는 경로가 PosixPath 타입이다

    Scenario: path.join도 posixResolve로 교체
      Given electron.ts에서 path.join()으로 경로를 조합하는 코드가 있다 (symlink 테스트 등)
      When path.join() 호출을 posixResolve()로 교체한다
      Then 해당 경로도 POSIX 슬래시로 통일된다

  Rule: ad-hoc .replace(/\\/g, "/") → posix() 통합

    Scenario: capacitor.ts의 Android SDK 경로 변환을 posix()로 교체
      Given capacitor.ts _configureAndroidSdkPath에서 sdkPath.replace(/\\/g, "/")로 forward slash 변환한다
      When .replace(/\\/g, "/") 패턴을 posix(sdkPath)로 교체한다
      Then local.properties에 POSIX 스타일 SDK 경로가 기록된다

  Rule: Java 경로 이스케이프는 POSIX 변환 대상이 아니다

    Scenario: gradle.properties의 JAVA_HOME 이스케이프를 유지
      Given capacitor.ts _configureAndroidJavaHomePath에서 java21Path.replace(/\\/g, "\\\\")로 이스케이프한다
      When 마이그레이션을 수행한다
      Then 해당 이스케이프 코드는 변경하지 않는다
      And gradle.properties에 이중 백슬래시로 이스케이프된 Java 경로가 유지된다

  Rule: import 변경

    Scenario: path 모듈 import를 posixResolve/posix import로 교체
      Given capacitor.ts와 electron.ts에서 import path from "path"를 사용한다
      When posixResolve, posix를 @simplysm/core-node에서 import한다
      Then path.resolve/path.join 사용처가 제거되고 posixResolve로 대체된다
      And path 모듈이 더 이상 필요 없으면 import를 제거한다
      And path.dirname, path.basename, path.relative 등 posixResolve로 대체 불가한 것은 유지한다
```

## 구현계획

### 배경

sd-cli의 경로 처리를 `posix()`/`posixResolve()`/`PosixPath`로 통일하는 마이그레이션의 일부로, 네이티브 앱 빌드 모듈(capacitor.ts, electron.ts)의 `path.resolve()`/`path.join()` 호출과 ad-hoc 정규화 패턴을 교체한다.

### 목표

- capacitor.ts의 `path.resolve()` ~37건, `path.join()` 1건 → `posixResolve()` 교체
- electron.ts의 `path.resolve()` ~22건, `path.join()` 2건 → `posixResolve()` 교체
- capacitor.ts의 `sdkPath.replace(/\\/g, "/")` → `posix(sdkPath)` 교체
- import 정리: `posixResolve`, `posix`를 `@simplysm/core-node`에서 import

### 비목표

- Java 경로 이스케이프(`\\` → `\\\\`) 변경 (D2)
- `path.dirname()` 등 resolve/join이 아닌 path 유틸 교체
- 기존 테스트가 없으므로 단위 테스트 추가 (기존 파일에 테스트 없음)

### 설계

기계적 교체:
- `path.resolve(a, b)` → `posixResolve(a, b)`
- `path.join(a, b)` → `posixResolve(a, b)` (입력이 절대 경로이므로 동일 결과)
- `x.replace(/\\/g, "/")` → `posix(x)` (단순 슬래시 변환)
- capacitor.ts: `path.dirname` 3건 유지 → `import path` 유지
- electron.ts: `path` 미사용 → `import path` 제거

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| path.dirname도 posix(path.dirname(...))로 래핑 | 미채택 | PosixPath 입력 시 path.dirname은 forward slash를 정상 인식하여 POSIX 결과 반환. 타입 안전성은 이 Feature 범위 밖 |
| createRequire 인자를 file:// URL로 변환 | 미채택 | PosixPath 문자열을 createRequire가 정상 수용 |
