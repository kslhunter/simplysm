## 구현계획

### 배경

sd-cli의 파일 복사/배포 유틸리티(`copy-src`, `copy-public`, `replace-deps`)와 설정/패키지 유틸리티(`sd-config`, `package-utils`, `build-env`)에서 `path.join()`, `path.resolve()`, `path.relative()`, `path.dirname()` 등 Node.js `path` 모듈을 직접 사용하고 있다. Feature 1.1에서 도입된 `posix()`/`posixResolve()`로 통일하여 FsWatcher(PosixPath 반환)와의 경로 비교 일관성을 확보한다.

### 목표

- 6개 파일의 모든 `path.*` 호출을 `posix()`/`posixResolve()` 래핑으로 변환
- FsWatcher 콜백에서 받는 PosixPath와 내부 경로 변수 간 타입 일관성 확보

### 비목표

- 함수 시그니처의 파라미터/반환 타입을 `PosixPath`로 변경 (Feature 4.1 오케스트레이터에서 호출측 마이그레이션 시 함께 처리)
- `commands/replace-deps.ts` 변경 (wrapper — 직접 path 조작 없음)
- `replace-deps.ts`의 `replaceDepsCopyFilter` 내 `path.basename()` 변경 (파일명만 추출하므로 슬래시 방향 무관)

### 설계

각 파일의 변경은 기계적 패턴 치환이다. 새로운 로직이나 API를 도입하지 않는다.

| 파일 | 변경 패턴 | 건수 |
|------|-----------|------|
| `sd-config.ts` | `path.resolve()` → `pathx.posixResolve()` | 1 |
| `build-env.ts` | `path.join()` → `pathx.posix(path.join())` | 1 |
| `package-utils.ts` | `path.join()` → `pathx.posix(path.join())`, `path.dirname()` → `pathx.posix(path.dirname())` | ~17 |
| `copy-src.ts` | `path.join()` → `pathx.posix(path.join())`, `path.relative()` → `pathx.posix(path.relative())`, `path.dirname()` → `pathx.posix(path.dirname())` | ~10 |
| `copy-public.ts` | 동일 패턴, `pathx` import 이미 존재 | ~15 |
| `replace-deps.ts` | `path.resolve()` → `pathx.posixResolve()`, `path.join()` → `pathx.posix(path.join())`, `path.relative()` → `pathx.posix(path.relative())` | ~10 |

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| `pathx.posix()` 네임스페이스 import | 채택 | `copy-public.ts`와 `replace-deps.ts`는 이미 `pathx` import 사용. 나머지 파일도 `pathx`로 통일하여 일관성 유지 |
| `posix`, `posixResolve` 직접 import | 미채택 | `pathx.isChildPath` 등 다른 pathx 유틸과 혼용 시 네임스페이스가 더 명확 |
