## 구현계획

### 배경

replace-deps 화이트리스트 전환이 완료된 상태에서, 코드 리뷰에서 발견된 3건의 품질 이슈를 수정한다.

### 목표

- 테스트가 실제 동작을 정확히 검증하도록 개선 [근거: LOGIC-001, TEST-001]
- setupReplaceDeps와 watchReplaceDeps의 에러 처리를 일관되게 통일 [근거: CONSIST-001]

### 비목표

- 프로덕션 로직 변경 (CONSIST-001의 try-catch 추가 제외) [근거: wbs 경계]

### 설계

**1. LOGIC-001: 타겟 package.json version 차별화**

`replace-deps-setup.acc.spec.ts:29` — beforeEach에서 타겟 package.json 생성 시 version을 `"2.0.0"`으로 변경:
```typescript
JSON.stringify({ name: "@test/pkg", version: "2.0.0" })
```

`replace-deps-setup.acc.spec.ts:140` — 검증에서 `"2.0.0"` 확인:
```typescript
expect(targetPkgJson.version).toBe("2.0.0");
```

**2. CONSIST-001: watchReplaceDeps entry 단위 try-catch 추가**

`replace-deps.ts:148-174` — for 루프 내부를 try-catch로 감싸고, `setupReplaceDeps`와 동일한 에러 로그 패턴 적용:
```typescript
for (const entry of entries) {
  if (watchedSources.has(entry.resolvedSourcePath)) continue;
  watchedSources.add(entry.resolvedSourcePath);

  try {
    // 기존 로직 (loadFilesField ~ FsWatcher.watch)
  } catch (err) {
    logger.error(`[${entry.targetName}] 감시 설정 실패: ${err instanceof Error ? err.message : err}`);
  }
}
```

**3. TEST-001: npm 기본 파일 watch 테스트 추가**

`replace-deps-watch.spec.ts` — beforeEach에서 소스에 README.md를 추가하고, 새 테스트 케이스에서 README.md 변경 → onChanged 호출을 검증:
```typescript

  // beforeEach에서 README.md 생성 → watch 시작 → README.md 변경 → onChanged 호출 검증
}, 10_000);
```
