## 구현계획

### 배경

v12에서 v14로 마이그레이션 시 `._progress` 요소의 위치 기준이 `right: 0`에서 `left: 0`으로 변경됨. 이 변경이 width 계산 로직과 일치하는지 검증하는 Feature. [근거: wbs "width 계산 로직과 일치하는지 확인"]

### 목표

- `left: 0` + `width = value * 100%` 조합이 표준 LTR progress bar 동작과 일치하는지 확인 [근거: Rule "progress bar는 왼쪽에서 오른쪽으로 채워져야 한다"]

### 비목표

- progress bar 방향 변경 [근거: wbs 경계 "의도적 변경인 경우 유지"]
- width clamping 로직 변경 [근거: v14 개선사항]

### 설계

**검증 결과: 코드 변경 불필요**

- `left: 0` + `width: value * 100%` → 왼쪽에서 오른쪽으로 채워짐 (표준 LTR)
- `_barWidth` computed가 0-100% 범위로 clamping → 방어적 처리 완비
- v12의 `right: 0`은 비표준 방향(오른쪽→왼쪽)이었으며, v14에서 의도적으로 수정됨

### 대안 검토

| 접근 방식 | 선택 여부 | 사유 |
|---|---|---|
| v14 유지 (`left: 0`) | **선택** | 표준 LTR 관행, 의도적 개선 |
| v12 복원 (`right: 0`) | 미선택 | 비표준 방향, 퇴행에 해당 |
