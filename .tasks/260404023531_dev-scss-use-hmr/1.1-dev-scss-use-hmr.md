## 구현계획

### 배경

`sdAngularPlugin`의 `handleHotUpdate` 훅은 `isInProgram` 체크(L261-267)로 ts.Program에 없는 SCSS 파일 변경을 모두 무시한다. `client-transform-stylesheet`에서 `scssDependencies` Map(L93, closure 변수)에 `@use` 의존성을 수집하지만, `handleHotUpdate`에서 역방향 탐색이 구현되어 있지 않다. watch 모드(`ngtsc-build.worker.ts` L261-273)에는 동일 패턴이 이미 구현됨.

### 목표

- dev 모드 `handleHotUpdate`에서 SCSS `@use` 의존성 변경 시 영향받는 컴포넌트를 HMR으로 재컴파일
- inline styles와 styleUrl 모두 지원

### 비목표

- watch 모드 수정 (이미 정상 동작)
- SCSS 파일 자체의 직접 변경 감지 (이 Feature는 `@use` 간접 의존성만 다룸)

### 설계

`handleHotUpdate`에서 SCSS 파일 변경 시 `isInProgram` 체크 전에 SCSS 전용 분기를 추가한다:

1. `server` 디스트럭처링 추가 (기존: `file`, `modules`만)
2. `.scss` 파일이면 `scssDependencies` 역방향 탐색:
   - `scssDependencies`의 모든 entry를 순회
   - 변경된 파일이 entry의 deps(value) Set에 포함되면 → entry의 key(ownerFile)를 수집
   - inline styles: ownerFile = TS 파일
   - styleUrl: ownerFile = SCSS 파일
3. 수집된 ownerFile이 없으면 early return (무관한 SCSS)
4. `compiler.update(affectedFiles)` 호출:
   - inline: TS 파일 직접 재컴파일
   - styleUrl: `sourceFileCache.invalidate([scssFile])` → `modifiedFiles.add()` → `getResourceDependencies()` 체크로 TS 컴포넌트 탐색
5. `emitAffectedFiles()` → `emittedFiles` 업데이트
6. `server.moduleGraph.getModulesByFile()` → 영향받은 TS 모듈 조회 → HMR 반환

경로 호환성: `extractDependencies()` (scss-compiler.ts L16-20)는 `url.pathname` 기반 forward-slash 경로를 반환하며, Vite `handleHotUpdate`의 `file` 파라미터도 forward-slash. `pathx.posix()`로 정규화하여 비교.

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| `handleHotUpdate`에서 `scssDependencies` 역방향 탐색 | 채택 | watch 모드와 동일 패턴, 최소 변경 |
| Vite `addWatchFile()`로 SCSS 의존성 등록 | 미채택 | Angular 파이프라인 재컴파일을 트리거할 수 없음 |
| SCSS 변경 시 전체 페이지 리로드 | 미채택 | HMR 대비 DX 저하 |
