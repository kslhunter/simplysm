## 구현계획

### 배경

`MysqlDbConn.executeParametrized` (`mysql-db-conn.ts:136-181`)는 mysql2의 `conn.query()` 결과를 파싱하여 `Record<string, unknown>[][]`를 반환한다. 현재 코드는 multi-statement 결과를 단일 배열로 병합하여 `resultSetIndex >= 1` 접근 시 `undefined`를 반환한다. [근거: debug.md H1]

### 목표

- mysql2의 multi-statement 반환값을 올바르게 분리하여 각 statement 결과를 별도 result set으로 반환 [근거: Rule "multi-statement 결과 분리"]
- 기존 single-statement 동작을 깨뜨리지 않음 [근거: Rule "single-statement 기존 동작 유지"]

### 비목표

- `executeDefs`의 `resultSetStride` 지원 [근거: wbs 경계]
- `executeDefs`의 bounds check 방어 코드 [근거: wbs 경계]

### 설계

mysql2의 반환 형식:
- **single SELECT**: `queryResults = [RowDataPacket, RowDataPacket, ...]` — flat 배열
- **single INSERT**: `queryResults = ResultSetHeader` — 객체 (배열 아님)
- **multi-statement**: `queryResults = [ResultSetHeader | RowDataPacket[], ...]` — 중첩 배열

감지 로직:
1. `queryResults`가 배열이 아니면 → single INSERT/UPDATE/DELETE → `[[]]` 반환
2. 배열이고 첫 요소가 `Array.isArray` 또는 ResultSetHeader(`affectedRows` + `fieldCount`) → multi-statement → 각 요소를 별도 result set으로 매핑
3. 그 외 → single SELECT → `[queryResults]` 반환

```typescript
// multi-statement 감지
const first = queryResults[0] as Record<string, unknown> | undefined;
const isMultiStatement = first != null && (
  Array.isArray(first) ||
  ("affectedRows" in first && "fieldCount" in first)
);

if (isMultiStatement) {
  // 각 statement 결과를 별도 result set으로 분리
  return (queryResults as unknown[]).map((item) =>
    Array.isArray(item) ? (item as Record<string, unknown>[]) : [],
  );
}

// single SELECT
return [queryResults as Record<string, unknown>[]];
```

### 대안 검토

**요소 수 기반 감지 (비채택)**: 결과 행 수와 statement 수를 비교하는 방식. 구분이 불가능한 edge case가 많아 부적합.
