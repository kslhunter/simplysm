## 구현계획

### 배경

`deps/` 디렉토리에 4개 파일이 flat하게 존재하며, 개발 시점 의존성 관리(replace-deps, collect-deps)와 빌드 시점 산출물 생성(server-production-files)이라는 두 관심사가 혼재한다. 소비자도 완전히 분리되어 있어 서브디렉토리 분리가 자연스럽다. [근거: ARCH-001]

### 목표

- deps/ 디렉토리의 파일을 관심사별 서브디렉토리로 분리하여 역할을 즉시 파악 가능하게 한다 [근거: wbs Impact "디렉토리 구조에서 파일의 역할을 즉시 파악한다"]

### 비목표

- 파일 내용(로직) 변경 [근거: wbs 경계 "파일 내용 자체는 변경하지 않음"]
- 패키지 루트 index.ts 수정 (deps/ 파일은 re-export되지 않음) [근거: 코드 확인]

### 설계

순수 파일 이동 + import 경로 수정. 디렉토리 구조 변경:

```
deps/
├── replace-deps/
│   ├── replace-deps.ts          ← 이동 (from deps/)
│   ├── replace-deps-resolve.ts  ← 이동 (from deps/)
│   └── collect-deps.ts          ← 이동 (from deps/)
└── server-externals/
    └── server-production-files.ts  ← 이동 (from deps/)
```

### 대안 검토

없음. 서브디렉토리 분리는 WBS에서 이미 결정된 사항이며, 파일 이동만 수행하는 단순 작업이다.
