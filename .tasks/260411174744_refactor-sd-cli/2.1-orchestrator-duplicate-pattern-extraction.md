## 구현계획

### 배경

4개 Orchestrator에서 세 가지 중복 패턴이 발견되었다:
1. `ts.FormatDiagnosticsHost` 생성 + `sortAndDeduplicateDiagnostics` + `formatDiagnosticsWithColorAndContext` — BuildOrchestrator:464-494와 TypecheckOrchestrator:341-367
2. `getVersion()` → `_baseEnv` 설정 — BuildOrchestrator:163-164와 DevOrchestrator:62-63
3. `_initializeMode` 시그니처의 미사용 `options` 파라미터 — BaseOrchestrator:104-108

### 목표

- 진단 포맷팅 로직을 `diagnostic-utils.ts`의 공통 함수로 통합 [근거: Rule "진단 포맷팅은 단일 함수로 처리"]
- 환경변수 설정을 BaseOrchestrator로 이동하여 서브클래스 중복 제거 [근거: Rule "환경변수는 BaseOrchestrator에서 중앙 설정"]
- `_initializeMode` 시그니처를 실제 사용에 맞게 정리 [근거: Rule "_initializeMode는 config과 targets만 받음"]

### 비목표

- 작업 생성 → 동시성 제어 패턴 추상화 [근거: wbs 경계 "오버엔지니어링 리스크로 제외"]
- 에러 로깅 패턴 통합 [근거: wbs 경계 "범위 밖"]
- BuildOrchestrator의 환경변수 설정 변경 [근거: D1 "독립 클래스이므로 자체 유지"]

### 설계

#### 1. `formatDiagnosticsOutput` 공통 함수 (diagnostic-utils.ts)

```typescript
export function formatDiagnosticsOutput(diagnostics: ts.Diagnostic[], cwd: string): string {
  if (diagnostics.length === 0) return "";
  const formatHost: ts.FormatDiagnosticsHost = {
    getCanonicalFileName: (f) => f,
    getCurrentDirectory: () => cwd,
    getNewLine: () => ts.sys.newLine,
  };
  const uniqueDiagnostics = ts.sortAndDeduplicateDiagnostics(diagnostics);
  return ts.formatDiagnosticsWithColorAndContext(uniqueDiagnostics, formatHost);
}
```

[근거: Rule "진단 포맷팅은 단일 함수로 처리" — BuildOrchestrator와 TypecheckOrchestrator의 동일 패턴을 캡슐화]

#### 2. BaseOrchestrator에 `_baseEnv` 추가

```typescript
// 필드 추가
protected _baseEnv!: { VER: string; DEV: string };

// initialize()에서 설정 (loadSdConfig 이후, _initializeMode 이전)
import { getVersion } from "../utils/build-env";
const version = await getVersion(this._cwd);
this._baseEnv = { VER: version, DEV: params.dev ? "true" : "false" };
```

[근거: Rule "환경변수는 BaseOrchestrator에서 중앙 설정" — DevOrchestrator의 중복 코드 제거]

#### 3. `_initializeMode` 시그니처 정리

```typescript
// Before (BaseOrchestrator)
protected abstract _initializeMode(
  config: SdConfig, targets: string[], options: string[],

// After
protected abstract _initializeMode(
  config: SdConfig, targets: string[],

// 호출부 (BaseOrchestrator.initialize)
// Before: await this._initializeMode(sdConfig, params.targets, params.options);
// After:  await this._initializeMode(sdConfig, params.targets);
```

[근거: Rule "_initializeMode는 config과 targets만 받음" — options는 initialize()의 loadSdConfig()에서만 사용]

### 대안 검토

**진단 포맷팅을 클래스 메서드로 추출 vs 유틸 함수:**
클래스 메서드는 BuildOrchestrator와 TypecheckOrchestrator가 서로 다른 계층(독립 클래스)이므로 공통 베이스 클래스에 넣을 수 없다. 유틸 함수가 유일한 합리적 선택이며, 기존 `diagnostic-utils.ts`에 관련 함수가 이미 있어 자연스러운 위치이다.
