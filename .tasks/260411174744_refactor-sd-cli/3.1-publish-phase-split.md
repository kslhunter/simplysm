## 구현계획

### 배경

현재 `runPublish()` 함수(index.ts:76-453, 377줄)에 설정 로드, 사전 검증, 버전 관리, 빌드, git 워크플로, 배포, 후처리가 모두 밀결합되어 있다. 개별 페이즈를 독립적으로 테스트하거나 수정할 수 없는 구조이다. [근거: DESIGN-002]

### 목표
- git 워크플로(사전 검증 + 버전 커밋)를 `git-phase.ts`로 추출 [근거: Rule "git-phase는 사전 검증과 버전 커밋을 수행한다", D1]
- 배포 오케스트레이션을 `deployment-phase.ts`로 추출 [근거: Rule "deployment-phase는 의존성 레벨 순서대로 배포한다"]
- 후처리 스크립트 실행을 `post-publish-phase.ts`로 추출 [근거: Rule "post-publish-phase는 postPublish 스크립트를 순차 실행한다"]
- `runPublish()`를 페이즈 순차 호출하는 경량 오케스트레이터로 축소 [근거: Rule "runPublish()는 경량 오케스트레이터"]

### 대안 검토

**단일 gitPhase() 함수로 사전 검증과 버전 커밋을 통합** — 사전 검증은 빌드 전, 버전 커밋은 빌드 후에 호출되므로, 단일 함수로 만들면 호출자가 "빌드 전후" 시점을 파라미터로 전달해야 하는 어색한 구조가 됨. 두 함수로 분리하는 것이 명확.

**phase를 클래스로 추상화** — 3개 페이즈에 공통 인터페이스가 없고(파라미터가 모두 다름), 오버엔지니어링. 단순 함수로 충분.
