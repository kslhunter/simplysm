## 구현계획

### 배경

sd-cli의 4개 Worker Thread 파일(library-build, ngtsc-build, server-build, client)이 동일한 초기화 보일러플레이트를 반복하고 있다. 기존 `runtime/worker-utils.ts`에 개별 유틸리티(`setupWorkerConsola`, `registerCleanupHandlers`, `createOnceGuard`)가 이미 존재하며, 이를 조합하는 상위 함수를 추출한다.

### 목표

- 4개 워커의 ~150줄 초기화 보일러플레이트를 단일 함수 호출로 대체 [근거: Rule "공통 초기화 시퀀스는 단일 함수 호출로 대체된다"]
- 새 워커 추가 시 초기화 패턴 복사 불필요 [근거: STRUCT-001]

### 비목표

- 각 워커의 고유 cleanup 로직 변경 [근거: WBS 경계]
- 빌드/감시 로직 변경 [근거: WBS 경계]
- `runtime/worker-utils.ts`의 기존 개별 함수 삭제 [근거: 다른 곳에서 개별 사용 가능성]

### 설계

#### `workers/shared-worker-lifecycle.ts` 신규 파일

```typescript
import { consola } from "consola";
import { registerCleanupHandlers, setupWorkerConsola, createOnceGuard } from "../runtime/worker-utils.js";

export function setupWorkerLifecycle(
  workerName: string,
  cleanupFn: () => void | Promise<void>,
): { logger: typeof consola; guardStartWatch: () => void } {
  setupWorkerConsola();
  const logger = consola.withTag(`sd:cli:${workerName}:worker`);
  registerCleanupHandlers(cleanupFn, logger);
  return { logger, guardStartWatch: createOnceGuard("startWatch") };
}
```

[근거: Rule "공통 초기화 시퀀스는 단일 함수 호출로 대체된다", refactor.md 제안 코드]

#### 워커 수정 패턴

각 워커에서 개별 초기화 코드를 제거하고 `setupWorkerLifecycle` 호출로 대체:

- **Before (library-build 예시):**
  ```typescript
  setupWorkerConsola();
  const logger = consola.withTag("sd:cli:library-build:worker");
  // ... cleanup 함수 정의 ...
  registerCleanupHandlers(cleanup, logger);
  // ... (다른 코드) ...
  const guardStartWatch = createOnceGuard("startWatch");
  ```

- **After:**
  ```typescript
  const { logger, guardStartWatch } = setupWorkerLifecycle("library-build", cleanup);
  ```

- `setupWorkerConsola`, `registerCleanupHandlers`, `createOnceGuard`의 import를 `setupWorkerLifecycle` import로 교체
- cleanup 함수 정의는 워커에 유지 (setupWorkerLifecycle 호출 전에 정의)
- client.worker.ts는 `const { logger } = setupWorkerLifecycle("client", ...)` 형태로 guardStartWatch 생략 [근거: D1]

### 대안 검토

| 대안 | 선택하지 않은 이유 |
|------|------------------|
| 클래스 기반 BaseWorker 추출 | 현재 워커들이 함수형 패턴이므로 클래스 도입은 과도한 변경 |
| worker-utils.ts에 함수 추가 | WBS에서 `workers/shared-worker-lifecycle.ts` 위치를 명시 — 워커 전용 조합 함수는 workers/ 디렉토리가 적합 |
| createOnceGuard를 optional 파라미터로 제어 | D1 결정에 따라 항상 반환 방식 채택 — 시그니처 단순화 |
