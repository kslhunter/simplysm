## 구현계획

### 배경

v14의 sd-sheet 컴포넌트는 signal-based, standalone 아키텍처를 사용한다. 컬럼 정의(`SdSheetColumn` 디렉티브)의 input 값들은 `useSheetLayoutEngine`에서 `SdSheetColumnDef`로 매핑되고, 이를 기반으로 `SdSheetHeaderDef[][]` 2차원 테이블이 생성되어 헤더가 렌더링된다. 템플릿 참조(`TemplateRef`)는 데이터 인터페이스에 포함하지 않고 `_columnControlMap`을 통해 접근하는 패턴을 사용한다(`sd-sheet.ts:458-473`). [근거: v14 코드베이스 분석]

### 목표

- headerStyle input을 통한 헤더 셀 커스텀 스타일링 복원 [근거: Rule "headerStyle은 CSS 인라인 스타일을 적용"]
- tooltip input을 통한 네이티브 툴팁 + 시각적 표시 복원 [근거: Rule "tooltip은 title 툴팁과 dotted underline 제공"]
- headerTplRef contentChild를 통한 커스텀 헤더 템플릿 렌더링 복원 [근거: Rule "headerTplRef는 커스텀 템플릿으로 대체"]

### 비목표

- cellTplRef의 directive→string ref 변경 [근거: wbs 경계 "의도적 변경"]
- 제네릭 `<T>` 제거 [근거: wbs 경계 "cellTplRef 변경의 필연적 결과"]
- ordering input의 v14 신규 기능 변경 [근거: wbs 경계 "v14 신규 기능으로 유지"]

#### 스타일링 변경

**useSheetCellStyling** (`useSheetCellStyling.ts`): [근거: D3 — getHeaderCellStyle에 병합]

`getHeaderCellStyle` 함수에서 `colDef.headerStyle`을 기존 스타일에 병합:

```typescript
function getHeaderCellStyle(cell: SdSheetHeaderDef): string | null {
  if (cell.colDef == null) return null;
  const parts: string[] = [];
  const baseStyle = headerColumnStyles().get(cell.colDef.key);
  if (baseStyle != null) parts.push(baseStyle);
  if (cell.colDef.headerStyle != null) parts.push(cell.colDef.headerStyle);
  return parts.length > 0 ? parts.join("; ") : null;
}
```

#### 템플릿 변경

**sd-sheet.ts**: [근거: v12 sd-sheet.control.ts:166-186 헤더 렌더링 로직 복원]

헤더 셀(`<th>`) 바인딩 추가:

```html
<th
  ...기존 바인딩...
  [attr.title]="cell.colDef?.tooltip ?? cell.text"
  [class.help]="cell.colDef?.tooltip"
>
  @if (cell.colDef && getColumnHeaderTpl(cell.colDef.key); as headerTpl) {
    <ng-template [ngTemplateOutlet]="headerTpl" />
  } @else {
    <span>{{ cell.text }}</span>
  }
  ...정렬 아이콘 (기존 유지)...
  ...리사이저 (기존 유지)...
</th>
```

헬퍼 메서드 추가: [근거: D2 — _columnControlMap 패턴]

```typescript
getColumnHeaderTpl(key: string) {
  const col = this._columnControlMap().get(key);
  return col?.headerTplRef() ?? null;
}
```

### 대안 검토

**SdSheetHeaderDef에 style/tooltip/headerTplRef 필드 추가 (WBS 원안)**

- 장점: 헤더 셀 데이터가 자기 완결적, 모든 헤더 행(비-leaf 포함)에 적용 가능
- 단점: SdSheetColumnDef와 데이터 중복, TemplateRef를 데이터 인터페이스에 포함하면 v14 패턴 불일치(`cellTplRef`/`summaryTplRef`는 데이터 인터페이스 미포함), layout engine 복잡도 증가
- 미채택 사유: v14의 기존 패턴과 불일치, 계층형 헤더 카테고리 셀에 개별 컬럼의 스타일/템플릿 적용은 의미적으로 부적절
