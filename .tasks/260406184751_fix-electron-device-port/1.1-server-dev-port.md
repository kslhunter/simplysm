## 구현계획

### 배경

`sd-cli device` 명령은 `.dev-port` 파일에서 포트를 읽어 Electron/Capacitor 앱을 실행한다. 현재 `server: string`일 때 클라이언트 패키지의 `.dev-port`(Vite HMR 포트)를 읽지만, Fastify 서버 포트를 읽어야 한다. [근거: debug.md ACH 분석]

### 목표

- 서버 런타임이 listen 완료 시 `.dev-port` 기록 [근거: Rule "서버 런타임이 listen 완료 시 .dev-port를 기록"]
- `device.ts`가 `server: string`일 때 서버 패키지의 `.dev-port` 참조 [근거: Rule "device.ts가 server: string일 때 서버 패키지의 .dev-port를 읽음"]

### 비목표

- `client.worker.ts`의 `.dev-port` 기록 로직 변경 [근거: wbs 경계]
- Capacitor 흐름 변경 [근거: wbs 경계]

### 설계

**수정 1: `packages/sd-cli/src/workers/server-runtime.worker.ts`**
- `import fs from "node:fs"`, `import path from "path"` 추가 [근거: .dev-port 파일 I/O에 필요]
- 모듈 레벨 `let mainJsDir: string | undefined` 추가 [근거: D2 - cleanup에서 경로 접근 필요]
- `start()` 함수: `server.listen()` 후, `sender.send("serverReady")` 전에 `.dev-port` 기록 [근거: D1]
- `cleanup()` 함수: 서버 종료 전에 `.dev-port` 삭제 [근거: D3]

**수정 2: `packages/sd-cli/src/commands/device.ts`**
- `server: string`일 때 `pathx.posixResolve(cwd, "packages", clientConfig.server)` 경로의 `dist/.dev-port` 참조 [근거: debug.md - 서버 패키지 포트를 사용해야 함]

### 대안 검토

- 오케스트레이터에서 `serverReady` 이벤트 수신 시 `.dev-port` 기록: 서버 워커를 수정하지 않지만, 오케스트레이터에 파일 I/O가 추가되고, `client.worker.ts`의 기존 패턴(워커 내부에서 직접 기록)과 불일치. 미채택.

### Slice 분할

#### [x] Slice 1: server-runtime.worker.ts에 .dev-port 기록/삭제

- **구현 내용:** fs/path import 추가, mainJsDir 변수 추가, start()에서 .dev-port 기록, cleanup()에서 .dev-port 삭제
- **Scenarios:** 서버 listen → .dev-port 기록, 포트 충돌 시 실제 포트 기록, cleanup → .dev-port 삭제

#### [x] Slice 2: device.ts에서 서버 패키지 포트 참조

- **의존:** Slice 1
- **구현 내용:** server: string일 때 서버 패키지 경로의 .dev-port 참조
- **Scenarios:** server: string → 서버 .dev-port 참조, server: number → 기존 동작 유지
