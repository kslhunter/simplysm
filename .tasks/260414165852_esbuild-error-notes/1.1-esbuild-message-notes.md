## 구현계획

### 배경

esbuild 빌드 결과(`BuildResult`)의 `errors`/`warnings`는 `esbuild.Message[]` 타입이며, 각 `Message`에는 `text`(주 메시지)와 `notes: Note[]`(보조 컨텍스트)가 있다. 현재 3개 파일 8곳에서 `.map((e) => e.text)`로 변환하여 `notes`가 유실된다.

### 목표

- esbuild Message → string 변환 시 notes 텍스트를 포함한다
- 3개 파일 8개 지점을 일관된 유틸 함수로 통일한다

### 비목표

- `notes[].location` 포함 — 과도한 정보로 가독성 저하
- esbuild 외부 에러 포맷팅 변경

### 설계

`output-utils.ts`에 `formatEsbuildMessage` 함수 추가:

```typescript
export function formatEsbuildMessage(msg: { text: string; notes: ReadonlyArray<{ text: string }> }): string {
  if (msg.notes.length === 0) return msg.text;
  return [msg.text, ...msg.notes.map((n) => `  ${n.text}`)].join("\n");
}
```

호출 패턴: `.map((e) => e.text)` → `.map(formatEsbuildMessage)`

`client.worker.ts:175` catch 블록의 타입 캐스트도 notes 포함으로 변경.

### 대안 검토

| 대안 | 불채택 사유 |
|------|-----------|
| `esbuild.formatMessages()` 사용 | async API, 기존 동기 흐름에 맞지 않음 |
| 각 사이트에 인라인 | 8곳 반복, 포맷 불일치 위험 |
| `esbuild/` 디렉토리에 신규 파일 | 단일 함수를 위한 파일 생성 과잉 |
