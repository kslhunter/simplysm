## 구현계획

### 배경

`packages/sd-cli/src/electron/electron.ts`의 `Electron` 클래스에 리뷰에서 발견된 4건의 이슈가 있다. 모든 수정은 `electron.ts` 단일 파일에서 이루어지며, 외부 인터페이스(설정 타입, public API)는 변경하지 않는다.

### 목표

- `_copyBuildOutput`의 glob 경로 해석 오류 수정 (빌드 산출물 복사 실패 방지)
- `run()` 종료 시 시그널 핸들러 정리 및 double dispose 방지
- `exclude` 패키지를 esbuild external에 추가
- `description` fallback 보강 및 파일명 sanitize

### 비목표

- `fsx.glob` 래퍼 자체의 `cwd` 처리 방식 변경 (영향 범위가 넓음)
- `SdElectronConfig` 타입에 새 필드 추가
- 테스트 파일 추가 (외부 프로세스 의존이 높아 통합 테스트 수준이 필요)

### 설계

#### LOGIC-001: glob 경로 수정

`fsx.glob("*.exe", { cwd: distPath })` → `fsx.glob(path.resolve(distPath, "*.exe"))`. 코드베이스의 기존 패턴(`copy` 함수의 `path.resolve(sourcePath, "*")`)과 일관.

#### LOGIC-002: 시그널 핸들러 정리

`cleanup` 함수를 도입하여 `resolveTermination`과 `signalHandler` 양쪽에서 공유. disposed 플래그로 이중 실행 방지. `process.removeListener`로 핸들러 제거.

#### DESIGN-001: exclude external 추가

`_bundleMainProcess`와 `run()` 양쪽의 esbuild `external` 배열에 `...this._exclude` 추가.

#### DESIGN-002: description 안전 처리

- `_getProductName()` 헬퍼: `this._npmConfig.description ?? this._npmConfig.name`
- `_sanitizeFileName()` 헬퍼: `<>:"/\|?*` 문자 제거

### 대안 검토

| 접근 방식 | 선택 여부 | 이유 |
|-----------|-----------|------|
| `fsx.glob` 래퍼에 `cwd` 처리 로직 수정 | 미채택 | 모든 호출자에 영향. 변경 범위가 이 Feature를 초과 |
| glob `absolute: true` 옵션 사용 | 미채택 | `fsx.glob` 래퍼가 `path.resolve`를 이미 적용하므로 이중 절대 경로화. 절대 패턴이 더 단순 |
| `SdElectronConfig`에 `productName` 필드 추가 | 미채택 (D2) | 설정 항목 증가 + 기존 사용자 migration 필요. fallback으로 충분 |
