# 개인 지식 위키

누적 지식 위키는 `~/.claude/wiki` 에 있음. 목차(`index.md`)는 SessionStart 훅으로 세션 시작 시 컨텍스트에 자동 주입됨. 본문은 각 토픽 페이지(`<topic>.md`)에 두고, 목차엔 요약만 둠.

## 페이지 활용 시

- 작업이 목차 항목과 관련되면 해당 페이지(`~/.claude/wiki/<topic>.md`)를 Read 로 열어 활용.
- 페이지끼리는 마크다운 링크로 연결됨 — 필요하면 타고 들어가 확인.
- 페이지를 열었을 때 갱신 날짜가 오래됐고 현재 작업과 맞지 않으면, 사용자 요청을 기다리지 말고 그 자리에서 재검증·갱신.

## 무엇을 담는가 (대상)

작업 중 알게 된 **오래 재사용될 지식** — 빌드·실행 명령, 디버깅 원인·해결, 라이브러리·API 동작, 설계 결정, 반복 패턴 등.

- **판정 질문**: "다음에 비슷한 상황을 만났을 때 이 페이지를 열어 시간을 아낄, 비자명하고 반복되는 내용인가?" 아니오거나 애매하면 넣지 않음.

## 무엇을 담지 않는가 (비대상)

위키는 재사용 지식만 담음 — "방금 한 작업" 을 기록하는 곳이 아님. 아래는 새 페이지로 만들지도, 기존 페이지에 덧붙이지도 않음.

- **일회성 작업 기록**: 이번 한 건의 작업 절차·변경 내역·영향 요약(작업 서사·완료 보고·리네임/마이그레이션 기록 등). 다시 펼칠 일이 없음.
- **단순 문서 요약**: 공식 문서·`claude-code-guide` 등으로 그 자리에서 쉽게 재확인되는 일반 사실. 단, 문서로는 찾기 어려운 함정·우리 환경 특이 동작·반복 적용 패턴은 예외로 대상.
- **과거 기록물**: commit·PR·이슈·로그·CHANGELOG 성 내용.

작업 과정의 단발 정보는 그 작업 산출물(코드 주석·PR 설명·spec)에 남기고 위키엔 올리지 않음. 위키는 얇게 유지하는 편이 검색·주입 비용 면에서 이득.

## 반영 방법

- 겹치는 기존 페이지가 **있으면** 그 페이지를 갱신·통합(중복 페이지 생성 금지), **없으면** 새 토픽 페이지(`<topic>.md`) 생성.
- **`index.md` 항목 = 라우팅 전용**: `[제목](<topic>.md) — 한 줄 요약` 형식. 요약엔 *그 페이지를 언제 여는지*(어떤 상황·문제에서 펼치는지)만 적음. **본문 사실의 복제 금지** — 수치·코드·구체 패턴·근거·날짜·세부 결론은 index 에 넣지 않고 페이지 본문에만 둠(목차만 읽고 내용을 다 알게 만들면 안 됨). 한 항목은 한 줄, 대략 100자 이내. index.md 전체는 SessionStart 로 매번 주입되므로 비대해지면 주입이 잘림 — 얇게 유지가 비용·정확성 양면에서 필수.
- **모순 처리**: 새 지식이 기존과 모순되면 무판단 덧붙이기 금지 — 어느 쪽이 노후인지 판단해 덮어쓰거나, 둘 다 맥락상 유효하면 적용 조건을 명시해 공존.
- **페이지 본문에만 둘 것 (index 금지)**: 핵심 주장의 근거·출처, 검증 방식(실행확인·코드확인·외부출처(미검증)·추정), 불확실 항목, 시간 민감 지식의 갱신 날짜. 이것들은 페이지 본문에만 두고 index 요약엔 넣지 않음. 외부 출처에서 옮긴 미검증 주장은 사실로 단정하지 말고 미검증임을 명시.

## 유지·점검 (사용자 요청 시)

- 비대상 기준에 어긋나는 페이지(작업 기록성·단순 문서 요약), 노후 정보, 페이지 간 모순, 고아 페이지(인바운드 링크 없음), 끊긴·누락 링크, 보강 필요 지점을 점검.
- 목차는 얇게 유지. 항목이 많아지면 카테고리별 sub-index 로 분리하고 최상위 목차엔 sub-index 만 둠.
