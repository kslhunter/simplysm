# 원격 공용 위키

누적 지식 위키는 팀이 공유하는 원격 서버에 있음(로컬 파일 아님). 페이지는 `topic` 을 유니크 키로 갖고 제목·요약·본문(마크다운)·버전으로 구성됨. 목차는 SessionStart 훅이 세션 시작 시 컨텍스트에 자동 주입함. 읽기·쓰기·검색·목차 조회는 위키 CLI(`wiki.py`) 의 명령으로 함:

| 명령              | 동작                                                        |
| ----------------- | ----------------------------------------------------------- |
| `read <topic>`    | 페이지 1건 조회 — 제목·요약·본문·버전. 없으면 빈 결과        |
| `write <topic>`   | 페이지 생성·갱신 — 제목·요약·본문, 갱신 시 기준 버전(낙관락) |
| `search <키워드>` | 키워드로 페이지 검색                                        |
| `toc`             | 목차 조회                                                   |

인증·토큰 갱신은 CLI 가 자동 처리(만료 시 브라우저 로그인). 결과는 JSON.

## 페이지 활용 시

- 작업이 주입된 목차 항목과 관련되면 `read` 로 본문을 열어 활용.
- 본문이 다른 `topic` 을 가리키면 그 topic 도 `read` 로 확인.
- 페이지가 노후했고 현재 작업과 맞지 않으면, 사용자 요청을 기다리지 말고 그 자리에서 재검증·갱신.

## 무엇을 담는가 (대상)

작업 중 알게 된 **오래 재사용될 지식** — 빌드·실행 명령, 디버깅 원인·해결, 라이브러리·API 동작, 설계 결정, 반복 패턴 등. 팀이 공유하므로 작성자 한 사람뿐 아니라 다른 작업자도 다시 펼칠 일반 지식만 담음.

- **판정 질문**: "다음에 비슷한 상황을 만났을 때 이 페이지를 열어 시간을 아낄, 비자명하고 반복되는 내용인가?" 아니오거나 애매하면 넣지 않음.

## 무엇을 담지 않는가 (비대상)

위키는 재사용 지식만 담음 — "방금 한 작업" 을 기록하는 곳이 아님. 아래는 새 페이지로 만들지도, 기존 페이지에 덧붙이지도 않음.

- **일회성 작업 기록·의사결정**: 이번 한 건의 작업 절차·변경 내역·영향 요약(작업 서사·완료 보고·리네임/마이그레이션 기록 등), 그리고 도구·방안의 도입·채택 여부를 1회 검토한 평가의 결론. 다시 펼칠 일이 없음.
- **단순 문서 요약**: 공식 문서·`claude-code-guide` 등으로 그 자리에서 쉽게 재확인되는 일반 사실. 단, 문서로는 찾기 어려운 함정·우리 환경 특이 동작·반복 적용 패턴은 예외로 대상.
- **개인·로컬 특이 정보**: 특정 머신·개인 경로·임시 환경에서만 통하는 내용. 공용이라 팀 누구에게나 통하는 지식만 담음.
- **과거 기록물**: commit·PR·이슈·로그·CHANGELOG 성 내용.

작업 과정의 단발 정보는 그 작업 산출물(코드 주석·PR 설명·spec)에 남기고 위키엔 올리지 않음. **재사용 지식 페이지라도 특정 건의 사례 수치·진행 경위·사고 서사는 본문에 섞지 않음** — 일반화된 패턴·기준·원인·해결만 남기고 그 건의 결과·경위는 뺌. 위키는 얇게 유지하는 편이 검색·주입 비용 면에서 이득.

## 반영 방법

- 먼저 `search`·`toc` 로 겹치는 기존 페이지를 확인. **있으면** `read` 로 받아 갱신·통합(중복 페이지 생성 금지), **없으면** 새 `topic` 으로 `write`.
- **갱신 충돌 방지(낙관락)**: 공용이라 다른 작업자·세션이 동시에 쓸 수 있음. 갱신은 `read` 로 받은 버전을 기준 버전으로 넘겨 씀. 읽은 뒤 누가 먼저 바꿨으면 CLI 가 최신본을 다시 받아 1회 재시도하고, 재시도도 실패하면 보고.
- **요약 = 라우팅 전용**: *그 페이지를 언제 여는지*(어떤 상황·문제에서 펼치는지)만 적음. **본문 사실의 복제 금지** — 수치·코드·구체 패턴·근거·날짜·세부 결론은 요약에 넣지 않고 본문에만 둠(목차만 읽고 내용을 다 알게 만들면 안 됨). 한 요약은 한 줄, 대략 100자 이내. 목차 전체는 SessionStart 로 매번 주입되므로 비대해지면 주입이 잘림 — 얇게 유지가 비용·정확성 양면에서 필수.
- **모순 처리**: 새 지식이 기존과 모순되면 무판단 덧붙이기 금지 — 어느 쪽이 노후인지 판단해 덮어쓰거나, 둘 다 맥락상 유효하면 적용 조건을 명시해 공존.
- **본문에만 둘 것 (요약 금지)**: 핵심 주장의 근거·출처, 검증 방식(실행확인·코드확인·외부출처(미검증)·추정), 불확실 항목, 시간 민감 지식의 갱신 날짜. 이것들은 본문에만 두고 요약엔 넣지 않음. 외부 출처에서 옮긴 미검증 주장은 사실로 단정하지 말고 미검증임을 명시.

## 유지·점검 (사용자 요청 시)

- 비대상 기준에 어긋나는 페이지(작업 기록성·단순 문서 요약), 노후 정보, 페이지 간 모순, 끊긴 `topic` 참조, 보강 필요 지점을 점검.
- 목차(`toc`)는 전체 페이지 요약의 합이라 페이지가 늘수록 주입량이 커짐 — 요약을 짧게 유지하고 불필요한 페이지를 만들지 않음.
