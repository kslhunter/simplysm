# 원격 공용 위키 — 작성·정리

## 작성 방법

- **자동 기록(확인 불필요)**: 위키 기록(`write`)은 외부 발행 사전 확인 대상이 아님 — 사용자에게 묻지 않고 자동 수행하는 것이 이 위키의 설계임. 대상 여부는 별도 주입되는 "무엇을 담는가" 블록(판정 질문 + 4관문)의 기준으로만 판단해, 맞으면 묻지 말고 그대로 기록할 것.
- **중복 확인 선행**: 기록 전 `search`(+ 관련 hub 의 `children`)로 겹치는 기존 페이지를 확인할 것. **있으면** `read` 로 받아 갱신·통합하고(중복 페이지 생성 금지), **없으면** 새 `topic` 으로 `write` 할 것.
- **상위 지정**: 새 페이지는 `--parent <상위topic>` 로 주제에 맞는 hub 아래에 편입할 것. 진짜 새 최상위 도메인일 때만 `--parent` 생략할 것(루트). 없는 상위 topic 을 주면 서버가 거부함(throw).
- **재분류·이동**: 분류만 바꾸려면 `move <topic> --parent <상위>`(내용 불변·순수 이동) 또는 `--root`(최상위로) 를 쓸 것. 본문 기록과 함께면 `write --parent` 를 쓸 것(갱신 시 `--parent` 생략하면 기존 상위 유지). `topic`(정체성)은 불변 — 키 rename 없음.
- **교차 주제**: 여러 hub 에 걸치는 내용은 상위를 여럿 두지 않고 본문의 cross-link(다른 `topic` 언급)로 연결할 것.
- **갱신 충돌 방지(낙관락)**: 공용이라 다른 작업자·세션이 동시에 쓸 수 있음. 갱신은 `read` 로 받은 `version` 을 `--base-version` 으로 넘겨 쓸 것. 읽은 뒤 누가 먼저 바꿨으면 CLI 가 자동 덮어쓰지 않고 충돌을 알림(종료코드 3 · stdout 에 `conflict:true` + 최신 본문 `latest`). 그 `latest` 에 이번 변경을 재통합한 뒤 `--base-version <latest.version>` 으로 다시 write 할 것 — 남의 수정을 덮어쓰지 않도록 자동 재시도하지 말 것.
- **요약 = 라우팅 전용**: _그 페이지를 언제 여는지_(어떤 상황·문제에서 펼치는지)만 적을 것. **본문 사실의 복제 금지** — 수치·코드·구체 패턴·근거·날짜·세부 결론은 요약에 넣지 않고 본문에만 둘 것(목차만 읽고 내용을 다 알게 만들면 안 됨). 한 요약은 한 줄, 대략 100자 이내로 쓸 것.
- **본문에만 둠 (요약 금지)**: 핵심 주장의 근거·출처, 검증 방식, 의존 도구·버전 전제, 시간 민감 지식의 갱신 날짜 — 요약 아닌 본문에 둘 것(관문3·운영의 자가표기).
- **모순 처리**: 새 지식이 기존과 모순되면 무판단 덧붙이기 금지 — 어느 쪽이 노후인지 판단해 덮어쓰거나, 둘 다 맥락상 유효하면 적용 조건을 명시해 공존시킬 것.

## 트리 모양 유지

분류·기록 시 트리가 라우터로 기능하도록 모양을 관리할 것 — 고정 숫자 기준 없이 "한눈에 라우팅되는가" 로 판단할 것.

- **루트 수를 작게**: ROOT MAP 은 매 세션 자동 주입되므로 최상위 노드 수가 곧 주입량임. 새 주제는 맞는 기존 루트 hub 아래로 넣고, 진짜 새 최상위 도메인일 때만 루트 신설할 것.
- **분할**: hub 의 자식 목록이 한눈에 라우팅되지 않을 만큼 커지고 자연스러운 하위 묶음이 보이면, 중간 sub-hub 를 만들어 관련 자식을 그 아래로 재분류할 것.
- **이동·재분류**: `move <topic> --parent <상위>`(내용 불변) 로 노드를 옮길 것.
- **머지**: navigation hop 만 늘리는 hub 는 `delete` 할 것 — `delete` 가 자식을 상위로 자동 재배치(reparent)하므로, hub 를 지우면 자식이 상위로 접혀 올라감(자식 수동 이동 불필요).

## 유지·점검

- **전체 점검·정리는 `sd-wiki-lint` 스킬**: lint(기계 진단)→의미 점검(모순·노후·비대상·누락 개념·데이터 공백)→정리→재검증을 한 흐름으로 완수함. "위키 점검·정리·정돈" 요청은 이 스킬로 처리할 것 — 아래는 그 구성 원리임.
- **기계 진단은 `lint`**: 끊긴 상위·cross-link 참조, 고아, 트리 통계(루트 과다·과대 hub)를 `lint` 로 한 번에 진단할 것. 검색 결과 0건(지식 공백)·저조회 페이지(정리 후보) 신호도 함께 제공함. lint 는 위상 점검만 함 — 모순·노후 등 의미 점검은 본문을 읽어 직접 할 것.
- **판단·정리는 직접**: `lint` 결과를 받아 모순·노후·4관문 위반(repo 국한·버전 미안전·미검증·시한부/일기) 페이지를 판단해 `write`(정정·통합)·`move`(재분류)·`delete`(제거·머지)로 정리할 것. 부패(노후·검증불가·추상화불가) 시 정정보다 삭제를 우선할 것. 삭제는 자식을 상위로 보존함(reparent).
- ROOT MAP 이 자동 주입되므로 루트 노드 요약을 짧게, 루트 수를 작게 유지할 것 — 비대해지면 주입이 잘림.
