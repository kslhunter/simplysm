# sd-wiki-lint

위키 점검·정리를 요청 한 번에 끝까지 완수한다. 메인 루프가 직접 오케스트레이션.

위키 CLI 실행 형식은 세션 시작 reference 로 주입된 `references/wiki.md` 의 값을 따른다(Claude Code 기본값: `bun "${CLAUDE_PLUGIN_ROOT}/cli/wiki.ts" <명령>`). 위키 구조·명령·작성 규칙(담기 전 4관문)·트리 모양은 해당 reference 가 권위 — 이 스킬은 그 "유지·점검"을 전 과정으로 실행하는 절차다.

핵심: `lint` CLI 는 **기계로 가능한 위상 점검만** 한다(끊긴 상위·cross-link·고아·트리 통계). 모순·노후·누락 개념·데이터 공백 같은 **의미 점검은 LLM(이 스킬)이** 본문을 읽어 판정한다 — 둘을 합쳐야 전체 점검이다.

## 절차

### 1. 기계 진단 (`lint`)

`lint` 실행. 결과 해석:

- `orphans`·`brokenLinks` — 끊긴 참조·고아. 즉시 수정 대상.
- `treeStats`(`rootCount`·`hubChildCounts`) — 트리 모양 입력(루트 과다·과대 hub 판단).
- `unlinkedTopics` — 독립 지식이 많은 위키에선 정상. 그 자체로 문제 아님(과잉 cross-link 강요 금지).
- `lowViewPages` — 전부 `0` 이면 추적 미성숙 = 노이즈로 무시. 편차가 있을 때만 저조회를 정리 후보 신호로.
- `knowledgeGaps` — 지식 공백 후보.

### 2. 전수 본문 수집

`toc` 로 전체 topic 확보 → 모든 페이지를 `read`(의미 점검엔 본문이 필수). 대량이면 셸 반복으로 한 번에 묶어 읽고, 출력이 크면 파일로 받아 읽는다. 표본·요약만 보고 판단하지 않는다.

### 3. 의미 점검 (전수)

각 페이지를 아래 렌즈로 빠짐없이 판정. 근거는 본문·**현 코드베이스**·**현 버전** 대조(추정으로 단정 금지):

- **모순** — 같은 주제를 상반 서술하는 페이지. 어느 쪽이 노후인지 판단.
- **노후** — 현 코드/버전/도구/경로와 어긋난 주장. 코드베이스를 실제로 열어 대조해 확인.
- **검증·출처(관문3)** — 근거·검증·**재방문 가능한 출처(URL·문서명·식별자·실행명령·사용자 전언)** 없이 단정한 주장. `references/wiki.md` 관문3 기준. 검증·출처 확인되면 단정 유지(출처 보강), 검증 불가·추정·전언·자기 repo 코드 출처는 제거(없는 게 낫다).
- **4관문 위반** — repo 국한(라이브러리 *만드는* 지식·고객 1곳 정책 포함)·버전 미안전(구버전서 틀림·시점 의존)·시한부(X→Y 마이그레이션)·일기(작업 경위·사례 수치). `references/wiki.md` 4관문 기준. 라이브러리 *쓰는* 지식은 4조건(버전 명시·상태규칙·근거검증·repo 독립) 충족 시에만 허용.
- **누락 개념** — 본문이 반복 언급하나 별도 페이지가 없는 중요 개념(페이지화 후보).
- **데이터 공백** — `knowledgeGaps`·검색 0건 영역(보강·조사 후보).
- **품질** — 요약이 라우팅 전용인지(본문 사실 복제 금지), 본문에 특정 건의 수치·서사·경위가 섞였는지.

### 4. 트리 모양 점검

`references/wiki.md` "트리 모양 유지" 기준으로:

- **루트 과다** — 관련 묶음을 sub-hub 로 접을 후보 식별(새 hub `write` + 자식 `move`).
- **과대 hub** — 자연스러운 하위 묶음이 보이면 중간 sub-hub 로 분할.
- **잉여 hub** — navigation hop 만 늘리는 hub 는 `delete`(자식이 상위로 reparent 됨).

### 5. 정리 적용 — 자동/보고 분류

판정을 행동으로 옮긴다. **근거가 한 선택만 가리키면 묻지 말고 즉시, 애매한 것만 모아 1회 보고**(단계마다 묻지 않는다):

- **자동(즉시 실행)** — 끊긴 참조 수정, 4관문 위반 삭제(repo 국한·시한부·미검증), 명백한 노후·근거표기 정정, 루트 과다 sub-hub 묶기, 요약/품질 정정, 잉여 hub 머지. 부패(노후·검증불가·추상화불가) 시 정정보다 삭제 우선.
  - `delete` 전 본문 `read` 로 살릴 내용 확인. 낙관락 위해 읽은 `version` 을 `--base-version` 으로 전달. 부모·자식 함께 지울 땐 자식부터.
  - `move` 는 본문 불변·위치만. `write` 갱신은 `--parent` 생략 시 기존 상위 유지.
- **보고(마지막에 한 번에)** — 둘 다 유효할 수 있는 모순, 코드만으로 노후 확정이 안 되는 항목, 새 페이지화·데이터 공백 보강 제안 등.
- 다중 작업은 **전부성공/전부실패** — 일부라도 실패하면 부분 적용 사실을 보고(silent skip 금지).

### 6. 재검증·보고

`lint` 재실행으로 무결성·트리 통계 개선을 확인. before/after(페이지 수·`rootCount`·무결성) + 자동 처리 내역 + 보고 대기(애매) 항목을 정리해 제시.
