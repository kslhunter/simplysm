# sd-review

리뷰를 직접 오케스트레이션으로 수행하는 스킬임.

## 절차

1. 사용자가 지정한 대상을 확정할 것. 대상이 모호하면 조사로 후보를 좁힌 뒤 가능한 해석을 안으로 만들어 `제안`할 것.
2. 대상을 식별하고 대상에 맞는 지침/매뉴얼을 조사할 것.
3. 조사한 지침/매뉴얼의 내용을 관점(정리정돈·명확성·유지보수성 등)별로 정리할 것.
4. 정리된 관점별 각각의 서브에이전트를 수행하여 병렬로 리뷰할 것. (`자동`, `결정` 분류도 함께 수행할 것.)
   - `자동`: 리뷰어 재량이 개입하지 않고 정답이 하나로 확정되는 것 — 아래 4유형.
     대상 종류(코드·문서 등)를 가리지 않고 동일하게 적용할 것.
     - 명문 규칙 기계적용: 적용할 규칙(대상의 지침·매뉴얼·lint 설정 등)이 정답을 단일 확정하는 것.
       예: 종결형·조사·용어 표기 통일, 줄길이·기호 표기 규칙, lint 자동수정 범위, 명명 규칙 위반.
     - 사실 오류 교정(대상 부재형): 산출물이 가리키는 대상이 실재하지 않는 것.
       예: 없는 경로·심볼·옵션, 바뀐 시그니처를 가리키는 주석·문서.
       양쪽 다 실재하고 동작·값만 다르면 `결정`임 — 어느 쪽이 맞는지가 사용자 결정 사항임.
     - 파생물 동기화: 종속 관계가 자명한 종속물이 원본과 어긋난 것. 예: 목차↔섹션, 배럴 export↔파일.
       어느 쪽이 원본인지 안 서면 `결정`임.
     - 확정된 사용자 결정 반영: 대화에서 사용자가 명시 확정한 사항의 직접 적용 대상이 어긋난 것.
       인접 대상으로 넓혀 적용하지 말 것(확대해석 금지).
   - `결정`: 위 4유형에 해당하지 않는 모든 항목. 근거 규칙을 못 대거나 정답이 둘 이상이면 `결정`임.
     - 아래는 형식 정리로 보여도 `결정`임.
       - 재진술·중복 문장 삭제 — 발동 범위(예시·조건 열거)가 깎임.
       - 식별자 rename — 공개 API 면 소비자 영향, 내부라도 호출부 전수 확인이 전제임.
       - 죽은 코드 제거 — 미사용 판정 자체가 검증 대상임.
       - 타입체크·테스트 통과를 등가 근거로 삼는 리팩터링 — 통과는 동작 불변의 근거가 아님.
   - 각 서브에이전트는 대상을 세밀하게 전수 리뷰할 것.
   - 대상 파일이 하나이거나 관점이 하나이면 서브에이전트 없이 직접 수행할 것.
5. `결정` 발견별로 각각의 독립 서브에이전트(`subagent_type: sd:sd-verify` — 검증 전용)에서 적대적 검증할 것. `자동`은 직접 적대적 검증할 것.
6. 검증에서 살아남은 발견들을 취합하고, 관점 간 중복 발견을 병합할 것.
7. `자동`건을 즉시 적용할 것.
8. `결정`건은 전체를 나열하지 말 것. 스스로 우선순위를 정해 sd.md `제안` 규칙대로 가장 우선한 1건만 `제안`할 것(발견 목록 통째 제시·"뭐부터 할지" 메뉴 질문 금지). 그 1건이 처리되면 다음 1건을 같은 방식으로 `제안`할 것.
