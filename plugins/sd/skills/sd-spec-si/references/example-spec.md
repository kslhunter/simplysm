# WMS 요구 분석서 (예시)

> sd-spec-si §별 본문의 형식 모범. 실제 산출물은 spec bundle 로, 여기의 각 § 는 하위 page 로 분리된다(§1·§10·§11 은 루트 `spec.md`, §2-§9 는 각 page) — 이 파일은 그 page 본문의 형식 모범으로만 참조한다.
> 가상의 WMS 시나리오 — 박스 단위 Location 관리 + ERP 단방향 통보.
> 시나리오 일자 = 2026-04-01 (사용자 확정 시작일 가정).

## 1. 개요

### 1.1 핵심 목적

박스 단위로 Location 을 추적하고, 입출고 발생을 ERP 와 연동하는 WMS (Warehouse Management System).

### 1.2 주요 목표

- 박스 입고 처리
- 박스 출고 처리
- 입출고에 따른 재고 확인
- 입출고 정보의 ERP 동기화

### 1.3 최종 사용자/이해관계자

- 창고 작업자: 현장에서 PDA 를 들고 물건을 옮기는 작업자
- 창고 관리자: 사무실에서 PC 로 마스터·재고·지시서를 관리하는 담당자

### 1.4 환경/장치

```
   ┌─────────┐              ┌─────────┐
   │   PC    │              │   PDA   │
   └────┬────┘              └────┬────┘
        │                        │
        └───────────┬────────────┘
                    ▼
              ┌───────────┐   통보(단방향)   ┌───────┐
              │ WMS 서버  │ ───────────────► │  ERP  │
              └─────┬─────┘                  └───────┘
                    │
            ┌───────┴────────┐
            ▼                ▼
      ┌───────────┐   ┌───────────────┐
      │ A4 Printer│   │ Label Printer │
      └───────────┘   └───────────────┘
```

- PC — 창고 관리자가 마스터·출고지시서·재고 화면 운용에 사용
  - OS: Windows 11
  - Browser: Chrome 최신
  - 해상도: 1920 x 1080
- PDA — 창고 작업자가 박스·Location 스캔에 사용
  - Model: DS60S
  - OS: Android 9
  - 해상도: 360 x 568
- A4 Printer — 출고지시서 출력 및 Location 바코드 다중 출력 (A4 1매에 여러 라벨 배치)
  - 스펙: 시중에서 일반적으로 판매되는 A4 프린터 (특정 모델 제약 없음)
- Label Printer — Location 라벨을 1매씩 출력
  - Model: [OPEN]

## 2. 업무 프로세스

### 2.1 입고

```mermaid
flowchart LR
    S([물건 도착]) --> T1[창고 작업자: PDA 박스 바코드 스캔]
    T1 --> T2[창고 작업자: PDA Location 바코드 스캔]
    T2 --> E1([입고 등록 완료])
```

- 박스 1개는 단일 품목·단일 Location 만 가짐 (박스 1개가 2개 Location 에 동시 존재 불가)
- 입고 등록 시점 = 박스의 최초 Location 적치 시점 (재입고·이동은 본 프로세스에서 제외)
- 박스 바코드는 외부에서 이미 부착된 상태로 도착함 (창고에서 발급하지 않음)
- ERP 통보는 박스번호를 키로 멱등 처리됨 (동일 박스 재시도 시 ERP 측이 중복 무시)

관련 섹션: [화면.입고 스캔], [화면.품목 관리], [화면.Location 관리], [화면.재고 확인]

### 4.1 품목 관리 (PC)

Actor: 창고 관리자
관련 섹션: [프로세스.입고]

기능 개요:

- 품목 마스터 CRUD: 등록 / 편집 / 삭제·복구 / 엑셀 업·다운로드

#### 와이어프레임

```
┌──────────────────────────────────────────────────────────────────────────┐

│ [화주 자료 업로드]                                                       │
│ ──────────────────────────────────────────────────────────────────────── │
│ <품목 목록 시트>                                                         │
└──────────────────────────────────────────────────────────────────────────┘
```

#### 항목

**필터**

| 항목 | 종류   | 필수 | 비고                     |
| ---- | ------ | ---- | ------------------------ |

**품목 목록 시트** (코드까지 fixed)

| 컬럼  | 종류             | 필수 | 도메인 매핑      | 비고              |
| ----- | ---------------- | ---- | ---------------- | ----------------- |
| `[ ]` | 선택 체크박스    | -    | -                |                   |
| ID    | 숫자 + 편집 버튼 | -    | [모델.품목.ID]   | 클릭 시 편집 모달 |
| 코드  | 문자             | -    | [모델.품목.코드] |                   |
| 명칭  | 문자             | -    | [모델.품목.명칭] |                   |

#### 동작

- `[조회]` 클릭: 검색 필터 조건으로 목록을 갱신
- `[등록]` 클릭: → 품목 등록·편집 을 빈 폼 상태로 모달 띄움
- ID 버튼 클릭: → 품목 등록·편집 을 해당 행 데이터로 채워 모달 띄움
- `[선택 삭제]` 클릭: 선택된 행들의 활성 여부를 false 로 전환 (이후 해당 품목 입출고 불가)
- `[선택 복구]` 클릭: 선택된 행들의 활성 여부를 true 로 전환
- `[엑셀 업로드]` 클릭: 엑셀 파일 선택 후, 코드를 키로 일괄 등록·수정
- `[엑셀 다운로드]` 클릭: 현재 필터가 적용된 목록을 엑셀로 내보냄
- `[화주 자료 업로드]` 클릭: [공통 정의.화주 품목 자료] 파일을 선택받아, 아래 업로드 양식을 적용한 뒤 코드를 키로 일괄 등록·수정

#### 시각 규칙

- 비활성 행: 전체 텍스트에 취소선 + 회색 처리

#### 업로드 양식

[공통 정의.화주 품목 자료] → [모델.품목]

| 파일 컬럼          | 도메인 모델      | 변환·규칙                        |
| ------------------ | ---------------- | -------------------------------- |
| `화주코드` + `SEQ` | [모델.품목.코드] | `<화주코드>-<SEQ>` 형식으로 합성 |
| `품목명`           | [모델.품목.명칭] | 1:1                              |

## 5. 자동 처리

### 5.1 재고 스냅샷

목적: 과거 시점 재고 조회를 지원

트리거: 매일 0시 정각 (자정)

관련 섹션: [기타.과거 재고 조회], [화면.재고 확인]

#### 처리

- 트리거 시점의 [모델.재고] 전체를 [모델.재고 스냅샷] 에 해당 날짜로 저장

#### 예외 처리

- 스냅샷 생성 실패 시:
  - 위험: 당일 분 누락 시 해당 날짜의 과거 시점 조회가 불가
  - 대처: 관리자에게 알림 발송. 동일 일자에 재실행할 경우 (날짜, 박스) 유일성 제약으로 중복 생성을 방지
  - 재시도 한계: 자동 재시도 없음 (다음 날 0시에 정상 동작)

## 7. 공통 정의

### 7.1 용어 사전

- 박스: 외부에서 이미 바코드(품목코드 + 수량 + 박스번호 합성)가 부착된 상태로 도착하는 입고 단위
- Location: 창고 내 적치 위치. 라벨 규격은 [공통 정의.Location 라벨] 참조
- ERP 통보: 입출고 발생 시 WMS 에서 ERP 로 보내는 단방향 알림
- 활성 여부: 마스터 데이터의 소프트 삭제 플래그 (true = 정상, false = 삭제 처리됨). UI 의 "삭제·복구" 액션과 매핑됨. 마스터 데이터는 DB 레코드를 물리적으로 삭제하지 않음

### 7.2 박스 바코드 형식

[OPEN] 박스 바코드 형식 미확정 — 첨부B.pdf p.5 "박스 코드 체계" (외부 송장 시스템 규격) 분석 필요. [모델.박스] 의 비즈니스 키 구조와 직결되므로 [모델.박스] 와 함께 검토.

### 7.3 Location 라벨

```
┌────────────────────────────────┐
│                                │
│   [Code128 바코드: A-01-03]    │
│                                │
│            A-01-03             │
│                                │
└────────────────────────────────┘
```

- 표시 항목: 바코드 + Location 코드 텍스트
- 심볼로지: Code128
- 라벨 크기: 100 × 50 mm
- 라벨 재질: 유포지, 흰색 무지

### 7.4 화주 품목 자료

화주(품목을 본 WMS 에 보관 위탁한 거래처)가 자체 ERP 에서 수시로 다운로드한 뒤, 화주별로 별도 파일을 전달함. 신규 화주 등록 시점이나 화주 측 품목 마스터 변경 시점에 본 WMS 로 1회 일괄 업로드함. 식별 키는 `화주코드` + `SEQ` 2개 컬럼의 합성값.

| 컬럼     | 필수 | 설명                                                 |
| -------- | ---- | ---------------------------------------------------- |
| 화주코드 | O    | 화주 ERP 의 품목 코드. 영문 대문자 + 숫자, 최대 8자  |
| SEQ      | O    | 같은 화주코드 내 개정(revision) 일련번호. 숫자 3자리 |
| 품목명   | O    | 화주 측 명칭                                         |
| 단위     | X    | `EA` / `BOX` 등                                      |

## 8. 도메인 모델

### 8.1 품목

필드:

| 필드      | 타입    | 필수 | 비고                 |
| --------- | ------- | ---- | -------------------- |
| ID        | 숫자    | O    | 자동 부여            |
| 코드      | 문자    | O    | 자유 형식, 수정 가능 |
| 명칭      | 문자    | O    |                      |
| 활성 여부 | boolean | O    |                      |

키/제약:

- 식별 키: ID (자동 부여)
- 비즈니스 키: 코드 (사용자 부여, 수정 가능)
- 유일성 제약: 활성 품목 범위 내에서 코드, 명칭 각각 유일

### 8.2 박스

필드:

| 필드     | 타입        | 필수 | 비고                                   |
| -------- | ----------- | ---- | -------------------------------------- |
| ID       | 숫자        | O    | 자동 부여                              |
| 박스번호 | 문자        | O    | [공통 정의.박스 바코드 형식] 형식 따름 |
| 품목     | 참조 - 품목 | O    |                                        |
| 수량     | 숫자        | O    |                                        |

키/제약:

- 식별 키: ID (자동 부여)
- 비즈니스 키: 박스번호
- 박스 1개는 단일 품목만 가짐
- 유일성 제약: 박스번호는 전체 박스에서 유일

### 8.3 Location

필드:

| 필드      | 타입    | 필수 | 비고                                                                |
| --------- | ------- | ---- | ------------------------------------------------------------------- |
| ID        | 숫자    | O    | 자동 부여                                                           |
| 코드      | 문자    | O    | 영문 대문자/숫자/하이픈. 수정 가능. 예 `A-01-03`, `ZONE1-RACK7-LV2` |
| 활성 여부 | boolean | O    |                                                                     |

키/제약:

- 식별 키: ID (자동 부여)
- 비즈니스 키: 코드 (사용자 부여, 수정 가능)
- 유일성 제약: 활성 Location 범위 내에서 코드는 유일

### 8.4 재고

필드:

| 필드     | 타입            | 필수 | 비고      |
| -------- | --------------- | ---- | --------- |
| ID       | 숫자            | O    | 자동 부여 |
| 박스     | 참조 - 박스     | O    |           |
| Location | 참조 - Location | O    |           |

키/제약:

- 식별 키: ID (자동 부여)
- 박스 1개는 동시에 1개 Location 에만 존재 (박스-재고 = 1:1)
- Location 1개에 박스 다수 적치 가능

### 8.5 재고 스냅샷

필드:

| 필드     | 타입            | 필수 | 비고        |
| -------- | --------------- | ---- | ----------- |
| ID       | 숫자            | O    | 자동 부여   |
| 날짜     | 날짜            | O    | 스냅샷 일자 |
| 박스     | 참조 - 박스     | O    |             |
| Location | 참조 - Location | O    |             |

키/제약:

- 식별 키: ID (자동 부여)
- 비즈니스 키: (날짜, 박스) 조합이 유일

## 9. 외부 인터페이스

### 9.1 ERP 입고 통보

- 상대 시스템: ERP
- 방향: WMS → ERP
- 전송 방식: REST API (POST)

관련 섹션: [화면.입고 스캔]

#### 자료 매핑

| ERP 필드 | WMS 출처              |
| -------- | --------------------- |
| 품목코드 | [모델.박스.품목.코드] |
| 수량     | [모델.박스.수량]      |
| 박스번호 | [모델.박스.박스번호]  |
| 발생시각 | 입고 등록 시각        |

#### 예외 처리

- 호출 실패 시 (네트워크 오류, ERP 서버 일시 다운 등):
  - 위험: 단순 재시도 시 ERP 에 같은 박스가 2번 입고 등록될 수 있음 (예: 첫 호출이 ERP 에 도달했으나 응답만 못 받은 경우)
  - 방지 전제: ERP 측이 박스번호를 키로 사용하여 이미 받은 통보를 무시하도록 구성되어 있어야 함
  - 대처: 위 전제 하에 지수 백오프로 재시도, 최대 5회까지
  - 재시도 한계 초과 시: 관리자에게 알림 발송 (이후 수동 확인 필요)

### 재고 차감 시점 — 출고 확정 시 (피킹 시 아님)

- 현재 결정: 재고는 출고 확정 시점에 차감.
- 근거: 사용자 결정 — 피킹 취소가 잦아 피킹 시 차감하면 재고가 흔들림 (회의록.md L60-72).
- 기각 대안: 피킹 시 차감 — 실시간성은 낫지만 취소 롤백 부담으로 기각.
- 검토 경계: 확정 시·피킹 시 두 안만 검토. 예약 재고(soft reserve) 방식은 논의 안 함 — 후속 LLM 이 재고 정확도 이슈로 재설계하려면 이 미검토 영역부터.
