# sd-proposal

요구 범위로부터 고객을 설득하는 제안서를 산출합니다.

- 최우선 목적은 근거 있는 설득이며, 근거 없는 우월 주장, 정량효과 과장, 현행 왜곡을 차단합니다.
- 고객이 "부풀렸다"고 의심할 여지를 남기지 않습니다.

견적이 함께 필요하면 `sd-estimate` 를 연계 안내하세요.

## 입출력

- Input (자유) — 제안 대상 범위를 알 수 있는 자료라면 무엇이든 됩니다.
  - 정형, 비정형 무관합니다. 자료 예: spec(spec.md/spec-si.md), 레거시 코드베이스, 회의록, 기능/화면 목록, 구두 설명.
- Output — PPT식 16:9 슬라이드 deck 입니다.
  - 자기완결 단일 HTML(외부 폰트, CDN 의존 없음) + 고객 전달용 PDF.
- 저장 위치 — 입력 자료 옆 또는 사용자 지정 경로(`제안서.html`).

## 핵심 원칙 (편향 차단 — 위반 시 제안서 무효)

1. 근거 있는 주장만 씁니다.
   - As-Is 통증, To-Be 장점, 도입 효과를 전부 입력 근거에 연결해야 합니다.
   - 근거가 없으면 그 항목을 빼거나 `[OPEN]` 으로 표시하세요.
2. 정량효과를 단정하지 마세요.
   - "3배 빨라짐", "비용 50% 절감" 같은 수치는 실측, 제공 근거가 있을 때만 기재하세요.
   - 없으면 정성으로 서술합니다.
3. As-Is 는 사실로 씁니다.
   - 현행을 비하하거나 왜곡하지 마세요.
   - 장점은 As-Is↔To-Be 대비에서 드러나게 하고, 현황 서술 자체를 우월성 근거로 쓰지 마세요.
4. 미확정은 협의 항목으로 분리합니다.
   - 정해지지 않은 범위, 연동, 규격을 확정인 척 단정하지 말고 협의 사항이나 OPEN 으로 분리하세요.
   - 일정은 추정이며 가변임을 명시해야 합니다.

## 절차

1. As-Is / To-Be 재료 도출 — 입력 자료를 직접 읽어 현행 구성, 한계(코드, 사실 근거와 함께)와 제안하는 모습(업무 흐름, 아키텍처, 기능 범위, 외부 연동)을 도출하세요.
   - As-Is 가 없는 신규 구축이면 As-Is 대신 "도전 과제(왜 필요한가)"로 도출합니다.
2. 변화 축 / 핵심 로직 정리 — 전환, 통합, 마이그레이션이면 As-Is → To-Be 변화 축을 비교 매트릭스로 정리하세요.
   - 계산, 판정이 핵심인 시스템이면 그 핵심 메커니즘을 정리합니다.
3. 스토리라인 합의 (생성 전) — 장수, 순서, 각 장의 메시지를 내용 우선으로 설계해 사용자와 합의해야 합니다.
   - 1 슬라이드는 1 메시지입니다.
   - 설득에 기여하지 않는 장은 넣지 말고, 필요한 장은 새로 만드세요.
4. deck 생성 — 아래 "출력 형식"을 따르세요.
5. 잘림 점검 + PDF 출력 — 각 슬라이드가 720px 안에 잘리지 않고 들어갔는지 확인하세요 (`.slide` 은 `overflow:hidden`).
   - 넘치면 슬라이드를 쪼개거나 항목을 줄이세요. 폰트, 패딩은 템플릿 값을 유지하고 항목 수로 조절해야 합니다.
   - 확인이 필요하면 헤드리스 브라우저로 슬라이드별 1280×720 스크린샷을 뜨세요.
   - 맞춘 뒤 `sd-html-to-pdf` 스킬로 PDF 를 출력합니다. 템플릿 `@page` 1280×720 덕에 1 슬라이드가 1 페이지입니다.
6. 출력 전 자가 점검 — 위 핵심 원칙 4개 준수 여부와, 클로징 슬라이드에 근거 출처, 작성일, 공급자를 명기했는지 확인하세요.

## 출력 형식

[references/proposal-template.html](references/proposal-template.html) 은 디자인 토큰(`:root`) + 슬라이드 프레임 + 컴포넌트 카탈로그 + 슬라이드 예시 + fit, 페이지번호 스크립트입니다.

- 그대로 채우는 게 아니라 참고해 내용에 가장 적합한 deck 을 구성하세요. 슬라이드를 자유롭게 추가, 삭제, 분할, 병합, 재배치하고, 안 쓰는 `.frame` 은 통째로 삭제합니다.
- 템플릿의 슬라이드 목록과 `[공통, 필수]`/`[선택]` 라벨은 권장 예시일 뿐 고정 양식이 아닙니다.
- 슬라이드 단위는 `.frame > .slide` 이며 1280×720px 고정입니다 (96dpi 기준 PPT 와이드 16:9).
- 디자인 토큰, 컴포넌트 클래스, 슬라이드 프레임은 그대로 재사용해야 합니다.
  - 카탈로그로 표현이 마땅치 않으면 같은 디자인 언어(토큰, 카드/그림자, 여백 리듬) 안에서 새 레이아웃을 구성해도 됩니다.
- `@media print`, `@page`, fit, 페이지번호 스크립트는 수정하지 마세요. PDF 1슬라이드=1페이지, 배경 출력, 자동 페이지번호 품질을 좌우합니다.
  - 페이지 번호(`.pg`)는 스크립트가 채우므로 비워 두세요.
- 액센트 1색만 도메인, 브랜드에 맞게 조정할 수 있습니다. navy+blue 베이스 팔레트는 고정입니다.
- 플레이스홀더 `「…」` 는 전부 실제 내용으로 채우고, 채울 근거가 없으면 그 항목을 빼거나 OPEN 처리하세요.
- 자기완결 1파일이어야 합니다. 외부 폰트, CDN, 스크립트에 의존하지 마세요. 폰트는 템플릿의 시스템 스택을 그대로 쓰세요.
