# sd-docs

`@simplysm/*` 패키지의 API 문서를 코드를 근거로 작성, 갱신합니다.

- 메인이 패키지 목록 추출과 상위 README 인덱스 갱신을 맡습니다.
- 패키지 1개당 서브에이전트 1개로 문서 작성을 위임합니다(가능하면 병렬).

## 산출물

- 활성 references 경로의 `apis/<패키지명>/README.md` — 패키지당 1개, 필수.
- 같은 경로 `apis/<패키지명>/<군명>.md` — 군이 커서 README 한 장에 풀어쓰면 다른 군 정보까지 함께 읽혀 부담이 커지는 경우에만 분할.
- 같은 경로 `README.md` 의 "패키지 인덱스" 섹션 — 메인이 갱신.

## 절차

### 1. 패키지 목록 추출

워크스페이스 루트의 `packages/*/package.json` 을 모두 읽어 `private: true` 가 아닌 패키지 목록을 만드세요 (`shortName` 은 `@simplysm/` 접두사 제거).

### 2. 패키지별 위임

패키지마다 [references/subagent-prompt.md](references/subagent-prompt.md) 를 작성 규칙으로 전달하세요. 치환값:

- `<패키지명>` 은 `shortName`, `<패키지 디렉토리>` 는 패키지 경로입니다.
- `<매뉴얼 인덱스>` 는 활성 references 경로 `README.md` 의 "개발 매뉴얼" 트리거 표입니다 (전 패키지 동일 값).

풀 재작성입니다.

- 기존 파일을 참고하지 않고 처음부터 작성합니다.
- 규칙 변경이 매번 반영되도록 코드가 안 바뀐 패키지도 다시 씁니다.
- 코드에서 사라진 군의 파일은 삭제하세요.

범위는 `apis/<패키지명>/` 뿐입니다. 상위 `README.md` 는 건드리지 마세요.

### 3. 인덱스 갱신

전건 성공해야 진입합니다. 오류로 끝났거나, 정상 종료했어도 필수 `apis/<패키지명>/README.md` 가 산출되지 않았으면 실패입니다.

- 실패분만 재수행하세요.
- 재수행에도 실패가 남으면 인덱스를 갱신하지 말고 실패 목록, 사유를 보고한 뒤 중단해야 합니다.

상위 `README.md` 는 풀 재작성 대상이 아닙니다. "패키지 인덱스" 섹션의 항목 리스트만 재구성하고 섹션 머리, 다른 섹션은 건드리지 마세요.

- 형식: `- **<패키지명>** — <한 줄 트리거 요약>. 자세히: [apis/<패키지명>/README.md](./apis/<패키지명>/README.md)`
  - 줄 전체가 영문 200자(한글 100자)를 넘지 않도록 요약 길이를 맞추세요. 링크부와 패키지명이 길수록 요약을 줄여야 합니다.
- 패키지명 알파벳순입니다. private 패키지와 코드에 더 이상 없는 패키지는 제외하세요.

### 4. 보고

재작성한 패키지 목록, 분할이 생긴 패키지, 삭제한 분할 파일, 인덱스에서 제거한 항목을 보고하세요.
