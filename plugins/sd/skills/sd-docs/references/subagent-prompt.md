# API 문서 작성 규칙 (sd-docs)

패키지 1개의 API 문서를 작성·갱신할 때 따르는 규칙. 산출 자리는 활성 references 경로의 `apis/<패키지명>/` (`<패키지명>` = `@simplysm/` 접두사 제외한 짧은 이름. 예: `@simplysm/foo` → `apis/foo/`).

## 1. 입력 분석

문서 **내용의 진실 근거**는 다음만 사용함 — 외부 자료·과거 git 기록·다른 패키지의 사용처는 참조 금지.

- `<패키지 디렉토리>/src/index.ts` 의 export — **entry 시작점**. 여기서 노출된 심볼만 문서 대상임.
- 위 entry 가 재노출하는 각 심볼의 정의 파일(타입 시그니처 + 본문).
- 위 정의 파일 또는 동일 패키지 안의 다른 파일에 달린 JSDoc 주석.
- `tests/` 디렉토리 중 해당 패키지를 import 해 검증하는 테스트 코드 (존재할 경우에만).

타입 시그니처에서 직접 드러나지 않는 사용 패턴을 보강해야 하면 위 4개 소스 안에서만 추론함.

개발 매뉴얼은 **내용 근거가 아니라 사용법 링크 대상**으로만 사용함 (다음 "1.1. 매뉴얼 링크" 참조). 매뉴얼 본문을 API 문서로 복사·보강하는 것은 금지.

### 1.1. 매뉴얼 링크 (사용법은 매뉴얼로 연결)

사용법·사용 예는 API 문서에 적지 않고, `manuals/` 의 해당 매뉴얼로 링크함(api → 매뉴얼).

- 입력으로 주입된 매뉴얼 트리거 표:

<매뉴얼 인덱스>

- 위 표에서 **이 패키지의 심볼·기능에 걸리는 트리거**의 매뉴얼을, 해당 심볼·군 항목 옆에 상대경로 링크로 연결함 (예: `사용법: [orm.md](../../manuals/orm.md)`).
- 걸리는 매뉴얼이 없으면 링크 생략함. 매뉴얼 본문을 API 문서로 복사하지 않음 (링크만).
- **금지**: 매뉴얼 → API 로의 역링크. sd-docs 는 `manuals/` 를 절대 수정하지 않음 (읽기 전용).

## 2. 사용 트리거 군 분류

entry 의 export 심볼들을 "한 작업 컨텍스트에서 함께 참조될 군"으로 묶음. 예: 에러 처리 군, 값 타입 군, 큐/이벤트 군. 분류 기준은 폴더 구조나 심볼 종류가 아니라 **사용 시점**(언제 같이 읽힐 것인가) 기준임.

군이 모호하거나 작아 트리거가 1-2개뿐인 심볼은 별도 군을 만들지 말고 README 의 공통 인라인 섹션에 배치함.

## 3. 산출 단위 판정

기본은 `README.md` 1장임. 다음 조건을 **모두** 만족하는 군만 별도 `<군명>.md` 로 분할함.

- 해당 군의 사용법·주의사항을 README 에 풀어쓰면, 무관한 다른 컨텍스트 정보까지 같이 끌려나와 다른 작업 시점에서 읽기 부담이 커지는 경우.
- 해당 군 단독으로 사용 예·시그니처·주의가 합쳐 8줄 이상 필요한 경우.

위 조건을 만족하지 않으면 README 안에 유지함.

## 4. 풀 재작성 모드 (범위: `apis/<패키지명>/` 자리만)

- 기존 `apis/<패키지명>/README.md` 와 분할 `<군명>.md` 가 있어도 **참고하지 않고 처음부터 작성함**. 코드 + 본 문서의 형식 규칙(아래 README 형식·분할 .md 형식·작성 원칙) 만을 진실 근거로 삼음.
- 기존 파일 내용·표현 보존 시도 금지. 규칙 변경(예: 식별자 풀이 의무) 이 자동 반영되도록 매번 패키지별 산출물(README + 분할 `<군명>.md`) 을 다시 작성함.
- 결과적으로 코드가 변경되지 않은 패키지도 표현이 달라질 수 있음 — 정상임.
- 코드에서 사라진 군의 분할 파일은 삭제함.
- **범위 밖**: 상위 활성 references 경로의 `README.md` 는 건드리지 않음 (인덱스 섹션은 취합 단계에서 별도 처리).

## 5. README.md 형식

각 패키지의 `apis/<패키지명>/README.md` 는 다음 구조를 따름. H1 은 `# @simplysm/<short-name>` 형식으로 고정함.

```markdown
# @simplysm/<short-name>

<패키지 한 줄 개요>

## 사용 트리거 인덱스

- **<심볼 또는 군 이름>** — <언제·어떤 작업에서 쓰는지 1줄>. (분할된 군이면 `자세히: [<군명>.md](./<군명>.md)`)
- ...

## <인라인 군 이름 1>

각 심볼별로 짧은 시그니처 + 옵션·prop·필드·enum literal(열거형 리터럴 값) 1줄 풀이를 작성. 본질적으로 큰 군이라 분할된 경우 이 섹션은 두지 않고, 위 인덱스에서 `자세히:` 링크로 안내.
```

**식별자 풀이 의무**: 시그니처에 나오는 옵션·prop·필드·enum literal 각각에 1줄 풀이 부착함. 풀이 구성 = `<무엇을 함>` + (enum/boolean 인 경우) `<값별 동작 차이>` + `<언제 쓰는지 단서 1조각>`. 단 각 조각은 §7 의 검증 게이트를 통과한 것만 기재함 — 근거 못 대는 조각은 지어내지 말고 생략함. 이름만 콤마로 나열하고 끝내는 형식 금지(최소 타입·리터럴 값은 기재).

예 (나쁨/좋음):

```
[나쁨]
inputs: selectMode, autoSelect: "click"|"focus", useAutoSort, focusMode: "row"|"cell"

[좋음]
- selectMode: "single"|"multi" — 행 선택 모드. 미지정 시 선택 비활성. 다중 선택 화면이면 "multi".
- autoSelect: "click"|"focus" — 자동 선택 트리거. "click" = 클릭 시 선택, "focus" = 키보드 포커스 이동만으로도 선택. 키보드 위주 화면이면 "focus".
- useAutoSort: boolean — 클라이언트 정렬. true 면 sorts 변경 시 items 를 sd-sheet 가 직접 정렬. 서버측 정렬(페이징 포함)이면 false 로 두고 외부에서 items 재조회.
- focusMode: "row"|"cell" — 키보드 포커스 단위. "row" = 행 전체 이동, "cell" = 셀 단위 이동. 셀 편집·복사 화면이면 "cell".
```

## 6. 분할 .md 형식

`<군명>.md` 는 다음 구조를 따름. H1 은 `# @simplysm/<short-name> — <군명>` 형식임.

```markdown
# @simplysm/<short-name> — <군명>

<군 개요 1~2줄: 언제 같이 읽히는 묶음인지>

## <심볼>

시그니처, 옵션·prop·필드·enum literal 1줄 풀이(위 "식별자 풀이 의무" 와 동일 적용), 주의사항.
```

## 7. 작성 원칙

- 산출물의 소비자는 에이전트임. 사람 가독성보다 에이전트가 즉시 따를 수 있는 간결·명확성이 우선함.
- **코드 본문에 드러난 동작은 JSDoc 이 없어도 기재함**. 옵션·prop·필드·enum literal 의 동작을 본문(분기·기본값·사용처) 에서 추론해 풀이함.
- **검증 게이트 (추측 절대 금지)**: 풀이의 각 조각(`무엇을 함`·`값별 동작 차이`·`언제 쓰는지`)은 §1 의 4개 소스 안 **특정 위치**(시그니처·분기·기본값·사용처·JSDoc·테스트)를 근거로 댈 수 있을 때만 기재함. 근거 못 대는 조각은 지어내지 말고 그 조각만 생략함. 코드에 없는 동작·기본값·권장 시나리오를 자명하다고 단정해 메우는 것 = 추측, 금지.
- **식별자만 나열 금지** — 위 "식별자 풀이 의무" 강제함. 이름을 콤마로 나열하고 끝내지 않음(최소 타입·리터럴 값 기재). enum literal 의 값별 동작·boolean 토글 효과·함수형 prop 호출 시점은 검증 게이트를 통과하면 반드시 풀이하고, 코드로 확인 불가하면 그 조각만 생략함.
- 분량을 늘리기 위한 부연·중복·꾸밈 금지. 단, 식별자 풀이는 "분량 늘리기" 가 아니라 필수 정보로 취급 — 풀이 생략을 통한 분량 절약 금지.

## 8. 구조화 결과 반환

작성·갱신을 마치면 다음 항목을 구조화해 반환함 (상위 README 인덱스 취합·사용자 보고에 사용).

- `shortName`: `@simplysm/` 제외한 짧은 이름.
- `writtenFiles`: 산출·갱신한 파일 목록 (README + 분할 `.md` 모두).
- `deletedFiles`: 삭제한 파일 목록 (코드에서 사라진 군, 없으면 빈 목록).
- `triggerSummary`: 패키지의 한 줄 트리거 요약 (상위 README 인덱스에 옮겨 적을 문장).
