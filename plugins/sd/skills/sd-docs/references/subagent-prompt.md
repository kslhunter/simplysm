# API 문서 작성 규칙 (sd-docs)

패키지 1개의 API 문서를 작성, 갱신할 때 따르는 규칙입니다.
산출 자리는 활성 references 경로의 `apis/<패키지명>/` 이며, `<패키지명>` 은 `@simplysm/` 접두사를 제외한 짧은 이름입니다 (예: `@simplysm/foo` → `apis/foo/`).

## 1. 진실 근거

내용 근거는 아래 4개만 사용하세요. 외부 자료, 과거 git 기록, 다른 패키지의 사용처를 참조하지 마세요.

- `<패키지 디렉토리>/src/index.ts` 의 export — entry 시작점입니다. 여기 노출된 심볼만 문서 대상입니다.
- 그 entry 가 재노출하는 각 심볼의 정의 파일 (시그니처 + 본문).
- 그 파일 또는 동일 패키지 안 다른 파일의 JSDoc.
- 해당 패키지를 import 해 검증하는 `tests/` 코드 (있을 때만).

### 매뉴얼 링크

사용법, 사용 예는 API 문서에 적지 않고 `manuals/` 의 해당 매뉴얼로 링크합니다.

- 매뉴얼 트리거 표:

<매뉴얼 인덱스>

- 위 표에서 이 패키지의 심볼, 기능에 걸리는 트리거의 매뉴얼을 해당 심볼, 군 항목 옆에 상대경로로 연결하세요 (예: `사용법: [orm.md](../../manuals/orm.md)`). 걸리는 게 없으면 생략합니다.
- 매뉴얼 본문을 API 문서로 복사하지 마세요. `manuals/` 는 읽기 전용이라 수정, 역링크를 하지 마세요.

## 2. 군 분류와 분할

export 심볼을 "한 작업 컨텍스트에서 함께 참조될 군"으로 묶으세요. 기준은 폴더 구조나 심볼 종류가 아니라 사용 시점(언제 같이 읽힐 것인가)입니다.

기본은 `README.md` 1장입니다. 아래를 모두 만족하는 군만 `<군명>.md` 로 분할하세요.

- README 에 풀어쓰면 무관한 컨텍스트 정보까지 끌려나와 다른 작업 시점에서 읽기 부담이 커집니다.
- 그 군 단독으로 사용 예, 시그니처, 주의가 합쳐 8줄 이상 필요합니다.

트리거가 1-2개뿐인 심볼은 별도 군을 만들지 말고 README 의 공통 인라인 섹션에 두세요.

## 3. 형식

H1 은 `README.md` 면 `# @simplysm/<short-name>`, 분할 파일이면 `# @simplysm/<short-name> — <군명>` 으로 고정입니다.

README 구조는 패키지 한 줄 개요 → `## 사용 트리거 인덱스` → 군별 인라인 섹션입니다.

- `## 사용 트리거 인덱스` 는 심볼, 군마다 `- **<이름>** — <언제, 어떤 작업에서 쓰는지 1줄>` 로 씁니다.
- 분할된 군은 인덱스 항목에 `자세히: [<군명>.md](./<군명>.md)` 를 붙입니다.
- 분할된 군은 인라인 섹션을 두지 않습니다.

## 4. 식별자 풀이 의무

시그니처에 나오는 옵션, prop, 필드, enum literal 각각에 1줄 풀이를 부착하세요.
구성은 `<무엇을 함>` + (enum, boolean 이면) `<값별 동작 차이>` + `<언제 쓰는지 단서>` 입니다.
이름만 콤마로 나열하고 끝내지 마세요.

```
[나쁨]
inputs: selectMode, autoSelect: "click"|"focus", useAutoSort, focusMode: "row"|"cell"

[좋음]
- selectMode: "single"|"multi" — 행 선택 모드. 미지정 시 선택 비활성. 다중 선택 화면이면 "multi".
- autoSelect: "click"|"focus" — 자동 선택 트리거. "click" = 클릭 시 선택, "focus" = 키보드 포커스 이동만으로도 선택. 키보드 위주 화면이면 "focus".
- useAutoSort: boolean — 클라이언트 정렬. true 면 sorts 변경 시 items 를 sd-sheet 가 직접 정렬. 서버측 정렬(페이징 포함)이면 false 로 두고 외부에서 items 재조회.
- focusMode: "row"|"cell" — 키보드 포커스 단위. "row" = 행 전체 이동, "cell" = 셀 단위 이동. 셀 편집, 복사 화면이면 "cell".
```

검증 게이트 (추측 금지): 풀이의 각 조각은 §1 의 4개 소스 안 특정 위치를 근거로 댈 수 있을 때만 기재해야 합니다.

- 근거 위치: 시그니처, 분기, 기본값, 사용처, JSDoc, 테스트.
- 근거를 못 대는 조각은 지어내지 말고 그 조각만 생략하세요.
- JSDoc 이 없어도 코드 본문에 드러난 동작은 기재합니다.

풀이를 생략해 분량을 아끼지 마세요.

- 그 외 부연, 중복, 꾸밈은 금지입니다.
- 소비자는 에이전트입니다.

## 5. 반환

아래 4개를 반환하세요.

- `shortName`
- `writtenFiles`: README + 분할 파일 전부.
- `deletedFiles`
- `triggerSummary`: 상위 README 인덱스에 옮겨 적을 한 줄.
