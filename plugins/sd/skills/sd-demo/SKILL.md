# sd-demo

명세는 SI spec bundle 의 화면 page 또는 대화로 받은 화면 요구 어느 쪽이든 됩니다.
와이어프레임의 배치, 라벨, 동작 흐름과 일치하는 클릭 가능 UI 를 산출하고, 후속 단계에서 같은 자리에 실제 로직을 채워 진화시킵니다.

## 본질: UI 가 1순위

대상은 시연을 받는 사용자입니다. 사용자는 화면만 보고, 코드는 후속 단계에서 다시 작성됩니다.

- 주력은 template(HTML) 복원입니다. 와이어프레임을 시각적으로 정확하고 정돈되게 재현하세요.
- 코드 골격(시그널, effect, DI, 핸들러)은 코드베이스에서 분석해 따르세요. 본 스킬에 라이브러리 규약을 적어두지 않습니다.
- 데이터 변경을 시뮬레이션하지 마세요. 저장, 삭제 핸들러는 마커만 남기고, 클릭은 받되 결과를 반영하지 마세요.
- 모달 띄우기는 실제로 작동시켜 시연 가치를 확보해야 합니다.

## 절차

### 1. 입력 확보

- 명세 출처 — spec bundle 이면 루트 `spec-si.md` 화면 인덱스에서 대상 행의 page(`design/screens/*.md`)를 읽으세요.
  - 그 본문이 `[화면.X]`, `[모델.X]`, `[공통 정의.X]` 로 가리키는 page 를 재귀적으로 읽어야 합니다.
  - 루트의 결정 맥락, 작업 메모도 읽으세요. 그 화면 관련 결정, 제약이 거기 또는 page 의 NOTE, 인라인 `[OPEN]` 에 모입니다.
  - spec 이 없으면 대화에서 확보하고 부족분은 물으세요.
- 화면 식별자 — 매칭이 안 되면 화면 인덱스에서 후보를 제시해 확정받으세요.
- 산출 위치 — 클라이언트 패키지와 화면 폴더입니다. client 타겟이 1개면 자동 선택하세요 (2단계 끝에서 도메인 인접 결과로 갱신).
  - 여러 개면 도메인 인접성, 명세와의 일치도로 우열이 분명한 쪽을 자동 선택하고 완료 보고에 선택 근거를 남기세요. 우열이 안 가려질 때만 후보 제시 후 확정합니다.
- 충돌 — 대상 화면이나 동반 모달의 파일이 이미 있으면 덮어쓰기 / 명세 변경분만 보강 / 취소 중 무엇인지 물으세요.
  - 호출 발화에 분기가 명시돼 있으면 묻지 않고 진행합니다.

와이어프레임은 데모 재현의 핵심 입력입니다. 확보되지 않으면 사용자에게 받아 진행하세요. 임의로 작화하지 마세요.

동작에 등장하는 모달 호출 3형을 모두 수집하세요.

- `→ <모달명>`: 부모 종속
- `→ [화면.X]`: 화면 전체
- `→ [화면.X] 의 <영역>`: 영역 재활용

### 2. 분석

A → B → C 순서로 진입해야 합니다. "참고할 화면이 없다"는 신호는 A 를 건너뛸 이유가 아닙니다.

- A. 라이브러리 문서 — `@simplysm/*` 이면 SessionStart 가 주입한 활성 references 경로의 `README.md` 를 읽고 "개발 매뉴얼" 표에서 현재 트리거에 해당하는 항목에 진입하세요.
  - 그 외 framework 는 코드베이스 안의 동등 위치 문서를 찾으세요.
- B. 컴포넌트 소스 — 사용 예정 컴포넌트의 본체 소스를 직접 읽어 input/output, 동작을 파악해야 합니다. 사용처 검색만으로는 prop 을 놓칩니다.
- C. 부위별 패턴 수집 — 화면 하나를 통째로 따라하지 마세요.
  - 대상 화면이 쓰는 부위(화면 골격, 헤더/타이틀, 툴바, 영역 분할, 리스트, 폼, 모달, 빈 상태)마다 화면 2-4개씩 template 을 발췌해 읽고, 다수에서 반복되는 패턴만 채택하세요.
    - 1회만 쓰인 변종은 배제합니다.
  - 부위마다 다른 화면을 골라도 되며, 도메인이 가까운 화면을 우선하세요.
  - 패턴이 갈리면 대상 와이어프레임이 어느 쪽인지로 선택합니다.

부위별 후보가 0개인 부위가 있으면 그 부위만 사용자에게 한 번 물으세요. "비슷한 화면이 없어서 알아서 그렸다"는 금지입니다.

산출 위치 확정 — 같은 sub-app, 도메인 폴더에 기존 화면이 1개 이상 있으면 그 폴더로 갱신하세요(자동 채택). 0개면 라우팅, 메뉴 등록 위치를 한 번 질문하세요.

### 3. 생성

2단계 분석을 1순위 근거로 template(HTML) 부터 채우세요.

- 파일명, selector, 시그널, DI 명명은 A 가 정한 형식 그대로 적용하세요.
- 슬롯, 영역 분할, 클래스 패턴은 C 의 부위별 채택분을 그대로 적용해야 합니다. 부위마다 참조 화면이 달라도 각 채택분을 그대로 옮기세요.
- 채택분의 출처 파일 경로를 메모해 4단계 점검의 입력으로 쓰세요.
- 모달은 유형별로 다릅니다. 부모 종속형은 대상 화면 컴포넌트에 딸린 모달로, 화면 전체형은 동반 화면으로 함께 생성하세요.
  - 영역 재활용형은 그 화면이 미생성이면 동반 생성 여부를 확인하세요.

마커는 고정입니다. 후속 단계가 검색으로 추적하므로 변형하지 마세요.

- 더미 데이터 선언 위: `// sd-demo: 더미 — 구현 단계에서 교체`
- 미구현 핸들러 본문: `// sd-demo: 미구현 — 동작 자리`
- 더미 타입 인라인 선언 위: `// sd-demo: 더미 타입 — 구현 단계에서 @모델/X 로 교체`
- 임의 추정값 선언, 사용 위: `// sd-demo: 임의 추정값 — 확인 필요`

### 4. 자체 점검

- 부위별 패턴 일치 — 2-C 에서 부위마다 채택한 레퍼런스 화면을 다시 읽어 부위별로 대조하세요.
  - 임의 변형, 새 클래스 발명, 새 슬롯 사용이 있으면 수정해야 합니다.
  - 어긋난 부위는 채택분이 비어 있다는 뜻이므로 2-C 로 돌아가 재수집하세요.
- 라이브러리 문서 위배 — 2-A 매뉴얼 항목별로 확인하고 위배분은 수정 후 재점검하세요.

생성한 파일 목록을 보고한 뒤 종료하세요.
