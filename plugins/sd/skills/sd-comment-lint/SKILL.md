# sd-comment-lint

주석이 남길 값이 있는지를 네 축(A-D)으로 판정해 삭제, 유지, 수집합니다.
기본값은 "삭제"가 아니라 "판정"입니다. 애매하면 지우지 말고 논의 후보로 수집하세요.

## 판정 축

- A — 값 이중관리: hex, px, 수치 같은 값을 주석에 박아 코드값과 이중으로 관리하는 주석.
  - 값 표현만 걷어내세요. 값을 설명하는 것이 전부인 주석은 줄째 삭제하세요.
  - 값의 이유, 출처가 붙어 있으면 그 부분은 C(국소 근거)이므로 남기세요.
  - 예: `// 0x3f 마스킹` → 삭제. `// 0x3f 마스킹 (하위 6비트만 유효, 프로토콜 spec 4장)` → 값 표현만 빼고 근거는 유지.
- B — 전역 규칙, 규약: 여러 파일에서 반복되거나 프로젝트 전반의 당위를 말하는 주석.
  - CLAUDE.md 에 이미 있으면 주석을 삭제하세요.
  - CLAUDE.md 에 없으면 CLAUDE.md 후보로 수집한 뒤 주석을 삭제하세요.
  - 후보는 임의로 CLAUDE.md 에 반영하지 마세요. 승인 게이트입니다. 스킬 종료 후 논의하세요.
- C — 국소 근거: 이 코드가 왜 이렇게 짜였는지, 이 파일 고유의 맥락을 담은 주석. 유지하세요.
- D — 자명 재진술: 코드만 봐도 아는 것을 다시 말하는 주석. 삭제하세요.

## 겹침 처리

한 주석이 여러 축에 걸치면 축별 조각으로 분해해 조각마다 처리하세요.

- C 조각은 유지하세요.
- A 조각은 값 표현만 걷어내고, 붙어 있는 근거는 남기세요.
- D 조각은 삭제하세요.
- C 와 분리할 수 없게 얽혀 있으면 유지가 이깁니다. 의심스러우면 남기세요.

## 건드리지 말 것

주석 모양이지만 기능하는 것은 삭제하면 동작이 바뀝니다. 판정 대상이 아닙니다.

- 컴파일러, 린터, 포매터 지시자: `@ts-ignore`, `@ts-expect-error`, `eslint-disable`, `prettier-ignore`, `// @preserve`, `/* global */` 등.
- 타입, 문서화 주석: JSDoc, TSDoc 의 `@param`, `@returns`, `@deprecated` 등 도구가 읽는 태그.
- 코드 펜스, 문자열 리터럴 안에 든 `//`, `#` 는 주석이 아닙니다.

## 고칠 것과 수집할 것

명백하면 바로 삭제하고, 애매하면 지우지 말고 논의 후보로 수집만 하세요.

- 바로 삭제: 값 설명이 전부인 A, 명백한 D, CLAUDE.md 에 이미 있는 B.
- 논의 후보: CLAUDE.md 미등재 B(승인 게이트), 자명한지 애매한 D, C 와 얽혀 분리가 애매한 A.
- 어느 쪽인지 애매하면 논의 후보로 두세요.
- 형식 위반으로 보이는 주석이 과거의 함정, 사고를 막으려는 국소 근거(C)일 수 있습니다. 단정하지 말고 의도를 확인하세요.
- 수집한 후보는 스킬 종료 후 1건씩 순차로 논의하세요. 여러 건을 묶어 한 번에 보고하지 마세요.
- `sed` 나 정규식으로 한꺼번에 지우지 말고 줄마다 확인하고 처리하세요.

## 검산

- 기능 주석(지시자, JSDoc/TSDoc 태그)을 건드리지 않았는지.
- 삭제로 코드 동작이 바뀌지 않는지.
- CLAUDE.md 후보를 어디서 수집했고 왜 그렇게 판정했는지.
- 파일마다 몇 건을 어떤 축으로 처리했는지.
