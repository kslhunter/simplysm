# 심플리즘 거버넌스 지침 — 문제 해결

## 문제 해결

원인을 찾을 때 적용함.

- 같은 시도 2회 이상 실패하면 즉시 멈출 것.
  - 같은 방식으로 재시도 금지 — 실패 원인 먼저 규명 후 다음 행동 결정할 것.
  - 사과 후 같은 시도 반복 금지.
- 의존 라이브러리 동작에 이상 있으면 라이브러리 측 원인부터 조사할 것.
  - 버그·누락으로 판단되면 사용자에게 보고 후 수정 방법·이슈 발행 `제안`할 것.
  - 불가피하거나 사용자가 명시 요청한 경우에만 우회 코드 작성 `제안`할 것.

**절차**:

1. 최소 2개 이상 가설 탐색할 것.
2. 각 가설의 `결정 근거`를 조사할 것 — 그에 따라 채택·기각 결정할 것.
3. 채택된 각 가설의 반론을 검토할 것.
4. 채택된 원인·해결책을 사용자에게 제시해 선택받을 것. 즉석 처리하지 말 것.

## 비정형 자료

회의록·메일·STT 전사·구두 전달·붙여넣기 등 비정형 원본 자료를 해석·근거로 삼을 때 적용함.

- 비정형 원본은 `결정 근거`(사용자 발언)이지만 오기·오해석·고객 착오 섞임 — 표면을 그대로 확정하지 말 것.
  - 원문은 발췌로 보존할 것.
  - 모호·다의·비합리한 부분이나 화자 간 충돌은 추측으로 채우지 않고 사용자에게 확인할 것.
- STT 전사는 음성인식 특성상 단어가 동음·유사발음으로 깨져 박힘(예: "단가"→"당가").
  - 글자를 곧이곧대로 읽지 않고 문맥에 맞는 단어로 복원해 해석할 것.
  - 복원 모호하면 사용자에게 확인할 것.
- 익숙한 업무 용어(출고·마감·주문 등)일수록 의심할 것 — 현장 은어가 시스템 동작 여러 개에 매핑됨.
  - 자동 매핑하지 않고 어떤 동작인지 사용자에게 확인할 것.
