# 심플리즘 거버넌스 지침 — 코드

## 코드

코드를 쓸 때 적용함.

- 소비자 경험(직관성+사용성) >> 구현의 어려움 > 코드 복잡성 > 수정할 코드량 (왼쪽일수록 지키고, 오른쪽일수록 포기할 것).
  - 사용자 UI·외부 API는 직관적·단순하게 만들 것 — 이를 위한 어려움·구현량·코드 복잡성은 충분히 포기 가능함.
- 결측(null/undefined)은 타입·계산·출력 전 계층에 그대로 전파할 것 — 기본값(`""`·`0`·`false`) 치환이나 비-nullable 타입으로 숨기지 말 것.
  - 나쁜 예: `category ?? ""` 로 받아 미분류와 빈 분류를 뭉갬.
  - 좋은 예: `category?: string` 로 받아 미분류(undefined)를 끝까지 유지함.
- 전역 객체 속성과 혼동될 수 있는 단독 식별자 사용하지 말 것.
  - 나쁜 예: `const name = ...`, `function f(name: string)`.
  - 좋은 예: `const fileName = ...`, `function f(userName: string)`.
- 코드 변경 시 관련 테스트 코드 검토하고 함께 수정할 것.
  - 먼저 테스트 가치를 평가할 것 — 가치 없는 테스트는 삭제할 것.
  - 동작·예외를 검증하지 않는 테스트(예: 텍스트 존재 여부만 확인)는 삭제할 것.
- 구현 방향 선택이나 의미 변경 가능성 있는 코드 변경은 먼저 분석·자료 조사로 계획을 수립할 것.
  - 계획을 이루는 개별 선택을 `결정 단위`로 하나씩 확정하고, 최종 산출물은 그 확정들의 결과로 구성할 것.
  - 코드 품질 규칙(결측 전파·식별자 명명·silent skip 금지·테스트 등)은 계획 단계에서 검증할 것 — 각 선택이 이를 만족하는지 확인하고 위반 설계는 계획에서 배제할 것.
    - 실행 시점 점검이 아니라 설계 제약이므로 "아직 계획이라 나중에"로 미루지 말 것.
- 오타·명백한 단순 수정처럼 의미 변경 가능성 없는 변경은 별도 계획 승인 없이 가능함.

## 오류

코드에서 예외·오류 상황을 다룰 때 적용함.

예외·오류 상황 만나면 throw할 것.

- silent skip 절대 금지 — 문제는 언제나 겉으로 드러낼 것.
- 로그·README·토스트 등 비차단 알림 후 정상 흐름 지속도 silent skip으로 봄.
- 자동 복구 가능 시 자동 복구 제안할 것.
- 다중 작업은 "전부 성공" 아니면 "전부 실패(throw)"임.
  - 일부만 성공한 채 정상 종료하지 말 것.
  - 롤백 가능한 작업(트랜잭션 등)은 이미 적용된 부분도 되돌려 전무 상태로 만들 것.

사용자 노출 알림(로그·토스트 등)은 성격에 맞는 등급으로 분류할 것.

| 성격 | 분류 기준                                                                                              | 흔한 명칭        |
| ---- | ------------------------------------------------------------------------------------------------------ | ---------------- |
| 오류 | 문제 발생. 예외를 잡았는지·무시했는지·재시도했는지 여부와 무관하게 "문제가 일어난 사실"이면 전부 해당. | `error`·`danger` |
| 경고 | 문제는 아니지만 사용자가 인지해야 할 중요한 알림.                                                      | `warn`·`warning` |
| 정보 | 알면 좋은 일반 알림.                                                                                   | `info`           |
| 완료 | 정상 완료 알림.                                                                                        | `success`        |
