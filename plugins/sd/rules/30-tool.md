# 심플리즘 거버넌스 지침 — 도구

## 도구 사용

도구를 실행할 때 적용함.

- 현재 코드베이스 상태(기능 존재·구현 방식·현재 값) 파악은 현재 소스 파일(Grep·Glob·Read)로만 할 것.
  - git diff·log·show·과거 커밋, 세션 주입 `gitStatus` 는 조사 수단으로도 근거로도 열지 말 것 — 최근 변경분에 앵커링돼 현재 전체상을 왜곡함.
  - 예외: 사용자가 "무엇이 바뀌었나"를 명시 질의했거나, 커밋 skill 내부 동작일 때만.
- Grep·Glob은 대상을 찾는 수단임 — 그 출력(매치 줄·주변 문맥·파일 목록)을 판단 근거로 쓰지 말 것.
  - 근거로 삼을 파일은 전체를 Read할 것 — 매치 줄은 그 줄이 어떤 역할·전제·예외 아래 있는지 안 보여줌.
  - 판단이 체계(여러 파일이 모여 하나의 동작·의미를 이루는 것 — 규칙·설정·타입·문서 세트 등)에 걸리면 그 체계의 파일 전부 Read할 것.
    - 한 파일만 보면 파일 간 모순·중복·공백을 못 봄 — 한 곳만 고쳐 체계가 어긋남.
- 아래 경로는 사용자 명시 없이 읽거나 참고하지 말 것.
  - `.back` 폴더 (주의: git commit 엔 포함됨)
  - `.gitignore` 등재 경로
- 사용자가 작업·분석 수행을 명시 요청한 경우, 판단·검증에 필요한 종료되는 단발 명령(빌드·테스트·typecheck·lint 등)은 실행 가능함.
- 서버·상시 프로세스는 실행하지 말 것 — 필요하면 사용자에게 실행 요청할 것.
- 대기 목적의 background 명령(sleep·완료 폴링 루프 등) 실행 금지 — subagent·background 작업 완료는 자동 알림으로 수신됨.
  - 사용자에게 "뭔가 도는 중"으로 보여 대기를 유발하고, 종료 조건 실수 시 무한 잔류함.
- 파일 내용 일괄 치환 금지(`sed`·`awk` 등 — 부작용 큼).
- `subagent`는 명시 요청됐거나 독립 리뷰·검증처럼 격리 이점 분명할 때만 사용할 것. 대화·코드 맥락의 정확한 전달이 결과를 좌우하면 메인 에이전트가 직접 수행할 것.
- 도구의 절단 신호 무시 금지 — 필요한 정보 누락될 수 있으므로 해결 방안 찾아 수행할 것.
- 패키지 매니저 의존성 조사는 `node_modules` 등이 아닌 `lock` 파일·매니페스트 사용할 것.

## hook 동작

도구를 실행할 때 적용함.

hook이 도구 호출에 아래처럼 개입함. 차단은 미리 피하고, 자동 동작은 중복 수행하지 말 것.

**차단**

- 기존 파일 Write는 그 파일을 Read한 뒤에만 허용됨. Read 안 했거나 Read 후 파일 바뀌면 차단되니, (다시) Read해 현재 내용 반영 후 재시도할 것.
- `cd`로 디렉터리 변경하지 말 것.
- `npx tsc`·`npx eslint` 차단됨 — 프로젝트 루트 package.json scripts의 typecheck·lint 명령 사용할 것.
- `git` 변경·발행 명령 차단됨 — 읽기전용 조회만 허용됨. 커밋 등은 사용자가 전용 skill을 직접 호출하는것만 허용됨.
- 전역설치 차단됨: `npm`·`pnpm`·`yarn`·`bun`의 `-g`·`--global`, `yarn global`, `mise use`·`mise install`·`mise i`. 필요한 도구는 프로젝트 로컬(의존성)로 설치하거나 사용자에게 요청할 것.
- `pnpm` 에 `--` 를 붙이지 말 것 — 차단됨. 인자는 `pnpm <script> <args>` 로 바로 붙일 것.
- `playwright-cli`의 `screenshot`·`pdf`·`snapshot`에 `--filename`을, `state-save`·`video-start`에 경로를 지정하지 말 것 — 생략하면 `.playwright-cli/`에 자동 저장됨.

**자동**

- Write·Edit한 파일은 선언된 포맷터(prettier·oxfmt)로 자동 포맷되니, 수동 포맷 정리 따로 하지 말 것.
