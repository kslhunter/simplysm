# 금지 명령어

- `git stash`, `git checkout`, `git restore`, `git reset`, `git clean` 사용 금지.
- `cd` 명령을 통한 타 폴더로의 이동 금지.
- `npx tsc` 사용 금지. 반드시 `pnpm typecheck [targets..]`등의 스크립트 사용
- `npx eslint` 사용 금지. 반드시 `pnpm lint [targets..]`등의 스크립트 사용
- `sed` 사용 금지. 너무 위험함.

# 대화 규칙

- 사용자 요청의 의도가 불명확할 때는 `$sd-inner-clarify` 스킬을 호출하여 명확화.
- 맥락에 맞는 용어 사용
  - 업무 기능·요구사항 논의 → 업무 용어 (사용자가 화면에서 뭘 하는지)
  - DB 스키마 설계 → 테이블·컬럼명
  - 코드 구현 → 함수·클래스명
- 한국 개발 현장 통용 용어 사용
- **CRITICAL**: 사용자가 명시하지 않은 사항 추측으로 행동 금지. 추측한 것이 맞는지 사용자에게 직접 질문하고 응답을 기다릴 것.
  - 명시적 요청없이 다음 단계를 추측하여 바로 작업 하지 말것
  - 명시적 요청없이 코드/문서등을 바로 수정하지 말것
  - 사용자가 목표·방향·통합 여부를 확정했더라도, 구현 방식은 별도 결정사항으로 본다.
  - 구현 방식이 2개 이상 가능하거나 새 개념(내부 모드, 플래그, 래퍼, 호환 계층, 파일 삭제/이동, 호출 흐름 변경)을 도입해야 한다면, 수정 전에 `.codex/rules/sd-options.md` 형식으로 선택지를 제시하고 사용자 응답을 기다린다.
  - 문제 회피를 위해 사용자가 말하지 않은 우회 구조를 만들지 않는다. 재귀, 순환 의존, 호환성 문제 등을 발견하면 먼저 문제로 보고하고 `.codex/rules/sd-options.md` 형식으로 해결 방안을 질문한다.
- 사용자가 직접 확인해야할 사항이 있으면, 계속 진행하지 말고 멈추고 사용자에게 직접 확인 결과를 요청할 것.

# Playwright

- 사용자가 접속주소를 알려주지 않았다면, 반드시 사용자에게 접속주소를 요청할것. (서버 강제 실행 금지)

# 코딩 룰

- 프론트엔드: `.codex/references/sd-frontend-design.md`
- barrel export 금지: `src/` 루트의 `index.ts`외, 하위 폴더 re-export `index.ts` 금지
- 다른 패키지에 대한 re-export 금지
- 정적 import가 불가능한 경우를 제외하고 `import()` 사용 금지
- 구조화된 문법 처리 시 파서 사용 필수. 정규식·문자열 치환으로 우회 금지
- null/undefined 비교 규칙: 일반 값 비교는 `===`/`!==`, null/undefined 검사는 `== null`/`!= null`을 사용.
- 내부 모듈 import 시 `.js` 확장자를 붙이지 않는다. (번들러가 확장자 해석)
- 타입 추론을 해제하는 방식의 수정 금지
- 불필요한 `as` 캐스팅 금지

## 주의사항

- 세션내 작업 수행중 사용자가 특정 부분 코드를 수정했을 수 있음. 임의로 롤백하지 말것
  - 알고있던 정보와 상이한 코드 정보가 있다면, 사용자에게 보고후 확인을 받을 것.
